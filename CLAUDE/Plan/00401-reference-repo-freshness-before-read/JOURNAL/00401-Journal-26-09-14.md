## 12:40 · action · T1.1 — discovery.py, 23 tests, 100% coverage

Two boundaries carry the design, and both were written as tests first:

- A checkout is a `.git` of EITHER kind. A worktree and a submodule carry a
  `.git` FILE, so an `is_dir()` test would silently skip exactly the checkouts a
  multi-worktree workflow produces.
- The walk is depth-bounded and a non-positive bound finds NOTHING. A root is
  configuration and configuration can say `/`; failing closed on a nonsense
  value is what keeps a typo from becoming a filesystem-wide walk.

## 12:45 · finding · T1.1 — a green test that could not fail

Coverage came in at 90.5% and the gap was informative rather than cosmetic. Two
`OSError` branches were unreachable because **this container runs as root**, so
the `chmod 0o000` in my "unreadable subtree" test denied nothing — the test
passed without ever entering the path it claimed to cover.

Rewritten to force the failure by patching `os.scandir`, which exercises the
contract regardless of uid, plus a second test for an entry whose `is_dir()`
stat raises. A third case covered the remaining branch: a root that is ITSELF a
checkout, where `.git` must not be walked because a worktree admin dir inside it
carries its own `.git` and would be invented as a governed repo.

Module coverage now 100%. The lesson worth keeping: a passing test under `root`
proves less than it appears to, and coverage was the only thing that said so.
