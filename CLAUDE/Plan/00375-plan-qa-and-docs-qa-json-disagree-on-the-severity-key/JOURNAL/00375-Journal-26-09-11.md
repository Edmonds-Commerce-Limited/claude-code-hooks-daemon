## 12:06 · finding · — — my own CI wait used an abbreviated SHA and could never match

The second wait loop polled `gh run list --commit 3e1b9fc6c`. That silently
matches nothing — `--commit` compares against the full 40-char `headSha`, so an
abbreviated SHA returns an empty list forever. The loop would have run its full
40-minute cap and reported `CI WAIT CAP REACHED`, which reads as "CI is slow"
rather than "this probe cannot succeed". The first wait worked only because it
happened to be given the full SHA.

The shape of the bug is the one the `pgrep` self-match rules exist for: a probe
that always returns the same answer regardless of the truth. Subsequent waits
use `$(git rev-parse HEAD)`.
