## 17:03 · decision · — — R5 baseline is the default branch tip; R6 one config source

Re-review R5 and R6 (F-BYPS re-review, `untracked/agent-reports/00613-F-BYPS-re-review.md`).

**R5 rule chosen (simplest sound one).** The committed seed baseline is the config at `refs/heads/<default>` of the main checkout, and only while the main checkout's HEAD is attached to that branch:

- `git symbolic-ref --quiet HEAD` fails (detached) -> no baseline.
- The default branch comes from git (`git_sync.default_branch`: `<remote>/HEAD`, else a local `main`/`master`), never from the working config, which is the file the check distrusts. Unresolvable -> no baseline.
- HEAD's ref is not `refs/heads/<default>` -> no baseline.
- The config is shown as `refs/heads/<default>:.claude/hooks-daemon.yaml`, fully qualified, so a same-named tag cannot stand in.

No baseline means every protected link entry refuses; unprotected entries are unaffected. Rejected alternatives: reading the default branch tip while the checkout is elsewhere (the working copy then judges against a tree the human is not looking at, and the "branch the daemon runs from" is the checkout's branch anyway); `branches.default` from config (agent-editable in the working tree).

**R6.** `refuse_uncommitted_protected_links(main, entries)` now takes no pattern source: it reads the main checkout's config on disk itself (strict `Config.load`), so the creation hook and `seed-worktree` judge with one source. An unreadable config, or unreadable `secret_file_guard` options in it, refuses whenever an entry is not already in the committed baseline. Handler tests' repo fixture now carries a config and is on `main`, as an installed project is.
