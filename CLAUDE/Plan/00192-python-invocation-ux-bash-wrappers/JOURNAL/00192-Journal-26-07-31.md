## 19:28 · decision · — — emit resolved absolute paths, never a shell variable

The correct pattern already exists here: `pipe_blocker` does not tell the agent
to run `echd-capture`, it resolves and prints the ABSOLUTE path
`/workspace/scripts/echd-capture`. Every `$PYTHON` site should do the same.

## 20:24 · finding · — — fixture mixes two code sources (documented gotcha)

Provisioning ran my UNCOMMITTED `install_version.sh` change while building the
venv from a worktree at HEAD. Both happened to be aligned here, but they need
not be:

| Component | Source | Sees uncommitted work? |
| --- | --- | --- |
| `scripts/install_version.sh` | main checkout | yes |
| everything under `src/` | worktree at HEAD | no |

So an uncommitted `src/` fix is silently NOT exercised, and you would conclude
it does not work when it was never installed. Documented in
`CLIENT-MODE-TESTING.md` with the rule: commit `src/` before provisioning.
