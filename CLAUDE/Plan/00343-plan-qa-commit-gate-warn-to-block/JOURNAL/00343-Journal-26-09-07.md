## 22:05 · finding · — — filed from a lever Plan 00341 reached and left alone

Plan 00341's whole argument was that an ADVISE finding is not enough: one fired
on commit `923fd583` and the plan it named stayed `Not Started` for five days
anyway. So 00341 shipped a BLOCK-level finding — and then had to record that
this changes nothing today.

`PlanQaCommitGateHandler.handle()` filters `finding.level == Level.BLOCK`, but
only DENIES when `self._plan_qa.commit_gate_mode == _MODE_BLOCK`. This project
runs `warn`, and the warn path passes EVERY finding — block and advise alike —
through `format_advisory()`. So the gate's entire BLOCK tier is currently
decorative, and adding more BLOCK checks cannot change that.

The config comment says "warn-first rollout; flip to block after clean
dogfooding", which is a decision nobody has ever come back to make. That is
itself a small instance of the rot 00341 is about: a document promising a
state that does not exist.

**Filed separately rather than folded into 00341 on purpose.** The flip arms
every commit-stage check at once, not just the one 00341 added, so its blast
radius belongs to the subsystem rather than to one check — and flipping it as
a side effect is exactly the over-reach a warn-first rollout exists to prevent.

Phase 1 is deliberately a replay rather than a judgement, because the same
technique already earned its keep once: 00341 Task 2.1 replayed 250 commits
and the result CHANGED the rule (it exposed a 25% false-positive shape that
argument had missed).
