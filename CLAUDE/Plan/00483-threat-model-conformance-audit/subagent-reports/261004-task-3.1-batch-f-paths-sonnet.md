# Task 3.1 batch F: N184, N221 (secret path matching), branch worktree-p483-paths

## Outcome

Both reproduced on main 71be09660 (matcher called directly, pattern `<T>/vault/**`): `cat <T>/x/../vault/r.md`, `cat r.md` with cwd `<T>/vault`, `cd vault && cat r.md`, `cd <T>/vault && cat r.md`, `cat ../vault/r.md` from `<T>/x`, and a `cd vault; python3 -c ...` one-liner all returned no mention. Both are fixed.

- **N184**: `_token_mention` (`utils/secret_file_matching.py`) now also matches the `os.path.normpath` form of an absolute word (`_anchored_spellings`). Lexical only; no symlink is resolved.
- **N221**: new `effective_cwds(command, cwd)` lists the hook cwd plus each literal `cd`/`pushd` target, accumulated in order. A relative word is joined to each and collapsed, then matched. All directories are tried (over-approximation, fail closed) so no per-word ordering is needed. A target containing `* ? [ $ \` { ~`, `cd -`, or a relative `cd\` with no known absolute cwd is not tracked (out of scope, unchanged).
- `iter_protected_mentions` / `find_protected_mention_detail` take an optional `cwds`; `secret_file_guard._bash_interpreter_one_liner_mention` passes the whole command's directories to each shell-exec literal, which is how the one-liner after `cd` is covered.
- The cwd join applies to `context="bash"` only, so prose words in scanned file content are not joined to the cwd.

## Decisions

- No shared cd-tracker exists on main for this: `subagent_full_qa_blocker` and `reference_repo_freshness` track cwd privately inside larger analyses, and the plan_number_helper re-rooting is on an unmerged branch. A 25-line helper local to the matcher was written instead of importing either.
- A spelling that already matches as written (`vault/../open/r.md` under `vault/**`) still matches; collapsing only adds a spelling to judge. Pinned by a test.
