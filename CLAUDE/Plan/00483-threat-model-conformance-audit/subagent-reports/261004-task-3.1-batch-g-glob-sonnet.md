# Task 3.1 batch G: N220, N249, N124 (secret guard glob and pattern operands), branch worktree-p483-glob

## Outcome

- **N220** reproduced (`cat dir/*`, `grep x dir/*`, `ls dir/*`, `cat */*` all allowed with a protected file in `dir`). Fixed: `_bare_glob_mention` in `utils/secret_file_matching.py` expands a glob-shaped word whose last component has under two literal characters against the filesystem (project root, hook cwd, each literal `cd` target) using the existing `_expand_glob_token` walker. Cap `_MAX_BARE_GLOB_FS_EXPANSIONS` = 5000 examined paths; past it `TooManyToEnumerateError` propagates to the guard's fail-closed wrapper (deny). A word that occurs only as a whole quoted word (`'dir/*'`) is literal and skipped (`_GlobExpansionGate.is_quoted_literal`).
- **N249** no longer reproduces on main cdf7403b4: the double-quoted escaped-inner-quote one-liner, its single-quoted twin and the `env python3 -c` form all deny. Pinned with tests; no code change for it.
- **N124 residual** reproduced for `grep -n 'foo\.secret' f`, `grep -n 'a\|.vault-pass' f` and the `rg` twin. Cause: `is_grep_pattern_only_mention` refused any command with a backslash, `|` or similar anywhere in the text, even inside single quotes. Fixed: the expansion-character refusal now looks at the command with plain single-quoted content blanked (`_without_single_quoted_content`; `$'...'` is left alone and refuses as before), and `rg` joins the grep family. File operands stay paths; the closed option list means an option `rg` does not share with grep (`--hidden`, `-g`) voids the relaxation. Non-grep regex tools (`find -regex`, `python3 -c`) stay open, as the triage row says.
- **N347** pinned: `git show worktree-x-mkdir:CLAUDE/Plan/00999-x/PLAN.md` is allowed (test in `test_plan_number_helper.py`). Ledger status updated.
