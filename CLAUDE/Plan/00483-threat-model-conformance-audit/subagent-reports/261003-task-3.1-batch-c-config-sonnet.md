# Task 3.1 batch C: N50, N54, N43 (config handling), branch worktree-p483-config

## Outcome

All three reproduced on this code and are fixed with tests.

- **N50** (`registry.py` blind `setattr`): `apply_handler_options` set `self._<key>` for every option. `human_docs_dir` replaced `MarkdownOrganizationHandler._human_docs_dir`, and `pauses_path` replaced the method in `cron_stop_enforcer`, `cron_subagent_stop_enforcer` and `persistent_cron_assertor`. New `unsettable_option_reasons(handler_cls, options)` refuses a key that starts with `_`, or whose `_<key>` is a method, static or class method, or a read-only property. `apply_handler_options` skips such keys. `_withhold_invalid_options` drops them in pass 1 and returns the reason, so they reach `option_failures` (the session-start alert) as any invalid option value does. Tests: `tests/unit/handlers/test_registry_option_shadowing.py` (unit cases, the shipped markdown and cron handlers, and a `register_all` case).
- **N54** (per-Stop `Config()` rebuild): new `utils/config_cache.default_config()` (`functools.cache`). All eight fallback sites beside `load_config_cached` use it: `recovery_cron_advisor`, `plan_status_snapshot`, `cron_stop_enforcer`, `cron_subagent_stop_enforcer`, `failsafe_cron_session_advisor`, `failsafe_cron_blockage_suppressor`, `background_process_tracker`, `usage_pause_gate`. Tests: `tests/unit/utils/test_config_cache_default.py`.
- **N43** (redaction inert on a config that does not load): `_resolve_active_path` now falls back to `secret_word_list_path` read from the raw YAML, else the shipped default path. Only an unknown project root stays inert. Tests: three new cases in `tests/unit/utils/test_secret_redaction.py` (broken YAML, schema-rejected config, configured path recovered from raw YAML); two existing assertions changed from "INERT" to the new warning text.

## Decisions

- A key naming no attribute at all is still applied. Handlers take options they do not pre-declare and project handlers cannot be enumerated, so "must pre-exist" would break working configs. The refusal targets what breaks: methods, read-only properties and `_` names.
- A property WITH a setter stays settable. A first strict version refused it and failed `test_registry_option_injection` for `bash_safe_mode` (`mode`, `exempt_patterns`) and the idle housekeeping setters.
- N54 covers all eight sites, not the two named: same defect, one shared helper.
- N43 recovers the word list path from raw YAML rather than only the default, so a project that moved its list stays redacted.
- Release note added as `CLAUDE/UPGRADES/UNRELEASED/release-notes/003-...md` (N50 visibly changes behaviour). `CHANGELOG.md` is unchanged: 3.68.0 is released and the file has no Unreleased section.

## Evidence of red

The N50 and N54 tests import names that did not exist (`unsettable_option_reasons`, `default_config`), and the N43 cases returned `()` before the change (the old code set the active path to `None` on any config failure).
