## 09:20 · finding · P1 — root cause of the SessionStart "Missing hook registration" flood

Triggered by user report: a newly installed/upgraded project floods every
session with `WARNING: Missing hook registration for {Event} in settings.json`
(ConfigChange, CwdChanged, Elicitation, ElicitationResult, FileChanged,
InstructionsLoaded, MessageDisplay, PermissionDenied, PostCompact, PostToolBatch,
PostToolUseFailure, Setup, StopFailure, SubagentStart …).

Chain traced:

- `hook_registration_checker` → `utils/hook_registration.py::validate_settings_hooks`
  requires every `wired_event_metas()` event (all catalogued events are
  `wired=True`) to be a key in `settings.json.hooks`. Expectation = 30 events.
- THREE generators produce that hook block and disagree:
  1. `install.py::_DAEMON_FORWARDER_HOOKS` → 30 (in sync).
  2. tracked `.claude/settings.json`, copied by the shell installers → 30 (in sync).
  3. `scripts/install_version.sh::generate_settings_json` bash fallback → **15**,
     explicitly "NOT kept in lockstep with the full Plan 00170 wired set".
- Deployment is a clobber `cp`, never a merge: `upgrade_version.sh` step 9
  `cp`s the template over the client file; when `$SETTINGS_JSON_SOURCE` is absent
  it skips ("using existing") → client's stale registrations survive while the
  Python checker advances → flood. `hook_registration_checker` only DETECTS: it
  auto-migrates command *shape* (`migrate_settings_to_bash_invocation`) but never
  ADDS missing events → nags forever.
