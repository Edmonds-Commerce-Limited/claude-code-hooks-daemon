## Design facts for items 3 to 5 (third agent)

- **One nonce binds one agent.** `dispatches/<nonce>.json` holds one record and
  `_chain_problems` compares it to one reviewer, so two reviewers need two requests. The
  `request` command mints as many requests (nonces, prompts) as `admit_request` returns.
- **Hook order depends on the dispatch mode.** A background dispatch's PostToolUse arrives
  at launch; a foreground one arrives after the agent finishes, so SubagentStop can run
  before `agentId` is recorded. So: PreToolUse writes the dispatch record with
  `tool_use_id` and an empty `agent_id`; PostToolUse alone fills `agent_id`, only when it is
  empty and the `tool_use_id` matches; SubagentStop finds its nonce through `meta.json`
  `toolUseId` and never writes `agent_id` itself (else check 02 is self-fulfilling).
