Review fix (2), D-EXEC F1: the no-value delete is now a compare-and-delete.

`_delete_rejected` called `git branch --delete --force <name>` after `record_removal`, so a
branch moved between the tip re-check and the delete lost the new commits and their reflog.
It now calls `_compare_and_delete`: `git update-ref --no-deref -d refs/heads/<name> <approval.tip>`.

Probed on git 2.47 in a scratch repo before choosing the flags:

- a mismatched old value is refused ("is at X but expected Y");
- `update-ref -d` removes the reflog with the ref, but leaves `branch.<name>.*` config;
- `update-ref -d` does not refuse a branch checked out in a worktree;
- WITHOUT `--no-deref`, deleting a symref alias also deletes its TARGET;
- WITH `--no-deref`, the old-value compare is skipped for a symref.

So the guard refuses a symref and a worktree-checked-out branch itself, immediately before the
delete. Both refusals go down the existing git-refused path, which cancels the ledger line. On
success, `branch.<name>.*` is removed when present. A failure there is logged, never reported
as a refusal, since cancelling a real removal would undercount the rate.
