# Plan 00484 Task 3.2: defence enumeration

## What was built

`hooks-daemon defences [--json] [--project-root PATH]` (`cmd_defences` in `daemon/cli.py`).

- Active handlers come from `DocsGenerator.active_handlers()`, a new public method over
  the existing `_collect_handlers(include_disabled=False)`. It is the set `generate-docs`
  renders, tag gates and handler defaults included. `generate-docs` and `defences` share
  one builder, `_build_docs_generator`, so they cannot drift.
- Rules come from `discover_handler_rules(include_project_handlers=True)`, the index
  `explain-rule` reads. The join is on handler class name
  (`rule_explain/defences.py`, `collect_active_defences`).
- No second hand-maintained list exists anywhere in the change.

Record fields: `rule_id`, `handler`, `handler_class`, `event`, `priority`, `behavior`,
`statement` (the rule's `blocked` text), `defect_class`, `docs`, `detector_entry_point`.

Against this repository's config it emits 129 records, 8 of them rule-less.

## Choices made

- One record per rule of each enabled handler. An enabled BLOCKING handler that declares
  no rule gets one record with `rule_id` and `statement` null, so the 5.3 gap stays visible
  instead of the handler vanishing. Rule-less advisory handlers are not defences and are
  omitted.
- `docs` is `hooks-daemon explain-rule <ID>` (or `explain-handler <key>` when rule-less).
- `detector_entry_point` is `hooks-daemon probe <event> --json <payload>`. It is null when
  the section key is not a wired hook event (plugin, project and pseudo-event sections).

## Gaps (fields with no source today, emitted as null)

1. `defect_class` is null for every record. `CLAUDE/Security/README.md` maps a category to
   a detector script, not a rule to a category, and `Rule` has no such field. Closing it
   needs a mapping decision (a `Rule` field, or a register column naming rule IDs).
2. 8 enabled blocking handlers declare no rule, so `rule_id` is null: `dispatch_declaration`,
   `cron_stop_enforcer`, `cron_subagent_stop_enforcer`, `subagent_report_path_verifier`, and
   the project handlers `ReleaseBlockerHandler`, `EnforceLlmQaHandler`,
   `PlanDoneRequiresHoldingAreaHandler`, `RuffFormatBlockerHandler`.
3. `detector_entry_point` cannot name one handler: `probe` takes an event and a payload and
   runs the whole chain (CONFORMANCE gap G11, `probe --only`, is still open).
4. Plugin handlers are listed only if blocking, and are never joined to rules (the rule
   index does not discover plugins). Project-scope findings in CONFORMANCE (B's and C's
   scripts) are not daemon defences and are not listed.
