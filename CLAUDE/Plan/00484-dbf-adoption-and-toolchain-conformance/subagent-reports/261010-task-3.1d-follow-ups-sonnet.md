## 4. `--path FILE`: one checker added

Added to `scripts/qa/check_british_english.py`, with a shared `out_of_scope_reason` used by both the
tree run and the single-file run; covered by the existing parametrised
`tests/unit/qa/test_qa_single_file_subset.py` (a new checker entry, plus scope cases for
CHANGELOG.md and Plan files, which are refused). Skipped, with reasons recorded in CONFORMANCE G8:

- `check_module_length.py`: report-only, always exits 0, so a one-file run has no verdict.
- the twelve checkers whose `--path` already takes a DIRECTORY and writes a scoped artefact beside it:
  accepting a file changes what that artefact means. Each needs its own design, not a mechanical change.
- cross-file / whole-tree checkers (inventories, drift, doc-truth, handler-reference, hook-contract,
  repo-hygiene): a file is not their unit.

## 5. B rows in `defences`: SKIPPED, needs a ruling

CONFORMANCE (section 4.2 "Remaining gap", G6) says B's `scripts/qa` checkers are not rows of `defences`
and that which are Defences is a Defence-membership call. Options for the coordinator:

- (a) No B rows: `defences` stays the daemon's runtime handlers; B checkers are listed elsewhere
  (e.g. `qa-rules.json`). Cheapest; leaves 5.1/5.3 as graded.
- (b) Rows only for checkers that are the batch equivalent of a write-time handler (british_english,
  error hiding, sensitive content, qa suppression: `check_british_english`, `audit_error_hiding`,
  `check_sensitive_content`, `check_inline_suppressions`), each pointing at the same defect class and a
  `llm_qa.py`/`--path FILE` entry point. Keeps the Defence set tied to defect classes.
- (c) Every `scripts/qa` checker gets a row, with a `kind: batch-check` field. Largest, and makes
  "Defence" mean any gate.
  Each needs a `Defence` schema decision (a `rule_id` source, handler field, and entry point) first.
