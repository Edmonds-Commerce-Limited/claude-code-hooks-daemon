**Location:** `scripts/qa/audit_error_hiding.py:973`; `tests/unit/qa/test_qa_rules.py:66-127`

**Fix:**
- Give the six findings stable kebab-case IDs as `RULE_*` constants, keyed by pattern (e.g. `shell-or-true`), and add their entries.
- Make the discovery fail closed. A `rule` value it cannot resolve (an f-string, or a name that is not a module constant) should fail the test, not be skipped.

### B2. G1: the detector ignores directives honoured by tools this project gates on (Confidence 90%)
**Location:** `scripts/qa/check_inline_suppressions.py:111-130`

An in-memory probe through `_python_comments` and `judge_comments` returns `(0, [])` for all of these. The detector does not even count them:
- `# pyright: ignore[reportX]`. Pyright is a registered gate.
- `# pyright: reportMissingImports=false`
- `# mypy: ignore-errors`
- `# ruff: noqa` and `# flake8: noqa`. These suppress the whole file.

The project's own write-time list, `strategies/qa_suppression/python_strategy.py:13-17`, already names `pyright: ignore`, `mypy: ignore-errors` and `pylint: disable`. So the two lists have drifted apart.

There are no such directives in the tree today. But the batch detector is the only check on a file written through Bash, and an agent fixing a pyright error writes `# pyright: ignore` without thinking. Python and shell are the only languages the project lints; the one `.ts` file is an acceptance fixture.

**Fix:**
- Add these forms to `_DIRECTIVES` and `_PREFILTER`.
- Match `ruff:`/`flake8:` before `noqa`. Today the directive must start the segment, so `ruff: noqa` slips past.
- Better: build both lists from one shared source so they cannot drift again.
