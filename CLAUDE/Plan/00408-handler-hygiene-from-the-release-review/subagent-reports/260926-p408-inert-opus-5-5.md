## Design

`utils.shell_segmentation` gains `INERT_COMMAND_HEADS` (`echo`, `printf`, `:`,
`true`) and `blank_inert_command_arguments(command)`. They sit beside
`strip_inert_spans` and are additive: no existing function was changed.
Callers compose `blank_inert_command_arguments(strip_inert_spans(command))`.
The function blanks to EQUAL LENGTH, so `merge_target`'s re-slice stays
aligned.

A segment's arguments are blanked only when ALL of these hold:

- it is a top-level simple command whose head is exactly one of the four,
  bare;
- it is not piped (`|`, `|&`);
- it carries no unquoted `>` or `&>`;
- it carries no `$` outside single quotes;
- for `printf`, there is no `-v` once quoting is removed.

The whole command is left untouched when any of these holds:

- quoting is unbalanced;
- it holds unquoted `(`, `)`, `{`, `}` or a backtick, `$(` or `$'`, or a
  backtick or `$(` inside double quotes;
- any segment head is a compound word (`if`, `do`, `while` and so on) or is
  built by expansion (`$x`);
- any word, with quoting removed, is `alias`, `enable`, `eval`, `source`,
  `exec` or `function`;
- a `.` appears as a command word.

Scanning stops at the end of the first heredoc opener's line, so body text
is never exempt. A `#` at a word start is skipped to the end of its line, so
a quote inside a comment cannot swallow the next line.

Membership verdicts, as the brief asked:

- `echo -e` and `printf %b`: KEPT. They only decode escapes into output, and
  output is covered by the pipe, redirect and substitution refusals.
- `printf -v`: made CONDITIONAL. It is refused in any quoting (`-v`, `-"v"`,
  `-\v`).
- A redirect to a file sourced later: refused, because any `>` withholds the
  segment.
- `:` and `true`: KEPT. Only expansion could act, and any `$` withholds the
  segment.

The daemon guard's own acceptance test used `echo "cd .claude/hooks-daemon"`
expecting DENY. It now uses `bash -c 'cd .claude/hooks-daemon && pwd'`: a real
directory change, confined to a child shell.

## For the reviewer

- Every refusal errs toward withholding, which costs a false positive, never
  a bypass. Known over-withholds: `echo x 2>&1`, `echo "$HOME"`, and any
  command that contains the word `source` or `eval` anywhere. Each is still
  denied only if it names a guarded command.
- The whole command is withheld on ANY `$(`, not just the segment holding
  it. `$(`, `$'` and backticks can desynchronise a flat quote scan, so a
  per-segment rule would be unsound.
- `destructive_git` and other `strip_inert_spans` callers still over-deny
  `echo 'git reset --hard'`. Adopting there was outside this brief's three
  guards; the primitive is ready for them.
