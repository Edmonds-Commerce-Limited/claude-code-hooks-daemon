## Design

`utils.shell_segmentation` gains `INERT_COMMAND_HEADS` (`echo`, `printf`, `:`,
`true`) and `blank_inert_command_arguments(command)`. They sit beside
`strip_inert_spans` and are additive: no existing function was changed.
Callers compose `blank_inert_command_arguments(strip_inert_spans(command))`.
The function blanks to EQUAL LENGTH, so `merge_target`'s re-slice stays
aligned.

A segment's arguments are blanked only when ALL of these hold:

- it is a top-level simple command whose head is exactly one of the four,
  bare;
- it is not piped (`|`, `|&`);
- it carries no unquoted `>` or `&>`;
- it carries no `$` outside single quotes;
- for `printf`, there is no `-v` once quoting is removed.

The whole command is left untouched when any of these holds:

- quoting is unbalanced;
- it holds unquoted `(`, `)`, `{`, `}` or a backtick, `$(` or `$'`, or a
  backtick or `$(` inside double quotes;
- any segment head is a compound word (`if`, `do`, `while` and so on) or is
  built by expansion (`$x`);
- any word, with quoting removed, is `alias`, `enable`, `eval`, `source`,
  `exec` or `function`;
- a `.` appears as a command word.

Scanning stops at the end of the first heredoc opener's line, so body text
is never exempt. A `#` at a word start is skipped to the end of its line, so
a quote inside a comment cannot swallow the next line.

Membership verdicts, as the brief asked:

- `echo -e` and `printf %b`: KEPT. They only decode escapes into output, and
  output is covered by the pipe, redirect and substitution refusals.
- `printf -v`: made CONDITIONAL. It is refused in any quoting (`-v`, `-"v"`,
  `-\v`).
- A redirect to a file sourced later: refused, because any `>` withholds the
  segment.
- `:` and `true`: KEPT. Only expansion could act, and any `$` withholds the
  segment.

The daemon guard's own acceptance test used `echo "cd .claude/hooks-daemon"`
expecting DENY. It now uses `bash -c 'cd .claude/hooks-daemon && pwd'`: a real
directory change, confined to a child shell.

## For the reviewer

- Every refusal errs toward withholding, which costs a false positive, never
  a bypass. Known over-withholds: `echo x 2>&1`, `echo "$HOME"`, and any
  command that contains the word `source` or `eval` anywhere. Each is still
  denied only if it names a guarded command.
- The whole command is withheld on ANY `$(`, not just the segment holding
  it. `$(`, `$'` and backticks can desynchronise a flat quote scan, so a
  per-segment rule would be unsound.
- `destructive_git` and other `strip_inert_spans` callers still over-deny
  `echo 'git reset --hard'`. Adopting there was outside this brief's three
  guards; the primitive is ready for them.

## Round 2: the exemption is whole-command only

Brief `p408-fix-2.md`, answering review `p408-review-2` (NOT READY, three
BLOCKERs). Commit `ca1d3c371` holds the implementation and tests. The docs
commit follows it. The gate was NOT queued, per the brief.

### What changed

- The coordinator narrowed the design. `blank_inert_command_arguments` and
  all of its per-segment machinery are REMOVED: `_TopLevelSegment`,
  `_top_level_segments`, `_rebinds_or_nests`, `_inert_argument_span`, and
  the rebinding-word, compound-word and separator tables.
- It is replaced by one predicate, `is_wholly_inert_command(command) -> bool`,
  in `utils.shell_segmentation`. It is True only when all of these hold:
  - The raw command matches `[ \t]*(echo|printf|:|true)[ \t]` at its start.
    That pattern is built from `INERT_COMMAND_HEADS` and uses bash's blanks,
    not Python's whitespace.
  - There is no `\n` or `\r` anywhere.
  - No unquoted `; & | ( ) < > { } $ ~ * ? [ !` appears. The list covers
    operators, grouping, redirection and heredocs, every expansion, and
    history expansion.
  - No `$`, backtick or `!` appears inside double quotes.
  - Quoting is balanced, and there is at least one non-empty argument.
  - A `printf` has no first argument starting with `-`, once quotes are
    removed. That refuses `-v`, `-"v"`, `-\v` and `--`.
- Each guard now calls the predicate on the RAW command. If it returns True,
  the guard does not match. Otherwise the guard runs main's code unchanged
  (`strip_inert_spans(command)`, and nothing else). The three call sites are
  `merge_target`, `DaemonLocationGuardHandler.matches` and
  `PlanNumberHelperHandler._new_plan_folder_in_mkdir`.
- `#` is treated as an ordinary character, so the scan never needs to find
  a comment. The rest of the text still has to pass every refusal, so a
  comment can only make the result more conservative.

### Why each BLOCKER is now structural

- BLOCKER 1 (escaped `#`): each of its shapes contains an unquoted `;`.
- BLOCKER 2 (`$_`): each shape is compound and contains `$`.
- BLOCKER 3 (`trap`, `BASH_ALIASES`): each shape is compound, or contains a
  line break.
- Minor (Python whitespace): the head regex accepts only `[ \t]`, and the
  name must be followed by a space or tab.

### For the re-reviewer

- The cost is deliberate. Any compound command that contains an `echo`
  naming a guarded command is denied, exactly as on main, including
  `echo x; echo 'git merge y'`.
- Newlines inside quotes, globs, `~`, braces, `!`, `2>&1` and
  `printf --` are also refused, even where harmless.
- Outside the predicate's reach: a function or alias named `echo` that
  the user's own shell environment defines before the command runs (for
  example, an exported `BASH_FUNC_echo%%`). No command-text guard can see
  that, and main's guards make the same assumption about `git` and `cd`.
