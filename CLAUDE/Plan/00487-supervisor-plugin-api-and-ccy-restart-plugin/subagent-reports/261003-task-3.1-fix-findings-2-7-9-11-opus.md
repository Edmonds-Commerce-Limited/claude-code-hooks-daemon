## Finding 2: the relaunch is now non-interactive

The fix has three layers.

1. **The resolved choices travel in argv.** `ccy_restart_choice_args` emits:

   - `--token <the token FILE the session used>`. This is a path, never the token value. A path also avoids the name glob picking an older, expired file.
   - Each key as `--ssh-key <path>`, or `--ssh-agent` for the sentinel. With no keys it emits `--no-ssh`.
   - `--github-443` when 443 mode was on.
   - `--network <the network it joined>` or `--no-network`.

   `ccy_restart_relaunch_args` now removes these launch-choice flags from the original argv, but only before `--`. Choices made at a prompt therefore win over flags that were typed. A restart of a restart reproduces the same argv; this is tested.

2. **A restart marker.** The handler exports `CCY_RESTART_RELAUNCH=<session id>`. `ccy_restart_marker_take` reads it early in the launcher, validates it as a UUID and unsets it. On a restart, stdin is `/dev/null` from that point until just before `container_cmd run`. Any prompt not accounted for therefore gets EOF and cannot wait. A structural test asserts that all 19 `read -rp` prompts on the launcher's launch path sit inside that window.

3. **Explicit decisions per prompt.** Prompts with exactly one safe answer take it. The others refuse through `ccy_restart_refuse`, which exits non-zero, gives the reason on stderr and prints `ccy --resume <id>`. Restore and restart share a `CCY_UNATTENDED_LAUNCH` flag, which feeds `ccy_restore_passphrase_take`, the zombie-container check and the sibling-container check.

## Finding 7: restart history

The history now lives in `CCY_RESTART_HISTORY_DIR="$HOME/.cache/claude-yolo-restart-history"`, one file per project hash. The handler creates it with `mkdir -p` immediately before the budget is taken, and a failure there refuses the restart. Tests cover:

- the directory is created when absent;
- nothing is written under the update-check cache;
- the handler text no longer mentions `VERSION_CHECK_CACHE/restart-history`;
- no `rm -rf` targets the new directory;
- an uncreatable directory refuses the restart.

## Findings 9 and 11

- **9.** The order is now: the stale-request discard, then the deadline comment with `ccy_lifecycle_finalize`, then the whole auto-compact comment block (including its "`${VAR:-default}`" paragraph), then the "`set -e` would turn…" comment directly above `container_rc=0` / `container_cmd run`.
- **11.** Each builder's process-substitution status is now checked with `wait "$!"`, which works on bash 5.3 here. A non-zero status or an empty result refuses the restart. Both builders run before the budget and the image update, so a bad argv spends nothing.

## Changelog lines (user-visible behaviour changes)

- A `--max-age` restart now relaunches with the token file, SSH keys (or `--ssh-agent` / `--no-ssh`), GitHub-443 mode and project network that the session actually ran with, including choices made at prompts. The relaunch asks nothing.
- An unattended restart stops with an error and the manual `ccy --resume <id>` command, instead of waiting at a prompt, in three cases: an SSH key that needs a passphrase (unless a server restore's passphrase file is in force; use `--ssh-agent` or a key without a passphrase for unattended restarts), an expired token, or a token that fails validation. The key check runs before the restart budget or an image update is spent.
- On a restart, ccy keeps old `.claude/ccy/sessions` dirs without asking. It also leaves zombie containers, starts alongside sibling containers, rejoins its network without offering to start compose services, and skips network detection when the session had no project network. It prints a banner naming the session and the manual resume command.
- The restart budget's history moved to `~/.cache/claude-yolo-restart-history/`, so `--rebuild` and version rebuilds no longer reset the crash-loop bound. Counts start fresh once.
- Before relaunching, the launcher removes its staged SSH key copies and temp config. Previously the exec left them behind.
