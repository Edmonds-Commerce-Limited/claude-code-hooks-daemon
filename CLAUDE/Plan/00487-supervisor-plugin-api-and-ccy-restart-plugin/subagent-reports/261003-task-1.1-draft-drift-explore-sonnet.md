- **Worker restart path:** VERIFIED. `PolicyWorker.restart()` (S:6484) is called from `reload_if_stale` (S:6473) and from `_make_worker_decider._decide` (S:7269-7313). `WorkerCrashGuard` (S:6522) gates respawn after a death.
- **`--disable-plugin` feasibility:** FEASIBLE but not wired. `start()` builds the worker argv as `[python, self, "--worker"]` plus an optional `--arm` (S:6396-6398). Adding `--disable-plugin X` there is trivial. `main()` checks `_WORKER_FLAG` at S:7196 and passes only `dry_run` to `run_worker`, so the flags must be parsed at S:7203. `_parse_supervisor_flags` (S:7069) is only called on the host path.
- **Spawn:** VERIFIED. `pty.fork()` is at S:6862, with `os.execvp(argv[0], argv)` in the child at S:6868 and `os._exit(127)` after it. Spawn happens exactly once. `waitpid` is at S:7049 and the exit code via `_exit_code_from_status` at S:7050. There is no respawn path.
- **Flags:** VERIFIED. Only `--dry-run`, `--arm` and `--log` exist (S:7080-7101). An unknown flag is an argparse error. `_USAGE` (S:273) will need updating.
- **`supervisor-status.json`:** VERIFIED. `write_supervisor_status` (S:1860) writes only `version`, `source_hash`, `pid` and `started_at`, and is called once at S:7236. It has no plugin list. The signature is keyword-only, and the daemon reads it, so adding a `plugins` key must stay backward-compatible.

   - Host-side load failures belong in `main()` after S:7229.
   - `PolicyWorker.__init__` (S:6354) and `start()` (S:6396) get the disabled set and the `--plugin` argv. The `_make_policy_worker` call at S:7248 and the `PolicyWorker` construction at S:7263 are where the flags are passed.

   - Add a new block at the end of the `decide_once` cascade, after the session-actions branch (S:5900) and before S:5905. Use the same gate as its siblings: `payload is None and evaluation.decision is NOOP and signal_path is None and machine.state is MONITOR`. ## Caveats

- The draft's phrase "ranked with the operator signal (after compact/continue)" is correct (S:5337-5340).
- `decision.log` and the status files live in different directories (see above). Check which one the audit lines should target.
- The `from_json` default-tolerance pattern (S:6180-6195) means a new `TickOutcome` field is hot-reload-safe in the worker. It is not safe on the host, which needs a session restart. `CcySupervisor.md` documents this hot-reload contract.
