# QA Review: fedora-desktop `feature/ccy-hooks-daemon-plugin` (3597b29e..d9488a15 + working tree)

Reviewer: fedora-desktop `qa-reviewer` role (opus), read-only. Clone:
`untracked/work/fedora-desktop`. Scope: three commits (ccy 3.74.0, 3.75.0, the mypy fix) and
the uncommitted semgrep fix in `scripts/test-ccy-restart-request.bash:214`.

**Verdict**: BLOCK

The branch as committed would break every ccy launch on any host that runs the play (finding 1).
After that is fixed, the restart path still stalls at an interactive prompt for most real
launches (finding 2). That defeats the feature's purpose, which is an unattended restart at
an idle point.

---

### Blocking

1. **The play never deploys the two new libraries, but the launcher sources them unconditionally.**
   `playbooks/imports/play-claude-yolo.yml:373-390`
   The "Install Shared Helper Libraries" task copies an explicit list of 9 files.
   `restart-request.bash` and `session-lifecycle.bash` are not in it. The launcher sources both
   (`files/var/local/claude-yolo/claude-yolo:66-69`) and lists them in `CCY_LIBS` (line 27). It
   then calls `ccy_lifecycle_validate_options` on every launch (line 259). After the play runs,
   `/var/local/claude-yolo/claude-yolo` is the new launcher sitting next to the old lib set, so
   every `ccy` invocation fails, including plain `ccy` with no new option. This breaks all users.
   The tests miss it because they source the libs from the repo tree. `test-ccy-lifecycle.bash:409`
   asserts that the playbook copies the *plugin*, but nothing asserts that it copies the *libs*.
   This is AgentNotes "the seam between two tested components".
   **Fix:** add both files to the loop at lines 382-390. Then add a test that asserts every entry
   in `CCY_LIBS` (the launcher's own list) appears in that loop. Put it in
   `test-ccy-lifecycle.bash` or a small dedicated gate, so the next new lib cannot repeat this.

### Should fix

2. **A restart relaunch stops at interactive prompts, so an unattended max-age restart hangs.**
   `files/var/local/claude-yolo/claude-yolo:3343` (the `exec`) and `:1014-1049`
   `ccy_handle_restart_exit` re-execs the launcher with the *original* argv plus
   `--resume <id>`. Take the common launch `ccy --max-age 3d` with no `--token`, `--ssh-key` or
   `--network` given. The relaunch meets the quick-launch condition at line 1014 and blocks on
   `read -rp "$CCY_PROMPT_QUICK_LAUNCH "` at line 1047. Only `SESSION_RESTORE` skips that prompt
   (line 1043), and the relaunch never sets it. The same happens with interactive token, network
   or ssh-key selection. It also happens with an ssh-key passphrase prompt, and with the
   existing-project-containers prompt when a second container of the project is running
   (`check_project_containers_startup`, line 1503). The changelog claims the relaunch keeps "the
   token, keys and network" (`docs/ccy-changelog.md:53`). That is only true when they were passed
   as flags. `OWNER-LIVE-TEST.md` has no step that exercises this.
   **Fix:** relaunch non-interactively. Choose one of these:
   (a) append the *resolved* choices (`--token "$SPECIFIED_TOKEN"`, each `--ssh-key`, `--network`
   or `--no-network`) to the relaunch argv; or
   (b) pass a restart marker that the launcher treats like `SESSION_RESTORE` for the
   one-safe-answer prompts. That reuses `ccy_restore_passphrase_take` for keys, and refuses
   loudly where no safe answer exists.
   Add a test that runs the relaunch with stdin closed. Add a live-test step: launch with
   `--max-age 30m` and no other flags, and confirm the session comes back unattended.

3. **`--max-age`, `--run-for` and `--until` kill the launch on any project whose supervisor predates the plugin API, with an argparse error instead of the documented message.**
   `files/var/local/claude-yolo/entrypoint.sh:412-427`
   The entrypoint checks that the wrapper names `claude-supervise.py` and ends in `--`. It does
   not check that the deployed supervisor understands `--plugin`. The released supervisor in this
   very clone (`.claude/ccy/claude-supervise.py:6823-6856`) parses strictly with
   `parser.parse_args`. On every project not on unreleased hooks-daemon main, `--plugin` therefore
   becomes "unrecognized arguments" and the container exits 2. The plugin API is not released yet
   (HANDOVER step 3), so today that is every project except hooks-daemon itself.
   **Fix:** in `ccy_lifecycle_extend_wrapper`, probe the supervisor before adding the flag, for
   example with `grep -q -- '--plugin NAME=WORKER.PY' /workspace/.claude/ccy/claude-supervise.py`,
   which matches the usage text at supervisor line 290. When the probe fails, fail with "this
   project's hooks daemon is too old for --max-age/--run-for/--until; upgrade it". Add a case to
   `test-ccy-lifecycle.bash`.

4. **The plugin's state file is per project, not per container, so two concurrent sessions in one project reset each other's age clock.**
   `files/var/local/claude-yolo/supervisor-plugins/ccy_lifecycle.py:1323-1340` (`_state_path`, `_load_or_create_state`)
   The supervisor's plugin `state_dir` is `/workspace/.claude/ccy/state/plugins/ccy-lifecycle/`.
   Every container of the project shares it (supervisor `_ccy_state_dir`, `claude-supervise.py:3719-3731`).
   ccy supports several containers per project (`get_next_container_name`, `lib/common.bash:943`).
   Session B's `on_start` overwrites `lifecycle.json` with launch id B. On A's next worker start
   (any hot reload or worker respawn), A reads launch B, treats itself as "a new container" and
   resets `started_at` to now. A max-age session sharing its project with another session may
   therefore never restart. A's `_save_state` also clobbers B's state in turn.
   **Fix:** key the state file by launch id (`lifecycle-<launch_id>.json`, which is safe because
   `_LAUNCH_ID` is validated). Keep the "deadline already announced" carry-over in a separate file
   keyed by the deadline epoch. Prune stale files on start. Add a test with two halves that use
   different launch ids against one `state_dir`, interleaved with a reload.

5. **The image's staleness check hashes only the Dockerfile, while the image now bakes a plugin whose edits nothing forces a rebuild for.**
   `files/var/local/claude-yolo/lib/common.bash:829,912`; `scripts/git-hooks/pre-commit:123-124`; `files/var/local/claude-yolo/Dockerfile:137-142`
   The plugin's only route to a rebuilt image is a manual `claude-yolo-version` bump. The
   pre-commit hook enforces `CCY_VERSION` for the launcher and `lib/`, but nothing enforces the
   container version for `Dockerfile`, `entrypoint.sh` or now `supervisor-plugins/`. A future
   plugin edit without a bump would ship a stale plugin with no error. This is the "check names
   one file by path" pattern from AgentNotes (Plan 00081). The entrypoint gap already existed;
   this branch widens it.
   **Fix:** either include `supervisor-plugins/` (and `entrypoint.sh`) in the
   `claude-yolo-dockerfile-hash` input, or extend `scripts/git-hooks/pre-commit` so that a staged
   change under `Dockerfile`, `entrypoint.sh` or `supervisor-plugins/` requires the LABEL and
   `REQUIRED_CONTAINER_VERSION` to move together.

6. **The changelog says a project with no supervisor fails "before any prompt", but the refusal only happens inside the container.**
   `docs/ccy-changelog.md:34-36`; `docs/ccy.md:110-111`; `files/var/local/claude-yolo/entrypoint.sh:437-441`
   `ccy_lifecycle_validate_options` only refuses `--no-supervise`. The "no supervisor" check is
   the entrypoint's `exit 1`, which runs after every host prompt and the container start.
   **Fix:** before the prompts, check on the host for `.claude/ccy/claude-supervise.py` (and do the
   finding 3 probe there too) when any lifecycle option is set. Or correct both docs to say the
   check happens at container start.

7. **The restart budget lives in a cache directory that the launcher deliberately wipes.**
   `files/var/local/claude-yolo/claude-yolo:3339` vs `:1687,1698,1708,1732`
   The history file sits in `$VERSION_CHECK_CACHE`. The launcher `rm -rf`s that directory on
   every `--rebuild` and on every version-mismatch rebuild. That resets the crash-loop bound and
   puts a safety counter in a directory whose contract is "disposable".
   **Fix:** move it to its own directory, for example `$HOME/.cache/claude-yolo-restart-history/`.
   Create it with `mkdir -p` before `ccy_restart_budget_take`. Today the handler relies on line
   1623 having created the cache directory earlier in the same run.

8. **The plugin tests run against a hand-written fake API rather than the supervisor's real harness, and the plugin documents a supervisor behaviour that is not true.**
   `tests/helpers/ccy_lifecycle/test_plugin.py:2240-2258`; `ccy_lifecycle.py:1120-1121`; commit d9488a15 message
   The supervisor ships `PluginTestHarness` (`claude-supervise.py:4335-4406`). It loads a plugin
   through the real loader, with the same vetting, API-major check and budgeted calls. The fake
   matches today: `Notify(kind, minutes)`, `ExitForRestart(reason)`, `audit`, `state_dir`,
   `tick.now`, all checked. But nothing will notice drift.
   The `Config` docstring and the commit message both say "the supervisor may import this file
   without registering it in sys.modules". The real loader does register it
   (`claude-supervise.py:4193`). Only the test's own `load_plugin_module` (test_plugin.py:2216)
   skips registration.
   **Fix:** reword the docstring to state the actual constraint (the test loader). When a
   supervisor with the plugin API is present (`.claude/ccy/claude-supervise.py` exposing
   `PluginTestHarness`), add one contract test through it, and skip with a printed reason when it
   is absent. The skip must be visible, not silent.

### Contract check (HANDOVER "The contract between the two sides")

- Wrapper line: conforms. The plugin flag is added only when a feature is set, and the default
  line is byte-identical (tested). It fails on old supervisors (finding 3).
- Worker hook: conforms. `on_start` and `on_idle` return `Notify("restart-soon", 1..240)`,
  `Notify("deadline-reached")`, `ExitForRestart(reason ≤120, printable)` or `None`. The plugin
  supplies no chat text. `PLUGIN_API = 1`, `name == "ccy-lifecycle"` (matches the
  `--plugin ccy-lifecycle=` name), `version` is a str. The file and directory are root-owned with
  modes 644 and 755, which passes `check_plugin_file`.
- Exit for restart and launcher: conforms. Status 75 plus a fresh file (≤300 s, while the
  supervisor's `requested_at` is set when `/exit` is typed, with a ≤30 s wait) leads to consume,
  `update_claude_inplace`, then `--resume`. The budget is 3 per hour per project, overridable.
  No file, or a malformed one, means an ordinary exit with a stderr note, and a malformed file is
  discarded. `restarted.json` is untouched (tested). One difference: the launcher accepts only
  UUID session ids, while the supervisor permits `[A-Za-z0-9][A-Za-z0-9_-]{0,127}`. A non-UUID id
  would be refused as "not a restart". That is safe, and Claude Code ids are UUIDs.
- RESTARTED notice: supervisor-side only, and the launcher leaves the marker alone.
