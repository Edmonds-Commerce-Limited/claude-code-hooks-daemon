# Plan 00487 — Journal 26-10-03

_Scaffolded by `mkplan.bash`; timestamps in this file are UTC._

> **Append-only activity log** for plan 00487. One file per day
> (`00487-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM, ONLY with
> `mkplan.bash --journal <plan-number> <category> <body-file>` (it stamps the
> real UTC time; a hand-written entry is denied); NEVER edit earlier entries
> (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff` | `correction`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - A `correction` corrects an earlier entry without touching it. Its `REF`
>   (`--ref`, required) names that entry: `HH:MM` in this file, or
>   `YY-MM-DD/HH:MM` in an earlier one. An entry a correction names in this
>   file no longer counts for time order, so a future-dated stamp can be
>   corrected at the honest time.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 12:20 · decision · —   — Phase 1 review fixes and Task 1.3c

Phase 1 review fixes and Task 1.3c are built, test first, in `.claude/ccy/claude-supervise.py`.

The opus review (CHANGES REQUIRED) found five defects, all fixed:

1. A plugin `print()` could corrupt the worker reply channel and crash the PTY host. The worker now dups the real stdin and stdout to private streams and points fd 0 at `/dev/null` and fd 1 and `sys.stdout` at the worker error log before any plugin loads (`_isolate_worker_channels`). The host's reply decode treats any exception as a bad reply.
2. The in-process fallback imported and ran plugins in the host. `PluginHost.in_process_runtime` is gone; the fallback runs the built-in families only and plugins resume when a worker answers.
3. An abandoned exit-for-restart was re-requested every 30 seconds. There is now a 600 s cooldown and a cap of 3 abandoned attempts per plugin, after which the plugin is disabled through the uniform failure path (new closed kind `exit-stuck`, worker restarted without it, one fixed-template notice).
4. The exit reason is now validated inside the budgeted thread and must be a plain `str`.
5. Host-side plugin setup and handling are contained: a flag that fails vetting skips only that plugin, `_make_plugin_host` never raises, a failing worker-argv provider starts the worker without plugins, and the first unexpected exception in the PTY loop's plugin handling switches that handling off for the process.

Task 1.3c adds `Notify(kind, minutes=None)` (kinds `RESTART_SOON` with 1 to 240 minutes, `DEADLINE_REACHED`) as an `on_idle` result. The supervisor renders the line from its own templates, types it at the idle choke point after the plugin-failure notice, and rate-limits it per kind (600 s and 1800 s). The RESTARTED notice uses a separate marker `.claude/ccy/state/restarted.json`, written at exit-for-restart and consumed once by the supervisor that resumes that session. The launcher must leave it in place when it removes `restart-request.json`.

Choice the brief left open: the `exit-stuck` notice is armed and shown on the status line at once, but its typed line waits behind the abandoned `/exit` own line like every own-line family. Version skew was re-tested in both directions against `main` as a real test, not a probe.
