## 10:44 · decision · P2 — armed-detection predicate (delegated map)

Explore mapped the supervisor status-file contract. Material findings:

- Status file is `untracked/supervise/supervisor-status.json` — FIXED name,
  GLOBAL (not per-session, not per-host), schema `{version, source_hash, pid,
  started_at}`. Written ONCE at launch, unlinked on clean exit. **No `armed`
  field.**
- Daemon reader `ccy_supervisor_integrity` decides live via `_pid_alive`
  (`os.kill(pid,0)`) + source_hash currency. No mtime/age freshness check.
- Consequence: a handler CANNOT confirm "armed vs dry-run" nor "belongs to THIS
  session" from the status file alone.

**Decision (Technical Decision 3): predicate = config-armed AND pid-alive AND
source-current.** `config-armed` = ccy.env `CCY_CLAUDE_WRAPPER` references
`claude-supervise.py --arm` (the existing `_is_armed` check). Because the launch
flag is fixed by that config, a live supervisor in a config-armed project IS
armed — this closes the dry-run hole the status file cannot. Residual edge:
shared-repo multi-session where MY session is unsupervised but another's
supervisor wrote the status file — my session-keyed signal then TTL-expires
unconsumed and that ONE reinforcement is lost (no hook fallback fired). Mild:
the authorisation was already established in full on turn 1, and the next
in-window prompt re-attempts. Documented, accepted.

**DRY**: the liveness pieces (`_pid_alive`, status read, source hash, untracked
dir) currently live inside `ccy_supervisor_integrity`. Extract to a shared util
so the new handler and that one share ONE implementation, rather than a second
copy.

## 10:44 · decision · P2 — supervisor channel ships OPT-IN (default off)

Ordering hazard: the daemon and supervisor release together, but a session's
RUNNING supervisor only updates when ccy is relaunched, not on daemon restart.
So if the handler routes reinforcements to `*.standing-auth-intent` signals the
running supervisor doesn't yet consume, those reinforcements are LOST (no hook
fallback) for supervised sessions — including the dogfood session itself. Fix:
gate the whole channel behind a config option `supervisor_channel_enabled`
(default False). Off → Phase 1 hook-context behaviour, zero change. On (opt-in,
after the supervisor supports it) → route to signal when `armed_supervisor_live`.
Mirrors the CCY_FLAG_COMPACT opt-in convention; lets Phase 2 land inert.

Plan: (2a) extract shared `utils/ccy_supervisor.py` liveness/arming helpers from
`ccy_supervisor_integrity` (DRY) + refactor that handler to use them; (2b) add
the default-off channel routing to `standing_authorisations` using the util.
Then Phase 3 = supervisor consumer, Phase 4 = config/docs (documents the opt-in).
