## 21:20 · decision · — — #50 stops on cost, not on evidence, so it needs a new question

This is why #50 did not become an implementation task despite passing Q2.

`1h` cache writes are billed at a higher rate, and `"1h"` is ignored while a
subscription is in overage. So the advice only pays off on workloads that reuse
the cache across gaps — exactly the qualifier in #50's own title. A blanket
SessionStart advisory to set `1h` would cost money for users whose subagents are
short and cache-cold, and this project cannot see which kind a user has.

Added **Q4**: may this project issue advice with a billing consequence when the
workload deciding whether it pays off is invisible from here? It generalises —
every future performance setting has this shape, so answering it once is worth
more than deciding #50 alone.

Worth recording that the evidence bar moved in BOTH directions this week: #46
failed Q2 on inference, #50 passes it cleanly, and the difference is simply
whether the vendor chose to self-document the key. That is not something this
project controls, which is itself an argument about how any such policy should
be written.
