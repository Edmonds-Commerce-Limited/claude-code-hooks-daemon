## 14:10 · finding · T2.1/T2.2 — identity-binding feasibility spike (live)

Ran a live `/proc` probe against the two-terminal setup (A=`7ef60468`,
B=`e7247afe`). Decisive results reshaping Decision 1:

- **H4 (open transcript fd) FAILS.** claude does NOT keep its
  `~/.claude/projects/<slug>/<session>.jsonl` transcript continuously open —
  the probe found NO process (in the whole container) holding ANY `.jsonl`
  open. So `/proc/<child>/fd → transcript → session_id` is not viable.
- **Env-var route WORKS.** `CLAUDE_CODE_SESSION_ID=7ef60468…` is present in
  claude's DESCENDANT process environs (e.g. pid 65776, a `bash -c` tool-call
  child of claude pid 76). Not in the claude process's OWN environ (set after
  exec), but reliably in its children while it works. Learnable + cacheable.
- **Containers are the clean separator.** Each `ccy` terminal is a SEPARATE
  podman container / PID namespace. The env scan surfaced ONLY A's own
  `7ef60468` — NOT B's `e7247afe` — even though B's sidecar AND B's transcript
  are BOTH visible on disk (shared bind-mounted `untracked/` and
  `~/.claude/projects/`). So process-env identity is container-local and
  excludes foreign sessions by construction; only the on-DISK shared surfaces
  leak across, which is exactly what the actuator must filter.

### Revised Decision 1 (identity source)

Bind the supervisor to its OWN session-id set by scanning its container's
processes for `CLAUDE_CODE_SESSION_ID` (its child claude's descendants),
CACHE the set (ids are stable per claude process), and FILTER the shared
sidecar/signal dir to act only on files whose `session_id` ∈ that set.
Fail-safe: until the main id is learned, act on NOTHING (never resume/compact
off an unidentified signal). Minimal viable fix for the reported bug =
filter `load_compaction_signal` to the learned id set (compaction is a
main-session event), which alone stops A resuming on B's compaction.

Open design fork for Phase 3 (needs a steer): (a) precise —
walk the direct-child claude's process subtree/descendants for the id set
(handles subagents that stay in-tree; misses ones reparented to pid 1);
vs (b) namespace-broad — treat EVERY `CLAUDE_CODE_SESSION_ID` found in the
container as "mine" (correct under one-container-per-terminal; over-broad
only if a deployment shares a PID namespace across terminals, e.g.
`--pid=host`). Leaning (b) with a documented caveat + `CLAUDE_HOOKS_*`
socket-isolation escape hatch for shared-namespace setups.
