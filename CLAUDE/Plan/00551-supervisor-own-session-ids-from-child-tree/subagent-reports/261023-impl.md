## How the child pid reaches the scan

- `resolve_own_session_ids(child_pid, proc_root)` reads `/proc/<n>/stat` for every numeric entry, parses the ppid
  with `_proc_stat_ppid` (fields taken after the LAST `)`, so a comm holding spaces or parentheses cannot forge a
  parent), walks the descendants of `child_pid`, and reads `environ` ONLY for tree members. Child gone or no `/proc`
  gives the empty set.
- `cached_own_session_ids(child_pid, ...)`: `None` returns the empty set with no scan and without exposing an earlier
  set; a new child pid clears the union cache and last-scan time first; the Plan 00182 throttle is unchanged.
- PTY host (`supervise()`): the `pid` from `pty.fork()` is passed to `cached_own_session_ids(pid)` in
  `_handle_plugin_outcome` and in the `_poll_once` in-process fallback, and sent to the worker on every tick as
  `TickFacts(child_pid=pid)` (serialised in `_facts_to_json` / `_facts_from_json`; absent key reads as None).
- Worker: the worker starts before the fork, so the pid cannot ride its argv. `main()` builds one `WorkerChildPid`,
  passes it to `run_worker(child=...)` (which calls `child.learn(facts.child_pid)` each tick and uses
  `cached_own_session_ids(child.pid)`), and gives `child.own_session_ids` to `_make_worker_plugin_runtime` as the
  plugins' `session_ids`. `PluginRuntime(session_ids=...)` is now required, so nothing can default back to an
  unscoped lookup.
- Hot-reload fallback (coordinator decision, kept): a host that predates `child_pid` sends none; the worker then
  takes the host's single other child (by stat ppid, excluding itself) as Claude, stored only on success. Ambiguous
  children, none, or a host of pid 1 give no pid and so the empty set. Never the broad scan. Documented in the
  `WorkerChildPid` docstring and in `CLAUDE/development/CcySupervisor.md` ("Own-session identity: the child's process
  tree").

## Fix-forward: hot-reload fallback

Branch `worktree-plan-00551-fallback`, base `e39f0ee88`, pushed. Commits: `a5c4db2c0` RED, `aa3373dbd` GREEN plus
docs, `ce81758ff` pyright fix in the new tests; this section's commit is the head.

- Cause: the live host (pid 2) has two other children, a pingbus seat (pid 70, no session id) and claude (pid 78,
  whose tool shells carry the id). The single-other-child fallback read that as ambiguous, so the own set was empty
  and the decision log stayed at `noop: no sidecar reading`.
- Fix (coordinator's rule): while no `child_pid` has been sent, `WorkerChildPid.own_session_ids()` uses
  `cached_host_session_ids(host, worker)`, which is backed by the new `resolve_host_session_ids`. That reads every
  descendant of the host (the worker's parent) except the worker's own subtree. The host's own environ is not read.
  A host of pid 1 or a host that has exited gives the empty set. A sent `child_pid` still wins, and `learn()` no
  longer derives a pid. The tree walk is shared (`_tree_session_ids`), and so is the union cache and throttle
  (`_cached_session_ids`, keyed by the child pid or by `(host, worker)`). `run_worker` now reads identity through
  `child.own_session_ids()`. The namespace-wide scan is never used.
- Tests: `TestLegacyHostFallback` in `tests/unit/supervise/test_session_identity.py` builds a fake `/proc` with the
  live shape (tini, host, pingbus without an id, claude whose grandchild bash carries the id, the worker with a
  child carrying another id, and a foreign claude under tini). It covers both the resolver and `run_worker` on a
  legacy line. The pid-1 host test is kept. The two old tests that relied on the single-child fallback were
  removed. `test_abandoned_input_flush.py` and `test_compaction_origin.py` now send `child_pid` in their ticks as
  a current host does, because otherwise they would fall through to the fallback and read the real `/proc`.
  `tests/unit/supervise/`: 1551 passed, 1 skipped.
