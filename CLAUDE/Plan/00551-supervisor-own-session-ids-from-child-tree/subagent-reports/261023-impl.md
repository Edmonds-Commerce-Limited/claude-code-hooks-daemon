## How the child pid reaches the scan

- `resolve_own_session_ids(child_pid, proc_root)` reads `/proc/<n>/stat` for every numeric entry, parses the ppid
  with `_proc_stat_ppid` (fields taken after the LAST `)`, so a comm holding spaces or parentheses cannot forge a
  parent), walks the descendants of `child_pid`, and reads `environ` ONLY for tree members. Child gone or no `/proc`
  gives the empty set.
- `cached_own_session_ids(child_pid, ...)`: `None` returns the empty set with no scan and without exposing an earlier
  set; a new child pid clears the union cache and last-scan time first; the Plan 00182 throttle is unchanged.
- PTY host (`supervise()`): the `pid` from `pty.fork()` is passed to `cached_own_session_ids(pid)` in
  `_handle_plugin_outcome` and in the `_poll_once` in-process fallback, and sent to the worker on every tick as
  `TickFacts(child_pid=pid)` (serialised in `_facts_to_json` / `_facts_from_json`; absent key reads as None).
- Worker: the worker starts before the fork, so the pid cannot ride its argv. `main()` builds one `WorkerChildPid`,
  passes it to `run_worker(child=...)` (which calls `child.learn(facts.child_pid)` each tick and uses
  `cached_own_session_ids(child.pid)`), and gives `child.own_session_ids` to `_make_worker_plugin_runtime` as the
  plugins' `session_ids`. `PluginRuntime(session_ids=...)` is now required, so nothing can default back to an
  unscoped lookup.
- Hot-reload fallback (coordinator decision, kept): a host that predates `child_pid` sends none; the worker then
  takes the host's single other child (by stat ppid, excluding itself) as Claude, stored only on success. Ambiguous
  children, none, or a host of pid 1 give no pid and so the empty set. Never the broad scan. Documented in the
  `WorkerChildPid` docstring and in `CLAUDE/development/CcySupervisor.md` ("Own-session identity: the child's process
  tree").
