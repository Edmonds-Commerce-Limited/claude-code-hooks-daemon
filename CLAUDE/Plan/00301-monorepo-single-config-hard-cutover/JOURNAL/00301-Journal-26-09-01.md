## 10:40 · finding · P6

Classified the six deferred consumers from 00301's original journal entry
(08:25 above). `british_english` — the one the coordinator's brief suspected
was PROJECT-level — turned out to be REPO-level BY DESIGN: attempted a
per-file rewiring via `resolve_layout`/`layout_for` first (TDD test written,
implementation added), but the new test
`test_declared_project_without_own_layout_does_not_inherit_the_roots` FAILED
because `ProjectLayout.for_project` always sources
`agent_docs_dir`/`human_docs_dir` from the ROOT project's `doc_axes` —
`LayoutConfig` has no per-project override for those two fields at all (by
Plan 00300's own explicit design: "Sibling truths that DO already have a
home — doc tree names ... deliberately NOT duplicated here"). So
`layout_for(file)` returns the SAME doc-tree names for every file in the
repository regardless of which project it resolves to; the rewiring was a
no-op that only LOOKED project-aware, and the second test correctly caught
it returning `True` where it should have been `False` since the resolved
layout was never actually per-project. Reverted the rewiring, declared
`british_english.workspace_scope = REPO` instead, and documented the
rationale as a worked example in WorkspaceResolution.md's new section (the
axis is about the CONCERN, not about whether the handler processes one file
at a time).

`worktree_file_copy` (the other suspect) WAS genuinely PROJECT-level, and
unlike `british_english` its underlying truths (`source_dirs`/`test_dirs`/
`config_dirs`) genuinely differ per declared project. But it judges a Bash
COMMAND that can name paths under any two declared projects, not a single
file with one owning project — so `resolve_layout`'s per-file shape doesn't
fit either. Added `_all_main_repo_code_dirs()`, aggregating
`main_repo_code_dirs()` across every project via
`self._project_registry.iter_layouts()` (falling back to the single root
`_project_layout` when no registry is injected, mirroring the existing
`resolve_layout` fallback convention). New test
`test_matches_honours_a_declared_projects_own_source_dir` pins a
sub-project's own `layout.source_dirs` being protected even though the
command never resolves to one "owning" project.

`goal_injection`, `recovery_cron_advisor`, `plan_workflow`, `docs_qa_sweep`
confirmed correctly REPO-level (all key off `plan_dir`/the docs corpus as a
whole, both repository-singular truths) and left unrewired — closing
00301's "Deliberately NOT rewired in this pass" caveat with a decision on
each, not just a deferral.
