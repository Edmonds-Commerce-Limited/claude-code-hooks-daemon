## Design notes

- **Standalone script, not a rule inside `check_doc_truth.py`.** That
  script's fixture tests run against trees with no daemon config, and
  `generate-docs` cannot run there. A drift rule inside it would either break
  those tests or skip silently.
- **Regeneration goes through the real CLI**: `sys.executable -m claude_code_hooks_daemon.daemon.cli generate-docs --project-root ROOT --output <TemporaryDirectory>`. PYTHONPATH is pinned to this checkout's
  `src/`, so the comparison is against the generator the change ships, and the
  config, plugins and project-handler loading are never reimplemented. It
  takes about 0.8s.
- **Marker exclusion** uses `utils/deployed_version.VERSION_MARKER_RE`, the
  same parser behind `upgrade.sh`'s reader, rather than a restated pattern.
  The exclusion covers the whole marker line. That line also carries the
  environment-dependent `Regenerate: <cli path>` suffix, so excluding it is
  what lets fixture and CI output compare cleanly.
- **Fail-fast**: a missing committed doc, or a generator that exits non-zero,
  gives exit 2 with the reason on stderr, never a clean result. Tests:
  `TestOperationalFailures`.
- **Report denominator**: `summary.lines_checked`, which `llm_qa.py` renders
  as "(228 lines checked)".
