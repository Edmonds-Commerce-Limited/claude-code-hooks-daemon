# Playbook harness probes #350, #351 and #125: diagnosis and fix

**Result**: the harness (`tests/acceptance/test_playbook_harness.py`) now fails only on #125, against the restarted worktree daemon: 1 failed, 4 passed. Before the fix, 3 of 259 probes failed. #125 is not a regression on this branch. It is ledgered as N677 (filed as N673, renumbered when main took that ID).

## #350 and #351 (ConflictMarkerCommitGateHandler, expected ALLOW): a regression on this branch, now fixed

- **The rule that denied.** R-SECRET-READ by the `search` route. The message carried the `_SEARCH_REMEDY` text ("This recursive search would read a protected file under its roots"), and the matched glob was the private-key default. It was NOT the "moves into more than 16 directories" overflow cause: the earlier theory named the wrong rule.

- **How the deny happens.**

  1. `cd -` is a move the guard cannot place, so `_SearchCwds.indeterminate()` adds every directory link from the link scan to `tracker.computed_links`.
  2. The next segment's head is `git`, and `_reads_files` returns True for it. It calls `_is_search`, which is true for ANY `git` head. `_is_search` is a dispatch gate: it says "head is git, now look for `grep`". It is not a test for "reads a tree".
  3. So every directory link is yielded as a `Read` root, and one of them reaches a protected-named dummy.

- **Why this is the branch's code.** Main has no `computed_links` or `unscanned` branches, and main allows every one of these commands.

- **Directory links now present.** The count comes from the verified link index (not from `find`): 12 holding directories, 7 directory links, 24 links in total. The packing was incomplete. Three scratch fixtures still hold directory links, and they are what reached the dummy:

  - `untracked/scratch/p623/bigl/proj/w000/zz/latedir`
  - `untracked/scratch/p623/cap513/proj/w000/zz/latedir`
  - `untracked/scratch/614-r6/deepfx/proj/q/sub/a/dl`

  These were deliberately left in place as a live reproduction.

- **The fix** is in `src/claude_code_hooks_daemon/utils/recursive_search.py`. A new function, `_git_reads_no_tree`, is used only by `_reads_files`; `_is_search` and its dispatch are unchanged. Because `_reads_files` drives all three fail-closed branches (`unscanned`, `computed_links` and `lost`), the narrowing applies to each of them.

  - **No longer counted as a reader:** a literal `git commit` or `git status`, with no global option other than `--no-pager`/`-P`, and no diff-printing option.
  - **Still a reader:**
    - a subcommand given by expansion
    - `-c` or `--config-env` (these can define an alias or move the work tree)
    - any other global option
    - a diff-printing option: `-v`, `-p`, `--verbose`, `--patch`, `--interactive`, or any prefix of those long options
  - **Why it is safe.** `git commit` and `git status` read the index and lstat the work tree. They never follow a link and never recurse through one, and without a diff option they print no file content. A file operand (`-F`, a pathspec) is a word, and the mention scan still judges words through every link from every effective cwd; this change does not touch that.

- **No loosening against main.** I compared in-process, main's code against the branch's, on a tmp project holding a directory link to a protected dummy:

  - `cd ~- && git status`, `cd ~- && git commit -m x`, `cd - && git status` and `cd - && git commit -m x -- p` are allowed on both.
  - `cd ~- && git log -p` is allowed on main and denied on the branch.

## What is still open

That is a separate fail-closed, and this fix does not change it. The brief scoped the fix to the complete-scan case. The test documents the deny.

## #125 (WorktreeFileCopyHandler): not a regression on this branch (N677)

- **The deny observed:** R-WRITE-OUTSIDE-PROJECT-ROOT, from `project_containment` at priority 14, which runs before `worktree_file_copy` at 15.
- **The cause:** the probe's event cwd is `$MAIN_CHECKOUT_DIR` (`/workspace`), while a worktree daemon's project root is the worktree. The rsync target `src/` therefore resolves to `/workspace/src`, which is outside that root.
- **Main's code decides it the same way.** Run in-process with the worktree as the project root, main's `project_containment` matches the #125 event exactly as the branch's does, and neither matches #124.
- **Against main's own `/workspace` daemon, all three probes pass.** There the cwd is the project root, so containment never fires.
- **Ledgered as N677** in `CLAUDE/Plan/00474-niggles-ledger-seventeen/NIGGLES.md`. The fix belongs to the harness or the probe, not to either handler.
