## 01:47 · finding · — — how this plan was found, and what nearly hid it

Not filed from a review. Plan 00346 put CI on the locked toolchain, which
turned the `Format (black)` job green and left `Tests + coverage` as the only
remaining failure on `main` — and only then was that failure legible as a
separate defect rather than part of the noise.

The originating instance is fixed at `f17fabcd`. What made it worth a plan
rather than a one-line fix was measuring the blast radius afterwards: 73 stat
calls under `handlers/`, of which ~12 judge a path the caller supplied.

**Three things about this were not obvious and are worth carrying forward.**

It never reproduces locally. This container runs as root, so mode bits do not
apply and every one of those paths stats fine. The suite passed 25/25 here
while CI was red. Any test written against real permissions is therefore
worthless — it must FORCE the error, which is what `f17fabcd` does.

It is not a crash. I initially recorded it as "takes the hook down", then
checked `chain.py:291` and found the chain catches it. That made the finding
WORSE, not better: with `strict_mode: false` — the client default — the
handler's guard just silently stops applying, so a DENY handler treats an
unreadable parent directory as an exemption. This repo runs `strict_mode: true`
and gets the opposite failure, a spurious block on legitimate work. Two
different wrong answers from one defect, split by config.

The fix's first draft was itself wrong, and the repo caught it. `except OSError:
destination_is_dir = False` failed `audit_error_hiding.py`: "assigns a fallback
value with no logging or re-raise — failure becomes indistinguishable from
success." Correct call. Without a record, "the guard decided this is not a
directory" and "the guard could not look" read identically to whoever is asking
why a policy did not fire. The warning log is load-bearing.

## 01:47 · decision · P3 — a gate, not twelve patches

## 02:05 · finding · T2.2 P1 — the classification falsified this plan's own Phase 1

Delegated the 73-site classification. It came back 14 caller-supplied / 59
daemon-controlled, none uncertain — and it broke the design I had just written.

**Phase 1 said "one canonical answer": treat an unstattable path as
not-a-directory, mirroring what pathlib does for the stat failures it already
ignores.** That is right for `_written_paths`, which is where I generalised it
from, and it is WRONG as a rule. `write_clobber_guard.matches()` reads:

```python
# Creating a new file destroys nothing.
if not Path(path).is_file():
    return False
```

A `False` fallback there means "not a file" means "nothing to destroy" — the
guard declines to fire and the clobber it exists to prevent is allowed. The
safe fallback is `True`. Verified by reading the function myself rather than
taking the report's word for it.

So a single canonical fallback is worse than none: it looks principled while
silently inverting a DENY guard at some sites. Phase 1 is rewritten to make the
predicate REQUIRE the caller to name the value, with no default, so the choice
is visible in review instead of inherited.

Three shapes now recorded, because the contrast is the whole point:

- **Inverted** — `write_clobber_guard.py:155`, above.
- **Naive-safe** — `comment_size.py:226`, where `False` genuinely is right: the
  consumer reads "no prior content" as growth, biasing toward the DENY.
- **No single safe boolean** — `plan_qa_edit.py:165` / `docs_qa_edit.py:140`
  feed `file_exists_before` to three consumers, and
  `plan_qa/checks/archive_immutability.py:30` tests `is not True`, so `False`
  AND `None` both disable it.

One correction to the report: it called `archive_immutability` a "DENY-class
immutability guard". It is `Level.ADVISE`, so the cost of a wrong fallback
there is a lost advisory, not a lost block. The mechanism claim was exact; the
severity label was not. Worth catching rather than propagating — a subagent's
conclusion is evidence, not testimony.

The pass also found **four caller-supplied sites my hand-curated list missed**:
`markdown_table_formatter.py:233` (the sibling of `:224`, which I had listed —
so I had read the right file and still missed the line beneath),
`github_auto_close_keywords.py:242`, `tdd_enforcement.py:358` and
`worktree_remove_handler.py:57`. Task 2.1 now converts from the traced list,
not from the eyeballed one.

## 02:20 · action · T1.1 T1.2 — the predicates, with the choice forced on the caller

`utils/path_predicates.py` + 43 tests. Shape:

```python
def path_is_file(path: str | Path, *, unreadable_means: _Fallback) -> bool | _Fallback:
```

Three decisions in that one line, each of which had an obvious wrong answer:

- **Keyword-only.** `path_is_file(p, True)` says nothing about what the `True`
  means; `unreadable_means=True` says all of it. The parameter name is the
  documentation, so it must be unavoidable at the call site.
- **No default.** This is the whole deliverable. A default would be one guess,
  made in one file, on behalf of 14 sites that provably disagree — and at
  `write_clobber_guard` it would silently exempt a DENY guard while looking
  principled.
- **`bool | _Fallback`, not `bool`.** `plan_qa_edit` feeds `file_exists_before`
  to a consumer testing `is not True`, so `None` has to survive as itself
  rather than collapsing into `False`.

The fallback covers ONLY what pathlib raises on. A missing path still answers
`False` through the normal return — widening to ENOENT would make every guard
read "not there" as "could not look", a louder lie than the one being fixed.
Tested explicitly rather than left to inference.

Vacuity guard earned its place again. The trap here is specific: a fallback
that happens to MATCH the path's real answer makes an unpatched predicate look
like a working one. So `TestTheFixtureIsNotVacuous` asserts the forced denial
really raises for all three predicates, and then asserts a fallback that
CONTRADICTS reality (a file that genuinely exists, asserted `False`).

`audit_error_hiding.py` clean. The shape that passes it is `logger.warning(...)`
followed by `return fallback` — two statements. Its `silent-fallback` and
`log-and-continue` rules both key on a single-statement handler body, so the
log is not decoration: drop it and the auditor fires.

Also verified: mypy clean, ruff clean, black clean.

## 02:55 · finding · T2.1 — the report's recommendation was wrong on the one site it reasoned hardest about

All 14 caller-supplied sites converted across three commits. The split came out
11 `False` / 1 `True` / 2 `None`, which is the plan's own prediction confirmed —
but the interesting part is where the classification report and I disagreed.

For `plan_qa_edit` / `docs_qa_edit` the report recommended biasing to `True`, so
that `archive_immutability` keeps firing. That is wrong, twice over:

1. **`archive_immutability` tests `is not True`, not `is False`.** Its author
   already decided uncertainty should not raise this advisory. Forcing `True`
   from the PRODUCER overrides a choice the CONSUMER made deliberately — and
   the consumer is the one that knows what the advisory means.
2. `True` sends `content_before = file_path.read_text(...)` straight into the
   same `PermissionError` one line later. Staying upright would then need a
   second untruth: content `None` while claiming the file exists.

`None` is what the daemon actually knows, and `CheckContext` has typed the field
`bool | None` all along. The report's MECHANISM was exact — three consumers,
three different readings — and its RECOMMENDATION did not follow from it. Same
lesson as the `archive_immutability` severity label yesterday: a subagent's
reasoning is evidence, its conclusion is not testimony.

Switching to `None` also lit up a branch that was safe while the value was a
boolean: `if not exists_before` is TRUE for `None`, so a path the daemon merely
could not read would have been recorded as a fresh plan-number ALLOCATION.
Narrowed to `is False`, with a test pinning that a genuinely-new file still
records one. That is the second time in this plan that a tri-state has broken a
truthiness test written when the value could only be two things.
