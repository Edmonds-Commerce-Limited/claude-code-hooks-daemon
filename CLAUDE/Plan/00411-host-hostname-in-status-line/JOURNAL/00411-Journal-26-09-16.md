## 10:44 · decision · — waiting for a desktop is a bad way to close a criterion

The third success criterion — "on a desktop host and under LXC, the real
hostname shows with no export needed" — was left unticked for a good reason:
it is covered by unit tests, and the lesson of the other two criteria was that
live behaviour had already surprised the tests once. Ticking it on a passing
test would have repeated exactly the mistake the plan learned from.

But the remedy on file was "wait until somebody is sitting at a desktop or an
LXC box", and that is a criterion with no owner and no date. It would have held
this plan open indefinitely while being nobody's task.

There is a real host available on every single push: `.github/workflows/qa.yml`
declares no `container:` key, so the job runs directly on the `ubuntu-latest`
runner VM. To `detect_container_runtime()` that is a bare host. **CI is the
desktop.** And it is better evidence than one person checking once, because it
re-verifies for ever rather than at a moment.

## 10:46 · action · — the criterion, written as an assertion

`tests/integration/test_host_hostname_on_a_real_host.py` pins three things on a
non-container machine, with rung 1 cleared by fixture so rung 2 is genuinely
what answers:

- the resolved name is `socket.gethostname()`;
- its source is `LOCAL` and `inferred` is False — an `/etc/hosts` hint winning
  here would be the WRONG rung answering, since rung 3's correctness depends on
  the host distribution while rung 2 cannot be wrong on a real host;
- an explicit hand-off still outranks it. That is the matched pair: without it,
  "rung 2 answers on a host" could be true because the ladder had quietly
  stopped consulting rung 1 at all.

It SKIPS inside a container, with the reason stated in the skip message, so it
is CI doing the verifying and not this session pretending to.

A test that only ever skips proves nothing, so the assertions were run here
against a forced bare-host detection before committing:

```
resolved   : HostName(name='75e26bf99362', source=<HostNameSource.LOCAL: 'local'>)
gethostname: '75e26bf99362'
ALL THREE ASSERTIONS HOLD on a simulated bare host
```

One assumption was wrong and caught by doing this rather than reasoning about
it: the first draft asserted `socket.gethostname().split(".")[0]`, on the guess
that the cleaner trimmed a domain. It does not — `_clean_host_name` strips
whitespace and REFUSES a bad name outright rather than editing it, precisely so
a filtered name is never displayed as though it were the machine's. The
assertion now compares against the name verbatim.
