Dissolves the DESIGN §1a live conflict: a project configuring

Notable behaviour-preservation details, found by TDD against the existing
191-test suite rather than assumed up front:

- The old hardcoded plan-subdirectory set was `("completed", "cancelled",
  "archive")`, all three unconditional regardless of config. The facade's
  `plan_archive_dirs` defaults to `("Completed",)` only —
  `plan_workflow.qa.cancelled_dir` defaults to `None` ("archive cancelled
  plans under completed_dir"), so a naive read would have silently BLOCKED
  the always-recognised `CLAUDE/Plan/Cancelled/` folder for every
  zero-config project. Fixed by keeping BOTH `"archive"` and `"cancelled"`
  as permanent legacy extras (`_LEGACY_PLAN_ARCHIVE_EXTRAS`), unioned onto
  the facade's dirs — caught by the pre-existing
  `test_matches_returns_false_for_cancelled_plan_directory` test failing
  before the fix.
- The plan-number validation is now checked BEFORE the agent-docs-tree
  branch (previously nested inside `if normalized.startswith("claude/")`),
  since `plan_dir` is not guaranteed to be nested under `agent_docs_dir` —
  a project can configure them independently. Zero-config default
  (`CLAUDE/Plan` under `CLAUDE`) is unaffected; added a test with a
  non-nested `plan_dir: "Plans"` to pin the general case.
- Daemon-repo-specific allowances
  (`src/claude_code_hooks_daemon/guides|skills/**.md`) stay hardcoded per
  the task brief — they describe the daemon's own shipped assets, not
  client project layout.
- `self._project_layout` defaults to `None` when a handler is constructed
  directly (as the existing unit tests do, bypassing the registry
  injection); added module-level fallback constants matching the Config
  defaults exactly (`CLAUDE`, `docs`, `CLAUDE/Plan`, `("Completed",)`) so
  behaviour is identical whether or not the facade was injected.
