Owner answered "fine" to "orange and 600 s as defaults?". Implemented on this branch, tests first (17 new or changed cases went RED, then GREEN):

- The idle-compaction gate is now the sidecar's `tier` at or above `CCY_IDLE_COMPACT_TIER` (default `orange`; `yellow`/`orange`/`red` allowed, anything else is `orange`). The tier is the daemon's own classification, so orange is 30% of a 1M window and 51% of a 200k one. An unknown sidecar tier never fires.
- `CCY_IDLE_COMPACT_PCT` is unset by default; when set it replaces the tier gate (back-compat for a project that pinned 30).
- Settle default 600 s (was 60).
- Idle defined precisely and tested negatively: every busy signal (screen footer, `work_idle`, not at the prompt, a non-empty input box, Claude Code's own status/sub-agent/task records) restarts the settle clock mid-settle. A pending standing-auth reminder, session-actions directive or cron-reconcile prompt now goes first (`_idle_compact_yields_to`); a capped reconcile no longer blocks.
- Mode default still `dry-run`: the owner's answer covered the tier and the settle period, not arming. Arming (`CCY_IDLE_COMPACT=on`) stays Task 3.1.
- Docs: `CLAUDE/development/CcySupervisor.md`, `.claude/ccy/ccy.env` comments, release note 004.
