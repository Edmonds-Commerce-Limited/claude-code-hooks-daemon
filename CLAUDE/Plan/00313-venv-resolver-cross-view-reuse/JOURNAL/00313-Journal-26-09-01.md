## 20:57 · finding · T1.3 — bash resolvers shell out to the SSOT, no separate fix needed

- `scripts/lib/resolve_venv.sh::_rv_pick_python` does glob
  `${daemon_dir}/untracked/venv-*/bin/python(3)` and take the first
  executable hit — but that scan only selects an INTERPRETER to invoke
  `paths.py resolve-venv` with, not the final resolved venv. The actual
  answer returned to every caller is `paths.py`'s stdout (`resolved` in
  `_rv_resolve_python_impl`), which is the now-fixed SSOT. Even a
  slug-mismatched venv's `bin/python` is safe to use here: `paths.py` only
  needs 3.11+ stdlib to run and compute its own (slug-aware) answer.
  `src/claude_code_hooks_daemon/skills/hooks-daemon/scripts/_resolve-venv.sh`
  sources this library directly (`resolve_venv_python "$DAEMON_DIR"`), so
  it inherits the fix transitively. No independent scan logic duplicates
  the defect in bash; no separate fix applied.
