## 11:55 · finding · — — the acceptance failures were a STALE DAEMON, not contention

A full QA run reported 18 errored tests, every one in `tests/acceptance/`, and I
had diagnosed it as my own tool calls contending with the suite — reasoning that
those tests drive the live daemon and every tool call is daemon traffic. I cited
the failing set "reshuffling" between runs as proof of flakiness.

That was wrong, and the run had said so in plain text:

```
⚠️  TOOL ERROR: Daemon source freshness check failed: STALE DAEMON: the running
daemon's loaded code (source_fingerprint 3f2bb76b7671) does not match the current
working tree (source_fingerprint ff3b69ba8ce5).
```

`tests/acceptance/test_daemon_source_freshness.py` exists precisely to catch
this and had errored among the 18. The N5 edit to `daemon/cli.py` was committed
without restarting, so every live-dispatch test graded the OLD code. The
"reshuffling" was me comparing a completed run against a partial one.

Correction recorded rather than quietly dropped: I stated a cause one step
beyond what I had observed — the same pattern already noted for N3.
