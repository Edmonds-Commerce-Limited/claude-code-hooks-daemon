**Real bug found and fixed along the way (not cosmetic)**: `DaemonController`'s
`config` constructor parameter is NEVER populated by the real daemon startup
path — `cli.py::_build_initialised_controller` always does
`DaemonController()` with no config, then threads individual config slices
into `initialise()` instead (`plugins_config`, `plan_workflow`,
`pseudo_events_config`, ...). This means `self._config.strict_mode` and
`self._config.enable_hello_world_handlers` are DEAD CODE in production today
— `daemon.strict_mode: true` in a real project's `hooks-daemon.yaml` is
silently ignored. Fixed this FOR verdict_log specifically (threaded
`verdict_log` through `initialise()` the same way, with a regression test —
`test_cli_verdict_log_wiring.py` — pinning that `_build_initialised_controller`
actually passes it). Did **not** fix the pre-existing `strict_mode` /
`enable_hello_world_handlers` gap — that's a real, separate latent bug outside
this plan's scope, flagged here rather than silently left, and NOT verified
against a live daemon (see below).
