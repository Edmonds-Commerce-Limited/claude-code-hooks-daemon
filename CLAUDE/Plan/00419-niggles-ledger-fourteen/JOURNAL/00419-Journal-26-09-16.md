## 10:20 · finding · T1.4 — docs QA hardcodes the plan tree, which is the cost the ruling predicted

The decision flagged "docs_qa must learn the plan directory and archive names
from plan_workflow config, which today it does not" as the build cost. It is
sharper than that: `docs_qa/corpus.py` carried the names as module constants
(`_PLAN_SUBDIR_NAME = "Plan"`, `_PLAN_COMPLETED_DIR_NAME = "Completed"`,
`_PLAN_CANCELLED_DIR_NAME = "Cancelled"`) and tested them positionally against
`rel_parts`. So this was already a live defect independent of N2: a project
that set `plan_workflow.directory` or renamed `qa.completed_dir` had its LIVE
plans excluded from the doc corpus and its real archive indexed — silently,
and in the direction that produces no error.

That made the plumbing decision easy. The plan tree's shape now travels WITH
`DocumentationPolicy`, exactly as `vendor_scopes` (Plan 00331) and
`exclude_paths` (Plan 00362) already do, and for the third time on the same
recorded argument: docs QA's scope judgement reads the POLICY, so a value
injected only onto the handler instance can never reach it.

## 10:35 · decision · T1.4 — who reports a relocated link, so that nobody reports it twice

The ruling says the live-`PLAN.md` signal "goes from a docs-QA advisory to a
plan-QA advisory with a better remediation — no one loses a signal". Taken
literally that leaves a gap, because plan QA's `tree_targets()` yields only
`PLAN.md`: a live supporting doc (`NIGGLES.md`) or a doc outside the plan tree
would be silenced by docs QA and picked up by nobody.

Settled by making docs QA yield NARROWLY rather than wholesale. A relocated
link is silent from an archived source (doctrine), silent from a `JOURNAL/`
day-file (append-only makes the repoint structurally impossible), silent from
a live `PLAN.md` (plan QA speaks, with the repointed path) — and reported at
ADVISE from everything else. No fact reaches two session-start advisories, and
no fact reaches none.

## 10:50 · thought · T1.4 — the live-PLAN.md advisory has nothing to say today, and that is fine

Zero of the 19 relocated links sit in a live `PLAN.md`, so `plan-link-resolves`
reports nothing on this tree right now. That is not evidence the check is
inert: the class it covers is created the moment a plan with outbound sibling
links is archived while its targets stay live, which is exactly what happened
on 00413 and will happen on 00419. Its unit tests pin the behaviour against
that shape directly.

The thing this check really buys is the sweep's credibility. `plan-qa --sweep`
reported `0 findings` over eight dead links, twice, because it was never
looking at links at all. It is looking now.
