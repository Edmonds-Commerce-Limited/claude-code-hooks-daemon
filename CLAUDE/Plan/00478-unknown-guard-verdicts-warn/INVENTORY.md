## Uncertain, and why

- **Row 16 (`write_protected_paths`).** The secret guard's accepted line was "a protected path literally in the input denies". Here the path is literally named, so the same line would keep it denying. But the unknown-verb deny (`_unknown_command_violation`) fires on a positively named path with an undecided action, and the `**`-glob and depth-bound branches deny on text that does not name the path. Needs an owner call on which of these count as positive.
- **Row 1 and row 3 (`destructive_git`).** `git branch -D` and `git push --delete` are positively recognised, and the ruling says a recognised dangerous action still denies. The deny here is on "could not prove it loses nothing". Treating these as UNKNOWN converts a large part of the guard. Needs an owner call. The substitution case (row 2) is clearly UNKNOWN.
- **Row 5 (evacuation).** Both the evacuating and the destroying step are positively present; only the link between them is unplaceable. Likely UNKNOWN, but it could be read as positive.
- **Rows 7, 14, 15.** Same shape: a positive-match rule ID reused for "could not place". Converting needs a separate advisory and log line, since the rule ID is also used by the real finding.
- **Rows 17, 18 (ESLint, post-tool-use).** Not a pre-write guard; the write has landed. The deny only forces a retry. Still a could-not-decide deny, so listed.
- **Row 12 and 13 test gap.** No test by name for the simulation-incomplete deny in `test_docs_qa_commit_gate.py` or `test_plan_qa_commit_gate.py`; a search by content, not name, may find one.
- **Misnamed test.** `test_conflict_marker_commit_gate.py::TestAGrepFailureIsReported::test_a_failing_grep_allows_with_a_visible_advisory` asserts `Decision.DENY`. Its name says allow.
- **Stale test name.** `test_secret_file_guard.py::test_an_unparseable_shebang_script_still_fails_closed` (`:2638`) asserts only `matches()`, which is also True for the advisory route, so it does not pin a deny.
- **Not examined (no conclusion either way).** `sed_blocker` (deny by the word `sed`), `pipe_blocker`, `curl_pipe_shell`, `root_recursion_guard`, `github_issue_assignment_guard` and `issue_filing_gate` (what happens when `gh` fails), `reference_repo_freshness` (R-REFERENCE-REPO-NOT-VERIFIED), `release_merge_freeze`, `merge_to_main_approval`, `plan_close_approval`, `markdown_organization` (`tests/unit/handlers/pre_tool_use/test_heredoc_grammar_chain.py:206` says it "fails closed on an unreadable body"), `plan_number_helper` (`tests/unit/handlers/pre_tool_use/test_plan_number_helper.py:1097` says an unenumerable brace list fails closed), `verification_result_gate`, `bash_safe_mode`, `worktree_file_copy`, `quarantine_artefact_read_guard`, `git_message_backtick`, `host_command_guard`, `subagent_worktree_write_guard`, the usage-pause and cron stop gates.
