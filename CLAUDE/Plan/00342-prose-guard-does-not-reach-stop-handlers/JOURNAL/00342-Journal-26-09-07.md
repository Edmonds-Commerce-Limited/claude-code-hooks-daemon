## 19:30 · finding · — — found by the bug happening, not by looking

Filed from Plan 00337 Phase 3, where the defect occurred in the change being
written. The first draft of `_declares_human_blocked` matched
`[awaiting-human]` anywhere in the stop text, so a stop message REPORTING the
feature armed cron suppression on a session that was not blocked:

```
STOPPING BECAUSE: Phase 3 is shipped — the `[awaiting-human]` token now arms
the marker, and QA is green.
```

That instance is fixed (anchored to the declaration position) and pinned. What
is not fixed is that nothing would have caught it.

The guard for this exact class exists — Plan 00228's
`test_handlers_do_not_match_prose.py` — and excludes Stop handlers by
construction, in its own words:

> Restricted to the PreToolUse package because the fixture is a Bash tool
> call. Handing that payload to a Stop handler asks it a question about an
> event it never receives, and the answer is meaningless — an early draft of
> this guard did exactly that and reported every Bash fixture as a failure of
> `AutoContinueStopHandler`.

That reasoning was correct when no Stop handler matched text to make a
decision. Plan 00298 gave it four phrases, Plan 00314 widened one, and Plan
00337 added a token — so the premise expired without anyone revisiting the
conclusion.

## 19:32 · thought · — — why this one fails quietly, which is why it is worth a plan

A prose false positive in a PreToolUse handler produces a wrong DENY: loud,
immediate, and the agent is told exactly what happened. The same defect here
produces the opposite — the marker arms, cron ticks are dropped before they
reach the model, and the only symptom is something NOT happening.

A session could lose its recovery net for a whole day (the marker's default
expiry) and the transcript would show nothing at all. That asymmetry is the
argument for extending the guard rather than relying on review.

## 19:34 · finding · P2 — the prose patterns have it too, and may not be fixable

The four `_HUMAN_BLOCKED_PATTERNS` phrases have the same weakness and always
have: a stop message quoting "blocked only on human input" — while explaining
this subsystem, say — arms the marker. Plan 00298 behaviour, not a regression,
and never tested in either direction.

But the token's fix may not transfer. Anchoring worked there because the
guidance already told the agent to put the token immediately after the prefix,
so anchoring cost nothing. The prose patterns were deliberately written to
match natural phrasing ANYWHERE in a stop reason, and Plan 00337's Non-Goals
forbid regressing wordings that work today. So Phase 2 opens with establishing
the intended rule, and Task 2.3 explicitly allows the answer "cannot be
narrowed without regressing" — the token exists precisely so the patterns can
stay frozen, and concluding they must also stay imprecise is a real result if
it is written down.
