## Key decisions

- **Terminality is decision-level.** `terminal` is kept, reduced to "once I
  have denied, skip the rest" — it cannot change the chain's decision.
  Deleting it would touch 125 constructors, the docs generator and the
  verdict-log schema for no semantic gain.
- **PermissionRequest opt-in is event-level** (`_ALLOW_IS_FINAL_EVENTS` in
  `core/router.py`), never a handler flag.
- **Attribution (Task 3.3)**: the FIRST restrictive handler owns both the
  reason shown and the `To disable:` footer. This changes Plan 00190 Task
  0.5's rule (a later terminal deny used to replace the shown reason); the
  affected test was re-pinned.
- **Collect-all does not short-circuit on deny**: measured 2.03 ms p50 /
  2.49 ms p95 on the worst four-deny path vs 0.34 ms short-circuited,
  against a ~100 ms budget (`MEASUREMENTS.md`).
- **Bounds (Task 3.4)**: lead deny uncut; 4 extra denies at 1500 chars;
  8 advisory rows at 160 chars; overflow handlers still named.
- **Side effects (Phase 2)**: rollback journal after the decision rather
  than a two-phase handler split; the hook fires in every mode, so the
  pre-existing default-mode exposure is closed too. `lsp_enforcement`'s
  block-once is fixed at the controller (per-handler verdict recording).

## Behaviour changes worth a reviewer's eye

- Stop chain: a handler registered above `auto_continue_stop` now RUNS on
  an allowed stop (it used to be dead on every stop). Shadowing remains on
  blocked stops.
- Handler history (`data_layer.history`) records per-handler verdicts;
  `count_blocks()` totals fall accordingly (they used to count every matched
  handler as a denier on a denied call).
- A terminal handler's ALLOW context is now delivered alongside a later
  deny's `permissionDecisionReason` (as `additionalContext`).
