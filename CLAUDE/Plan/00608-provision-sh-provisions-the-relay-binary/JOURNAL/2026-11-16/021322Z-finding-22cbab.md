CI teardown error (OSError 39 on untracked/) reproduced locally on the symlinked-project daemon test. Cause proven: the temp project has the relay on by default and no binary, so the daemon's start-up repair (follow-up a) spawns a detached child; the left-over tree showed untracked/relay-repair/ with a state file written by that child (status=failed, FileNotFoundError on .claude/hooks) while rmtree ran. Product defect: daemon stop did not end the repair it started. Fix: the daemon-start path uses spawn_owned and HooksDaemon.shutdown calls stop_owned_repairs (SIGTERM then SIGKILL to the process group, bounded, reaped; an unfinished running claim is withdrawn so the next start retries). The SessionStart path stays detached on purpose. The proof test passes unchanged with the relay on, three runs of the file (14 passed each). Release note 080 updated.
