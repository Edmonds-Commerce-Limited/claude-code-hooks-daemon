Branch `worktree-p468-docs`. It is not merged.

## G3: vendored docs

These pages were captured with `bin/hooks-daemon remote-docs add` from the
URLs listed in the vendored `llms.md`:
`https://code.claude.com/docs/en/{plugins,plugins-reference,discover-plugins,plugin-marketplaces,hooks}.md`.
They landed under `remote-docs/code.claude.com/docs/en/` with
`fidelity: converted`, and `.claude/REMOTE-DOCS.md` was regenerated.
`remote-docs check` reports everything fresh.

The vendored `hooks.md` carries upstream example UUIDs (for example
`550e8400-...`). The `session-uuid` public pattern flags 28 of them in the
`sensitive_content` QA check.

The first fix was a path entry in `exclude_paths`. The coordinator rejected it:
this project takes no new QA exclusions, and every future vendored page would
need another one. It is replaced by a rule:

- **The rule.** Public patterns stand down for the body of a faithful vendored
  copy. That is a markdown file in the remote-docs tree with valid provenance,
  whose body still hashes to the recorded `source_sha256`.
- **No schema change or backfill.** Capture stores the fetched bytes as the
  body after one separating newline. I checked all 16 vendored files, and
  every body hashes to its `source_sha256`. The separator is now the shared
  constant `CAPTURE_BODY_SEPARATOR`.
- **One implementation.** `remote_docs.provenance.is_faithful_vendored_copy`
  (with `is_remote_tree_document`) is called by all three surfaces:
  - the handler's `Write` path;
  - its `git commit` staged-content scan, which judges the whole index blob
    (or the working tree for `commit -a`), never the working copy of a staged
    file;
  - `scripts/qa/check_sensitive_content.py`, which imports it.
    An `Edit` is always scanned, because it carries only a fragment.
- **What is never stood down.** The secret word list, and file names.
- **Tests, RED first:**
  - `tests/unit/remote_docs/test_provenance.py`: 8 tests.
  - `tests/unit/handlers/pre_tool_use/test_sensitive_content.py`: 9 tests,
    covering `Write`, `Edit` and the staged scan, including an index blob that
    differs from a faithful working copy.
  - `tests/unit/qa/test_check_sensitive_content.py`: 4 tests.
    Between them they cover the lead's four cases: faithful not flagged, edited
    flagged, secret term flagged, non-vendored flagged.
- **Residual limit (documented in `CLAUDE/RemoteDocs.md`).** The hash proves
  the body is unchanged since the frontmatter was written. It does not prove
  the body came from upstream: an author who writes frontmatter and computes
  the hash by hand looks like a capture. This is why only the public patterns
  stand down.
- **Separate gap, not fixed here.** The CLI capture path builds
  `SensitiveContentHandler()` without the configured options, so its
  `scan_text` runs with no public patterns at capture time.
