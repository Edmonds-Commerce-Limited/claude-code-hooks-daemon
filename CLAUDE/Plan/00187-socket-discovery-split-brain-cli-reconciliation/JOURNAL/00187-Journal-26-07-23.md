## 16:05 · finding · — — root cause

`init.sh` (lines ~468-480) consults the daemon's socket **discovery file** as a
fallback, but the Python management CLI (`_resolve_socket_path`/`_resolve_pid_path`)
does not. A stale git-tracked `hooks-daemon.env` pinning a non-canonical socket
name diverges the two halves: hooks fire on the pinned socket while
`status`/`health` compute the canonical hash name → `NOT RUNNING`. The daemon
ALWAYS writes its actual bound socket to the discovery file at startup
(`cli.cmd_start` line ~539), at a deterministic (untracked + hostname) location
independent of the env override — so the CLI can read it too.
