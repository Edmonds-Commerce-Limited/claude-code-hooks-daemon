## Blocker

### B1. A command that ends in the full suite gets past the daemon: the M1 memo is keyed so that one word per reference defeats it

**Where.** `subagent_full_qa_blocker.py`:

- `:3673-3678`: the memo key is `(path, kind, argv, directory)`;
- `:3803`: `parse_budget` is charged in `_read_new`, once per PATH;
- `:3698`: `_first_full_run` re-parses the file for every key it has not seen.

So a file referenced with a different argv each time (`bash f.sh a0; bash f.sh a1; …`), or from a
different directory each time (a `cd` before each self-reference), is parsed once per reference,
exactly as before the fix. The shared parse budget is charged only once for the file.

**Reproduced (handler alone, `probe_463r8_m1_out.txt`):**

| Command                                                                   | Length | Time        |
| ------------------------------------------------------------------------- | ------ | ----------- |
| `bash self60.sh` (review 7's shape: 60 × `bash self60.sh`)                | 60     | 0.04 s      |
| `bash heredocs32k.sh; ` × 200 (review 7's shape)                          | 13,400 | 2.00 s      |
| `bash heredocs32k.sh a<i>; ` for i in 0..199                              | 13,890 | **> 120 s** |
| `bash words32k.sh a<i>; ` for i in 0..199                                 | 13,690 | **51.7 s**  |
| `cd fx && bash cd30.sh` (30 × `cd d<i>` then `bash <abs>/cd30.sh`)        | 110    | **20.0 s**  |
| `cd fx && bash cd60.sh`                                                   | 110    | **> 120 s** |
| `bash argv60.sh x` (60 × `bash <abs>/argv60.sh "$1"<i>`)                  | 62     | 2.7 s       |
| `bash heavy10.sh x` (10 argv self-references + 16 KiB of heredoc openers) | 63     | 7.5 s       |

**Through the worktree daemon (`probe_463r8_m1_daemon_out.txt`).** I sent
`bash words32k.sh a0; … bash words32k.sh a199; pytest tests` (13,702 bytes) as a sub-agent event.
After 30.1 s the forwarder returned `"A hook handler exceeded the 30s budget … socket_timeout"`
with **no `permissionDecision`**. The command is ALLOWED and `pytest tests` runs. The
110-byte `cd30` command took 19.5 s through the daemon: under the budget, but at 30 lines.

This is the failure review 6 M1 and review 7 M1 reported, now with an ending that turns it into a
false allow. It takes one `Write` of a small file, or no write at all when the command references an
existing ~30 KiB script. The tests (`test_subagent_full_qa_blocker.py:1723-1762`) pin only the
same-argv, same-directory shapes, and they use wall-clock budgets.

**Direction.** Make the bound structural, not a property of the key:

- Charge `parse_budget` with the bytes of every PARSE (`_invocations`/`_python_code_runs` input),
  not every new path read. Past the budget, go to the scan path, whose result is already cached per
  path.
- Or key the memo on `(path, kind)` alone, and judge argv-dependence separately (`$1`/`$@` present
  or not).
- Pin it deterministically (see "The flaky test"): count the bytes handed to the parser in one
  event and assert they stay at or under 32 KiB, for the distinct-argv and distinct-directory
  shapes above.

### M1. A command string held in a variable, a constant or a function is no longer read in Python

**Where.** `_python_code_runs` (`:2839-2851`) now judges only the literals inside a
process-starting call's own parentheses (`_process_call_spans`, `:2759-2790`). The M2 fix
introduced this.

**Reproduced (`probe_463r8_fn_out.txt`).** Each is `python3 <file>` from the worktree root.

- **Allowed at HEAD, denied at `700f0d34`:**
  - `cmd = "pytest tests"` then `subprocess.run(cmd, shell=True)`;
  - `c = "pytest tests"; os.system(c)`;
  - `cmd = "./scripts/qa/llm_qa.py all"` then `subprocess.run(cmd, shell=True)`;
  - a module constant `FULL = "scripts/qa/llm_qa.py all"` with `subprocess.run(FULL.split())`;
  - `CMD = "pytest tests"` then `subprocess.run(shlex.split(CMD))`;
  - `CMDS = {"full": "pytest tests"}` then `subprocess.run(CMDS["full"], shell=True)`;
  - a function that returns `"pytest tests"`, passed to `subprocess.run`;
  - a `)` inside a comment in the call (`subprocess.run(  # see (1))` followed by the literal on
    the next line). `_closing_paren` (`:1324`) is a shell quote tracker and does not know Python
    comments.
- **Allowed at both** (not new, for completeness): `run = subprocess.run`, `getattr(subprocess, "run")(...)`, `functools.partial(subprocess.run, …)`, `"pytest " + "tests"`, an f-string,
  `.format`, `asyncio.create_subprocess_shell`, `pty.spawn`, and a list held in a variable naming
  `./scripts/qa/llm_qa.py`.

Holding the command in a variable or a module constant is the ordinary way to write a Python
runner, so this is the most realistic false allow in the corpus. The M2 fix traded it for the
docstring false deny.

**Direction.**

- Keep M2's intent (prose is not a command) without the call-span restriction. Judge every literal
  that shlex can parse AND whose first word is a program (or is a whole argv element).
- Or resolve a Name argument inside a call span to a same-module assignment.
- Add RED rows for the variable, constant, dict and function-return shapes above.

  `nodenv`, `conda`, `direnv`, `brew` and `ssh-agent`;
- `_COMPLETION_WORD in words[1:]` accepts ANY producer with the word `completion` anywhere in its
  arguments;
- `command_word` strips the directory, so a project file named `ssh-agent` is trusted.

It is used at `:2079` (a pipe or process-substitution producer) and at `:2416` (`eval`/`-c` of a

- `eval "$(<fx>/ssh-agent)"`\* and `eval "$(./ssh-agent -s)"`\* after `cd` into it, where `<fx>/ssh-agent`

**Direction.**

- Require `completion` to be `words[1]`, with the shell name the only operand after it.
- Refuse a producer word that is a path (`./ssh-agent`, `/x/ssh-agent`).
- Pin each row above as RED.

### m3. `find -exec`: `{}` inside a word, and narrowing under a targeted start path

- GNU find replaces `{}` wherever it appears in a `;` action's argument (checked:
  `find tests -maxdepth 0 -exec echo ARG={}/ \;` prints `ARG=tests/`). `_resolve_find` (`:2627`)

  - `find tests -maxdepth 0 -exec pytest {}/ \;`
  - `find tests -maxdepth 0 -exec pytest ./{} \;`
  - `find tests -maxdepth 0 -exec pytest {}/unit/.. \;`
- The false deny is the reverse. A narrowing test can only select a SUBSET of the start paths, and

**Direction.** Replace `{}` inside a word, and let the start paths decide whether `{}` is full.

- **n1.** `_scanned_verdict` now strips comments (a per-character Python loop) or tokenizes before
  the cheap `program not in text` test, on every scanned file. The scan budget is 16 MiB per event,

    `bash x_tgt.sh; source y_addopts.sh; bash x_tgt.sh`, where `y` exports

    denied. It was denied at `700f0d34`.

- **n3.** The reference says `conda shell.* hook` and `brew shellenv` (`:1412`). The code accepts

  This is the review 7 n2 loophole with one more word. A constant string (`yield "read failed"`),

## The flaky test

`TestTheCodeFileReaderIsBounded::test_a_file_that_feeds_itself_and_others_takes_under_a_second`
(`test_subagent_full_qa_blocker.py:1608-1616`).

- **Twenty runs under load** (load average 7.5 to 11 on 8 cores, other gates running;
  `probe_463r8_flaky_pytest_out.txt`): **2 of 20 failed**, at 1.19 s and 1.08 s.

- **In-process, 20 interleaved runs each** (`probe_463r8_flaky_out.txt`):

  | Handler  | Median  | Max     | Runs at 1.0 s or more |
  | -------- | ------- | ------- | --------------------- |
  | HEAD     | 0.876 s | 1.168 s | 3 of 20               |
  | 700f0d34 | 0.551 s | 0.757 s | 0 of 20               |

- **Both do the same work.** Wrapping the module's own functions counts 1,302 files read, 6
  `_invocations` calls and 1,297 name scans for each.

- **Attribution** (`probe_463r8_flaky_attrib_out.txt`): with `_without_comments` stubbed out, the
  HEAD median falls from 0.986 s to 0.575 s.

**Verdict: a real regression, not a pure timing flake.** The M2 fix's comment stripping on the scan
path (nit n1) costs about 60% more per scanned file. That pushes a test with 0.45 s of headroom at
`700f0d34` to within 0.1 s of its limit on a loaded host. Excluding it with `-k` hid the only test
that measured the regression.

**A deterministic replacement.** Either kind of failure below is a correctness bug, never a
timing effect.

1. Count work, not seconds. Add two counters to `_Event`: `parsed_bytes`, charged wherever text is
   handed to `_invocations`/`_python_code_runs`, and `scanned_bytes`, charged wherever text is
   handed to `_without_comments`/`_without_python_prose`/`_named_pattern`. Or wrap those functions
   with `monkeypatch`, as `probe_463r8_flaky.py`'s `Counter` does.
2. Assert, for this fixture and for B1's shapes (distinct argv, distinct directory), that
   `parsed_bytes <= _MAX_PARSED_FILE_BYTES` and `scanned_bytes <= _MAX_SCANNED_FILE_BYTES`.
