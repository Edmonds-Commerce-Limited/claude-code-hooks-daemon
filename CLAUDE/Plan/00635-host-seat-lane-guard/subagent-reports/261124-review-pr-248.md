## Important Issues

### I1. The no-answer refusal text says a seat's "duty cannot be read" (Confidence: 85%)

**Location:** `src/claude_code_hooks_daemon/handlers/pre_tool_use/host_seat_lane_guard.py:91-95`. The test `tests/unit/handlers/pre_tool_use/test_host_seat_lane_guard.py:400` asserts the old wording.

**Problem:** `_UNKNOWN_REFUSAL` is now reached only when the probe gave no answer (UNRESOLVED). It still reads "this session holds a teamchat seat whose duty cannot be read". The rule text, CLAUDE.md, the config manifest and note 091 were all reworded to "whose teamchat probe gives no answer". The handler is now the only surface that keeps the old wording. It also asserts that a seat is held, which UNRESOLVED (for example `KIT_MISSING`) does not establish. It also contradicts the new rule that an unreadable duty is silent.

**Fix:** Reword it to: "Host seat lane: the teamchat probe gave no answer, so the guard stays armed, and this is a test, build, lint or QA command. If this is a host seat: ...". Update the assertion at test line 400 to the new phrase.

### I2. Stale comment in the shared classifier, and the lane patterns are now a second copy (Confidence: 80%)

**Location:** `src/claude_code_hooks_daemon/utils/long_running_command.py:148-151` and `tests/unit/strategies/lane_commands/test_registry.py:92-95`.

**Problem:** The comment says the groups exist "so a guard can take a subset (host_seat_lane_guard takes test, build and QA ...)". The guard no longer imports `TEST_PATTERNS`, `BUILD_PATTERNS` or `QA_PATTERNS`. The strategies hold byte-identical copies. A test pins them in one direction only (every shared pattern is also in the lane) and uses a magic `BUILD_PATTERNS[1:]` slice that silently shifts if anyone reorders that tuple. So a new test runner added to `TEST_PATTERNS` arrives in the lane only because that test fails, not by design. Nobody is told which copy is the source of truth.

**Fix:** Take one of two options:

- (a) Make the strategies the source of truth and have `long_running_command` build its test, build and QA groups from the registry.
- (b) Keep the shared groups as the source and have each strategy reference them.

At a minimum, rewrite the comment to say the lane guard keeps its own per-language copy, pinned by `test_registry.py`. Also replace `BUILD_PATTERNS[1:]` with an explicit named tuple, so a reorder cannot drop a pattern unseen.

### I3. PLAN.md does not record the 2026-11-24 arming ruling or the strategy move (Confidence: 75%)

**Location:** `CLAUDE/Plan/00635-host-seat-lane-guard/PLAN.md:25-30` and `:59-69`.

**Problem:** The Decision section still describes only Q64 D3 plus "unreadable whoami armed". The narrowing to "only an explicit host arms; null/missing/unreadable duty is silent" appears nowhere in PLAN.md. Neither does the finding-2 re-scope (which tables were dropped, and which gaps were closed). Task 2.1 still says "reusing the slow-command classification" and lists finding 2 as OPEN in full. Today that narrative lives only in the subagent report and release note 102.

**Fix:** Add a dated Decision line for the owner's null-duty ruling and the finding-2 re-scope. Mark in Task 2.1 which finding-2 items were closed (`npm t`, `pre-commit run`) and which were accepted as won't-chase. Keep `docker exec`/`ssh` open as an owner question.

## Suggestions

- **S1. `rspec` and `phpunit` end on a word boundary, against the rule commit 45dd3f569 states.**
  - Location: `strategies/lane_commands/ruby_strategy.py:11` and `php_strategy.py:10`.
  - Problem: the commit says the new patterns end on whitespace or end-of-string, but `rspec-x`, `bundle exec rspec-queue`, `phpunit-x` and `phpunit-watcher watch` are lane. The impact is small, since these are mostly test tools.
  - Fix: use the same whitespace-or-end lookahead as the other new patterns, and add a negative-neighbour test.
- **S2. No test covers the sequence "resolved, then no answer".**
  - Location: `tests/unit/handlers/pre_tool_use/test_host_seat_lane_guard.py` (TestArming).
  - Problem: the behaviour is right by construction, because the TTL cache keeps no last-good answer, but no test pins it.
  - Fix: add a test with a fake resolver that returns a RESOLVED worker context, then `SeatContext.unresolved(...)`. Assert silent, then armed.
- **S3. The acceptance-test set duplicates `pytest tests/unit`.**
  - Location: `host_seat_lane_guard.py:303-322` and `python_strategy.py:15`.
  - Problem: the handler's own acceptance test and the Python strategy's are the same command. The `unseated` string duplicates `common._HARNESS_CANNOT_PRODUCE`.
  - Fix: drop the handler's own pytest case, or change the strategy's command to `python -m pytest`. Import the shared string from `common`.
- **S4. Note 102 describes "no longer arms" and "as before" against behaviour that never shipped.**
  - Location: `CLAUDE/UPGRADES/UNRELEASED/release-notes/102-host-seat-lane-commands-per-language.md`.
  - Problem: note 091 (also UNRELEASED) introduces the handler. Operators upgrading will see both notes, and 102's narrowing and "every command it recognised before" refer to a state they never ran.
  - Fix: fold 102 into 091, or reword 102 as a description of current behaviour without a before/after.
- **S5. The new domain has no `CLAUDE.md` pointer.**
  - Location: `strategies/lane_commands/`.
  - Problem: `CLAUDE/Code/StrategyPattern.md` step 7 says each domain's `CLAUDE.md` should point to it. `tdd/` and `lsp_noise/` have one; `lint/` does not either, so this is soft.
  - Fix: add the short pointer file.

  - Location: `host_seat_lane_guard.py:182`.
  - Problem: E501 is ignored, but the line exceeds the 100-character line length.
  - Fix: wrap it.
