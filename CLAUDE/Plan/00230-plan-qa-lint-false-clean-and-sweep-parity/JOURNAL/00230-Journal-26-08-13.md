## 07:12 · finding · P1 — `--lint` certifies files it never examined

Probes against the live tree:

| Probe                                                   | Exit | Output                     |
| ------------------------------------------------------- | ---- | -------------------------- |
| `plan-qa --lint CLAUDE/Plan/00131-…/PLAN.md` (relative) | 0    | "plan tree is clean"       |
| `plan-qa --lint /workspace/CLAUDE/Plan/00131-…/PLAN.md` | 1    | BLOCK status-enum-and-date |
| `plan-qa --lint /workspace/README.md`                   | 0    | "plan tree is clean"       |
| `plan-qa --lint /workspace/CLAUDE/Plan/README.md`       | 0    | genuine clean (plan index) |

Mechanism: `paths.py:163` — `classify()` short-circuits to `OUTSIDE` unless
`path.is_relative_to(context.plan_dir)`, and `plan_dir` is absolute.
`cli.py:3699` passes `Path(args.lint)` through unresolved. A relative path
therefore never classifies, `edit_target()` returns `None` for every EDIT
check, and the run prints a clean bill of health.

This is not a theoretical invocation: the shipped skill
(`skills/hooks-daemon/plan-qa.md:33`) documents the relative form verbatim —
`… plan-qa --lint CLAUDE/Plan/00042-thing/PLAN.md`. Every client typing the
documented command gets a false clean.

Why the test suite cannot see it: every lint test in
`tests/unit/daemon/test_cli_plan_qa.py` builds its target as
`root / "CLAUDE/Plan/…"` — always absolute. The tests and the documentation
disagree about the input shape, and only the tests are executed.

## 08:40 · finding · P3 — the obvious fix would have been a new blindness

Started Phase 3 intending to add `Stage.SWEEP` to each EDIT `CheckSpec`.
Checked `sweep_context()` first: it sets no `file_path`/`file_content`. So
`edit_target()` returns `None` at sweep and a re-registered check no-matches
every folder — registered, running, finding nothing, and indistinguishable
from a pass. The obvious one-line fix would have SHIPPED the appearance of
coverage with none of it.

Built `tree_targets()` + `document_rule_checks()` instead: each rule is
written once against a `DocumentTarget` and adapted to both surfaces.
`TestNaiveReRegistrationWouldBeASilentNoOp` pins the trap.

`DocumentTarget` also carries `text`. `path-existence` read
`context.file_content` directly, which is exactly the coupling that made it
silently edit-only — that field is `None` on a sweep context.
