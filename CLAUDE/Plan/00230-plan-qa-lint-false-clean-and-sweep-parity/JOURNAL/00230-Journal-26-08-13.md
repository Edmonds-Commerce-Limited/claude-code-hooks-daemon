## 07:12 · finding · P1 — `--lint` certifies files it never examined

Probes against the live tree:

| Probe                                                   | Exit | Output                     |
| ------------------------------------------------------- | ---- | -------------------------- |
| `plan-qa --lint CLAUDE/Plan/00131-…/PLAN.md` (relative) | 0    | "plan tree is clean"       |
| `plan-qa --lint /workspace/CLAUDE/Plan/00131-…/PLAN.md` | 1    | BLOCK status-enum-and-date |
| `plan-qa --lint /workspace/README.md`                   | 0    | "plan tree is clean"       |
| `plan-qa --lint /workspace/CLAUDE/Plan/README.md`       | 0    | genuine clean (plan index) |

Mechanism: `paths.py:163` — `classify()` short-circuits to `OUTSIDE` unless
`path.is_relative_to(context.plan_dir)`, and `plan_dir` is absolute.
`cli.py:3699` passes `Path(args.lint)` through unresolved. A relative path
therefore never classifies, `edit_target()` returns `None` for every EDIT
check, and the run prints a clean bill of health.

This is not a theoretical invocation: the shipped skill
(`skills/hooks-daemon/plan-qa.md:33`) documents the relative form verbatim —
`… plan-qa --lint CLAUDE/Plan/00042-thing/PLAN.md`. Every client typing the
documented command gets a false clean.

Why the test suite cannot see it: every lint test in
`tests/unit/daemon/test_cli_plan_qa.py` builds its target as
`root / "CLAUDE/Plan/…"` — always absolute. The tests and the documentation
disagree about the input shape, and only the tests are executed.

## 07:20 · finding · P2 — an unparseable status falls through the sweep

`PlanDoc.parse` on 00131/00132 returns `status_line_present=True, status=None`
(`_parse_status_value` requires an exact or prefix match on an enum token).

`location-status-coherence` is the one SWEEP check that reads status. It tests
`doc.is_terminal` (False when `status is None`) and
`doc.status in _NON_TERMINAL_STATUSES` (also False). Its `status_line_present`
branch passes, because the line IS present. So a garbage token satisfies every
branch and the sweep sees nothing. Line 84 even writes
`doc.status.value if doc.status else 'unknown'` — the `None` case was known to
be reachable, but only handled in a message, never as a case.

## 07:26 · finding · P3 — no document-level check has a batch twin

Stage census across `plan_qa/checks/`:

- **SWEEP-registered**: `structure-archive-dirs`, `no-new-collisions`,
  `stats-recount`, `row-folder-bijection`, `index-row-length`,
  `location-status-coherence`, `journal-freshness`, `journal-folder-present`,
  `staleness-nag`, `dormant-honesty`, `claim-spotcheck-queue` — every one of
  them TREE-level (cross-file relationships).
- **EDIT-only**: `status-line-present`, `status-enum-and-date`,
  `header-body-coherence`, `task-grammar`, `template-metadata`,
  `path-existence`, `plan-doc-size`, `terminal-placement-hint`,
  `journal-dayfile-naming`, `archive-immutability`, `journal-append-only`,
  `journal-dayfile-is-today` — every single-document check.

So no check ever reads a `PLAN.md` already on disk. This is the corollary in
CLAUDE.md Standard 15, live: a write-time-only guard leaves everything
predating it permanently unexamined.

Three of the twelve are correctly edit-only — `archive-immutability`,
`journal-append-only` and `journal-dayfile-is-today` are about the *act of
writing*, not about on-disk state. A day-file dated last week is fine sitting
on disk; only appending to it is wrong. Phase 3 has to record that distinction
per check rather than blanket-registering twins.
