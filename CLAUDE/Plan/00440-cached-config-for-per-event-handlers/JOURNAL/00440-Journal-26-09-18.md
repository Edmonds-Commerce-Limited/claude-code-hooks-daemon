## 02:16 · finding · T1.1 — which callers are actually hot

Checked every `Config.load_or_default` call site before scoping, because the
last three ledger rows all turned out wider or narrower than filed:

- `utils/secret_file_matching.py:185` and `utils/secret_redaction.py:229` run
  on every Write/Edit but already cache behind a module-level resolved flag.
  They never invalidate — a config edit is invisible to them until restart —
  which is a real question, but a separate one, and not a cost question.
- `daemon/cli.py` (14 sites), `install/*` and the `session_start` handlers are
  one-shot per process or per session. A cache buys them nothing and a stale
  read would be a new failure mode.
- `handlers/pre_tool_use/remote_docs_routing.py:109` is per-event but only on
  `WebFetch`, behind a `self._tree().is_dir()` gate. Worth routing through the
  accessor for consistency; it is not the cost centre and this plan should not
  claim it is.

So the two cron enforcers are the finding, and for once the row named its scope
correctly.

## 02:18 · decision · P2 — the cache must be locked

Dispatch is not single-threaded. `daemon/server.py:1443` runs the controller
via `await loop.run_in_executor(None, self.controller.dispatch, hook_input)`,
and the default executor is a `ThreadPoolExecutor`. Plan 00437 measured what an
unlocked read-modify-write on a daemon-lifetime singleton does under that pool:
nothing at all at the default 5 ms switch interval, and 26 `KeyError`s once
`sys.setswitchinterval(1e-9)` drove the interleaving. The concurrency test here
has to be shown failing against an unlocked replica before it is worth
anything — under the GIL, "it did not raise" is not evidence.
