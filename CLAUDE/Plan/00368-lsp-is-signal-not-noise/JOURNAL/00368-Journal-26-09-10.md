## 09:20 · decision · T2.2 — owner ruling: every supported language, not Python alone

Team lead relayed the owner's correction mid-task: `lsp_noise_checker`
must not be Python-only - "LSP should be signal, not noise" applies to
every language server Claude Code runs. Restructured as a Strategy
Pattern registry (`strategies/lsp_noise/`, mirroring the `tdd` archetype
exactly: `protocol.py`, `common.py`, one `{language}_strategy.py`, a
`registry.py` with `create_default()`) behind a handler reduced to a thin
orchestrator with zero language logic. A follow-up correction: PHP must be
a REAL strategy, researched rather than assumed, and if intelephense
genuinely has no per-project knob the advisory must print the exact
settings snippet, never say "unsupported".

Research (no WebFetch tool available to this subagent; used `curl` via
Bash against public docs and GitHub directly instead, everything captured
to `untracked/scratch/` before being deleted as scratch): fetched
`code.claude.com/docs/en/discover-plugins.md` for the official
language→plugin→binary table, then the ground truth -
`anthropics/claude-plugins-official`'s `.claude-plugin/marketplace.json` on
GitHub - which shows EVERY official LSP plugin (`pyright-lsp`,
`typescript-lsp`, `gopls-lsp`, `rust-analyzer-lsp`, `php-lsp`) ships with NO
`settings`/`initializationOptions` at all. That single fact splits the five
languages into three real shapes: Python/TypeScript read their own project
file regardless of who launches the server (pyright/tsserver always have);
Go/Rust have no exclude list at all, so the check becomes "does a
non-project tree hold this language's source files" (Rust's fix routes
through `Cargo.toml`'s `[workspace] exclude`, a real editable knob; Go's
routes through a nested `go.mod` module boundary); PHP's intelephense
(confirmed via `bmewburn/intelephense-docs`, not phpactor - the owner's
placeholder guess) reads NO project file whatsoever, so the only real fix
is a project-scope LSP plugin re-registering `.php` with its own
`settings` (`plugins-reference.md`'s "first server registered wins the
extension" rule), which the strategy now scans for under
`.claude/plugins/*/` and, when absent, prints in full.

Implementation: 5 strategies + `common.py` + `protocol.py` + `registry.py`,
TDD throughout (test file before source for every new module, including
bare `__init__.py` - the daemon's own `tdd_enforcement` does not exempt
dunder files). Moved two structurally-identical private view dataclasses
(`_ConfigView` used by Python and TypeScript, `_OverrideView` used by PHP)
into `common.py` as `ConfigView`/`OverrideView` after
`qa/strategy_pattern_checker.py` flagged them: it scans every class
defined in a `*_strategy.py` file for `get_acceptance_tests()`, so a
private helper dataclass living beside the real strategy class read as a
second, non-compliant "strategy". Handler rewritten as pure orchestration:
scans the process table ONCE per session (not once per language) via a
`known_names` union, then filters per strategy for staleness. Rewrote the
handler's test file around fake strategies for orchestration coverage,
independent of any one language's file-reading specifics (which stay
covered in each strategy's own test file). PLAN.md, config-changes
manifest, release-notes callout 19, HANDLER_REFERENCE.md and
`constants/handlers.py`/`init_config.py`/`.claude/hooks-daemon.yaml`(.example)
comments all updated from "Python projects only" to the five-language
table. 137/137 lsp_noise + handler tests pass; mypy and pyright both clean
on every touched file; `strategy_pattern_checker` clean except two
pre-existing, unrelated violations in `comment_size.py`/
`staged_lint_gate.py` (Plan 00347, untouched by this branch).
