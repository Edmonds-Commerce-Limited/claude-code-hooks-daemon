**`result_types.py`'s two documented `reportIncompatibleVariableOverride`
errors**: did not just trust the docstring's "don't widen" warning —
tried the one typed alternative that looked plausible, `Final[Literal[
...]]` on the narrowed override (pyright exempts `Final` attributes from
its invariance check). Reproduced in a throwaway pydantic 2.13 model
matching this file's shape and it is actively worse than doing nothing:
Pydantic v2 treats a `Final`-annotated field carrying a default as a
**class variable, not a model field** — `Narrow(decision=Decision.DENY)`
silently keeps the class default (constructor argument dropped on the
floor), and direct mutation raises `AttributeError: ... is a ClassVar ...
cannot be set on an instance`, which is exactly the write path
`merge_pseudo_results` depends on. Confirmed via a real interpreter run,
not just pyright. So this stays the one documented exception to Task 3.1's
"every pyright error" — a pyright/mypy variance disagreement on a
deliberately covariant field, with the only pyright-silencing workaround
proven (not assumed) to break the feature at runtime.
