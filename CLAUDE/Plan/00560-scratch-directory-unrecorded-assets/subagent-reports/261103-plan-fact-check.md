## REFUTED (most consequential first)

**R1. CODE-FACTS F9 (also behind DESIGN-QUESTIONS D4):** "`CLAUDE/Plan/mkplan.bash:350-351` and `CLAUDE/PlanJournalling.md:200-202`: the documented journal body location is `untracked/scratch/journal-*.md`."

- `CLAUDE/PlanJournalling.md:200-202` does use `untracked/scratch/journal-190-260924-1405.md`. So does `plan_journal_guard.py:569,638,642`.
- `mkplan.bash:350-351` (its `--help` usage text) does not. Its examples are `untracked/scratch/entry.md` and `untracked/scratch/fix.md`, which are not `journal-*.md` names.
- Live practice differs from the pattern too. The top level of scratch holds journal bodies such as `j558-standin.md` and `j558-standin-2.md`, written today.
- **What it changes:** D4's working allowlist has `journal-*.md` as the journal shape. Under Goal 6 / Task 5.1, that would deny bodies written exactly as mkplan's own help text shows, and bodies named in the `j<plan>-*` style already in use. Phase 1 needs to do one of two things. Either align the mkplan usage text (and its install template `install/templates/mkplan.bash`) with `journal-*.md` as part of Task 2.3, or widen the shape. It also needs to treat a body passed to `mkplan.bash --journal` as consumed whatever its name (D1).

**R2. CODE-FACTS F5 (feeds DESIGN-QUESTIONS D6 and Task 3.2):** "`untracked/agent-dispatch-registry/` exists (a registry keyed per dispatch)".

- The directory exists. It is not keyed per dispatch.
- `utils/agent_dispatch_registry.py:15-17,53-56`: there is one file per `(session_id, name)`.
- `handlers/pre_tool_use/agent_dispatch_recorder.py:110-113` records it only when the dispatch sets `name` ("named only").
- `agent_dispatch_registry.py:70-72`: a later dispatch of the same name replaces the whole row.
- **What it changes:** an unnamed dispatch leaves no registry row at all, and a repeated name overwrites the earlier one. As it stands, the registry cannot carry "the declared destination of this dispatch" for Task 3.2 or for D6's tracked-counterpart check. Phase 1 must either key a new record by something per-dispatch (for example `tool_use_id`, or the `agent_id` resolved at SubagentStart) or extend the recorder to unnamed dispatches. D6 should not assume the existing carrier is enough.

**R3. CODE-FACTS F3 (minor citation):** "ANY path-shaped token (`:106`, `\S*/\S+`)".

- `_PATH_TOKEN_PATTERN = re.compile(r"\S*/\S+")` is at `handlers/pre_tool_use/dispatch_declaration.py:105`. Line 106 is blank.
- **What it changes:** the citation only. The behaviour claim is correct.
