## Task 4.1: lossless force removal (done)

- `core/force_removal.py` proves containment with ONE `git rev-list <tips> --not [--exclude=<ref>]... --glob=refs/heads --glob=refs/remotes --glob=refs/tags` call. This is a deliberate deviation from `for-each-ref --contains`. With several `--contains` arguments, `for-each-ref` lists the refs that contain ANY of the tips, so it cannot say which tip is held. With `rev-list`, a held tip drops out of the output, so one call answers for every tip. The refs the same command deletes are excluded, nested branch names are covered, and a git failure raises `ContainmentUnknown`, which denies.
- `destructive_git`:
  - `git branch -D` and `update-ref -d` are allowed when any surviving branch, tag or remote-tracking ref holds every tip.
  - The new R-GIT-WORKTREE-REMOVE-FORCE judges every `git worktree remove`, forced or not. It checks ignored content outside `regenerable` and, when forced, the status and whether HEAD is held.
  - Each loss is stated with its commit count and paths, and every deny appends `BRANCH_LIMIT_PRINCIPLE`.
  - `branches.force_removal.mode: off` keeps the old remote-only check and leaves worktree removal unjudged.

## Task 4.5: evacuate then destroy

Same command (done):

- `core/evacuation.py` provides `evacuate_then_destroy(command, cwd)`, built on `simple_commands`.
- An evacuation is `git diff`/`show` (not a summary form such as `--stat`), `stash show -p` or `format-patch`. It must land through a file redirect, a piped `tee` or `-o`/`--output-directory` in a path that `git ls-files --error-unmatch` does not track. That covers ignored, new and out-of-repo paths.
- A destruction is `worktree remove`, `branch -d/-D/--delete`, `update-ref -d refs/heads/...` or `rm -r`.
- They match when:
  - the evacuation's toplevel is the removed path or lies under it; or
  - a branch matches, meaning the evacuation's checked-out or named revision against the deleted branch or the removed worktree's branch.
- A `cd` chain or `-C` that cannot be placed counts as a match, so the check fails closed.
- Git is only run when both shapes are present syntactically.
- `destructive_git` checks this first, before any lossless allowance. `matches()` also claims an `rm -r` that only the evacuation makes destructive.
  - Under `block`, it denies with R-GIT-EVACUATE-THEN-DESTROY. The deny says to commit or push on the lane's branch or to ask a human, and ends with the principle.
  - Under `warn`, the normal verdict stands, and an allow carries the note as context.
  - Under `off`, the check is skipped.
- Tests: `tests/unit/core/test_evacuation.py`.
