# Tasks 3.2 and 3.3: WorktreeRemove branch delete and dogfood fixes

Branch `worktree-558-wtremove` (from main at 260daaf2c), pushed, not merged.

## Task 3.2 (DESIGN.md section 8)

`handlers/worktree_remove/worktree_remove_handler.py`:

1. Maps the payload path through `git worktree list --porcelain`; a path that is not a LINKED worktree (a stray directory, the main checkout) is never removed.
2. Runs `core.branch_cleanup.worktree_blockers` first. Any modified or untracked file, or ignored path outside `branches.cleanup_after_merge.regenerable`, leaves the worktree in place and logs the paths. This matters because plain `git worktree remove` also deletes ignored files, so scratch notes are only safe if the check runs before every removal, not only the forced ones.
3. Adds `--force` only when `git for-each-ref --contains HEAD` (run in the worktree) names a ref other than the worktree's own branch. A git failure withholds `--force`.
4. For a branch matching `<slug>-<8 hex>` (`core.worktree_naming.is_worktree_create_name`), calls the new `branch_cleanup.delete_if_merged`. That checks policy, then `cleanup_targets` (the default and integration lines), then a cheap `merge-base --is-ancestor` probe so an unmerged branch never pays for `git cherry`, then `classify_branch(content_tier=False)`, and then `delete_branches` with no bundle, for the merged tiers only. It logs the restore line and the remote delete command. Anything else is left for `branch-sweep --clean`. The log line says that eligibility comes from the name because no creator record exists yet.
5. Always prunes, with a `GIT_CONTEXT` timeout.

Budget: a `_Clock` caps every git call at the time left of `EVENT_HANDLER_BUDGET[WORKTREE_REMOVE]` (60 s). An exhausted budget skips the remaining steps and logs them. The branch step needs `2 * GIT_CONTEXT` left to start. Residual: `worktree_blockers` and `classify_branch`/`delete_branches` use their own module timeouts, so they are not individually capped. `classify_branch` only runs after the ancestry probe has proved the branch merged, which keeps it on its fast path.

`core/worktree_reaping.py`: orphan pruning now lists every branch and keeps `is_daemon_created_branch` names (`agent-*` or `<slug>-<8 hex>`), for both the full listing and the `--merged` listing. `AGENT_BRANCH_GLOB` is removed because nothing used it any more.

## Task 3.3

1. An empty directory is never a blocker (`_empty_tree`: a real directory with only empty directories beneath it). One file anywhere under `untracked/scratch/` still blocks.
2. A `store/` glob also matches a symlink of that name, including a broken one (`_judged_form` adds the `/`). A symlink the globs do not name still blocks.
3. Eight new `regenerable` defaults. `.coverage` and `.CLAUDE.md.pre-inject` are anchored (`/.coverage`) so that they match only at the root. The manifest entry is updated in `config-changes/v3.72.0.yaml`, because the key is new in this unreleased version.
   - Verification: `branch-sweep --clean --dry-run` from /workspace (with both main's code and this branch's code) printed "Nothing to clean: no merged or patch-equivalent local branch". No worktree candidate exists to show the change on.
   - Instead, `worktree_blockers` ran read-only on /workspace with the old defaults and then the new ones. The new defaults clear `.CLAUDE.md.pre-inject`, `untracked/.python-cmd-cache`, `untracked/context-sidecar/` and `untracked/logs/`. `repair.log`, `repair.txt`, `.coverage` and `acceptance/` were not present there.
4. `core.branch_sweep.session_summary` takes `behind_threshold` and, on new sessions only, adds `Behind <default>: <name> is N commits behind (branches.sweep.behind_threshold: T); ...` for each unmerged work branch (merged, patch-equivalent and never-work excluded) more than T behind. These lines go into the capped entries. `effective_behind_threshold` falls back to the legacy `behind_main_threshold`. The handler passes it in, and its guidance text and acceptance pattern mention the line.
