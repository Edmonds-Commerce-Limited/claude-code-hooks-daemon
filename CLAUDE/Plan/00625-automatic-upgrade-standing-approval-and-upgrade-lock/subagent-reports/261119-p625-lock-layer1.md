## Takeover race fix (requested mid-task, both scripts, lockstep kept)

In `_upgrade_lock_takeover`: the stale lock's token is read before the re-judge under `<lock>.takeover`.
Verdict 2 (the lock vanished) no longer removes anything: it only tries to create the lock, and
reports "taken first" if that fails. Verdict 0 removes the lock only if its token is unchanged
from just before the re-judge. Two new tests (`TestTakeoverNeverRemovesAFreshLock`) stub the judge
to simulate a fresh lock appearing; the fresh lock survives and takeover does not report success.

Residual window: two takers must both see the takeover file as stale (over 60 s), which needs a
crash inside a takeover. The token re-read narrows the harm but does not close it.
