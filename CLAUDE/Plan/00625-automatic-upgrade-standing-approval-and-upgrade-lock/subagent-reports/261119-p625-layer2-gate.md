# Plan 00625 Phase 4: Layer 2 and the gate

## What changed

- `src/claude_code_hooks_daemon/install/upgrade_gate.py`: `_write_verdict` appends `escalations=<n>` (count of READ THIS FIRST reasons) after the nonce and verdict lines. Old readers still work (they read `nonce=` first, then scan for `verdict=`). `upgrade_gate_standalone.py` needed no change.
  - Note: the count is the same with and without a digest. A digest-confirmed MAJOR bump gives `verdict=proceed` plus `escalations=1`. That is what lets Layer 2 refuse it regardless of the digest.
- `scripts/upgrade_version.sh`:
  - `readonly LAYER2_SUPPORTS_UNATTENDED=1` (exact line, near the top). It is also read in the stop message, so shellcheck sees a use and no suppression is needed.
  - `--unattended` is parsed from argv (`${@:4}`) and from `UPGRADE_FLAGS`. The `UPGRADE_FLAGS` source counts only when the handoff is a genuine Layer 1's, the same rule as the digest. It is also passed on to the second-pass `exec`, because that pass has no handoff.
  - `run_pre_deploy_phase` reads `escalations=` from the verdict. New `stop_unattended_for_a_human` runs before the exit-code `case`, for gate exits 0 and 3 only. If escalations is above 0, or the count is missing or non-numeric (fail closed), it calls `abort_before_deploy 5`. That is the same restore path as the exit-3 stop, so the checkout goes back to the installed version. An ordinary reading stop with escalations=0 stays exit 3 unattended.
  - Exit 5 was not used anywhere else in Layer 2. It is now a named constant `UNATTENDED_NEEDS_HUMAN_EXIT`. The header comment documents exits 3 and 5 and the flag.
  - Steps 15 and 16, unattended: `UPGRADE_STARTED` stays true and the script exits 1, so `cleanup_on_failure` restores the snapshot, restores the tracking record and runs `restart_daemon_quick`. Step 15 does not call `_record_tracking` unattended. Attended behaviour is unchanged.
  - Old venv: `eager_cleanup_stale_venvs` used to run right after Step 15 and can delete the previous daemon's venv. Unattended, it now runs after Step 16 passes. Attended runs keep the old position.
- `CLAUDE/LLM-UPDATE.md`: exit-code table gains rows for 5 and 75.
- Tests:
  - `tests/unit/install/test_upgrade_gate.py`: verdict file lines, with a MAJOR bump and with an ordinary reading stop.
  - `tests/integration/test_upgrade_pre_deploy_phase_runs_on_layer1.py` (end to end, a real Layer 2 against a fixture origin): the capability line is present. A direct Layer 2 call with `--unattended` plus a valid digest on a MAJOR bump exits 5 with the checkout restored and nothing deployed. An ordinary reading stop with `--unattended` still exits 3. `_assert_stopped_and_restored` gained a `stop_text` argument.
  - `tests/integration/test_upgrade_unattended_rollback.py` (new): the real Step 15 and 16 blocks plus the real `cleanup_on_failure` run against stubs. Checked: unattended rolls back and restarts the previous daemon, attended does not, the tracking record is skipped unattended at Step 15, the cleanup is deferred, and the second pass carries the flag.
