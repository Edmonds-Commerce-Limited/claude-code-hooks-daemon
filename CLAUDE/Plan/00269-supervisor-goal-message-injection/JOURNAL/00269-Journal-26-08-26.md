## 06:18 · decision · T1.2 — rendered_lines is a LIST-OF-ONE joined line

Decision 2 says the DAEMON joins logical lines into one physical line before
writing the signal; the Task 1.2 schema names a `rendered_lines` list. Both
honoured: the daemon renders + validates logical lines (caps apply
pre-join), joins with the fixed separator, and writes `rendered_lines` as a
list-of-one containing the joined physical line — keeping the field
list-shaped so a future safe multi-line mechanism can extend it without a
schema break. The supervisor re-joins whatever list it finds (identity for
list-of-one) and validates the result (marker prefix, length/line caps,
printable charset, hard newline ban). Full contract in SIGNAL-CONTRACT.md.
