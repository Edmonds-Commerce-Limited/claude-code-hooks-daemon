## 17:00 · finding · T2.1 — shellcheck needed source RESOLUTION, not laxer rules

First run of the new guard failed with SC1091 ("not following") on every
forwarder and skill script, plus SC2034 "DAEMON_DIR appears unused". The SC2034
looked like a real defect; it is not. Our scripts source siblings through a
computed path (`source "$(dirname "$0")/_resolve-venv.sh"`), shellcheck cannot
evaluate `$0`, so it declines to follow the source and then reports the
consequences of not having looked — including a variable the sourced file uses.

Fixed the invocation, not the assets: `--norc -x --source-path=SCRIPTDIR`.
`--norc` is the point of the guard (throw OUR config away). `-x
--source-path=SCRIPTDIR` is resolution, not rule suppression — shellcheck's own
SC1091 message recommends `-x`, and the same one-line setting is now in the
client boundary doc. With it, all four shell assets are clean at every severity.

That failure was also the guard's own negative control: it demonstrably fails on
non-clean output before it was made to pass.

## 19:25 · finding · — — the unexplained bit was my own environment

Answered it rather than leaving it hanging. Re-running the QA `tests` gate on
its own reported `collected 11890 items / 2 errors` — the collection failure
the first full run did not have. The difference is not the harness: the first
invocation was `PYTHONPATH=<worktree>/src … llm_qa.py all`, and that variable
propagates into the pytest subprocess. The bare re-run had no PYTHONPATH.

So there is no mystery and no harness quirk: in a worktree, EVERY route to
pytest needs `PYTHONPATH=<worktree>/src`, because the venv's editable install
points at `/workspace/src`. With it, the full suite runs 11,891 passed / 15
skipped / 1 failed — that one being the index-row length, now fixed. Without
it, 2 collection errors and nothing else runs.

Worth noting for whoever picks this up in a worktree next: the QA runner also
needs a venv it can find (`untracked/venv-*/bin/python`), which a worktree has
none of. Two git-ignored symlinks to the real venv plus the PYTHONPATH export
make the whole suite runnable from here.
