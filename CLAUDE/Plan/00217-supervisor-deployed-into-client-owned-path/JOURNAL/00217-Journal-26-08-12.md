## 17:00 · finding · T2.1 — shellcheck needed source RESOLUTION, not laxer rules

First run of the new guard failed with SC1091 ("not following") on every
forwarder and skill script, plus SC2034 "DAEMON_DIR appears unused". The SC2034
looked like a real defect; it is not. Our scripts source siblings through a
computed path (`source "$(dirname "$0")/_resolve-venv.sh"`), shellcheck cannot
evaluate `$0`, so it declines to follow the source and then reports the
consequences of not having looked — including a variable the sourced file uses.

Fixed the invocation, not the assets: `--norc -x --source-path=SCRIPTDIR`.
`--norc` is the point of the guard (throw OUR config away). `-x
--source-path=SCRIPTDIR` is resolution, not rule suppression — shellcheck's own
SC1091 message recommends `-x`, and the same one-line setting is now in the
client boundary doc. With it, all four shell assets are clean at every severity.

That failure was also the guard's own negative control: it demonstrably fails on
non-clean output before it was made to pass.
