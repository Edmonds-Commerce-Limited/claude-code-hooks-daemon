## 17:32 · decision · — — two findings, one plan, and why

These are two different defects — a test-fixture premise and a secret-content
gap — and filing them together needs a reason beyond "both turned up this week".

The reason is that the ARGUMENT is identical, and it is the argument in Core
Standard 15's corollary: a guard that fires only at write time cannot see what
arrives by another route. In A the route is the developer's shell environment; in
B it is `mv`. In both, the matcher and the rule already existed and were already
correct — the only thing missing was a guard standing where the failure actually
happens. Splitting them would produce two plans whose Overview sections argue the
same point, and would make it easy to close one and quietly leave the other,
which is how a class becomes a recurrence.

Recorded that either phase can ship independently, so the pairing does not turn
into a scheduling dependency.

## 17:35 · finding · — — the tempting fix for A is the one that must not happen

Worth stating before anyone reaches for it, because it is one line and it looks
like a fix: adding `git config --global user.email/user.name` to
`.github/workflows/qa.yml`.

CI sets NO identity today, and that is the *only* reason any of these seven
occurrences was ever caught. Supplying one turns every future instance green and
makes the runner permanently blind to the whole class — trading seven visible
failures for an unknown number of invisible ones. The fix runs the other way:
make the local environment as bare as the runner's. Filed as Decision 1 rather
than left as a note, so a later "CI is broken, add an identity" has something to
run into.
