## 13:35 · finding · N1 — 00384 DID consider it, and the reasoning is where the defect is

The ledger opened on the assumption this might be an oversight. Reading Plan
00384 rather than guessing reversed that: it considered the failsafe cron
explicitly and justified leaving it undeclared.

> `recovery_cron_advisor` already establishes this shape for the failsafe cron.

Checking "this shape" against the code is what turned a design choice into a
defect. The sentence defines the shape as *asserting at SessionStart*, and the
advisor does not do that:

```text
handlers/session_start/persistent_cron_assertor.py    SessionStart
handlers/post_tool_use/recovery_cron_advisor.py       PostToolUse
grep -l 'failsafe|recovery' handlers/session_start/   (no match)
```

`matches()` returns True only when `_detect_lifecycle_phase` finds a plan
CREATION/PROGRESS/COMPLETION moment. So a session gets its recovery net at the
first plan write, not at session start.

Worth recording that the counter-argument is real: if no plan work is happening,
there may be nothing to resume. It does not hold, because an `issue-sdlc` tick,
a release, a review or a long Q&A session can all stall without a plan write —
and a session that WILL do plan work is uncovered until its first one.

## 13:42 · finding · N2 — the push rule and the CI config were destroying each other

Flagged for hedging about CI state, so I checked instead of asserting. The check
returned something worse than the anecdote I had been repeating: not "a few runs
got cancelled" but 13 of the last 20.

That reframed it. I had been treating the cancellations as MY scheduling
mistake — something to work around by spacing pushes — and had even said so
twice. It is a configuration defect, and the workaround I invented was me
absorbing the cost of a bug rather than reporting it. `qa.yml` groups every push
to main under `refs/heads/main` with `cancel-in-progress: true`, so the standing
authorisation to never hold a push mechanically guarantees that the release
gate's evidence is destroyed.

Fixed rather than graduated: one line, reversible, and it needs no ruling
because it does not trade anything off — the repository is public, so runner
minutes are not metered, and PR branches keep the cheap behaviour.

Worth stating plainly: N1 came from a question the owner asked, and N2 came from
a hook telling me to stop hedging. Neither was found by the work itself.
