## 15:14 · decision · —   — settings.json not covered; self-install skipped

Decision: the managed .gitattributes block covers `.claude/hooks/**` and `.claude/init.sh`, NOT `.claude/settings.json`, and it is NOT written in self-install mode.

settings.json: it is a merged file. The daemon's registrations sit beside project-owned entries (permissions, other hooks, env). With `-merge`, a conflict keeps "ours" and writes no markers, so a genuine edit made on the other branch would be dropped silently, with no later signal beyond the unmerged index entry. The hook stubs and init.sh carry no project-owned content (they are generated), so keeping one side loses nothing: the next install or upgrade redeploys them. For settings.json, `reconcile-settings` re-adds missing daemon registrations, and the status line already reports invalid JSON. A conflicted settings.json is a loud, recoverable failure; a silently dropped project entry is not.

Self-install: this repository's own `.claude/hooks/*` are tracked source that developers edit on branches (and the generator rewrites them). `-merge` here would keep one side of a real edit and lose the other. Both install paths (`install.py` and `scripts/install/hooks_deploy.sh`) skip the block in self-install mode, and this repo carries no `.gitattributes`.

Wiring: one module, `claude_code_hooks_daemon.install.git_attributes` (`ensure_managed_block`, CLI `--project-root`). The shell step `deploy_gitattributes_block` in `deploy_all_hooks` serves both install_version.sh and upgrade_version.sh; `install.py` calls the function directly. Begin/end markers are `#` comment lines that cannot be mistaken for conflict markers. A begin marker without an end marker (or the reverse) is an error, never guessed at.
