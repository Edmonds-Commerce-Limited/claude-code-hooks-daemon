## 07:35 · finding · P1 — neither obvious proof works alone

Measured the seven real stale branches before designing anything, rather than
assuming what a proof should be. Neither candidate check is sufficient:

```
branch                                  ancestor  patch-equiv-upstream  unique-by-patch-id
agent-a02a4f175153ba3e7-2a8a9759        no        1408                  65
feature/00135-tmux-send-keys-injection  no         925                  59
feature/performance-tuning              no        1089                  57
worktree-agent-a42029b565a9e3299        no        1043                  57
```

Ancestry fails on all seven (the rewrite severed it), so `git branch -d`
refuses everything. Patch-equivalence nearly holds — the rewrite preserved
patch-ids while changing shas — but 57–65 commits per branch remain unique.

A single-check design would therefore either refuse every branch or approve on
a proof that does not hold. Hence the tiered model.

## 07:52 · decision · T1.1 — dropped the path-level tier during RED

Writing the tests exposed a flaw before any implementation existed. The draft
had a `content-subsumed` tier that passed when every path on the branch also
appeared somewhere in main's history. A path existing says nothing about the
CONTENT at that path, so the branch could still hold the only copy of a file
version — the tier could approve a lossy deletion, which is not a proof.

Replaced with `content-preserved`, which compares **blob shas**. Blob sha *is*
content identity in git. `test_a_path_main_knows_but_whose_content_differs_
stays_unproven` pins the difference so the weaker form cannot creep back.

## 08:20 · finding · T3.3 — the tool immediately corrected my own manual analysis

Before building this, I had hand-verified the seven branches and told the user
"nothing is lost". The tool contradicted that twice over, both times because my
ad-hoc checks were weaker than the ones I then codified:

1. My basename heuristic classified `AUDIT-v1.md` as "relocated" because *some*
   file of that name existed on main — the exact path-vs-content confusion the
   dropped tier would have baked in.
2. My blob check only examined path-unique files, so it found 1 content-unique
   file. The tool checks every blob in the tip tree and found 41–42 per branch:
   older versions of `CHANGELOG.md` and plan documents that main never had.

Corrected position: no whole file is lost (26 of 27 path-unique files are
byte-identical to blobs still in main), but the branches did hold unmerged WIP
edits. Stated plainly to the user rather than repeating the earlier claim.
