# Fact check: Plan 00475 PLAN.md (whole document, calibration run)

## REFUTED (most consequential first)

**R1. Claims 4 and 5: "CI, which already runs the full pytest suite on every push to `main`" (Non-Goals) and "CI runs the whole pytest suite off-host" / "which CI runs on every push to `main` anyway" (Design).**
`.github/workflows/qa.yml` classifies each push (`classify` job, line 47). The `targeted` job runs for `tier != 'full'` (line 90) and runs `llm_qa.py changed --range` (line 173) or the docs checks (line 169). The three-Python matrix job `qa` runs only for `tier == 'full'` (line 191). The whole pytest suite therefore runs on a push to `main` only for build/CI-config changes, nightly, dispatch, or when `scripts/ci/full_suite_if_unmapped.bash` finds an unmapped file. This is the plan's own Phase 3b. The Design mitigation ("the only thing deferred is the unmapped part of the pytest suite, which CI runs on every push anyway") is only partly true: the unmapped part runs via the fallback step (line 175), not as a whole-suite run. The Non-Goal "Changing CI" also contradicts Phase 3b, which changes CI. Plan change: reword to "the unmapped fallback and the nightly matrix", and drop or qualify the Non-Goal.

**R2. Claim 9: "the mapper does not link handler code to `tests/acceptance/test_playbook_harness.py`".**
`scripts/qa/changed_tests_map.yaml:91-92` maps `src/claude_code_hooks_daemon/handlers/*.py` to `tests/acceptance/test_playbook_harness.py`. The claim describes a past state. Plan change: say "did not, until the map entry was added", or state the fix.

**R3. Claim 10: "a repo-wide check that `changed` does not run" (the `eacces_safe` check).**
`eacces_safe` is in `CHANGED_TOOL_NAMES` (`scripts/qa/llm_qa.py`, about line 813). Same stale-past-tense issue as R2.

**R4. Claim 7: "Today `untracked/qa/.llm_qa.lock` is per checkout, and `hooksdaemon-full-qa.lock` covers whole-suite pytest only."**
`scripts/qa/llm_qa.py:143-153` defines `HOST_LOCK_NAME = "hooksdaemon-full-qa.lock"` under the git common dir. It is taken for every `llm_qa.py` run, with a bounded wait (`configured_wait_seconds`, default 600), and `tests/unit/qa/test_llm_qa_host_lock.py` exists. Only `scripts/qa/run_all.sh:46` still uses the per-checkout `untracked/qa/.llm_qa.lock`. The plan's own Task 2.3 and Success Criteria say this is done. Plan change: past tense, or "before Task 2.3".

**R5. Claim 6: "about 15 docs still tell the main thread to run `all` at every step".**
The listed docs now describe `all` as a release step: `CLAUDE/Worktree.md:175`, `CLAUDE/AgentTeam.md:57`, `CLAUDE/CodeLifecycle/Features.md:221`, `CLAUDE/CodeLifecycle/README.md:76`. `CLAUDE/CodeLifecycle/General.md:366` lists `all` but labels it "the release's Full tier, main thread only". This contradicts the plan's own Success Criterion ("No doc outside the release documents requires `llm_qa.py all`"). Plan change: past tense.

**R6 (internal inconsistency, minor). Claim 17: "All but `security_downgrade_flags` are cheap enough for the targeted tier."**
`dependencies` is among the eleven and is NOT in `CHANGED_TOOL_NAMES`. It is excluded because it judges the local venv, not because of cost (`llm_qa.py` comment near line 803; Task 2.1 says so). The sentence is cost-correct but misleading about what the tier runs.
