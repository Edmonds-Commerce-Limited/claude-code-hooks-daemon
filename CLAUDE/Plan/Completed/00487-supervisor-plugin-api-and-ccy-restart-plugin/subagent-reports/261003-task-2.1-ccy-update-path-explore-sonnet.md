**1. How Claude Code is installed and updated**
- It is baked into the image at build time. `CY/Dockerfile:134` runs `RUN npm install -g @anthropic-ai/claude-code`, and the entrypoint only sets `installMethod: native` in `.claude.json` (`entrypoint.sh:390`, Dockerfile comment at line 133).
- Nothing at container start installs it, and I found no `npm install` in `entrypoint.sh`.
- Claude Code's own auto-updater is not explicitly disabled. I grepped for `DISABLE_AUTOUPDATER` and `autoUpdates` and found no hits in `CY/` (Dockerfile, entrypoint or launcher). Only `DISABLE_INSTALLATION_CHECKS=1` is set (`Dockerfile:361`). The container runs as root with no `USER` directive (`Dockerfile:363`).
- ccy updates it from the host, once per day per image, as a gated step in the launcher (`claude-yolo:1455-1475`, help text at `:263`).
  - It compares the image's bundled version with the npm `latest` tag.
  - If the image is behind, `update_claude_inplace` (`claude-yolo:1585-1617`) runs `npm install -g @anthropic-ai/claude-code@latest` in a throwaway container. It then runs `container_cmd commit` over the image tag, with no full rebuild.
  - If the version is unknown (offline), it proceeds on the existing image.
  - `CCY_AUTO_UPDATE=0` turns this into notify-only.
  - `ccy --rebuild[=claude|project]` does the same update by hand (`claude-yolo:207`, `:1627-1645`, `:1765`).
- The install location is image-only. The only persistent mounts are `$PWD:/workspace` and the config import (`claude-yolo:2120-2123`), plus `.claude/ccy/mounts` and `CCY_EXTRA_MOUNTS`.
  - `/root/.claude` is replaced by a symlink to `/workspace/.claude/ccy` (`entrypoint.sh:310-322`). That holds sessions and settings, not the npm global tree.
  - The container is `--rm` (`claude-yolo:3262`), so any in-container update dies with it.

**2. Does restarting only `claude` pick up a new version?**
- No. A respawn inside the running container re-execs the same image-baked `/usr/local/lib/node_modules/@anthropic-ai/claude-code`. A newer version needs a new container started from a re-committed or rebuilt image.
- The sequence is: the host launcher's daily gate (or `ccy --rebuild=claude`) updates the image, then a fresh `podman run` uses it.
- A running container cannot be updated from the host without a new run. An in-container `npm i -g` would work for the current container only. It is not persisted, and it is a manual operation against the repo's IaC rules.
- Consequence for a restart plugin: "restart claude" fixes state and tokens, not the version. A version-refreshing restart must be a host-side relaunch, such as `ccy --resume` after the image update. That is the same host-relaunch shape Plan 00146 line 24 describes (`claude-yolo` relaunching itself with `--token X -- --resume <id>`).

**3. The supervisor wrapper line**
- The entrypoint picks the wrapper in this precedence (`entrypoint.sh:511-563`):
  1. `CCY_CLAUDE_WRAPPER` forwarded from the host.
  2. `CCY_CLAUDE_WRAPPER` exported by the project `ccy.env`, sourced just above. The tracked `.claude/ccy/ccy.env:17` sets `/workspace/.claude/ccy/claude-supervise.py --arm --`.
  3. The default at `entrypoint.sh:554`: `CCY_CLAUDE_WRAPPER="python3 $CCY_SUPERVISOR_PATH --"`. This is unarmed, and `CCY_SUPERVISOR_PATH` defaults to `/workspace/.claude/ccy/claude-supervise.py` (`:531`). It is syntax-checked first (`:544`).
- The exec is at `entrypoint.sh:566-568`. The wrapper string is split with `read -ra` and then run as `exec "${_ccy_wrapper[@]}" "$@"`. The `--` separator ends the supervisor's own flags, and `"$@"` is `claude --dangerously-skip-permissions <args>` (`claude-yolo:3262-3294`).
- The launcher side:
  - `--supervise` sets `CCY_CLAUDE_WRAPPER=python3 …/claude-supervise.py --arm --` (`claude-yolo:3172`).
  - `--no-supervise` sets `CCY_NO_SUPERVISOR=1`.
  - The container receives `-e CCY_CLAUDE_WRAPPER` and `-e CCY_NO_SUPERVISOR` (`claude-yolo:3280-3281`).
- To add `--plugin name=path`, put the flags inside the wrapper string. For example, extend the default at `entrypoint.sh:554`, or export it from `ccy.env`, as `python3 $SUP --plugin restart=/opt/claude-yolo/plugins/x.py --`.
- The supervisor currently has no `--plugin` flag. Its argparse (`.claude/ccy/claude-supervise.py:6827-6862`) parses only `--dry-run`, `--arm` and `--log`, after `argv[:argv.index("--")]`. That is the hooks-daemon API gap that Plan 00146's `UPSTREAM-REQUEST-supervisor-plugins-draft.md` describes.
- A ccy-owned plugin location outside the bind mount should be baked into the image under `/opt/claude-yolo/`. The Dockerfile already stages skills there (`Dockerfile:333-336`, `CCY_SKILLS_SRC`) and ships `CY/plugins/` (currently `phpantom-lsp`).
  - It must not go under `/root/.claude`, which is the symlink into the project, nor `/workspace`.
  - Everything in the container runs as uid 0. "Owned by the supervisor uid" means root with mode 0644 or 0755, set by `COPY --chmod`. Root-owned and not group/world-writable is easy to arrange there.
  - A Dockerfile change requires a version bump (see 4).

**4. ccy option parsing and the version-bump rule**
- Option parsing is a `for arg` if/elif chain in `claude-yolo`, from about line 600 to line 640.
  - Flags without values use a boolean, for example `--supervise` at `:610`.
  - Flags with values use a `NEXT_IS_*` flag, for example `--token` at `:624`, and `--update-token=` takes the `=` form.
  - Unknown args fall through to `CLAUDE_ARGS+=` at `:640`. That is why `--resume` and `--continue` are passed to Claude Code.
- A new `--max-age`, `--run-for` or `--until` goes in that chain, before the final `else`.
- Fail-fast validation of leftover `--*` flags against `claude --help` follows (`:650+`). An unconsumed flag would be rejected there.
- Add it to the help text (about `:200-280`) and to the completion word list (`:735`).
- Version bump rule (`.claude/rules/ccy-version-bump.md`, `CLAUDE/ContainerRules.md:92-108`):
  - Any launcher or `lib/*.bash` change bumps `CCY_VERSION` (currently `3.72.1`, `claude-yolo:17`), with a changelog entry in `docs/ccy-changelog.md`.
  - A Dockerfile or `entrypoint.sh` change also bumps `LABEL claude-yolo-version` (`Dockerfile:36`, currently `2.40`) and `REQUIRED_CONTAINER_VERSION` (`claude-yolo:73`, currently `2.40`). The two must match.
  - A pre-commit hook enforces the bumps.
  - Run `./scripts/qa-all.bash` before committing.
