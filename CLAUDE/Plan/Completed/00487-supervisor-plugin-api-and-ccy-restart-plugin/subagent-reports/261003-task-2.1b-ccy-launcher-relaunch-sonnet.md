## What it does

- New `lib/restart-request.bash` (registered in `CCY_LIBS`).
  - `ccy_restart_request_read` accepts only a regular, non-symlink file of 1 to 4096 bytes. It must be a JSON object with a UUID `session_id` and a numeric `requested_at` between 60 s in the future and 300 s old. The reason is printable-only and truncated.
  - `ccy_restart_request_discard` removes the file and refuses a directory.
  - `ccy_restart_budget_take` allows at most 3 restarts per project in 3600 s. `CCY_RESTART_MAX` and `CCY_RESTART_WINDOW_SECONDS` override. The history lives host-side in the update-check cache, so the container cannot reset it. A corrupt history is an error.
  - `ccy_restart_relaunch_args` builds the relaunch argv, NUL-separated. It keeps the ccy options, including `--ssh-agent`. It drops one-shot options and any opening message. It replaces `-c`, `--continue`, `-r`, `--resume` and `--session-id` with one `--resume <id>`.
- Launcher (`claude-yolo`):
  - Discards any stale request before the run.
  - Captures the container exit status with `|| container_rc=$?`.
  - On status 75, `ccy_handle_restart_exit` reads the request and consumes it first.
  - It then checks the budget, runs `update_claude_inplace "$IMAGE_NAME"` forced, and touches the daily stamp.
  - It then `exec`s `$SCRIPT_DIR/claude-yolo <relaunch args>`.
  - If the update or budget step fails, it exits 1 with the manual `ccy --resume <id>` command.
  - Status 75 with no file, or with a bad file (which is discarded), reports on stderr and exits 75 as before.
  - Any other status is passed through unchanged.
- Docs: changelog entry, `docs/ccy.md`, `CLAUDE/QA.md` table, and a gate in `scripts/qa-all.bash`.

## Notes for the plugin work

- The relaunch rebuilds the whole launcher flow. Anything the original run asked interactively (token and key menus) is skipped only if the original flags pinned it. Pinned flags are kept.
- The supervisor must write `requested_at` as epoch seconds, as `time.time()` does, and the session id as a UUID.
