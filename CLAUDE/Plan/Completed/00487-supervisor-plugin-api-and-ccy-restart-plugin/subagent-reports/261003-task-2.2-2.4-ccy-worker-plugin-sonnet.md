## What was built

- **Plugin (2.2)**: `files/var/local/claude-yolo/supervisor-plugins/ccy_lifecycle.py`. Stdlib only. `PLUGIN_API = 1`, `create_worker_half(api)`.
  - Config from `CCY_LIFECYCLE_MAX_AGE_SECONDS` (1800 to 2592000), `CCY_LIFECYCLE_DEADLINE_EPOCH`, `CCY_LIFECYCLE_WARN_MINUTES` (1 to 240, default 10, must be shorter than max age), `CCY_LIFECYCLE_LAUNCH_ID` (required when a feature is on). All absent means off: no state written, `on_idle` returns None. Invalid values raise `ValueError` from `on_start`, so the supervisor disables the plugin and tells the session.
  - State in `api.state_dir/lifecycle.json` (0600, atomic). The state dir survives a container restart, so a launch id decides: same id (hot reload) keeps the start time and flags; a new id (new container) restarts the age clock and the warning. Corrupt state raises rather than silently resetting.
  - Max age: `Notify(RESTART_SOON, minutes)` once at max age minus lead (minutes clamped to the time left); `ExitForRestart` at max age. The audit line for the request is written once.
  - Deadline: `Notify(DEADLINE_REACHED)` once, keyed by the deadline value, so a relaunch into a new container does not repeat it. It never exits. Once the deadline has been announced, the max-age restart stands down.
  - Decision on "forced restart": none. The supervisor only calls `on_idle` at idle, so a never-idle session restarts at its first idle after the age. Documented in the plugin docstring and `docs/ccy.md`. The 30 minute forced restart in DECISIONS.md item 4 is therefore not implemented.
  - Decision on defaults: max age is OFF unless `--max-age` or the host `CCY_MAX_AGE` is set. The 3 day / 10 minute values are the documented examples and the lead default, not an enabled default.
- **Launcher (2.3)**: new `lib/session-lifecycle.bash`, registered in `CCY_LIBS`.
  - Options `--max-age`, `--run-for`, `--until HH:MM` (help text and the did-you-mean list updated). Durations are `1d12h` style.
  - Validated right after argument parsing, before any prompt. A bad value gives a message with examples and exit 1 (a CLI flag value, not a prompt, so no re-prompt loop).
  - `--run-for` with `--until` is refused. `--no-supervise` with any feature is refused.
  - The relative deadline is resolved just before `container_cmd run`. A new `CCY_LIFECYCLE_LAUNCH_ID` is made per launch. Four `-e CCY_LIFECYCLE_*` flags are added to the run.
  - Registry classification: `--max-age` keep-value, `--run-for` and `--until` drop-value. `scripts/test-ccy-session-registry.bash` derives flags from the launcher and passes.
  - Entrypoint: `ccy_lifecycle_extend_wrapper` inserts `--plugin ccy-lifecycle=/opt/claude-yolo/supervisor-plugins/ccy_lifecycle.py` before the wrapper's final `--`, only when `CCY_LIFECYCLE_MAX_AGE_SECONDS` or `CCY_LIFECYCLE_DEADLINE_EPOCH` is non-empty. It fails the launch if the wrapper is not the supervisor line ending in `--`, if there is no supervisor, or if the plugin file is missing. With no option the tail is the old code path. A test confirms the default and armed wrapper lines are byte-identical.
  - Dockerfile: `COPY supervisor-plugins/`, chown root, directory 755, file 644, plus an `ast.parse` check. The playbook `play-claude-yolo.yml` has a new task copying the directory into the build context.
- **Relaunch (2.3, 2.4)**:
  - The deadline is absolute. `ccy_handle_restart_exit` exports `CCY_RELAUNCH_DEADLINE_EPOCH` before the `exec`. The relaunch drops `--run-for` and `--until` through the registry classes, and `ccy_lifecycle_validate_options` takes the carried epoch and unsets the variable. `--max-age` is kept, so its clock restarts with the new container.

## Notes and risks

- A project `ccy.env` could set `CCY_LIFECYCLE_*` itself. The plugin is validated either way, and the plugin path is fixed in the entrypoint (no override).
- The supervisor's `Notify` is typed after rate limiting, so the warning wording is the supervisor's fixed template. The plugin passes only the minutes.
- `--run-for`/`--until` with a session whose supervisor refuses `ExitForRestart` (more than one own session id after `/clear`) is unaffected. The `--max-age` restart request would be refused and logged by the supervisor, which is its documented behaviour.
