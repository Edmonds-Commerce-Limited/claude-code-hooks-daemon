## Trigger

`pull_request` to `main` plus `workflow_dispatch`. The release branch is named
**`release/<version>`** (Design 1 creates it; Task 3.1 must use that name).
`on.pull_request.branches` filters only the base branch, so the root `layout` job
has `if: github.event_name != 'pull_request' || startsWith(github.head_ref, 'release/')`.
Every other job needs `layout`, so a pull request from any other branch skips the
whole gate. `permissions: contents: read`, no secrets, `fail-fast: false`, and
`concurrency` keyed on the PR number (or the ref), with cancel-in-progress.

The 42 fast checks plus `tests` are 43, the full `ALL_TOOL_NAMES`. The `layout`
job enforces that, and checks that each Python runs every shard exactly once and
that one Python collects coverage. A new check or shard therefore fails the gate
until someone places it.

The perf_sweep tests are deselected in the shard runs (`PYTEST_ADDOPTS: -m "not perf_sweep"`)
because they miss their CPU bounds under coverage. They run only in `perf-sweep`.

### Script change: shard selection (TDD)

`run_test_matrix.py` could not select a shard, so it gets two flags:

- `--shard NAME` (repeatable): run only those shards, under the running
  interpreter only. It plans no extra interpreters; any other version is a
  `ProvisionError`. It reaches no coverage verdict. A leg with a `rest` shard
  is serial, so `ensure_daemon` restarts an idled-out daemon before each shard.
- `--coverage` (only valid with `--shard`): run as the primary (`run_tests.sh`).
  Each shard's coverage data is kept for the `coverage` job.

With no flags, `llm_qa.py tests` and the local stage behave exactly as before.
The tests are in `tests/unit/qa/test_run_test_matrix_shard_selection.py`: 14
tests, RED first and then green. They cover argument parsing, `plan_selected`,
`this_interpreter_only` and `selected_primary_report`. The existing
run_test_matrix tests (124 in all with the new file) pass.

## Daemon idle approach

**There is no config or env route.** `daemon.idle_timeout_seconds` is read only
from the tracked `.claude/hooks-daemon.yaml`. No env variable overrides it (only
log level and input validation have one), and the loader has no overlay file.
Editing the yaml on the runner would dirty the tracked tree that the tests and
the leg-checkpoint digest read, so I rejected that. The fallback is the trial's
keepalive: every 60 s it connects to the socket and starts the daemon if nothing
answers, bounded by `timeout 10800`. It runs only in the `rest` jobs, it is
commented as a fallback, and it logs to `untracked/daemon-keepalive.log`, which
is uploaded with the artifacts. The per-shard `ensure_daemon` covers the gap
between shards. Trial re-run 39719698731 was still in progress, so the keepalive
is not yet proven by a run.
