# Plan 00476 Task 3.1: release procedure rewritten for the release pull request

Branch `worktree-476-release-procedure`. Task 3.1 is ticked in PLAN.md.

## What changed

`CLAUDE/development/RELEASING.md` is the single source; the procedure follows
Design 1 to 4 and 7.

- **Step numbering kept.** Steps 1 to 15 keep their numbers and meanings, so
  the many references across the repo (Step 3, 5, 6, 1c, 8b, 10, 11, 12.0,
  12.4, 14, 15.1) still hold. Step 8 is still "the QA gate", now in CI. What
  changed per step:
  - **1b**: no local full QA. Main Claude cuts `release/X.Y.Z` from the
    CI-green `main` (no `v`, which `release-gate.yml` requires). Then the agent
    validates: clean tree, on the release branch, versions, no tag, gh auth.
    The state file is written after 1a returns 0, as before.
  - **1H** now runs after 1b and commits on the release branch.
  - **7.1 (new)**: commit on the release branch. The "stage src/ too" warning
    moved here from the old Step 13.
  - **8**: release pull request plus CI gate. **8a** pushes and runs
    `gh pr create --base main --head release/X.Y.Z`, then writes the `ci`
    record (pr_number, run_id, head_sha, conclusion `pending`) at once,
    because that record arms the freeze. **8b** is the start-up budget, still
    local. **8c** waits with `timeout 7200 gh run watch <run_id> --interval 60 --exit-status`
    in the background (or `gh pr checks --watch` under the same timeout), then
    records the real conclusion. Every push starts a new run, which must be
    recorded and waited for.
  - **9 to 12** may run while 8c waits. The Step 12 FAIL-FAST cycle is now:
    targeted QA, commit, push, record the new run, wait, restart, rerun.
  - **13**: verify CI and merge. 13.1 nothing left uncommitted or unpushed.
    13.2 `scripts/release/check_release_ci.py`. 13.3
    `git merge-base --is-ancestor origin/main HEAD` (the branch is up to date).
    13.4 `gh pr merge <N> --merge --match-head-commit <head_sha>`, then
    `git switch main && git pull --ff-only`.
  - **14**: tag the merge commit. 14.0 requires `HEAD^2 == ci.head_sha` and
    `HEAD^{tree} == <head_sha>^{tree}` before the tag. Body, tag, `gh release create`
    and `publish_bootstrap_assets.sh` are as before.
  - **15**: delete the merged release branch and the state file (this lifts the
    freeze).
- **New section, "The Release Pull Request and the Merge Freeze"**:
  - Why a pull request.
  - Why the merge commit of an up-to-date pull request has the gated tree.
  - What R-RELEASE-MERGE-FREEZE blocks, and what it does not: the release
    branch push, the tag push and `git pull`.
  - If `main` moved: merge `origin/main` into the release branch, push, CI
    re-runs, re-record, re-enter Step 13.
  - Finishing or aborting lifts the freeze.
- The state-file section now covers:
  - the `pending` conclusion, and when the record is written and rewritten;
  - both of its readers;
  - resuming past Step 8: switch to the branch, never open a second pull
    request.
- Updated: the Pipeline Overview, Rollback (abort = close the pull request,
  then delete the state file), Manual Release, Prerequisites and Related.

**Skill and agent.** `.claude/skills/release/SKILL.md` and `invoke.sh` are
