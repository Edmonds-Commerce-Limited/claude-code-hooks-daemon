## Design

- One matrix job `check`, `fail-fast: false`, `timeout-minutes: 360`, `permissions: contents: read`, no secrets.
- Set-up copied from the qa.yml `targeted` job: checkout `fetch-depth: 0`; setup-python 3.11 with pip cache; `pip install --user uv`; venv built at the fingerprint path by `resolve_venv.sh` with `uv sync --frozen --all-extras`; venv bin on `GITHUB_PATH`.
- Every job writes `.claude/hooks-daemon.env`, sets `HOOKS_DAEMON_RELEASE_GATE=1` and runs `./bin/hooks-daemon restart` and `status`, because any check may probe the daemon and it is cheap.
- Extras by check: `tests` sets up Python 3.11, 3.12 and 3.13 (3.11 first so it is the default `python`), because `run_test_matrix.py` runs the suite under every Python in qa.yml's matrix. `shell_check` and `shell_audit` apt-install shellcheck. `tests` and `smoke_test` build the relay (rustup musl target, `relay/build.sh`, install to `untracked/bin/hooks-relay`).
- Upload: `actions/upload-artifact@v4`, name `qa-<check>`, path `untracked/qa/`, `if: !cancelled()`.
- Timing: the job duration (`gh run view --json jobs`) is the wall-clock. The run step also prints `check=<name> exit=<rc> seconds=<n>` for the check alone, separate from the set-up time.

## How each check is invoked

`./scripts/qa/llm_qa.py "$CHECK"` with the check name taken from the matrix through `env: CHECK`, one tool per call. llm_qa writes `untracked/qa/<tool>.json`, the artefact. Checks flagged `live_daemon` (`tests`, `smoke_test`) start the daemon themselves if it is down, as well.

## Known or likely problems on a runner (from reading llm_qa, not yet confirmed)

- `tests` is the long one. It runs `run_test_matrix.py`: the primary Python's whole suite with coverage, then each extra Python in its own venv under `untracked/qa-interpreters/` (provisioned with uv; the extras' unit tests run in parallel with the primary, their other directories run serially). Locally this is one process tree on a loaded host. On a runner it is one job of probably more than an hour, so it is the sharding candidate for Task 1.2. `test_shards.yaml` already names slices of `tests/` for it. The `perf_sweep` tests (Task 2.2) are still inside it here.
- `llm_qa.py` takes a host-wide lock and stamps provenance against the worktree state (`worktree_state`, `stale_reason`). Per-tool runs on a fresh checkout should be unaffected, but this is untested on a runner.
- Checks that read git state (`git_history`, `released_changelog`, `repo_hygiene`) depend on full history and tags, which the checkout provides. A push-triggered checkout is a detached head at the pushed sha, not the branch name, which could matter to anything that reads the current branch.
- `semgrep` and `pyright` rely on dev extras and (pyright) the runner's node; both are in the frozen sync, so they should work, but they are unconfirmed.
- Nothing in the checks was found that needs a secret or the network beyond uv, pip and apt.
