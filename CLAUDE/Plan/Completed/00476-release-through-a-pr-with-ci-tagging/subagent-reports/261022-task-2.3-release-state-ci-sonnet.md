# Task 2.3 report: release state file records the CI run (Design 7)

## Design

- `untracked/release-state.json` gains an optional `ci` object with exactly four
  required fields: `pr_number` (positive int), `run_id` (positive int),
  `head_sha` (40 lowercase hex), `conclusion` (non-empty string). Unknown or
  missing fields, wrong types and bools-as-ints are errors. Other top-level keys
  are untouched (legacy keys such as `publish_authorised` still tolerated).
- `scripts/release/check_release_ci.py` (new) verifies on resume: the record
  exists, conclusion is `success`, `head_sha` equals `git rev-parse HEAD`, and
  `gh run view <id> --json conclusion,headSha` still reports the same
  conclusion and head sha. Each failure prints one line
  `release-ci: <reason>: <detail>` to stderr and exits 1. Reasons: no-state-file,
  unreadable-state-file, no-ci-record, malformed-ci-record, ci-not-green,
  head-not-tested, live-run-mismatch, live-run-unavailable, head-unresolvable.
  There is no offline or fallback path.
- Seams: `main(argv, head_resolver=, fetch_run=)` and `verify(..., fetch_run=)`;
  tests never touch the network.
