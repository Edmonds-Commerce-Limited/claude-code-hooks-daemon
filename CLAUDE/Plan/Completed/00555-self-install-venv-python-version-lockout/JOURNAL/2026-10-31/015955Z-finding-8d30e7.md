## 01:59 · finding · —

The DBF fix branch caused a regression, and it is now fixed on `p555-dbf-fix` (`f43d472fb`).

- **Symptom:** the full QA gate hung for over 90 minutes. The py3.11 and py3.12 `unit-daemon` legs stopped inside `tests/unit/daemon/test_cli_cmd_start.py`. On 3.13 the same file fails 4 tests with BrokenPipeError. Main passes all 30 tests in that file, so the branch caused it.
- **Cause:** `cmd_start` reaps stale venvs on every start (`_cleanup_proven_stale_venvs`, `_enumerate_venvs`, `live_venv_realpaths` and `classify_untracked_venvs`). On the branch those functions judge each candidate through `venv_interpreter_usable`, and the gate ran its probe even when `bin/python` was absent. That spawned processes for nothing on the start path. The test helper `_starting_child` patches `os.pipe` and holds the first pipe opened, which was now a probe's pipe and not the start pipe.
- **Fix:** the gate returns False for a missing interpreter or a dangling symlink without launching a probe. Absence is proof of unusability, so it does not trust the exec bit. Test: `test_the_gate_refuses_a_missing_interpreter_without_launching_it`, red before the fix.
- **Also fixed in the same commit:** the detector's remediation text and its `qa-rules.json` fix advice named `_venv_interpreter_runs`, which no longer exists. They now name the gates in `GATES`.
- **Process note:** the QA run had no per-test timeout, so a hang in one leg held the host QA lock for over 90 minutes before the watchdog tick surfaced it.
