# Plan 00555 Task 2.3: `repair` without a working venv

## Problem

A venv with a matching `pyvenv.cfg` version resolves, yet it cannot import
`claude_code_hooks_daemon`. The wrapper then exec'd the Python CLI and died with
`ModuleNotFoundError`. A rebuild would also have reused that venv, because its lock hash matches.

## Change

- `bin/hooks-daemon` and its template (byte-identical, one `cp`):
  - `_package_importable` runs `timeout ${HOOKS_DAEMON_IMPORT_PROBE_TIMEOUT_SECONDS:-20} "$PYTHON" -c 'import claude_code_hooks_daemon.daemon.cli'`. A hang counts as "cannot import".
  - The probe runs for the `repair` verb only, after the interpreter resolves. Every other verb and the hook hot path pay nothing. Other verbs were deliberately not probed: a CLI import on each would be a cost, and `repair` is what names the fix.
  - On failure, `_explain_unimportable_venv` runs Task 2.4's `paths.py diagnose-venv --daemon-dir D --venv-dir V` under the venv's own `bin/python`, never a bare `python3` (main's rule since 63913dd53), bounded by the same timeout. It also prints the probe's own error text. `bare_python_invocation` passes.
  - The wrapper then re-enters the existing `_run_venv_free_verb` repair arm. That arm takes two new variables, `_VENV_FREE_REASON` and `_VENV_FREE_REBUILD`.
- `scripts/venv_bootstrap.sh`: `repair <daemon_dir> --rebuild`. `_vb_repair` takes the flag as a second argument and sets `_VENV_FORCE_REBUILD=1`. Any other third argument is a usage error.
- `scripts/install/venv.sh`: `_venv_is_fresh` returns 1 when `_VENV_FORCE_REBUILD=1`. This covers both the lock-free check and the re-check under the lock in `_ensure_venv_build`.
- `tests/venv_bootstrap_sandbox.py`: `timeout` added to the sandbox tool set.

  - plain bootstrap `repair` still reuses a lock-fresh venv;
  - `--rebuild` rebuilds it;
  - an unknown third argument is a usage error.
- A healthy-venv case is covered by the existing `TestRepairWithAVenvIsUnchanged`, which stubs the bootstrap driver. It still passes.
- I ran `test_bin_hooks_daemon_repair_*`, `test_venv_bootstrap_driver.py` and `tests/unit/install` together. 2251 passed. The only failure was an over-strict assertion of mine, which I removed: the diagnosis legitimately prints the probe's `ModuleNotFoundError`.
