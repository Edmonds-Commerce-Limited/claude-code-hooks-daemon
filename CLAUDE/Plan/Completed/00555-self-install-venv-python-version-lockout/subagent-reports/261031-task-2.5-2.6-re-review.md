## Bypass hunt

### Glob dialect differences
No bypasses. Every difference makes the port stricter than the daemon, never looser:
- **Case:** both matchers are case-sensitive, so `Secrets/**` does not cover `SECRETS/db.txt` in either.
- **`**` forms:** `**`, `a**b`, `***/x`, `x/**/`, `**/`, `/**/q` and `**/b/**` all agree.
- **Leading `./` and trailing `/` in a glob:** treated as literals in both.
- **`!`, `{a,b}`:** literals in both.
- **`[…]`:** the port's extra `fnmatch` check treats it as a character class, so it also protects `a.key` under `[ab].key`. Stricter only.
- **Newlines:** the port's `**` and prefix cross a newline and the daemon's do not. Stricter only.

### Symlinks, odd paths and outside paths
All denied:
- A symlink with a harmless name pointing at a protected file (`cat notes.txt`, and Read of it).
- A symlinked directory leading to a protected file (`cat harmless_dir/db.txt`, `git log -- harmless_dir/db.txt`).
- Symlink loops (`cat loopA`, `cat loopA/x`, Read of `loopA`).
- `cat` of a directory (`cat secrets`, `cat a`).
- Paths with an embedded NUL or newline, and paths with a trailing `/`, `/./` or `//`.
- `cat /etc/hostname`, Read `/etc/hostname`, and Read of a file outside the repo.
- `git log -- :/config/credentials.yml`.

Two results are allowed and match the daemon matcher, so they are not new gaps: `ls harmless_dir` and `ls secrets` list file names (not contents) under a `secrets/**` glob. Realpath on a path that does not exist ends in `isfile` being false, so it is denied.

### N1 (new, CONFIRMED, low): Read can reach outside the project through a symlinked directory
**Location:** `/workspace/init.sh:498-510`, `_path_allowed`.

The I1 fix runs the containment check and the `isfile` check only on the physical realpath. The lexically normalised path now only gets the `_is_protected` glob test. A Read is resolved lexically, so it can open a file the judge never checked.

**Setup:** `dl` is a symlink to `<proj>/a/b/c/d`, a decoy `<proj>/a/b/decoy.txt` exists, and the target `<root>/decoy.txt` lies outside the project.
- Read `<proj>/dl/../../decoy.txt` → **ALLOW**.
  - The judge checked the physical path `<proj>/a/b/decoy.txt`.
  - Node's `path.resolve` gives `<root>/decoy.txt`, and `readFileSync` returned `OUTSIDE`.
  - The pre-fix `judge_lib.py` denies this, so it is a regression.
- `cat dl/../../decoy.txt` → ALLOW, which is correct: bash opens the inside file.

Only files outside the project that match no protected glob can be reached this way (for example `~/.aws/credentials`). It also needs a planted directory symlink plus a decoy file inside the project, which is outside the careless-agent threat model, so it is not merge-blocking.

**Fix:** also require `_relative_to(absolute, root)` for some root, plus `isfile`/`isdir` on `absolute`. This is the "keep the lexical check as a second check" from the original I1 fix. Add a red test for Read `<proj>/dl/../../decoy.txt`.
