# Plan 00555 Tasks 1.1 and 2.2: interpreter-drift detection

## Change

- `src/claude_code_hooks_daemon/daemon/paths.py`
  - `_venv_interpreter_runs` now runs a probe that prints `major.minor` and fails when the venv's `pyvenv.cfg` records a different one. The resolver's metadata step (step 2), keyed step (3) and scan step (4) all use it, so a drifted venv falls through to the existing build path.
  - New `venv_cfg_major_minor` (first `version_info` or `version` line wins), `venv_interpreter_drift`, `_drift_reason`.
  - `classify_venv` returns `stale` with an "interpreter drift" reason. The check runs after the slug-eligibility check (another view's venv stays `unproven`) and before the metadata check, so a lock_hash match no longer keeps a drifted venv.
- `scripts/lib/resolve_venv.sh`: `_rv_candidate_runs` uses the same probe code. New `_rv_cfg_major_minor` and `_rv_check_cfg_drift` apply the same rule. `_rv_pick_python` therefore skips a drifted venv, and the wrapper falls to its no-venv path.
- A cfg with no version line, or an interpreter whose output cannot be parsed, is "cannot tell" and passes in both layers.

## Tests (written first, red 8 of 16, then green)

- `tests/unit/daemon/test_paths_venv_interpreter_drift.py`: the probe, resolver steps 2 and 4, and `classify_venv`.
- `tests/integration/test_resolve_venv_interpreter_drift.py`: bash and Python parity for both cfg keys, plus `_rv_pick_python`.
- Fixed `tests/unit/daemon/test_cli_unproven_venvs.py`. Its fixture linked `bin/python` to the real interpreter but hardcoded `version = 3.11.2`, which now correctly reads as drift. It now records the running version.

## Known gaps (not in scope)

- The bash hot-path cache (`resolve_venv.sh` around line 473) serves the cached path without probing. After drift it keeps returning the stale venv until the mtime of `untracked/` changes. A follow-up needs a cheap version check there.
- `_rv_check_cfg_drift` is skipped when `mktemp` fails (no probe output to read). The Python layer still catches the drift in that case.
- The re-key and rebuild half of Task 2.2 (editable install, dev extras, renaming the directory) is the builder's job and is untouched. Detection now lets the existing build path trigger.
