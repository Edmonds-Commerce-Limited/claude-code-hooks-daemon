## 15:05 · finding · P1 — the banner printed; the wording was the bug

The field report read like an agent ignoring a mandate. Traced the actual
path instead:

- The deployed skill shim (`skills/hooks-daemon/scripts/upgrade.sh`) carries
  no upgrade logic — it FETCHES `scripts/upgrade.sh` from `main` and execs
  it, so Layer 1 was current, not stale.
- Layer 1 checks the target version out into `DAEMON_DIR` FIRST ("Step 8:
  Delegate to Layer 2 (now available after checkout)") and only then runs
  `$DAEMON_DIR/scripts/upgrade_version.sh` — so Layer 2 is the NEW version's
  script.

The v3.60.0 banner therefore did print, saying "MANDATORY NEXT STEP: run the
config-optimisation review **in your next Claude Code session**" — printed
immediately after "IMPORTANT: Restart Claude Code… 1. Exit your current
Claude Code session". The agent complied with what it was told.

The client's from_version is recoverable from the report: it named
`dispatch_declaration`, `subagent_report_size_blocker` and
`config_optimisation_reminder` (all v3.59.0) plus
`budget_exhaustion_detector` (v3.60.0) as new, so it came from ≤v3.58.x.
