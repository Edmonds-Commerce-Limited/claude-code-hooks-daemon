# Plan 00495 Task 2.4: skip the CLAUDE.md format when the block is unchanged

Commit: 9456b40fe (code, test, release note 066). The PLAN.md tick and this report are the follow-up commit.

## Assumptions (owner may rule otherwise)

1. Where the "what was formatted last time" record lives: inside the repository's git dir
   (`<git-dir>/hooks-daemon-claude-md-format`, two SHA-256 lines). Chosen because it is never tracked, needs no
   `.gitignore` entry in client projects (a new root sidecar would have needed one plus a gitignore_safety_checker
   entry), and is per worktree. Outside a git repository nothing is recorded and every start formats, as today.
2. A formatter failure is remembered like a success. The formatter is deterministic, so identical input fails
   identically and the fallback written is the input itself. The cost: after a failure the formatter is not retried
   until the block or the file changes, and its warning is not repeated each start.
3. Why not compare "the block on disk" with the generated block directly: the disk holds the formatted block and the
   generated one is raw (tables are unaligned until formatted), so they are never byte-equal. The record is the
   formatter's own (input, output) pair instead.

## Design

`ClaudeMdInjector._format_or_reuse(updated, original)`: if the remembered pair equals
`(sha256(updated), sha256(original))`, the file already is `format(updated)` and is reused; otherwise
`_format_fail_safe(updated)` runs as before and the new pair is recorded after the write. The comparison covers the
whole file, so an edit anywhere (not only inside the block) still reaches the formatter. A concurrent-edit retry still
works because the check runs inside the existing re-read loop. A changed block is formatted by the same function as
before, so its output is identical (test below compares against a never-cached run).

Steady state is reached on the second start after a change: the first formats the new block, the second formats once
more because its input now sits in an already-formatted surround, and from the third start the input is stable.

## Measurement

Method: Phase 1's (the injector on this repository's CLAUDE.md, CPU time, no profiler). A throwaway git repo holding a
copy of the 113,844-byte CLAUDE.md, a stub handler returning that file's own block as promoted guidance, two injects to
reach steady state, then `time.process_time()` around 5 `inject()` calls. "Before" is `git archive HEAD` of the parent
commit put on `PYTHONPATH`; "after" is the worktree. Three interleaved rounds, host loaded by other agents' work.

| round | before (median of 5) | after (median of 5) |
| ----- | -------------------- | ------------------- |
| 1     | 0.194 s              | 0.0062 s            |
| 2     | 0.209 s              | 0.0064 s            |
| 3     | 0.211 s              | 0.0065 s            |

Note: this is lower than Phase 1's 0.39 s figure for the same step (a different host load, and process_time here
excludes the git child processes). The saving is the whole formatter cost, about 0.2 s here. The script is
`untracked/scratch/measure_inject.py` (not committed).
