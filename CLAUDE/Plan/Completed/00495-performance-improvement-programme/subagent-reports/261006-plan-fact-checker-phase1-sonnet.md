## PARTIAL (wording to tighten)

- C13 "`docs-qa-sweep` ... recomputed in full every start" (Task 1.2) and Task 2.6 "no cache". `build_and_save_corpus` (`src/claude_code_hooks_daemon/docs_qa/corpus.py:835-873`) reuses cached per-file records when mtime and size are unchanged, and persists an index. What is recomputed every start is the SWEEP-stage `run_stage` check run (`docs_qa_sweep.py:90-95`), plus the `stat` walk. So there is no result cache, but the corpus parse IS incrementally cached. Say "no result cache; checks re-run in full".
- C6 "YAML config parsed about 4 times": the profile shows 4 `yaml.safe_load` calls inside the harness (`prof-cum.txt:27`), but the harness runs `find_and_load` once. The real `cmd_start` path also loads before forking (`daemon/cli.py:633`) and again in the child (`cli.py:855`), so real parses per start are at least as many as profiled. "About 4" is a floor for the daemon child; not wrong.
