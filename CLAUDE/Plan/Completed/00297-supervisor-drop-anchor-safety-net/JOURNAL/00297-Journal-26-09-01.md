TDD: 10 new tests appended to `tests/unit/supervise/test_drop_anchor.py`
(escalated-anchor sends ESC; reason names observed model/effort; no ESC
before escalation; no ESC while `reading.compacting`; ESC fires once
compaction clears if still violated; ESC's own cooldown rate-limits repeats;
the cooldown never blocks the independent effort retry; state round-trips
through export/import; legacy state defaults safe; a fresh episode is never
throttled by a prior episode's ESC cooldown).

Implementation in `.claude/ccy/claude-supervise.py`:

- `_ANCHOR_ESC_COOLDOWN_SECONDS` (60s, own cooldown, separate from
  `_ANCHOR_RETRY_COOLDOWN_SECONDS`) and `_DRY_RUN_ANCHOR_ESCAPE_BODY`.
- `CompactStateMachine._anchor_esc_last_sent_ts`, `anchor_esc_due()`
  (active AND escalated AND cooldown elapsed), `mark_anchor_esc()`; reset
  to `None` alongside the rest of the anchor's per-episode state whenever
  `_evaluate_anchor` clears the invariant, so a fresh violation is never
  throttled by a stale prior-episode cooldown.
- `decide_once`'s DROP ANCHOR block gained an ESC branch, checked ahead of
  the existing `/effort low` retry branch: when the input box is empty, no
  compaction is in flight (`reading.compacting`), and `anchor_esc_due()` is
  true, the decision becomes `Decision.WOULD_ESCAPE` with the REUSED
  `_ESC_PAYLOAD`/`submit=False` keystroke path (armed) or
  `_DRY_RUN_ANCHOR_ESCAPE_BODY` (dry-run) — the same mechanism
  `AWAIT_COMPACTING`'s ESC-flush already uses, not a parallel one. A new
  `is_anchor_escape` flag on `TickOutcome` (with JSON round-trip for the
  worker split) lets the HOST's `_apply_post_injection_bookkeeping` call
  `mark_anchor_esc` only for this send, distinct from the flush's own
  `_escapes_sent` counter.
- The compaction guard closes a real edge case found while implementing:
  `machine.state` stays `MONITOR` on the very FIRST tick that observes
  `reading.compacting` (before `_enter_await` can run, inside the
  `evaluate()` compacting branch which returns `WOULD_CONTINUE`), and the
  anchor block already treats `WOULD_CONTINUE` as `anchor_preempts_continue`
  — so without an explicit `reading.compacting` check, ESC could fire on
  the exact tick a compaction starts. Guarded with a local
  `compacting_in_flight` check inside the anchor block.
- The retry-until-verified `/effort low` correction is UNCHANGED — it keeps
  firing on `anchor_injection_due()`'s own cooldown regardless of the ESC
  branch's cooldown state, so ESC clearing the turn and the effort retry
  landing remain two independently-timed corrective actions, not a
  sequential dependency.
