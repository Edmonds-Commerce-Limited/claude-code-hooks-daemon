## Chosen entry file name

```
<plan>/JOURNAL/YYYY-MM-DD/HHMMSSZ-<category>-<6 hex>.md
```

- One `date -u +%Y-%m-%d %H%M%S` call gives the folder and the time, so a midnight straddle cannot split them.
- 6 hex from `/dev/urandom` (`od`): two writers in the same second with the same category collide with odds 1 in 16.7M,
  and the file is created with `noclobber`, so even that collision fails loudly instead of overwriting.
- Four-digit year in the folder (brief), so a folder never reads as a plan folder (`NNNNN-<letter>`).
- The file holds `## HH:MM · category · REF   — title`, a blank line, the body. The heading grammar is unchanged, so
  `journal_entry_headings` reads it as one entry. No preamble per file: the grammar is documented once.
- `--ref` is unchanged (`HH:MM` today, `YY-MM-DD/HH:MM` earlier). A minute may now match several entry files; a
  correction voids that minute on that date, as it already did inside a day-file.

## Reading order

Sort every entry of a plan by `(UTC date, HH:MM, source rank, name)`:

- legacy day-file entry: date from the file name, `HH:MM` from the heading, source rank 0, file order kept;
- entry file: date from the folder, `HH:MM:SS` from the name, source rank 1, then file name.

Worked example, plan 00543, both layouts on one day:

```
JOURNAL/00543-Journal-26-10-21.md       ## 16:40 action   (legacy, written before the switch)
JOURNAL/00543-Journal-26-10-21.md       ## 17:05 finding
JOURNAL/2026-10-21/170500Z-action-3fa2c1.md   ## 17:05     (same minute: legacy first)
JOURNAL/2026-10-21/171233Z-decision-0b9e44.md ## 17:12
JOURNAL/2026-10-22/090101Z-handoff-77d0aa.md  ## 09:01     (newest; the next agent's entry point)
```

The newest entry is the last file of the newest date folder, unless a legacy day-file is dated later (only possible on a
branch cut before the switch).

## Does the map make the design wrong?

No blocker, three adjustments:

1. Checks only see `JOURNAL/` direct children today, and `classify` puts nested files in `JOURNAL_OTHER`. Keeping entry
   files one folder down means an OLDER daemon sees them as `JOURNAL_OTHER` and reports nothing false (issue's point),
   but the new checks must opt them in explicitly. Only date-shaped folders count, so an existing non-date subfolder of
   `JOURNAL/` is not suddenly judged.
2. The reframed today-only rule closes legacy day-files to every edit, including removing conflict markers by hand.
   That was already blocked for any day-file not dated today; the route stays `mkplan.bash --resolve-conflict`.
3. The commit-stage half of "never edited" must not flag the `git mv` into `Completed/` (a content-identical rename),
   so it judges `M` and `D`, and an `R` only when content changed.
