## 15:18 · finding · P2 — coverage failure was a concurrent-pytest artefact

The first full QA run reported `tests` at 92% (fail_under 95) and flagged
`claude-supervise.py` at 47%. Root cause: I ran foreground `pytest`
(flag-compact + effort-restore checks) WHILE the background `llm_qa.py all` was
collecting coverage into the shared `.coverage` file — the two clobbered each
other (pyproject already notes parallel `--cov` is fragile here). Proof: REST
of the tree was 96.43% and the file's own tests give it 91.34%; corrected
overall ≈ 96%. Re-ran QA cleanly (nothing else touching pytest) → **25/25
PASSED, coverage 95.1%**. Lesson: never run a foreground pytest while a
coverage QA run is in flight.
