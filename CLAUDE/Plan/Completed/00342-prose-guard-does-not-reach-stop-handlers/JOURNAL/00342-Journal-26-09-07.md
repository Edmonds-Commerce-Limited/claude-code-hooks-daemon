## 19:32 · thought · — — why this one fails quietly, which is why it is worth a plan

A prose false positive in a PreToolUse handler produces a wrong DENY: loud,
immediate, and the agent is told exactly what happened. The same defect here
produces the opposite — the marker arms, cron ticks are dropped before they
reach the model, and the only symptom is something NOT happening.

A session could lose its recovery net for a whole day (the marker's default
expiry) and the transcript would show nothing at all. That asymmetry is the
argument for extending the guard rather than relying on review.

## 19:55 · decision · T2.1 — anchoring is out, and that was measured too

The obvious fix is to copy the token's: anchor the prose patterns to the
declaration position. Tested it before writing code, and it fails:

```
first-sentence match=True   STOPPING BECAUSE: blocked only on human input - need a decision...
first-sentence match=False  STOPPING BECAUSE: I have finished everything I can. The release needs the owner's decision.
first-sentence match=False  STOPPING BECAUSE: all three plans are at their limit. Waiting on the user's decision about scope.
```

Two realistic, legitimate declarations would stop arming. Plan 00337's
Non-Goals forbid regressing wordings that work today, so anchoring is out —
for a demonstrated reason rather than a hunch.

**The rule that survives: a match inside a QUOTED span does not declare.** An
agent ASSERTS a blockage and CITES a phrase. No legitimate declaration quotes
itself, and quoting is the shape this plan's own Evidence describes.

This is the OPPOSITE call to `security_antipattern` and `sensitive_content`,
which refuse a quoted-span exemption on purpose. Not an inconsistency: there,
quoted text can still EXECUTE, so exempting it is a one-character bypass. Here
the text is a message and can never run.

## 20:00 · finding · T1.1 — `_denies()` would have made the Stop axis vacuous

The guard's existing predicate asks "did the handler DENY?". Copying it to the
Stop axis would have produced a guard that passes on every input, because
`AutoContinueStopHandler` writes the marker as a SIDE EFFECT and then returns
its normal decision. The guard would have looked healthy while covering
nothing — and the failure it exists to catch is already silent, so nothing
else would have surfaced it either.

`_arms_suppression()` therefore observes the marker FILE, against a redirected
untracked dir. Consequence, not decision.

**The apostrophe hazard is the subtle part, and the integration guard cannot
see it.** Two frozen patterns contain an apostrophe — `the owner's input`,
`the user's decision`. Naive single-quote pairing reads that apostrophe as
OPENING a span running to the next one, swallowing the phrase the pattern
exists to match. The narrowing would then have silently disabled the very
patterns it was protecting — a fix quietly becoming the bug. The single-quote
arm requires a non-word character on both sides, and
`test_an_apostrophe_never_opens_a_quoted_span` pins it.

## 20:10 · decision · T2.3 — the residue is a decision, and it is asserted

Unquoted prose describing the mechanism still arms:

> "The daemon drops a tick when a session declares it is blocked only on human
> input."

Not separable lexically from "the release is blocked only on human input",
which MUST arm. The difference is semantic. Rather than leave that implicit,
`test_unquoted_prose_about_the_mechanism_still_declares` asserts the current
behaviour, and its docstring says that making it False later — without
regressing the assertions above it — is an IMPROVEMENT, not a regression.

This is the outcome Plan 00337 designed for. The sentinel exists so the
patterns can stay frozen and imprecise; chasing the residue with another round
of widening is the thing that has already failed twice.
