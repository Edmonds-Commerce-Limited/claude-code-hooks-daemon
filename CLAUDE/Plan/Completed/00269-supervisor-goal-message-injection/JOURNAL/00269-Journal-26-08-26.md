## 08:05 · action · P3 — code-review fixes (verdict: FIX FIRST)

Coordinator review returned three findings; all applied TDD-first:

1. **SECURITY — verbatim header gate.** `_validate_goal_lines` accepted any
   payload merely PREFIXED with the marker, so anything able to write the
   signal file (a bash redirect is enough — this handler's own recorded
   Bash-blindness verdict) could get arbitrary text, including asserted
   human consent, typed into the chat. The gate now requires the joined
   payload to open with the ENTIRE fixed header verbatim (alone, or followed
   by the separator); new `_GOAL_HEADER_TEXT` supervisor constant with a
   lockstep test asserting it equals `goal_injection._HEADER_TEXT` (mirrors
   the supervisor `__version__` lockstep pattern), plus a forged-payload
   RED test (marker prefix + malicious consent text, valid caps → REJECTED)
   and a header-only ACCEPT test.
2. **MEDIUM — cap burned on failed injection.** `decide_once` incremented
   `goal_injections` before the PTY write; a write failure burned the cap
   while the signal survived for retry. The decision is now pure:
   `_apply_decision` returns whether a payload was actually injected, and
   BOTH hosts (in-process `_poll_once`, worker path in `_on_poll` — after
   adopting the worker's pre-increment state so it is not overwritten)
   count the goal only on success. Tests: decide_once exports count 0;
   successful `_poll_once` increments + consumes; OSError writer leaves
   cap 0 and signal on disk.
3. **Small.** `inject-goal` no longer reads `ProjectContext._initialized`:
   it initialises unconditionally (RuntimeError = already initialised,
   logged at debug; ValueError remembered) and a write failure now names
   the real cause ("project context unavailable: ...") instead of "see
   daemon log" — with a test.

**Deliberate decision (recorded, not an accident):** the dogfood
`.claude/hooks-daemon.yaml` enables `goal_injection` in THIS repo. That is
signal-only exposure — the handler just writes `<session>.goal-intent`
