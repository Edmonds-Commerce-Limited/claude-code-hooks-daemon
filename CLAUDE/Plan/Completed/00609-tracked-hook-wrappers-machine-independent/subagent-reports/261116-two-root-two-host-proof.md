# Plan 00609 proof: hook wrappers are byte-identical across checkout root and hostname

Commit proved: `e76583327f516fd16bc086969a506877a71545e8` (main). Tracked tree clean.
origin/main is `fbbf9ca5f` (a descendant; HEAD is an ancestor of it, so this is NOT at origin/main: 1 or more newer commits exist, the newer one is a test-timing change per its title).
Re-run: `/workspace/.venv/bin/python /workspace/untracked/scratch/proof-609/prove.py` (exit 0 only if all checks hold).

## Method
- Two root shapes, each run under two hostnames, one fresh Python process per combination with real env HOSTNAME and XDG_RUNTIME_DIR (and a different uid-like value in the latter) set: short root (21 chars, fits AF_UNIX) and long root (130 chars, overflows AF_UNIX by 70-78 bytes, daemon's real events dir is then `/tmp/hooks-daemon-<hash>-<hash>-events`, the shape that used to be baked). Roots carry `src/claude_code_hooks_daemon/` so they resolve to the self-install layout `<root>/untracked`, the same as /workspace.
- Generation: (a) `generate_forwarder_content` for all 31 top-level `.claude/hooks/*` wrappers, from the bare source (the generator's own strip of the tracked wrappers), for three transports (relay, nc, both); (b) the real deploy path `regenerate_deployed_hooks` over a copy of the tracked wrappers.
- Hostname: the generator never reads a hostname at generation time (no hostname call in forwarder_generator.py); the generated bash derives `-${HOSTNAME:-localhost}` (lowercased, spaces to `-`) at RUN time. So host-independence holds by construction and is also shown by the byte comparison. The generating process does see a hostname suffix via `paths._get_hostname_suffix` (shown in the output), which the wrappers do not contain.

## Not proved / caveats
- A real OS hostname change could not be forced: `unshare -Ur --uts` is unavailable here, so only the HOSTNAME env var varied (socket.gethostname() stayed the container's). The generator does not read it, so the claim stands, but this is untested at OS level.
- Self-install layout only. A client install puts the untracked dir at `.claude/hooks-daemon/untracked`, so its wrappers differ from this repo's by that fixed relative layout string (a layout difference, not a machine one); not exercised here.
- The wrappers were not executed at run time here (the repo unit tests do that); this proof is about generated bytes.
- The "tracked" comparison is an idempotence-plus-generation check: generated-from-stripped equals tracked, and regenerating tracked rewrites nothing.
- Step 5 loads the pre-00609 generator from `git show 8ea7c03c6^1:...` as a scratch module.
