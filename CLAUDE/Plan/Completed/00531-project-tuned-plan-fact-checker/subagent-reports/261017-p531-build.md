# Plan 00531 build report

## Assumptions (owner-level choices, recommended and carried on)

- The tuned agent is named by `handlers.post_tool_use.plan_fact_check_feed.options.tuned_agent`, one string, empty by default. The feed's existing options surface (setattr of `_<key>`) carries it with no new config model.
- A configured name that is unsafe (not a plain slug) or whose `.claude/agents/<name>.md` is absent falls back to the generic agent with a logged warning, rather than failing the hook.
- The derived-from marker is a new line, `hooks-daemon-derived-from: <shipped agent> <version>` in an HTML comment, which the project puts in place of the copy's `hooks-daemon-agent-version` line. It is distinct from the agent-version marker because a copied template keeps that one by accident, and the shipped-revision ledger classifies by md5 and name, so a tuned copy never enters it.
- The tuning advice is given once per project: a `tuning-advised` marker file in the fact-check state directory, appended to the first delivered instruction while the generic agent is in use.
- Template version bumped to 1.1.0 (its header text changed); 1.0.0 is ledgered as a historic revision so pristine deployments upgrade.

## Reused paradigm

- `install/agent_assets.py`: version markers, shipped-revision md5 ledger, `historic_versions`. Added `DerivedAgent`, `derived_from_marker`, `stale_derived_agents` beside `classify_agent`.

- The feed's option mechanism (`apply_handler_options`) and `confirm_dispatch`, now matched on the resolved agent name.
