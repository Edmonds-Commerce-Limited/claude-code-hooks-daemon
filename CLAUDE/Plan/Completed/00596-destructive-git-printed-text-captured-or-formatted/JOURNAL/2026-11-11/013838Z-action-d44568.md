## 01:38 · action · — — Plan complete: #197 closed, merged 5638615ac, main CI green; fail-closed redesign

Plan 00596 is complete. It merged at `5638615ac`, main CI run 42936949523 is green, and GitHub #197 is closed.

**What review caught.**

- Round 1 approved with two suggestions: a written script fed to a shell on stdin, and `printf -v`.
- Round 2 found that the fix for those carried a `cat` across `;` and `&&` and over-blocked ordinary commands.
- Round 3 found the structural flaw: 18 commands that run the written git text were allowed. The capture relaxation removed a deny whenever `_runs_written_script` returned false. That function can only CONFIRM a run, and returns false whenever it cannot read a word. So `sh "$x" < s.sh`, `$SHELL s.sh`, `${!r}`, `declare -n`, a write to `~/.bashrc`, and a write to a git hook all slipped through.

**The redesign fails closed.** A print-only capture is data only when every segment of the command is:

- an assignment from a print-only substitution;
- an `echo`/`printf` (not `-v`) with no redirect; or
- a pure-formatter pipe stage.

An independent check over 362 probes confirmed it: 8 commands go from deny to allow, all #197 shapes, and 29 go from allow to deny, all running written text.

**Lesson.** A detector that can only confirm danger must never be the condition for removing a deny. Relax on a positive proof of safety (an allowlist of the whole command), not on the absence of a detected danger. This is the same shape as Plan 00478's lesson: converting a deny-by-default net exposes every gap the net was silently catching.

The follow-ups are listed in PLAN.md. None of them lets a destructive command run.
