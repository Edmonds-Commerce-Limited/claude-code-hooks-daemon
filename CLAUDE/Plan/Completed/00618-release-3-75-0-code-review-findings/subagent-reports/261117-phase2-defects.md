## Owner decisions

1. **N-7 and N-8 (the B-2 area).** Fixing either would make the stop guard allow stops it refuses on main.
2. **T-7.** Removing the false positive would allow a branch creation that main denies, because `bash -s script x` cannot be told apart from a command that does run the script.
3. **Task 2.5, daemon half.**
   - **The constraint.** `lint_on_edit`'s 15 s `Timeout.LINT_CHECK` runs under the 20 s PostToolUse chain deadline.
   - **Why it was not load-scaled.** A scaled budget above about 15 s is cut off by the chain deadline, which produces a "skipped" reply. The harness does not recognise that reply as INCONCLUSIVE, so it would turn today's skip into a hard failure.
   - **What a real fix needs.** The three-layer event budget the Worktree events use: PostToolUse entries in `EVENT_HANDLER_BUDGET`, `EVENT_CHAIN_DEADLINE` and `EVENT_CLIENT_WAIT`, the `init.sh` mirror, and the registered hook timeout.
   - **Existing finding.** A configured per-language lint timeout above about 15 s, such as the documented `PHP: 30` example, is already cut by the chain deadline today.
4. **Partial notes inside fixed items** (N-11, N-12, N-14) are listed in the table. None of them turns a deny into an allow.
