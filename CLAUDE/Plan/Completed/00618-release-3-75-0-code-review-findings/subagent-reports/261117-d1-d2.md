## What changed

The change is in `branch_stop_guard._pressure_findings`, the only source of the DORMANT and OVER_CAP stop findings. Its only caller is `_judge_branch`, which runs on main-thread stops for the session's own branches.

- **D-1.** The DORMANT finding gets `advisory=True` when `dormancy.mode == "warn"`. The OVER_CAP finding gets it when `wip.mode == "warn"`. `branch_stop_gate.decide_stop` already sends advisory findings to context ("Branch left behind (advisory): ...") and keeps them out of the deny and the block counter. Mode `off` still produces no finding, and `block` still denies.
- **D-2.** The over-cap count now calls `branch_sweep.open_work_count(inventory)`, the existing tip-deduplicated `pool_count(..., Pool.OPEN)` helper. It replaces the by-name `sum(...)`. No count logic is duplicated, and no import cycle results (the gate already imports `branch_sweep`).
- **Docs.** `docs/guides/CONFIGURATION.md` now covers the stop behaviour in the dormancy paragraph and the `wip.cap` / `wip.mode` row, including that branches on one tip count once. `docs/guides/HANDLER_REFERENCE.md` gets the same in the branch stop guard entry, which never mentioned the dormant and over-cap checks before.
- **Release note 093.** It says plainly that both changes allow stops the previous build denied.

## Where this could loosen beyond D-1 / D-2

Both changes deliberately allow stops that main denies. Beyond that:

1. **Repeated warnings.** In `warn` mode the advisory line repeats on every stop while the condition holds, with no hourly throttle like the noisy line. That is noise, not loosening.
2. **Dedup across local and remote.** The same-tip dedup also folds a remote-only twin into its local branch, because `same_tip_as` is computed over local-or-remote tips. That is the same definition the creation guard and `open_work_count` already use, so the stop count now matches them rather than being looser than them.
3. **Unchanged behaviour.**
   - `stop_guard.mode` still governs the dirty, unpushed and merged checks on its own.
   - `merged.mode` and `parked.mode` were not wired in, which would have gone beyond D-1.
   - The stop guard still compares `open > cap` and ignores `creation_grace`.
4. **Nothing else touched.** The block counter, the handover rules and the sub-agent path are unchanged. Pressure findings never ran for sub-agent or handoff stops, and still don't.
