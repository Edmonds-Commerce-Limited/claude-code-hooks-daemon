## Task 2.5 measured constraint (owner decision)

- `Timeout.LINT_CHECK` is 15 s. PostToolUse runs under `CHAIN_DEADLINE_DEFAULT` 20 s (no `EVENT_CHAIN_DEADLINE` entry); the client waits `SOCKET_DISPATCH_ROUNDTRIP` 30 s; the registered hook timeout is 60 s; the harness probe dispatch is `2 * max(LINT_CHECK, ESLINT_CHECK)` = 60 s.
- Scaling `_timeout_for` above 15 s alone is cut by the 20 s chain, giving a "skipped" text `inconclusive_probe` does not recognise: a hard failure instead of a skip. Not done.
- The real fix is the three-layer Worktree pattern for PostToolUse: a lint ceiling, `EVENT_HANDLER_BUDGET`/`EVENT_CHAIN_DEADLINE`/`EVENT_CLIENT_WAIT` entries, the `.claude/init.sh` `_event_socket_wait` mirror with `test_event_budgets.py`, the settings template timeout, and the probe timeout derived from the ceiling. It lengthens how long any hung PostToolUse handler holds a session, so it is the owner's call.
- Finding either way: a configured per-language lint timeout above about 15 s (the yaml example documents `PHP: 30`) is already cut by the 20 s chain deadline today.

## User-visible changes (release note)

- A slow config lock no longer holds the plan-number guard past its deadline; it fails fast after 2 s.
- A relay repair can no longer be started after the daemon stop began.
- The QA scope walk now fails on a corrupt git index instead of treating the tree as "not a repository".
- A failed worktree add no longer deletes a directory git still lists.
- `record-venv-tracking` refuses `--tracked-sha`/`--last-release-tag` without `--tracked-ref`.
- `branch-sweep` and `branch-preflight` help text follows the real batch size and exit code.
- A failed events-dir location write leaves no temp file.
