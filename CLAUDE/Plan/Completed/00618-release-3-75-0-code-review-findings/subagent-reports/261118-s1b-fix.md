## What changed

### F5 and F1: shell-state tildes

- **Root cause.** `Path.expanduser()` raised on `~+` and `~-`, because it reads `+` as a user name. The secret guard turned that raise into an advisory allow. The flaggable guard turned it into a deny.
- **Fix.** `recursive_search.expand_tilde` replaces the call. `~` and `~user` for a real user are expanded as before. Every other tilde fails closed in both guards: `~+`, `~-`, `~N`, `~+N`, `~-N`, and an unknown `~user`.
- **Where it applies.** The tilde fails closed wherever it appears:
  - as a `git -C` or `--work-tree` value;
  - as a search root;
  - as a `git grep` path or pathspec;
  - in a later read after a `cd`/`pushd` to such a tilde. A segment that reads nothing stays allowed.
- **`~+` is not placed at `$PWD`.** The RED commit pinned `~+/sub` as ALLOW. Placing it precisely would have turned the tip's crash-advisory rows into silent ALLOW rows, so `~+` fails closed instead. The fix commit flips those pins to DENY.

### F2: the flaggable guard's `git -C` placement

- **`cd` is followed.** A relocated `git grep` is placed from where the shell is after an earlier `cd`/`pushd`, including one inside `( ... )`. It is also still placed from the payload cwd. Either placement reaching the flagged directory denies.
- **Hidden `-C` values deny.** That covers a `-C` value containing an `xargs -I`/`--replace` token, and any `-C` under `parallel`.
- **Ancestors deny.** A `-C` above the project counts as reading the whole project, for example `git -C .. grep --no-index` from the root. This applies only to the shell placement, which is where git really runs.
- **Expansions are unchanged.** A `-C` built by an ordinary expansion (`$X`) still gets the unplaced advisory (Plan 00478).
