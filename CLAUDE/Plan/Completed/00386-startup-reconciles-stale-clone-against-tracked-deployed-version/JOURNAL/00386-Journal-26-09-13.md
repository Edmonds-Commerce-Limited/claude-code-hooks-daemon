## 11:29 · finding · — — the close was never gated; the plan document said otherwise

This plan recorded that its final criterion was left unticked because
"closing a plan is human-approved in this project
(`plan_workflow.close_requires_human_approval`)". That was false, and it was
written as fact into both this plan and 00389.

Checked rather than re-assumed:

```text
.claude/hooks-daemon.yaml:1051   close_requires_human_approval: false
plan_close_approval.py:110-111   if not self._close_requires_human_approval: return False
```

`matches()` returns False before touching anything else, so the handler is
inert here and no Write/Edit of a `**Status**:` line was ever going to be
denied. The plan sat finished-but-open across a multi-day cron run on a gate
that does not exist, and the owner was briefed to run two `approve-plan-close`
commands that would have done nothing.

The daemon message that *is* involved was accurate: `header-body-coherence`
says "Flip the status header to `**Status**: Complete` (and move the plan to
the archive directory per the plan lifecycle)" — an instruction to close, not
a refusal.
