## 12:44 · finding · N1 — it is the same mechanism as Plan 00388, not a sibling

The instinct was a cadence backoff mirroring Plan 00337. Reading the suppressor
instead of designing from memory changed the answer:

```python
# failsafe_cron_blockage_suppressor.py:269
is_cron_prompt = isinstance(prompt, str) and CANONICAL_CRON_PROMPT_MARKER in prompt
```

`CANONICAL_CRON_PROMPT_MARKER` is the literal `"FAILSAFE RECOVERY CHECK"`, so no
other cron can ever satisfy it — and a prompt that fails it CLEARS the marker.
So suppressing this cron needs the handler to recognise an automated tick, which
is exactly the question Plan 00388 is blocked on, and the marker would be wiped
before it could be read anyway.

Neither ships usefully alone. That is a dependency, not a resemblance.

## 13:26 · finding · — — a terminal crash did NOT test the cron declaration

Asked directly whether the persistent-cron system had worked after a terminal
crash, and whether the `issue-sdlc` cron had been re-created. It had not been —
and that is the answer, not a failure:

```text
CronList after the crash:  57ccaf1d (failsafe), 482c9b7f (issue-sdlc), f7c00aa1 (watchdog)
CronList before the crash: 57ccaf1d,             482c9b7f,             f7c00aa1
```

Identical IDs, and no `CronCreate` call was made after the crash. So nothing was
re-established; the crons survived. The reason is that the session was RESUMED,
not restarted: one session dir only (`c3d160b5-…`), no new transcript, the same
`c3d160b5-….jsonl` still being appended, and the backgrounded `gh run watch`
re-spawned at 13:19:13 with the same run ID it was given at ~13:12.

**The consequence: this crash exercised none of the declaration machinery.** It
is untested by this event. What it does establish, and what was not written down
anywhere, is that "session-only" means session-SCOPED, not process-scoped — a
crash-and-resume keeps crons, and only a genuinely new session ID starts empty.

Recorded and NOT filed as a niggle, deliberately. The daemon's SessionStart text
says crons "have to be re-created after each new session starts", which is true
of a new session and says nothing false about a resume. No defect was observed,
and inventing one to look thorough is the failure the ledger exists to prevent.
