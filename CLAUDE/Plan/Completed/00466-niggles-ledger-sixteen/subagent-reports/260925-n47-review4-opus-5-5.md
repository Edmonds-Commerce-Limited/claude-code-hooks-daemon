## Finding details

### 1 (MAJOR): the removed DROP ANCHOR can return undetected

**Reproduction.** In a copy of HEAD, insert after `payload = _resolve_payload(...)` in `decide_once`:

```python
if payload is None and can_inject and reading is not None and _model_family(reading.model_id) == "fable" and reading.effort not in (None, "low"):
    payload = "/effort low"
```

Run `tests/unit/supervise`: 806 passed. `probe_n47r4_anchor_test.py` (a Fable 5.1 reading at `high`, one tick) shows `payload: None` on HEAD and `payload: /effort low` when mutated. No suite test drives a Fable reading above low through `decide_once`. This is the most prominent behaviour N47 removed. The NIGGLES entry (`:88-94`) says "RED tests … prove the supervisor never EMITS `/effort` in any scenario … `probe_n47r3_scenarios.py`-style payload-level assertions cover the rest". That probe is an untracked reviewer scratch file, so it is not coverage.

**Direction.** Add payload-level tests that drive `decide_once`, `_poll_once` or `run_worker` with real sidecar sequences and assert that no payload starts with `/effort`. Cover at least these cases:

- Fable at each of medium, high, xhigh and max;
- an attributed downgrade and its whole episode;
- a manual `/model`;
- compaction and resume;
- a human-typed `/effort` through the raw-input tap.

Then correct the NIGGLES sentence to name those tests.

### 2 (MAJOR): the daemon still prescribes a global effort pin

**Reproduction.** Look at `src/claude_code_hooks_daemon/handlers/session_start/optimal_config_checker.py:121-145`:

- `passed = effective == "high"`.
- The `why` text says "Medium/low saves tokens but reduces quality".
- The `fix` is `{"effortLevel": "high"}` or `export CLAUDE_CODE_EFFORT_LEVEL="high"`.

It is run by `_run_checks()`, which `cli check` reuses. The hooks-daemon skill's `check.md:25,43` shows `[OK] Effort Level: effortLevel='high'` as the healthy state. With the owner's intended config (per-model entries and no top-level key), `cli check` reports Effort Level as FAILED, "not set". If the owner follows the env-var fix, `CLAUDE_CODE_EFFORT_LEVEL` outranks everything (model-config.md:546) and pins every model for every session. Fable is then no longer at low, the fallbacks are no longer at xhigh, and Opus 5.5 is no longer at medium. The fixer's commit message says finding 10 is fixed, but only the write was removed. The daemon still carries a second effort opinion, and that is what the SSoT requirement rules out.

**Direction.** Stop judging a level. Either drop the Effort Level check, or turn it into an SSoT check that passes when effort is left to settings.json. It should WARN when `CLAUDE_CODE_EFFORT_LEVEL` or a project/local top-level `effortLevel` is set, since those override per-model `modelSettings`. Update `check.md` and the `test_optimal_config_checker.py` effort tests (`:146-185`) to match.

### 3 (MINOR): the item-C latch accepts a record at any later time

**Reproduction.** `probe_n47r4_scenarios_test.py::test_s3`, run in `probe_n47r4_tree2`, output in `probe_n47r4_scenarios.out`:

1. A Fable reading, then an Opus reading, with no record. This is the human's manual pick, and it sets the latch.
2. 30 minutes later, still on Opus, a `fable→opus` record with a NEW `record_ts` appears for this session.
3. The supervisor opens an episode and types `/model fable`.

The race the latch exists for is short: the reading renders before the PostToolUse recorder publishes. The latch lives for as long as the session stays on the fallback.

**Direction.** Bound the retro attribution. Accept it only when the record's own `record_ts` (the transcript time of the fallback) is not later than the drop observation plus a small skew. Or expire the latch after a bounded number of ticks or seconds. Add a test for "a record arriving well after a manual pick opens nothing".

### 4 (MINOR): an untimestamped record re-arms on a manual switch

**Reproduction.** `test_s1` in the same probe:

1. An auto downgrade with `record_ts: ""`. The episode opens, the restore lands, and the episode closes. `spent` stays `None` (item E's rule).
2. Two hours later, the human manually picks Opus.
3. `_downgrade_is_attributed` matches the still-republished `""` record, and `/model fable` is typed at the human.

In review 3's framing, E fixed "the second untimestamped downgrade is missed" by reopening the MAJOR-4 fight for that same class of record.

**Direction.** Give the record a real identity when the timestamp is missing, for example the transcript record's `uuid` or line offset in `model_fallback_records.py`. Then spend that identity, so neither edge fails.

### 5 (MINOR): individual M4 guards are unpinned

See the table in item 3. The most important survivors are these:

- "Retro does not stamp record_ts". Without it, the retro episode never spends.

**Direction.** Add one test per guard, each asserting on the `/model` payload, not only on `downgrade_episode`. Also add an export/import round trip for `pending_unattributed_drop`.

### 6 (MINOR): the restored cap test is self-referential

`test_model_restore.py:224-230` loops `range(_mod._MAX_MODEL_RESTORES)`. **Direction:** hard-code the expected cap (2). Assert that restore N-1 still fires and restore N does not. Add a session-change close test.
