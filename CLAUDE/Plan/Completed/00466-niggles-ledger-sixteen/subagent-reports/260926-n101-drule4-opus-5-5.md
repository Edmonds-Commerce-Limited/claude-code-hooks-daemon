## The allowlist, entry by entry

None of the entries can run text as shell or as code through its options:

- **`cd`, `pushd`, `popd`, `pwd`:** no evaluation. `pushd +N` is parsed as a plain number, not as arithmetic.
- **`echo`, `true`, `false`, `:`:** their arguments are only expanded. The expansions that can run code are withdrawn: any `${...}` other than a plain name, `$((`, `$[` and `$(`.
- **`mkdir`, `ls`, `cat`, `grep`, `sleep`:** none has an option that runs anything.
- **`set`:** only xtrace runs PS4, and every spelling of it withdraws the exemption. `-k`, `-T` and `-o posix` run nothing.
- **`export`:** the operand pattern rejects options and array subscripts.
- **Python:** this entry is sound only on the premise that code text reaches a shell by nothing but a run-time self-read. The MAJOR below is about that premise.

**The wrappers:** the stated reasons are sound. `sudo -A` runs an askpass file, and `command -p` uses the system default PATH. Neither takes text from the command line.

**The wrapper-grammar narrowing** (removing `E`, `D`, `R`, `chdir`, `chroot`, `preserve-env` and `env -C`) only makes callers stricter. `_receiver_is_data_sink` and `_downstream_is_all_data_sinks` treat `None` as "scan it". `quoted_heredoc_command_words` drops `None` (`shell_segmentation.py:983`), but `strip_quoted_heredoc_bodies` judges each heredoc on its own. I probed `sudo -E bash`, `sudo -R / cat` and `env -C / cat` heredocs, and all three bodies were kept for scanning.

**Other round-4 changes:** each one either adds enumeration or withdraws the exemption, so none loosens a rule. They are `skip_parameter`, `$[`, `saw_bare_paren` now applying anywhere, the unquoted-heredoc check, `printf` leaving the sibling list, `_decodes_as_utf8` and the `LookupError` handling.
