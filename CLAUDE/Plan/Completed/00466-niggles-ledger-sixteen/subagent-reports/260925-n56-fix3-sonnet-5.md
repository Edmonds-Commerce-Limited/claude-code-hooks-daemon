# N56 fix round 3 report (Sonnet 5)

Branch `worktree-n466-n56`. Scope: review 3's two blocking items.

## What changed

`tests/integration/test_no_root_conditioned_skips.py`:

- New `_root_polarity(node, ctx)`: whether a proven root-related condition
  evaluates `True` when the process IS root, `False` when it's `True` only
  when NOT root, or `None` when this scan can't tell. Needed to decide which
  branch of an `if` actually runs as root — `_is_root_expr` only proves the
  condition is identity-related, not which direction.
- New `_is_vacuous_pass_guard` + `_is_pass_only`/`_is_noop_or_empty`: catches
  `if <root check>: pass else: <real check>` (review 3's
  `match_guard_pass`) — a `pass`-only branch opposite a substantive one is
  the same early-exit-for-root shape as `return`/`skip`, just spelled as
  "do nothing". Gated on `_root_polarity` so the reverse shape (no-op on the
  non-root branch, real work on the root branch — which still runs, always,
  in this always-root container) is correctly left alone.
- New `_contains_assert` + a check in `_if_guarded_findings`: an `assert`
  gated by an identity condition with no `else` at all, where
  `_root_polarity` is `False` (true only when NOT root), is now flagged
  (`assert_only_when_nonroot`) — the assertion silently never runs as root.
  First cut ignored polarity and false-positived on the existing
  `getuid_used_non_skip` fixture (`if root: assert True`, no else — fine,
  since it DOES run as root); `_root_polarity` fixed it.
- NIT: `lambda_in_dict` (`_checks = {'root': lambda: ...}` then
  `_checks['root']()`) now resolves — `_resolve_context` collects a dict
  literal's constant-keyed lambda values into `ctx.lambdas` under a
  synthetic `dict_name[key!r]` name, and `_resolved_bare_call_name` renders
  a `Subscript` call site the same way, so the existing fixed-point loop
  over `ctx.lambdas` resolves it exactly like a bare zero-arg lambda call.
- `try_except_permission_pass` recorded as a documented, owner-referred
  residual: new `_KNOWN_RESIDUALS` dict + `TestKnownResidualsRemainUncaught`,
  asserting it stays uncaught (so a future fix flips that assertion red
  instead of the note drifting stale). No syntactic root check exists in
  this shape at all — the root-dependence is a runtime property of what
  `open()` does, which review 2's own proposed remedy (a runtime probe
  diffing the collected/skipped set under both identities) would need, not
  another AST case.
- Module docstring, `CLAUDE/QA.md` and the plan's `NIGGLES.md` N56 section
  updated to describe the two new shapes and the residual.
- Corrected fix round 2's report: its "all 41 ... pass" claim was false (3
  missed); added a correction note pointing at review 3 and this round.
