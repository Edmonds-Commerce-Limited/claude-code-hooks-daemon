# N56 review 1: root-conditioned skips (branch `worktree-n466-n56` @ 6ae2158f)

Adversarial review. Every claim below was checked by running something. The
probes are in `/workspace/untracked/scratch/probe_n56r1_*`. The mutations were
made in a `git archive` copy (`probe_n56r1_copy/`), never in the branch. The
worktree was clean at the end (`git status --short` printed nothing).

## Verdict: NOT READY

The three rewritten tests are good. The detector is not. It lets through the
exact defect that Plan 00351 found, which the deleted test did catch. It also
misses most of the evasion shapes the brief listed. The release note and the
QA.md text claim more coverage than the detector has.

## Findings, ranked

### F1 (HIGH): regression, the Plan 00351 shape is no longer detected

`tests/integration/test_no_root_conditioned_skips.py:68-85`
(`_mentions_root_uid`) fires only on a `getuid()`/`geteuid()` call compared
to 0. The deleted `test_skipif_reasons_match_their_conditions.py` keyed on the
reason text ("as root", "running as root", …). That is how it caught
`skipif(Path("/").stat().st_uid == 0, reason="Running as root")`. Probe
`skip_reason_mentions_root_other_condition` is MISSED by the new detector.

The new file's own docstring (lines 3-10) cites this defect as its origin. The
replacement is therefore weaker than what it replaced on the one shape with a
real history in this repository. Fix: keep a reason-text leg. Any
`skipif`/`xfail`/`skip` whose reason names root should fail, whatever the
condition is.

### F2 (HIGH): the detector misses most of the brief's evasion shapes

`probe_n56r1_detector.py` result: **15 of 24 root-skip shapes missed**.

Missed:

| Shape                                                                        | Why it is missed (line)                                                 |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `IS_ROOT = os.geteuid() == 0` then `skipif(IS_ROOT)`                         | only the literal arg subtree is walked, no name resolution (`:102-104`) |
| conftest `requires_non_root = pytest.mark.skipif(_ROOT, …)` using a constant | same                                                                    |
| `def _is_root(): return os.geteuid() == 0` then `skipif(_is_root())`         | same                                                                    |
| `if not os.geteuid(): pytest.skip(...)`                                      | requires a `Compare` with a constant 0 (`:77-80`)                       |
| `skipif(not os.geteuid(), …)`                                                | same                                                                    |
| `os.geteuid() in (0,)`                                                       | the 0 sits in a Tuple, not a Constant operand                           |
| `pwd.getpwuid(os.getuid()).pw_name == "root"`                                | no comparison to 0                                                      |
| `getpass.getuser() == "root"`                                                | no uid call at all                                                      |
| `@unittest.skipIf(os.geteuid() == 0, …)`                                     | `_CONDITIONAL_MARKS` is `skipif`/`xfail` only, case-sensitive (`:42`)   |
| `if os.geteuid() == 0: self.skipTest(...)`                                   | `_SKIP_CALLS` lacks `skipTest` (`:47`)                                  |
| `if … == 0: raise pytest.skip.Exception(...)`                                | `Raise` is not a guarded statement (`:113-121`)                         |
| `if os.geteuid() != 0: … else: pytest.skip()`                                | only `node.body` is checked, never `orelse` (`:130`)                    |
| `skipif(condition=os.geteuid() == 0, …)`                                     | only `node.args[0]` is read, not the `condition=` keyword (`:100-102`)  |
| `skipif("os.geteuid() == 0", …)` (pytest string condition)                   | a string constant is not parsed                                         |
| `skip_reason_mentions_root_other_condition`                                  | F1                                                                      |

Caught: `os.getuid() == 0`, `0 == os.geteuid()`, `from os import geteuid`, a
conftest marker with an inline condition, `pytestmark = …`, an
`if … : pytest.skip` in a helper or fixture (including after another
statement), `if … and …: return`.

No false positives: "project root" wording, a root-worded reason on an
unrelated condition, and a `geteuid()==0` guard that does not skip all come
back clean. The full scan of the repository passes today.

  modules under `tests/` are not scanned. One of them,
  `tests/relay_gate_guard.py`, handles skips. The rest of the QA.md wording
  (the rule, the fault techniques) is accurate and reads well.

### F5 (LOW, outside this diff, same class): a chmod fault root bypasses, with no skip

`tests/unit/handlers/stop/test_auto_continue_stop.py:1121-1141`
(`test_matches_handles_oserror_reading_transcript`) sets `chmod(0o000)` and
expects the OSError path. `probe_n56r1_mode000` confirms root reads a mode-000
file. So as root the test takes the normal read path, and it passes without
ever exercising the OSError branch. It does not skip, so the letter of the N56
rule is met, but "every test must prove its behaviour as root" is not. The
same fix technique applies. Also worth noting: `tests/daemon/test_paths.py:845`
calls `skipTest` when `/run/user/{uid}` is absent. `/run/user/0` does not
exist in this container, so it skips here. The skip depends on the
environment, not on root, but it never runs where the work happens.

## The three rewritten tests: sound

Each one patches the call production actually makes:

- `shutil.copytree` at `src/claude_code_hooks_daemon/install/skills.py:127`;
- the backup `cp "$target" "$backup"` at `scripts/install/settings_deploy.sh:113`,
  where `$2` matches `*.bak-*`;
- `os.access(untracked, os.W_OK)` at `daemon/paths.py:773`, with `untracked`
  a `Path` equal to the test's.

Baseline in the copy, as root: 3 passed. Each mutation made its test fail:

| Mutation                                                      | Result                          |
| ------------------------------------------------------------- | ------------------------------- |
| copytree wrapped in `except PermissionError: log; return`     | `DID NOT RAISE PermissionError` |
| `return 1` after the failed backup deleted                    | `assert 3 == 1`                 |
| `os.access(untracked, W_OK)` replaced by `untracked.exists()` | `assert True is False`          |

Minor: `test_skills` now faults only the copy step. The old chmod on the
project also faulted creating `.claude/skills`. `_fake_access(path, mode)`
would raise `TypeError` if any call on that path passed keyword arguments to
`os.access`. None do today.
