# Plan 00197 — Journal 26-08-07

> **Append-only activity log** for plan 00197. One file per day
> (`00197-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` local 24h (the date is in the filename); times increase down the file.
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 07:31 · decision · — — new check vs. ratcheting journal-dayfile-naming

Chose a NEW check `journal-dayfile-is-today` (Stage.EDIT, BLOCK by default)
rather than ratcheting `journal-dayfile-naming`'s level. Rationale: SRP —
naming validates grammar/plan-number/calendar-validity, the new check owns
write-time recency exclusively. Narrowed `journal-dayfile-naming` to drop its
today-or-yesterday tolerance sub-check (that tolerance was exactly the
midnight-rollover confusion the new check exists to close), so the two
checks never give contradictory advice about one file. New config knob
`plan_workflow.qa.journal.today_only_mode` (advise | block | off, default
block) is independent of the existing `journal.mode` — this check does not
get the advise-first rollout grace period the rest of journalling shipped
with, per the user's explicit request to enforce this immediately.
