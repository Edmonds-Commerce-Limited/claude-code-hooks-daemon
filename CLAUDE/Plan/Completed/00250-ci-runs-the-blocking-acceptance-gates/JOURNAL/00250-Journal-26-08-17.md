> **Append-only activity log** for plan 00250. One file per day
> (`00250-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` local 24h (the date is in the filename); times increase down the file.
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 14:02 · finding · — — I misread a correct guard as a false positive

Worth recording because I nearly weakened a working check.

Writing this journal tripped `journal-append-only` ("rewrites earlier journal
history"). My first read was that it must be a false positive: the file is
untracked with no committed history, and the check's own docstring says "new
file (no `file_content_before`) → creation, clean".

Read the check before touching it. `journal_append_only.py:45-48` exempts
creation only when `file_content_before is None` — and it was not None, because
`mkplan.bash` scaffolds the day-file from `_JOURNAL_TEMPLATE_.md`. So the file
existed, carrying the entry-grammar preamble and a first `plan scaffolded`
entry, and my `Write` had discarded both.

The advisory was therefore correct and I was wrong. Confirmed against the repo
rather than reasoning about it: **79 of 94** day-files keep the template
preamble and **82 of 94** use the `## HH:MM · category · REF` grammar, so the
template convention is the established house style and my write was the
outlier. This file has been reconstructed to match it.

The near-miss is the lesson: the fix I was about to make would have exempted a
scaffolded file from the append-only check, permanently, to accommodate my own
mistake. A guard that fires on something you just did is the case where
verifying first matters most.

Plan 00249's journal has the same defect and is already committed
(`a74b0489`). Restoring its preamble would mean PREPENDING to a journal, which
is the very rewrite the rule forbids — so it stays as it is, and further entries
there use the correct grammar.
