# Fact-check: Plan 00518 and the N457 ledger diff (2026-10-13)

## REFUTED (most consequential first)

1. "other handlers read it (`agent_type`): `dispatch_declaration`, `agent_isolation_advisor`" (PLAN Overview; N457 Evidence).
   Both read `tool_input["subagent_type"]` of a Task/Agent DISPATCH call, not the payload field `agent_type`
   (`dispatch_declaration.py:336`; `agent_isolation_advisor.py:57,140`). Neither reads `agent_type` at all. The handlers
   that do read payload `agent_type` are `subagent_stop/subagent_report_size_blocker.py` (SubagentStop) and
   `status_line/multithread_indicator.py`. No PreToolUse handler reads it today. Change: cite those two instead;
   the exemption would be the first PreToolUse reader of `agent_type`.
2. "a sub-agent's PreToolUse payload carries `agent_type` (`core/input_schemas.py`, line 252)". Line 252 is inside
   `SUBAGENT_STOP_INPUT_SCHEMA` (SubagentStop). `PRE_TOOL_USE_INPUT_SCHEMA` (lines 42-56) declares no `agent_type`.
   The true source is the vendored contract `contracts/claude-code-hooks/PreToolUse.json` line 30 ("Present when the
   session uses --agent or the hook fires inside a subagent... subagent's type takes precedence"), line 29 for
   `agent_id`. The claim is right in substance, wrong in citation. Change: cite the contract, not input_schemas.py.

Risk the plan should record (not refuted, but contradicts an assumption): `core/handler_scope.py:15-19` says
`agent_type` "is deliberately NOT consulted. It fails in BOTH directions": it is present but EMPTY in 4 of 5 measured
real subagent STOPS, and `--agent` sets it on a main-thread event. Task 0.1 (measure on PreToolUse) is therefore
essential, and an empty `agent_type` must be denied.

Also not mentioned in the plan: a host-wide full-QA lock already exists (`src/claude_code_hooks_daemon/qa/full_qa_lock.py`;
`tests/conftest.py` refuses a whole-suite pytest unless it is held). Task 1.2's new lock file overlaps this sink-side
lock; the design should say how they relate.
