# Fact check 01: Plan 00601 and Plan 00474 edits

Checked against the current tree on branch plan-00601-contract-docs (main contains the commits cited).

## REFUTED (most consequential first)

1. **N611 is stale as written.** It says `_write_park_commit` "passes no signing option (`core/branch_park.py:141`)". The current `_write_park_commit` (branch_park.py:182-195) calls `_signing_requested` and adds the sign flag when `commit.gpgsign` is true, failing the park clearly otherwise. Commit d2e73d0e9 "Plan 00594 Task 4.9: branch-park writes a signed commit when commit.gpgsign is true" is an ancestor of main. The Status "Open, filed as Plan 00594 Task 4.9" should read done, or the entry should be dropped or marked fixed.
2. **N619 overstates the runtime impact.** `schema_registry()` (which does the `referencing` import) is defined at `core/state_schemas.py:62` and the import is lazy, inside the function (lines 68-69). Within `src/` nothing calls it; its callers are tests only (`test_state_schemas.py`, `test_session_state_document.py`, `test_cli_session_state.py`, `test_cli_mode_history.py`). So "would fail on the first `session-state` ... call" is not supported: the session-state command itself does not import `referencing`. Only schema validation through the registry would fail. The docstring itself says the import is there "so the daemon's runtime never needs it".
3. **N617 "scaled only by CPU speed" is wrong.** `scaled_cpu_seconds` (`tests/load_scaling.py:92`) multiplies by the host load factor (load average per CPU, clamped 1..16) and by a tracing factor of 8 when coverage is installed. It does not scale by CPU speed. The better-supported cause is that a spike in host load after the multiplier is read is not covered. The claim that the test "measures wall time" is correct.
4. **N607 line references are stale.** `branch_park.py:159-168` and `:101-112` do not hold the park commit, `update-ref` and push sequence. The relevant code is `_write_park_commit` (182), `_keep_refused_remote_park` (211, uses `update-ref` at 219) and `_park_remote_only` (238). Also the claim "the remote-only path parks nothing on a failed push" is refuted: `_keep_refused_remote_park` keeps a local branch plus record on a failed remote-only push. The behaviour part (local park survives, "locally, not pushed", exit 0) is contradicted too: `cmd_branch_park` (cli.py:6737) returns `EXIT_PARKED_NOT_PUSHED` with a "WARNING ... locally, not pushed" line when `result.pushed` is false, not 0. N607's entry (and its Status) rests on an out-of-date reading.
5. **N609 minor.** `paths.py:3190-3192` is a docstring in `daemon/paths.py`; the `is_dir()` skip is at line 3207. The substance (a candidate that is not a directory is skipped) is true.
