## Fix

Fault 2: new `_directory_pattern(glob)`: the longest run of literal directories above a wildcard-only last component, matched as whole names (quotes allowed around components, so `protected/x`, `./protected/x`, `"protected"/x`, and `<root>/protected/x` all name it). `_text_naming` uses it when `_name_pattern` is None. A glob with no literal directory (`**`, `*`, `*/**`) returns None and stays fail-closed (unchanged).

Fault 3: `_spelled_violation` now runs `strip_quoted_heredoc_bodies` (shell_segmentation, the shared helper with the DATA_SINKS allowlist that pipe_blocker's exemption uses) before brace enumeration. Bodies fed to `bash`, `sh`, `python3`, or `cat <<'EOF' | sh` are kept (receiver and downstream stages are both checked by the helper); the opener line is always kept, so `cat <<'EOF' > protected/x` is still seen.

## `_text_naming` callers (all fail-closed paths)

1. `_spelled_violation` brace overflow: now correct. Text that does not mention the directory is allowed; a mention denies.
2. `_command_violation` unreadable text (unclosed quote): same, correct.
3. `_rescanned` unreadable text: same, correct.
4. `_deep_violation` (nesting past depth bound, brace/time overflow): same, correct; any mention of the chain denies.
5. `_verbs_violation` awk program that writes: DELIBERATELY UNCHANGED via `computed_destination=True`. An awk `print > $1` computes its destination, so what the program mentions says nothing about where it writes. Seven existing tests (`TestAwkReadsWithOperatorsAreNotWrites::test_a_real_write_is_still_denied`, e.g. `awk '{print > "out.txt"}'`) require this deny under `protected/**`; the first run of my change broke them, so I kept the old behaviour here rather than edit them. `awk '{print > "protected/x"}'` is denied by both routes.
