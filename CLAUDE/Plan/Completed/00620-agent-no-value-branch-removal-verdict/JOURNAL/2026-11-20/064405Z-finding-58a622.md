## 06:44 · finding · — — Task 2.2: batch rate, guard-written bundles, CLI correction

Review of the first Task 2.2 unit found three more holes. Each was closed with a red test first:

- **Batch rate bypass.** Phase one appends nothing to the ledger, so every branch in one `delete-branch a b c` saw the same window count. `approve_removal` now takes `pending`, the number of removals the batch has already approved.
- **Reused bundle trusted on header alone.** A probe on git 2.47 showed that `git bundle verify` passes a planted bundle with a truncated pack, and a planted `--filter=blob:none` bundle. `write_bundle` would have reused either one. The guard now writes a `<bundle>.sha256` sidecar when it creates a bundle and refuses any existing file whose sha256 does not match it. A `@filter` header capability also refuses.
- **Correction to the 06:30 entry and the handoff.** That entry said the CLI needs no new except clause. That is wrong: `main_checkout`, called while building the route, raises `RejectError` outside `delete_branches`, so the CLI must handle it.

Fail-closed branches now covered by tests: the failed git-refused append ("wrongly records"), a bundle altered between approval and the append, a concurrent consume, and recording a dry-run approval.
