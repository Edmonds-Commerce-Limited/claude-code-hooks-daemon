## 16:12 · finding · — — Peer report: a bundle-and-reason removal route for rejected work

A client reports five parked branches that are rejected work (superseded drafts, dead fixes), with content deliberately NOT in the default branch, so no content proof can pass. Today the only route is a no-content merge into the default branch, which can trip the repo's own checks. The client suggests a guarded `branch-reject <name> --reason` that writes and verifies a recovery bundle, records the reason, and then permits that one remote delete, and cites the owner's rule "has value keep merge, no value remove, human should not be required". This is the same problem this plan solves. Add the bundle-and-reason route to the design options for the owner's questions (it keeps the no-ref-sprawl property of the design and gives recovery a durable file, which answers Q6's recovery weakness), and keep the Opus verdict as the "no value" authority: a reason typed by the requesting agent must never be enough on its own.
