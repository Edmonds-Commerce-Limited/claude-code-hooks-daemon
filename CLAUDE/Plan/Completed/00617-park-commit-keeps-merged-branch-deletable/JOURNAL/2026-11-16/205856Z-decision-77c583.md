Task 1.2 decision: classify park-only branches as merged-equivalent (implemented); do NOT move the park record off the branch in this plan.

Classifier: one function, `branch_park.is_park_residue`, beside the writer. A commit is a park commit only when its message is exactly what `_message` writes (rebuilt from the reason and user read back out of it), it has one parent, and its tree equals that parent's. Used by the inventory (`_pair_facts`), the creation guard, the remote-delete proof / `R-GIT-PUSH-DELETE-REMOTE`, and now `classify_branch` (new `park-carried` tier, and park commits left out of patch equivalence). Moving the record off the branch (a ref, a note, or daemon state) was evaluated:

- For: parking would never change what the branch is, so the classifier would never be needed for new parks.
- Against: existing parked branches already carry park commits on every remote, so the classifier is needed regardless; the commit is what lets OTHER clones and the remote see the park (`commit=False` already gives an off-branch record, but it lives in this clone's git config only); a note or ref namespace would need its own fetch/push plumbing and its own pool counting, a larger change than this defect.
- Result: the classifier closes the defect for old and new parks alike. Moving the record is left as a separate design question for the owner; no migration (Task 2.3 not applicable).
