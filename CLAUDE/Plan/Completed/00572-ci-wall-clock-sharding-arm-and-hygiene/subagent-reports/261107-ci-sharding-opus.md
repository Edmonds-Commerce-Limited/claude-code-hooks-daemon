## Disagreements with the brief, with evidence

- **No pytest-split.** No committed per-file durations exist, and the release-gate artifacts carry only the slowest 50 tests. A plain directory split could not work either, because `tests/integration` is flat (258 files, one small `handlers/` subdirectory). So integration is split by an explicit file list, which the existing shard format already supports. The new integration remainder needs no edit when a file is added.
- **The fallback runs on its own `map` job.** A job output is only available once the job finishes, so the fallback cannot wait on the `targeted` job without also waiting for all of its static work. The `map` job is only install plus a mapper call.

## Expected effect (estimates from run 41884438839; confirm on the first real run)

- Release gate: the slowest test leg drops from 2880 s to roughly 1400 s, the integration half under coverage. At peak 19 jobs run at once.
- qa.yml code-tier fallback: from one serial whole-suite step to the slowest no-coverage leg, roughly 1100 s plus setup.
- Nightly: the serial per-Python suites (4174-6658 s each) become the same sharded `full` profile as the release gate.
