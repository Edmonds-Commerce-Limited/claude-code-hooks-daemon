## Blockers

### B1: the sink can be skipped with ordinary pytest flags, and the handler lets the wrappers that carry them through

The round 9 docstrings, the 9d ruling and the new advisory all say the same thing: the sink
"refuses or serialises a whole-suite pytest run however it was launched". That is false.

| Probe (fixture suite, 8 of 8 files, no lock held)  | Result                                                       |
| -------------------------------------------------- | ------------------------------------------------------------ |
| `pytest tests/`, the control                       | refused, rc=1                                                |
| `pytest --noconftest tests/`                       | **8 passed**. The conftest never loads, so there is no hook. |
| `pytest --rootdir=<empty dir> tests/`              | **8 passed**. `_test_root` counts 0 files and returns.       |
| `pytest -c /dev/null --rootdir=<empty dir> tests/` | **8 passed**                                                 |
| `pytest -p no:tests.conftest tests/`               | refused. This shape is closed.                               |

The same result on the REAL suite, collect-only so that nothing executed:

- `pytest --co tests/` gives `REFUSED`, rc=1.
- `pytest --co --rootdir=<empty dir> tests/` gives **28419 tests collected**, rc=0, with no refusal.

The cause is in `full_qa_gate.py`. `_total_test_file_count` counts under `config.rootpath`, and the
caller controls that value. `total == 0` then returns early, which is a fail-OPEN on a security path.
`--noconftest` removes the plugin entirely.

**Composite route through both layers.** `probe_handle.py` shows two handler results:

- `perl -e 'exec "pytest", "--noconftest", "tests/"'` gives ALLOW, **with no advisory at all**.
- `node -e 'require("child_process").execFileSync("pytest",["--rootdir=/x","tests/"])'` gives
  ALLOW, with no advisory.

Put those in front of the sink results above, and a sub-agent runs the whole suite with no lock and
no warning.

**Fix direction.** Count from the conftest's own directory (`Path(__file__).parent` in
`tests/conftest.py`), not from `config.rootpath`. Treat `total == 0` as unable to judge, which
refuses. That closes the `--rootdir` and `-c` routes.

`--noconftest` (and, if the plugin moves to a `pytest11` entry point, `-p no:` and
`PYTEST_DISABLE_PLUGIN_AUTOLOAD`) cannot be closed from inside the process being checked. **This
needs a coordinator or owner decision.** The 9d ruling ALLOWS UNSEEN code on the premise that the
sink is a guarantee, and a plugin inside pytest cannot be one. There are two options:

- Reverse the ruling for UNSEEN code, which means going back to denying it.
- Keep the ruling, and restate every "guarantee" / "every route" claim as a best-effort backstop.
  This is an accepted residual, which the owner rules say is not a terminal state.

### B2: `full_qa_lock_is_held` accepts an UNLOCKED descriptor, so two runs can overlap

The proof checks two things: that some fd points at the lock path, and that SOMEONE holds the lock.
It never checks that the inherited descriptor is the one holding it.

Repro (G in `probe_sink.py`):

1. Process 1 runs `exec 8>>lock; flock 8; sleep 6`.
2. Meanwhile, the evader does `os.open(lock)` WITHOUT flock and passes the fd to `pytest tests/`.
3. Result: **8 passed, not refused**, while process 1 still holds the lock.

So a second whole-suite run overlaps the gate's own run. That is exactly the case the lock exists to
prevent, and the docstring's "PROVEN, never claimed" does not hold.

**Fix.** For the matching inherited fd, call `fcntl.flock(fd, LOCK_EX | LOCK_NB)` on THAT
descriptor.

- If it succeeds, this open file description holds the lock (or now holds it, which serialises the
  run legitimately).
- If it raises `BlockingIOError`, another holder has it, so return False.

Add a RED test with the G shape: a holder subprocess, plus an unlocked fd passed to a fixture-suite
pytest.

### M1: the UNSEEN advisory is inaccurate, and it ships in generic code

`handle()` (`subagent_full_qa_blocker.py`, the `match.fail_closed` branch) and the handler's
documentation text both say "the host-wide full-QA lock sink (`tests/conftest.py`) will refuse or
serialise it". This is wrong in three ways:

- **In this repository**, B1 and B2 show the sink neither reliably refuses nor serialises.
- **The handler is a shipped, opt-in handler** (`get_default_enabled` is False, and it takes
  generic `full_qa_patterns`). A client project that opts in has no such sink. For them the 9d
  ruling silently turns every UNSEEN full run into an allow, with an advisory that points at a
  file they do not have.
- **The sink covers pytest only.** `llm_qa.py all`'s other steps are never refused, and when
  wrapped they run once the run_tests.sh lock is acquired.

**Fix.** Make the text true, and make the UNSEEN policy something the project states, not something
hardcoded to this repository. For example, an option that says whether a sink exists, with the
default being to deny UNSEEN code.

## Ledger candidates (below MAJOR)

- **m1: a leaked lock fd can hold the lock indefinitely, and `run_tests.sh` / CI wait with no
  bound.** Repro H in `probe_sink.py`:

  1. Run `bash -c 'exec 8>>lock; flock 8; (sleep 5 &); exit 0'`.
  2. After that exits, `flock -n lock true` gives rc=1, because the orphan still holds it.

  `exec {FD}>>` without CLOEXEC is inherited by every descendant of run_tests.sh, and a
  forked/backgrounded descendant that outlives it keeps the lock. The next `flock "${FD}"` has no
  timeout and blocks forever.

  A crash of the holder itself is fine, because the kernel releases the lock on process death.

  Fix: `flock -w <bound>`, with a message naming the pids that hold the file (from `/proc/*/fd`).
  Mark the fd CLOEXEC in pytest once the proof has passed.

- **m2: `pytest tests/ -k <one test>` is REFUSED.** Repro K: `-k test_ok_0` selects 1 of 8, and the
  run is still refused. The gate's `pytest_collection_modifyitems` runs before the mark plugin
  deselects, so it counts pre-deselection files. The refusal then sends the caller to run_tests.sh,
  which is the whole suite.

  Fix: `@pytest.hookimpl(trylast=True)`, plus a test.

- **m3: `whole_suite_refusal_message` says to "acquire it via ... `llm_qa.py changed`".** Neither
  `llm_qa.py changed` nor `run_changed_tests.py` acquires the lock; only `run_tests.sh` and CI do.
  Reword the message.

- **m4: the xdist paragraph in the `full_qa_gate.py` docstring is inaccurate.** The xdist controller
  does not collect items (its `pytest_collection` short-circuits), so "the controller's own
  collection ... would have refused" is not how xdist works. It is moot today because xdist is not
  installed (`-n 2` gives rc=4), but the docstring must not state it. Delete the paragraph, or
  enforce in workers by summing across workers.
