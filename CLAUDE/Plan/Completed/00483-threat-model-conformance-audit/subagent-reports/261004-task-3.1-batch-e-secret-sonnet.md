# Task 3.1 batch E: N170, N242, N136 (secret_file_guard), branch worktree-p483-secret

## Outcome

All three reproduced on this code and are fixed with tests in `tests/unit/utils/test_secret_file_matching.py`.

- **N170**: `is_exempt_invocation` (`utils/secret_file_matching.py`) looked only for `;`, `&&`, `||`, `|`, newline and `<(`. It now also refuses `&`, `$(` and a backtick (`_COMPOUND_MARKERS`) anywhere in the command, so `secret-meta x & cat <file>`, `git rm --cached foo $(...)` and the backtick forms are no longer exempt. The check is textual and quote-blind, so a `&` inside a quoted argument also voids the exemption (fails closed). Tests: `TestExemptInvocationIsOnlyThatInvocation`.
- **N242**: `python -m pkg.secret_x` was denied. `_without_import_module_paths` now also drops the module span after `python|pypy[ver] [-X...] -m` (`_PYTHON_DASH_M_RE`). A value-taking option such as `-W ignore` before `-m` is not recognised, so that shape stays denied.
- **N136**: the `-c "import a.b.secret_x as s"` shape already worked when the import came first; one that follows another statement (`import sys; import a.b.secret_x`, or after a newline) was denied. `_DASH_C_SCRIPT_RE` finds the quoted `-c` script and `_IMPORT_STATEMENT_IN_SCRIPT_RE` drops import module spans inside that body only.
- Tests: `TestDottedModuleNamesAreNotPaths`.

## Decisions

- Removal is positional and scoped: only the module span goes. A file operand after `-m pkg` (`-m pytest tests/x.secret`), a path later in the `-c` body, the same name read elsewhere (`&& cat pkg.secret_x`) and an `echo 'x; import a.secret'; cat a.secret` outside any `-c` are still mentions (pinned by tests).
- No change to fail-closed handling, allowlists or exclusions.
- Release note: `CLAUDE/UPGRADES/UNRELEASED/release-notes/008-secret-guard-exemption-and-module-names.md`.
