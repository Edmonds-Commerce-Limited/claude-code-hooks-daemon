# Task 3.1 batch D: plan-folder mkdir guard (N141, N179, N186)

Branch worktree-p483-mkdir, based on main 9e1cbaa2d. Handler:
`src/claude_code_hooks_daemon/handlers/pre_tool_use/plan_number_helper.py`.

## Reproduction

Red tests were written first in `tests/unit/handlers/pre_tool_use/test_plan_number_helper.py`
(`TestHandRolledPlanFolderCreation`). Ten of the new cases failed on main:

- N141 SH1: archive path, later `| wc`, trailing comment. Cause: `matches()` returned early
  for the `| wc` and archive-subdirectory exemptions before the creation rule ran.
- N141 SH3 `cd` form: `cd CLAUDE/Plan && mkdir 00999-x`, `cd CLAUDE && mkdir Plan/00999-x`.
  Cause: the operand was read without the `cd`.
- N179: `mkdir 2>&1 CLAUDE/Plan/00999-x` and `>/dev/null 2>&1`. Cause: the `&` in the
  redirection split the command, so the operand was read as a new command. (`2>/dev/null`
  before the operand already matched.)
- N186: `0{0999,1000}-x` and `{00999,01000}-x`.

All four reproduced; none had gone stale.

## Fix

- The creation check now runs before the `| wc`, archive-subdirectory and commit-message
  discovery exemptions.
- Redirections are blanked, then the command is cut into segments. A segment that is just
  `cd`/`pushd <dir>` re-roots later relative operands; the operand as written stays a
  candidate, so a `cd` only adds spellings.
- Operands are brace-expanded with the shared `expand_braces`; a list past its cap fails
  closed when it names the plan dir.
- Every operand is judged against the existing checks (inside workspace, not already a
  directory, scaffolder deployed), not only the first plan-shaped one.

## Left alone, as triaged

SH2 (quoted space), SH4 (`ln -s` then mkdir), `$'...'`, `$"..."` and `$m` spellings.

## Allowed shapes kept allowed (tests)

`Completed`, `JOURNAL/` inside an existing plan (also after a `cd`), `-p` re-create of an
existing folder, paths outside the workspace, `{Completed,Archive}` brace list.
