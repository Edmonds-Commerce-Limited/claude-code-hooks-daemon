# Task 3.1 batch I: four ordinary conditions (N171, N172, N248, N250)

Branch worktree-p483-ordin, based on main 0bde607c4. All four reproduced on main; none was already fixed. The
remedies on the dropped worktree-d-00421 branch were re-done from the ledger text, not cherry-picked.

| Niggle | Component                                                              | Behaviour now                                                                                                                                                                                                                                                                                                                                 |
| ------ | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N171   | `utils/scan_scope.walk_files`                                          | `os.walk` gets an `onerror` that raises `WalkError` (an `OSError`) naming the directory. A missing root still yields `[]` (checked up front, because `os.walk` also reports a missing root through `onerror`). An unlistable root raises.                                                                                                     |
| N172   | `scripts/qa/check_git_history.py`, `check_sensitive_content.py`        | The term matcher, redactor, term list and word-list resolver raise the checks' own `ConfigError` when the daemon package cannot be imported, which each already reports as a failing finding. `_never_matches` is gone. In `check_sensitive_content` the matcher is resolved inside the `ConfigError` handler.                                |
| N248   | `utils/secret_redaction.project_secret_terms`, `scripts/debug_info.py` | New `project_secret_terms(project_root, config_path)` resolves the list from the raw YAML (so a config the schema rejects still yields its path, the N43 rule) with no `ProjectContext`. `_secret_terms` uses it. An unreadable list, or a bare interpreter without PyYAML, still gives `None` and the "Secret word list not applied" banner. |
| N250   | `daemon/cli._sensitive_content_guard`                                  | Raises `_ContentGuardUnavailableError` instead of returning `None`. `remote-docs add` and `refresh` build the guard once up front, print the reason, return 1 and write nothing.                                                                                                                                                              |

## Tests (red first where the old behaviour was observable)

- N171: `tests/unit/utils/test_scan_scope.py::TestWalkFiles::test_an_unreadable_subdirectory_fails_the_walk` (patches `os.scandir`; red by ImportError of `WalkError` on main).
- N172: `TestAnInterpreterWithoutTheDaemonPackageFailsRatherThanChecksNothing` in `tests/unit/qa/test_check_git_history.py` and `test_check_sensitive_content.py` (module entry set to `None` in `sys.modules`, so the import raises).
- N248: two tests in `tests/unit/test_debug_info.py::TestTheOutputIsScrubbed` (both red on main) and `TestProjectSecretTerms` in `tests/unit/utils/test_secret_redaction.py`.
- N250: `TestUnscannedCaptureIsAnnounced` in `tests/unit/remote_docs/test_cli_remote_docs.py` (the old stderr-warning test was replaced by a refusal test, plus add and refresh write-nothing tests).

The N172 and N250 remedies were written before I ran the new tests on the old code; the old branches returned a
matcher that never matches and `None` respectively, so those tests could not have passed there.

## Decisions to review

- N248 keeps the banner on an unobtainable list rather than the dropped branch's ruling to refuse outright on a bare
  interpreter. The task text asked for a clear report, and `debug_info.py` exists to run when the daemon is broken.
- The `except ImportError` fallbacks in `filter_excluded_files` and `resolve_public_pattern_exemption` stay: they fall
  toward scanning more, not less.
- A callers' view of N171: a walker now exits with a `WalkError` traceback on an unlistable directory. That is loud and
  non-zero, which is the point; no per-walker handler was added.
- The pre-existing error-hiding exclusion for `cli.py` was not touched.
