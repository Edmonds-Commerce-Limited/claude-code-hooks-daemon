## Review round 1

False positive: on the real project `ls */*/*` was denied (main allows it). Cause, measured: the project root was walked once (root and hook cwd are one directory), but the walk included dot-entries that bash skips: 5133 entries walked against 4530 bash-visible paths, past the 5000 cap. Dot-entries were also judged by name, which bash would never expand to.

Fix:

- `bounded_recursive_glob` and `_expand_glob_token` take `skip_hidden` (bash default: a wildcard or `**` component does not match a leading `.` unless the pattern component starts with `.`). Only `_bare_glob_mention` sets it, so every other caller is unchanged.
- `_expand_glob_token` takes `include_project_root`; `_bare_glob_mention` walks the project root for the first working directory only, so a differing `cd` target no longer re-walks it. An absolute word is walked once.
- The cap stays 5000: it now counts only paths bash would produce, and the measured repo-scale cases leave a margin below it.

Tests (`TestBareStarFollowsBashRules`, red first, 5 of 6 failed before): dot-entries do not count towards the cap, a `*` does not reach a protected dot-entry while `.*` does, a `*` component does not descend a dot directory, the project root is walked once across working directories, a naive walk over the cap with a real result count under it is allowed.

Measured on /workspace with the real guard, `ls <glob>`: `*/*` deny (0.009 s, a real protected file under `untracked/`), `*/*/*` allow (0.10 s, 4530 bash-visible paths), `*/*/*/*` deny (0.08 s, 18373 bash-visible paths, past the cap, fail closed). Dot-entries are ignored as bash ignores them by default; a shell with `dotglob` set would expand them and is not covered.
