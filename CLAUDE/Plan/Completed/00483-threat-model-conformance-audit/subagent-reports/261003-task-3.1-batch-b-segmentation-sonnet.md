## Outcomes

- **N85**: not reproducible. The N241 command-position work (merge f3d13077e) already reads a single-quoted
  message as ending at the next quote. Regression tests added (both directions).
- **N48**: `sed_blocker._is_git_command` used a raw-text `[;&|]` check. It now blanks quoted-heredoc bodies,
  splits with the shared quote-aware segmenter (`SEGMENT_SEPARATORS`, newline included) and requires EVERY
  `sed` to sit in the same command as a preceding `git commit`. This also closes a neighbouring hole: only the
  first `sed` was examined, so `git commit -m 'about sed' && sed -i ...` was allowed. A `;` inside a quoted
  message no longer defeats the exemption (fewer false positives).
- **N87**: root cause is `resolve_shell_word` returning None for `$'...'`, so `_narrow_shell_body` left the
  body undecoded. It now decodes via the shared `ansi_c_string` (standard escapes), fixing every caller.
  One existing test asserted `$'cat'` resolves to nothing; bash resolves it to `cat`, so the test moved to the
  "resolves" list.
- **N93**: `project_containment` treats a literal `eval` body (arguments joined by spaces) like a `-c` body,
  through a new `_inner_command_targets`. `eval "$VAR"` stays out of scope per the threat-model ruling.
