# Fact check: Plan 00500 PLAN.md

## REFUTED (most consequential first)

1. Task 2.1 "Key each step's result to the tree it ran on (commit plus a dirty-tree hash)" is presented as missing, but the gate already does this. `scripts/qa/llm_qa.py:371-520` has `PROVENANCE_FILE = "provenance.json"`, `worktree_state()` (HEAD plus a digest of `git diff HEAD --binary` and untracked files), `stale_reason()`, `output_reason()`, `run_record()` and `record_provenance()`. `run_tools` at about line 2640 records every tool per run (`_record_run`), and `--read-only` skips running and fails any result whose tree or report hash differs. The file `untracked/qa/provenance.json` exists. Change to the plan: Task 2.1 becomes "reuse the existing provenance records". Task 2.2 is the only missing piece: a mode that runs only the tools whose record fails `stale_reason`. The `--read-only` code path is the base to extend.

2. Goal 2 and Task 1.3 imply per-test durations are not recorded. `scripts/qa/run_tests.sh:116-122` already writes a per-test `duration` (`test["call"]["duration"]`) into `tests.json`. The catch is that this happens only on the `pytest_json_report` branch. `pytest-json-report` is not installed in any venv on disk (`untracked/venv-workspace-py311-*`, `untracked/qa-interpreters/py3.12` and `py3.13`) and is not in `uv.lock` or `pyproject.toml`. So the fallback text branch runs, and the current `untracked/qa/tests.json` has 0 `"duration"` entries. No `--durations` appears in `pyproject.toml`, `run_tests.sh` or `run_test_matrix.py`. Change to the plan: Task 1.3 should state that per-test timing is wired but dormant because the plugin is absent. The fix is to add the plugin or pass `--durations=N` on the fallback branch.

3. Task 2.3 "Split the test step into shards (for example integration and unit...)" and Task 3.1 "steps that can run concurrently ... repeated matrix legs" miss existing structure. `scripts/qa/run_test_matrix.py:69-79` already defines scopes `unit` (`tests/unit`) and `rest` (`tests --ignore=tests/unit`). The docstring (line 16) says Phase 1 runs the primary and each extra interpreter's `tests/unit` at the same time. The matrix already runs concurrently across interpreters, and the logs `untracked/qa/tests-py3.12-unit.log` and `tests-py3.12-rest.log` exist. The tool loop in `llm_qa.py` (~line 2650, `for name in tools`) is sequential. Change to the plan: say what is already sharded, so Phase 2 and 3 do not re-plan it.
