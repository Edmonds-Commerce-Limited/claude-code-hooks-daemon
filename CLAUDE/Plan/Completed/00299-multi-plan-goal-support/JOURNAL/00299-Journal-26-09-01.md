**Daemon side** (`goal_ledger.py`): added `LivePlanRef` + `GoalLedger.
live_plan_refs(plan_dir)`, resolving each still-`In Progress` ledgered plan's
folder + PLAN.md text (factored `_candidate_folders`/`_find_plan_md_text` out
of `_plan_state` rather than duplicating the glob). `goal_injection.py`:
added `LivePlan` + `render_combined_goal_line()` — one live plan degrades
byte-for-byte to the existing `render_goal_line()` output (backward
compatibility, Task 2.4); two or more render a single work line naming every
live plan number (`Work on Plan(s) 00296, 00298 ...`), with every other
configured line (built-in or project) still applied since none reference a
per-plan placeholder. `GoalInjectionHandler.handle()` now renders+ledgers
this plan on an In-Progress flip, then always calls the new
`_write_combined_signal()` to render+write the FULL live set (falling back to
the single-plan text only if the ledger/render path is unavailable). A write
that flips a plan to a TERMINAL status now also runs
`_maybe_refresh_on_retirement()`: if this session ever ledgered that plan
number, the combined signal is re-rendered immediately (via `PlanDoc.parse`,
not a hand-rolled regex) so a completing plan drops out of `/goal` text
promptly rather than waiting on some unrelated plan's next write. No entry
point exists to actively CLEAR the signal file when the live set becomes
empty — the pre-existing behaviour (a stale single-plan signal already
lingered until the supervisor's TTL reaper) is unchanged, just documented.

**Supervisor side** (`claude-supervise.py`): `load_goal_signal()` and its
call site were already payload-agnostic (they just validate/type whatever
`rendered_lines` says), so NO changes were needed there — the combined
payload is consumed exactly like the single-plan one always was (Task 3.1).
Added the thrash guard (Task 3.2): `CompactStateMachine._last_goal_text`
(exported/imported like every other per-episode field), a `last_goal_text`
property, and a new decision-time check in `decide_once`'s goal branch —
`goal_line == machine.last_goal_text` short-circuits to a deduped NOOP
instead of re-typing an identical `/goal`. Recorded only on a SUCCESSFUL
injection (`mark_goal_injection(goal_line)`, called from
`_apply_post_injection_bookkeeping` alongside the existing cap counter) so a
failed PTY write never poisons the guard. This matters because the daemon
now re-renders+rewrites the signal file on ANY ledgered plan's status flip
(not just this session's own plan), so an unrelated edit could otherwise
rewrite a byte-identical signal with a fresh timestamp and get re-typed.
