## 13:52 · finding · T1.3 — Task 1.1 broke a contract it should have read

Task 1.3 was filed as a gap (a monorepo sub-project's `vendor_dirs` would be
ignored). It is a defect Task 1.1 INTRODUCED. `WorkspaceScope.PROJECT`'s own
docstring in `core/handler.py` already says a project-shaped question "Must
resolve via the injected `_project_registry` … never `ProjectContext.
project_root()`" — and Task 1.1 wired 12 sites to `self._project_layout`,
which is the root.

Why it read as correct: in a single-project repo the root layout and the
owning project's layout are the same object, so every test passed and every
manual check agreed. Only a declared sub-project separates them. That is the
same shape as the bug this whole plan exists to fix — a value that looks
threaded through but is really the built-in one — reintroduced one level up.

## 13:58 · decision · T1.3 — generalise `tdd_enforcement`'s block, don't invent one

`resolve_layout` had exactly ONE production caller: `tdd_enforcement`, which
had grown a 7-line inline block (root lookup → `resolve_layout` →
`fallback_root_layout=self._project_layout`). Rather than repeat that at 12
sites or write a fresh helper, lifted it verbatim onto the base class as
`Handler.layout_for(file_path)` and moved `tdd_enforcement` onto the helper
it prototyped. Nothing new to justify: the shape was already in production.

Left on the root layout deliberately: `monorepo_detector` and
`worktree_seed_suggestions`. Both answer a repo-WIDE question, where "the
owning project of this file" has no referent.

## 14:04 · finding · T1.3 — the root-layout test could not have caught this

`layout_declaring_vendor_dirs` (the conftest helper added under Task 1.4)
only ever builds a ROOT layout, so a test using it passes whether the handler
resolves per-file or reads the root. Added
`registry_declaring_vendor_dirs`, which declares ONE sub-project and leaves
siblings undeclared, so a test can pair "the declaring project skips it"
against "an identically-shaped sibling does not". The sibling half is the
discriminating one — without it the assertion is true of the broken code too.
