## 02:45 · decision · T4.10 — close by elimination, not by re-adding bookkeeping

Two candidate fixes, and the choice matters more than the code:

- **A — restore the side effect.** A PostToolUse recorder that observes the
  `mkdir` and calls `record_plan_allocation`. Faithful to the finding, adds no
  new block. Costs a whole new handler (constants, config, docs, guidance
  verdict, acceptance tests, dogfooding config) for a bookkeeping side effect,
  and keeps a discouraged path alive by accounting for it.
- **B — remove the path.** Deny `mkdir <plan-dir>/NNNNN-name` and name
  `mkplan.bash` in the reason. The scaffolder takes an atomic-mkdir lock and
  writes the counter itself, so redirecting to it closes the window rather than
  narrowing it. No new handler: `plan_number_helper` already owns the
  plan-number domain, already matches Bash, already carries the "use
  mkplan.bash" guidance in its `get_claude_md()` — it simply never enforced it.

Chose **B**. DBF says fix the guard that should have caught it, and the guard
here is the one that was only ever advice. It also fixes more than the counter:
a hand-rolled folder skips the PLAN.md scaffold and the JOURNAL/ scaffold too.

Option A's one advantage — no new blocking behaviour — is worth naming rather
than glossing: B does change behaviour for every project on upgrade. That is
recorded as a `truth-changes` entry so upgrading projects reconcile their own
docs instead of discovering it from a block.

## 02:47 · decision · T4.10 — the five conditions, and what each one is for

The rule is narrow on purpose. Each condition exists because a legitimate
command looks like the blocked one until you apply it:

| Condition | Rules out |
| --- | --- |
| direct `NNNNN-name` child of the plan dir | `mkdir -p <plan-dir>/Completed` (archive dir) |
| not inside a heredoc body | writing the command into a document |
| folder does not already exist | `mkdir -p <plan>/JOURNAL` on an existing plan; a `-p` re-create |
| target resolves inside the workspace | acceptance-test fixture trees under `/tmp` |
| `mkplan.bash` deployed | a project with no scaffolder, where `mkdir` is the ONLY path |

The fourth is not hypothetical: `plan_workflow.py` ships
`setup_commands=["mkdir -p /tmp/acceptance-test-planwf/CLAUDE/Plan/099-test"]`,
which the rule would otherwise deny during acceptance testing. The fifth is the
one that would have been easiest to skip — denying the only available path
would leave an agent unable to create a plan at all, and the deny message would
name a script that is not there.

Absolute and relative spellings resolve through one expression, because pathlib
`/` lets an absolute right-hand side replace the base:

```python
target = self._workspace_root / candidate   # handles both spellings
```

## 03:02 · finding · T4.10 — reading my own diff found a false positive `..` defeats

The containment check was `(workspace_root / candidate).is_relative_to(workspace_root)`.
pathlib joins **lexically** and keeps `..` as a literal segment, so
`workspace/../sibling-repo/CLAUDE/Plan/00250-x` still *begins with* the
workspace root and tested as "inside". A plan folder in a neighbouring checkout
would have been denied, with THIS project's scaffolder named as the remedy.

Test first, and it failed exactly as predicted (`assert not True`). Fixed with
`Path(os.path.normpath(...))` — purely lexical, no filesystem access and no
symlink resolution, which is what a containment question actually needs.

Worth naming the shape: this was found by re-reading my own diff before
committing, not by any test I had thought to write. The five conditions were
each defensible; the one that was wrong was the one I had implemented most
confidently.

## 03:08 · finding · T4.10 — the heredoc guard I wrote was itself an evasion

My first pass used a hand-rolled `_HEREDOC_PATTERN` and bailed if it matched
**anywhere** in the command. That exempts the WHOLE command, so appending a
throwaway heredoc waves the creation straight through — a guard that teaches
its own bypass.

`strip_quoted_heredoc_bodies` in `utils/shell_segmentation.py` already existed
and blanks only the BODY of a quoted-delimiter heredoc, leaving the rest of the
command intact. It is what `pipe_blocker` uses. So the fix was to delete my
constant and compose the shared utilities:

```python
scannable = blank_shell_literal_spans(strip_quoted_heredoc_bodies(command))
```

DRY, and it matches the documented project-wide convention (quote the delimiter
for prose; an unquoted heredoc IS scanned, deliberately). Both directions are
now tested: a `mkdir` inside a quoted body is allowed, a `mkdir` after the
closing `EOF` is not.

Checked the composition ORDER by measurement rather than argument, because a
heredoc nested inside a quoted string could plausibly desynchronise the two
passes:

```
raw                  needle_present=True
quotes only          needle_present=False
heredoc only         needle_present=True
heredoc -> quotes    needle_present=False
quotes -> heredoc    needle_present=False
```

Both orders blank correctly on that input; no ordering bug. Recorded because
the theory that sent me looking was wrong, and the measurement is what settled
it.

## 03:14 · thought · T4.10 — the live probe blocked itself, which is the design working

The first attempt at the final probe was denied by the very handler it was
testing: the script passed `mkdir -p CLAUDE/Plan/99999-probe` as a shell
argument, and the full command string carries that literal.

This is not a bug and must not be "fixed" — `CLAUDE.md` states it outright:

handlers by embedding dangerous commands in strings. The remedy is the
