## 09:00 · finding · P1 — the mechanism, observed

Filed as a follow-on to Plan 00336 Task 4.3, which fixed the drifted file and
deliberately left the reason it went unnoticed to this plan.

```
$ git check-ignore -v .claude/skills/hooks-daemon/SKILL.md
.claude/.gitignore:3:hooks-daemon/	.claude/skills/hooks-daemon/SKILL.md
```

`.claude/.gitignore` line 3 sits under the comment "Exclude the cloned daemon
repository (users install it themselves)" — the intended target is
`.claude/hooks-daemon/`. Without a leading slash git matches the pattern at any
depth, so the deployed skill tree is swept up with it.

The asymmetry is what makes it a design question rather than a typo: the other
deployed skill, `.claude/skills/docs-qa/`, IS tracked, and its own drift
surfaced immediately when `deploy_skills` ran during 00336. Two adjacent
deployed trees, opposite treatment, no decision behind it.

## 15:47 · finding · T1.2 — no client can have this, which changes the fix's scope

The plan assumed the client case was the one that mattered, on the reasoning
that the installer writes this file everywhere. It writes a DIFFERENT line:

```bash
# ensure_claude_gitignore(), scripts/install/gitignore.sh
hooks-daemon/untracked/
```

Two segments, so it cannot match `.claude/skills/hooks-daemon/` however
unanchored it is. A repo-wide search finds the bare `hooks-daemon/` in exactly
one file — this repo's own `.claude/.gitignore`, present since the initial
commit and written by no template. So the defect is local to the self-install
checkout, and no installer change is needed.

Worth recording as a correction: the plan's own framing ("the CLIENT case is
the one that actually matters") was reasonable and wrong, and checking took
one grep.

## 15:52 · decision · T3.1 — an integration test, not a docs_qa check

The plan suggested folding this into `generated_doc_hand_edit`, which already
owns "this file is generated". It does not fit: that check is keyed by a
manifest of document globs, and a skill tree is not a document — it ships
`.sh` scripts too. The property is whole-tree equality, file SET as well as
contents, which a per-file manifest cannot state.

A new entry in the 25-check QA suite was the other candidate. Rejected as
disproportionate for one structural invariant: a pytest integration test runs
in the same suite, fails with the drifted paths listed, and needs no new JSON
artefact or docs. `test_plan_index_navigability.py` is the precedent.

The test states its properties over the trees that EXIST rather than a
hardcoded list, so a seventh skill is covered the day it is added.
