## Why none is a FIX

init.sh's forwarder runs no venv by design (init.sh says "Venv Python only needed for daemon
startup, NOT for hot path"). The snippets run exactly when the daemon or venv is absent or
unusable, and each has a static, python-free last resort (`_hooks_daemon_static_deny`,
the printf answers at init.sh:609-613). No resolved interpreter exists at those call sites, and
resolving one would add latency to every hook. The remaining hazard is "PATH python3 is < 3.11",
which is only harmless if the snippets run on the oldest Python. That was tested, not assumed.

## 3.8 / 3.9 evidence

Interpreters: `uv python find 3.8` = 3.8.20, `3.9` = 3.9.25 (3.10 absent).
New test `tests/integration/test_init_sh_hot_path_runs_on_old_python.py` (24 tests, passing:
12 cases x {3.8, 3.9}). It deploys init.sh into a scratch checkout, puts the old interpreter
first on a curated PATH as `python3`, with jq absent, then sources init.sh and calls the real
functions. Each case asserts a correct result and no `Traceback`/`SyntaxError` on stderr. Source
extraction is done by bash itself, so the `$`-expanded snippets are tested as they really run.
A harness test asserts the shim's minor version is < 11.
