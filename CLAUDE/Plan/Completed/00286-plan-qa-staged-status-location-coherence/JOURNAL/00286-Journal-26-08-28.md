## 20:25 · finding · P1 — root cause confirmed

`staged_context()` (`plan_qa/context.py`) builds `context.tree` by scanning
the WORKTREE filesystem (`PlanTree.scan`), not the staged git index. The
COMMIT-stage registration of `location-status-coherence`
(`plan_qa/checks/location_status_coherence.py`) reads `context.tree`, so it
inspects worktree content even when invoked as the commit gate — it never
looks at what `git commit` would actually write. `terminal-state-atomic`
reads the STAGED blob correctly (`gitfacts.staged_file_text`), but only in
the flip→must-move direction, not the mv→must-carry-terminal-status
direction the field bug hit. Proceeding to TDD a new
`archived-status-coherence` check that reads staged blobs directly.
