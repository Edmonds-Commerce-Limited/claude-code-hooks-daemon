## Resolver public API (for Phases 3 and 4)

`claude_code_hooks_daemon.utils.claude_config`:

- `claude_config_dir(*, environ: Mapping[str, str] | None = None, home: Path | None = None) -> Path`
  returns `$CLAUDE_CONFIG_DIR` (with `~` expanded), else `~/.claude`. The
  result is not resolved.
- `config_dir_within(project_root: Path, *, config_dir: Path | None = None) -> str | None`
  returns the config dir's POSIX path relative to the project when it is
  inside it (both paths resolved), else `None`. It never returns the root
  itself.

`claude_code_hooks_daemon.utils.claude_plugins`:

- `resolve_enabled_plugins(project_root: Path, *, config_dir: Path | None = None, managed_dir: Path | None = None) -> PluginInventory`.
- `default_managed_settings_dir() -> Path`.
- `PluginInventory(config_dir, enabled: tuple[EnabledPlugin, ...], unresolved: tuple[UnresolvedPlugin, ...])`
  has these methods: `find_agent(scoped_id) -> PluginAgent | None`,
  `agents()`, `skills()` and `lsp_servers()`.
- `EnabledPlugin` has these fields: `plugin_id`, `name`, `marketplace`,
  `enabled_by: SettingsScope | None`, `install_scope`, `install_path`,
  `version`, `agents`, `skills`, `hooks`, `lsp_servers` and `problems`. It
  also has a `.hook_events` property.
- The other types:
  - `PluginAgent(scoped_id, path, frontmatter)`;
  - `PluginSkill(scoped_name, kind: SkillKind, path, frontmatter)`;
  - `PluginHookSource(path | None, events)`, with `.event_names`;
  - `PluginLspServer(name, command, extension_to_language)`, with `.extensions`;
  - `UnresolvedPlugin(plugin_id, enabled_by, reason)`.
- Enums: `SettingsScope` (USER, PROJECT, LOCAL, MANAGED) and `SkillKind`
  (SKILL, COMMAND).

`claude_code_hooks_daemon.utils.subagent_tool_resolution`:

- `resolve_agent_definition(agent_type, project_root, *, config_dir=None) -> AgentDefinition | None`.
  The tiers are checked in the order project, user, built-in, then plugin.
  The plugin tier applies only when the id contains `:`.
- `AgentDefinition(agent_type, source: AgentSource, path, frontmatter, can_write)`
  has the properties `.isolation` and `.declares_worktree_isolation`.
- `resolve_agent_can_write(agent_type, project_root, *, config_dir=None) -> bool | None`.

The other public additions:

- `markdown_format.parse_frontmatter_lenient(content) -> dict | None`;
- `subagent_report_paths.sanitise_component`;
- `tool_report.plugin_costs.plugin_listing_costs(inventory) -> tuple[PluginListingCost, ...]`;
- `skill_scan.extraction.derive_transcript_dir(project_root, *, config_dir=None)`.

Test helper: `tests/claude_plugin_fixture.install_fake_plugin(config_dir, project_root, ...)`.

## Known limits

- These sources are not resolved: `@skills-dir`, `@synced` and `--plugin-dir`
  plugins, and MDM or server-managed settings. The resolver reports them in
  `unresolved`; the bare user-scope `phpantom-lsp` lands there.
- A project-scope install records `projectPath: /workspace`. In a git worktree
  (a different project root) the resolver therefore treats DBF as not active.
  Whether Claude Code does the same in a worktree session is not verified.
- `claude_config_dir()` reads the daemon's environment, which is fixed when it
  starts.
