## 18:42 · finding · —   — Sweep, RED evidence, and a neighbouring journal race

Re-verified the plan against today's code before building. Dispatch is still threaded (`server.py:1443`, `run_in_executor(None, controller.dispatch, ...)`). All eight listed sites still carry the unlocked select-then-evict. The DBF sweep used two techniques: the new semgrep rule, and a grep for `len(self._x) >=` bounded maps plus `del self._x[` deletes. Together they found 12 instances in 10 handlers. The two the review missed are `git_context_injector` (a `min()` victim scan) and `standing_authorisations`.

RED, at the minimum switch interval (32 threads x 2000 calls): all 12 site contention tests raised `KeyError` or `RuntimeError`, and so did the `write_clobber_guard` Read test. The FIFO-order tests already passed. Every site was FIFO, so those tests pin the behaviour rather than fix it.

A neighbouring defect showed up at the two journalled sites. `SideEffectJournal` shared one undo list across concurrent requests. Its RED test showed `IndexError` from racing rollbacks, and one request's commit or rollback leaking into another's state. It is fixed with per-thread records, because a dispatch runs `handle()` and `commit_side_effects()` on one thread.

A second neighbour is out of scope: `recovery_cron_advisor._cached_phase` passes per-call state between `matches()` and `handle()` through the singleton. It is filed as 00466 N23.

`test_each_key_is_claimed_exactly_once_under_contention` (model_fallback_detector) was not observed RED before the change. The check-then-insert window without an eviction is too narrow to hit. It stays as a pin on `insert_if_absent`.

## 18:42 · decision · —   — Task 3.1 and the primitive

Task 3.1: build the QA check, and make it block. The rule is `scripts/qa/semgrep/unlocked-eviction.yaml` (`unlocked-select-then-evict`), and the existing semgrep gate picks it up with no wiring. It had no false positives over `src/` and `scripts/`, and the locked spelling inside `with <lock>:` is exempt, so its precision is already paid for. It went in before any fix (commit 5e3e784f), per Defence Before Fix.

Primitive: a second small primitive, `BoundedFifoMap`, not a framework. `SessionAdviceCounter` fits none of the remaining sites, because none is a per-session rate limit. `setdefault` is exposed as `get_or_insert`, because overriding `setdefault` with a required default breaks `MutableMapping`'s signature (pyright). The inherited `setdefault` still bounds and cannot raise.

Journalled insert order: the victim is snapshotted before the new key. Rollback undoes newest-first, so it removes the key before restoring the victim, and the restoration cannot evict an innocent entry from a full map.
