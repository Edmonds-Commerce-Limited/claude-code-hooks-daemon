# Fact check: Plan 00499 PLAN.md (whole document, new plan)

## REFUTED (most consequential first)

1. Task 1.1 lists `sed -i` among the routes "Reuse the accessor ... uses" covers. The accessor does not read `sed -i`.
   `core/utils.py` `_write_target_tokens` (lines ~855-885) recognises only: redirect operators (`>`, `>>`, `>|`, `&>`, `&>>`),
   `tee`, `cp`/`mv`/`install` (`_COPY_VERBS`, line 58) and `dd of=`. `_WRITE_INDICATOR_RE` (line 122) lists
   `>|of=|tee|cp|mv|install|dd`. There is no `sed`, `ln`, `rm` or `truncate` handling anywhere in it. The same goes for
   `: >`, which only works because it is a plain redirect.
   Changes in plan: the "extend it" half of Task 1.1 must add `sed -i` (and `-i` combined flags, `--in-place`), `ln`, `rm` and
   `truncate` as NEW verb recognisers, not just "relocation and deletion targets". The covered/new split should be restated:
   covered = redirect, `tee`, heredoc redirect, `cp`/`mv`/`install`, `dd of=`; new = `sed -i`, `ln`, `rm`, `truncate`.

2. Task 1.1 implies `get_written_file_paths` ("the accessor lint_on_edit uses") returns relocation targets. It does not.
   `get_written_file_paths` (`core/utils.py:589-628`) calls `get_bash_write_targets(..., authored_only=True)`, which drops
   `cp`/`mv`/`install`/`dd` (they are `authored=False`, lines 876-888, 936). It also handles only `Write`/`Edit` (line 625), not
   `NotebookEdit`. A location guard must use `scan_bash_write_targets` (line 354) with `authored_only=False`, and must fail
   closed on its `.unreadable` and `.unresolved` fields (docstring lines 339-343). The plan's "denied when it cannot parse and
   names a listed path" matches that second function, not the one named. Also `dd of=` is a relocation (not authored) in the
   accessor, while the plan groups it with authoring.
   Changes in plan: name `scan_bash_write_targets` (not `get_written_file_paths`) as the base, and say NotebookEdit is
   handled separately via `notebook_path`.

3. Overview/Task 2.3 journal: "The copy the coordinator had written was removed". On disk, `ls -la /workspace/.claude/ccy`
   still lists a `ccy.env.local` entry, with `ls: cannot access ... Permission denied` and `-?????????? ? ? ? ?`.
   `git check-ignore -v` matches it via `.claude/ccy/.gitignore:3:*`. Whether it is a real file, a mount or a stale entry cannot
   be settled from here, but the entry is present, so "removed" is contradicted by the current tree. Changes in plan: confirm
   the state before the Phase 3 hand-off and the Success Criteria wording ("agent can read it") assume a readable file; an
   agent cannot stat the entry that exists now.
