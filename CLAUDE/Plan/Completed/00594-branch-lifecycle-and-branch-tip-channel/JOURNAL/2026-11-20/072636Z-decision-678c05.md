Finding 4 (Low) ACCEPTED RESIDUE, with reasons:

- Holder leases: `git push --force-with-lease=<ref>:<sha>` only constrains a ref the push itself updates; a lease naming a holder the push does not touch is ignored, and git has no "assert this other ref" primitive. Pushing the holder to itself under a lease would be a no-op update with no atomicity across refs unless `--atomic` is supported by the server, and it would then write to the holder. Not worth the risk; the force-push guard already covers rewriting a holder.
- Raw hook route: the hook allows or denies the agent's own `git push --delete`; it cannot add a lease to it. Denying raw deletes outright and pointing to `delete-branch --remote-only` (which leases) would close the race, but it changes the contract of an allowed command, so it is a decision for the coordinator, not this fix.

Pre-existing gap for the coordinator to ledger (Finding 2; NOT put in the niggles ledger on this branch, to avoid number collisions): `gh pr close N --delete-branch` (also `-d`) and `gh api -X DELETE repos/{o}/{r}/git/refs/heads/<name>` (also `--method DELETE`) delete a remote branch with no proof, and no handler reads them. `gh pr merge --delete-branch` after a real merge is the false-positive shape a fix must judge rather than deny.
