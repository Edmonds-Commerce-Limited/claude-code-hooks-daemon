## 05:50 · finding · T3.1 — the gate went 33/35 on drift this plan exposed but did not cause

`llm_qa.py all` returned 2 failed gates, and both were one root cause:
`handler_reference` flagged `subagent_cron_delete_blocker` as a PreToolUse
blocking handler with no section in `docs/guides/HANDLER_REFERENCE.md`, and the
`tests` gate's single failure was `test_handler_reference_check.py`, which
fronts the same check.

Verified as pre-existing rather than assumed: a worktree at `1b8e2692` (before
this plan began) has the handler present and the doc section absent, so the gap
shipped with Plan 00423.

The interesting part is WHY it surfaced now. The coverage rule reads
`.claude/HOOKS-DAEMON.md` — the generated "Active Configuration" inventory —
and that file had not been regenerated since the handler landed. This plan's
`generate-docs` run added the row:

```
+| 14 | subagent_cron_delete_blocker | BLOCKING | Deny ``CronDelete`` inside a subagent; the coordinator is unaffected |
```

and the rule fired immediately. So the guard was never broken; it was reading a
stale inventory, and a coverage rule whose inventory goes stale reports clean
over a shrinking set without ever saying so. Worth noting as a defect SHAPE:
the check's own docstring calls this limitation out ("the rule is therefore a
floor, not a ceiling") for DISABLED handlers, but the staleness path is the
same hole from a different direction.

Fixed in `5f492887` as its own commit, since it is not this plan's work.
