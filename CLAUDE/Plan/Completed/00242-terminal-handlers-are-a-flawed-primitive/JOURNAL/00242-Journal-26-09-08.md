> **Append-only activity log** for plan 00242. One file per day
> (`00242-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` local 24h (the date is in the filename); times increase down the file.
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 21:55 · finding · P1 — the old chain terminated on ANY terminal match

whatever the decision; the Plan 00144 most-restrictive-wins merge only
governed which result was SHOWN. The legacy `FrontController` had the same
shape. `Handler.__init__` defaults `terminal=True`, so 26 handlers were
terminal by omission on top of 17 explicit ones.

## 22:20 · finding · — — the Stop-chain guard encoded the old semantics

`test_stop_chain_terminal_shadowing.py` asserted a probe above priority 10
is shadowed on an ALLOWED stop. Under the invariant it now runs; it is
shadowed only when `auto_continue_stop` BLOCKS the stop (no `STOPPING

## 22:30 · decision · P2 — rollback journal, not a two-phase handler split

Side effects stay in `handle()`; `Handler.commit_side_effects(hook_input,
chain_decision)` (concrete no-op) is called by the chain for every executed
handler after the merged decision, in every mode. `SideEffectJournal`
(`core/side_effect_journal.py`) snapshots a key before mutation and rolls
back on a restrictive decision. `command_hints` and `recovery_cron_advisor`
adopt it; `lsp_enforcement`'s block-once is fixed at the controller, which
now records each handler's OWN verdict in the history instead of the merged
decision for every matched handler. Full audit: `SIDE-EFFECTS.md`.

## 22:35 · finding · T1.2 — collect-all costs ~2 ms on the worst path

Real controller from this repo's config (59 PreToolUse handlers), 200
iterations per cell. Four-deny Write: 0.34 ms short-circuited vs 2.03 ms
p50 / 2.49 ms p95 collect-all; two-deny Bash 0.19 vs 1.15 ms. Under the
~100 ms p95 budget by two orders of magnitude, so a deny does not
short-circuit in collect-all mode. Table and bounds: `MEASUREMENTS.md`.

## 22:45 · decision · T4.1 — keep `terminal`, reduced to an optimisation

Deleting the flag touches 125 handler constructors, the docs generator's
BLOCKING/ADVISORY fallback, `hooks-daemon handlers` output and the verdict
log schema for no semantic gain: under the invariant the flag can no longer
change what the chain decides, only whether the rest of the chain runs after
a deny. Kept with that meaning, documented in `Handler` and
HANDLER_DEVELOPMENT.md; the classification in `TERMINAL-HANDLERS.md` records
which handlers' ALLOWs were the defect class.
