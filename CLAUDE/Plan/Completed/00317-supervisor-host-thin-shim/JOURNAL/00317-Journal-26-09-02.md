## 10:10 · decision · T2.2 — Ctrl+C gate stays host-side

Per the audit: the byte-level swallow (`CtrlCGate.filter`) cannot round-trip
to the worker without adding forwarding latency or reintroducing a
hold-and-forward buffer — exactly what the plan warned against. Its policy
inputs (env-resolved window/enabled) are read once at session start, not
per-tick, so hot-reloading them would need a new re-arming mechanism with no
clear benefit. Event surfacing (status-line hint) is synchronously tied to
the swallow decision. No code change needed here beyond what the audit
documents — the existing implementation was ALREADY minimal.

## 10:45 · action · T2.1/T2.3 — raw-input tap + worker-side recognition

Added `RawInputTap` (bounded bytearray, oldest-drop overflow, host-side,
fed alongside `InputActivity.record` in `_forward_io`). `TickFacts` gained
`human_raw_input` (base64, JSON round-tripped). `run_worker` now owns its
own persistent `HumanInputLine` instance, fed each tick's raw input, and
OVERRIDES the host-sent `human_compact_submitted`/`human_model_command`/
`human_effort_command`/`input_line_empty` with what it recognises — this is
the piece that makes recognition hot-reloadable. Host's own `HumanInputLine`
(on `InputActivity.line`) kept unchanged, now serving ONLY the in-process
fallback path (`_poll_once`) — deliberately not hot-reloading, matching the
pre-existing fallback-degradation pattern.

New tests: `tests/unit/supervise/test_raw_input_tap.py` (tap bounds,
fail-open forwarding with an un-drained tap), additions to
`tests/unit/supervise/test_policy_worker.py` (worker recognises a command
from raw input across split ticks; a JSON roundtrip for the new field;
and — Task 2.3's reload proof —
`test_worker_restart_alone_picks_up_changed_recognition_behaviour`, which
edits an on-disk COPY of the script (renaming the recognised `/model` prefix)
and shows a fresh `PolicyWorker` over that copy recognises differently,
proving the change ships via worker restart alone, no host code touched.

All 618 pre-existing `tests/unit/supervise/` tests pass UNCHANGED (624 total
after additions) — the host-side `InputActivity`/`HumanInputLine` API surface
those tests exercise was deliberately left alone. Module docstring and
