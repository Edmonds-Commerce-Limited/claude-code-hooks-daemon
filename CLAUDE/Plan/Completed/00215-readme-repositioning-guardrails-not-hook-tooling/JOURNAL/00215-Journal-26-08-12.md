## 16:10 · finding · — — exact line counts were the defect, not the cure

Closing check on the "every number re-measured" criterion found the two
line-count figures already stale — within the hour, from a single merge:

```
claimed:   69,419 lines of source, 157,974 lines of tests
measured:  70,601 lines of source, 159,656 lines of tests
```

Nothing was wrong when they were written; the Plan 00209 merge landed ~2,300
lines and moved them. Re-measuring would have bought a few hours before the
00213 merge (+2,767 lines) invalidated them again. So the honest fix was to
stop asserting a precision that decays on every commit: the figures are now
`~70,000` / `~160,000`, which stay true for a long time, and the interesting
claim — the `2.3×` ratio — is unchanged and still measures 2.26.

Worth stating as a general point for this README: a number that must be
re-derived on every merge to remain true does not belong in a document nobody
re-derives on every merge. Either round it until it is robust, or generate it.

The test-count badge (`11400+`) needed no change — a floor claim is already
robust by construction, and the suite now stands at 11,964.
