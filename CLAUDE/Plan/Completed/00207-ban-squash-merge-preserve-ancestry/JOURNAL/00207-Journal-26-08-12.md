Design: three ordered `(pattern, label)` pairs mirroring `destructive_git`'s

already matches "gh" inside a path-qualified binary). All three patterns scope

different chained command, or the words "squash"/"rebase" in a commit message
or filename, cannot false-positive. `mode` defaults to `"block"` (plan-specified
wording, distinct from `git_stash`'s `"deny"`), alternate `"warn"`; escape hatch
`MUST_SQUASH_BECAUSE="reason"` covers both squash and rebase-merge per Task 1.2.

## 16:05 · finding · T3.2 — the probe harness was wrong, not the handler

Closed the outstanding live verification at the real project root. First
attempt returned `allow` for all six deny cases, which read as "the handler is
not firing":

```
FAIL  expect=deny   got=allow   git merge --squash feature
FAIL  expect=deny   got=allow   gh pr merge --squash 12
... 4 more
```

That was a false result. Minutes earlier the live daemon had blocked the very
same command when it went through the real hook path — it blocked my own
`Bash` probe loop, because the handler matches the full command string and my
loop had the literal in it. Two observations of the same daemon disagreed, so
one of them had to be the instrument.

The instrument was mine: a hand-rolled `AF_UNIX` client that guessed the wire
protocol. Rewrote it to drive the PRODUCTION forwarder
(`.claude/hooks/pre-tool-use`) with the payload on stdin, and assembled the
blocked literals from fragments at runtime (`"--" + "squash"`) so the launching
Bash command never contains them:

```
OK  expect=deny   got=deny   git merge --squash feature
OK  expect=deny   got=deny   gh pr merge --squash 12
OK  expect=deny   got=deny   gh pr merge --rebase 12
OK  expect=deny   got=deny   git  merge   --squash  feature
OK  expect=deny   got=deny   gh pr merge 12 --squash
OK  expect=deny   got=deny   /usr/bin/git merge --squash feature
OK  expect=allow  got=allow  MUST_SQUASH_BECAUSE="platform mandates it"; git merge --squash feature
OK  expect=allow  got=allow  git merge --no-ff feature
OK  expect=allow  got=allow  gh pr merge --merge 12
OK  expect=allow  got=allow  git rebase main

10/10 spellings behaved as specified
```

Takeaway worth carrying: a verification tool that bypasses the production entry
point can fail in the direction that reports a working guard as broken — or, far
worse, a broken guard as working. The only reason this was caught is that a
contradicting observation existed. Probe through the real entry point.
