# Plan 00256 Journal — 2026-08-19

## 09:20 · closing · the round is done, and one guard outlived it

Closing this plan. All ten tasks were delivered and verified; the status line
had simply never been flipped, which is exactly the `header-body-coherence`
shape the plan QA edit rule blocks on new material. It sat that way through the
whole of the v3.54.0 release pipeline without anything noticing — worth saying
plainly, because the sweep only *advises* on what is already on disk.

**What was actually delivered**: eight documentation corrections (`4e064e15`,
plus two more in the release commit `3b1c99a0`), and one guard.

**The guard is the part that matters.** Task 1.4 was a one-line fix — a
`config-changes` manifest still carrying `date: "UNRELEASED"` after being moved
into the live directory. Task 1.5 existed because fixing that one line was the
wrong stopping point: the same placeholder had already escaped in four shipped
manifests, and nothing in the codebase could see it. Nothing reads that field
at runtime — `ConfigMigrationManifest` parses it into an attribute that is
never rendered or compared — so a wrong value is completely silent, and a
static check was the only possible guard. That is `check_repo_hygiene.py`'s
`unreleased-manifest-date` rule.

This is the DBF principle doing real work rather than being quoted: the defect
was the symptom, the blind guard was the bug. Four instances had already
shipped precisely because the hand-fix had been available all along and the
guard had not.

**What I would not claim**: that the release documents are now free of drift.
This round fixed what two gates surfaced from one release. The general problem
— documents restating counts and procedures that generators own — is only
partly addressed, and Tasks 3.1/3.4 fixed the instances found, not the class.
`RELEASING.md` is long, and I read the parts the release exercised.

Follow-on work lives in Plan 00257 (three daemon guards misfired during this
release; two of the three are still open) and Plan 00259 (the artefact
blocker). Neither is blocked by closing this one.
