## 14:10 · progress · Phase 1 Tasks 1.1 and 1.2 decided against the code

Gap confirmed: nine lint strategies, no YAML one, and no YAML handling
anywhere else.

Two of the report's suggestions did not survive contact with the code.

**A path allowlist misses `site.yml`** — the canonical Ansible entry point sits
at the repository root and matches none of `playbooks/`, `tasks/`, `roles/`,
`play-*.yml`.

**And a parse-based content test cannot see the file this feature exists to
catch.** The obvious content discriminator is "top-level LIST with `hosts:`" —
which cleanly separates a playbook from a workflow, a daemon config and an
inventory, and which requires the file to PARSE. The motivating incident was a
file that failed to parse. That test would lint every healthy playbook and skip
every broken one.

So: accept on path OR a crude text sniff that still works on a broken file;
use the parse only as confirmation, never as a gate. Vault files are excluded
by content prefix and never read.

**Where the discriminator lives.** `get_strategy` maps by extension suffix
alone, and `skip_paths` is a substring blacklist — neither can express "only
these YAML files". Adding the test to `LintStrategy` would break the suite:
it is `runtime_checkable`, `isinstance` on such a protocol tests member
PRESENCE, and there are 13 `isinstance(strategy, LintStrategy)` assertions that
would start failing for eight strategies that have no use for the method.
A separate capability protocol avoids all of it, and is already the house
idiom — `HasClaudeMd` in `core/claude_md_injector.py` is the same shape.

**Task 1.2 needed no new machinery at all.** `_MODULE_ROOT_MARKERS` +
`_find_module_root` already walk up from a file to the nearest marker and feed
the result to the subprocess `cwd`; Go uses it for `go.mod`. Ansible maps to
`ansible.cfg`. The one-marker-per-language limit is recorded rather than fixed
— widening it touches Go's entry and its tests for a layout nobody has
reported.

## Tasks 1.3-1.5 — the strategy, the registry, and the guidance

`AnsibleLintStrategy` built to the Task 1.1 rule: excluded-path, then vault
prefix, then playbook-path, then a line-based `- hosts:` / `- import_playbook:`
sniff. Two tests carry the whole argument — an unparseable playbook is still
claimed, and an unparseable NON-playbook is still declined, so surviving a
broken parse is not the same as claiming any broken YAML.

`NarrowsByPath` went into `protocol.py` as its own capability protocol, and
`get_strategy` now `continue`s past a strategy that declines. A test asserts a
non-narrowing strategy is unaffected, because that is the property the other
eight depend on.

**QA found a real defect in my own `_sniff`, and the finding was correct.**
`error_hiding`'s `return-none-on-error` fired on the `except (OSError,
ValueError): return None`. It was tempting to read that as a false positive —
the absent-file case is real and documented. It was not one. The handler
collapsed three different situations into one answer: absent, a directory, and
UNREADABLE. The third is the problem — a playbook the daemon cannot read would
have been silently reported as "not Ansible", so a permissions fault would take
the lint off with no signal anywhere.

The fix removes the handler rather than excluding the rule. `is_file()` is a
precondition, and it already answers absent, directory, unstattable and
malformed-path (Python catches `OSError`/`ValueError` inside it — verified, not
assumed). A genuine read failure after that gate now propagates. No suppression
was added, and none was needed.

Guidance names which YAML is claimed and which is left alone, both tiers, and
the `ansible.cfg` cwd rule. QA 23/23; daemon RUNNING.

**The client-mode check cannot see uncommitted work.** `dummy-client-repo.sh`
provisions a detached worktree at `HEAD` and drives the production installer
over it, so a fixture built while this sat unstaged registered nine languages
and no Ansible — correct behaviour, not a failure. Commit first, then rebuild
the fixture. Worth stating plainly here because the empty result looks exactly
like a broken install.
