## 14:10 · progress · Phase 1 Tasks 1.1 and 1.2 decided against the code

Gap confirmed: nine lint strategies, no YAML one, and no YAML handling
anywhere else.

Two of the report's suggestions did not survive contact with the code.

**A path allowlist misses `site.yml`** — the canonical Ansible entry point sits
at the repository root and matches none of `playbooks/`, `tasks/`, `roles/`,
`play-*.yml`.

**And a parse-based content test cannot see the file this feature exists to
catch.** The obvious content discriminator is "top-level LIST with `hosts:`" —
which cleanly separates a playbook from a workflow, a daemon config and an
inventory, and which requires the file to PARSE. The motivating incident was a
file that failed to parse. That test would lint every healthy playbook and skip
every broken one.

So: accept on path OR a crude text sniff that still works on a broken file;
use the parse only as confirmation, never as a gate. Vault files are excluded
by content prefix and never read.

**Where the discriminator lives.** `get_strategy` maps by extension suffix
alone, and `skip_paths` is a substring blacklist — neither can express "only
these YAML files". Adding the test to `LintStrategy` would break the suite:
it is `runtime_checkable`, `isinstance` on such a protocol tests member
PRESENCE, and there are 13 `isinstance(strategy, LintStrategy)` assertions that
would start failing for eight strategies that have no use for the method.
A separate capability protocol avoids all of it, and is already the house
idiom — `HasClaudeMd` in `core/claude_md_injector.py` is the same shape.

**Task 1.2 needed no new machinery at all.** `_MODULE_ROOT_MARKERS` +
`_find_module_root` already walk up from a file to the nearest marker and feed
the result to the subprocess `cwd`; Go uses it for `go.mod`. Ansible maps to
`ansible.cfg`. The one-marker-per-language limit is recorded rather than fixed
— widening it touches Go's entry and its tests for a layout nobody has
reported.
