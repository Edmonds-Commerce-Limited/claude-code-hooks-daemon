The report replays superseded truths rather than the current delta. Verified
directly in the emitted output, the plan-creation truth appears three times:

- v3.23.0 — WAS "no bundled scaffolding script" → NOW "run `mkplan.bash`"
- v3.25.0 — WAS "installer-deployed only" → NOW "deployed from config SSoT"
- v3.26.0 — WAS "deployed from config SSoT" → NOW "opt-in, defaults false"

Only v3.26.0 is current. The skill says to update the project's doc to assert
each `now`, so following it literally writes a claim and then contradicts it
twice. `## Notes & Updates` → `## Delivery & Milestones` repeats the shape
across v3.40.0 and v3.49.1.

This is why Phase 1 leads on collapsing rather than bounding: bounding a
report that instructs wrong work just truncates the wrong work.

large reports to a file") and its own upgrade flow does the thing that
handler exists to prevent.
