## The safety net was built first

The net was committed before any test that touches signal code was run.
`tests/unit/test_signal_safety_net.py` proves each refusal on a net whose
delegates are recording fakes, so a defect in the net cannot deliver anything.
Only then does it exercise the installed net. Before calling `os.kill(1, SIGKILL)`
or `os.killpg(own_group, SIGKILL)`, it asserts two things: the wrapper is the
installed one, and the wrapper's refusal function refuses that target. It then
asserts the call raises.

A refusal is recorded as well as raised. A function-scoped autouse fixture
fails any test that leaves a refusal behind, so code that wraps its kill in
`except Exception` cannot hide one. One existing test sent SIGWINCH to its own
pid. It now uses `signal.pthread_kill` to the main thread instead.

## Helper contract (`utils/safe_signal.py`)

The helper refuses, in every case:

- a pid that is not `type(pid) is int`, or is \<= 1 (this covers a bool and a
  `MagicMock`);
- this process, the leader of its own group, and any ancestor (from
  `psutil.Process().parents()`).

For a daemon, it checks the command line with the SSOT matchers in
`process_verification`, and the project root must equal the root given. The
psutil handle re-checks the start time before each signal. It raises
`ProcessLookupError` or `PermissionError` as appropriate. For a group, the
target must be still running, unreaped (`poll()` is None; a mock's non-int
`poll()` answer is refused), and must lead its group, which may not be ours.
Tests use real children started with `start_new_session=True`.

## Not changed, and why

- `cli.py cmd_stop` keeps using `read_pid_file(verify_daemon=True)`. The
  Detector accepts that as proof. Moving it to the project-root check would
  stop an unattributable daemon (one with no `--project-root` and a venv
  outside the project) from being stopped by `stop` at all.
- The skill installer's aside heartbeat, the inner heartbeat `sleep`s and the
  resolver's own watchdog are signalled by `$!` while alive by construction.
  The Security page gives the reasoning.
- N53's unmerged branch must route `_kill_process_group` through
  `signal_own_session_child`. The Detector will report it when that branch
  rebases onto this one.
