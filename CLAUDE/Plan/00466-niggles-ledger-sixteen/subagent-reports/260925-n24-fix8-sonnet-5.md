## R4-B1 (blocker) — fixed, then hardened per team-lead follow-up

`utils/realpath.py`'s hand-written walk matched CPython 3.11's symlink-loop
handling but diverged from 3.13's rewrite: a loop followed by `..` resolved
differently, and a Write through it bypassed `project_containment` on 3.13
(confirmed both ways with the reviewer's own `probe_n24r4_venv313`).

- Deleted the custom `_join_realpath`/`_join_missing` walk. `realpath()` now
  delegates straight to `os.path.realpath(path, strict=False)`.
- Removed `test_a_deep_missing_path_costs_logarithmically_many_lstat_calls`
  (encoded the old fast path's O(log depth) guarantee, which no longer
  holds — traded back for correctness per the assigned fix, since the walk
  it verified was exactly the divergent code). `test_cost_grows_linearly_with_depth`
  stays and still passes (linear cost, well under the superlinear-ratio
  threshold).

**Follow-up (this same round, after team-lead review of the first pass):** a
version-dependent containment answer is not acceptable for a security check —
review 4 proved a REAL Write escapes through loop-then-`..`, so the handler
must DENY on every Python version, not just agree with whichever answer
`os.path.realpath` happens to give on the one running.

- Added `has_symlink_loop(path)` to `utils/realpath.py`: resolves with
  `os.path.realpath(path, strict=True)` and reports `True` only for `ELOOP`
  on the existing prefix, distinct from a plain missing component
  (`ENOENT`/`ENOTDIR`, the ordinary harmless case of a Write to a path that
  does not exist yet). This is version-independent by construction — `ELOOP`
  is a kernel-level `lstat` outcome, not part of the divergent resolution
  logic.
- `project_containment._is_within` now checks `has_symlink_loop(candidate)`
  first and returns `False` (not within) on a loop, before ever calling
  `realpath()`. This denies in BOTH roles `_is_within` serves: the
  root-containment check (a loop candidate is never within the root, so it
  is flagged as offending → DENY) and every exemption check (a loop
  candidate is never within an allowed path either, so it is never exempted).
  Never raises, which matters here: `front_controller.dispatch` wraps the
  WHOLE handler chain in one `try/except Exception` that returns
  `HookResult.error(...)` — its own comment says "allows operation" — so an
  uncaught exception from ANY handler's `matches()`/`handle()` would have
  aborted the entire PreToolUse chain and defaulted to ALLOW. Checked this
  deliberately: `has_symlink_loop` never raises for a filesystem error, only
  `ValueError` for a NUL byte (matching `realpath()`'s own existing
  contract), so the loop path can never trigger that fail-open route.
- Also fixed `secret_file_matching.protecting_pattern` (secret_file_guard)
  and `sensitive_content`'s `_is_secret_list_itself`/`_relative_path_text`,
  the two other callers team-lead named — see their own commits below.
- `test_realpath.py`'s new `TestHasSymlinkLoop` (6 cases: loop, loop+`..`,
  ordinary existing path, plain missing component, dangling link, NUL byte).
- `test_project_containment.py`'s `TestASymlinkLoopFollowedByDotDotOutOfTheRoot`
  now hardcodes DENY (both the escaping shape and a loop whose eventual
  target stays inside the root — the loop itself is what is denied, not
  merely its destination).
- Verified on both interpreters: `.venv` (3.11) and the review's own
  `probe_n24r4_venv313` (3.13, `PYTHONPATH=src`, `ensurepip` + `pip install mdformat` to unblock the handler import chain). `test_realpath.py` +
  `test_project_containment.py` + `test_secret_file_matching.py` +
  `test_sensitive_content.py`: 546/546 pass on 3.11, 546/546 on 3.13.
  1939 tests across every file referencing `project_containment`,
  `secret_file_matching` or `SensitiveContentHandler`: all pass on 3.11.

## R4-MA1 (major) — fixed

`init.sh`'s PreToolUse branch denied only a fixed allowlist of named
`error_type`s (`socket_timeout`, `malformed_response`, `connection_lost`,
`connect_backlog_full`, `socket_not_found`, `connection_refused`); anything
the transport's `except` clauses did not name explicitly (`PermissionError`
from a chmod'd socket, `NotADirectoryError`, an over-long socket path, any
other `OSError`) fell into the generic `except Exception` and then to
`emit_error_json`'s fail-open `else` branch.

- Inverted the default: PreToolUse now denies for every `error_type` except
  `invalid_hook_input` and the exact daemon-recovery command.
- Added a version-aware `verb` (`reached`/`responded` for the four
  post-connect types, `unreachable` for everything else including every
  newly-covered unclassified type) so the deny text never claims a daemon was
  "reached" when `connect()` itself never succeeded.
- New tests in `test_init_sh_pretooluse_fail_closed.py`
  (`TestUnclassifiedConnectErrorsFailClosedForPreToolUse`): a real
  `NotADirectoryError` (a socket-path component that is a plain file) and a
  real `OSError`/ENAMETOOLONG (a path past AF_UNIX's ~108-byte `sun_path`
  cap) both DENY end-to-end, the recovery command still isn't denied, and a
  non-PreToolUse event still fails open. RED-checked against the pre-fix
  `init.sh` (`6801b4a96`) with a standalone repro script — confirmed
  fail-open there, fail-closed on the fix.
- `test_init_sh_pretooluse_fail_closed.py`: 25/25 pass.

## Ledger later (not merge-blocking; review 4's own items, for team-lead to file)

- **mi-A**: the MA4 recovery-command carve-out trusts the command TEXT
  (`bin/hooks-daemon restart`), not the binary it resolves to — a planted
  `bin/hooks-daemon` in the hook's `cwd` runs. Not a new capability (the same
  indirection exists while the daemon is up), but cheap to close: require
  the carve-out's `cwd` to be the project root, or `realpath(cwd/bin/hooks-daemon)`
  to equal the project's own launcher.
- **mi-B**: `emit_error_json`'s deny reason says "reached" for
  `socket_not_found`/`connection_refused`, which never actually connected.
  Fix 8 (this round) already gave the equivalent `emit_hook_error` deny path
  a version-aware verb (`unreachable` vs `reached`/`responded`) for R4-MA1 —
  `emit_error_json`'s `verb` at `init.sh`'s PreToolUse branch could take the
  same treatment for the two named types.
- **mi-C** (owner call): `mv .claude/hooks-daemon .claude/hd-old && kill <pid>`
  is allowed by the daemon, and the real hook sequence then reports
  `NOT_INSTALLED`, which is fail-open — indistinguishable from a genuinely
  fresh clone that also has the committed config. Needs an owner decision
  (e.g. an untracked install stamp, or an install-command carve-out in place
  of the fail-open).
- **NIT**: `_open_pidfd` falls back to by-number signalling on Linux for
  `ESRCH`/`EMFILE`, not just an unsupported platform. `ESRCH` should mean
  "not running" (no fallback needed); only `EMFILE`/unsupported-platform
  cases should fall back.
- **NIT**: in the pidfd path's race (the pinned process dies during the
  proof), `cmd_stop` deletes the PID file and socket even though the proof
  just attributed a live process to this project.
- **NIT** (review 3's, still open): the relay's timeout is labelled "os
  error 11" instead of a readable name.
