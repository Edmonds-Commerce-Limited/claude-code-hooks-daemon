## What changed

### Helper: `hooks-daemon probe <event> --json <payload> | --file <path>`

- No similar verb existed. `transport-probe` only reports relay
  availability.
- Code: `src/claude_code_hooks_daemon/daemon/hook_probe.py`; the verb is
  `cmd_probe` in `daemon/cli.py`.
- It sends the payload through the project's own
  `.claude/hooks/<bash_key>` as a `bash` subprocess, the same route the
  acceptance harness uses.
- It sets `synthetic_source` to `manual-probe`. That value is the new
  `MANUAL_PROBE` constant in `daemon/synthetic_traffic.py`.
- A caller's own non-empty marker is kept. A marker the classifier would
  ignore (empty, or not a string) is refused with exit 2, because sending it
  would recreate the defect.
- It fills in whatever the payload leaves out: `hook_event_name`, `cwd`, and
  a fresh `session_id` of the form `manual-probe-<hex8>`.
- The event can be named `PreToolUse`, `pre-tool-use`, `pre_tool_use`, or
  `Status` for the status line.
- Exit codes:
  - 0: the daemon answered, whatever it decided. The Stop forwarder's exit 2
    on a block counts as an answer.
  - 1: no verdict. The daemon was not reached, rejected the event, answered
    with something that is not JSON, or timed out.
  - 2: bad input, and nothing was sent.
- A raw-stdout event such as the status line prints its raw answer.
- `response_decision` and `response_text` moved from the private helpers in
  `tests/acceptance/test_playbook_harness.py` into `hook_probe`, so both
  callers share one copy. The acceptance test collects cleanly; I did not
  run it, because it needs the full live playbook.

### Guard: `tests/integration/test_documented_hook_probes_are_marked.py`

- **Documents checked.** The corpus is the same as
  `test_documented_commands_are_not_self_denied`, plus `.claude/agents/`,
  `.claude/skills/` and the upgrade template.
- **What counts as a probe.** A command counts when it does one of these:
  - pipes into `.claude/hooks/<name>`: with or without `bash`, with an
    absolute or relative prefix, or split with `\` or a leading `|`;
  - redirects into one with `<` or a heredoc;
  - sends a `hook_input` envelope to the daemon socket with `nc -U`. A
    `_system` control message is excluded, because it records no verdict.
- **The rules.** Each probe must carry `synthetic_source`, and each document
  that has one must also show `hooks-daemon probe`.
- **Before the fix.** It found 27 unmarked entry-point probes in 10 documents. Widening
  the detector to the socket then found 4 unmarked `nc -U` sends, in
  documents already on that list.
- **The detector is tested too.** It has positive and negative cases. A
  markdown table row that names `.claude/hooks/status-line` is not a probe.

## Design question: a marked probe cannot test a MAIN- or SUB-scoped handler

`core/handler_scope.py:111` (`scope_admits`) refuses a synthetic event for any
handler scoped `MAIN` or `SUB`. The marker therefore changes the verdict as
well as the log line.

- **Measured.** A marked Stop probe answered `{}`. The same payload unmarked
  was blocked with `R-STOP-NO-REASON`.
- **Handlers affected today:** `auto_continue_stop`, `cron_stop_enforcer`
  and `teammate_reap_advisor` (`MAIN`), and `subagent_cron_delete_blocker`
  (`SUB`).
- **Also affected:** the `orchestrator_simulate` project handler declines
  synthetic events itself. So probing orchestrator-simulate with a marked
  payload tests nothing. That was the case that exposed N12.

So the brief's "mark every documented probe" would have broken
`DEBUGGING_STOP_HOOK.md` and `transcript-inspector.md`. Every Stop probe in
those files exists to see `auto_continue_stop` block, and a marked probe
answers `{}`, which those docs read as "broken". What I did instead:

- The auto_continue_stop probes stay unmarked, each behind a
  `# unmarked-probe: <reason>` line. The guard requires that line, and a
  reason under 20 characters does not count.
- The helper prints a note on events that carry `agent_id`: handlers scoped
  MAIN or SUB never see a marked probe.
- `DEBUGGING_HOOKS.md` names the affected handlers.

I told the lead about this mid-task.

**Owner decision needed.** A marked probe should label the log line without
opting out of scope. One option is a separate field, for example
`probe_as: main|sub`, which `scope_admits` honours only when
`synthetic_source` is also set. The verdict log would still class the event
as synthetic. Without something like that, probing a scoped handler costs a
"real" record every time. This is worth a new ledger entry.

## Other findings (not fixed)

1. **`install/transport_verify.py` sends unmarked probes.** Its payloads use
   session `transport-toggle-probe`, which no rule recognises. Every
   `transport on|off` verification is therefore logged as real traffic. This
   is the same class as N12. The fix is one line per payload, or adding the
   session id to `_SESSION_EXACT`.
2. **Documented probes of guarded commands are denied as typed.**
   `destructive_git` judges the prober's own Bash command. So an agent typing
   `echo '{..."git reset --hard"...}' | bash .claude/hooks/pre-tool-use` is
   denied before the probe runs. I hit this with `probe --json`. This affects
   LLM-INSTALL.md step 5, LLM-UPDATE.md and GETTING_STARTED.md.
   `DEBUGGING_HOOKS.md` now says to use `--file` for such probes. The other
   docs still show the inline form, which works for a human at a terminal but
   not for an agent.
