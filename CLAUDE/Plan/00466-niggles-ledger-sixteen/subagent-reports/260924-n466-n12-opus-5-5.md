## What changed

### Helper: `hooks-daemon probe <event> --json <payload> | --file <path> [--as main|sub]`

- The code is in `src/claude_code_hooks_daemon/daemon/hook_probe.py`. The
  verb is `cmd_probe` in `daemon/cli.py`.
- It sends the payload through the project's own `.claude/hooks/<bash_key>`
  as a `bash` subprocess, the same route the acceptance harness uses.
- It fills in whatever the payload leaves out:
  - `synthetic_source: manual-probe` (the `MANUAL_PROBE` constant);
  - `probe_as` on events that can carry `agent_id`: `main` by default, `sub`
    with `--as sub`, which also sets `agent_id: manual-probe-agent`;
  - `hook_event_name`, `cwd`, and a fresh `session_id` of the form
    `manual-probe-<hex8>`.
- It refuses the following with exit 2, sending nothing:
  - a marker the classifier would ignore (empty, or not a string);
  - a `probe_as` that contradicts `--as`;
  - an `agent_id` on a main probe, or a non-probe `agent_id` on a sub probe;
  - `--as` on an event with no scope.
- A caller's own non-empty marker is kept. The helper prints a note only when
  that marker is not probe-class, because then `probe_as` is inert. The old
  always-on caveat is gone.
- Exit codes:
  - 0: the daemon answered. A Stop block's exit 2 counts as an answer.
  - 1: no verdict.
  - 2: bad input.
- `response_decision` and `response_text` moved into `hook_probe`. The
  acceptance playbook harness imports them from there.

### Design: `probe_as`

A probe answers two separate questions:

- `synthetic_source` says whether it belongs in the real record. A probe does
  not.
- `probe_as` says which thread a scoped handler should judge it as.

Before this change, `scope_admits` refused every synthetic event for `MAIN`
and `SUB`. Measured: a marked Stop probe answered `{}`, while the same
payload unmarked was blocked.

- **Where it lives.** `daemon/synthetic_traffic.py` holds `PROBE_AS_FIELD`,
  `ProbeThread`, `PROBE_CLASS_SOURCES`, `PROBE_AGENT_ID` and `probe_thread()`.
  `core/handler_scope.py` holds `acts_as_main_thread` and `acts_as_subagent`,
  which `scope_admits` uses.
- **Only a probe-class MARKER may name a thread.** `PROBE_CLASS_SOURCES` is
  `manual-probe` and `transport-verify`, declared by name. The session-shape
  fallback never counts. A harness run, a cron tick or a supervisor event
  keeps the refusal whatever it carries.
- **`main`** requires no `agent_id`.
- **`sub`** requires exactly `agent_id == "manual-probe-agent"`. That is a
  documented fixed identity, deliberately not the 17-character shape Claude
  Code mints. A real teammate's id is refused, so a probe cannot borrow one.
- **A contradictory claim is refused whole**, not half-honoured.
- **Real traffic ignores `probe_as`.** Only a synthetic event consults it.
- **Consumers of `agent_id` and of probe events.** Each one was checked, and
  every sensor that records state about real agents now declines a synthetic
  event:
  - `subagent_report_persistence`: `matches` returns False for a synthetic
    event, so no report file is written for the probe agent;
  - `subagent_cache_aggregator`: the status-line totals are not fed by
    probes;
  - `goal_injection`: returns ALLOW early. The goal ledger is project-wide,
    so a probe would otherwise flip a real session's goal;
  - `auto_continue_stop`: a probe never records the human-blocked marker that
    silences the failsafe cron, and its `stop-events.jsonl` line is tagged
    `"synthetic"`.
  - The `orchestrator_simulate` project handler uses `acts_as_main_thread`
    in place of its own agent_id and synthetic checks.
  - `teammate_reap_advisor` and `cron_stop_enforcer` are MAIN-scoped and
    only read the event, so they are covered by scope.

The design is also recorded briefly in `HANDLER_DEVELOPMENT.md` ("Probing the
Live Handler: The design, in brief") and in full in `DEBUGGING_HOOKS.md`.

### Guards

**`tests/integration/test_documented_hook_probes_are_marked.py`** applies
three rules. None has an exemption, and the unmarked-probe annotation is
gone:

1. Every documented dispatch sets `synthetic_source`. A dispatch is any of
   these:
   - a pipe into `.claude/hooks/<name>`, including `\` or leading-`|`
     continuations;
   - a `<` or heredoc redirect;
   - an `nc -U` send of a `hook_input` envelope. A `_system` message is
     excluded.
2. A document with such a command also shows `hooks-daemon probe`.
3. **New:** every inline probe is judged as a Bash PreToolUse, and fails if
   denied. An inline probe is an `echo` payload or `probe --json`, and a prose
   line is judged by its code span. The judge is the real `DaemonController`
   with this repository's own `.claude/hooks-daemon.yaml` handler section.
   - A vacuity test proves the judge denies a guarded inline probe.
   - Before the doc fix, the rule failed on exactly the six
     destructive-git sites. I then checked all 42 inline probes in the
     corpus, and the judge flagged nothing else.
   - Judging by the real handlers means a new guard is covered automatically,
     with no pattern list to maintain.

**The guard: `tests/integration/test_live_probes_are_marked.py`.**

- **Corpus.** `tests/acceptance`, `tests/integration` and `scripts/`
  (`.py`, `.sh`, `.bash`).

- **Which files are judged.** A file is judged when it has a route to the
  LIVE daemon:

  - this repo's `.claude/hooks/` entry points (a path string or a
    `".claude" / "hooks"` join);
  - the `daemon_socket` or `daemon_running` fixtures;
  - `daemon-*.sock`;
  - `nc -U`.

  A test that starts its own daemon in a temporary directory writes to a log
  deleted with it. `test_daemon_smoke` and `test_plugin_daemon_integration`
  are like that, and are not judged.

- **What a payload is.** A dict literal, or a JSON text (a string or bytes
  constant, or a shell line), carrying `hook_event_name`, or both
  `tool_name` and `tool_input`. Docstrings and `_system` control messages
  are not payloads.

- **What marked means.**

  - `synthetic_source` resolves to a probe-class source. A literal counts,
    and so does a `synthetic_traffic` constant.
  - On an `AGENT_ID_EVENTS` event, or a tool payload with no event name,
    `probe_as` resolves to `main` or `sub`.
  - A `**spread` counts only when it names a module-level dict literal in
    the same file, so each file declares its marker once. Any other spread
    is unmarked. There is no annotation escape.

- **Its own samples** are built at runtime, so the guard judges its own file
  with no exemption. Two deliberately unmarked samples in the doc guard's
  detector tests now use `stop_hook_active` in place of `hook_event_name`.
  The doc detector keys on the pipe into a hook, so they still exercise it.

- **RED and GREEN.** The guard found 42 unmarked sites before the fix, and
  0 after.
