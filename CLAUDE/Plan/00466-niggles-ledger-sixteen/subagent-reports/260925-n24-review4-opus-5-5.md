## R4-B2: the mi5 fix turned TestCmdStop's signal guard into a no-op; the tests can now SIGTERM and SIGKILL a real pid 12345 (BLOCKER: the N59 crash class)

- **Where**: `tests/unit/daemon/test_cli_commands.py`, `TestCmdStop` (`:363`) and `TestCmdStopGenericException` (`:534`). Both carry `usefixtures("pid_proven_ours")`, which makes the proof accept ANY pid. They use `read_pid_file` → `12345`, and they guard the signal only with `patch("os.kill", …)`.
- **Why it is now unsafe**: since `b5729d58f`, `cmd_stop` signals through `os.pidfd_open` + `signal.pidfd_send_signal`, and neither call is patched in these tests.
  - The commit message says the fake pid "make[s] os.pidfd_open fail in the real test sandbox". That is true only while pid 12345 is free.
  - `pid_max` here is 4,194,304, and the pid counter is past 400k and wraps. Any gate run in which 12345 is live sends it a real SIGTERM. `test_stop_timeout` and the escalation test then send it a real **SIGKILL**, because the fixture re-proves it.
- **Repro** (`probe_n24r4_test_hazard.py`): `test_stop_timeout`'s exact patch set, with the pid replaced by the probe's own `sleep` child as a stand-in for a live 12345.
  - Result: "Sent SIGTERM", then "escalating to SIGKILL", and the child exited **-15**. It was killed by a real signal although `os.kill` was patched.
- **The binding rule this breaks**: "Never let a MagicMock pid reach a real signal call", together with the N59 root cause.
- **Direction**: use `_UNREAL_PID` (2\*\*22+7, already defined at `:559`) in every stop test, and patch `os.pidfd_open` in both fixtures. Add a conftest-level guard that makes `signal.pidfd_send_signal`, `os.kill` and `os.killpg` raise for any pid the test did not spawn.

## mi5: pidfd (`probe_n24r4_pidfd.py`)

The container's `ns_last_pid` is read-only, so the probe EMULATES recycling: after A is reaped, an `os.kill` by number of A's pid is redirected to B, which is the probe's own `sleep` child. The proof reaps A and "passes" mid-proof, the worst case.

- **pidfd path**: no signal by number reached the recycled pid, and B is **alive**. cmd_stop printed "Process … not found (stale PID file)" and returned 0. **Holds.**
- **Fallback path** (`pidfd_open` raising AttributeError, as on macOS): SIGTERM, then polls, then SIGKILL, all by number to the recycled pid. B was **killed**. This is the documented pre-existing race; it is confined to platforms without pidfd.
- **NIT**: `_open_pidfd` also returns None on Linux for `ESRCH`/`EMFILE`, and so falls back to by-number signalling. `ESRCH` should mean "not running". Only an unsupported platform should fall back.
- **NIT**: in the pidfd path's race (the pinned process dies during the proof), cmd_stop deletes the PID file and socket even though the proof just attributed a live process to this project.
