## Findings and how each is closed

### 1. D-RULE-4 MAJOR 1: a brace group against code

- **Code.** `shell_expansion.python_program_streams` now returns `code_words` next to `literals`. `code_words` holds every word `iter_brace_words` finds in the raw program text (the same discovery main uses), less the words that sit wholly inside one string literal or comment token. Those words are already enumerated through `literals`.
- **View.** `BraceExpansionView.code_words` carries these words.
- **Enumeration.** `secret_file_matching._code_word_spellings` enumerates each code word on its own, with the normal spelling and depth caps.
- **Past a cap.** It does not fail closed. It yields `shell_expansion.brace_skeleton(word)` instead, a linear stack scan that replaces every group, nested ones included, with `*`. `_token_mention`, the guard's existing protected-pattern matcher, then judges that skeleton as a glob. A literal still fails closed past a cap (round 3's ruling).
- **No limit on the number of code words.** A 500-word cap here would bring back the original N101 false positive. Volume is bounded by the program's length and by the scan deadline.
- **Tests** (`TestRoundFourFindingsAreClosed`, through `HandlerChain`):
  - `test_a_brace_group_against_code_denies_d_rule_4_major_1`, in heredoc and `-c` forms. RED at 36b8228b0.
  - `test_an_over_cap_code_word_that_could_name_a_path_denies`. The skeleton is `.vault-*-*-…`. RED at 36b8228b0.
  - `test_an_over_cap_code_word_naming_nothing_stays_allowed`. A nine-group dict display is past the cap and allowed. This is a pin.
- **View-level tests:** `TestCodeWordsAreReported` and `TestBraceSkeleton`.
- **False-positive corpus.** `untracked/scratch/n101f4/probe_fp.py` was re-run over the same 140 programs. The output is byte-identical to round 4's `fp-r4.txt`: 85 allowed, 54 `R-SECRET-BASH-MENTION` and 1 `R-SECRET-EVALUATION-ERROR`. Output is in `untracked/scratch/n101f5-fp.txt`.

### 2. D-SEC-4 unexamined 2: Python must read the text as the scanner does

`python_program_streams` returns `None`, so the program is not exempted, in the cases below. Its docstring states that the scanner models CPython 3.8 to 3.14 source grammar, apart from these shapes.

- **(a) `\r` anywhere in the program.** I chose to withdraw rather than normalise.
  - Test: `test_a_program_holding_a_carriage_return_is_not_exempted_d_sec_4_2a`, with `\r`, `\r\n` and a `\r` inside a literal. The first two are RED; the literal case already failed to tokenise at 36b8228b0, so it is a pin.
  - View-level test: `test_a_carriage_return_withdraws`.
- **(b) An f- or t-string field** holding the string's own quote, a backslash, `#`, a newline, or a nested f- or t-string (a prefix holding `f` or `t` before a quote).
  - How it is found: `_template_field_may_drift` scans each f- or t-string's source. On 3.11 that is one STRING token; on 3.12 and later it is the FSTRING_START..END span. The scan handles `{{`, `\N{…}`, `\\` and raw prefixes. Nested format-spec fields are tracked by depth.
  - Test: `test_an_f_string_field_versions_read_differently_is_not_exempted_d_sec_4_2b`, 7 shapes, all RED at 36b8228b0.
  - **Note:** the worktree venv is CPython 3.13, not 3.11, so the PEP 701-only shapes parse there and are RED too.
  - View-level tests: `TestPythonMustReadTheTextAsTheScannerDoes`, which checks both the withdrawn shapes and those that stay exempt.
  - Cross-check: I ran the helper over the same shapes on the system CPython 3.11.2 (`untracked/scratch/n101f5-cross311.py`) and on 3.13. Both agree.
- **Deviation from the brief, sent to team-lead for a ruling.** A field holding only the OTHER quote kind (`f's-{e["k"]}'`) keeps the exemption.
  - Why: the round-4 pin `test_a_realistic_dict_and_f_string_program_stays_allowed` has exactly that shape. A blanket "any quote" rule turns it red, so the brief's two rules conflict.
  - Why this is sound: PEP 701 reads such a field the same way in every version. Only the enclosing quote is read differently, and that quote cannot even parse before 3.12.
  - No reply had arrived when I committed. If team-lead rules for the blanket rule, the change is one line in `_field_end` plus flipping that pin to expect a deny.
- **(c) `tokenize` and `ast` disagree on any literal's span.**
  - How it is found: `_literal_spans_agree` checks that every string node `ast` reports starts where a string token starts and ends where one ends, and that every string token lies inside a string node. `ast` byte columns are converted to characters. Nodes inside an f- or t-string are not visited, because their positions are not the source's before 3.12.
  - Test: `test_tokenize_and_ast_disagreeing_on_a_literal_withdraws_d_sec_4_2c`, RED at 36b8228b0. No known CPython disagrees, so the test patches `ast.parse` to report strings one column late.
  - View-level test: `test_tokenize_and_ast_agree_on_ordinary_literals`.

### 3. D-RULE-4 observation: an allowlisted head as a shell function

- **Behaviour.** The exemption was already withdrawn at 36b8228b0: `()` sets `saw_bare_paren`, and `function` is a redefining word. No code change was needed.
- **Pin:** `test_an_inert_head_redefined_as_a_function_withdraws` covers `cd() { echo; }` and `function ls { echo; }`, each with `;` and newline forms, in heredoc and `-c` routes.
- **Recorded in NIGGLES N101** (these are the same limits main has):
  - a function inherited through the environment (`BASH_FUNC_x%%`) or through Claude Code's shell snapshot cannot be seen;
  - the model is bash, not zsh.

### 4. D-SEC-4 unexamined 1: can an allowlisted head's option run a program?

- **Answer:** no, and no code is needed. D-RULE-4 answered it entry by entry in "The allowlist, entry by entry" of `260926-n101-drule4-opus-5-5.md`, and the coordinator confirmed it by reading the list.
  - `cd`, `pushd`, `popd`, `pwd`, `mkdir`, `ls`, `cat`, `grep` and `sleep` have no option that runs anything.
  - `echo`, `true`, `false` and `:` only expand their arguments, and the expansions that can run code are withdrawn.
  - Every spelling of `set -x`/xtrace withdraws.
  - `export` rejects options and array subscripts.
