## 1. What the release gate requires

### 1.1 Authorisation

- A release starts only when a **human invokes `/release` in the current session**. An agent must never start one on its own initiative: `CLAUDE/development/RELEASING.md:7-8`, `:25-30`, the table at `:32-38`, and `.claude/skills/release/SKILL.md:9-15`, `:39-40`.
- **Consequence for this session.** The owner's instruction "go for /release" is a message. It is not a `/release` invocation. The gate text allows no agent-initiated start, and the owner's wording does not change that. When the slate is clean, the coordinator should stop with `[awaiting-human]` and ask the owner to type `/release`. It should not invoke the skill itself.
- Write the state file `untracked/release-state.json` only **after** the slate check returns `0` (`RELEASING.md:85-102`, `SKILL.md:28-31`).

- The procedure is at `RELEASING.md:240-274` and `.claude/skills/release/invoke.sh:22-41`. The logic is in `src/claude_code_hooks_daemon/core/release_slate.py`.

### 1.3 "Known defect", operationally

A non-defect (a refactor, a design question, a judgement call) may be filed as a plan instead (`:204-208`). Step 10 repeats the rule (`:557-560`).
