# N211 fixer report: merge-conflict markers disguised by the formatter

Branch `worktree-n466-n211`, from main `44d1b1b3b`. Fix commits `a98303563`
and `705898fba`.

## Route

`git log -m -S` puts every disguised line in a merge commit:

- The escaped opener above N118 (`\<<\<<\<<< HEAD`) and the closer
  `> > > > > > > worktree-n466-superlinear` after N106 both arrived in
  `fd4956813` (Merge worktree-n466-superlinear). N118 (from main) and N106
  (from the branch) sit between them; the separator was deleted.
- The closer `> > > > > > > main` after N100 arrived in `b2b5ee290` (Merge
  main into worktree-n466-guard-defects) and reached main through the N59
  merge `69efecdab`.

Mechanism, reproduced on a `git archive` of main: running
`MarkdownTableFormatterHandler.handle` on a conflicted `.md` turns the opener
into `# \<<\<<\<<< HEAD ours` (a heading, because the separator line becomes
a setext underline) and the closer into a seven-deep blockquote. The advisory
said only "aligned table pipes". A resolver searching for raw markers finds
none and commits.

The brief named two lines; the sweep found a third (the escaped opener).

## Fix

- `src/claude_code_hooks_daemon/utils/conflict_markers.py`: one classifier
  for raw and disguised markers (escaped opener, including when folded into a
  heading or table cell; the blockquoted `<` and `>` forms; an escaped
  separator). Seven `=` or seven `|` count only between an opener and a
  closer.
- `utils/markdown_format.format_markdown_document` raises
  `UnresolvedConflictError` on a conflicted document. The formatter handler,
  `format-markdown` and the CLAUDE.md injector (the three callers that rewrite
  a file) use it. `docs_qa/quotes.normalise_markdown` still uses the pure
  transform, because it rewrites no file.
- New PreToolUse `conflict_marker_commit_gate` (priority 42, rule
  `R-CONFLICT-MARKER-COMMIT`). It denies `git commit` and
  `merge|cherry-pick|revert|rebase --continue` when an ADDED line carries a
  marker, and names each `file:line`. It reads what the commit records:
  index, `-a` working tree (including on an unborn branch), pathspecs relative
  to the command's directory, `-i`, and the directory named by an earlier
  `cd`/`pushd` or by `git -C`. It uses `--no-renames` so a
  renamed file's lines count as added. It checks a protected file but withholds
  that file's line text. If git cannot answer, it allows with a visible
  "NOT checked" advisory. `--dry-run` is not a commit. I used 42 because the
  project handler `enforce-llm-qa` already holds 41.
- The three lines are removed from NIGGLES.md. The N211 entry and its PLAN.md
  row are added, plus a config-changes entry and release note 121.

### Done in 343abb493

- **B1 / N226 (shared).** `utils/git_commit_parsing.extract_commit_pathspecs`
  now takes the COMMAND.

  - It reads the command with `command_words`, a `shlex` lexer that knows
    shell punctuation. Before lexing, unquoted heredoc bodies are removed,
    fd numbers (`2>&1`, `{fd}>`) are joined to their operator, and newlines
    become `;`.
  - Redirections and their targets are dropped, and the walk stops at the
    next operator.
  - Option values follow git-commit's own option table
    (`_COMMIT_LONG_OPTIONS`, from `--git-completion-helper-all`), including
    unambiguous abbreviations. The optional-value letters `-u`/`-S` no
    longer eat the next word.
  - `docs_qa`, `plan_qa` and `guard_config` pass the command. There are
    tests for `docs_qa` (the capture idiom) and `plan_qa` (the capture idiom
    reads the index).
  - In the gate, named pathspecs that match nothing fall back to judging
    the index.

- **M1.** Commits are found with a new shared walker,
  `git_commit_parsing.git_invocations`.

  - `git` counts as any word, found through `command_word` and
    `git_subcommand_index`, which is the sibling gates' detector.
  - An `eval` or `sh -c` string is walked recursively.
  - A `cd` inside a subshell is scoped to that subshell.
  - `is_git_commit` over `tokenise_command`, main's floor, still matches
    anything else (for example `bash <<EOF`), and those commands are judged

  - The exemption at `test_blocking_handler_evasion.py:527` is removed. The

  - Placement is the gate's existing cd/`-C` reading, now made fail-closed.
