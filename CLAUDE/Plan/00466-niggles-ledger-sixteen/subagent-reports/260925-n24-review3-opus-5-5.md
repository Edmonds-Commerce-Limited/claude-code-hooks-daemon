## Blocker

### B1: `utils/realpath.realpath` diverges from `os.path.realpath`, and `project_containment` can be bypassed through it (regression against `main`)

- **Where**: `src/claude_code_hooks_daemon/utils/realpath.py:38-73`. Its callers include `project_containment._is_within` (`project_containment.py:475`), `secret_file_matching.protecting_pattern` (`:285`), `sensitive_content` (`:1136`, `:1189`), `workspace._resolve_or_self`, `worktree_paths` and `docs_qa_edit`.

- **Differential test** (`probe_n24r3_realpath.py`, 2 seeds x 10,000 generated paths). The tree includes dirs, files, relative and absolute links, dangling links, loops, chains, `..` targets, `.`, `//`, trailing `/`, relative paths and long spellings. **79 mismatches** (42 + 37), in two classes:

  1. **Spelled path at or over PATH_MAX** (57 of the 79). A run of `/.` or `//` pushes the spelled prefix past 4096 bytes. `lstat` then fails with `ENAMETOOLONG`, and the binary search stops before the symlink. The rest is appended **unresolved**. `os.path.realpath` skips `.` and empty components as it walks, so its accumulated path stays short and it resolves the link.
     - Example: `<base>/` + `./`x2100 + `l_d1/f2` gives `<base>/l_d1/f2`; `os.path.realpath` gives `<base>/d1/f2`.
  2. **A symlink whose target contains `missing/..`** (22 of the 79). The kernel cannot traverse `nope/..`, so `lstat(prefix)` fails. Python resolves `..` lexically, and so does `os.path.realpath`.
     - Example: `l_missing_dotdot/l_up_e1`, where `l_missing_dotdot -> nope/../d1` and `d1/l_up_e1 -> ../e1`. `os.path.realpath` gives `<base>/e1`; the new function gives `<base>/d1/l_up_e1`. It matches neither the kernel nor Python.

  - The module docstring's premise does not hold: "whether a prefix can be `lstat`-ed is monotonic… The answer is exactly `os.path.realpath`'s". The fixer's exhaustive 4-component comparison could not reach either class.

- **End-to-end** (`probe_n24r3_containment_e2e.py`, real scratch daemon, legacy socket). Setup: `l_out -> /tmp` inside the project; Write `file_path = <root>{filler}/l_out/probe_n24r3_escape.txt`.

  | spelling    | branch verdict                      | `main` verdict (same probe, `PYTHONPATH` = `git archive main`) |
  | ----------- | ----------------------------------- | -------------------------------------------------------------- |
  | short       | DENY `R-WRITE-OUTSIDE-PROJECT-ROOT` | DENY                                                           |
  | `/.` x 2100 | **ALLOW `{}`**                      | DENY                                                           |
  | `/` x 4200  | **ALLOW `{}`**                      | DENY                                                           |

  - **Exploitability**: this needs the writer to normalise the spelled path before it opens it. Node's `path.resolve`, which I understand Claude Code's file tools apply, collapses the run to `<root>/l_out/…`, and that write lands in `/tmp`. I did not verify Claude Code's normalisation in this review.
  - **Wider reach**: `secret_file_guard` and `sensitive_content` use the same function for the "symlink to a protected file" check (`secret_file_matching.py:263-268`). I did not drive those end-to-end: building a synthetic protected-name file needs the guard's own globs in a script, which `R-SECRET-SCRIPT-AUTHOR` rightly refuses.

- **Direction**:

  - Drop `""` and `"."` components before the search; that is semantics-preserving. Then check the boundary against the *resolved* path: if `lstat(resolved_prefix + "/" + tail[0])` succeeds, the kernel and Python disagree, so fall back to `os.path.realpath`. Fall back as well on any `lstat` errno other than `ENOENT`/`ENOTDIR`.
  - Put the generator from `probe_n24r3_realpath.py`, long spellings and `missing/..` link targets included, into `tests/unit/utils/test_realpath.py`.
  - Prove RED on a `git archive` copy of HEAD.

## Majors

### MA1: GIL starvation still fails OPEN once the daemon's accept backlog is full, on both rungs

- **Repro**: `probe_n24r3_gil.py`, with the probe handler making one `re` call that holds the GIL.
  - While the daemon is wedged:
    - The python rung denies `socket_timeout`, and so does the wedging call itself.
    - The relay denies `transport-fail-closed`.
    - `stop` escalates to SIGKILL and recovers the daemon in 7.4 s.
  - Then 100 pending connections fill each socket's backlog (asyncio's default `backlog=100`; the kernel refuses the 101st with `EAGAIN`), and the next destructive call **ALLOWs**:
    - **Python rung**: `connect()` raises `BlockingIOError`. That falls to `init.sh:1988` `except Exception` → `fail('BlockingIOError', …)` → the fail-open `else` branch: "HOOKS DAEMON: Not currently running… Hook safety handlers are inactive".
    - **Relay**: `connect timed out`. With `--no-fallback` that exits 10. In production the forwarder passes `--fallback`, so the relay execs the bash forwarder, which lands on the same python rung and ALLOWs.
- **Why it is reachable**:
  - A pending connection stays queued until it is accepted, even after its client gives up. A wedged daemon therefore collects every hook call from every session: PreToolUse, PostToolUse, and the status line, which polls.
  - Review 2 measured wedges of 37–73 s. The class this branch closes is "a wedged daemon must never ALLOW", and the 101st caller is still allowed.
- **Direction**:
  - In `init.sh`, treat `BlockingIOError`/`EAGAIN`, and any `OSError` after the socket is created other than `FileNotFoundError`/`ConnectionRefusedError`, as "reached". Better still, invert the default for PreToolUse: deny on every error type except the explicitly never-reached ones.
  - Add a test with a fake server that calls `listen(0)`, never accepts, and has its backlog pre-filled.

### MA2: the relay still ALLOWs daemon responses that are not a PreToolUse verdict; the python rung denies the same responses

- **Repro**: `probe_n24r3_validation.py` and `probe_n24r3_failopen.py malformed`, sent to the per-event `pre-tool-use.sock` through the HEAD-built relay.
  - **ALLOW on the relay**: each of these shapes is a valid JSON document that is not a PreToolUse response, and the relay passes it through untouched:
    - `tool_name: 5` and `tool_input: [...]` get `{"result": {"decision": "deny", "reason": "HOOKS DAEMON ERROR - denied for safety …invalid_request…"}}`. The daemon *intends* to deny, but the controller's `invalid_request` path (`controller.py:1157` → `to_response_dict`) returns a `{"result": …}` envelope. Claude Code ignores that, so it is an ALLOW.
    - Hook input `[]` or `null` gets `{"error": "Missing required field: hook_input"}` (`server.py:1654`).
    - The strict-mode `{"error": "input_validation_failed"}` path (`server.py:757`) has the same shape. This repository's config enables it.
  - **DENY on the python rung**: every one of these shapes is denied as `malformed_response`, because `_pretooluse_response_looks_valid` rejects it.
  - **Context**: Claude Code always sends a dict, so the list/null cases are synthetic. But `invalid_request` and `input_validation_failed` are reachable by any payload-schema drift, and the relay trusts any non-empty bytes (`hooks_relay.rs:367` only special-cases *empty*).
- **Direction**:
  - In `_handle_event_client`, for the PreToolUse wire key, apply the `_pretooluse_response_looks_valid` contract server-side, and replace any other shape with `_pre_tool_use_transport_deny_response()`.
  - Or make every PreToolUse error path return the `to_json` hook shape.
  - Add relay-rung tests for both.

### MA3: `init.sh`'s python transport executes backticks from a comment on every hook call

- **Where**: `init.sh:1979` and `init.sh:1982`, inside the double-quoted `python3 -c "…"` body (`init.sh:1541-1990`). They are the comments "the generic `` `except Exception` ``" and "(server.py's `` `_drain_oversized_request` ``)", both added in `1fdcd5019` (mA1).
- **Effect**:
  - Bash performs command substitution inside double quotes. Every python-rung invocation, for **every** event (I saw it on PreToolUse and PostToolUse), runs `except Exception` and `_drain_oversized_request` as commands.
  - Each call prints `.claude/init.sh: line 1541: except: command not found` and the `_drain_oversized_request` equivalent. The captures are in every `[python]` line of `probe_n24r3_f_basic.out` and `probe_n24r3_f_nonpre.out`.
  - Today it is noise and two extra shell lookups on the hot path. In a client environment with an `except` executable on `PATH`, it runs that executable.
  - Nothing caught it: no test asserts that the transport's stderr is empty. The `main` version of that block contains no backticks.
- **Direction**: remove the backticks. Add a test that `send_request_stdin`'s stderr is empty on a successful exchange, or a static check that no backtick appears between `python3 -c "` and its closing quote.

### MA4: an unreachable daemon still ALLOWs PreToolUse (socket missing, relay down, daemon fails to start)

- **Repro** (`probe_n24r3_f_missing.out`, `probe_n24r3_badcfg.out`):
  - Socket missing: python rung ALLOW `socket_not_found`.
  - The relay's `--fallback` goes to the same rung.
  - A daemon that refuses to start, for example on any pydantic field error such as `deadline_seconds: -5`, makes `ensure_daemon` fail. `emit_hook_error "PreToolUse" daemon_startup_failed` then emits a fail-open `hookSpecificOutput` (`init.sh:283-318`, `:349-371`) unless CI enforcement is on.
- **Status**:
  - This is deliberate and documented (`init.sh:1791-1798`), and pre-existing: `main` also refuses to start on a pydantic field error (same probe, `main` source).
  - The brief lists "relay down" and "socket missing" as routes that must DENY, and the standing rule says an exception or a timeout never means allow. So this needs an explicit owner decision rather than a silent carry-over.
  - Plan 00421's degraded mode (below) removes the "refuses to start" half for schema errors. It does not cover the socket-missing half.
- **Direction**: for an *installed* project (config present, venv present), deny PreToolUse when the daemon cannot be reached after `ensure_daemon`, keeping the exact recovery-command carve-out. Keep fail-open only for "not installed at all".
