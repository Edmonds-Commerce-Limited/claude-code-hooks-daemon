## BLOCKER 1 (N117): closed

**Ruling applied.** ENAMETOOLONG proves absence only when the literal
component bash would open is longer than `os.pathconf(dir, "PC_NAME_MAX")`,
with 255 as the fallback. A whole-path (PATH_MAX) overflow fails closed. One
error no longer stops the rest of the walk.

**How:**

- **`shell_expansion.py`.** `bounded_recursive_glob` now drives a
  per-component walker, `_GlobWalk`, for every pattern. Before, only `**` and
  root-anchored patterns went through it, and everything else used
  `Path.glob`.
  - Literal components are looked up by name with `stat`/`lstat`, the same
    lookup bash makes.
  - Wildcard components are matched against `os.scandir` entries, so their
    own length proves nothing, and nothing is ever opened by that name.
  - `**` means zero or more directories. The pruned names and the
    entries-visited cap still apply, and each listing is counted once.
  - `_record` handles lookup errors:
    - ENOENT, ENOTDIR and ELOOP are absence. These are the errnos pathlib's
      glob already ignored.
    - ENAMETOOLONG is absence only when the component is longer than
      NAME_MAX.
    - Any other error either raises (when `errors=None`, the existing
      contract) or is appended to the caller's per-call `errors` list, and
      the walk carries on.
- **`secret_file_matching._expand_glob_token`:**
  - Walks every base through that function with an `errors` list.
  - Returns a protected match as soon as one is found.
  - Otherwise raises the first collected error once every branch and base
    has been walked.
  - A result past `max_expansions` now raises `TooManyToEnumerateError`.
    Before, it returned `None`, so the 201st path was never judged and the
    command was allowed.
  - `_PROOF_OF_ABSENCE_ERRNOS` is gone.
- **Quarantine guard.** Its strict route, `find_protected_mention_strict`,
  calls the same `_expand_glob_token`, so the same rule covers it.
- **Side effect worth knowing.** On py3.11, `Path.glob`'s wildcard listing
  swallowed `PermissionError`, so main allowed a glob through an unreadable
  directory. The walker fails closed there.

### Defects found by the measurement, all fixed

1. **Regression against main.** At 79d3104e4,
   `cat <<$'EOF'\nbody\nEOF\necho hi > /opt/x` and the `<<$"EOF"` and
   `<<$(echo)` versions were ALLOWED, and main denied all three.
   - Bash decodes `$'…'` and removes `$"…"` in a delimiter word, and keeps a
     `$( )` span verbatim. The scanner's word ended at `(` or kept the `$`,
     so its body never closed and every later line was treated as data.
   - `_read_word` now reads `$'…'` (decoded, quoted), `$"…"` (quoted) and
     `$( )`, `$(( ))` and backtick spans (verbatim, not quoted).
   - `<<a$(echo x)b` was allowed on main too.
2. **An ANSI-C string invents a heredoc (main has it too).**
   `cat $'\' <<'EOF' '\'\ngit reset --hard\nEOF` was allowed by
   `destructive_git`, `pipe_blocker` and `project_containment` (with a
   write body). Bash runs line 2.
   - The scanner read `$'\'` as a plain quote. It now skips a `$'…'` string
     to its first unescaped quote.
   - `$$` is the pid, so in `echo $$'\' <<\EOF '\'` the heredoc is real.
     Checked in bash.
3. **`split_unquoted` misreads ANSI-C and comments (main has it too).**
   `pipe_blocker` allowed `echo $'it\'s' && pytest tests | tail -3` and
   `echo hi # it's\npytest tests | tail -3`.
   - It now skips `$'…'` strings and `$$`.
   - Quotes in a comment are plain characters. The comment's separators
     still split, which is the conservative reading.
4. **`bash_text_for_shlex` read `$$'` as ANSI-C.** It now copies `$$`
   whole.
5. **An unclosed heredoc body was treated as data.** A delimiter read
   differently from bash looks exactly like one. The body's text is now
   `unreadable`, so a deny caller fails closed. This is the backstop for
   any delimiter spelling not yet modelled. The containment message now
   says "unbalanced quote or heredoc".

**One decoder.** The ANSI-C decoder moved from `core/utils.py` into the new
`utils/ansi_c.py`, and `core/utils`, `heredoc_operators` and
`shell_segmentation` all use it. The comment rule is
`heredoc_operators.COMMENT_PRECEDERS`. The old copy in `heredoc_operators`
was missing `<`/`>`, and bash's `echo hi >#c` is a syntax error that proves
they belong.

`shell_expansion.py` keeps its own older `$'…'` decoder for brace spelling.
That code is on main and is not changed here.
