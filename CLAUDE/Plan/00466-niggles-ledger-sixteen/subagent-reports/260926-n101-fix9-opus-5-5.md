## BLOCKER 1 (N117): closed

**Ruling applied.** ENAMETOOLONG proves absence only when the literal
component bash would open is longer than `os.pathconf(dir, "PC_NAME_MAX")`,
with 255 as the fallback. A whole-path (PATH_MAX) overflow fails closed. One
error no longer stops the rest of the walk.

**How:**

- **`shell_expansion.py`.** `bounded_recursive_glob` now drives a
  per-component walker, `_GlobWalk`, for every pattern. Before, only `**` and
  root-anchored patterns went through it, and everything else used
  `Path.glob`.
  - Literal components are looked up by name with `stat`/`lstat`, the same
    lookup bash makes.
  - Wildcard components are matched against `os.scandir` entries, so their
    own length proves nothing, and nothing is ever opened by that name.
  - `**` means zero or more directories. The pruned names and the
    entries-visited cap still apply, and each listing is counted once.
  - `_record` handles lookup errors:
    - ENOENT, ENOTDIR and ELOOP are absence. These are the errnos pathlib's
      glob already ignored.
    - ENAMETOOLONG is absence only when the component is longer than
      NAME_MAX.
    - Any other error either raises (when `errors=None`, the existing
      contract) or is appended to the caller's per-call `errors` list, and
      the walk carries on.
- **`secret_file_matching._expand_glob_token`:**
  - Walks every base through that function with an `errors` list.
  - Returns a protected match as soon as one is found.
  - Otherwise raises the first collected error once every branch and base
    has been walked.
  - A result past `max_expansions` now raises `TooManyToEnumerateError`.
    Before, it returned `None`, so the 201st path was never judged and the
    command was allowed.
  - `_PROOF_OF_ABSENCE_ERRNOS` is gone.
- **Quarantine guard.** Its strict route, `find_protected_mention_strict`,
  calls the same `_expand_glob_token`, so the same rule covers it.
- **Side effect worth knowing.** On py3.11, `Path.glob`'s wildcard listing
  swallowed `PermissionError`, so main allowed a glob through an unreadable
  directory. The walker fails closed there.

### Bash 5.2.15 facts (probe scripts in `untracked/scratch/n101r10/probe*.sh`)

- **No heredoc; the next line runs:**
  - `${x:-<<EOF}`, including inside `$( )`;
  - `(( … ))`, `for ((`, `$[ … ]`;
  - `a=(x <<EOF)` (a syntax error, but bash goes on to the next line);
  - an extglob `@(x|<<EOF)`;
  - `` `# <<X` ``: the comment ends at the newline or at the closing backtick.
- **Syntax errors that make bash stop (nothing is hidden):** `[[ a <<EOF ]]`,
  `case x in a<<EOF)`, `x(<<EOF)`.
- **`${` closes at its first unquoted `}`.** A bare `{` does not nest:
  `${x:-{a}<<EOF}` really opens a heredoc whose delimiter is `EOF}`.
- **Quotes are live inside `${ }`, even within double quotes** (`"${x:-'}"`
  reads on for the closing quote). Quotes are also live inside `$(( ))`.
- **`((cat <<EOF⏎…⏎) )` is re-parsed as subshells, and badly.** Bash ran the
  body lines as commands.
- **Line continuations:**
  - A single-quoted string, `$'…'`, a comment and a QUOTED heredoc body keep
    `\⏎`.
  - An unquoted body joins it BEFORE the closer is matched: `foo\⏎EOF` is no
    closer, `\⏎EOF` is one, and `foo\\⏎EOF` is not a continuation.
  - `<<EO\⏎F`, `<<\⏎EOF` and `<<\⏎-EOF` all join. The result is unquoted, and
    in the last case it is strip-tabs with delimiter `EOF`.
  - `echo a\⏎# <<X` is the word `a#`, so `<<X` IS a heredoc there.
- **A delimiter containing `${…}` is that literal text, blanks included.**
  Quotes inside it do not make it quoted (`<<${x:-'a'}` expands the body).

### Design (for the next agent)

**Key point:** failing to see a heredoc that bash DOES see is also unsafe.
Its body is then read as commands, and a fake `<<Y` in that body hides a
later line bash runs. So "treat as commands" is not enough on its own. Under
uncertainty the scanner must STOP:

- report no further heredocs;
- drop pending operators;
- keep only heredocs with `closer_end <= at`;
- make every newline at or after `at` a break;
- set a new `HeredocScan.stopped_at`.

`scan_bash_write_destinations` then reports `command[stopped_at:]` as
`unreadable`, so the write callers fail closed. The existing
unterminated-quote `return False` paths should call `_stop` too.

In `utils/heredoc_operators.py`:

1. **New frames.** Give `_Frame` a `start` field, and add these frames:

   - `PARAMETER` (`${`): closes at the first `}`; quotes, `$(`, `${` and
     `$((` live; no comments; no `<<` operator.
   - `BRACKET` (`$[`): counts `[` and `]`.
   - `ARITHMETIC` for a bare `((` at word start, as well as `$((`. Quotes are
     live in it.
   - `ARRAY` (`name=(`): comments allowed.
   - `PATTERN` (any other `word(`): no comments.

   `_redirection` runs only in the UNQUOTED, SUBSTITUTION and BACKTICK
   frames.

2. **Arithmetic mis-parse.** A `)` that takes an arithmetic frame's depth
   from 2 to 1 and is not followed by `)` means bash re-parses the text as
   subshells. Call `_stop(frame.start)`.

3. **Backtick comments.** A `#` right after a frame's opening backtick is a
   comment. Inside a backtick frame, the comment ends at the newline or at
   the closing backtick.

4. **Continuations.**

   - `_read_word` treats `\⏎` as removed, not as quoting.
   - `_double_quoted_span` drops `\⏎`.
   - `_redirection` skips `\⏎` inside the `<` run, before `-` and among the
     blanks.
   - `_read_body` for an UNQUOTED operator joins lines that end in an odd run
     of backslashes before comparing a line with the delimiter.
   - A `\⏎` glued to a two-character token calls `_stop` at the backslash: a
     previous char in `$(`, or a non-blank previous char with `(` or `#` next.
   - A `${` or `$[` in a delimiter word, or a newline inside a PARAMETER,
     BRACKET, ARITHMETIC, ARRAY or PATTERN frame while an operator is
     pending, also calls `_stop`.

5. **MAJOR B (normaliser).** `normalise_line_continuations`, reached through
