## Findings, ranked

### BLOCKER-1 — `agent_terminated_early_failure_detector` requires an `Error:` prefix the hook's `error` field never carries

`src/claude_code_hooks_daemon/handlers/post_tool_use_failure/agent_terminated_early_failure_detector.py:70-74`:
`\A\s*Error:\s*Agent terminated early ...`.

The fixer modelled `error` on the transcript's `toolUseResult` string. The hook
gets something else. In the installed Claude Code 2.1.282 binary, the failure
path does this:

```
let ur=B3n(Mo,…) … for await(let Rr of dPn(s,e,n,b,je,ur,…))   // hook: error: ur
… content:[{type:"tool_result",content:ur,is_error:!0,…}],toolUseResult:`Error: ${ur}`
```

The PostToolUseFailure hook input is built as `{…, error: <that same ur>, …}`.
So `error` is the tool_result **content**, and `"Error: "` is added only to the
transcript's `toolUseResult` decoration. The corpus agrees. Across 2906 is_error
results, `toolUseResult == "Error: " + content` every time, and no content
starts with `Error:`. The vendored contract example also agrees:
`"error": "Exit code 1\nError: …"` has no leading `Error: `.

What I executed:

- Replay (`probe_n46r3b_replay.py`): the one real is_error death fires with the
  `toolUseResult` string, and does **not** fire once the prefix is stripped to
  the content form (`death_is_error_fires_without_Error_prefix=False: 1`).
- Adversarial probe (`probe_n46r3b_adversarial.py`):
  `PTF Agent error, bare content shape (REAL hook shape)` gives expected=True,
  actual=False. The same holds for a Task session-limit death.
- Live, through the probe worktree daemon via `.claude/hooks/post-tool-use-failure`:
  - the `Error:`-prefixed payload returns the advisory;
  - the bare-content payload, the real shape, returns `{}`.
- Fix check (`probe_n46r3b_fixcheck.py`): over all 3216 real is_error tool_result
  contents,
  - the shipped regex fires 0 of 1 deaths;
  - `(?:Error:\s*)?` fires 1 of 1, with 0 of 3215 false positives.

The tests pin the wrong shape:
`tests/unit/handlers/post_tool_use_failure/test_agent_terminated_early_failure_detector.py:52-62,124`.
The ledger's claim of "4 of 4" (NIGGLES.md N46, review-2 paragraph) holds only
under that wrong model. Against the real hook it is 3 of 4.

**Fix:**

- Make the prefix optional.
- Pin a test on the bare-content shape, the real one, and keep the prefixed
  shape as a second case.
- Correct the three prose claims that the `error` field is `Error: Agent terminated early…`: the module docstring (lines 16-22), `HANDLER_REFERENCE.md`
  (agent_terminated_early_failure_detector entry), and the NIGGLES.md N46 text.
