## D-RULE-6 MAJOR 1: a brace word inside a Python literal was dropped

**Finding.** In `s = '''a' /proj/.vault-{\x7b,pass} 'b'''`, Python's value is `/proj/.vault-{{,pass}`, which spells nothing. Bash reads the triple quote as `''` `'a'`, so the middle word is unquoted and spells `/proj/.vault-pass`. The containment filter dropped the raw word.

**Closed.**

- `python_program_streams(...).shell_words` is now `iter_every_shell_brace_word(source)`. This is every word bash splits from the raw text that holds a brace, whatever its quoting, inside a literal or not.
- `_code_shell_words`, the span anchors and the containment filter on shell words are gone. The quote-blind `code_words` keep containment.
- The literal's decoded value is still enumerated.

**Corpus.** No verdict moved, so I did not keep the fallback the brief allowed (containment for literals whose raw text equals their decoded value).

- 140 programs: byte-identical to round 6 (`n101f6/fp-r6.txt`). That is 85 allowed, 54 `R-SECRET-BASH-MENTION` and 1 `R-SECRET-EVALUATION-ERROR`.
- 142-program main-snapshot variant: identical too.

**Differential test** (`tests/unit/utils/test_shell_expansion_bash_differential.py`). Each generated word is printed by bash with `printf '%s\n' WORD`. This runs under `set -f`, in an empty `tmp_path`, with no substitutions or parameters. Every non-empty spelling bash prints must be one the guard reads.

  - Bash expands 822 of them to more than one spelling.
  - The guard gives up on none.
- 1,000 words with Python escapes sit inside `s = '''a' WORD 'b'''`, read through `python_program_streams(...).shell_words`. Bash expands 385 of them.
- Both fail at 0779559fa (5 failures). On main the file cannot import (`iter_shell_brace_words`), so it is RED there too.

**What the differential found beyond the brief.** The round-6 quote-aware expander paired braces innermost-first. Bash does not:

- a `}` that comes before any comma is text;
- a group with no comma that is not a sequence is text;
- a `${` opens a level.

On a 600-word and 300-program sample it missed 15 and 20 words after N111 was fixed. For example, bash reads `{pass},}` as `pass}` and the empty word.

- **Fix.** `_BashBraces` is a port of bash 5.2 `braces.c` (`brace_expand`, `expand_amble`, `brace_gobbler`), read from the GNU tarball. It replaces `_brace_syntax_mask` and the innermost-first expander. `shell_word_spellings` cuts pieces at bash's own top-level groups.

- **Consequence.** A `${…}` inside a group is now resolved as bash's scanner reads it (`.p-{"${x:-"}"}",q}` spells `.p-q`) instead of failing closed.

  - `test_quoting_that_cannot_be_resolved_fails_closed` keeps only the `$(case …)` shape.
  - The `${…}` shape moved to `test_a_parameter_expansion_in_a_group_is_read_as_bash_reads_it`. It still denies, now with `R-SECRET-BASH-MENTION`.

- **Cost bound.** Bash retries every `{` against the rest of the word, which is quadratic. The first port took 14 s on a 16 KB `{a{a…` word. Two changes bound it:

  - The scan visits only the unquoted brace-syntax characters, found once per word.
  - A `{` is not retried once no `}` or separator follows it.

  A 250,000-visit budget (`_BRACE_SCAN_BUDGET`) fails closed past that. `"{a" * 8000 + ",}"` now raises in 0.05 s, and `"{a" * 8000` returns at once. Tests: `test_a_scan_past_its_budget_raises` and `test_no_brace_is_retried_once_no_closing_brace_is_left`. Main allows that first word; it is a pathological false positive, not a loosening.

- **Primitive tests:** `test_a_group_is_what_bash_s_brace_scanner_accepts` (6 shapes, each checked against bash) and `test_a_parameter_expansion_is_read_as_bash_s_brace_scanner_reads_it`.

## N111: `$"…"` kept its `$`

**Closed.** An unquoted `$"` drops its `$` in `_decode_span`, so `normalise_word` and every stream built on it read `$"…"` as `"…"`. `"$"` inside double quotes keeps its `$`, as in bash.

## N112: braces decoded from `$'\x7b'` were never expanded

**Closed.** ANSI-C decoding is the one quote removal that makes braces the raw text lacks.

- A word holding `$'` has its decoded value read as a command whatever it holds (`_nested_command_words(..., decoded=True)`). Every word of it that holds a brace is reported (`every_word`).
- `eval`'s joined arguments are read the same way when one of them holds `$'`.
- Other words keep the quoted-brace gate.

**Tests:** `test_braces_decoded_from_ansi_c_quoting_reach_a_shell_n112` runs through `HandlerChain` with `bash -c`, `eval`, `sh -c`, `su -c` and `ssh`, using `\x7b`, `\173` and `{`. All 5 are RED on main and at 0779559fa. Also `test_braces_decoded_from_ansi_c_quoting_are_read_n112`.

## N113: an unrelated prefix switched off N107 coverage

**Closed.** `_may_hold_a_group` returns true when a brace group could still arrive. That means any of these:

- a `{` other than `${` with a `}` after it;
- a `$'…'` whose decoded body holds a brace;
- an expansion whose value is unknown (`$x`, `${`, `$(`, a backtick), where a word hands text to a shell to read again (`eval`, `source`, `.`, `su`, `ssh`, a shell by name, an option cluster holding `c`).

Only when none of these holds does the scan stop. Otherwise it raises and the guard fails closed.

**Tests:**

- `test_an_unrelated_unresolvable_prefix_does_not_end_the_scan_n113`: the two `$'…'` shapes are RED on main and at 0779559fa. The `eval "…$(printf '\x7b')…"` shape already denied on both, so it is a pin.
- `test_a_group_that_may_arrive_after_unresolvable_quoting_raises_n113`, 4 shapes.
- `test_nothing_that_may_arrive_after_unresolvable_quoting_ends_the_scan`: `: ${x:-'a'} ; echo "$HOME" done` and `echo "${x:-"a"}" $'tab\there'` stay allowed.
