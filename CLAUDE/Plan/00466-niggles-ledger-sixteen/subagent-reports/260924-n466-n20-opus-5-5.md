# Plan 00466 N20 delivery report: the capture-corruption auditor reads logical commands

**Branch/worktree**: `worktree-n466-n20` (from main at `954922b7`)

## The defect

`scripts/qa/audit_capture_corruption.py` judged shell a physical line at a
time. B1 taught it to join backslash continuations, but a quoted string that
spans lines (`echo 'x` followed by `y' >&2`) was still split. The redirect
after the closing quote went unseen, and the echo was flagged: a latent false
positive of the kind that broke B1's gate.

## What checking the rest of the file found

The same assumption sat in three more places, all in heredoc detection. Each
used one regex per physical line:

- **Operators inside quotes and comments.** `_HEREDOC_OPEN_RE` matched `<<WORD`
  anywhere, including inside quotes and comments. `scripts/upgrade.sh:949`
  (`printf '\n<<<UPGRADE_METADATA\n'`) opened a false heredoc whose terminator
  never appears. The auditor blanked the file's last 12 non-empty lines, so
  that code was never audited. This is a false negative, and it is live today.
- **Quoted and backslashed delimiters.** `<<"EOF"` and `<<\EOF` did not match,
  so their bodies were audited as code, including any apostrophe in the prose.
- **Here-strings and arithmetic.** A here-string `<<<WORD` and an arithmetic
  shift `$(( 1 << n ))` could each be read as a heredoc.

`_collect_captured_function_names` was also per line, so a capture written as
`VAR=$(` with the function on the next line was never recorded. And a `}` at
column 0 inside a multi-line string ended the enclosing function early.

## The remedy

One tokeniser, `_ShellTokeniser` driven by `_logical_lines`, replaces
`_strip_heredoc_bodies`, `_line_continues` and `_join_continuations`:

- **Across lines**, it tracks a stack of spans: single, double and `$'`
  quotes, `$(...)`, backticks, and `$((...))` or `((...))`. Bash quoting rules
  apply inside each span. A backslash is literal in single quotes. An
  apostrophe inside `"$(... )"` opens a real quote.
- **A command stays open** while a span is open or the line ends in a
  backslash. It is joined onto its first physical line, and the lines it
  swallows are blanked, so every finding keeps its physical line number. Only
  the last physical line of a command keeps its comment, so a trailing
  `# capture-audit: allow -- ...` marker still applies.
- **A heredoc operator counts only in code**, never in quotes, comments,
  here-strings or arithmetic. The delimiter may be quoted or backslashed. The
  body starts after the first newline that is real shell syntax, and body and
  terminator lines are blanked.
- **A `case` inside a substitution is tracked** (`_case_step`), so a
  pattern's `)` never reaches the paren count that closes the `$(...)`. Each
  substitution span keeps its own stack of open `case`s, in three phases:
  subject, then pattern after `in`, then body after the pattern's `)`.
  `;;`, `;&` and `;;&` go back to pattern, and `esac` closes the `case`.
  - A pattern may open with the optional `(`. Extglob parens inside a pattern
    must balance before the pattern closes.
  - The last clause may omit `;;`: `esac` in command position still closes it.
  - `case` and `esac` count as reserved words only in command position, so
    `$(echo case in a)` opens nothing.
  - Nesting works because a `$(case ...)` inside a clause is its own span with
    its own stack.
- **It fails closed.** Quote state now decides which lines get judged, so a
  span or heredoc left open at end of file is reported as `unparseable-shell`
  at the line where it opened. It is not audited as one run-on line.
