### Bash 3.2 / macOS compatibility

`printf '%(...)T'` needs bash >= 4.2; macOS's system `/bin/bash` is 3.2.57,
which several existing comments in this codebase (BSD `pgrep`/`stat`
portability, `${arr[@]+"${arr[@]}"}` for bash < 4.4) already treat as a real
target. `_hp_bash_supports_printf_time` gates the builtin on
`BASH_VERSINFO`; below 4.2 it falls back to `date` (fine on macOS, since a
hostile/stripped PATH there is the bootstrap scenario, not "date does not
exist on the system"), and only fails loudly when neither is available.

## N31 — dispatch-declaration misses "File to write to: <path>"

**Fixed**, in
`src/claude_code_hooks_daemon/handlers/pre_tool_use/dispatch_declaration.py`.

Root cause: `_DESTINATION_PATTERN` required a keyword immediately followed
by whitespace + `to`/`in`/`under`/`into` + whitespace + a path; "File to
write to: <path>" has "to:" (colon, no whitespace) which broke the match,
and "file" as a noun was not in the keyword list at all.

Fix: `_prompt_declares_destination` pairs any destination keyword
("write"/"save"/"report"/"output"/"store"/"file") with a path-shaped token
in the SAME CLAUSE (split on `.`/`!`/`?`/newline) — no fixed preposition
required. A keyword match INSIDE the path token itself is excluded (a
plan-folder name like `...-file-based-report-handoff` contains "file" and
"report" as hyphen-bounded substrings; without the exclusion a bare
plan-folder mention would wrongly count as a destination, regressing Plan
00460 review finding m4). The clause boundary is what keeps that same m4
distinction correct: a path in one sentence and the verb in the next still
does not pair up.

RED-then-GREEN tests, `TestDestinationPhrasingRecognition` in
`tests/unit/handlers/pre_tool_use/test_dispatch_declaration.py`:

- `test_recognises_label_colon_path_phrasing` — the exact reported miss.
- `test_recognises_save_at_phrasing` — "save ... at ..." (not one of the
  old to/in/under/into prepositions).
- `test_recognises_report_destination_label_phrasing` — a bare
  "<label>: <path>" pairing, no verb-preposition grammar at all.
- `test_still_advises_when_no_path_is_present` — a keyword with no path
  still draws the advisory (broadening the phrasing must not turn into
  recognising a bare keyword).
- `test_plan_folder_mention_in_a_different_clause_still_not_a_destination`
  — the m4 regression guard.

All new tests confirmed RED against the pre-fix code, then GREEN. First
two new tests initially used `CLAUDE/Plan/NNNNN-` paths, which satisfied
the SEPARATE plan-folder declaration route regardless of the
destination-phrasing bug and would have passed even unfixed (a self-caught
test-design flaw, corrected to non-plan-shaped paths before trusting the
RED result).
