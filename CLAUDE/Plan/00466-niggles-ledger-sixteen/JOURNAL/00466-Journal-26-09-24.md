> **Append-only activity log** for plan 00466. One file per day
> (`00466-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

second line of defence for any other caller). Fail-safe pinned with a RED

## 18:27 · action · —   — N10: interior-wildcard glob-intersection fix

Closed the interior-wildcard bypass of `secret_file_guard` (ledger N10). A
wildcard sitting in the MIDDLE of a protected name — `cat .vault-pas?word`,
`cat prod.vault-passw*rd` — had neither a leading nor a trailing open edge,
so it was invisible to every existing check: the leading/trailing overlap
check is gated on an open edge by construction (deliberately, to avoid
re-litigating the N4/m1 false positives), and the substring+fnmatch check
needs the residue to already be a literal substring of the stem, which an
interior truncation never is.

Added `_globs_can_intersect(a, b)` to `secret_file_matching.py`: a real
two-glob language-intersection test over `*`/`?` (standard sequence-alignment
DP, O(len(a) · len(b))), not another edge heuristic. A new
`_interior_wildcard_mention` runs it for every token whose raw spelling
carries glob syntax, over each of its bracket-expanded forms, so a finite
bracket class (`.vault-pa[sz]word`) is covered too even after expansion
strips its wildcard-ness to a plain literal (the intersection test degenerates
correctly to exact-match there).

Scoped narrowly to keep the N4/m1 fixes intact: only a token with NEITHER a
leading NOR a trailing wildcard reaches the new check (an open-edge token
stays on the pre-existing, already-fixed path), and a pattern with wildcards
on BOTH edges (`*.secret*`, `*vault_pass*`) is excluded from it — full
intersection against a "contains this text anywhere" pattern is satisfiable
by nearly any token with its own wildcard (`report-[0-9]*.txt` and
`secret*.py` genuinely glob-intersect with `*.secret*`; live-verified as new
false positives during implementation, neither is evidence of a protected
file). This mirrors the existing near-total-match discipline
`_both_edges_residue_is_near_total_stem_match` already applies for the
same reason elsewhere in this module.
