No such guard exists. `grep -rn 'mcp__' src` returns nothing, and a case-insensitive `mcp` search over `src/**/*.py` hits only `constants/events.py`, `tool_report/report.py:135`, `tool_report/plugin_costs.py:16` and `utils/claude_plugins.py:226` (the `mcpServers` key). None of these decides anything about an MCP tool call. The entry's own remedy ("Likely none today ... close as no consumer") agrees with the code, but the title and the Evidence sentence assert a prefix-keyed guard that is not there. The entry should be retitled "the daemon reads neither `mcp_server` nor the `mcp__` prefix", and the claim that a decision is made by tool name should be dropped.
