## N392: full-QA gate under xdist

Cause: workers are exempt via `_is_xdist_worker`, and the xdist controller's `pytest_collection` short-circuits, so
`pytest_collection_modifyitems` never judged a `-n N` run.

Fix in `src/claude_code_hooks_daemon/qa/full_qa_gate.py`: the judging logic moved to
`_refuse_if_whole_suite_without_lock`, shared by the existing hook and a new
`pytest_xdist_node_collection_finished(node, ids)` hook (`optionalhook=True`, since pluggy otherwise raises when xdist
is absent). The reviewer proved it against a real xdist 3.8.0: `-n 2` is refused with rc=1.

Round 1 review fixes:

- `pytest_configure` (trylast): when the `dsession` plugin is present and the hook has no spec, exit with the
  unable-to-judge message, so a renamed xdist hook cannot make the gate fail open. Red first: the test failed with rc 5.
- `TestXdistControllerIsJudgedToo` now registers a copy of xdist's hookspec in `pytest_addhooks` and calls the hook
  through `session.config.hook`; the duplicate body of the small-report test was removed.
