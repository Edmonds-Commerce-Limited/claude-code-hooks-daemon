Branch `agent-ab9769c816332d0b8-fc3ca42b`.

## N392: full-QA gate under xdist

Cause (verified by reading the plugin, not by a real xdist run, since xdist is not installed): workers are exempt via
`_is_xdist_worker`, and the xdist controller's `pytest_collection` short-circuits, so
`pytest_collection_modifyitems` never judged a `-n N` run.

Fix in `src/claude_code_hooks_daemon/qa/full_qa_gate.py`: the judging logic moved to
`_refuse_if_whole_suite_without_lock`, shared by the existing hook and a new
`pytest_xdist_node_collection_finished(node, ids)` hook. That hook is marked `optionalhook=True`, because without it
pluggy raises "unknown hook" when xdist is absent (seen red during development). The controller process holds the lock
descriptor, so the lock proof is made there.

Tests (`tests/unit/qa/test_full_qa_gate.py::TestXdistControllerIsJudgedToo`): a plugin simulates the controller
(collection returns True, ids are reported to the hook). Red first: the refusal test failed (no hook, rc 3). Green: 21
passed in that file. Residual risk: raising `pytest.exit` inside xdist's hook call is unproven against a real xdist.
