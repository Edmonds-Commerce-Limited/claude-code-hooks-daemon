## REFUTED / needs rewording (most consequential first)

1. Claim 6, "a linter timeout has no such path". Misleading. The harness already has a dedicated path for it:
   `inconclusive_probe` (playbook_harness.py:665), `lint_unusable_failure` (:722) and `inconclusive_skip_reason` (:740).
   A lint timeout is detected and turned into a skip, not scored. What is true is that it is not a non-scoring
   warning like N593's. It becomes a skip, and the skip is escalated to a failure under `HOOKS_DAEMON_RELEASE_GATE=1`.
   The plan should say "a timeout becomes a skip, not a warning", and the proposal then reads as a change to that
   existing path.
2. Claim 8, "the blocking skip stays for the release-time run ... where the daemon is warm", is only partly supported.
   The escalation is not release-only. `HOOKS_DAEMON_RELEASE_GATE=1` is also set in `.github/workflows/qa.yml:132`,
   `.github/workflows/test-shards.yml:94` and `scripts/qa/run_tests.sh:90`, as well as `release-gate.yml:135`.
   That is why main CI went red. A "CI-only warning vs release-time skip" split therefore needs a way to tell those
   invocations apart, which today is the same env var in every one of them. "Warm" appears nowhere in RELEASING.md.
   RELEASING.md only says the daemon is started before Step 12.0. Treat "warm" as an assumption.
3. Claim 5 (the Kotlin budget). The 15 s is not Kotlin-specific. It is the generic `Timeout.LINT_CHECK = 15`
   (src/claude_code_hooks_daemon/constants/timeout.py:163), used by `LintOnEditHandler._timeout_for`
   (post_tool_use/lint_on_edit.py:203-206) when no `options.timeouts.<Language>` override exists. A per-language
   override exists (lint_on_edit.py:138-201), and `.claude/hooks-daemon.yaml:926` shows it only as a commented example.
   So the alternative "raise the Kotlin budget" is already available as config, with no code change.
