## REFUTED (most consequential first)

1. **N280 Probable cause: "It also matches the original report, where the pid file changed and older guidance appeared."**
   NIGGLES.md:672-675 (the N280 Found paragraph) says the opposite: "The pid file of this checkout's daemon did not change during the run, and only that one daemon was running afterwards." The Investigation bullet (NIGGLES.md:710) also says "pid unchanged". So the CI teardown error (pid file changed) does NOT match the original report on the pid point. The same N280 Investigation says `ClaudeMdInjector` "already skips a linked worktree", which contradicts the "if a worktree's run started a daemon" route to main's `CLAUDE.md`. Change: delete the "matches the original report" sentence, or say the pid-file evidence differs and the worktree route is unexplained. "Probable cause fixed by N425" in the N280 status overstates it for the same reason.
2. **N425 bullet: "This is the N280 symptom on a runner with no daemon of its own."** The N280 symptom had an unchanged pid file. Only the CLAUDE.md rewrite matches. Narrow to "the CLAUDE.md-rewrite half of N280".
3. **N425 cause 1: "Over-budget text still fails closed."** `fail_closed` is only a flag on the match (subagent_full_qa_blocker.py:6040 etc.). The default `unseen_policy` is advisory, so the command is ALLOWED with an advisory. It is denied only when `unseen_policy: deny` is set (lines 6822-6830, 6886-6908). The CI case failed because the test treats an UNSEEN match as a failure, not because the handler denied. Reword to "stays UNSEEN, so `unseen_policy` decides".
4. **N425 cause 2: "made the same work 3-4x slower."** The report and the `TRACING_FACTOR` comment (tests/load_scaling.py) give 0.3 s idle, about 1.2 s under local coverage (4x), and 1.7-2.2 s on the runner (6-7x). The CI slowdown is 6-7x, not 3-4x. The factor chosen is 8.0.
