## Doubtful / unverifiable (most consequential first)

- U1 (exit code): the claim that `git merge ... -F -` "exits 129 with `could not read file '-'`". Exit 129 is git's usage-error code, while a failed file read normally dies with 128. I was told not to run git merge, so I could not settle it. `git merge -h` (git 2.39.5) does say `-F, --file <path>  read message from file`, which supports "takes a path". Settling it needs `git merge -F - topic </dev/null` in a scratch repository. If the exit code is 128, change the wording to the observed one.
- U2: "the `merge` is a builtin, which a `!` alias cannot shadow". This is git's documented behaviour and nothing in the repository can check it.
- U3: "evaluation error now allows (B5)". The ledger cites B5 elsewhere (NIGGLES.md:260) as a rule that disallows a denial without a positive finding. The probe's allow decision is consistent with this, but I did not find the B5 definition itself.
