### 00450 release skill vs acceptance-test: NOTHING-LANDED, and it BITES the next /release run

Plan status Not Started; no commits. On main, `.claude/skills/release/invoke.sh` lines 170 to 176 still describe the acceptance-test skill as "Groups tests into batches (3-5 tests each); Spawns parallel Haiku agents to execute ALL batches concurrently". `.claude/skills/acceptance-test/invoke.sh` line 14 says "Sub-agent testing is FORBIDDEN" and line 74 runs "Main Thread Sequential". Neither skill file has changed since v3.69.0. The release text is only a description of what the invoked skill "does" (the release script invokes the skill with `args: all` and does not itself spawn Haiku agents), but an agent reading both will see a contradiction and may follow the release text. Mitigation, low cost: a one-paragraph edit to the release `invoke.sh` lines 170 to 176 to say "executes every test sequentially in the main thread"; also confirm RELEASING.md Step 12 wording (Plan 00450 Task 2.3). This is not a release blocker, but it is the most likely agent misstep during the release itself.
