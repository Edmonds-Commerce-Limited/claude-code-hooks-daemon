# N311 and N313 false positives (sonnet)

Branch `worktree-fp-n311-n313`.

## N313: awk as an inert pipeline stage

`is_inert_pipeline_stage` (utils/shell_segmentation.py) now also answers true for
`_awk_stage_only_reads`. An awk stage is inert only when ALL hold:

- command word is `awk`; no substitution or process substitution in the stage;
- redirects judged as for a sink (`_inert_redirects`, fds assumed able to run);
- the first non-redirect word is the program, a single-quoted literal with no inner quote and none of
  `system`, `getline`, `|`, `>`, `@`;
- every other word is a plain file operand: resolved, not starting with `-`, no `=`.

So `-f`, `-v`, `--`, `name=value` operands and a double-quoted or variable program all stay "not inert".
Only consumer of the function is `command_position._pipeline_is_inert`-style logic in
utils/command_position.py, used by git_stash, destructive_git, dangerous_permissions, curl_pipe_shell,
daemon_location_guard, plan_number_helper, subagent_full_qa_blocker, process_probe; all their test files pass.

## N311: upgrade_approval_guard

Reproduced first (red): two real causes.

1. A subshell `(`: the segment's first word read `(PYTHONPATH=/x/src`, neither assignment nor command.
   The deny only happened because the assignment VALUE contained `/`, so the word was judged as a script
   that could not be found. With no `/` in the value the same subshell was ALLOWED for everything:
   `(PYTHONPATH=x bash -c ...)` and `(PYTHONPATH=x ./run.sh)` were holes. `_live_segments` now strips
   grouping parentheses (`_without_grouping`) before judging, so both are denied now.
2. A path-named interpreter (`.venv/bin/python`, relative, or missing) was judged as a script that
   must be readable; unreadable counts as the upgrade once anything steers (the `export PYTHONPATH=... && .venv/bin/python -m pytest` shape from a worktree with no `.venv`). A path whose basename matches
   `python[0-9.]*` is now judged by its arguments through `_variable_program_is_upgrade` (the N285 logic).
