Scope: the diff at untracked/plan-fact-check/00474-niggles-ledger-seventeen.diff. Verdicts are against the current tree.

## REFUTED / qualified

1. C8 (REFUTED as worded): "`scripts/lib/resolve_venv.sh` scans the same way, so the upgrade's gate step ran under the legacy interpreter."
   - The bash scan is `_rv_pick_python`, lines 290-307 of `scripts/lib/resolve_venv.sh`. It globs `untracked/venv-*/bin/python`, then `bin/python3`, and takes the first candidate that is executable and passes `_rv_candidate_runs`.
   - It does not "scan the same way" as paths.py. It has no fingerprint-keyed step before the scan, no `_venv_slug_eligible` check, no legacy-stamp skip, and no sorting beyond the shell glob order. It does add a run probe.
   - Its result is the interpreter used to run `paths.py resolve-venv` (lines 330-336 of the same script and the header at line 36). It is not the final resolved venv; paths.py decides that.
   - Consequence for the plan: reword to "also takes the first runnable `venv-*` in glob order, with no slug or lock_hash check, as the interpreter that runs paths.py." Also, the Remedy says "both scan fallbacks prefer a slug-eligible venv". The bash scan has no slug logic today, so the remedy adds slug eligibility to bash. It does not just reorder.
   - The claim that the gate step "ran under the legacy interpreter" is a reporter claim. See the unverifiable item U1.
