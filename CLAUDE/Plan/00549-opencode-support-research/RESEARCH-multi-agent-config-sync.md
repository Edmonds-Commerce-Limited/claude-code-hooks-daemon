# RESEARCH: Multi-agent project config that stays in sync (state of the art)

Plan 00549, Task 1.6. Research only. Gathered 2026-10-22.

**Scope.** This document covers four things. First, the `AGENTS.md` standard and who honours it. Second, where each major
tool keeps its config. Third, the generator and sync tools that exist. Fourth, the patterns those tools use. It ends
with what nobody solves yet and the options open to this daemon.

**Relationship to other documents.**

- The opencode and Claude Code specifics are established in `RESEARCH-dual-tool-repos.md` (Task 1.3). They are cited
  here, not re-derived: opencode v2 reads only `AGENTS.md`, Claude Code reads `AGENTS.md` from v2.1.277, and both read
  `.claude/skills`.
- Claude Code `AGENTS.md` equivalence is Task 1.5's subject.

**Evidence conventions.**

- Repository metadata (stars, licence, last push) comes from `gh api repos/<owner>/<repo>` on 2026-10-22.
- Much of the per-tool path data comes from the rulesync documentation. That is a **secondary** source: rulesync tracks
  roughly 60 tools and cites each vendor's docs, but it is not the vendor. Cells resting on it say so.
- Claims we could not confirm are marked **UNVERIFIED**.

## 1. Headline findings

1. **`AGENTS.md` is the settled cross-tool instruction file.** It is stewarded by the Agentic AI Foundation (AAIF), a
   directed fund under the Linux Foundation. OpenAI donated it in December 2025, alongside MCP and goose
   ([openai.com/index/agentic-ai-foundation](https://openai.com/index/agentic-ai-foundation/);
   [agents.md](https://agents.md): "stewarded by the Agentic AI Foundation under the Linux Foundation").
   - It is plain markdown with no schema. **The only shared semantic is "nearest file wins".**
   - Each tool differs in how it handles everything else: whether it loads only the nearest file or stacks all of
     them, whether it loads them lazily or eagerly, which fallback names it accepts, whether it expands `@` imports,
     and what size cap it applies (§2).
   - The spec has never formalised any of these behaviours. The "v1.1" proposal that would have done so was closed
     unmerged (agentsmd/agents.md#135, closed 2026-08-24).
2. **The sync problem is now solved for content-shaped artefacts by mature generators.**
   - **rulesync** (dyoshikawa/rulesync, MIT, about 1.5k stars, v40.1.0 released 2026-10-22) generates from one
     `.rulesync/` source. It covers eight feature types (rules, ignore, MCP, commands, subagents, skills, **hooks** and
     **permissions**) across about 60 tools, and has a CI `generate --check` mode.
   - **ruler** (intellectronica/ruler, MIT, about 3k stars) covers rules, MCP, skills and subagents for 31 agents.
   - Rules-only and symlink tools exist but are small (§4).
3. **Hook *registration* is translated by rulesync; hook *semantics* are not translated by anyone.**
   - rulesync maps canonical camelCase events onto each tool's native event names and file locations. It even emits an
     opencode JS plugin (`.opencode/plugins/rulesync-hooks.js`).
   - The hook command itself still receives each tool's native stdin payload, and must answer in that tool's response
     protocol. Some targets lose the payload entirely (Pi gets no stdin).
   - Matchers are dropped wherever the target event has nothing to match on.
   - Blocking capability differs per event and per tool.
   - **A policy written once and enforced identically everywhere does not exist.** That is the daemon's opening (§6).
4. **A Claude Code hook-protocol monoculture is forming.** Several tools now use the Claude Code shape: PascalCase
   events, JSON on stdin and exit 2 to block.
   - **Factory Droid** has the same event names, stdin JSON, exit-2 blocking and `hookSpecificOutput`
     ([docs.factory.com/harness/hooks](https://docs.factory.com/harness/hooks.md)).
   - **Crush** and **Pool** get a "Claude-Code-style JSON payload on stdin", according to rulesync `file-formats.md`.
   - **Grok CLI** reads `.claude/settings.json` and `.cursor/hooks.json` hook files directly, according to xAI docs
     via search. The page itself returned 404, so this is **UNVERIFIED first-hand**.
   - This means a daemon that speaks the Claude Code protocol already covers more than Claude Code. **opencode is the
     outlier: it has in-process JS plugins, not shell hooks** (`RESEARCH-opencode-extension-surface.md`).
5. **Skills are the second shared format.** Agent Skills (`SKILL.md`) was published by Anthropic as an open standard
   ([agentskills.io](https://agentskills.io); agentskills/agentskills, Apache-2.0, about 26k stars).
   - It has broad adoption. `.agents/skills/` is emerging as the neutral directory: Vercel's `npx skills` symlinks into
     it, and opencode and Antigravity read it.
   - **Claude Code does not read `.agents/`** (vendored `memory.md` L387). Its readers are `.claude/skills`, opencode
     and others.
6. **Nobody enforces the canonical file.** Every tool found generates, links or checks. The checks are a CI
   `git status` diff, `rulesync generate --check`, `ai-rules status`, or a pre-commit hook in agentsync. None of them
   stops an *agent* from editing a generated file mid-session or from writing tool-specific guidance into the wrong
   file. That edit-time gate is exactly what this daemon already does for other files (§7).

**What follows for a canonical `AGENTS.md`:**

- **Nested-file behaviour is not portable.** Codex only sees files on the root→cwd path. Windsurf turns subdir files
  into globs. Zed reads only the root. Aider reads nothing unless configured. Content that *must* reach every tool
  belongs in the root file.
- **Size matters.** Codex truncates at 32 KiB. Antigravity truncates each rule file at 24,000 bytes and demotes rules
  over a 20k-token budget (rulesync supported-tools.md, citing antigravity.google/docs/rules). This repository's
  `CLAUDE.md` with its `<hooksdaemon>` block is far larger than 32 KiB, so a straight rename would be silently
  truncated under Codex.
- **`@` imports are not portable.** Claude Code, Gemini and Amp expand them. opencode and Codex do not. An
  `AGENTS.md` that relies on `@` hides the imported content from half the tools.
- **Claude Code's default skips `AGENTS.md` when any `CLAUDE.md` exists.** The working pattern is a `CLAUDE.md` that
  starts `@AGENTS.md` and holds only Claude-specific extras (memory.md "Share one file with other coding tools";
  dual-tool §4 strategy A).

### 2.4 Ecosystem churn worth knowing

These are reported by rulesync `supported-tools.md` and need re-checking before relying on them:

- Roo Code reached end of life (v3.54.0, 2026-05-15, repo archived). Zoo Code continues it.
- Continue "joined Cursor" on 2026-06-18. **Contradicted:** `gh api repos/continuedev/continue` shows it is not
  archived and was pushed 2026-10-20.
- Gemini CLI was succeeded by Antigravity CLI. The geminicli.com banner confirms this.
- Antigravity retires workflows on 2026-10-19 in favour of skills.
- Windsurf docs now redirect to Devin Desktop.
- The Tabnine CLI is now a distribution of opencode.

The tool landscape moves monthly. **Any generator the daemon depends on must be maintained at that pace, which argues
for depending on one rather than writing one** (§7).

**Observations.**

- **Only instructions converge.** All ten tools read `AGENTS.md`. Skills nearly converge on `SKILL.md`, but the
  directories differ.
- **Everything else is ten dialects.** That covers sub-agents, commands, MCP, permissions and hooks.
- **MCP has at least four shapes:** `mcpServers` JSON, `servers` JSON (VS Code), TOML `mcp_servers` (Codex), and
  opencode's `mcp.servers` with an array `command`.
- **Hooks have two architectures.** Most tools use out-of-process command hooks with JSON on stdin. opencode, Kilo,
  Amp and Pi use in-process JS/TS plugins.

## 6. What nobody solves yet

1. **Hook semantics portability.** rulesync relocates and renames hooks, but the script still sees N payload dialects
   and must emit N response dialects. The differences include:

   - `hookSpecificOutput.permissionDecision` vs Cline's `{"cancel": …}`;
   - Pi gets no stdin at all;
   - opencode's plugin hooks expose no matcher target for several events.

   No one offers **one handler, one decision, enforced identically**. A normalising dispatcher does exactly that: it
   takes each tool's event in, maps it to a canonical event, runs one handler set, and renders the decision back into
   each tool's dialect. This daemon already is such a dispatcher for one tool.

2. **Policy beyond allow/deny.** The structured-permissions work maps glob allowlists: rulesync's `permissions.jsonc`
   and agents.md#105. Nothing portable expresses the stateful or content-aware rules this daemon enforces, such as:

   - inspecting what a write contains (QA suppressions, secrets, changelog comments);
   - the TDD test-before-source gate;
   - commit-time gates;
   - plan-workflow invariants;
   - stop-explanation rules.

3. **Enforcement of the canonical file itself.** Generators assume a human runs them. Nothing blocks an agent from
   hand-editing a generated `CLAUDE.md` / `.cursor/rules/*` mid-session, or from writing Claude-only guidance into
   `AGENTS.md`. The drift is only discovered later in CI.

4. **Semantic drift between tool-specific extras.** The checks above are byte-equality between source and outputs. No
   one checks that a `CLAUDE.md` extras section does not contradict `AGENTS.md`. That is a docs-QA (SSoT) problem,
   which this daemon's `docs_qa` already addresses for single-tool trees.

5. **Verifying that guidance actually loaded.** Each tool reports loaded instructions differently (Claude Code's
   `InstructionsLoaded` hook, Gemini's `/memory show`, Claude's session line "AGENTS.md loaded: …"). There is no
   cross-tool "which instructions did this session get" probe. Codex's 32 KiB truncation is silent.

6. **Standards gaps.** `AGENTS.local.md` (#13), permissions (#105), hooks, sub-agents and skills linking (#149) are
   all open at the AAIF level.

## 7. Options for this project: provisioning and enforcing a canonical AGENTS.md

These are building blocks already in the tree:

- `ClaudeMdInjector` (`src/claude_code_hooks_daemon/core/claude_md_injector.py`) regenerates the `<hooksdaemon>`
  section and auto-commits it.
- `deployed_artefact_drift` (`handlers/session_start/deployed_artefact_drift.py`) reports a deployed file that has
  diverged from its template.
- The `validate_instruction_content` handler.
- The `docs_qa` and commit-gate handlers (`*_commit_gate`).

Options are listed with trade-offs only. There is no design here.

### Instruction layout

| Option                                                                                                                                               | Trade-offs                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **I1. `AGENTS.md` canonical; daemon provisions a `CLAUDE.md` shim = `@AGENTS.md` + Claude-only extras** (dual-tool strategy A)                       | Works on every Claude Code version and keeps `InstructionsLoaded`. opencode, Codex and Cursor see the shared content. Needs a migration of each client's existing `CLAUDE.md` content, and a rule for what is "Claude-only"                                                                        |
| **I2. Move the `<hooksdaemon>` injected section into `AGENTS.md`** (or emit a tool-neutral variant there and keep the Claude variant in `CLAUDE.md`) | Without this, opencode sessions get no handler guidance (dual-tool §1.1). The text names Claude tools (`Write`, `Edit`, `Bash`, `Task`), so it needs per-tool vocabulary or neutral wording. The section's size threatens Codex's 32 KiB cap; it would need trimming or a pointer-plus-skill split |
| **I3. Nested docs**: convert nested `CLAUDE.md` to `AGENTS.md` + shim, or keep root-only                                                             | Nested semantics differ per tool (§2.3). Content that must apply everywhere should live in the root                                                                                                                                                                                                |

### Sync mechanism for non-instruction artefacts (agents, commands, MCP, permissions)

| Option                                                                                                            | Trade-offs                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S1. Delegate to rulesync** (daemon checks for it, runs `generate --check`, reports)                             | Maximum coverage. Tracks the monthly churn so we do not have to. Adds a Node dependency to a Python project's clients. Its `.rulesync/` becomes a second SSoT that the daemon must respect. Its hook output for opencode is a generic shell-runner plugin, which would *compete* with a daemon opencode plugin |
| **S2. Daemon-native generator for the narrow set it owns** (its own agents, skills, MCP, and the opencode plugin) | Full control, no dependency. Re-implements a moving target. Scope creep beyond "hooks daemon"                                                                                                                                                                                                                  |
| **S3. Symlinks for identical content** (skills, possibly `CLAUDE.md`→`AGENTS.md` when no extras)                  | Simplest. Windows/git caveat. No tool-specific content. opencode already reads `.claude/skills`, so skills need nothing                                                                                                                                                                                        |
| **S4. Document and leave to the client**                                                                          | Zero cost. The drift persists                                                                                                                                                                                                                                                                                  |

### Enforcement and drift detection (the daemon's differentiator)

| Option                                                                                                                                                                                                                                                                                                                     | Trade-offs                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **E1. Edit-time guard**: PreToolUse deny of `Write`/`Edit` to a generated or shim file, naming the canonical source. The same idea as the `<hooksdaemon>` "do not edit" section, but enforced                                                                                                                              | Nobody else does this (§6.3). Claude-side only until an opencode adapter exists. Bash writes bypass it (the known class-wide blind spot)                                             |
| **E2. Content guard on `AGENTS.md`**: deny Claude-only constructs (tool names, `@` imports that opencode will not expand, `CLAUDE_*` vars) in the shared file; extend `validate_instruction_content`                                                                                                                       | Keeps the shared file portable. Needs a maintained list of tool-specific tokens                                                                                                      |
| **E3. SessionStart drift report**: in the style of `deployed_artefact_drift`, report generated files out of sync with their source, a size over Codex's 32 KiB, a stray `.cursorrules` that shadows `AGENTS.md` in Zed, and a `CLAUDE.local.md` that silently disables `AGENTS.md` loading in Claude Code (memory.md note) | Advisory and cheap. Proven pattern in-tree                                                                                                                                           |
| **E4. Commit gate**: deny a `git commit` whose staged tree has drift (`rulesync generate --check` exit 1, or the daemon's own check)                                                                                                                                                                                       | Catches Bash-authored drift too. Claude-only until opencode support lands                                                                                                            |
| **E5. Tool-neutral backstop**: provision a git pre-commit hook and/or a CI step running the same check                                                                                                                                                                                                                     | Covers any agent and humans. Opt-in per clone. Bypassable with `--no-verify`                                                                                                         |
| **E6. Lead on portable policy**: publish the daemon's canonical event/decision model as the "semantics" layer rulesync lacks. For example, rulesync's `claudecode` hooks target the daemon's forwarder, and a daemon opencode plugin covers opencode                                                                       | Positions the daemon as the enforcement layer above config-sync tools rather than competing with them. Largest scope. Depends on Phase 2 (`MAPPING-events.md`, `OPTIONS-support.md`) |

**Observation for Phase 2, not a decision.** The low-regret combination appears to be:

- **I1 + I2** for instructions;
- **S3/S4** for skills, since `.claude/skills` is already shared;
- **E1, E3 and E4** as the daemon's distinctive contribution, because enforcement is the gap no sync tool fills;
- **S1** as an optional integration that the daemon detects and checks, rather than a dependency it owns.

The hook-semantics gap (§6.1) is the strategic opening, and it belongs to `OPTIONS-support.md`.
