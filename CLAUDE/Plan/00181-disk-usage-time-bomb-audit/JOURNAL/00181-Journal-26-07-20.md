## 17:40 · finding · T3.2 — coverage-only 25-test regression → paths.py import discipline

The first Task 3.2 QA run surfaced 25 test failures that did NOT reproduce
under a plain `pytest tests/` (which passed / was flaky) but reproduced
DETERMINISTICALLY under the coverage harness (`--cov=src --cov=.claude/ccy`).
Root cause: I had added a TOP-LEVEL `from ...utils.retention import
prune_directory` to `daemon/paths.py`. paths.py is bootstrap-critical — it is
imported at module top by the standalone `python3 paths.py resolve-venv`
wrapper on the system Python, and `test_paths_import_under_310` explicitly
enforces that paths.py stays import-light (the Plan 00103 tomllib deferral).
Under coverage's eager full-module import, pulling the whole `utils/__init__`
chain into paths.py's module load produced order-sensitive failures.

Fix: moved the import into the body of `cleanup_stale_session_dirs`
(function-local), mirroring the tomllib deferral the same test file enforces.
Verified: the EXACT coverage harness that showed 25 failed now shows
**10443 passed, 0 failed** with only the import-location change — discriminating
variable confirmed. mypy clean on paths.py. Daemon restarted RUNNING
(PID 895839) on the fixed module.

Lesson: never add a top-level cross-package import to daemon/paths.py — it is a
bootstrap-path module; new dependencies must be function-local. (Candidate for
CLAUDE/development/LESSONS.md.)

## 18:30 · decision+action · T4.2 — surface reclaimable venvs (not auto-delete)

Reading `_enumerate_venvs` confirmed there is NO filesystem signal that a live
peer container is using a given-fingerprint venv (running `bin/python` bumps
neither the venv dir nor the `.daemon-version` stamp mtime). Auto-deleting a
"stale" venv could therefore destroy a live peer's env. Recorded as Decision 1
in PLAN.md: SURFACE, don't delete — matching the daemon's own
background_process_tracker principle ("never kills; surfaces; you decide").

Implemented:
- `_enumerate_venvs(project_root, include_size=False)` — skips the ~187 MB
  recursive size walk on the hot start path; sizes only the reclaimable set.
- `_reclaimable_venv_entries(entries, current_stamp)` — pure selector (legacy
  or non-current version-stale; never current). Mirrors prune-venvs predicates.
- `_stale_venv_advisory(project_root)` — cheap select → lazy-size → format;
  returns None when nothing to reclaim (zero disk walks in that common case).
- Wired into `_reap_stale_runtime_files` so it prints on every start
  (reuse + fork), pointing at the guarded `prune-venvs --stale --force`.

TDD: 6 tests (selector include/exclude, include_size=False skips walk, advisory
None cases, advisory reports count + prune command). Daemon-start suites: 44
passed.
