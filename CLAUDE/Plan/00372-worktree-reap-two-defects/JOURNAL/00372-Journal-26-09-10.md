## 12:55 · finding · — — Defect 2 reproduced in a throwaway repo

`git branch -d refs/heads/testbranch` fails with `error: branch
'refs/heads/testbranch' not found.`, while `git branch -d testbranch` (bare
name) succeeds — including when a same-named tag also exists, where it
correctly deletes the branch and leaves the tag alone. `git branch -d
heads/testbranch` (no `refs/` prefix) also fails. So `git branch -d`
resolves its argument only inside `refs/heads/` directly; it is not a
general ref-resolving command, and `branch_ref()`'s "bare name is ambiguous"
rationale (Plan 00254) does not apply to it. Grep confirms `worktree_reaping.py`
is the ONLY call site in the codebase that feeds `branch_ref()` output to
`branch -d`; every other `branch_ref()` use feeds a genuinely ambiguity-prone
command (`rev-parse`, `cherry`, `merge-base`, `diff` ranges).
