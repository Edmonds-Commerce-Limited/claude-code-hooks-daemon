## 20:42 · finding · — — the dataset is 48:1 test fixtures, and rows accrue per STOP

Measured twice, hours apart, across a session with three full QA runs and four
shipped commits. It did not move:

```
instrumented rows: 49
  acceptance/integration probes (literal ids): 48
  REAL sessions (uuid ids): 1
```

The reason is the useful part. A session is re-entered constantly by task
notifications and cron ticks, and NONE of those is a Stop hook event. The hook
fired once in 2.5 hours. So the sample grows per genuine stop, which means many
sessions over calendar time — this is a waiting plan, not a working one, and
Phase 1 says so explicitly.

The 48:1 ratio is the trap for whoever picks this up. The stop-hook acceptance
tests drive the real wrapper against the real daemon, so six synthetic rows
land per full QA run. Correct behaviour, not a defect to fix — but an
unfiltered read of this file concludes the stop hook does nothing but deny
0-byte transcripts.
