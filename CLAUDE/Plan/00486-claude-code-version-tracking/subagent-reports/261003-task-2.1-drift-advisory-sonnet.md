# Plan 00486 Task 2.1: review-drift advisory (Sonnet)

## What changed

`ContractStalenessHandler` now runs two independent checks and joins their advice:

1. Contract check (unchanged behaviour): installed Claude Code vs `META.json` `last_audited_claude_code_version`.
2. Review-drift check (new): installed Claude Code vs the newest `reviewed_through` in `CLAUDE/development/claude-code-versions.yaml`. When newer, one advisory names the running version, the last reviewed version, and the action: run the `claude-code-changelog-reviewer` agent over that range and record it in the YAML (RELEASING.md Step 1c).

Files: the handler, its unit test, `tests/integration/test_claude_code_version_record.py` (new pin), the YAML (new field), RELEASING.md Step 1c, `docs/guides/HANDLER_REFERENCE.md`, `CLAUDE/ARCHITECTURE.md`, PLAN.md tick, journal entry.

## Decisions

- New YAML field `reviewed_through`. The only reviewed entry (v3.68.0) has `claude_code_version: unknown`, so the end of the reviewed range (2.1.288) had nowhere to live. Added as optional per entry, required when `review_date` is known (integration test pins it). The drift check takes the newest valid `reviewed_through`.
- Silent in a client install two ways: the check requires self-install mode (fails closed when the mode is unresolvable), and it needs the file. The clone a client install uses is a full checkout of this repository, so the file may exist there; the self-install gate is what makes silence certain, not file absence alone.
- Dedupe: the existing contract advisory has no per-version dedupe (it fires on every new session while stale). The new advisory records `drift_advised_version` in the handler's existing cache file (`contract_staleness_cache.json`) and fires once per installed version; a newer unreviewed version re-arms it. The cache write was refactored into `read_cache`/`write_cache` so the version probe and the marker merge rather than clobber each other. An unwritable cache means the advisory repeats, not an error.
- "contract_status.py's existing reader": that module only reads `META.json` (and fetches), it has no YAML or version-comparison code. The handler reuses its own `_is_newer` and `_VERSION_PATTERN`; no second version parser was added. The YAML is read with `yaml.safe_load` in the handler.
- One-line descriptions in `init_config.py`, `hooks-daemon.yaml.example` and `.claude/HOOKS-DAEMON.md` were left alone: they are still true, and are config-template surfaces pinned by other tests.
- `get_claude_md()` returned None before; it now returns short guidance covering both checks. The regenerated CLAUDE.md section is produced by a daemon restart, which was not run here.
