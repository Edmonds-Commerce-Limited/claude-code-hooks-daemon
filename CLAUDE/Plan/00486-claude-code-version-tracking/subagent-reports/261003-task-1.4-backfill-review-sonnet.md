## Answer: does Claude Code have idle compaction?

**Not in anything I can read.** Across the whole changelog page (back to its oldest entries) there is no entry for compaction triggered by idleness, and neither the changelog nor the vendored `prompt-caching.md` and `context-window` references describe one. What exists is: auto-compact when context nears the window (`/autocompact` sets the window, saved per model from 2.1.288), reactive compaction on "Prompt is too long" (retry hardened in 2.1.284), manual `/compact`, `/recap` (an away summary that does not replace history), `/goal` idle check-ins, and a cache-expired footer hint. The owner's report is unconfirmed; it may come from a build or flag the changelog does not name.

**Where the daemon overlaps what does exist**:

- The ccy supervisor injects `/compact` when context goes red, gated on idle and a cooldown (`.claude/ccy/claude-supervise.py:18`). That is the daemon's own idle-gated compaction. It races Claude Code's window-based auto-compact whenever a user's `/autocompact` window sits below the daemon's red tier (`handlers/status_line/context_tiers.py:170`). The `compaction_signal` marker (`handlers/pre_compact/compaction_signal.py:1`) already covers a compaction of any origin, so the race is benign.
- `prompt-caching.md:182` says that after a break longer than the cache lifetime a compaction reprocesses the full history uncached, so it "costs the most" when the cache is cold. An idle-gated supervisor `/compact` fires in exactly that state. The Status payload's `prompt_cache.warm` (read in `handlers/status_line/prompt_cache_indicator.py:10`) would tell the supervisor which state it is in.
- `handlers/stop/auto_continue_stop.py:100` tells agents auto-compact handles context pressure; that stays true.
