wrapper exits 5.

which is why nothing local ever tripped over it.

## 05:24 · decision · T3.4 — the gate had no test file at all

The direct answer to "how did all this get through QA": `python_var_guidance`
shipped in Plan 00192 scoped to `src/` only, **with no test file**. Nothing
asserted where it pointed, so its scope was invisible — it reported green while
297 occurrences of the exact defect it exists to prevent sat one directory away.

A gate's scope is part of its contract. Written `tests/unit/qa/test_check_python_var_guidance.py`
(15 cases) covering all three variants, the same-line exemption semantics, the
scanned-suffix surface, and — critically — `TestRepositoryIsClean`, which runs
the gate against its real default roots. Narrowing `_DEFAULT_SCAN_ROOTS` in
future is now a test failure rather than a silent loss of coverage.

TDD was honoured: the three variant-3 cases were written first and observed
failing (`3 failed, 12 passed`) before the pattern was extended.

## 05:24 · finding · P2 — the docs were also teaching superseded procedures

Fixing the interpreter references exposed a second layer. Many of these snippets
were not merely naming a dead path, they were documenting a whole workflow that
had been replaced:

- `Worktree.md` taught `git worktree add` + `python3 -m venv untracked/venv` +
  editable pip install — all three superseded by `scripts/setup_worktree.sh`,
  which does the lot with a fingerprint-keyed venv. Hand-rolling the venv
  actively creates the layout the resolver rejects.
- `LLM-INSTALL.md` pointed at `install.py`, which carries its own DEPRECATION
  NOTICE (superseded by `install_version.sh`). Its "Manual Install" section also
  rationalised the dead path in writing: *"The commands below show the legacy
  path for readability"*. That sentence is how the rot survived a release — a
  path that does not exist is not a readability aid.
- `LLM-UPDATE.md` / `UPGRADES/*` taught reinstall-by-pip; superseded by
  `upgrade_version.sh` and the `repair` subcommand.
- Several docs (`LLM-INSTALL.md`, `GETTING_STARTED.md`) instructed
  `cd .claude/hooks-daemon`, which this daemon's own `daemon_location_guard`
  **blocks**. The docs were telling agents to do something the product forbids.
- `scripts/handler_status.py` invocations replaced with the `handlers`
  subcommand; import-check one-liners replaced with `health`; version-probe
  replaced with `bug-report`.

Verified every replacement against the live CLI before writing it (`handlers`,
`health`, `list-venvs`, `repair` all confirmed; there is no `--version` flag, so
I did not claim one, and there is no `VERSION` file, so a first draft citing one
was corrected to `git describe --tags`).
