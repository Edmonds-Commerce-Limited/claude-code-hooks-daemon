# Task 8.1 report: early usage-resume tick re-evaluates the pause (issue #132)

Code commit: 9a0eb8088 on worktree-issue-132-early-pause-reeval. This report is written inside the worktree (same relative path) because the cross-worktree write guard denied the /workspace path; it is committed as a second commit.

## Change

- `utils/usage_pause_gate.py`: `EARLY_READING_MAX_AGE_SECONDS = 900` (ten-minute tick plus half a tick of margin), `REBASE_TOLERANCE_SECONDS = 600` (one tick), `fresh_breaches`, `rebase_pause`, and helpers `_has_ceiling`, `_read_snapshot` (shared with `current_breaches`), `_reading_is_fresh`.
- Handler `_resume` now delegates a pre-`resume_at` tick to `_early_tick`:
  - fresh and under the ceiling: `_lift(..., verified_under_ceiling=True)`;
  - fresh and still over: silent re-base when `resume_at_for(breaches)` differs from the record by more than the tolerance (`paused_at` kept), then drop;
  - stale or missing: drop as before.
- Freshness: the snapshot must hold at least one window, and every PRESENT window must have `now - observed_at <= 900` (inclusive). An absent window is not stale: it rolled over or was never sent, and `find_breaches` already reads it as under. Requiring both windows would break the field case, where the status line showed only 7d.
- A host with no ceiling lifts an early pause, as the held-prompt path already does.
- Docs updated: both module docstrings, handler `get_claude_md`, `docs/guides/CONFIGURATION.md`, `docs/guides/HANDLER_REFERENCE.md`. The other "zero cost" hits (LLM-INSTALL.md, scaling.py, release note 213) are unrelated or historical. Release note: `CLAUDE/UPGRADES/UNRELEASED/release-notes/007-...md`.
