> **Append-only activity log** for plan 00518. One file per day
> (`00518-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM, ONLY with
> `mkplan.bash --journal <plan-number> <category> <body-file>` (it stamps the
> real UTC time; a hand-written entry is denied); NEVER edit earlier entries
> (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff` | `correction`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - A `correction` corrects an earlier entry without touching it. Its `REF`
>   (`--ref`, required) names that entry: `HH:MM` in this file, or
>   `YY-MM-DD/HH:MM` in an earlier one. An entry a correction names in this
>   file no longer counts for time order, so a future-dated stamp can be
>   corrected at the honest time.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 12:03 · finding · —   — Trial C: a stale name record denies the real exempt agent

Task 3.3 trial C found a defect. An UNNAMED `qa-full-runner` was dispatched (subagent_type `qa-full-runner`, now dispatchable in this session) while Plan 00517's targeted QA held the host-wide lock. Expected: the lock deny ("your agent type is exempt ... held by"). Observed: the PLAIN not-exempt deny, R-SUBAGENT-FULL-QA, matched `llm-qa-whole-suite` (report: `subagent-reports/261013-trial-c-qa-full-runner.md`).

Cause: trial D's record `{"name": "qa-full-runner", "subagent_type": "general-purpose"}` is still in this session's registry. An unnamed dispatch's payload `agent_type` is its definition type, `qa-full-runner`; `effective_agent_type` looks the value up as if it were a dispatch NAME, finds the trial-D record and resolves `general-purpose`. Once any teammate in a session has been NAMED after an exempt type, the real exempt agent is denied for the rest of that session. The failure is closed (a deny), never an over-allow, but the exemption is broken.

Fix direction: tell named from unnamed by the payload `agent_id`, measured in Task 0.1: unnamed `a57801934993f0485` (`a` + 16 hex), named `aprobe-named-518-…` (`a` + name + `-`). An `agent_id` of the unnamed shape means `agent_type` IS the definition type, so the records are not consulted; any other shape is treated as a named teammate whose type must come from its dispatch record, and no record resolves to no type (deny), fail-closed if the upstream format moves. Trial C itself is unproven until the fix lands; it is re-run after.
