## Verdict

Phase 1 NOT built. PreToolUse payloads from a sub-agent do carry a non-empty `agent_type`, but the measured value is the
dispatch NAME, not the agent definition type. The plan's key ("exact agent type") is therefore not what the payload
holds, and the design needs a ruling before anything keys on it.

## Consequence for the design

If `agent_type` is the dispatch name, then `exempt_agent_types: [qa-full-runner]` is satisfied by any dispatcher that
names its agent `qa-full-runner`, whatever definition (and tool allowlist) it uses; and a correctly dispatched
`qa-full-runner` that the coordinator also names (as this team does: `dev-518`, `burndown-audit`) would carry the NAME and
not match. The coordinator's naming habit would silently defeat or bypass the exemption.

Options for the owner/coordinator (not decided here):

- A. Probe first: dispatch a throwaway `qa-full-runner`-like agent (a trivial `.claude/agents` file) once with no name
  and once with `name: qa-full-runner`, capture both PreToolUse payloads, then decide. Cheapest, resolves unknowns.
- B. Key the exemption on the NAME explicitly (rename option to `exempt_agent_names`), documenting that the coordinator
  must name the dispatch `qa-full-runner`. Spoofable by naming, acceptable if the guard is anti-accident only.
- C. Resolve `agent_type` through `utils/subagent_tool_resolution.resolve_agent_definition` is no help (it takes a
  definition name), so a definition-type key would need another payload field; none was found.

Recommendation: A, then B or the unnamed form depending on the capture.
