### Things the coordinator should know

1. **The lock check is a pre-flight, not the serialiser.** `llm_qa.py` itself waits on the same lock (it waits up to
   600 s by default), so two exempt runs would also queue there; the handler denies the second one early and names the
   holder. A probe holds the lock for microseconds; a concurrent real run's own non-blocking attempt in that window
   would see it held.
2. The lock only reports a holder name when the holder is `llm_qa.py` (it stamps the file); a bare pytest holder is
   reported as "the holder is not named".
3. Residual limits (documented in guidance): an unnamed agent's `agent_type` is trusted as its type; a named agent is
   exempt only if `agent_dispatch_recorder` is enabled and the daemon saw the dispatch (a restart between dispatch and
   the Bash call keeps the file; a different daemon `untracked/` dir does not). A Workflow-tool agent is unmeasured.
4. A new handler adds invariants: entry in the guidance-coverage table (`tests/integration/test_claude_md_guidance_coverage.py`).
   The generated `.claude/HOOKS-DAEMON.md` and the `CLAUDE.md` hooksdaemon block regenerate on daemon restart; I did
   not edit them by hand.
5. Task 3.3 needs the daemon restarted so the worktree config and new handler load.
