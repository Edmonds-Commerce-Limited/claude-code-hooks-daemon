## REFUTED (most consequential first)

**C6. "Withholding the `.compacting` signal would not stop the `continue`, because the supervisor also reads `compacting` from the context sidecar."**
The supervisor parser does read a `compacting` key from the sidecar (`.claude/ccy/claude-supervise.py:2649`). But the only
daemon writer of the sidecar, `src/claude_code_hooks_daemon/handlers/status_line/context_sidecar.py:136-152`, emits no
`compacting` key (keys: schema_version, red, critical, compact_urgent, tier, pct, window_size, cost_usd, effort,
session_id, model_id, ts, seq, writer_pid). The daemon-side signal is `handlers/pre_compact/compaction_signal.py`
(`<session>.compacting` file) only; the supervisor sets `compacting=True` on a reading from that file
(`claude-supervise.py:7457-7480`). So withholding the file WOULD leave `compacting` False in practice, and the stated
reason for "no daemon lever" is wrong. The conclusion that Task 5.1 owns Ruling 07 can still stand, but the
justification needs rewording (e.g. the consequence for the `/compact` wait, see C7), or the sidecar claim dropped.

**C7. "It would also break the supervisor's wait after a `/compact` it typed: that wait never ends, and each wasted wait counts towards the injection fuse."**
Half wrong. The wait does end: `_evaluate_await` returns to monitor on `_await_timed_out`
(`claude-supervise.py:6669-6672`, `6763-6766`, "await-compacting timed out -> back to monitor"). The fuse claim is right:
the `_injections` counter is reset only on a confirmed compaction, and the timeout path deliberately keeps accumulating
(comment at `6538-6545`). Change "never ends" to "ends only by timeout".
