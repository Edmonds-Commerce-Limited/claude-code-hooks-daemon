# Fact check: Plan 00501 session focus mode

## REFUTED (most consequential first)

**R1. "every work-driving handler is already marked `drives_autonomy` and judged centrally in `core/chain.py`"** (Overview, lines 22-25; Task 1.1 line 63 and Goals line 32 repeat it).
Partly false. Only 9 handler files set `drives_autonomy = True`: goal_injection, session_actions_directive, cron_stop_enforcer, cron_subagent_stop_enforcer, recovery_cron_advisor, idle_housekeeping_advisor, failsafe_cron_session_advisor, persistent_cron_assertor, routine_qa_sweep (`grep -rn drives_autonomy src`). Two other work-driving mechanisms call `autonomy_allowed(hook_input)` INSIDE the handler and are NOT flagged:

- `auto_continue_stop`: the stand-in block (`handlers/stop/auto_continue_stop.py:706`) and the goal-ledger challenge (`:927`).
- `background_process_tracker` (`handlers/post_tool_use/background_process_tracker.py:392`).
  Effect on the plan: the gate in `chain.py:1123` (`handler.drives_autonomy and not autonomy_allowed(hook_input)`) does not cover them. Focus mode works for them only because they call `utils.autonomy.autonomy_allowed` directly, so Task 1.3 must change `autonomy_verdict`, not just the chain gate. The "every `drives_autonomy` handler is skipped" goal is true but incomplete. Task 1.1's "notably `auto_continue_stop`'s goal ledger" is correct as a worry: it is not `drives_autonomy`.

**R2. Implied: `failsafe_cron_blockage_suppressor` could be gated like other handlers; its tick recognition is "reused".**
The suppressor is not `drives_autonomy` and has no autonomy call (grep of its file finds none). It clears its marker on any non-tick prompt and takes its session from `hook_input`, with state files under the daemon untracked dir (`failsafe_cron_blockage_suppressor.py:295-320`). It must NOT be gated: gating it would stop it dropping ticks. The 00498 inventory says the same ("removes pressure rather than adding it"). The plan's tick dropping (Task 2.2) needs a new or extended handler. The suppressor's drop is keyed on an `[awaiting-human]` marker, not on session focus. Only `classify_tick` is reusable.

**R3. Minor: "keyed by the hook input's `session_id`".**
Today's verdict is keyed by environment and hostname, not session (`utils/autonomy.py:100-118`, `effective_hostname(hook_input)`). The plan introduces the session keying. It is a new input, not an existing one.
