## B-3 and B-4 (`utils/secret_file_matching.py`)

**Red.** The review's shapes reproduced through the handler, but only for a `<P>` absent from the tree. An indexed protected file is already denied by another route, which is why the review saw exact names deny. The tests run every deny shape with both names: the absent name was red, and the indexed name is kept as a regression case.

**Fix.** One predicate, `_git_option_takes_search_value`, now serves both spellings: the separate form (via `_opens_files`) and the attached form (`_git_search_value_prefix_before`, reached from `_bash_occurrence_counts` and `_is_git_search_word`). The exemption holds only when all of the following are true:

- **The command is git.** The segment's command word, from `segment_command_chain`, must be `git`, not a word that merely appears in the segment.
- **The subcommand allows the value.** It must be one where the option takes a value, probed against git 2.47 in a scratch repo:
  - `-S` and `-G`: log, show, whatchanged, diff, diff-tree, diff-index, format-patch.
  - `--grep`, `--author`, `--committer`, `--grep-reflog`: log, show, whatchanged, rev-list, format-patch.
  - Left out because they were unverified or have another meaning: shortlog, blame, grep, commit, diff-files, and rev-list for `-S`/`-G`.
- **The global options before the subcommand are known.** Every one must be in a known valueless set, a known separate-value set (which adds `--attr-source`, absent from the shared `GIT_GLOBAL_OPTIONS_TAKING_SEPARATE_VALUE`), or an `--opt=value` word. Any other option means no exemption.
- **No end-of-options marker comes first.** Neither `--` nor `--end-of-options` may appear before the option.
- **The option is not consumed as a value (separate spelling only).** If the word before it is an option, that option must provably take no value. A scratch-repo probe found that `git log -p --until -S f` and `git show --until -S f` print `f`'s content: `-S` becomes the date, and `f` becomes a pathspec.

**Tests.** They are in `tests/unit/handlers/pre_tool_use/test_secret_file_guard_option_values.py`, class `TestGitSearchExemptionIsScopedToSubcommand`.

- **Denied:** 21 shapes × 2 names, including:
  - `git grep -G <P>` and `git grep -G<P>`
  - `git blame -S <P> f` and `git blame -S<P> f`
  - `git -C log blame -S <P> f`
  - `git log -p -- -S <P>`
  - `git log -p --until -S <P>`
  - `git log -p -S -S <P>`
  - `sudo -u git git blame -S <P> f`
- **The narrowing proof:** `git log -S <P>`, `git diff -G <P>`, `git log --grep=<P>`, `git -C sub log -S <P>` and `git log -n5 -S <P>` stay ALLOWED, while the same `<P>` after the same letters on grep or blame is DENIED.

## B-5 (`_searched_paths_hold_no_protected_file`)

**Red.** The guard denied these shapes end to end, through another route. So the red tests sit at the function level, where the function judged `-ezz` and `--regexp=zz` (grep and rg) clean. `rg --files deep sub -g '*'` was red end to end: it was ALLOWED, with `deep` unchecked.

**Fix.** A segment is never judged clean when the first operand might not be the pattern. That covers:

- the separate `-e`, `-f`, `--regexp` and `--file` (as before)
- `--regexp=` and `--file=`
- any single-dash cluster containing `e` or `f` (`-ezz`, `-vezz`, `-rezz`, `-fpats`)
- `--`, where a dash-led directory after it was invisible to the operand filter
- `rg --files`, which takes no pattern

This is the verdict the separate spelling already got. "Treat every operand as a path" was rejected because it would ALLOW `grep -r --regexp=zz sub --include=*`, which the previous commit denied.

**Tests.** The class `TestGrepPatternOptionSearchesEveryOperand` covers both spellings for grep and rg, the cluster forms, `-fpats`/`--file=`, `rg --files`, a `-held` directory after `--`, and a function-level check.

## Differential (deny to allow)

`untracked/scratch/b3b5_differential.py` (in the worktree) runs the handler over a generated corpus of git and grep/rg shapes against a synthetic project. It compares the verdicts from the untouched tree (81e69799a) with those from the fixed tree.

**Result:** 204,390 commands were compared. **DENY to ALLOW: 0.** ALLOW to DENY: 33,304, all of them fail-closed tightenings in the expected classes.

- **Git subcommands now out of scope.** On blame, grep, commit, merge, rebase, stash, shortlog, diff-files, am, cherry-pick, range-diff and unknown subcommands, a glob-only name after the option now denies.
- **Unvouched global options.** `--unknown-global`, plus `-C`, `-c` and `--attr-source` in front of an out-of-scope subcommand.
- **Options consumed as a value.** On log, the only tightenings are where the option is taken as an earlier option's value (`--until`, `--grep`, `-S`, `-n` in front of it) or follows `--` / `--end-of-options`.
- **grep/rg attached and file pattern options.** The `-ezz`, `--regexp=zz`, `-rezz`, `-vezz`, `-fpats` and `--file=pats` spellings.
- **grep/rg end of options.** Commands containing `--`.
- **rg --files.**
- **Known over-deny.** `-ve zz` (a cluster ending in `e`, with the pattern as the next word) was correctly allowed before and is now denied. That is the price of matching clusters broadly.

The verdict dumps are `untracked/scratch/diff-base.json` and `diff-new.json` in the worktree, and the listing is `diff-compare.txt`.
