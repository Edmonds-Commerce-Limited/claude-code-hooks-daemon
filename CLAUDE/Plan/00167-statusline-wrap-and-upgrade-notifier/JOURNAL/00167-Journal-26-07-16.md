## 08:05 · finding · — — status-line investigation (pre-plan research)

Root-caused the four status-line questions from two research agents +
direct code reading:

- **Assembly**: `core/hook_result.py:164-185` joins enabled `status_line`
  fragments with `" | "` and returns `{"text": text}`. ZERO width /
  truncation / wrapping logic — narrow terminals lose right-hand segments
  off the edge.
- **Wrap is feasible**: Claude Code officially renders multi-line status
  (one terminal row per `\n`), and exposes terminal size via `COLUMNS`/
  `LINES` **environment variables** (v2.1.153+), NOT in the JSON payload.
- **Transport gap**: the daemon is a separate process and does not inherit
  `COLUMNS`. The jq-free transport (`init.sh` `send_request_stdin`, Status
  branch ~L960) runs in the wrapper's env and already rewrites the Status
  payload — the correct single injection point to forward width/height.
- **Cron**: NO scheduled-cron data reaches the status line — not in Claude
  Code's Status JSON, and nothing daemon-side is reachable. Non-Goal.
- **Unused Status-input fields**: top-level `version`, `cwd`,
  `output_style`, `exceeds_200k_tokens`, `rate_limits.*`, `prompt_id`, plus
  nested `agent.*`/`pr.*`/`worktree.*`/`vim.*`. `rate_limits` + `version`
  are the highest-value unused fields.

## 08:20 · finding · — — cron data IS on disk (corrects earlier "no")

User pushed back on the flat "no cron data" answer — dogfooded it. Result:
the Status **input JSON** carries no cron data (confirmed), BUT the harness
persists self-wake / scheduled-task state on disk:

- `~/.claude/jobs/<daemonShort>/state.json` records
  `"inFlight": {"tasks": N, "kinds": ["session_cron"]}` and
  `"selfWake": true` for backgrounded/self-waking jobs.
- `CronList` is the live per-session API (returned "No scheduled jobs" for
  this session right now — nothing active to render).
- `~/.claude/jobs/<id>/pins.json` and per-session `~/.claude/tasks/` dirs
  also exist.

Implication: a status handler COULD surface a "⏰ N crons" indicator by
reading `~/.claude/jobs/*/state.json` (or a CronList-equivalent store) from
disk — it is feasible, not impossible. Reframed in PLAN.md from a hard
Non-Goal to a documented future enhancement.

## 08:22 · decision · P3/P4 — daemon_stats rollout: off-by-default for clients, ON here

User correction: dropping `daemon_stats` is NOT a per-repo tweak. Direction:

  upgrade prompt, so clients lose nothing by having `daemon_stats` off.

  `daemon_stats` stays ENABLED here (reverses the earlier "disable it in
  this repo" task).
- Upgrade messaging must **strongly recommend** client projects that have
  explicitly enabled `daemon_stats` turn it off now that the upgrade prompt
  is a separate handler. Needs a `config-changes/v{X.Y.Z}.yaml` entry
  (recommended) + post-upgrade guidance.
