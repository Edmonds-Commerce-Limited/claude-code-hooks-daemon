## Why the session's snapshot cannot be identified

- `utils/claude_config.py` locates the config dir (`claude_config_dir`, `session_config_dir` from the transcript path).
  Shell snapshots live in `<config dir>/shell-snapshots/snapshot-bash-<epoch ms>-<random>.sh`.
- The hook payload carries no snapshot name, and nothing inside a snapshot names a session. The directory on this host
  holds 38 snapshots dating back to October, accumulated across sessions. The daemon is long-lived and reads its own
  environment, so it has no key to choose one.
- All 38 here say `shopt -u globstar` and `shopt -u dotglob`. Unanimity of the files present is not proof about the
  running session's own snapshot (it may be absent, or the profile may have changed). Treating "all agree" as a pick is
  a judgement the brief reserves, so I did not make it.

## Why the consistency-only fix is blocked

`ProtectedFileIndex.glob_matches` (`utils/protected_file_index.py`): bare `**` is a recursive component and is judged;
`**/*` is "wildcard-only from its first component, depth >= 2" and is deliberately allowed (`_names_no_place`).
Existing tests pin that: `MISSES` in `tests/unit/utils/test_protected_file_index.py` line 55 includes `**/*` and `*`,
and line 307 parametrizes `**/*` as nameless.

- Make `**` consistent by allowing it: narrows coverage for `globstar` clients, which is (b).
- Make `**/*` consistent by denying it: contradicts the existing tests above, which I may not edit, and reintroduces
  the `ls */*/*` false positives the nameless rule exists to prevent.
