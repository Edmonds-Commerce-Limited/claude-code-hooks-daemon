# Task 3.1 - issue #146: redirection `&` voided the trusted-consumer exemption

## Diagnosis

Confirmed, with a correction to the reporter's pointer. The cause is not
`_COMMAND_SEGMENT_SEPARATORS` (line ~2595, used only by `effective_cwds`). It is
`_COMPOUND_MARKERS = ("&", "$(", "`")`in`is_exempt_invocation`: any literal `&`anywhere in the command voided the exemption, so the`&`of`2>&1`did.`\_COMMAND_SEPARATORS` (`&&`, `;`, ...) was not involved. The encrypted-target path uses `\_REDIRECTION_OPERATORS\` on shlex tokens; that works on tokens and
there was no shared string-level helper to reuse, so one small helper was added.

## Fix

`src/claude_code_hooks_daemon/utils/secret_file_matching.py`:
`_REDIRECTION_AMPERSAND = \d*>&|&>>?|\d*<&` and `_without_redirection_ampersands`,
used only for the `_COMPOUND_MARKERS` check. Only the operator is rewritten to a
plain `>`; the redirection TARGET stays a word and is still judged by the
flag-position check, so `&> P`, `>&P`, `> P`, `2> P` stay denied. A real
background `&` (`&`, trailing `&`) matches none of the forms and still voids it.
