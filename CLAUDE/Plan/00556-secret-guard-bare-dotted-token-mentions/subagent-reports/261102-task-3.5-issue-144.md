# Task 3.5: issue #144 (N559), compound command around a grep-pattern-only search

## Result

`is_grep_pattern_only_mention` (src/claude_code_hooks_daemon/utils/secret_file_matching.py) now judges a
compound command statement by statement. Exempt only when every statement is either a grep-family search
whose file targets are unprotected (same per-token judge as before), or carries no protected mention.

- Separators: `;`, `&&`, `||`. A pipe, a background `&` and a subshell still void the exemption.
- The expansion-character check stays whole-command (`p=<name>; cat $p` still fails closed).
- Redirects and `-f`/`--file`/`--exclude-from` values are judged exactly as before.
- Per-statement mention scan uses the statement's own text, not a re-quoted join (a first attempt using
  `shlex.join` quoted `>` and turned a redirect into a word; an existing #145 test caught it).
- The grep option parser was extracted unchanged into `_grep_file_target_words` (returns None where it
  used to return False).
- Deny message not touched, per the coordinator's ruling.

## Newline decision

An unquoted newline is treated as `;` for statement splitting, but only when the command has no `<<`
anywhere. Fail closed otherwise: any heredoc in a multi-line command, a newline inside quotes, `\r`, and
a backslash line continuation (backslash and `\r` stay in the expansion set). A newline right after
`;`, `&&` or `||` continues the line.
