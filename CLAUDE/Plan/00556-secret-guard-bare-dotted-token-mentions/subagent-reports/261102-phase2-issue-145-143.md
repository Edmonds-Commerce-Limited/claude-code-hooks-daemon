## Design I settled on (not yet implemented)

Gate placed in `iter_protected_mentions` (`src/claude_code_hooks_daemon/utils/secret_file_matching.py`,
around line 2061), applied to the pattern `_token_mention` returns, so both `find_protected_mention`
and the script-content route (`find_protected_mention_detail(context="content")`) get it.

A token is "bare dotted" when it has a `.` after position 0 and none of: `/`, `\`, `:`, glob chars
`*?[]{}`, and does not start with `.`, `~`, `$`. Anything else keeps today's behaviour. Dotless names
(`id_rsa`) are unchanged (denied); this is a deliberate narrowing of the "every other match is
allowed" wording, to avoid weakening exact-name patterns. Say so if the owner disagrees.

A bare dotted token still counts (is yielded) when ANY of these holds:

1. `os.path.lexists` for it under any of `effective_cwds`, the hook `cwd`, or the project root;
   or the protected-file index finds it (`index.glob_matches(token, cwds)`).
2. It does not appear literally in the command text (it came from brace or decode streams): fail closed.
3. Bash context, checked per occurrence on the raw text, fail closed on anything unclean:
   - the char before is not start/whitespace (or a quote matched by the same quote after it), or the char
     after is not end/whitespace/`;|&`, or the prefix since the last `;|&\n(`+backtick separator has an
     odd quote count (inside a quoted script) -> counts;
   - the prefix ends in a redirect operator (`<`, `>`, `>>`, `2>`) -> counts;
   - `shell_segmentation.segment_command_chain(prefix)` is `None`, empty (token is the command
     word) or any chain word's basename is in a closed file-opening list -> counts. List: cat tac nl
     less more head tail bat view vi vim nvim nano emacs ed cp mv ln install rsync scp dd tee source `.`
     bash sh zsh dash ksh python\* perl ruby node php lua awk gawk mawk sed grep egrep fgrep rg ag ack
     find xargs sort uniq cut paste join comm diff cmp wc od xxd hexdump strings base64 file stat
     *sum tar zip unzip gzip gunzip zcat bzip2 xz 7z curl wget jq yq openssl gpg ansible* ssh-add
     ssh-keygen touch rm chmod chown tr rev fold fmt split shuf truncate; `git` counts unless the first
     non-option word is `config`.
     Allowed otherwise (echo, nmcli, git config, ...).
4. Content context (`.py`, `.js`, ... non-shell): an occurrence adjacent to a quote char (before or after:
   `'`, `"`, backtick) is a string and counts UNLESS it is the whole first argument of a closed list of
   module-name APIs and is module-shaped (`^[A-Za-z_][A-Za-z0-9_.]*$`): `import_module`,
   `importlib.util.find_spec`/`find_spec`, `run_module`, `patch(...)` (not `patch.object`),
   `getLogger`. Regex on the text before the opening quote: `(?:\b(?:import_module|find_spec|run_module|patch|getLogger))\(\s*$`.
   An occurrence not adjacent to a quote is an attribute chain or prose and does not count.
   An authored `.py` carrying a setting-key string inside an argv list stays denied (fail closed);
   the authored-script test for #145 uses a `.sh` file.

Known residual risk of (b), to state in the release note: a nonexistent, unindexed file read by a
command that is not in the file-opening list (or created earlier in the same command line by a
command that is not in it) is now allowed. The alternative that stays closer to the guard's
"deny by default, not a list of bad readers" rule is a closed ALLOWLIST of non-opening commands
(`nmcli`, `echo`, `printf`, `git config`, ...); it is safer but allows fewer key consumers. Decide
before building if in doubt; the tests above pass under either.
