# Task 2.7: build log path and last result (report)

## Design

One new file, `untracked/.venv-bootstrap.result` (key=value: `result=succeeded|failed|timed-out`, `finished_at`, `exit`, `log`), written by every build path. It sits beside the existing `.venv-bootstrap.current` holder record and uses its format. It is not fingerprint-keyed, so the stop hook and `status` need no fingerprint to find it. The holder record gains `holder=`.

## Changes

- `scripts/install/venv.sh`: `venv_write_build_result`, `venv_record_build_outcome`, `venv_build_result_field`, `venv_build_log_path`. `acquire_venv_lock` now writes a holder record (`holder`, `pid`, `started`, optional `log`, no `bound` so waiters keep the generic bound). `release_venv_lock` removes it if still ours. `ensure_venv` (upgrade, install) records its result and names the fingerprint log.
- `scripts/venv_bootstrap.sh`: results from `_vb_build_under_lock` and `_vb_judge_stop` (succeeded, failed, timed-out). The hook record carries `holder=hook`. `probe` prints `holder=` while running and `last_result=`, `finished_at=`, `exit=`, `log=` while idle. Foreground `repair` (including `--rebuild`) holds the lock as `holder=repair`, truncates and tees into the same `<fp>.log`.
- `venv_lock.py`: `venv_lock(..., holder=, log=)`, `write_build_result`, `read_build_result`, `last_build_lines`, `build_log_path`. `cli.py`: `repair` holds as `repair` and `_repair_venv_locked` records its result and log (uv stderr appended); start-time cleanup holds as `cleanup`; `status` (not running) prints `Last venv build:` and `Build log:`.
- `init.sh`: `_hooks_daemon_last_build_note` (pure bash file read) appended to the plain "Hooks daemon not running" Stop block in the jq and python encoders, and in the embedded `emit_error_json` python (one file read, no subprocess).
