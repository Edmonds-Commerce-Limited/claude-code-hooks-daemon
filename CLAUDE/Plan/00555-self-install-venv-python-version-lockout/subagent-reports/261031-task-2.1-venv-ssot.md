## QA fixes

Merged origin/main into the Task 2.1 branch; targeted QA then failed. Causes and fixes:

- **The judge was wrong, not only the stub.** In `_vb_build_under_lock` (scripts/venv_bootstrap.sh) the realpath comparison sat inside `if build_rc -eq 0 && resolved="$(resolve_venv_python ...)"`. When the version-aware resolver refused the venv (drift), the condition was false, nothing set `build_rc=1`, and the drifted venv was certified as a success. That is the original Plan 00555 hazard, reopened. Fix: a resolver failure now sets `build_rc=1` explicitly; the realpath check runs only when something resolved.
- **The test stub no longer matched the contract.** Real `ensure_venv_locked` echoes the venv directory it built; the test stub returned nothing, so `built` was empty and the matching case failed on a path mismatch. The stub now echoes the built venv. The drifted case still fails for drift: the resolver returns nothing for it. Test intent is unchanged.
- **semgrep `pathlib-quadratic-containment`** (paths.py, `resolved.is_relative_to(Path(override))`): replaced with `_is_beneath`, a `parts`-prefix comparison. `utils.path_containment.path_is_relative_to` is the repo's usual fix, but paths.py runs standalone under a bare interpreter (`paths.py resolve-venv`) and cannot import the package; the first attempt broke the matching-venv test with ModuleNotFoundError, so the helper is local and stdlib-only.
