# Task 3.1 (second half): dev extras on self-install

## Detection

The scope report offered two ways to tell the cases apart. I used the layout rule from `bin/hooks-daemon:290-295`. `install_layout.is_self_install_mode` is keyed on the project root, and a client daemon dir also holds `src/claude_code_hooks_daemon`, so a marker test on the daemon dir would misclassify a client install.

- Bash: `create_venv_at_path` builds `extra_args=(--extra dev)` unless the daemon dir is `.claude/hooks-daemon`. The array is added to all three `uv sync --frozen` calls (first copy-mode attempt, first hardlink attempt, and the hardlink-failure retry).
- Python: `install_layout.is_client_daemon_dir(daemon_dir)` (new, stdlib-only). `_repair_venv_locked` runs `[uv, "sync", "--extra", "dev"]` on a self-install and `[uv, "sync"]` on a client.

## Fingerprint and metadata

- The fingerprint is `py{MM}` plus a hash of the path. The lock hash covers `uv.lock`, which already resolves every extra. Neither records extras, and no change is needed. A given daemon dir is always one layout, so extras never differ for the same fingerprint.
- Residual gap: an existing self-install venv built before this change is reused as-is and gets no dev extras until `bin/hooks-daemon repair` runs or the venv is rebuilt. Repair now adds them. Whether to force a rebuild is a coordinator decision, and I made no change for it.
