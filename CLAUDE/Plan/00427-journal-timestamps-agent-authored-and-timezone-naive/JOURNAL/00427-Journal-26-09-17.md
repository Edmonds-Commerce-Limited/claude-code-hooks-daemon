## 09:38 · finding · — — the reported mechanism is not the implemented one

Issue #45 states the check "judges each writer against that writer's own
clock", so both writers pass. The check runs in `PlanQaEditHandler`, a
`PreToolUse` handler — it executes in the DAEMON process. One clock judges
every writer.

Measured against the real check with a one-hour offset:

```
tolerance = 30 min, future direction only

daemon UTC  vs agent BST (10:35): ahead=+59min  fires=True
daemon UTC  vs agent UTC (09:35): ahead=-1min   fires=False
daemon BST  vs agent BST (10:35): ahead=-1min   fires=False
daemon BST  vs agent UTC (09:35): ahead=-61min  fires=False
```

The consequence the reporter cares about survives — an agent BEHIND the daemon
is silent and its entry lands out of order — but via a different route, and
there is a second symptom they did not report: an agent AHEAD of the daemon is
flagged for a timestamp that is correct in its own zone.

This matters for remedy selection. "The check is blind" invites fixing the
check; "the check is blind in one direction because the entry and the clock are
in different zones and nothing records which" points at the grammar.

The reporter's own fixture reproduces exactly as described — 59.99 minutes
apart for a single instant.
