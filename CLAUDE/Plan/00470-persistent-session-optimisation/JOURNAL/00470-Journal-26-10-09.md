> **Append-only activity log** for plan 00470. One file per day
> (`00470-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM, ONLY with
> `mkplan.bash --journal <plan-number> <category> <body-file>` (it stamps the
> real UTC time; a hand-written entry is denied); NEVER edit earlier entries
> (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff` | `correction`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - A `correction` corrects an earlier entry without touching it. Its `REF`
>   (`--ref`, required) names that entry: `HH:MM` in this file, or
>   `YY-MM-DD/HH:MM` in an earlier one. An entry a correction names in this
>   file no longer counts for time order, so a future-dated stamp can be
>   corrected at the honest time.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 06:54 · action · —   — Task 6.4: initial thread only holds declared crons

Task 6.4 implemented: only the initial thread of a Claude Code session holds the declared persistent_crons.

Findings that shaped it:

- The daemon CAN learn the calling pid on the event-socket (relay) path: `SO_PEERCRED` is already queried for the hostname override, so `_stamp_peer_pid` stamps `hooks_daemon_peer_pid` on the payload. The legacy `init.sh` envelope socket path parses its request inside `_process_request` with no per-connection stamp, so it carries no pid and keeps today's behaviour (every session holds the crons). `init.sh` itself was not changed.
- The walk is lazy: the server stamps only the pid; the handlers walk `/proc/<pid>/stat` and `cmdline` only when a project has active declared jobs and the option is on. Bounded to 32 hops and 0.25 s, no shell, no signal.
- Group key is the `claude daemon run --spawned-by` ancestor pid plus its start time (stat field 22), persisted in `session-thread-groups.json` under the daemon untracked dir; the first session id claims the group, the map is capped at 256 groups. A corrupt or unwritable map means the caller holds the crons.
- Shared gate: `handlers/utils/initial_thread_exemption.py` (mixin) used by the assertor, the Stop enforcer and the SubagentStop twin. Not changed: `failsafe_cron_session_advisor`, `recovery_cron_advisor` and `background_process_tracker` only read whether a job is declared, to stand an advisory down, so a later thread is not asked for a cron there either. Open: `usage_pause_gate`'s lift directive still lists the declared jobs for any thread whose own pause ends, so a paused later thread would be told to re-create them.

## 07:12 · action · —   — Task 6.4 review r1: holder by worker shape and liveness

Review round 1 of Task 6.4 changed the holder rule. The first version held the crons in "the first session_id seen per group" with no liveness check. Two failures followed: a holder that exited left every remaining thread exempt, and the new thread's SessionStart (the first event to see a `claude daemon run` at all) could claim the group before the initial thread's next hook.

Now the holder is chosen by worker shape: `--fork-session --resume` is the initial thread, `--bg-spare` a later one, anything else holds. The registry stores the holder's worker (pid plus start time) and a claimant takes over when that process is gone or is another process on a reused pid. A spare that arrives with no live recorded holder scans `/proc` (bounded) for the group's live initial worker before deciding. The hook pid is read from `SO_PEERCRED` on both sockets and any caller-supplied value is dropped. `usage_pause_gate`'s lift directive now lists jobs only to a holder. Rulings came from the coordinator's review reply; the probe at untracked/scratch/review-6.4 prints FIXED for all three cases.
