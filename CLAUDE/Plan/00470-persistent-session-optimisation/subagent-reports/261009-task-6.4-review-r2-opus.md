## Fail-safe direction (checked path by path in `resolve`)

An exemption is returned only in two cases:

- a recorded holder worker is **live** (same pid AND start time) and is not this
  worker; or
- a scan that finished within budget **found** a live INITIAL-shaped worker whose
  own walk lands in the same group.

Every other path holds the crons: no pid, no session id, no transient-daemon
ancestor, no recognised worker (`worker is None`), unreadable `/proc`, scan UNSURE
(over `MAX_SCAN_ENTRIES` or past the deadline), corrupt registry, or unwritable
registry. An unreadable holder `/proc` entry reads as dead, which leads to takeover.
So the failure direction is "two threads hold" (duplicates), never "none hold".

I found no path that exempts a live session while no live thread holds.

## Boundedness

- The walk is unchanged: 32 hops, 0.25 s, stops at pid <= 1.
- The scan runs only for a SPARE with no live recorded holder. It returns UNSURE
  before reading anything when `/proc` has more than 4096 pids, and checks the
  deadline before every candidate.
- Each INITIAL-shaped candidate starts a nested walk with its own 32-hop / 0.25 s
  bound. So one scan is bounded at roughly the scan budget plus one walk.
- A FOUND or ABSENT outcome is recorded, so it is not repeated. UNSURE is not
  recorded, so a spare in that state rescans on each of its cron-handler events.
  That is still bounded per event and fails toward holding.
- Everything runs under `_registry_lock`, so concurrent claimants are serialised.
- No shell, no signals. `/proc` is read only (`stat`, `cmdline`, directory listing).

## Residual (not a finding; recorded for the plan)

The timing of the initial thread's move into a worker is not established by the
Task 6.3 probe. If the new thread's first hook arrives before the initial thread's
`--fork-session --resume` worker exists, the scan returns ABSENT and the spare takes
over. The initial thread is then exempt while it lives (`probe_r2.py`
`migration-lag`). This is the duplicate direction, not loss: the spare is
demanded at Stop.

A cheap hardening, if a live probe ever shows this happening: let an INITIAL-shaped
claimant displace a live SPARE holder that took over through the ABSENT branch.
That needs a `took_over` flag on `_Holder`. It is not needed to ship.
