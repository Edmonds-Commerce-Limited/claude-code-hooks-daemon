# Task 6.4 report: only the initial thread holds the declared crons

Revised after review round 1 ([review](261009-task-6.4-review-r1-opus.md)).

## Which pid the daemon can learn

The daemon learns the calling pid from `SO_PEERCRED` on BOTH sockets. `_peer_pid` is queried once per connection; the event-socket path stamps `hooks_daemon_peer_pid` (and the hostname) from that one query, and `_handle_client` passes the same result to `_process_request(peer=...)` on the legacy `init.sh` socket. Whatever pid a payload carries is dropped first (`_set_peer_pid`), so only the kernel's value is ever stamped; an unknown or non-positive pid stamps nothing and the session holds. `init.sh` itself is unchanged.

## What was built

- `utils/session_thread_group.py`: `find_thread_placement` walks `/proc/<pid>/stat` and `cmdline` (32 hops, 0.25 s, no shell, never signals) to the `claude daemon run --origin transient --spawned-by {"pid": N}` ancestor, noting the nearest worker: `--fork-session` plus `--resume` is the initial thread, `--bg-spare` a later one, anything else unknown (holds). `ThreadGroupRegistry.resolve` stores the holder as its worker (pid plus start time) per group (pid plus start time). Rules: the recorded holder is live and is this worker means hold (a new `session_id`, as after `/clear`, is just recorded); live and another worker means exempt; no live holder and the claimant is the initial worker means it becomes the holder; no live holder and the claimant is a spare means a bounded `/proc` scan for a live initial worker of the group (found: record it, exempt; none: the spare takes over, logged; cannot finish: hold). Holder choice never depends on arrival order. A corrupt registry warns once per path and then logs at debug; an unwritable one records nothing.
- `handlers/utils/initial_thread_exemption.py`: mixin used by `persistent_cron_assertor`, `cron_stop_enforcer`, `cron_subagent_stop_enforcer` and `usage_pause_gate` (its lift directive now lists the declared jobs only to a holder). One `_jobs_held_by_session` method; the verdict for a payload is kept for 2 s so a Stop's `matches` then `handle` walk `/proc` once.
- `persistent_crons.initial_thread_only` (strict bool, default true).
- Docs: yaml example and this repo's config, handler guidance, `IssueSdlc.md`, release note `004-...`, `v3.70.0.yaml` entry, `INPUT-ALLOWLIST.yaml`. The first-seen wording is gone from all of them.
