## 3. Proposed rotations (smallest set, reuse existing helpers)

All defaults below are proposals. I changed no files.

1. **Claude Code transcripts and subagents (ranks 1 and 2).**
   - These are outside the repo's write paths and the biggest number.
   - Smallest fix: a new `daemon.claude_transcript_retention_days` option, default 30. It would call `prune_subdirectories` on `~/.claude/projects/<slug>/<session>/subagents` and `.../tool-results`, plus `prune_directory(pattern="*.jsonl")`, with `protect=` set to the live session id, and write nothing for the current session.
   - Hook point: the `_SESSION_RUNTIME_DIR_SUBDIRS` loop at `daemon/paths.py:2466-2468`, or a sibling called from `cli.py:580`.
   - The option field goes next to `stale_file_days` at `config/models.py:1985`.
   - Caveat: this deletes data the user may want for `/resume`. Ship it default-off (0) or at 30 days and have a human decide.
   - The main `.jsonl` of a never-ending persistent session has no safe rotation point, since the session is still using the file.
2. **`qa-interpreters/` (rank 3, 1.0 GB).**
   - Add `prune_subdirectories(EXTRA_VENVS_DIR, max_age_seconds=14*86400, now=...)` after the interpreter matrix is built, at `scripts/qa/run_test_matrix.py:92`.
   - Option name: `qa.interpreter_retention_days`, default 14.
   - Only two dirs (`py3.12` and `py3.13`) exist, so it can instead be a documented `rm -rf` on demand. The reaper must skip an interpreter in use by a running matrix.
3. **`scratch/` (rank 4, 329 MB).**
   - Add `"scratch"` to `_SESSION_RUNTIME_DIR_SUBDIRS` at `daemon/paths.py:2416`. That is one tuple entry, and `prune_subdirectories` is already imported there.
   - Add a sibling `prune_directory(scratch, pattern="*", ...)` for the loose top-level files.
   - Option: `daemon.scratch_retention_days`, default 14, next to `stale_file_days` at `config/models.py:1985`. Use a separate value from the 7-day default so work in progress is not reaped. The directory mtime tracks the last child write only at depth 1, so a deep, active tree can look old. Test this before shipping.
4. **`supervise/decision.log` (rank 9).**
   - Wrap its writer in the ccy supervisor with `cap_log_file(path, max_bytes=1 MiB)`. The writer is not in this repo, so the hook point is wherever the supervisor appends. In this repo, `cli.py:3077` and `:3169-3170` should be corrected, or the cap added at daemon start with a one-line call from `_reap_stale_runtime_files` at `cli.py:566-583`.
   - Option: `daemon.decision_log_max_bytes`, default 1 MiB.
5. **`events-<hash>/` dirs and `refs/integration/changed-green/*`.**
   - The events dirs need the 7-day `daemon-` prefix sweep extended. Change the prefix check at `paths.py:2358` to also remove `events-*` dirs whose `daemon-<hash>.pid` is dead or missing.
   - The refs need `git for-each-ref refs/integration | git update-ref -d` for entries older than N days, in `scripts/qa/llm_qa.py` next to `:2059`. Option: `qa.changed_green_ref_days`, default 14.

## 4. Verification and caveats

- Sizes and counts come from `du -k --max-depth=1` and `find -printf '%T... %s'`. No transcript contents were opened. No find or du was run from `/` or `~` root, all were scoped to `~/.claude/projects/-workspace`, `/tmp/claude-0` and `/workspace`.
- The scratch spike on 10-02 (32,846 files, 187 MB) is a single copied tree, not a trend.
- The `daemon-*` pid and sock files are not all stale-safe: some are mtime-fresh because the live daemon touches them.
- Side effect: during this investigation I created five temp measurement files under `untracked/scratch/`: `g-du.txt`, `g-du-s.txt`, `g-du2.txt`, `g-du3.txt`, `g-du4.txt` (a few KB each). I did not delete them, per the instruction to delete nothing. Please remove them. They are gitignored.
- I did not check: whether `prune-venvs --stale` would reclaim anything now, the `hook-errors.log` rotation in practice, the transcript growth rate of sessions older than 3 days beyond the mtime histogram, and whether Claude Code itself has a `cleanupPeriodDays` setting that already reaps `~/.claude/projects`. That last one should be checked first before building rank-1/2 retention.
