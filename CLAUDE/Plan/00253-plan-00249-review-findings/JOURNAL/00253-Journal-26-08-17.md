## 18:20 · finding · P1 — I established git's rule by running it, before asserting it

The fix hinges on which ref `git branch -d` measures against, and the review and
the old code disagreed about it. Rather than pick a side from prose, I ran all
three cases:

```
CASE 1  upstream LEVEL with branch, HEAD elsewhere  -> -d exit 0 ("has been merged to")
CASE 2  no upstream, DETACHED HEAD not containing it -> -d exit 1 ("not fully merged")
CASE 3  no upstream, HEAD on main (common case)      -> -d exit 0
```

So the rule is exclusive, not preferential: **an upstream that resolves is used
alone** and HEAD becomes irrelevant (CASE 1 deletes a branch absent from HEAD),
and with no upstream **HEAD is the sole reference, detached or not** (CASE 2).

That third case mattered more than expected. `HEAD` resolves to a commit whether
or not it is symbolic, so one `merge-base --is-ancestor <name> HEAD` covers both
— no `symbolic-ref` special case, which is what I would have written from the
prose. There is a test pinning it, because "one expression covers both" is
exactly the sort of claim that quietly stops being true.

## 18:58 · decision · T4.1 — keep the root, and write down the trade

Finding E is really two questions, and only the first has an obvious answer. The
comment was wrong — `git -C <dir>` absolutely does select repo-local config, and
`ls-remote` reads `insteadOf`, `http.proxy`, `http.sslCAInfo` and `credential.*`
from it. So "which directory it runs in is immaterial" had to go.

The second question is whether to keep `/`. I kept it, and recorded WHY in the
comment instead of leaving the reader to re-derive it:

- The URL is fixed and known-external — this project's own GitHub repo.
- A client's repo-local `insteadOf` is almost always aimed at THEIR dependencies,
  so honouring it is about as likely to redirect this check to a mirror that has
  no such repository as it is to help.
- Proxy and CA settings that genuinely need to apply are conventionally global or
  system, and `git -C /` still reads both.
- The cost is bounded and fails safe: a project whose repo-local config really is
  load-bearing for github.com gets NO upgrade advisory, rather than a wrong one.

Renamed the constant to `_REMOTE_ONLY_CWD`, because `_CWD_IMMATERIAL` encoded the
false claim in the identifier where the next reader would trust it.
