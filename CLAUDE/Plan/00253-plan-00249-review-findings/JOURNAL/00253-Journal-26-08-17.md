## 18:20 · finding · P1 — I established git's rule by running it, before asserting it

The fix hinges on which ref `git branch -d` measures against, and the review and
the old code disagreed about it. Rather than pick a side from prose, I ran all
three cases:

```
CASE 1  upstream LEVEL with branch, HEAD elsewhere  -> -d exit 0 ("has been merged to")
CASE 2  no upstream, DETACHED HEAD not containing it -> -d exit 1 ("not fully merged")
CASE 3  no upstream, HEAD on main (common case)      -> -d exit 0
```

So the rule is exclusive, not preferential: **an upstream that resolves is used
alone** and HEAD becomes irrelevant (CASE 1 deletes a branch absent from HEAD),
and with no upstream **HEAD is the sole reference, detached or not** (CASE 2).

That third case mattered more than expected. `HEAD` resolves to a commit whether
or not it is symbolic, so one `merge-base --is-ancestor <name> HEAD` covers both
— no `symbolic-ref` special case, which is what I would have written from the
prose. There is a test pinning it, because "one expression covers both" is
exactly the sort of claim that quietly stops being true.

## 18:24 · decision · T1.3 — a third tier, not a widened second one

`merged-unpushed` already means "safe by our proof, but git's own safe delete
refuses it", which is true of the new case too. Reusing it would have been one
line.

Rejected. Its DETAIL tells the reader the branch is ahead of its upstream and to
push those commits — and in the new case there is no upstream to push to. A tier
whose name and text misdescribe the refusal is the same defect class this whole
plan is about; fixing a wrong promise by substituting a wrong explanation is not
progress. Added `TIER_MERGED_NOT_IN_HEAD`, which costs a constant, a detail
string and an `is_safe` entry — `delete_argv_for_tier` needed no change, since
force-delete is already its default for everything but plain `merged`.

Also extracted `_safe_delete_reference`, returning the REF rather than a boolean.
The old `_is_merged_into_its_upstream` answered a yes/no question that was not
git's question; returning the reference puts the exclusive choice in one place and
lets the caller name the right refusal reason from it.
