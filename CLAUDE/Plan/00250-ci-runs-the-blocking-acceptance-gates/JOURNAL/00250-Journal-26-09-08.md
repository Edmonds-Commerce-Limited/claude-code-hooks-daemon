## 04:07 · decision · T2.4 — recorded here rather than filed as a new plan

The dedupe scout checked 40 live plans and said "proceed — the overlap is
superficial", naming this plan and 00252 as adjacent. I read this plan before
accepting that, and disagreed with it.

The scout's distinction was "00250 provides the daemon; the new work removes
environment-specificity". True as far as it goes, but it under-weights that
**two of the three failing files fail for exactly the dependency this plan
exists to provision**. Filing alongside would have produced a plan whose Phase 2
duplicated this one's Phase 2, and the two would have had to be reconciled by
whoever picked up the second.

So: added as Task 2.4 here, with the premise correction above, rather than as
Plan 00349. The separable part (the hardcoded path) is called out as separable
inside the task, so it can be fixed without waiting for the daemon work.

**One trap written into the task explicitly**: do not resolve these by adding a
skip guard. It would turn CI green immediately and convert three loud failures
into three silent skips — the exact defect this plan was created to remove. A
red gate is bad; an invisible one is worse.
