## 17:05 · finding · — — the bug found me, mid-commit

I was writing the commit that records Plan 00234's Cohort H findings.
`enforce_llm_qa` DENIED it, because the message mentions the script that handler
guards.

That is not the intentional commit-message false positive `CLAUDE.md` describes.
This handler has a VCS allowlist specifically so git metadata is never read as
an invocation, and its docstring records repairing that allowlist once already
(the whole-string `startswith("git ")` test that lost the exemption on
`cd /workspace; git commit -m ...`).

Verified the mechanism against the live handler rather than reasoning about it —
`-m` single-quoted: allowed; `cd && git commit -m`: allowed; `-F - <<'EOF'`:
**DENIED**; real invocation: denied (correct); `cat` of the script: allowed
(correct). Segment split of the failing case: `[0] git`, `[1] Subject`,
`[2] prose`, `[3] EOF`. Segment 2 carries the script name with the English word
`prose` as its leading word.

Root cause: `_SEGMENT_SEPARATORS` includes a newline, so a quoted heredoc body
is chopped into pseudo-commands.

## 17:20 · decision · P1 — lift the rule, do not copy it

`pipe_blocker` already had this exact rule as a private module constant. Three
ways to fix: import its private name, copy the regex, or lift it into
`utils/shell_segmentation.py`.

Lifting it is the only one consistent with why that module exists. Its own
docstring opens with two handlers that grew separate scanners and got opposite
halves of the backslash rule — and it *already warns about this precise heredoc
failure*: "newlines are segment separators, so the 'command' before a pipe in
the body resolves to a line of English prose." That warning was written for
`value_can_substitute`, which only covers the `"$(cat <<'EOF' …)"` argument-value
shape. The plain `cmd <<'EOF'` shape was never covered. The warning was right and
the coverage was incomplete.

So this is the third instance of the same meta-bug: two handlers disagreeing
about bash. Copying the regex would have made it the fourth.
