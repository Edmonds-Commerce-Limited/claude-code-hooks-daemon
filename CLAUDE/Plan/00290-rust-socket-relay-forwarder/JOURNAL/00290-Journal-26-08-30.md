deployed forwarder is byte-identical to today; distribution via release
`SHA256SUMS` + plain-`rustc` build-from-source (no cargo, no crates).

## 09:38 · action · P3 — Phase 3 delivered: relay binary, tests, build script

(Container clock reads 09:38 UTC while earlier entries say 10:18 — the agents
have skewed clocks; this entry is appended after them in real order.)

Tasks 3.1–3.3 shipped by the Phase 3 agent:

- `relay/hooks_relay.rs` (~290 lines): std-only, zero crates, no cargo.
  Connects BEFORE reading stdin; on any connect failure execs
  `/bin/bash <fallback> --no-relay` with stdin intact; after connect it is a
  pure byte pump (stdin → socket, `shutdown(SHUT_WR)` as EOF framing,
  response buffered then copied to stdout). One timeout budget spans the
  whole exchange (connect via helper thread + `recv_timeout`, since std's
  `UnixStream::connect` has no timeout; per-op `SO_RCVTIMEO`/`SO_SNDTIMEO`
  armed with the shrinking remainder). Mid-exchange failures emit fail-open
  `{}` + exit 0; diagnostic exit codes 10/11/12 (connect/timeout/IO+oversize)
  only without a fallback / with `--no-fallback`, per design §3.1. Response
  capped at 16 MiB (mirrors `SocketLimit.REQUEST_BUFFER_BYTES`).
- `relay/test_relay.py`: stub Unix-socket server speaking the EOF framing;
  9 cases — happy path, daemon-absent → fallback exec (argv `--no-relay` and
  stdin integrity asserted), connect-fail diagnostic exit 10, timeout →
  `{}`/exit 11, mid-exchange disconnect (4 MiB payload → EPIPE) → `{}`/exit
  12, 2 MiB payload+response round-trip (sha256-verified), oversized
  (16 MiB+1) response → exit 12. **9/9 pass** against the built binary.
- `relay/build.sh`: plain `rustc --edition 2021 -O -C strip=symbols
  -D warnings --target x86_64-unknown-linux-musl` + `strip`, asserts no ELF
  interpreter (static), prints size + sha256. **Built: 570,056 bytes
  stripped** (under the 1 MB ceiling; sha256 f6484c23eb2d…). Output stays in
  git-ignored `untracked/relay-build/` — no binary committed.

## 11:20 · action · P2 — Phase 2 delivered: multi-socket listener + hygiene

Tasks 2.1–2.2 shipped (TDD, tests-first):

- `config/models.py`: new `TransportConfig` (`extra="forbid"`) with
  `relay_enabled`/`nc_enabled`/`timeout_seconds`/`relay_binary` exactly per
  design §4, plus a `per_event_sockets_needed` property; attached to
  `DaemonConfig.transport`. Defaults verified byte-identical (13 tests,
  `tests/unit/config/test_transport_config.py`).
- `daemon/paths.py`: `get_event_socket_dir_from_untracked`,
  `get_event_socket_dir(project_dir)`, `get_event_socket_path_in_dir`,
  `get_event_socket_path(project_dir, event_file_name)` — mirrors
  `get_socket_path`'s hostname-suffix + `_UNIX_SOCKET_PATH_LIMIT` fallback
  (returns `None` when even the events dir would overflow, per §1.1). 8
  tests (`tests/unit/daemon/test_event_socket_paths.py`).
- `daemon/server.py`: `HooksDaemon._bind_event_sockets()` (called from
  `start()` right after the legacy socket is chmod'ed, so a start that loses
  the reuse race never reaches it), gated on
  `transport.relay_enabled or nc_enabled`; wholesale-removes a pre-existing
  `events{suffix}/` dir, then binds one `asyncio.start_unix_server` per
  `wired_event_metas()` entry via `functools.partial(self._handle_event_client,
  meta.json_key)` — best-effort per socket (an `OSError` on one bind logs
  ERROR and continues, matching §1.2). `_handle_event_client` implements the
  EOF framing from design §2: reads to EOF via a new bounded
  `_read_event_payload` helper (asyncio's `read(-1)` doesn't honour the
  stream `limit` the way `readline` does, so the cap is enforced by hand at
  `SocketLimit.REQUEST_BUFFER_BYTES`), parses the raw hook payload, synthesises
  `{"event": <json_key from listener identity>, "hook_input": ...}` and
  dispatches through the SAME `_process_request` the legacy socket uses — no
  new dispatch path. Malformed/oversized payloads and any handling exception
  fail open with `{}` (never leave Claude Code without valid JSON). `shutdown()`
  now closes every per-event server and `shutil.rmtree`s the whole events dir
  (unlinking each socket individually would be redundant once the directory
  is gone). Legacy socket protocol byte-for-byte untouched — verified by a
  dedicated test connecting to both sockets in the same run. 7 tests
  (`tests/unit/daemon/test_event_socket_listeners.py`), real asyncio Unix
  sockets, no mocking of the framing/dispatch path.
- `daemon/cli.py`: `cmd_status` now prints
  `Per-event listeners: N active (<dir>)` (or a "transport enabled but events
  dir not found" line) when `daemon.transport` has a rung enabled; silent
  (byte-identical to today) when disabled. 3 tests
  (`tests/unit/daemon/test_cli_status_event_listeners.py`). `cmd_health`
  (the `_system`/`health` socket query) was left untouched — enriching it
  would mean threading transport state through `DaemonController.get_health`,
  a larger change than Task 2.2 scoped; flagging for Phase 6 or a follow-up
  if the health JSON payload needs the same visibility, not just the human
  CLI table.
