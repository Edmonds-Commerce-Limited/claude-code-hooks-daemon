The report frames it as a substring accident: the monorepo path
`…/apps/app/qaConfig/…` "contains the substring `/app/`", with the suggested
remedy being to make the match segment-exact so it stops firing inside
`apps/app/`. Executed against the real code:

```

   True  /workspace/apps/app/qaConfig/PHPStan/Rules/Foo.php

  False  /workspace/application/foo.php
  False  /workspace/happ/foo.php

  should_skip         : False

`matches_directory` normalises each pattern to leading AND trailing `/`

**correct** match on a directory genuinely named `app`.

So the suggested remedy would change nothing, because `app` already IS an exact
segment. The real defect is a scoping gap — no notion that a QA-tooling dir
inside a source root is not application source — and the fix for finding C
resolves it without touching a heuristic other PHP projects rely on. Recorded as
Non-Goal and Decision 1 so this is not re-litigated later.

This is the second time this week that verifying a report before acting on it
changed the fix rather than merely confirming it. Worth the ten minutes every
time.

## 15:20 · finding · P1 — the real root cause was an annotation that lied

Phase 1 was scoped as "extract the duplicated `_is_excluded`". Investigating why
it needed extracting found something better underneath.

Every copy carried `getattr(self, "_project_exclude_paths", None)`. That defence
exists because `core/handler.py` puts both registry-injected names in
`__slots__` (line 50-61) and annotates them `list[str] | None` (63-64) — but
`__init__` **assigns neither**. With `__slots__` an annotation creates the slot
and leaves it UNSET, so plain attribute access raises `AttributeError` on any
handler constructed outside the registry, which is every handler in a unit test.
`handlers/registry.py:364` injects it in production only.

So the annotation was the defect: it promised an attribute that is always
present. Measured the cost before fixing: **14 call sites across 9 modules**,
including `tdd_enforcement` itself (it already uses the idiom for
`_project_languages`).

Fixed by assigning both to `None` in `__init__`. RED first — two
`AttributeError`s — plus a third test pinning that the registry can still
overwrite them, because three handler test modules set them directly to simulate
project config and that had to keep working.

## 15:24 · decision · T1.2 — one script, not twelve Edits

files, and they must change TOGETHER: change the body first and the three
imports become unused (`F401`); change the imports first and the body references

## 15:52 · finding · T2.2 — the exclusion check goes BEFORE the strategy lookup

Both handlers resolve a language strategy from the file extension before doing
anything else, so the obvious placement for the new short-circuit was after it.
That would be wrong, and the reason is worth recording because it will look like
an arbitrary ordering choice to the next reader.

An `exclude_paths` entry is the **project** saying "this path is out of scope".
A strategy lookup is the **daemon** saying "I know how to reason about this
extension". The first outranks the second: if a project excludes
`**/vendor/**`, that must hold for a `.php` file (strategy exists) and for a
`.foo` file (none does) alike. Placing the check after the lookup would make an
exclusion silently conditional on upstream having a strategy for the extension —
a coupling with no defensible meaning.

In `lint_on_edit` it also lands before the `Path(file_path).exists()` stat,
which is a small bonus: an excluded path costs no syscall.

## 15:54 · finding · T2.3 — my test premise was wrong, not the code

Wrote the `lint_on_edit` exclusion tests with fictional paths, as in the
`tdd_enforcement` suite. The two control tests — the ones asserting a
NON-excluded path still matches — failed.

The code was right. `lint_on_edit.matches()` ends in `Path(file_path).exists()`
(line 104), because PostToolUse runs AFTER the write: a path that does not exist
cannot have just been written. So a fictional path can never match, and a test
built on one would have "passed" for entirely the wrong reason — the exclusion
assertions would have held whether or not the feature existed.

Fixed by giving the module a `_real_file(tmp_path, *parts)` helper that creates
the file on disk, and documenting why in the class docstring so nobody
"simplifies" it back. This is the second time this session that a control test
caught a fixture that would have made a feature test vacuous.

## 16:22 · decision · T3.2 — `test_dir` anchoring: I rejected the elegant option

Spent real time on this because the report's own example encodes a different
answer than the one I shipped, and a future reader will notice.

The report writes `test_dir: "qaConfig/Tests"` while the real directory is
`apps/app/qaConfig/Tests`. So its example is a **suffix**, resolvable by walking
up from the source file to the nearest ancestor named `qaConfig` and joining
there. That form is genuinely nicer for the reporter: one entry covers every app
in the monorepo.

I rejected it. It needs a second rule for the case where `test_dir`'s first
segment names no ancestor (`test_dir: "Tests"` under
`qaConfig/PHPStan/Rules/`) — and once a value's meaning depends on the shape of
the tree, the declaration has stopped being a declaration. Project-root-relative
is one rule, matches the anchoring a project already learned from `exclude_paths`
globs, and a typo surfaces in the deny message's searched-locations list, which
is the one place the author is already reading. The suffix form remains
addable later as a new spelling rather than a changed meaning.

Recorded as Decision 4 so the report's example is not mistaken for a spec I
failed to implement.

## 16:26 · decision · T3.2 — `test_locations` is a list of guesses; this is a fact

Task 3.2 required designing this against `_effective_test_locations` rather than
beside it, which reads at first like "add a fourth style token, `mapped`".

That is wrong, and naming why was the useful part: `test_locations` selects WHICH
of three built-in INFERENCE styles to attempt, whereas `test_path_map` is the
project asserting a FACT about its own tree. Putting a fact in a list of guesses
would make a project opt in twice, and would mean narrowing to
`test_locations: ["collocated"]` silently discarded the project's own declared
test root. So declared candidates are added unconditionally, and FIRST.

There is a test pinning exactly that (`test_a_declaration_is_not_gated_by_test_locations`),
because this is the kind of coupling a later "tidy-up" reintroduces by accident.
