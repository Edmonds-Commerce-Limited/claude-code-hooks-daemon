## 18:38 · decision · N16 — the remedy is deliberately NOT symmetric

Recorded the asymmetry in the entry rather than proposing "do what the failsafe
cron does". The failsafe backoff reads purely LOCAL state, so it decides at
`UserPromptSubmit` for zero tokens. Issue eligibility is REMOTE state, and a
handler that queried GitHub on the prompt path would be a worse trade than the
one `cron_cadence` makes.

Costing it against the failsafe implementation would repeat N15's error
exactly — that entry closed with "neither listed remedy as written (both were
costed against the wrong surface)". Naming the difference up front is the whole
value of the entry.

Cheapest remedy carried into Task 4.3: have the AGENT write a consecutive-no-op
marker at the moment it concludes "no eligible issue", reusing the
`[awaiting-human]` marker mechanism, so the suppressor can back off on local
state alone.

**Accepting the current cost is an explicitly valid outcome.** The defect is
that the asymmetry exists by omission rather than by decision — not that the
hourly cadence is wrong. Neither cron should be deleted; both runbooks say so.
