Established which steps actually apply the filter rather than guessing — the
whole point of the entry. `_venv_slug_eligible` has three call sites:

| line | function                                       | step                    |
| ---- | ---------------------------------------------- | ----------------------- |
| 836  | `resolve_existing_venv_python`                 | its scan fallback (3)   |
| 943  | `resolve_existing_venv_python_with_diagnostics` | metadata (2)            |
| 1037 | `resolve_existing_venv_python_with_diagnostics` | scan fallback (4)       |

two that glob `venv-*` rather than naming one path. Steps 1, 3 and 5 do not,
correctly: an explicit override, an exact fingerprint-keyed path, and the

qualified: usable for THIS view of the project.

mode rather than a version, so a future editor does not quietly drop it again.
