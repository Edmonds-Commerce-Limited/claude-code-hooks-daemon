## 10:54 · finding · N2 — the recorded remedy was a no-op as written

N2's remedy (1) says to add `untracked/` to `exclude_paths`. Doing exactly that
and restarting changed nothing: the same scratch file was still denied under
`R-LINT-FAILURE`.

`_glob_to_regex` full-matches, so `untracked/` becomes `(?:.*/)?untracked/`,
which matches the directory path and never a file inside it:

```
'untracked/'       -> False
'untracked/**'     -> True
'/untracked/**'    -> True
'untracked'        -> False
```

This is the failure mode worth naming: the config edit LOOKS like the recorded
remedy, the daemon accepts it, nothing errors, and the guard carries on firing.
Had I written the line and moved on, N2 would have been marked resolved while
staying broken.

## 10:56 · action · N2 — resolved, verified in both directions

Shipped `/untracked/**` under `lint_on_edit.options.exclude_paths` — `**` to
reach the files, leading `/` to anchor at the repo root. Scoped to the handler
rather than `daemon.exclude_paths`, which would have exempted the directory
from every guard including `sensitive_content`.

Proved by writing, not by reasoning: the identical lint-failing bytes that were
denied twice were accepted after the restart. Opposite direction checked too —
`src/**`, `tests/**`, `CLAUDE/**` and a nested `sub/untracked/**` all still
lint, so the exclusion did not leak.
