## 10:54 · finding · N2 — the recorded remedy was a no-op as written

N2's remedy (1) says to add `untracked/` to `exclude_paths`. Doing exactly that
and restarting changed nothing: the same scratch file was still denied under
`R-LINT-FAILURE`.

`_glob_to_regex` full-matches, so `untracked/` becomes `(?:.*/)?untracked/`,
which matches the directory path and never a file inside it:

```
'untracked/'       -> False
'untracked/**'     -> True
'/untracked/**'    -> True
'untracked'        -> False
```

This is the failure mode worth naming: the config edit LOOKS like the recorded
remedy, the daemon accepts it, nothing errors, and the guard carries on firing.
Had I written the line and moved on, N2 would have been marked resolved while
staying broken.

## 10:58 · finding · N3 — the nominated regression file fails the entry's own premise

N3 reads as a clean un-gated fix until you run it. Its regression file carries
**11** ordering regressions and only ONE is the future-dated case:

```
entries=20 regressions=11
  10:50 after 11:18   <- the future-dated correction
  ...ten more, all at stream joins
```

Three agents' streams were merged into that day-file, so the clock resets at
each join. The entry's closing criterion — "if the advisory still fires on that
day-file afterwards, the remedy did not work" — is therefore unreachable by
either named remedy, because ten findings have nothing to do with future-dating.

Two further things fell out of trying to implement it:

- **Remedy (1) cannot work at sweep stage at all.** It needs to know which
  entries are future-dated, but nothing in a file carries a machine-readable
  flag, and future-datedness cannot be recomputed later — every entry in a
  2026-09-16 file is in the past by the time a sweep reads it. That is the very
  reason `journal-entry-future-dated` is EDIT-only.
- **Remedy (2) is bigger than the entry assumed.** A `correction` category
  means editing the entry grammar in `_JOURNAL_TEMPLATE_.md`, which has two
  copies — one under `install/templates/`, shipped to every client.

So "not owner-gated" no longer clearly holds for N3, and it is the same shape
as the template question Plan 00427 raises for issue #45. Stopping here to ask
rather than pick a grammar change for every install unilaterally.

```

 109 over=  5  worktree-issue-42-remote-docs-add-overwrite

```

The middle row is a branch used earlier the same day, clearing the cap by four
characters. The margin is much tighter than "extreme paths only" implies.

The check calls the daemon's own helpers rather than reimplementing the rule in
bash, so it cannot drift. `get_socket_path` itself was unusable for this: it
sniffs self-install mode off disk and mkdirs as a side effect, so it cannot
answer for a directory that does not exist yet. Two small pure functions were
added instead — `prospective_socket_path` and `socket_path_overflow` — with the
limit still read from the one constant.

refused at 109/104 with no directory and no branch created; `worktree-n6ok`
