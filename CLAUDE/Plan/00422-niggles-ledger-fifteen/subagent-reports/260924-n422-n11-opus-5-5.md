# N11 (owner decision 4): acceptance fixtures leave the scratch directory

**Worktree**: `worktree-n422-n11` (branch `worktree-n422-n11`)
**Implementation commit**: `bf10107c`
**Decision implemented**: [DECISIONS.md](../DECISIONS.md) row 4. Acceptance
probe fixtures move from `untracked/scratch/` to a dedicated
`untracked/acceptance/` root.

## What moved

The helper that built fixture paths, `scratch_path()`, had no other kind of
caller: every one of its callers was an acceptance probe. It is now
`acceptance_path()`, rooted at the new `ProjectPath.ACCEPTANCE_DIR`
(`untracked/acceptance`). `scratch_path` is deleted, so a new probe cannot
import its way back into the human namespace.

There were more callers than the ledger's "about ten" strategies:

- **61 strategy files** across six families: `comments`, `error_hiding`,
  `lint`, `qa_suppression`, `security` and `tdd`.
- **24 handler files**. Most use `acceptance_path()` plus relative
  `mkdir -p` / `rm -rf` setup and cleanup commands. These probes spelled the
  scratch path literally, and each was moved individually:
  - `lint_on_edit`'s Bash-authored probe
  - `validate_eslint_on_write`'s Bash-authored probe
  - `sed_blocker`'s Bash probes
  - `pipe_blocker`'s unquoted-heredoc probe
  - the body file in `plan_journal_guard`'s allow probe
  - the in-repo allow probe in `project_containment` (retitled "The same
    throwaway write, inside the repository")
  - `secret_file_guard`, `quarantine_artefact_read_guard`,
    `write_clobber_guard` and `remote_docs_provenance`
- The `harness_cannot_produce` prose in `docs_qa_edit`, `plan_qa_edit`,
  `remote_docs_provenance` and `reference_repo_freshness` now names the new
  root and the renamed test and allow-list.

**Left in `untracked/scratch/` on purpose.** These are human working
locations, which is what scratch is for:

- `project_containment`'s deny guidance, which still points agents at
  `untracked/scratch/`, and its DENY probe's `expected_message_patterns`,
  which assert that guidance
- `pipe_blocker`'s capture guidance
- `plan_journal_guard`'s fix text
- `curl_pipe_shell`'s download advice
- `issue_report`'s reproduction prefix
- `.claude/skills/acceptance-test/invoke.sh`, which saves the generated
  playbook JSON to `untracked/scratch/acceptance_tests.json`. That file is a
  command capture, not a probe fixture. Moving it into the fixture root would
  put a non-fixture where the harness is allowed to delete.

## Harness, contract test, create/clean, gitignore

- **`playbook_harness.vet_probe_commands`** is bounded to
  `ProjectPath.ACCEPTANCE_DIR` (`_PROBE_ROOT`, which replaces
  `_PROBE_SCRATCH`). A fixture command that acts in `untracked/scratch/` is
  now refused, and the probe is reported as skipped. The comment gives the
  reason: a cleanup `rm -rf` there could delete an agent's working notes.
- **`test_acceptance_contract.py`** and **`tests/acceptance/test_playbook_harness.py`**
  bound their removal guards to the same root.
- **Creating and cleaning the directory.** Nothing creates the acceptance
  root up front, and nothing needs to. Each probe's `mkdir -p` setup creates
  its own fixture directory, and a Write payload's parent directories are
  created by the Write tool. `ensure_scratch_dir` still creates only
  `untracked/scratch/`. The module docstring says why nothing more is needed.
- **Gitignore.** This repository ignores all of `untracked/` from the root
  (`git check-ignore` confirms `untracked/acceptance/x.py` is ignored).
  A client gets `untracked/.gitignore` containing `*` from
  `ensure_scratch_dir`, and that also covers the new sibling. No gitignore
  change was needed. `test_the_acceptance_root_is_under_the_ignored_untracked_directory`
  pins this.

## N2's exclusion globs revisited

The only config that carries these globs is this project's own
`.claude/hooks-daemon.yaml`. The shipped defaults (`daemon/init_config.py`)
have no `exclude_paths` for `lint_on_edit`, so nothing shipped changed and no
config-changes entry is needed.

The changes, measured against the real matcher (`path_matches_globs`):

```
path                                                           old       new
untracked/scratch/rung.py                                      EXCLUDED  EXCLUDED
untracked/scratch/qa-out.txt                                   EXCLUDED  EXCLUDED
untracked/scratch/notes/deep/probe.py                          linted    EXCLUDED
untracked/acceptance/acceptance-test-lint-python/invalid.py    linted    linted
untracked/acceptance/acceptance-test-lint-bash/authored.py     linted    linted
untracked/acceptance/acceptance-test-eslint-bash/broken.ts     linted    linted
untracked/acceptance/acceptance-probe.md                       linted    linted
src/..., tests/..., sub/untracked/scratch/x.py                 linted    linted
```

- **`/untracked/scratch/*` becomes `/untracked/scratch/**`.** The depth limit
  was never a real boundary. It only kept fixtures one level down linted.
  Now that no fixture lives under scratch, the whole scratch tree can be
  excluded, and a nested note directory stops drawing lint noise. That was
  the residual N2 left.
- **`/untracked/qa/**` and `/untracked/worktrees/**` are unchanged.**
- **`/untracked/acceptance/` is deliberately NOT excluded.** The eight
  `lint_on_edit` DENY probes have to be linted there. I measured the negative
  case: adding `/untracked/acceptance/**` turned `test_acceptance_contract.py`
  red, naming all eight probes ("expected_decision=DENY but matches()
  returned False for its own declared input"). Removing it turned the test
  green again. So the guard that caught N2 covers the new root as well.
- **Why the config comment was rewritten.** It now states the rule without
  any history: name the directories rather than excluding all of
  `/untracked/**`, the whole scratch tree is safe to exclude because no probe
  writes there, and the acceptance root must never be excluded. It names the
  test that keeps the second point true.

## Guard tests (written RED first)

The first run, before any source change, gave 35 failures across five files.
The guard tests themselves:

- **`tests/integration/test_acceptance_tool_payload_agrees_with_prose.py::test_no_probe_acts_on_the_human_scratch_directory`**
  runs over the real `generate-playbook` output. It fails when any block's
  `command`, `tool_payload`, `setup_commands` or `cleanup_commands` contains
  `untracked/scratch`. Prose fields are exempt, because the
  `project_containment` deny message rightly names scratch. This is the guard
  the team lead asked for. Both it and the renamed location test ran and
  passed; they were not skipped.
- **`test_every_declared_write_targets_the_scratch_directory`** is renamed
  `..._the_acceptance_directory`, and its marker is now
  `untracked/acceptance`. `_OUTSIDE_SCRATCH_BY_CONTRACT` is renamed
  `_OUTSIDE_ACCEPTANCE_ROOT_BY_CONTRACT`.
- **Unit tests in `tests/unit/daemon/test_playbook_harness.py`.**
  `test_a_command_in_the_human_scratch_directory_is_refused` covers the
  harness half. The existing shape and traversal tests now use the new root.
- **Unit tests in `tests/unit/utils/test_scratch_dir.py`.** They check that
  `acceptance_path()` renders portably, that neither root is nested in the
  other, that the acceptance root is under `untracked/`, and that
  `scratch_path` is gone.
- **Strategy tests.** `tdd` and `qa_suppression` `test_uses_scratch_path` are
  renamed `test_uses_the_acceptance_root`.
- **N20 reproductions.** Four of them (`comment_changelog`, `comment_size`,
  `qa_suppression`, `path_segments`) now use the path probes actually write
  to.

## Observations, not acted on

- **Two bulk-rename sub-agents reported edits they had not made.** Four
  haiku agents did the mechanical renames. All three strategy agents were
  verified clean by grep. The handler agent reported 21 files done, but only
  13 had changed, most of them partially. I finished the rest by hand and
  confirmed the result by grep and the guard test. The lesson is the
  familiar one: verify a delegated bulk edit by its diff, not by its report.
- **`secret_file_guard` leaves an empty directory behind.** Its two probes
  each clean up only their own subdirectory (`.../encrypted`,
  `.../decrypted`), so an empty `acceptance-test-secret-guard/` is left over.
  This already happened before the move; only the location has changed. It
  is harmless.
- **The `ProjectPath` docstring is out of date.** It says "The three members
  that remain", but the class has more than three members, and did before
  `ACCEPTANCE_DIR` was added. I left it alone because it is outside this
  change.
