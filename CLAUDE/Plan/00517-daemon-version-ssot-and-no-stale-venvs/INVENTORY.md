# Plan 00517 Inventory: daemon version readers and staleness tests

Taken on branch `worktree-plan-517-version-ssot`, from a grep of `src/` and `scripts/`
(`cyber-flag` excluded). Line numbers are for that tree.

Two different facts get called "the version", and the plan keeps them apart:

- **Installed version**: what source is on disk and will run. Single source: the installed source tree's
  `src/claude_code_hooks_daemon/version.py` `__version__` literal.
- **Build record**: which daemon version (and lock hash) a venv was built from. Kept by the venv, as
  `.daemon-metadata.json` (`daemon_version`, `lock_hash`, `python_path`) and the older `.daemon-version` stamp.
  It tells venvs apart; it is never the installed version.

## C. Which side each belongs on

- Read `version.py` (installed version): A2 and its callers (A3 now). Shell scripts already do (A10-A14).
- Keep reading a build record (what built this venv): A4, A5, A6-A9, B7, B9. These tell venvs apart and answer
  "which daemon built this", and none of them may be used to answer "what is installed".
- Define stale: B1, B2, B4 are replaced; B7 becomes the one function; B3, B5, B6, B8 call it.
