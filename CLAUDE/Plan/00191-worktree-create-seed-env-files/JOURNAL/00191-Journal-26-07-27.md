## 09:00 · decision · P1 — pivot: symlink instead of copy (single source of truth)

Changed the mechanism from **copy** to **symlink**.

Rationale: copying forks each env file into two independent files. Edit the
canonical `.env.local` and the worktree's copy goes stale → two sources of
truth → confusion about which is authoritative. A symlink keeps the main working
copy as the **single source of truth**: the worktree's entry points back at the
canonical file, so an edit in one place is seen everywhere and there is no stale
duplicate to reconcile.

Implementation deltas:

- `shutil.copy2(src, dest)` → `dest.symlink_to(src)` (absolute target, resolves
  regardless of the worktree's location under the repo). Dropped the `shutil` /
  `os` imports; ruff's pathlib rule prefers `Path.symlink_to`.
- Source existence check relaxed `is_file()` → `exists()` (a link can target any
  existing path).
- Added a **never-clobber** guard: skip if the destination already exists or is
  already a symlink (e.g. a tracked file the checkout provided).
- Option renamed `copy_files` → `symlink_files`; constant
  `DEFAULT_WORKTREE_COPY_FILES` → `DEFAULT_WORKTREE_SYMLINK_FILES`.
- `get_claude_md()`, `hooks-daemon.yaml.example`, and the two
  `error_hiding_exclusions.json` reasons updated to say "symlink".

Behavioural note (intended, not a bug): editing an env file *inside* a worktree
now edits the canonical file — the worktree is deliberately no longer isolated
for these files. That is the point of the SSoT design.
