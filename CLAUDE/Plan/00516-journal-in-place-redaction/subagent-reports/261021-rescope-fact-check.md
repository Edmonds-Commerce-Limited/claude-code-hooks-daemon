## REFUTED claims

1. **Claim 2b (Bash route has the same exceptions).** The Bash route to a journal file allows only the exact `git show HEAD:<p> > <p>` restore. A Bash command that only strips conflict-marker lines is denied (`plan_journal_guard.py:434-456`, `:524-525`). Effect on the plan: any redaction tool that edits a journal file through Bash, or through a helper it runs, must not depend on the conflict-marker exemption. Only a Write/Edit route or an explicit audited exception can change an entry. The re-scope note's wording "except removing conflict-marker lines" should be qualified as Write/Edit only.

## Notes (not refutations)

- Claim 3 is blocking only for plans not in `legacy_plan_allowlist`. Plan 00516 needs to check its own allowlist status before it relies on the EDIT check.
- The guard and the check both stand down unless journalling is enabled and `mkplan.bash` deploys `--journal` (`plan_journal_guard.py:243-297`, `plan_qa/checks/common.py:322-338`).
- The guard also denies creating a new journal file through Write (`plan_journal_guard.py:355-365`). The note does not mention this, and it matters for a tool that writes a replacement entry.
