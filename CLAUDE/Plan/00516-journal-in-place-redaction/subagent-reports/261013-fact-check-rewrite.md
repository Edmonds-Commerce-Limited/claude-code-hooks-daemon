# Fact check: Plan 00516 rewrite, N389 status, draft #108 comment

Scope: PLAN.md, the N389 status sentence in NIGGLES.md, /workspace/untracked/scratch/triage-108.md. The daemon diff file is a diff of PLAN.md only (no daemon code), so it was used only to see what changed.

## REFUTED (most consequential first)

### R1. "An Edit-tool redaction of a past line is not blocked" and "the gap is policy, not mechanism"

Plan Overview bullet 1 and the closing sentence "So the gap is policy, not mechanism". The draft comment repeats it ("nothing mechanically stops the redaction N389 needed"). N389's status says `plan_journal_guard` "already lets a same-line Edit through, so the question is the policy".

- `plan_journal_guard` does let a same-line Edit through (plan_journal_guard.py lines 27-34, 352-356). That part is true.
- A second, independent control BLOCKS the same Edit: plan QA check `journal-dayfile-is-today`. See src/claude_code_hooks_daemon/plan_qa/checks/journal_dayfile_is_today.py: its `CHECK` is level BLOCK (line 111-116), and it fires on any journal day-file edit whose embedded date is not exactly today (line 91).
- `level_for_plan` (checks/common.py:255-264) downgrades to ADVISE only for plans in `legacy_plan_allowlist`. This repo sets `legacy_plan_allowlist: []` (.claude/hooks-daemon.yaml:1552), and the `journal:` block deliberately leaves `today_only_mode` at its `block` default (lines 1560-1561).
- N389's lines are in Completed/00413-niggles-ledger-thirteen/JOURNAL/00413-Journal-26-09-15.md (exists), which is not dated today (2026-10-13). So the Edit would be denied here.
- The repo config already records this exact case (.claude/hooks-daemon.yaml:1569-1578): "today_only_mode has no exemption for a SECURITY redaction of a historical day-file". The Plan 00201 redaction pass flipped it to `advise` for four edits and back. It also says the real fix is "a first-class escape hatch in the handler". That is a mechanism gap.
- Not verified: whether `journal_edit_target` applies to a path under `Completed/`. I did not read that function in full. The config comment suggests it does.

What changes in the plan:

- The premise is wrong. There IS a mechanical block, and the plan's own procedure (Edit-tool replacement in a past day-file) is blocked by default.
- Add `journal-dayfile-is-today` to "What the code allows today". Either the procedure needs a documented, temporary `today_only_mode: advise` step, or it needs the escape hatch the config comment asks for. That reopens the tooling question (open question 2), and the "policy only" framing and the Recommended answer.
- Task 2.2 should also cover `journal-dayfile-is-today`'s remediation (it currently says "never edit a stale day-file, even one dated yesterday").
- Correct the same sentence in the N389 status and in triage-108.md bullets 1, 2 and the paragraph "So the N389 lines were left alone because of policy... not a guard".

### R2. "nothing documents when an agent may change a past line in place" (partly refuted)

CLAUDE/PlanJournalling.md:219-222 (and the same lines in the install template) documents that `plan_journal_guard` allows "an `Edit` that adds no line: ... reordering, or redacting within a line". Line 55 documents "Never edit or remove an earlier entry; corrections are new dated entries". So the docs already say both: the guard permits a redaction, the policy table forbids edits. The accurate claim is that no redaction procedure is documented and the two statements are unreconciled. Reword.
