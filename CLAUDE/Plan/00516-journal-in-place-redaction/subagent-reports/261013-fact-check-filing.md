## REFUTED (most consequential first)

R1. PLAN.md Overview and Goal/Task 2.2: "`plan_journal_guard` ... denies any hand-written Edit, Write or Bash write into a `JOURNAL/` day-file", "no agent could replace it", "Confirm `plan_journal_guard` still denies a hand edit of the same line", Success Criterion "A hand edit of any day-file is still denied".
Evidence: `src/claude_code_hooks_daemon/handlers/pre_tool_use/plan_journal_guard.py` lines 27-34 (docstring) and 352-356 (code). For Write/Edit the guard denies only when the would-be content has MORE non-blank lines or MORE entry headings than the file now has. The docstring says: "An Edit that adds no line passes: a deletion ..., a reordering, a same-line redaction." A `Edit` that swaps text within one existing line therefore passes the guard. Write creating a new day-file is denied; Bash writes by any route are denied.
Effect on the plan: the premise is only true for Bash routes and for additive Write/Edit. A same-line Edit-tool redaction is not denied by this guard (the `journal-append-only` check, PlanJournalling.md:380, is advisory "always advise"). Task 2.2 and the success criterion cannot be met as worded; the plan should either state that same-line redaction already passes the guard (and so the real gap is policy, not capability, for Edit), or say the guard will be changed, which contradicts the Non-Goal "Changing `plan_journal_guard`'s rule for hand edits". Note the owner ruling text (OWNER-QUESTIONS-261011.md section 11 (e)) also asserts A is blocked for agents; that is true only for Bash.

R2. Open question 4 and Task 2.3: "when the commit-time scan finds a term in an existing journal line".
Evidence: CLAUDE.md sensitive_content guidance (commit gate scans the ADDED lines of staged files only); `sensitive_content.py` around lines 1147-1345 works on added lines. A term already committed in an unchanged journal line is not found by that scan, so the premise as worded does not occur. The scan fires only when a line carrying the term is added or re-added in a commit. The plan's remediation hook would need rewording (for example a Write/Edit-time or added-line hit inside a day-file) or a different trigger.
