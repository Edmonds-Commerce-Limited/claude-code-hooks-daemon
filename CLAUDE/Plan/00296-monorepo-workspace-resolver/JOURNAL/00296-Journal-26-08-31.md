## 15:24 · decision · T1.2 — no workspace override knob, and why

Reviewed every existing config surface that encodes "which sub-tree am I in".
**Decision: add no new override knob.** Resolution stays derived from the
edited file's own path; `_MANIFEST_KINDS` is the sole extension point.

Rationale — a knob naming each workspace is the same bodge as a root-level
manifest existing purely to satisfy tooling, which the field report rules out
explicitly. It would also be dead surface: the automatic answer is correct
wherever a manifest exists, and where none exists, declaring the location does
not conjure a toolchain.

The four surviving knobs are **not** workspace overrides and none is replaced:

| Surface                                          | What it actually is                                            |
| ------------------------------------------------ | -------------------------------------------------------------- |
| `markdown_organization.monorepo_subproject_patterns` | Documentation-layout sub-project; need not have a manifest |
| `tdd_enforcement.test_path_map`                  | Where tests live for a glob — orthogonal to which workspace    |
| `validate_eslint_on_write(workspace_root=…)`     | Test seam, constructor-only, never read from YAML              |
| `layout.source_dirs` etc.                        | Roles *within* a workspace — a different axis                  |

The `monorepo_subproject_patterns` finding is the load-bearing one: a docs site
with its own `docs/` and `CLAUDE/` and no `package.json` is a real layout, so
automatic manifest resolution **cannot** subsume that option. Task 2.5 makes it
an override of automatic resolution, not a replacement for it.

## 15:24 · finding · T2.2 — Ansible has a marker that is not a manifest

`lint_on_edit._MODULE_ROOT_MARKERS` maps Go→`go.mod` and Ansible→`ansible.cfg`.
`go.mod` is in `_MANIFEST_KINDS` so Go routes through the resolver unchanged,
but **`ansible.cfg` is not a manifest** — an Ansible tree with no other
manifest resolves to the project-root fallback.

Routing Task 2.2 naively through `Workspace.for_path()` would therefore *lose*
Ansible's working-directory resolution — a regression, and per the comment at
`lint_on_edit.py:250-261` the failure would be a denial the author cannot act
on (the linter failing for the wrong reason), which is worse than not running.
Task 2.2 must either add `ansible.cfg` to `_MANIFEST_KINDS` or keep a
supplementary marker lookup alongside the resolver. Recorded as a known limit
in the new doc.
