## 14:36 · finding · — — supervisor architecture confirmed

Origin: user pointed at anthropics/claude-code#43596 (Ctrl+Z suspends Claude,
hard to recover in a container) and asked whether the ccy supervisor can
intercept it, plus a status-line message with a TTL. Failsafe recovery cron
`2a71237b` created (hourly :37, non-durable).

- `_forward_io` (`.claude/ccy/claude-supervise.py:2192`) forwards stdin →
  `master_fd` byte-for-byte. Outer terminal is raw (`tty.setraw`, ~2379) so
  `ISIG` is OFF — Ctrl+Z arrives as a `0x1a` byte, not a SIGTSTP at the outer
  level. Interception point: strip `0x1a` before `os.write(master_fd, data)`.
- Source of truth is the tracked monolithic `.claude/ccy/claude-supervise.py`
  (pure dogfooding, no `src/` copy — `install/ccy_supervisor.py:10`); tests load
  it via `tests/unit/supervise/_load.py`. Editing it directly is correct.
- Proven atomic-write helper already exists: `write_supervisor_status` (`:933`)
  — per-pid temp `.{name}.{pid}.tmp` + `Path.replace()`.
- `supervisor_indicator.py` is the mirror read pattern (fail-silent) to copy.

## 14:37 · decision · — — scope confirmed with user (three requirements)

1. Message channel built as a GENERAL reusable mechanism; Ctrl+Z is its first
   consumer.
2. Message files MUST be thread/process safe.
3. Thread safety made a first-class, DOCUMENTED concern across all supervisor
   and status-line code (entry-point header comments + architecture docs), not
   just this feature.

Concurrency model: the `supervise/` files are touched by the supervisor host,
its `--worker` subprocess, the daemon (status handlers, separate process), and
multiple sessions sharing one daemon (Plan 00127). Rules adopted: atomic-replace
writes only (temp `.{name}.{pid}.{tid}.tmp` + `os.replace`, last-writer-wins);
fail-silent defensive reads; `threading.Lock` for in-process shared state.
