## 15:32 · decision · P2 — TTL = 10s, rate-limit = 1s

The status line renders on Status events (~per turn / periodic), not on
keypress. 10s TTL is long enough that the message survives to the next render in
the common case, short enough that a stale notice clears within a render or two.
1s min-interval means a Ctrl+Z key-mash rewrites the file at most once/second.
Both are named constants, revisable once live dogfood shows real render cadence.

## 16:30 · finding · P5 — Ctrl+Z→suspend is done by the tty line discipline

User asked where Ctrl+Z becomes a signal: it's the KERNEL tty line discipline
(`n_tty`, ISIG/VSUSP), NOT the terminal emulator — the emulator only transmits
byte `0x1a`. In cooked mode + ISIG the kernel raises SIGTSTP to the foreground
pgrp; in RAW mode it forwards the byte. `tty.setraw` on the outer terminal means
Ctrl+Z is normally a byte (stripped), but the SIGNAL can still hit us (pre-setraw
race, non-tty stdin, `kill -TSTP`, job control) — hence a signal-level guard.

## 16:32 · decision · P5 — which signals to swallow

Swallow SIGTSTP (Ctrl+Z suspend) and SIGQUIT (Ctrl+\ quit + core-dump — a
fat-finger next to Enter, almost never intentional). SIG_IGN SIGTTIN/SIGTTOU
(background-tty stops). LEAVE SIGINT (Ctrl+C) working — it's the legitimate
cancel in Claude's TUI; swallowing it would break real usage. Ctrl+S/Ctrl+Q
(flow-control freeze) is a related footgun but is XOFF/XON, not a signal, and
raw mode already disables IXON — out of scope.

## 18:20 · decision · P6 — message must ATTACH to the supervisor top hat

Live user feedback after relaunching ccy and pressing Ctrl+Z: the standalone
`status_message` status handler rendered its OWN top hat as a SEPARATE status
section (the clock sat between it and the `supervisor_indicator` top hat), so
TWO top hats showed. Also grey-on-orange text was illegible. Requirement
clarified: ONE top hat — the supervisor's own — whose background changes colour
with the message text immediately adjacent on the SAME background.

Root cause: two separate `|`-delimited segments can never read as one attached
block. The fix is architectural — the message must be rendered by the handler
that OWNS the top hat (`supervisor_indicator`), not a second handler.
