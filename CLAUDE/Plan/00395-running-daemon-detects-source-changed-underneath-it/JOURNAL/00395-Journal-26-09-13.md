## 15:10 · finding · — — the capability exists; only the caller is missing

The owner's report was that the daemon detects being out of date but not being
updated underneath it. Reading the code before designing anything changed the
shape of the work: Plan 00371 already shipped the entire comparison, including a
`check-source-fresh` CLI verb. Two facts make it inert for this case:

```text
controller.py:312   self._source_fingerprint = ...   <- assigned once, in initialise()
controller.py:1120  "source_fingerprint": ...        <- only ever read, in the health response
grep callers of describe_fingerprint_mismatch -> cli.py only
```

So the daemon cannot notice its own source moving, and the only automatic
invocation is `scripts/qa/run_smoke_test.sh` during a full QA sweep.

That reframes this from "build detection" to "wire existing detection to a
caller", which is a much smaller and much safer piece of work. Recorded because
the obvious reading of the request would have been to build a file-watching
subsystem alongside a comparison that already exists.

## 15:11 · finding · — — the cheap gate fails exactly when it is needed

Any live check needs a gate; hashing every `.py` per dispatch is not viable. The
obvious gate is mtime. Tested it rather than trusting it, with a `cp -p` over
changed content:

```text
before:  mtime=1789311874  ctime=1789311874  ino=425451172
after:   mtime=1789311874  ctime=1789311875  ino=425451172   content: changed
```

mtime unchanged, INODE unchanged, ctime advanced. So both obvious cheap gates
miss an installer-style redeploy, which is precisely the shape of "another
session upgraded it". A check that reports freshness it did not verify is worse
than no check.

The ccy supervisor contract already documents this same trap for its worker
reload, so it is one root cause solved twice — hence Task 2.5.

## 15:31 · finding · — — CORRECTION: the design above was built on ground never established

The owner challenged the design as over-engineered. It was, and the reason is
more specific than that.

The report was about a **version** changing under a running daemon. The daemon
already records its installed version and already reads it at startup:

```text
.daemon-metadata.json  (inside the fingerprint-keyed venv)
  daemon_version  vX.Y.Z | vX.Y.Z+<ref>.<sha>
  written_at      timestamp
  # metadata.py docstring: "read by the daemon on every startup"
```

One small JSON read answers the question. The earlier entries designed a
535-file ctime sweep plus a sha256 comparison instead.

**The mechanism of the error, which is the part worth keeping**: I grepped
`src/` for something adjacent, met Plan 00371's fingerprints first, and designed
around the first mechanism I found as though it were the only one. Then I
sampled ONE deployment mode — this self-install repo, where
`.claude/hooks-daemon/` has no `.git` — and generalised from it. There are two
modes, and `CLAUDE/LLM-INSTALL.md` and `CLAUDE/SELF_INSTALL.md` say so plainly.
Both are named in `CLAUDE/CLAUDE.md`'s routing table. I read neither before
filing a plan about deployment behaviour.

Then I compounded it: a cost measurement and a full design were committed on top
of that unestablished foundation, which made the frame harder to leave. When the
owner first asked whether this was over-engineered, I answered from INSIDE the
frame — "is it a git checkout?" — instead of stepping out to ask what the
deployment model actually is.

## 15:33 · finding · — — grounding properly surfaced something the sweep design missed

Reading `SELF_INSTALL.md`, `metadata.py` and `scripts/upgrade.sh` produced a
constraint the earlier design never had: the venv is fingerprint-keyed
(`untracked/venv-{slug}-py{MM}-{fingerprint}/`), so an upgrade that changes the
fingerprint inputs writes a NEW venv directory rather than rewriting the old
one.

A check that re-reads the path it remembered at startup would therefore find an
untouched file and report fresh — the exact failure it exists to prevent. The
check has to re-RESOLVE the venv, not just re-read a path. That is now Task 2.1,
as the first failing test.

Recorded because it cuts against a comfortable reading of this correction: the
lesson is not merely "the simple answer was simpler". Grounding also found a
real trap that the elaborate design had no idea about.
