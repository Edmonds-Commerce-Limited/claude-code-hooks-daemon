# Review: PR 238 (Plan 00636 Task 2.3, ci_state_reading), head 399e54d3c

Verdict: REQUEST CHANGES (one blocking).

## Blocking

1. Future `startedAt` falls back to the first attempt's `createdAt` and reads STUCK.
   `src/claude_code_hooks_daemon/utils/ci_state.py:180-181`. `_parse_created` returns None
   for a future time, and then `since` becomes `createdAt`. A re-run whose attempt started a few
   seconds "ahead" of the local clock (ordinary clock skew) is aged from the original creation.
   That is the exact false "stuck" commit 399e54d3c set out to fix, and it contradicts the module
   docstring ("in the future ... UNKNOWN").
   Failing input (now=2026-11-24T12:00Z, threshold 30 min):
   `[{"status":"queued","startedAt":"2027-01-01T00:00:00Z","createdAt":"2026-11-24T10:00:00Z"}]`
   gives STUCK 7200s. Expected: UNKNOWN, or treat a small skew as age 0.
   Fix: fall back only when `startedAt` is ABSENT or unparseable, not when it is future. Add a
   test (the existing future test, test_ci_state.py:105, covers only the row form).

## Low

2. Go zero time is read as a real timestamp. `ci_state.py:133-144`. Input
   `startedAt:"0001-01-01T00:00:00Z"` gives STUCK with age 63931118400s, and the createdAt
   fallback is skipped because the zero time parses. gh marshals an unset time.Time this way.
   Fix: treat year < 2000, or age > some sane cap, as unreadable (UNKNOWN).
3. Deeply nested JSON raises. `ci_state.py:239-242` catches only ValueError. Input `"[" * 100000`
   raises RecursionError out of read_ci_output and handle(). chain.py:711 isolates it, so this is
   not user-visible, but the "never raises" contract is broken.
   Fix: `except (ValueError, RecursionError)`.
4. Unbounded label echoed into context. `ci_state.py:178` and `:172`. A 1800-char
   `workflowName` (or a dict `name`, which renders as `"{'a': 1}"`) is pasted verbatim.
   Fix: accept str only and truncate (e.g. 120 chars).
5. Recognition gaps, which fail silent, not wrong:
   - Attached `-q.`/`-t...` is not seen as reshaped (`ci_state.py:114-116`). It falls through to
     row parsing, which ignores it.
   - `gh -R o/r run list` is not recognised at all (`ci_state.py:112`). A global flag before the
     noun is missed, so the advisory is silently absent for the common `-R` form.
     Fix: skip leading `-R/--repo X`.
6. Docs: `.claude/HOOKS-DAEMON.md` row prints RST double backticks ("``gh``"), taken from the
   class docstring (`ci_state_reading.py:68`). Use single backticks.
