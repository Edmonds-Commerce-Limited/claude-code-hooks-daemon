## Important Issues

### 1. N5 incomplete: a ccy `/goal` continuation keeps an old refusal "in chain", so a NEW unbumped wait passes (Confidence: 75%)

**Location:** `src/claude_code_hooks_daemon/utils/stop_hook_helpers.py:299-304`
(chain boundary = `type:user` prompt only) and
`src/claude_code_hooks_daemon/handlers/stop/owner_wait_stop_guard.py:509`.

**Problem:** The helper closes a chain only at a `type:user` prompt entry. The ccy
goal continuation is written as
`Stop hook feedback: [🤖 [ccy-supervisor] automated goal ...` (a str-content
`isMeta` user entry). The helper classifies that as a BLOCK, which is correct,
but it means the chain never closes. Sequence:

1. The guard refuses a wait.
2. The model bumps the thread and re-stops. The guard passes the re-stop (its
   pass is used).
3. The goal hook blocks the stop, and the model works on.
4. The model stops on a NEW wait (Q62), nothing posted.

At step 4 the guard still sees its step-1 refusal in "this chain", so
`matches()` returns False. Only the 200-line lookback
(`owner_wait_stop_guard.py:149`) bounds it. 40+ goal-feedback blocks appear in
this repo's recent transcripts.

**Proven at the guard's decision** (scratch pytest, full text in Appendix A).
`_chain(_Bus(_stale()))` with `_run(..., active=True)`, 86 transcript lines:

    WITH EARLIER OWN REFUSAL: allow | CONTROL (no earlier refusal): deny

**Assumption:** step 4 arrives with `stop_hook_active=true`. The transcript cannot
show the flag. It follows from the goal hook's block at step 3 being the
continuation that step 4 ends. If Claude Code resets the flag on a goal
continuation, `matches()` never consults the re-entry check and the case is safe.

**Related shape (same fix):** a prompt the human types mid-continuation is written
ONLY as a `queued_command` attachment (141 of 141 `commandMode: prompt` in 60
transcripts had no matching `type:user` entry). So it never closes the chain
either. This only matters when the chain extends past the guard's immediate
re-stop (another block, as above), so the fix below covers it.

**Why it matters:**
- It is a fail-open of exactly the class N5 was filed for ("passes a later chain
  another handler denied first").
- It occurs in the dominant coordinator session mode.
- PLAN.md Task 2.1d and release note 093 present the gap as closed.

**Suggested fix:** Adopt the plan's other fix direction. The re-entry pass applies
only when the LATEST Stop-hook block in the window is this guard's own
(`texts and RuleID.STOP_OWNER_WAIT_UNBUMPED in texts[-1]`), as
`_last_block_is_owner_wait_guard` already does in
`auto_continue_stop.py:92-109`. Keep the since-last-prompt scoping as well.

- **Cost:** after another handler's deny that FOLLOWS the guard's refusal, the
  guard refuses once more.
- **Why that cannot loop:** the new refusal becomes the latest block, so the next
  re-stop passes, and Claude Code's 8th-consecutive-block override is the hard
  bound.
- **Rejected alternative:** counting text-only assistant entries as "turn ends"
  does NOT work. 1,651 text-only assistant entries in real transcripts are
  immediately followed by a `tool_use` in the same turn.
- **Test:** add a unit test from Appendix A, asserting DENY.
- **If behaviour is left unchanged:** record this as a stated residual in PLAN.md
  Task 2.1d and soften release note 093's "no longer lets a later chain through".

## Suggestions

1. **`_entry_is_real_prompt` is wider than its docstring** (`stop_hook_helpers.py:308-320`; docstring 265-268 says "a cron tick or a human message").
   - **What it counts as a prompt:** `<task-notification>`, agent-bus deliveries,
     auto-compaction summaries (`isCompactSummary`),
     `<local-command-caveat>` / `<local-command-stdout>` / skill-body /
     "Goal check-in" / "A session-scoped Stop hook is now active" `isMeta`
     entries, and `[Request interrupted ...]`. Each one closes the chain (7 of 7
     shapes; the tool_result control does not; Appendix B).
   - **How often a reset lands mid-continuation:** in 60 real transcripts nearly
     all such user entries follow an ended turn, where the next stop is fresh
     anyway. One sat directly after a Stop-hook feedback entry, i.e. inside a
     continuation.
   - **Impact:** a bounded extra refusal per interleaved entry, hard-bounded by
     Claude Code's 8th-consecutive-block override (`auto_continue_stop.py:790-793`).
     Never an infinite loop.
   - **Remediation:** treat `isCompactSummary` and the "session-scoped Stop hook"
     notice as non-prompts, and make the docstring say what is really counted.
2. **Stale wording.**
   - `owner_wait_stop_guard.py:491-493`: `_reenters_own_refusal` still says
     "anywhere in the window".
   - `owner_wait_stop_guard.py:739-742`: `get_claude_md` says v1 `auto` "is
     allowed with an ADVISORY". After N6 there is no advisory when the stop
     message is unreadable. Add the exception.
3. **Test gaps** (`tests/unit/handlers/stop/test_owner_wait_followups_n4_n5_n6.py`). Add three tests:
   - An unreadable stop message under `on_unreadable_bus: allow`. Expected:
     ALLOW, empty context.
   - An attachment-only (`hook_blocking_error`) own refusal before a prompt.
     Expected: dropped.
   - A compaction summary between the refusal and the re-stop. This pins the
     Suggestion 1 choice.

```python
"""Important 1 at the GUARD decision: a /goal continuation keeps an earlier refusal 'in chain'."""
from pathlib import Path
from typing import Any
from tests.unit.handlers.stop.test_owner_wait_stand_in_cooperation import _Bus, _assistant, _chain, _feedback, _run, _stale
from claude_code_hooks_daemon.core import Decision

Q62 = "STOPPING BECAUSE: [awaiting-human] the owner has to choose B for Q62 (never posted)."
def _u(c: Any, **kw: Any) -> dict[str, Any]: return {"type": "user", "message": {"role": "user", "content": c}, **kw}
def _tu(i: int) -> dict[str, Any]: return {"type": "assistant", "message": {"role": "assistant", "content": [{"type": "tool_use", "id": f"t{i}", "name": "Bash", "input": {}}]}}
def _tr(i: int) -> dict[str, Any]: return _u([{"type": "tool_result", "tool_use_id": f"t{i}", "content": "ok"}])

def _entries(first_reason: str | None) -> list[dict[str, Any]]:
    e: list[dict[str, Any]] = [_u("[tick:failsafe] check", isMeta=True), _assistant("STOPPING BECAUSE: [awaiting-human] owner must pick (Q61).")]
    if first_reason is not None:
        e += [_feedback(first_reason), _tu(0), _tr(0), _assistant("STOPPING BECAUSE: [awaiting-human] bumped Q61.")]
    e.append(_feedback("[ccy-supervisor] automated goal -- Work on Plan 00636 until complete"))
    for i in range(1, 40): e += [_tu(i), _tr(i)]
    e.append(_assistant(Q62))
    return e

def test_goal_continuation_passes_new_wait(tmp_path: Path) -> None:
    chain = _chain(_Bus(_stale()))
    first = _run(chain, tmp_path, [_assistant("STOPPING BECAUSE: [awaiting-human] owner must pick (Q61).")])
    assert first.decision is Decision.DENY
    with_old = _run(chain, tmp_path, _entries(first.reason), active=True)
    control = _run(chain, tmp_path, _entries(None), active=True)
    print("\nWITH EARLIER OWN REFUSAL:", with_old.decision, "| CONTROL (no earlier refusal):", control.decision)
    assert with_old.decision is Decision.ALLOW and control.decision is Decision.DENY
```

## Appendix D: transcript-shape measurements (args = transcript .jsonl paths)

```python
"""(a) text-only assistant entries mid-turn; (b) what precedes system prompts that follow a user entry;
(c) whether a queued_command prompt is also written as a type:user entry."""
import json, sys, collections
def load(p):
    out = []
    for l in open(p, encoding="utf-8", errors="replace"):
        try: e = json.loads(l)
        except Exception: continue
        if isinstance(e, dict): out.append(e)
    return out
def blocks(e):
    c = (e.get("message") or {}).get("content")
    return [b for b in c if isinstance(b, dict)] if isinstance(c, list) else []
a_mid = a_end = 0; prev_user = collections.Counter(); qc_dup = collections.Counter()
for p in sys.argv[1:]:
    ents = load(p); conv = [e for e in ents if e.get("type") in ("assistant", "user")]
    for i, e in enumerate(conv[:-1]):
        if e["type"] == "assistant" and blocks(e) and all(b.get("type") == "text" for b in blocks(e)):
            n = conv[i + 1]
            if n["type"] == "assistant" and any(b.get("type") == "tool_use" for b in blocks(n)): a_mid += 1
            else: a_end += 1
    for i, e in enumerate(conv):
        c = (e.get("message") or {}).get("content")
        if e["type"] == "user" and isinstance(c, str) and (c.startswith("<task-notification>") or c.startswith("Another Claude") or c.startswith("[tick:")) and i:
            pv = conv[i - 1]; pc = (pv.get("message") or {}).get("content")
            if pv["type"] == "user":
                s = pc if isinstance(pc, str) else json.dumps(pc)
                prev_user["stop-feedback" if s.startswith("Stop hook feedback") else s.strip()[:25]] += 1
    users = [((e.get("message") or {}).get("content")) for e in ents if e.get("type") == "user"]
    ustr = set(u.strip() for u in users if isinstance(u, str))
    for e in ents:
        a = e.get("attachment")
        if isinstance(a, dict) and a.get("type") == "queued_command" and a.get("commandMode") == "prompt":
            pr = a.get("prompt"); pr = pr if isinstance(pr, str) else ""
            qc_dup["also a user entry" if pr.strip() in ustr else "attachment only"] += 1
print("text-only assistant followed by tool_use (mid-turn):", a_mid, "| otherwise:", a_end)
print("system prompts directly after a user entry:", dict(prev_user.most_common(8)))
print("queued_command(prompt):", dict(qc_dup))
```
