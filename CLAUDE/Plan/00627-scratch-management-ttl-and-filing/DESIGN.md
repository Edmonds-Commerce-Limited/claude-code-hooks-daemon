## 3. Taxonomy and the value test

### 3.1 The unit, and the verdicts

A **scratch root** is `untracked/scratch/` in the main checkout and in every registered worktree. An **entry** is a direct child of a session directory (section 7), or, for legacy content, a direct child of a scratch root. An entry is judged whole: one verdict, one action.

Verdicts are computed in this order. The first that applies wins.

| Verdict        | Meaning                                                                              | Action past TTL                                                             |
| -------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| **LIVE**       | Within TTL, or something is using it now (section 4)                                 | None                                                                        |
| **KEPT**       | A human pinned it, or an agent paused it and the pause has not run out (section 3.5) | None; reported                                                              |
| **PROTECTED**  | It holds work that exists nowhere else by a machine test (section 3.3)               | Never packed, never removed; reported every session with the filing command |
| **REFERENCED** | A tracked file names it by exact path (section 3.4)                                  | Packed to one archive with no expiry; reported as "overdue to file"         |
| **DISPOSABLE** | A proof in section 3.2 holds                                                         | Packed, held for the short retention, removed                               |
| **UNCERTAIN**  | None of the above                                                                    | Packed, held for the long retention, announced, removed                     |
| **STUCK**      | The sweep could not read, pack or verify it                                          | Left in place; reported with the reason                                     |

UNCERTAIN is the default, and it is safe by construction: its only route to removal is a verified archive that sits for the long retention with its restore command printed at every session start.

### 3.2 Proofs of NO VALUE (DISPOSABLE)

An entry is DISPOSABLE when it is past TTL, not LIVE, not KEPT, not PROTECTED, not REFERENCED, and **every** file in it is covered by one of these proofs. A mixed entry is UNCERTAIN.

#### 3.3.1 What "a remote holds it" means

The main repository's remote-tracking refs are a cache too, and a cached positive is what Plan 00626 moved the branch proofs away from. So this design reuses the rule of `core/remote_branch_proof.py` rather than writing a second one:

- **Live-verified remote tips.** One batched `git ls-remote` of the project's remote (`live_remote_tips`, the listing in `utils/remote_refs.py`). A remote-tracking ref in the main repository counts only when its sha equals the live tip of the same name. With no network answer there are no verified tips, and P3 and P4 prove nothing: entries fall to UNCERTAIN or PROTECTED, never to DISPOSABLE.
- **Test (c).** A commit is held when `git merge-base --is-ancestor <commit> <verified tip>` holds in the main repository for some verified tip. A commit object the main repository does not have is not held.
- **Remote-held blob set (P3).** Built once per sweep as the blobs in the tree of the verified default-branch tip (`git ls-tree -r`), keyed by blob hash. A scratch file passes when its blob id (git's `hash-object --no-filters` id, computed in-process from a descriptor opened `O_NOFOLLOW`, pinned by a test against git) is in that set. Hashing runs only for an otherwise-UNCERTAIN entry whose uncovered nodes are all regular files, and is bounded per sweep by a file count and a byte total; past the bound, files stay UNCERTAIN and the report says so. Historical blobs are deliberately left out: the set stays small, and a copy of the current tree is the case that occurs.
- Every failure and timeout is a reason, never a pass (the module's own rule).

A standalone repository's dirty or committed content is not proved by any of this, and needs no proof: it goes down the same ladder as a loose file (owner, R7 overturned).

A git command that times out, fails or is refused makes the entry STUCK, never DISPOSABLE.

### 3.4 Referenced by a tracked file (REFERENCED)

The reference set is built once per sweep, not once per entry: `git grep -h -o -E 'untracked/scratch/[A-Za-z0-9._/-]+'` over the main checkout's HEAD tree and over the tip of every local branch not merged into the default branch. An entry is referenced when a match equals its path or lies inside it. A bare word (the measurement's "word-only match") is not a reference.

As built (Task 2.4, `core/scratch_references.py`), with these deviations from the sentence above:

- **Character class** `[A-Za-z0-9._+@~/-]`. It adds `_` (without it `probe_run` matched only `probe`, which fails open) and `+@~`. A trailing run of `._+@~/-` is stripped to form extra candidates, so `untracked/scratch/foo_` and `untracked/scratch/foo.` still name `foo`; the raw form is kept too, so an entry named `foo.` matches. Stripping only adds candidates, so it can only over-protect.
- **Revisions.** HEAD, the local default tip (HEAD may sit on an older branch) and every local branch `--no-merged` into it. With no local default branch, every local branch. A line a merged branch added and the default branch later removed is not a reference.
- **The working tree** is searched as well, so an uncommitted edit to a tracked file counts.
- **Format pinned.** `-a -z -o -n --no-color -E`, with `grep.column`, `grep.fullName`, `grep.fallbackToNoIndex`, `submodule.recurse` and `core.quotePath` forced on the command line. A binary file is searched as text.
- **Matching.** The part after `<root>/` names an entry by its first segment, compared by equality (`foobar` is not `foo`), also after `posixpath.normpath` when that stays under the root (`./` and `../scratch/` resolve).
- **Fail closed.** Any git failure or timeout, output that does not parse from its first byte, an empty branch list, an unresolvable HEAD, a revision git was not asked for, or no project-relative root makes the whole set UNKNOWN: every due entry is STUCK and the report is incomplete. An entry whose NAME holds a character outside the class cannot be found by the search, so it alone is STUCK.
- **A sub-root** (security review F-BYPS 3; coordinator's ruling). For a root deeper than `untracked/<name>` (`--root untracked/scratch/sub`), the search is `<root>[class]*`, and a match that, stripped or dot-resolved, equals the root itself names EVERY entry in it, as does a path under the root for its own entry. A mention of a mere ancestor (`untracked/scratch/`, cited throughout the docs) names nothing, otherwise every sub-root sweep would be REFERENCED; a sibling sharing the prefix (`subway`) names nothing either. A top-level root (`untracked/scratch`) keeps the per-entry rule: a bare `untracked/scratch/` mention protects nothing.
- **Order.** Unknown references are STUCK beside "tracked files unknown"; then PROTECTED; then REFERENCED; then DISPOSABLE or UNCERTAIN. REFERENCED is not the archive-pack path yet (Phase 3).

A reference means a tracked file is leaning on evidence git does not carry. So a referenced entry must be filed (section 6). Until it is, it is protected from removal (R8), and past TTL it is packed to one archive with no expiry, which is what already happened by hand to `rv614c`. The sweep report names the referencing file and line.

To stop new references, a docs/plan QA check flags a tracked line that cites an `untracked/` path as evidence (advisory first; Phase 7).

### 3.5 Human work and pauses (KEPT)

"Anything the owner or a human wrote" cannot be recognised from file content, and there is no ledger of who wrote what (00560, owner ruling). Two mechanisms stand in:

- **`.scratch-keep`**: a file at the top of an entry, holding one line of reason. An entry with it is KEPT for ever. A guard denies an agent creating it (`Write`, `Edit`, or a Bash-authored path), so it is a human's mark (R15). As built (`scratch_keep_marker_guard`, Task 4.4) the guard also denies an agent changing or removing it (`touch`, `ln`, `rm`, the source of `mv`), because an agent's removal would undo a human's keep; it reads the shared write scan with mutations, and fails closed on an unresolved destination or unreadable text that names the marker. A recursive copy of a directory already holding a marker is not seen.
- **`scratch-sweep keep <entry> --reason "..." [--hours N]`**: an agent's pause, recorded in the store index, bounded by `scratch.keep.max_hours`, refused when the reason repeats the last one for that entry (the `branch-park` rule).

Legacy content has neither mark. For it, the long retention of UNCERTAIN is the protection, and that limit is stated plainly in the first dogfood report (Phase 8).

## 4. TTL and liveness

- **TTL** = the root's value in `scratch.untracked_ttl` (section 4.1); for `untracked/scratch/` the default is `24h`. An entry may carry a longer one in the session manifest (section 7), bounded by `scratch.max_ttl_hours` (default 72) or the root's TTL, whichever is longer. The maximum lifetime is likewise never shorter than the root's TTL.
- **Clock** = now minus the newest of: the mtime of every file and directory in the entry (`lstat`, links never followed), the entry root's ctime, and the session manifest's birth time for that entry. An mtime in the future is ignored for that inode and its ctime is used.
- **Why three inputs.** `cp -a` and `tar -x` restore old mtimes, so a fresh copy can look expired: the root's ctime and the birth time cover that. `touch` keeps an entry young for ever: `scratch.max_lifetime_hours` (default 168) is measured from birth, or from the first time the inventory saw an unmarked entry, and past it the mtime is no longer consulted.
- **Liveness unknown is not liveness absent** (security review F-BYPS low). The sweep reads working directories with `scratch_liveness.read_process_cwds`, which skips a pid only when it has exited and names every other pid it could not read. When no working directory was read at all (no `/proc`, another pid namespace) or any pid was unreadable, the report is incomplete and every due entry not otherwise LIVE is STUCK ("liveness unknown"), checked right after the TTL rung.
- **LIVE regardless of age** when: a process has its working directory inside the entry (`read_process_cwds`); or a tracked background process's command names the entry's path (`background_process_tracker` records); or the entry is younger than `scratch.min_age_minutes` (default 30) by birth or ctime.
- **Past TTL means due.** A due entry must leave by one of the four fates in R1. The sweep makes that true for every verdict except PROTECTED and KEPT, which it reports until a human or an agent acts.

### 4.1 TTLs for the directories under `untracked/` (R16)

The owner asked for "default/configurable TTL for untracked paths". The config is a map, `scratch.untracked_ttl`, keyed by one directory name directly under `untracked/`, plus `scratch.untracked_default_ttl` for any directory the map does not name:

```yaml
scratch:
  untracked_ttl:
    repos: "*"        # never cleared
    scratch: 24h
  untracked_default_ttl: "*"
```

- **Values** are `<N>h`, `<N>d` (N a positive whole number) or `"*"` (never cleared). `*` must be quoted: unquoted it is YAML alias syntax and the file does not parse.
- **A malformed value** (`7 days`, a bare `36`, `0h`, `-1d`, empty, a number), a malformed `untracked_default_ttl`, or an `untracked_ttl` that is not a mapping does not stop the config loading (a scratch typo must not take every other guard down), but it is never replaced by a default and never read as `*`: it is kept and logged, and every directory it governs is refused by the sweep, naming the key and the value (`ScratchConfig.ttl_hours_for` raises; `resolve_sweep_root` refuses). The dry run reports the root incomplete; `--apply` exits 1 and creates no store (Task 3.9). A key that is not a single directory name (`a/b`, `.`, `..`, empty) governs no directory and is dropped with a warning.
- **Never swept, whatever the config says**: `repos`, every path in `reference_repos.roots`, and the archive store (`scratch-archive`, section 5.1). A config that gives one of them a finite TTL is overridden and the sweep says so. A sweep root equal to or inside one of them is refused before it is listed; a protected path inside a sweep root is skipped as an entry and named in a note.
- **The scratch default stays 24 hours.** The owner typed "I suggest 24 hours" on 19 November and gave `scratch: 7d` on 20 November as an example in a request about the shape of the config. The example is a valid value (`scratch: 7d` loads), but the default is the owner's earlier explicit figure until the owner says otherwise.
- **An unlisted directory falls through to `"*"`, not to a finite TTL.** In self-install mode the daemon's own runtime directory is `untracked/` itself, so its venvs, `logs/`, `worktrees/`, `spend-ledger/`, `supervise/` and the rest sit beside `scratch/`, and no registry of them exists to exclude them by. A finite fallthrough would make each of them a sweep root, and `logs/*.log` already passes P1. The fallthrough is configurable; a client project whose `untracked/` holds only agent-written directories can set it.
- **A TTL only makes an entry due.** Every directory swept under this map goes through the same ladder (section 3), the same proofs and the same archive hold as scratch. Nothing is removed on age alone.
- `sweep.extra_roots` is retired in favour of the map (neither has shipped). Loose files directly under `untracked/` are not a directory, so the map does not reach them; they are left to Task 6.1.
- The default run sweeps `untracked/scratch/` only; `--root untracked/<dir>` sweeps another and takes that directory's TTL. Sweeping every finite-TTL directory in one run belongs with Task 6.1.
- **A root outside this project's `untracked/` is refused** (a tracked directory, a test tree, another checkout), and so is any root whose literal or link-resolved path passes through an `untracked/repos` or `untracked/scratch-archive` of any checkout. An entry holding a file the project tracks (one `git ls-files` per sweep) is PROTECTED; when that listing fails, every due entry is STUCK.

## 5. Removal: the archive store

### 5.1 Layout

`untracked/scratch-archive/` in the **main** checkout only, mode 0700, flat: archive files, one `index.jsonl`, one lock file. No directory trees, so the store adds one directory to the link index however much it holds.

Each index record: id, original path, checkout, verdict, proof ids, packed-at, expires-at (null for REFERENCED and for a kept record), entry counts by type, archive size and SHA-256, skipped special files, and the restore command. Loose files of one run and one verdict are packed together into one archive, so 3,500 loose files become a handful of files.

### 5.2 The order of operations (never both gone)

For each due entry that is DISPOSABLE, UNCERTAIN or REFERENCED, under the store's `flock` (as built, REFERENCED is NOT packed: see the section 13 departure row):

1. **Re-classify** from a full, unbudgeted walk of that entry. A cached verdict never authorises an action. The per-sweep git facts are rebuilt for the apply run, not reused from a report: the project's tracked-file listing (a file tracked since the report makes the entry PROTECTED), the worktree list, the live-verified tips and blob set (P3, P4), and the reference set (REFERENCED).
2. **Claim**: `renameat` the entry to `.sweeping-<name>` in the same directory, through a directory descriptor opened with `O_NOFOLLOW`. From here a late writer using the old path fails loudly instead of writing into a tree that is about to go.
3. **Re-check** liveness and the fingerprint (entry count, newest ctime) against step 1. Any change: rename back, verdict LIVE.
4. **Pack** with GNU tar by argv (no shell), from inside the claimed directory, with `--one-file-system`, never `-h` or `--dereference`. Links are stored as links. Sockets, FIFOs and device nodes are skipped and listed in the record.
5. **Verify, both ways**: `tar --compare` exits 0 with no output (archive against tree), and the archive's member count equals the walk's count less the listed skips (tree against archive, which `--compare` alone does not check). Then record the SHA-256 and `fsync` the archive and the index.
6. **Remove** the claimed tree with descriptor-based removal (`shutil.rmtree` where `avoids_symlink_attacks` is true; otherwise refuse), staying on one device.
7. **Expire**: a later sweep removes an archive whose `expires-at` has passed, after re-checking that no keep record or new reference covers it. Retention: `scratch.archive.disposable_hours` (default 12) and `scratch.archive.uncertain_hours` (default 168).

The claim rename is expected to change the entry root's own ctime (the builder confirms this in Task 3.2). So the fingerprint leaves the root inode out, and an entry renamed back carries a recorded "claimed at" time that the section 4 clock subtracts, so a STUCK entry does not look newly born. Both have a test.

A failure at steps 2 to 5 renames the entry back and marks it STUCK. A failure at step 6 leaves a `.sweeping-` tree and a complete archive; the next sweep finishes the removal after re-verifying the archive against it. At every point the original, a verified archive, or both exist.

### 5.3 What is never done

- No `find ... -delete`, no bulk `rm -rf` of a path string, in code or in any printed suggestion.
- No action on an entry whose walk hit a budget, an unreadable directory or a second device. Incomplete is STUCK.
- No following of a link, at the entry root or inside it. An entry that is itself a link has only the link removed, with its target recorded.
- No packing of a file whose link count exceeds the names seen inside the entry: its other name is outside, and the archive would copy content the entry does not own.
- No removal of a registered worktree's tree, and none of a PROTECTED or KEPT entry.
- No printing of file content. The sweep reports names, counts, sizes and proof ids only.

## 6. Filing: who does it and where

**The sweep proposes; an agent or a human files (R4).** For each UNCERTAIN, REFERENCED or PROTECTED entry the report prints a destination in a "Filing proposals" section bounded by `scratch.sweep.max_listed` (`core/scratch_filing.py`). A command is printed only for a single regular file going to a plan folder: `mv -n -- <src> <plan>/subagent-reports/`, both sides shell-quoted, and never when the name is unprintable, starts with `-`, the plan number is ambiguous, or the destination already exists. No delete command is ever printed. Nothing is moved by the sweep, because a filed file needs a name, a commit and the content guards (`sensitive_content`, `qa_suppression`, `markdown_organization`), which do not see a `mv`.

The destination is chosen by rule, and the rule is only a suggestion that never feeds the verdict. The hint comes from the entry's name, kind and size only; no file is opened. Signals are tried in the order below, first match wins:

| Signal                                                                    | Proposed home                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| PROTECTED by a repository in the entry                                    | Commit, then push to a branch on the remote; the entry then passes P4 (text only)           |
| PROTECTED because it holds a file the project tracks                      | A human decides                                                                             |
| Above `scratch.filing.max_bytes` (default 262,144)                        | "Too large to track: file a summary and let the rest expire"                                |
| The name starts with a plan number (`^\d{3,5}` then `-`, `_`, `.` or end) | `<plan>/subagent-reports/`; an active plan beats one under `Completed/`                     |
| A `.py`, `.sh` or `.bash` name                                            | `scripts/` or `tests/`, test first (`tdd_enforcement` applies)                              |
| `release` or `upgrade` in the name                                        | `CLAUDE/UPGRADES/UNRELEASED/`                                                               |
| Anything else                                                             | "No tracked home: ask the coordinator for a plan folder" (00560 Q1), and it stays UNCERTAIN |

**Deviations from the first draft of this section (Task 2.5).** There is no manifest signal: no manifest exists yet (section 7), so a plan is found only from the name. The hint is chosen from the name, never from content, unlike 00560 D4: reading content to pick a hint would open every uncertain file on every sweep. A command is printed only for a single file going to a plan folder; every other destination needs a judgement (a summary, a test, a release note) that a `mv` cannot make.

An entry that is filed is then deleted by its filer, or simply expires. An entry nobody files expires through its verdict. That is the owner's rule: filed, or deleted.

## 7. The convention: one directory per session

- **Name**: `untracked/scratch/s-<UTC date and time>-<first 8 of the session id>/`, created by the daemon at SessionStart in the checkout the session starts in, and announced in the SessionStart context as "your scratch directory". A sub-agent uses its parent session's directory name inside its own checkout's scratch root.
- **Manifest**: `.scratch-session.json` in that directory, written by the daemon: schema version, session id, birth time, checkout, branch, and an `entries` map. `hooks-daemon scratch new <name> [--purpose ...] [--plan NNNNN] [--ttl-hours N]` creates an entry, records its birth, purpose, plan and TTL, and prints the path. The purpose and plan feed only the filing proposal.
- **Owner and birth** therefore come from the daemon, not from the agent and not from mtime.
- **A session directory** is itself removed when it is empty apart from its manifest and older than the TTL.
- **Unowned entries** (a new file or directory made directly in a scratch root) draw an advisory naming the session directory, through the same accessor 00560 uses for Bash-authored writes. It starts as an advisory; the mode key allows a deny later.
- **Exporting the path to the shell is not used (Task 4.1 finding).** Claude Code supports it: `CLAUDE_ENV_FILE` is documented for SessionStart (`remote-docs/code.claude.com/docs/en/hooks.md`, "Persist environment variables"). But it is an environment variable of the hook PROCESS, not a payload field (the SessionStart contract's input carries no such field), and the daemon handler sees only the JSON relayed over the socket; neither the forwarder nor the relay passes it on today. A live SessionStart payload was not captured (the payload-capture directory was empty and a sub-agent cannot trigger one), so this rests on the contract and the docs. The export is also unnecessary: every Bash call already carries `CLAUDE_CODE_SESSION_ID`, equal to the hooks' `session_id` (Claude Code changelog; seen live, matching the session's transcript name). `hooks-daemon scratch new` therefore resolves the session directory by the session id's first 8 characters (validated against a strict charset) in the main checkout's scratch root, and SessionStart only creates and announces it. Creation is idempotent per session id (resume and compact fire SessionStart again) and never rewrites an existing manifest.

## 8. Caps

Counted from a cached inventory (`untracked/scratch-inventory.json`, one file): per entry, directories, files, bytes, newest mtime and verdict hint. The inventory is refreshed in a background thread at SessionStart, after a Bash command that creates directories under a scratch root, and by every `scratch-sweep` run. A hook only ever reads the file.

| Key                                | Warn                      | Block                     |
| ---------------------------------- | ------------------------- | ------------------------- |
| `scratch.caps.directories`         | 10,000                    | 25,000                    |
| `scratch.caps.bytes`               | 1 GiB                     | 4 GiB                     |
| `scratch.caps.entries`             | 500                       | 2,000                     |
| `scratch.caps.project_directories` | 50% of the link index cap | 75% of the link index cap |

Counts cover every scratch root, the archive store and the registered stores under `untracked/`, because the link index counts all of them.

- **At warn**: a SessionStart line and a must-do item naming `scratch-sweep --apply`.
- **At block**: rule `R-SCRATCH-CAP` denies a Bash command that creates a directory tree under a scratch root (`mkdir`, `git clone`, `git init`, `git worktree add`, `cp -r`, `tar -x`, `mktemp -d`), naming the largest entries and the sweep command. A `Write` of a file, and a redirect into a file, are never denied: commit and journal bodies must always be writable.
- **The creation scan** (`utils/scratch_dir_creation.py`, shared by the cap guard, the inventory refresher and the unowned-entry advisory) splits statements on `;`, `&&`, `||` and unquoted newlines (continuations joined), peels wrappers and assignments, reads shell `-c` bodies to a depth of 3, and carries `cd`/`pushd` to later statements (`( )` restores it). Makers also include `install -d/-D`, recursive `rsync`, `unzip` and `cp`/`mv -t`; `mv` and `ln -s` count only when a source is an existing directory. A target it cannot resolve (`$VAR`, a backtick, `cd -`, nesting past the cap) counts as under every scratch root. An interpreter's own code is not read.
- **Pressure mode**: at block, `scratch-sweep --apply` also packs entries that are not yet due, largest directory count first, provided they have been idle for `scratch.caps.pressure_idle_minutes` (default 30) and are held back by their TTL alone. An entry not yet due shows LIVE "within its TTL", and the rest of the verdict ladder still runs on it: its result is the row's `ttl_hold`, and pressure packs only an entry whose `ttl_hold` is DISPOSABLE or UNCERTAIN. An entry that is LIVE for a liveness reason (a working directory, a background command) has no `ttl_hold` and is never pressured. A keep marker, reference, tracked file, container hold or unknown liveness makes the `ttl_hold` KEPT, REFERENCED, PROTECTED or STUCK, and every post-pass overrule (cross-entry dependency, session container, session directory) lands on it the same way. A young entry holding a `.git` marker is never classified (git runs only for due entries), so its `ttl_hold` is STUCK: pressure never packs repository work. The archive records the `ttl_hold` verdict and proofs. Packing is not removal: such an archive expires no sooner than its entry's TTL plus its verdict's retention. An `--apply` run that skips a TTL-held entry reports its `ttl_hold` ("KEPT (not yet due: within its TTL)"), not the bare LIVE, so what holds it back underneath stays visible.
- **Never stranded**: if a sweep has run and the count is still over the block cap only because of PROTECTED, KEPT or LIVE entries, the deny becomes an advisory listing them.
- **An incomplete inventory** can raise a cap verdict and never lower one, and the report says it is incomplete.

**Rollout.** The cap guard is built in Phase 5 and the backlog is cleared in Phase 8, and this repository's scratch alone is at about 61,000 directories, over the proposed block cap; the registered stores have not been measured at all. So this repository runs `caps.mode: advise` until Task 8.3 has run, and the default figures in the table are provisional until Task 1.7's dry run has measured scratch and the stores.

A single command can still make 168,000 directories before any hook runs. The cap cannot prevent that; pressure mode is what bounds how long it lasts.

## 9. The link index

- No exclusion of any path, in config or code (R11). The index's promise is that it has seen every directory.
- The sweep reduces what it sees: a packed entry is one file, and the store is one directory.
- When Plan 00623 merges, the index exposes the number of directories it listed and its cap; `scratch.caps.project_directories` reads those instead of counting again. Until then the inventory's own count is used for scratch and the stores only.
- The sweep's reporting names the largest entries by directory count first, because directory count, not bytes, is what overflows the index.

## 11. Worktrees

- Each registered worktree's `untracked/scratch/` is a scratch root, swept from the main checkout or from inside that worktree.
- **On reap** (Task 6.2 ruling, `untracked/agent-reports/261121-task-6-2-ruling.md`, plus the coordinator's root-level-only decision): evacuation has exactly one caller, `worktree-reap --reap` (`daemon/cli.py` `cmd_worktree_reap` -> `daemon/worktree_evacuate.py` `evacuate_scratch`; gate in `core/worktree_scratch_evacuation.py` `evacuation_gate`).
  - Every reap first calls `branch_cleanup.worktree_blockers`; any path a plain `git worktree remove` would lose keeps the worktree (`KEEP <name>: ...`), in the dry run too. Before Task 6.2, `worktree-reap` had no such check (see the section 13 row).
  - Only when every blocker is under `untracked/scratch/` is evacuation offered. Preconditions (each a refusal before the store is opened): run from the main checkout; the target from a fresh `git worktree list --porcelain`, not prunable or locked; `untracked/scratch` a real directory; no `resolve_sweep_root` refusal; a finite TTL (a `"*"` root is moved by a human).
  - **Root-level entries only.** A worktree whose scratch holds any `s-*` session directory is KEPT, the human's next step named: file or delete its children by hand, then reap. Restore cannot recreate a session directory in the main checkout (section 13 row; niggle).
  - One fresh classification (background records of BOTH checkouts) feeds an all-or-nothing gate: every row must be due and DISPOSABLE/UNCERTAIN, or not due and held by its TTL alone. Anything else (PROTECTED, KEPT, REFERENCED, STUCK, any liveness LIVE, no birth stamp, a foreign inode, an incomplete walk, a name no row lists) keeps the worktree and packs nothing. Consent is bound before the question (`consent_to` with `Pressure(idle_hours=0, ttl_hours=<root ttl>)`), so a not-due entry is packed only while its name holds the consented inode.
  - The question needs stdin and stdout to be TTYs and the typed phrase `evacuate <worktree relative to main>`. No terminal, a wrong phrase or end of input keeps the worktree and names `hooks-daemon worktree-reap --reap --only <name>`; there is never a fallback to plain removal. The housekeeping step `worktree-reap-reap` therefore keeps every worktree with scratch.
  - **Accepted limit (review F-BYPS L2):** a TTY does not prove a human; an agent that wraps the command in a pseudo-terminal (`script`, `unbuffer`) can type the printed phrase. This is the same limit as the interim `scratch-sweep --apply` gate (section 13, F-BYPS F2 row), accepted under the threat model and recorded in the Security register's [unenumerated spelling](../../Security/UnenumeratedSpelling.md) corpus as rows `pty-answers-worktree-evacuation` and `pty-answers-scratch-apply` (`scripts/qa/dangerous-invocation-corpus.yaml`, `UNCOVERED-accepted`). Removing the gate, or denying a pty wrapper, is the owner's decision.
  - **Every keep predicate is read again after the answer** (review F-BYPS L1): the question waits as long as the human takes. After a yes and before packing, `evacuate_scratch`'s `recheck` re-collects the worktree's state (live processes via a fresh `/proc` scan, reapability), the running work-queue holds and git locks; any that now keeps the worktree packs nothing. Packing re-reads the background records of both checkouts per entry (`entry_live`). Once a question has been asked, each later worktree in the run is read afresh the same way, and the holds are re-read before `--reap-branches` prunes a worktree-less branch.
  - One `apply_sweep` into the main checkout's store with `expire=False` (evacuation expires nothing) and `checkout=<worktree>`. Every outcome must be `archived` (a resumed claim counts), then every keep predicate and `worktree_blockers` are read again; only a worktree nothing keeps and an empty blocker answer reach the unchanged `reap_worktree` (no `--force`, `git branch -d`). An archive restores into the main checkout's scratch root.
  - `cleanup_after_merge` is **not** an evacuating caller: it removes no worktree. When the holding worktree has scratch it prints the human `worktree-reap --reap --only <name>` line instead of `git worktree remove`, and packs, removes and opens nothing (`core/branch_cleanup.py` `holds_scratch`).
  - `branch-sweep --clean`, the WorktreeRemove handler and `destructive_git` refuse a worktree with scratch through `worktree_blockers`, unchanged.
- `NEVER_REGENERABLE` stays: scratch is never declared rebuildable. What changes is that there is a sanctioned way to empty it.
- A registered worktree that lives inside a scratch root (`w609-mainwt`) is reported with the `git worktree remove` command; the sweep never touches its tree.

## 14. Test plan

All test-first, with fake trees under pytest's `tmp_path`, an injected clock, injected process list and injected git runner where a real repository is not the point.

- **A tree builder** (`tests/helpers/scratch_tree.py`): entries with set mtimes and ctimes, session manifests, links to dummy files outside the fake root, hard links, FIFOs, unreadable directories, real `git init` repositories with and without a bare "remote", a clone of a fake project with dirty, stashed and unpushed states.
- **Clock**: newest mtime wins; a `cp -a` copy is not due; `touch` cannot outlive the maximum lifetime; a future mtime is ignored.
- **Verdicts**: one test per row of sections 3.1 to 3.3, plus the ordering (LIVE over everything, PROTECTED over REFERENCED, and so on) and "a mixed entry is UNCERTAIN".
- **Proofs**: P3 with a blob that exists only on an unpushed branch (not proved); P4 with stale remote refs inside the clone (not proved); P1 not matching `notes.txt`.
- **References**: exact path counts, bare word does not, a reference on an unmerged branch counts.
- **Archive**: round trip (pack, verify, restore, compare with the original); the archive is flat; mismatch injected at each verification refuses the removal.
- **Crash safety**: a failure injected after each of steps 2 to 6; assert the original or a verified archive exists, and that a second run converges.
- **Escapes**: a link at the entry root, a link deep inside, a link swapped in between classify and claim; assert the outside dummy file's content and mtime are untouched.
- **Races**: a write between classify and claim makes the entry LIVE; a process working directory inside refuses.
- **Dry run**: an apply-free run leaves every inode's mtime, ctime and name unchanged (a snapshot comparison).
- **Caps**: warn, block, pressure order, the never-stranded downgrade, an incomplete inventory.
- **Handlers**: unit tests per handler, plus acceptance tests for `R-SCRATCH-CAP`, `R-SCRATCH-KEEP-MARKER` and the SessionStart report, with fixtures under `untracked/acceptance/`.
- **A property test**: for random trees, after `--apply`, no path that a fresh classification calls LIVE, KEPT or PROTECTED has changed.
