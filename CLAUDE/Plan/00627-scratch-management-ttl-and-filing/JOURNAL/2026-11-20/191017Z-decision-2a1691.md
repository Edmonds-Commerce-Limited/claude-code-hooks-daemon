## 19:10 · decision · — — Task 3.5: batch packing, one record per loose file

Task 3.5 built: `core/scratch_archive_batch.py` (test first, `tests/unit/core/test_scratch_archive_batch.py`).

Decisions:

- **Record shape: one record per loose file, all sharing the batch's archive id and SHA-256.** The store contract (one record per entry) is unchanged, so `read_index`, `audit`, `discard_unrecorded` and `resume_claimed` need no new line type. `remove_claimed` proves a file of a shared archive by its own member (the partly-removed path: membership plus a restricted `tar --compare`), and additionally refuses a directory or a record whose counts are not that one file's kind. Expiry (Task 3.6) must delete a shared archive only when EVERY record carrying its id is past retention and unkept.
- Loose files are regular files and symlinks only; a directory, a special file, a file with nlink > 1, claims from two directories, a repeated claim, or a file changed since its claim refuses the whole batch and discards the unrecorded archive.
- `plan_batches` groups by verdict, sorts names, splits by member count and bytes; a repeated or claim-shaped name refuses.

Defect found and fixed in the Task 3.4 path: the restricted `tar --compare` passed member names as argv operands, which GNU tar treats as globs and backslash-unquotes. A name such as `*` or `a\b` then failed to compare (fail-closed, so no data loss, but a hostile name could keep an entry STUCK for ever, and a glob could in principle match a different member). Every operand run now carries `--no-wildcards --no-unquote`. The hostile-name batch test (`-rf`, `--files-from=x`, a newline, `*`, a backslash, a space, non-ASCII) covers it.

Crash test: hard stop after pack, after the first record, after all records, after one removal, and at the end; resuming every leftover claim twice converges, and every file is either back on disk unchanged or recorded and present in the archive.

New public helpers in `scratch_archive_pack.py`: `digest_fd`, `run_tar`, `tar_create_args`, `batched_compare`. No deletion surface added (the AST pin is unchanged).
