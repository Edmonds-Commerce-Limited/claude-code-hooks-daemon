## 14:05 · finding · Task 6.2 — worktree-reap lost ignored scratch; Unit 2 stopped at the restore gate

Task 6.2 Unit 1 (ruling untracked/agent-reports/261121-task-6-2-ruling.md). The ruling's suspicion is confirmed by running it: on a real repository with a linked `agent-*` worktree holding an ignored `untracked/scratch/notes.md`, `worktree-reap --reap` removed the worktree and the note with it (red test `test_an_ignored_scratch_note_keeps_the_worktree_and_the_note` failed with FileNotFoundError on the note). `is_reapable` reads `git status --porcelain`, which lists no ignored file, and a plain `git worktree remove` deletes ignored files without complaint. This was a live data-loss route, including through the housekeeping step `worktree-reap-reap`.

Fix: `cmd_worktree_reap` now calls `branch_cleanup.worktree_blockers` (unchanged) after the ownership and `is_reapable` checks and before `reap_worktree`; any blocker prints `KEEP <name>: ...` via the now-public `blockers_line`, counts as refused, and is never removed, in the dry run too. A git failure reading the worktree is a blocker. No exemption was added to any guard. `blockers_fn` is the test seam; the fake-git CLI tests pass a no-blocker function.

Unit 2 gate finding (not built): `scratch_archive_restore.restore` opens a session child's recorded session directory in the destination root with `_open_session` (O_RDONLY|O_DIRECTORY|O_NOFOLLOW, never created). After an evacuated worktree is reaped, its `s-*` directory exists in the main checkout only when the main checkout happens to hold one of the same name, so a session child's archive could not be restored. Meeting the ruling's gate needs a change to restore's destination rules, which the ruling reserves for a hand-off. Unit 2 is therefore stopped at that gate.
