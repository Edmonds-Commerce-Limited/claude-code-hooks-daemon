2. **Expiry**, under the lock:
   - Refuse the whole run when the index has a torn tail.
   - An archive id is deleted only when EVERY record carrying it (a batch) meets all of these:
     - it is complete,
     - its `expires_at` is non-null and parseable,
     - it is past the max of `expires_at` and its keeps' `until`,
     - an injected `covered(record)` predicate (a new reference) returns False.
   - An exception from the clock or the predicate means "not expired". An unrecorded archive is never deleted here.
   - Order: append the `expired` event, then `lstat` the archive (regular file, not a link), `unlink` it, and fsync the store directory. A rerun converges.
   - This unlink is a NEW deletion surface: add it to the expected set in `test_scratch_archive_remove.py::test_deletion_surfaces_are_only_the_listed_ones`.

   - It may only extend: a keep that would not extend the effective expiry is refused.
   - A reason is refused when it repeats a previous keep reason for that target. Compare stripped and whitespace-collapsed; `branch_park._refuse_same_reason` compares only the last reason, stripped, and this is stricter.
   - Consider a per-target count cap.
4. **Restore** `<id>`:

## Left: Task 3.7 (P6, new module `core/scratch_archive_adopt.py`)

- Keep the scope narrow, otherwise the answer is no adoption (UNCERTAIN, as DESIGN line 173 allows). Adopt only:
  - a directory original that is already claimed;
  - a tarball named by a plain name in the SAME parent descriptor, opened `O_NOFOLLOW`;
  - a regular file with `nlink` 1, owned by the effective user, on the store's device;
  - plain or gzip, chosen by magic bytes with an explicit `--gzip`;
  - members as a single top-level directory equal to the entry name.
- Verify before treating the original as covered:
  - the SHA-256;
  - a safe header pass;
  - a member set equal to the walk after stripping one component;
  - `tar --compare --strip-components=1` in the claimed directory, exit 0 with no output. This flag combination is still to be proven: test a changed file and a member with too few components.
- Then rename the tarball into the store (NOREPLACE, two descriptors), re-open it, check its identity and re-digest it.
  - On failure, rename it back. Never `discard_unrecorded` it: it is the user's file.
  - Moving the tarball out of scratch is a removal that the AST scan does not see (ctypes `renameat2`). List it by hand for Task 3.9.
- Do NOT loosen `verify`/`verify_remaining` based on what an archive looks like. Any non-canonical layout must be an explicit opt-in that defaults to today's behaviour, reachable only when the index record carries proof id `P6`. Otherwise `_prove` cannot remove an adopted original, so it needs that opt-in.
