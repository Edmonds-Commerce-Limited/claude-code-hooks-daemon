## Measured: git grep output (git 2.x, probed on a throwaway repository)

- With revs, `-z -o -n` emits `<rev>:<path>\0<line>\0<match>\n`. The rev separator stays `:`, not NUL. Paths may contain `:` and newlines, and are printed unquoted.
- With no rev, git grep searches the working tree's tracked files: `<path>\0<line>\0<match>\n`.
- Without `-a`, a binary file prints `Binary file <rev>:<path> matches`, with no line and no match. With `-a` it prints a normal record.
- Exit codes: 1 means no match and empty stdout. An unknown rev gives 128.
- An agent-side `git grep` over this repository is denied by `flaggable_content_channel_guard` unless you add `':!tests/fixtures/cyber-flag'`. The daemon's own subprocess is not affected. Write probe scripts to a file and run them with `bash <file>`, because sequenced inline commands need a `set` prelude.

## Task 2.4: the new module `core/scratch_references.py`

Write the test `tests/unit/core/test_scratch_references.py` first; `tdd_enforcement` requires it.

- **Character class.** Use `[A-Za-z0-9._+@~/-]`. It ADDS `_`, which the DESIGN 3.4 regex lacked: `probe_run` would match only `probe`, which fails open. `+@~` are also added. Record this as a DESIGN 3.4 deviation.
- **Unsearchable names.** An entry name with any character outside the class (a space, non-ASCII) cannot be found by the search. Its references are UNKNOWN: the entry is STUCK with a reason, and is never DISPOSABLE because "no reference was found". A root-relative path with an out-of-class character makes the whole set unknown.
- **Pattern.** The root-relative path is escaped by hand: `.` becomes `[.]` and `+` becomes `[+]`; every other class character is literal. Append `/[class]+` and pass the pattern with `-e`, plus `-a -z -o -n --no-color -E`. Put `-c grep.column=false -c grep.fullName=false -c submodule.recurse=false -c core.quotePath=false` before `grep`, so project config cannot change the format. Use a long timeout constant (about 120 s); a timeout means unknown.
- **Revs.**
  - `rev-parse --verify --quiet HEAD^{commit}`. A failure means unknown.
  - `for-each-ref --format=%(objectname) %(refname) refs/heads/`, to label each sha.
  - If the default branch resolves to a local `refs/heads/<default>`, search HEAD, the default tip itself (`--no-merged` excludes it, and HEAD may sit on an older branch) and `for-each-ref --no-merged=refs/heads/<default> refs/heads/`. Otherwise search every local branch.
  - Pass deduplicated shas. An empty rev list is unknown: never call git grep with no revs by accident, because that searches the working tree.
- **Working tree.** Run a second grep with no rev, to catch uncommitted edits to tracked files. It is fail-safe.
- **Parser.** Read the output from position 0 with one anchored regex, `([0-9a-f]{40}|[0-9a-f]{64}):([^\0]*)\0([0-9]+)\0(<class>+)\n`; the working-tree form has no sha. Any byte that does not fit makes the set unknown. Only rc 0 with records, or rc 1 with empty stdout, is known.
- **Matching.** Take the part of the match after `<root>/`. Try the raw form and the form with trailing `.` and `/` stripped; for each, also `posixpath.normpath(root/form)` when it stays under the root. Each candidate's first segment, other than empty, `.` or `..`, names an entry. Compare by equality, so `foo` never matches `foobar`.
- **Sites.** Store `<label>:<path>:<line>` per entry, where the label is HEAD, the branch name or `working tree`. The REFERENCED reason gives the count and the first site. `render_table` already escapes it.
- **`ProjectGit`.** Add `default_branch: str | None = None` as the LAST field and set it in `build_project_git`.
- **`quiet_project_git`** (`tests/support/scratch_tree.py`). It answers rc 0 with empty output to everything, which the new rules read as unknown, and about 20 sweep tests would go STUCK. Fix the helper; do not loosen the rule:
  - When `"grep" in args`, answer rc 1 and empty output.
  - When `args[:2] == ("rev-parse", "--verify")`, answer a fake 40-hex sha.
  - Nested calls start with `-c` and are unaffected.
- **`judge`.** Add a REQUIRED keyword `references` (a small `References(sites, unknown="")` type), so neither call site can omit it: `scratch_sweep.py` calls `judge` at lines 311 and 362. The order is:
  1. An unknown set is STUCK, placed beside `TRACKED_UNKNOWN`. Mark the report incomplete as well.
  2. PROTECTED.
  3. REFERENCED.
  4. DISPOSABLE (P7 included) or UNCERTAIN.
- **Enum changes.** Add REFERENCED to `Verdict` and to `_TABLE_ORDER`, after PROTECTED; `.index()` raises on a verdict that is missing. `NOT_EVALUATED` becomes `("KEPT",)`. Update the tests that pin it: `test_scratch_verdict.py:426` and `test_scratch_sweep.py:272,299`. Also update the CLI epilog (`daemon/cli.py`, scratch-sweep parser), the module docstrings, release note 017, and DESIGN 3.4.
- **Build once.** Build the set once per sweep in `run_sweep`, after `relative_root` is known. With no `project_git` or no `relative_root`, it is unknown.
- **Tests to write:**
  - An exact path counts. A bare word does not.
  - A reference on an unmerged branch counts. One only on a merged branch whose line `main` later removed does not.
  - A reference on the default tip counts while HEAD is on an older branch.
  - A reference to `foobar` is not one to `foo`.
  - A trailing `.` or `/` still matches, and an entry named `foo.` matches its raw form.
  - `probe_run` is found. A name with a space is STUCK.
  - A `./` segment is resolved.
  - A reference in a binary file counts, and so does one in an uncommitted tracked edit.
  - A file name with `:` and a newline is parsed.
  - `grep.column=true` set in the project's config does not break the parse.
  - Each failure is unknown: rc 128, rc 1 with output, rc 0 with output that does not parse, HEAD unresolvable, `for-each-ref` failure, no `relative_root`.
  - With the default branch unresolvable, every branch is searched.
