## Decisions already made (reviewed)

01. **New module `core/scratch_archive_apply.py`** holds the orchestration. `cli.py` only parses
    flags and calls it. The apply module holds NO `unlink`, `rmdir` or `rmtree`: every removal
    stays in `scratch_archive_remove.py` (its pin test already enforces that for that module).
02. **Scope by verdict.** Act only on rows that are `due` AND verdict DISPOSABLE or UNCERTAIN.
    Both are archived, verified, recorded, then the tree is removed; the ARCHIVE is held by
    retention (12h / 168h). There is no delete-without-archive path for any verdict (DESIGN 5.2).
    REFERENCED is NOT acted on: the coordinator's brief says never touch it, which diverges from
    DESIGN 5.2 (which archives REFERENCED with a null expiry). Flag the divergence in the journal and
    final reply. STUCK, PROTECTED, LIVE (and KEPT) are never touched.
03. **Order under `store.lock()`** (store = `<main checkout>/untracked/scratch-archive`; refuse
    `--apply` when run from a linked worktree, compare `GitRepo(repo).main_worktree_root()` with the
    project root, rather than create a second store):
    01. `reclaim_staging(store)`.
    02. For every root name starting `CLAIM_PREFIX`: `resume_claimed(root_fd, name, store, checkout=..., tar=, max_inodes=, clock=, retention_hours=)`.
    03. Fingerprint every listed non-claim name with `fingerprint_at(root_fd, name, max_inodes=)`
        BEFORE classifying; `WalkRefused` means not actionable this run.
    04. Fresh classification: build `project_git` (tracked files, worktrees, verified tips/blobs,
        references) and liveness inputs NEW inside this call, then `run_sweep`. Never accept a report
        as input. If `report.complete` is false, claim nothing new (resume/expiry still run).
    05. Per actionable row: `claim(root_fd, name, fingerprint_from_step_3, max_inodes=, liveness_ok=...)`. `liveness_ok` re-reads `read_process_cwds()` fresh and checks BOTH the
        original path and the `.sweeping-<name>` path (after the rename a process inside has its
        cwd under the claimed name). `check_entry_name` raises `ValueError` (not `ClaimRefused`):
        catch it. `RenamedBack` reports LIVE/STUCK.
    06. `pack(handle, store, new_archive_id(), tar=, max_inodes=)`; on `PackRefused`, `release`.
    07. Build the `ArchiveRecord` (original_path = root-relative from project, e.g.
        `untracked/scratch/<name>`; checkout; verdict `row.verdict.value`; proof ids; `packed_at`
        now ISO with zone; `expires_at` = packed_at + retention; counts/size/sha/skipped from the
        `PackResult`; `restore_command` `hooks-daemon scratch-sweep restore <id>`), `store.append`.
    08. `remove_claimed(handle.parent_fd, handle.claimed_name, store, record, tar=, max_inodes=, clock=, retention_hours=, expected=handle.fingerprint)`. `RemoveRefused` leaves the claim
        for the next run's resume.
    09. Unfinished adoptions: nothing produces adopt events from the CLI yet; only REPORT
        `unfinished_adoptions(store)` (finishing needs a verdict only a fresh row supplies). Record
        that in the residual row.
    10. `expire_due` LAST, with `still_referenced(records)` returning True when (a) any record's
        basename still has a `.sweeping-` name present in the root (a stuck partly removed tree
        whose archive is the only copy) or (b) the fresh reference set names the entry or is
        unknown. Running expiry after the appends also cuts a torn index tail (residual of the
        adopt row).
04. **Step hooks for crash tests.** Give the apply function an injectable `after_step` callback
    (or module-level seams) called after claim, pack, record append, and mid-remove. Tests raise a
    `BaseException` subclass from it (a kill, not an `Exception` a handler could swallow), then
    assert the original or a verifying archive exists, rerun apply, and assert convergence
    (entry gone + `restore` round trip equals the original, or entry intact).
05. **CLI surface.** `scratch-sweep` keeps its dry-run default. Add `--apply`, and nested optional
    subcommands `restore <id> [--entry NAME]` and `keep <id> --reason TEXT [--hours N]`
    (`batch_records` already prints `scratch-sweep restore <id> --entry ...`). Restore derives the
    destination from the record but re-validates it with `resolve_sweep_root` and opens it
    `O_NOFOLLOW`; never trust the index path string. The dry run must not open the store
    (`ArchiveStore.open` creates the directory): test that `untracked/scratch-archive` stays absent
    and the snapshot of all `untracked/` is unchanged.
06. **Replace the unreachable tests** with: an exact allow-list of non-archive importers of
    `scratch_archive*` (`daemon/cli.py` only), and an exact flag/subcommand pin
    (`--apply`, `restore`, `keep` plus the existing dry-run flags).
07. **Open-file liveness gap.** `entry_liveness` checks cwds, background records and minimum age
    only; nothing detects a process holding an open file inside the entry. Do NOT write a test that
    passes for another reason: test the cwd case, and record the open-fd gap as a new DESIGN

08. **No hypothesis** in the venv. The property test uses `random.Random(seed)` parametrised over

09. **Batch packing (Task 3.5's `pack_batch`)**: per-entry `pack` handles a loose file too
