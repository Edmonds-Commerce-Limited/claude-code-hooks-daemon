## Unit 1: removal's proof reads the events file

- `remove_claimed` and `resume_claimed` get REQUIRED keyword arguments `clock: Callable[[], datetime]`
  and `retention_hours: Mapping[str, float]`, with no defaults (fail closed). Update the test helpers
  `_remove` and `_resume`, plus the six or so direct calls.

- New `_removable(store, archive_id, clock, retention_hours) -> None`. It raises `RemoveRefused` when
  any of these holds:

  - the events file has a torn tail;
  - `complete_records(index, events, id)` raises `Incomplete`. That covers an `expired` event, a torn
    index and SHA/size disagreement;
  - `effective_expiry(records, keeps, retention_hours)` is `<= now`;
  - the clock raises or returns a naive instant.

  A `_Hold` from `effective_expiry` means the archive never expires, so removal is allowed. `_Hold`
  and `_keeps` are private in `scratch_archive_expire`: make them public, or add a public helper
  there, e.g. `removal_hold(index, events, id, now, retention_hours)`.

- `remove_claimed` calls it before `_prove`.

- `resume_claimed`, for each candidate:

  - if the archive is not removable and the WHOLE proof verifies, skip the candidate. The tree is
    intact, so falling through to rename-back is safe.
  - if only the PARTIAL proof verifies, return `stuck` ("partly removed; its archive is
    expired/due; a human restores"). It is never removed and never renamed back.

- Tests:

  - removal is refused when there is an expired event;
  - removal is refused when a record is retention-due (record with `expires_at` in the past, verdict
    retention present);
  - a keep that extends the expiry allows removal;
  - `expires_at=None` (all existing fixtures) still allows removal;
  - resume of an intact tree with a due archive gives `renamed-back`;
  - resume of a partly removed tree with a due archive gives `stuck`, the tree is untouched and the
    archive is present;
  - an events torn tail refuses removal.

- Residual to record: expiry does not know about a leftover `.sweeping-` claim. Task 3.8 should run
  `resume_claimed` before `expire_due`, or pass `still_referenced` covering claimed names.

## Unit 6: N2 variant, a separate git directory itself named `.git`

Probe result (`git init --separate-git-dir <root>/e/.git <outside>/wt`, then `git add f`):

- `e/.git/config` has `bare = false` and NO `core.worktree`;
- there is no `gitdir` back-pointer file in the git directory;
- `index` is present;
- only the outside work tree's `.git` FILE points in.

So neither `core.worktree` nor a back-pointer exists. The only signal is the index.

Decision (cheap, fail closed), in `scratch_repos._classify_one` for a `.git` DIRECTORY marker (work
tree = its parent):

- `core.worktree` set in config makes it OUTSIDE_POINTING. Check whether `_allowed` already rejects
  the key as BROKEN; either way it is not disposable.
- If `gitdir/index` exists, run `ls-files -z` through `_nested`. Any tracked path the walk did not
  see makes it OUTSIDE_POINTING ("tracked paths absent from the entry: its work tree may be
  elsewhere (git init --separate-git-dir)"). An `ls-files` failure is BROKEN (STUCK).
- This must run BEFORE the STANDALONE return.

Accepted false positive: an in-entry repository with deleted tracked files becomes PROTECTED. That
is already dirty work, so it is acceptable.

Residual: a separate git directory with commits but an empty index is indistinguishable. Its
objects hold only committed work, and this is still OPEN. One option is to require `HEAD`'s tree to
be fully present in the walk, via `ls-tree -r --name-only HEAD`, which is the same rule applied to
the commit. Prefer implementing that too if it is cheap.

Tests: the fixture above in `tests/unit/core/test_scratch_repos.py` (find the existing N2 tests via
`grep -n separate tests/unit/core/test_scratch_repos.py`) asserts not STANDALONE. A normal
committed standalone repository stays STANDALONE.
