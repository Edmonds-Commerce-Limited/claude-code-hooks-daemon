# Upgrade Guide: v3.60 → v3.61

## Summary

This upgrade renames one user-facing command and fixes three defects that
shared a single root cause: **instructions that existed but never reached the
agent that needed them**.

- The config-optimisation review moved from the standalone `/optimise` skill
  to `/hooks-daemon optimise` (Plan 00322). This is the only breaking change,
  and the installer does the file-level part of the migration for you.
- The mandatory post-upgrade review had been deferring itself into an optional
  hand-back note (Plan 00322), the review's checklist was scoring four handlers
  deleted back in v3.4x (Plan 00323), and four skills kept their real procedure
  in a script their `SKILL.md` never named — so it never ran (Plan 00324).
- Goal retraction landed: a retired goal no longer challenges every Stop for
  the rest of a session (Plans 00320, 00321).

**No configuration changes are required.** No handler was added, removed or
renamed, and no config key changed. If you never typed `/optimise` and have no
local documentation naming it, this upgrade needs nothing from you beyond the
usual upgrade command.

## Version Compatibility

- **Source Version**: v3.60.0
- **Target Version**: v3.61.0
- **Minimum Claude Code Version**: Any
- **Supports Rollback**: Yes
- **Breaking Changes**: Yes — one command rename (see below)
- **Config Migration Required**: No

## Pre-Upgrade Checklist

- [ ] Backup `.claude/hooks-daemon.yaml` (habit; nothing in this release edits it)
  ```bash
  cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
  ```
- [ ] Find any local reference to the old command name
  ```bash
  grep -rn "/optimise" --include='*.md' --include='*.sh' --include='*.yaml' . \
    | grep -v '.claude/hooks-daemon/'
  ```
  If this prints nothing, the breaking change does not affect you.
- [ ] Check for a project-owned skill that happens to share the retired name
  ```bash
  ls .claude/skills/optimise/ 2>/dev/null
  ```
  See "If you own a skill called `optimise`" below.

## Breaking Changes

### `/optimise` → `/hooks-daemon optimise`

**What changed.** The config-optimisation review used to deploy as a top-level
skill at `.claude/skills/optimise/`, invoked as `/optimise`. It is now the
`optimise` subcommand of the daemon's own skill:
`.claude/skills/hooks-daemon/optimise.md`, invoked as `/hooks-daemon optimise`
(Skill tool: `skill=hooks-daemon, args=optimise`).

**Why.** `optimise` is generic enough to collide with whatever else a project
or plugin calls `optimise`, and which one wins is not predictable. Every other
daemon capability already lives under the `hooks-daemon` skill; this one was
the outlier.

**What the installer does for you.** Deployment previously only ever WROTE the
skills it bundles, so a retired skill kept working from an earlier install's
copy — an orphan no upgrade could reach, still owning its slash command. The
installer now removes named retirements, so `.claude/skills/optimise/`
disappears on upgrade. It removes *named* retirements only; your own skills are
never touched.

**What you must do.** Update anything that names the old command — project
docs, runbooks, onboarding notes, wrapper scripts, agent instructions:

```diff
- Run /optimise after upgrading the daemon.
+ Run /hooks-daemon optimise after upgrading the daemon.
```

**If you own a skill called `optimise`.** The removal is provenance-checked:
the daemon only deletes `.claude/skills/optimise/` when its `SKILL.md` looks
like the copy the daemon wrote. A directory of your own with that name is left
in place, and the upgrade logs a WARNING naming the collision. You will then
have your own `/optimise` and the daemon's `/hooks-daemon optimise`, which no
longer compete.

## Changes Overview

### Changed

- **Config-optimisation review moved into the daemon's skill namespace**
  (Plan 00322) — see Breaking Changes above.
- **The review's instruction body is now reachable** (Plan 00322). Its
  395-line procedure lived in a sibling `invoke.sh` that nothing referenced,
  and Claude Code loads a skill's markdown only — a script beside `SKILL.md`
  never runs unless the markdown says to run it. Every run since the skill
  shipped therefore worked from an ~80-line summary, silently skipping the
  manifest-diff step. `optimise.md` now opens by running the script.

### Fixed

- **The mandatory post-upgrade review deferred itself out of existence**
  (Plan 00322). The banner carrying the mandate addressed "your next Claude
  Code session" and printed immediately after the block telling the agent to
  exit its current one, so it read as a hand-back note. It now claims the
  current session and prints before the restart instruction.
- **The review's checklist scored four handlers that no longer exist**
  (Plan 00323), capping every project at 25/29 (86%) and generating
  recommendations to "enable" handlers no config key can enable. Scoring is
  now out of 25.
- **Four skills kept their procedure in a script nothing ever ran**
  (Plan 00324) — and two of them read arguments the caller's typed arguments
  never reached.
- **`contract_staleness` handed client installs a maintainer-only remedy**
  (Plan 00322). It pointed every project at a refresh procedure that edits
  files under `.claude/hooks-daemon/` — a path the upgrade contract forbids
  editing and the next upgrade overwrites. Client installs now get a
  client-shaped remedy.
- **Goal retraction** (Plans 00320, 00321) — a retired goal no longer keeps
  challenging session stop, and a `PLAN.md` outside the project no longer
  emits an unsatisfiable goal.

## Step-by-Step Upgrade Instructions

1. **Upgrade the daemon** (Skill tool: `skill=hooks-daemon, args=upgrade`), or:
   ```bash
   .claude/hooks-daemon/scripts/upgrade.sh
   ```
2. **Run the config-optimisation review in the same session** — the upgrade
   ends by telling you to. It is a mandatory closing step, not an optional
   follow-up: handlers new in this version stay inert until it runs.
   (Skill tool: `skill=hooks-daemon, args=optimise`.)
3. **Update local references** to `/optimise` (see Breaking Changes).
4. **Restart Claude Code** to activate the upgraded hooks.

## Verification

```bash
# 1. Version
.claude/hooks-daemon/bin/hooks-daemon --version    # expect 3.61.0

# 2. The retired skill directory is gone (or, if you own one, still yours)
ls .claude/skills/optimise/ 2>/dev/null || echo "retired skill removed (expected)"

# 3. The subcommand is deployed
ls .claude/skills/hooks-daemon/optimise.md
ls .claude/skills/hooks-daemon/scripts/optimise-invoke.sh

# 4. Daemon healthy
.claude/hooks-daemon/bin/hooks-daemon status

# 5. Doc-reconciliation list for this upgrade
.claude/hooks-daemon/bin/hooks-daemon check-truth-changes --from 3.60.0 --to 3.61.0
```

Step 5 prints the `was → now` entries for the rename, which is the
authoritative list of statements in your own docs that this release made false.

## Rollback

Nothing in this release migrates config or rewrites project files, so rollback
is a plain version checkout:

```bash
cd .claude/hooks-daemon
git checkout v3.60.0
./scripts/install.sh
```

Note that rolling back re-deploys the standalone `.claude/skills/optimise/`
directory, restoring the `/optimise` command and the name collision it causes.
