# Upgrade Guide: v3.71.0 to v3.72.0

## Summary

- **Breaking changes:** No. `CLAUDE/UPGRADES/config-changes/v3.72.0.yaml` has `breaking: false`. Its `renamed` and `changed` entries all keep working on an existing config.
- **Config migration required:** Recommended, not required. Declare `branches.integration_lines` and `branches.exempt` before the branch guards fire, and rename `branch_count_advisor` to `branch_sweep`.
- **Pre-upgrade tasks:** none. **Post-upgrade tasks:** none.

## What changes for an existing project

- **Check for dormant branches BEFORE you upgrade.** The new branch creation guard blocks every new branch and agent worktree while an unmerged, unparked branch has been idle for 30 days or more (rule R-BRANCH-DORMANT). Run `bin/hooks-daemon branch-sweep` and decide each branch listed as `block` under "Dormant" (merge, `branch-park`, or delete), or set `branches.dormancy.mode: warn`.
- **Declare your integration lines and human-owned branches.** Add `branches.integration_lines` (for example `release/*`) and `branches.exempt` (for example `users/*`, `gh-pages`) so those branches are not counted as work or deleted by an agent.
- **Open work branches are capped at 10** (`branches.wip.cap`); a new branch is denied at the cap. `branches.wip.mode: warn` only warns.
- **The Rust relay is the default transport on Linux** for a config with no `daemon.transport.relay_enabled` key. To keep the legacy transport set `relay_enabled: false` or run `bin/hooks-daemon transport off`. An explicit `null` is invalid.
- **`goal_loop_detector` now defaults to `mode: act`.** Set `mode: observe` under `handlers.stop.goal_loop_detector.options` to keep the old logging-only behaviour.
- **Renamed (old key still read for one release):** `handlers.session_start.branch_count_advisor` becomes `branch_sweep`; its `max_open_branches` moves to `branches.wip.cap` and `behind_main_threshold` to `branches.sweep.behind_threshold`.
- **Commit the new `.gitattributes`.** Install and upgrade write a managed block setting `-merge` on `.claude/hooks/**` and `.claude/init.sh`.
- **ccy supervisor changes** (focus hold off by default, `hooks-screen`, supervisor indicator scoped to a session) start working at the next ccy relaunch.

## Steps

Follow the commands in `RELEASES/v3.72.0.md`, "Upgrading Existing Installations". If the gate exits 3, read what it lists and re-run with the `--skip-reading-confirmation=<digest>` it printed. Then run `bin/hooks-daemon branch-sweep --clean --dry-run` to see what a clean would remove.

## Verification

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
.claude/hooks-daemon/bin/hooks-daemon status
.claude/hooks-daemon/bin/hooks-daemon config-validate
.claude/hooks-daemon/bin/hooks-daemon branch-sweep
```

`status` prints a `WARNING:` line if the relay is enabled but its binary is missing; `bin/hooks-daemon transport on` provisions it.

## Rollback

Restore the backup of `.claude/hooks-daemon.yaml`, then upgrade to the previous tag with the same procedure and `v3.71.0` as the target.
