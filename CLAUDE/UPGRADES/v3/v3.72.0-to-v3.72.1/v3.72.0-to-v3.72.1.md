# Upgrade Guide: v3.72.0 to v3.72.1

## Summary

- **Breaking changes:** No. This release ships no config-changes manifest, so the pre-deploy gate lists nothing under `READ THIS FIRST` for it.
- **Config migration required:** No. One setting is recommended for projects that merge into release branches (below).
- **Pre-upgrade tasks:** none. **Post-upgrade tasks:** none. **Truth-changes:** none.

## What changes for an existing project

- **Declare release branches as integration lines.** If you merge feature branches into a `release/*` branch, set `branches.integration_lines: ["release/*"]` in `.claude/hooks-daemon.yaml`. A merged integration line is now deletable by an agent, locally and on the remote, once its remote-tracking tip is an ancestor of the default branch and `git ls-remote` confirms the live tip. An unmerged line, the default branch, `branches.exempt`, `branches.protected_names` and tags are still refused.
- **`optimise` may print a new suggestion.** When git worktrees live under the project root and no `claudeMdExcludes` glob covers them, it prints the exact globs to add. Nothing is written unless you confirm at the apply prompt.
- **Worktree removal no longer refuses over a seeded symlink.** An ignored symlink is never counted as content the removal would lose.

## Steps

Follow the commands in `RELEASES/v3.72.1.md`, "Upgrading Existing Installations". Then add `branches.integration_lines` if it applies to you.

## Verification

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
.claude/hooks-daemon/bin/hooks-daemon status
.claude/hooks-daemon/bin/hooks-daemon config-validate
```

## Rollback

Restore the backup of `.claude/hooks-daemon.yaml`, then upgrade to the previous tag with the same procedure and `v3.72.0` as the target.
