# Callout: docs-optimise skill, instruction-loading contract and `docs-qa --footprint`

**Plan**: 00532
**Audience**: client projects

The daemon now ships a pinned contract for how Claude Code loads `CLAUDE.md`, rules and `@`-imports, and builds three things on it. `docs-qa --footprint` reports what your project loads at session start versus on demand (line and byte totals, the Claude Code version the contract was audited against and the installed one, and what the contract leaves unmodelled), and never proposes changes to the daemon-owned block, daemon-deployed rules, agents and skills, `CLAUDE.local.md` or user-scope files; when walking nested `CLAUDE.md` files it skips your declared `layout.vendor_dirs` and `daemon.exclude_paths` (rules and imports are counted wherever they sit, because Claude Code loads them regardless), and it is run through `.claude/skills/docs-optimise/scripts/footprint.sh`. The new `docs-optimise` skill deploys to `.claude/skills/` and turns that measurement into a restructure proposal under `untracked/scratch/docs-optimise/`; it proposes and never applies, so no tracked file is modified. The `rules_file_shape` and orphan-shrink checks now scan nested `.claude/rules/` folders, and the R7a wording names `paths` as the only rules-file frontmatter field. In the daemon repository only, a newer installed Claude Code than the audited one raises a re-audit advisory. No config keys are added and no action is needed after upgrading. (reported as issue #123)
