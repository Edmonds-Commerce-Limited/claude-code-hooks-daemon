# Upgrade Guide: v3.73.0 to v3.73.1

## Summary

- **Breaking changes:** No. The config-changes manifest `CLAUDE/UPGRADES/config-changes/v3.73.1.yaml` only adds keys (`breaking: false`), so the pre-deploy gate lists nothing under `READ THIS FIRST` for it.
- **Config migration required:** No. Every new key has a default that keeps today's behaviour or derives from an existing setting.
- **Pre-upgrade tasks:** none. **Post-upgrade tasks:** none. **Truth-changes:** `CLAUDE/UPGRADES/truth-changes/v3.73.1.yaml` (admin-seat issue claims; three branch pools; bot-owned branches).

## What changes for an existing project

- **Branches sit in three pools.** Open work counts against `branches.wip.cap` as before. Parked branches move to their own pool (`branches.parked.cap`, `branches.parked.max_age_days`, `branches.parked.mode`) and no longer count against `wip.cap`. A merged branch that has not been deleted is in the merged pool (`branches.merged.*`) and denies branch creation until `branch-sweep --clean` removes it or `branch-keep <name> --reason ...` keeps it.
- **Bot-owned branches are in no pool.** `branches.bot_owned` (default `["dependabot/*"]`) names branches that are never counted, never judged by the creation guard and never deleted by `branch-sweep --clean`.
- **A repository admin seat is not blocked by a non-admin's issue assignment.** It gets an advisory, and `issue-validity N --claim` performs a recorded takeover. Non-admin seats, and issues held by another admin, keep the duplicate-work block.
- **Creating the default branch, or an exempt or protected name, is never denied by the branch cap.**
- **`worktree-reap` deletes merged branches safely**, and a running agent's hold matches however its path is written.
- **The upgrade's `modified_files` lists only the files the upgrade changed.**
- **The ccy supervisor opens a signal directory's entries only when they are regular files**, so a FIFO there no longer hangs it.
- **Upgrading to a commit whose short SHA is all digits** is treated as a commit, not stopped as a "MAJOR version change".
- **arm64:** releases ship attested aarch64 relay and hooks-screen binaries, and on an arm64 host the transport probe checks for the aarch64 musl target.

## Steps

Follow the commands in `RELEASES/v3.73.1.md`, "Upgrading Existing Installations". No configuration edit is needed; set the new `branches.*` keys only to change their defaults.

## Verification

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
.claude/hooks-daemon/bin/hooks-daemon status
.claude/hooks-daemon/bin/hooks-daemon config-validate
```

## Rollback

Restore the backup of `.claude/hooks-daemon.yaml`, then upgrade to the previous tag with the same procedure and `v3.73.0` as the target.
