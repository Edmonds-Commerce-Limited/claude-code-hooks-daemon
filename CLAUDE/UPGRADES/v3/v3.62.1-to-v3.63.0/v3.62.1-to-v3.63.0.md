# Upgrade Guide: v3.62.1 → v3.63.0

## Summary

This is a stability release: the client-upgrade-report defect ledger (Plan
00362, 26 tasks) is worked to zero, alongside the v3.57.0 and v3.60.0
release-review ledgers and a retune of the failsafe-cron/Stop-hook subsystem
after a live dogfooding incident. No handler was removed and no config key
was removed outright.

**The upgrade itself now merges `.claude/settings.json` instead of
overwriting it (Plan 00176)** — new in this release, not a carried-over
behaviour. Your own `statusLine`, hooks, `permissions` block and
`plansDirectory` survive an upgrade unattended; a recommended default you
never expressed an opinion about is upgraded, a value you chose is not; and
a merge that cannot complete safely changes nothing and leaves a
`settings.json.merge-proposal` beside your file instead of failing the
upgrade.

**No configuration changes are required.** Two new config options ship
dormant (`daemon.chain.collect_all_violations`,
`handlers.pre_tool_use.tdd_enforcement.options.test_path_map[].mirror`), and
two config keys that were already silently non-functional
(`handlers.stop.hedging_language_detector`,
`handlers.stop.dismissive_language_detector`) are now detected and
auto-migrated by the upgrade tooling — see Config Changes below.

## Version Compatibility

- **Source Version**: v3.62.1
- **Target Version**: v3.63.0
- **Minimum Claude Code Version**: Any
- **Supports Rollback**: Yes
- **Breaking Changes**: No
- **Config Migration Required**: No (one self-healing auto-migration; see below)

## Pre-Upgrade Checklist

- [ ] Backup `.claude/hooks-daemon.yaml` (habit; the upgrade merges, it does
  not overwrite)
  ```bash
  cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
  ```
- [ ] If you ever hand-configured the nitpick detectors, check whether you are
  still on the old key names
  ```bash
  grep -n "hedging_language_detector\|dismissive_language_detector" .claude/hooks-daemon.yaml
  ```
  If this prints a match under `handlers.stop:`, see "Config Changes" below —
  the upgrade migrates it for you, but it is worth knowing what changed.

## Config Changes

- **Added** (both dormant, opt-in): `daemon.chain.collect_all_violations`,
  `handlers.pre_tool_use.tdd_enforcement.options.test_path_map[].mirror`.
- **Renamed** (auto-migrated by the upgrade, no action needed):
  `handlers.stop.hedging_language_detector` →
  `pseudo_events.nitpick.handlers.hedging_language`, and
  `handlers.stop.dismissive_language_detector` →
  `pseudo_events.nitpick.handlers.dismissive_language`. A config that still
  carried the old key ran neither detector and `config-validate` called it
  valid; `upgrade.sh`/`upgrade_version.sh` move the key (with its `enabled`
  and `priority`) for you. Run `hooks-daemon audit-handler-keys` to check by
  hand, e.g. if you configure the daemon by editing a fresh
  `hooks-daemon.yaml` directly rather than upgrading an existing one.

See `CLAUDE/UPGRADES/config-changes/v3.63.0.yaml` for the full manifest and
`CLAUDE/UPGRADES/truth-changes/v3.63.0.yaml` for this release's `was → now`
doc-reconciliation entries (all `.claude/settings.json` merge-on-upgrade
behaviour — **new in this release** — the upgrade now merges your
`settings.json` instead of overwriting it; re-read your own docs if they
still describe the old overwrite-and-restore workflow).

## Step-by-Step Upgrade Instructions

1. **Upgrade the daemon** (Skill tool: `skill=hooks-daemon, args=upgrade`), or:
   ```bash
   cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
   git -C .claude/hooks-daemon fetch --tags
   bash .claude/hooks-daemon/scripts/upgrade.sh --project-root "$PWD" "v3.63.0"
   .claude/hooks-daemon/bin/hooks-daemon restart
   ```
2. **Review post-upgrade tasks** — `CLAUDE/UPGRADES/v3/v3.62.1-to-v3.63.0/post-upgrade-tasks/` has one optional task (dropping a now-unnecessary `HOOKS_DAEMON_PYTHON` override); read its index for whether it applies to you.
3. **Restart Claude Code** to activate the upgraded hooks.

## Verification

```bash
# 1. Version
.claude/hooks-daemon/bin/hooks-daemon --version    # expect 3.63.0

# 2. Daemon healthy
.claude/hooks-daemon/bin/hooks-daemon status

# 3. No stale handler keys
.claude/hooks-daemon/bin/hooks-daemon audit-handler-keys

# 4. Doc-reconciliation list for this upgrade
.claude/hooks-daemon/bin/hooks-daemon check-truth-changes --from 3.62.1 --to 3.63.0
```

## Rollback

Nothing in this release migrates config destructively — the one key move is
additive and reversible — so rollback is a plain version checkout:

```bash
cd .claude/hooks-daemon
git checkout v3.62.1
./scripts/install.sh
```
