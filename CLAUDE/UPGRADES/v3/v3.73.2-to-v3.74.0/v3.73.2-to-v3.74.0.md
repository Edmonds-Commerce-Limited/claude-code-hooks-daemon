# Upgrade Guide: v3.73.2 to v3.74.0

## Summary

- **Breaking changes:** No. The config-changes manifest
  (`CLAUDE/UPGRADES/config-changes/v3.74.0.yaml`) is not marked breaking, so
  the pre-deploy gate lists nothing under `READ THIS FIRST`.
- **Config migration required:** No. Two optional keys are added:
  `branches.home` and `branches.home_commit`.
- **Pre-upgrade tasks:** none. **Post-upgrade tasks:** one, recommended
  (`post-upgrade-tasks/01-set-home-branch-for-the-claude-md-block.md`).
  **Truth-changes:** none.

## What changes for an existing project

- **The CLAUDE.md block is written and committed only on a home branch.** By
  default that is the repository's default branch. On any other branch, or a
  detached HEAD, the daemon writes and commits nothing and logs why.
  `regenerate-docs` still writes on request from any branch but commits only
  on a home branch.
- **Declare the home branch if your main checkout lives elsewhere.** Set
  `branches.home` to exact branch names (globs are rejected). Set
  `branches.home_commit: false` when the home branch only accepts pull
  requests; the daemon then never writes CLAUDE.md there and reports a stale
  block at SessionStart.
- **Worktree removal:** ignored dependency directories beside a committed
  manifest and lock file count as regenerable, and the deny for other ignored
  content says to delete it in a separate command.
- **Branch and install fixes:** `branch-keep` covers same-tip siblings, a
  reused venv is re-stamped with the version being installed, and an identical
  `settings.json` backup is removed.
- **`lsp_enforcement`** no longer reads `semgrep <name>` as a symbol grep.

## Steps

Follow the commands in `RELEASES/v3.74.0.md`, "Upgrading Existing
Installations". Then read `post-upgrade-tasks/` and decide whether your project
needs `branches.home` or `branches.home_commit`.

## Verification

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
.claude/hooks-daemon/bin/hooks-daemon status
.claude/hooks-daemon/bin/hooks-daemon config-validate
```

## Rollback

Restore the backup of `.claude/hooks-daemon.yaml`, then upgrade to the
previous tag with the same procedure and `v3.73.2` as the target.
