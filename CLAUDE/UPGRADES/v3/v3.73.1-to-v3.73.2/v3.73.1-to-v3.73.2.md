# Upgrade Guide: v3.73.1 to v3.73.2

## Summary

- **Breaking changes:** No. This release has no config-changes manifest, so
  the pre-deploy gate lists nothing under `READ THIS FIRST`.
- **Config migration required:** No. No config key is added, renamed or
  removed.
- **Pre-upgrade tasks:** none. **Post-upgrade tasks:** none.
  **Truth-changes:** none.

## What changes for an existing project

- **A plan journal entry can no longer be stranded by a markdown formatter.**
  `format-markdown` skips plan journal files. The journal immutability check
  accepts a whitespace-only change: the same words in the same order. A
  titled journal heading is single-spaced. An entry already stuck with a
  whitespace-only change can now be committed.
- **Several guards warn instead of deny when they cannot decide.** The
  commit gates, six other guards and `validate_eslint_on_write` now allow
  with an advisory when their own evaluation fails. A positive match still
  denies.
- **Fewer false denials:** shell file tests, awk program text, a quoted
  search pattern naming `cd`, a grep filtering stdin, `git grep`, and a
  merged branch's remote delete chained after its worktree removal.
- **Worktree handling:** a seeded copy identical to its source no longer
  blocks a worktree removal, optional seed entries are not reported missing,
  and a failed worktree creation no longer leaves a locked worktree and
  branch behind.
- **Tooling:** `provision` repairs a stale venv, `explain-rule` and
  `explain-handler` resolve plugin handlers, generated forwarder stubs pass
  shellcheck, and the CLAUDE.md auto-commit waits for uncommitted handler
  sources.

## Steps

Follow the commands in `RELEASES/v3.73.2.md`, "Upgrading Existing
Installations". No configuration edit is needed.

## Verification

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
.claude/hooks-daemon/bin/hooks-daemon status
.claude/hooks-daemon/bin/hooks-daemon config-validate
```

## Rollback

Restore the backup of `.claude/hooks-daemon.yaml`, then upgrade to the
previous tag with the same procedure and `v3.73.1` as the target.
