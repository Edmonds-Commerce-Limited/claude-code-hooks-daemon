# Upgrade Guide: v3.74.0 to v3.75.0

## Summary

- **Breaking changes:** Yes, for scripts only. `hooks-daemon branch-sweep --clean`
  is now a dry run, and `hooks-daemon delete-branch` lost `--allow-unproven`,
  `--reason`, `--bundle` and `--no-bundle`. No handler is removed or renamed. The
  config-changes manifest (`CLAUDE/UPGRADES/config-changes/v3.75.0.yaml`) is not
  marked breaking, so the pre-deploy gate lists nothing under `READ THIS FIRST`.
- **Config migration required:** No. All new keys are optional. Two new
  defaults change behaviour when the key is left unset:
  `claude_md.ownership` defaults to `own` (the CLAUDE.md block gains an
  ownership sentence and handlers drop hints), and
  `branches.wip.creation_grace` defaults to `2` (a branch creation at
  `branches.wip.cap` now warns and is denied only at `cap + 2`).
- **Pre-upgrade tasks:** none. **Post-upgrade tasks:** none.
  **Truth-changes:** `CLAUDE/UPGRADES/truth-changes/v3.75.0.yaml` (three
  entries: `branch-sweep --clean`, `delete-branch`, the creation cap).

## What changes for an existing project

- **`branch-sweep --clean` previews.** Add `--apply` to delete
  (`--clean --remote --apply` for remote copies). `--apply` works in resumable
  batches of 50 and cannot be combined with `--dry-run`.
- **`delete-branch` is stricter.** `--allow-unproven`, `--reason`, `--bundle` and
  `--no-bundle` are gone, and `--protected-ref` accepts only the default branch
  or a declared integration line. `worktree-reap --base-branch` follows the same
  rule. Recovery bundles are no longer written; each delete prints a restore
  line, and `delete-branch --format json` returns a `restore` list in place of
  `bundle`.
- **The CLAUDE.md block leads with an ownership statement.** Set
  `claude_md.ownership: off` to keep the old block, or `custom` with
  `claude_md.ownership_text` for your own line.
- **Generated hook wrappers change once.** They no longer embed a
  machine-specific path; the next converge or upgrade rewrites each one. A
  project that tracks its wrappers commits that one diff.
- **Branch pools are counted per owner**, pressure moves to session start and
  stop, and `branches.wip.creation_grace` (default 2) softens the creation cap.
  Set `branches.wip.creation_grace: 0` to keep the old deny at the cap.
  `hooks-daemon branch-preflight` lists every blocker with its fix.
- **Worktree event waits grow.** Net from v3.74.0, the `init.sh` client wait is
  510 s for `WorktreeCreate` (was 90) and 180 s for `WorktreeRemove` (was 70);
  the next converge or upgrade rewrites `init.sh`.
- **New opt-in or optional surfaces:** `long_running_command_guard` (off),
  supervisor idle compaction (dry-run), `daemon.omit_permission_surface`
  (default `false`), `branches.park.commit` and `branches.park.push`,
  `hooks-daemon session-state`, and the `jsonschema>=4.18` dependency floor.

## Steps

1. Search your own scripts and housekeeping for `branch-sweep --clean` and
   `delete-branch` flags, and update them as above.
2. Follow the commands in `RELEASES/v3.75.0.md`, "Upgrading Existing
   Installations".
3. Decide whether to keep `claude_md.ownership` and
   `branches.wip.creation_grace` at their defaults, and write the choice
   explicitly; the config advisory lists both under "Recommended".
4. Reconcile your project's own docs against the truth-changes report
   (`hooks-daemon check-truth-changes --from 3.74.0 --to 3.75.0`).

## Verification

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
.claude/hooks-daemon/bin/hooks-daemon status
.claude/hooks-daemon/bin/hooks-daemon config-validate
.claude/hooks-daemon/bin/hooks-daemon branch-sweep --clean
```

The last command prints a plan and deletes nothing.

## Rollback

Restore the backup of `.claude/hooks-daemon.yaml`, then upgrade to the
previous tag with the same procedure and `v3.74.0` as the target.
