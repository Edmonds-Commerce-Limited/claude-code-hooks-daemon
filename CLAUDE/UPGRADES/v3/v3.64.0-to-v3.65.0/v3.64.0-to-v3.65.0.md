# Upgrade Guide: v3.64.0 → v3.65.0

## Summary

This upgrade is a guard-review release: a routine (`CLAUDE/Routine/`,
`hooks-daemon run-routine`/`routine-qa`) turns security review into a
recurring, ledgered activity rather than a one-off pass, and then runs it —
the run closed eleven guard bypasses and asymmetric-sibling defects,
five of them landing as five new `destructive_git` rules. Session start and
session end also gain teeth: SessionStart messages now carry a computed
action tier, a declared `persistent_crons` job is verified at Stop rather
than merely announced, and an operator channel (`hooks-daemon signal`) lets a
host warn a running session before a reboot.

**The headline is sixteen newly-denied command shapes.** None of them is a
config key rename or a behaviour flip on an existing default — each is a
guard that previously let something through and now does not. If your
project or its agents routinely run `git checkout -f`, write to a `~/`
path, relocate files into or out of a worktree with `install`/`dd`, or
publish through `gh release create --notes` / `gh gist create --desc` /
`gh pr review --body` / `gh repo edit --description`, read
[Breaking Changes](#breaking-changes) before upgrading — one of these is
likely to start refusing where it did not before.

**No config key was renamed. No existing default value changed. No handler
was removed.** `git diff v3.64.0..HEAD -- src/claude_code_hooks_daemon/config/`
is entirely string-concatenation reflow with zero behaviour change. Seven
new handlers ship, all enabled by default except the two that are
deliberately opt-in (`routine_qa_sweep`, `session_actions_directive`) — see
[Configuration Changes](#configuration-changes).

## Version Compatibility

- **Source Version**: v3.64.0
- **Target Version**: v3.65.0
- **Minimum Claude Code Version**: Any
- **Supports Rollback**: Yes
- **Breaking Changes**: Yes — sixteen newly-denied command shapes (see
  below). No API/output field was renamed or removed this release.
- **Config Migration Required**: No. Every new config key defaults to a
  safe value (`enabled: true` for the reporting-only/silent-unless-drifted
  handlers, `enabled: false` for the two genuinely opt-in ones). See
  [Configuration Changes](#configuration-changes).

## Pre-Upgrade Checklist

- [ ] Backup `.claude/hooks-daemon.yaml`
  ```bash
  cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
  ```
- [ ] Check whether any script or agent workflow in your project relies on
  a command shape that is about to start refusing:
  ```bash
  grep -rn -e 'checkout -f' -e 'checkout --force' \
           -e 'switch -f' -e 'switch --discard-changes' \
           -e 'reflog expire --expire=now' -e 'gc --prune=now' \
           -e 'filter-branch' -e 'filter-repo' \
           . --include='*.sh' --include='*.md' \
    | grep -v '.claude/hooks-daemon/'
  ```
  If this prints nothing, the five new `destructive_git` rules do not
  affect you.
- [ ] If your project writes to paths under the user's home directory
  (`~/...`) via `Bash` (curl `-o`, `cp`, redirects), confirm those targets
  are meant to live outside the project — `R-WRITE-OUTSIDE-PROJECT-ROOT`
  now expands a leading `~` before judging the destination.
- [ ] If your project or an agent runs `install`/`dd` to move files between
  a git worktree and the main checkout, confirm that's intentional —
  `R-WORKTREE-FILE-COPY` now covers those verbs alongside `cp`/`mv`/`rsync`.
- [ ] If your project publishes via `gh release create/edit --notes`,
  `gh gist create --desc`, `gh pr review --body`, or
  `gh repo edit --description`, or via a path-qualified `gh` binary
  (`/usr/bin/gh`, `./gh`), or via `-F <file>`/`--file=<file>` message
  bodies, confirm those bodies never contain flaggable content — the
  `sensitive_content` scan now covers all of these surfaces.
- [ ] If you have `persistent_crons.enabled: true` with declared jobs,
  read B14 below — a Stop/SubagentStop can now be denied when a declared
  cron is missing from the session.
- [ ] Read [Breaking Changes](#breaking-changes) below in full.

## Breaking Changes

Sixteen command/edit shapes that v3.64.0 allowed now deny. Each row names
the exact shape, the rule or handler responsible, and what to do if you
genuinely need it.

### Newly denied — always in effect

| #   | What now denies                                                                                                                           | Rule / handler                                                       | If you need it                                                                                                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B1  | `git checkout -f` / `git checkout --force`                                                                                                | `R-GIT-CHECKOUT-FORCE` (`destructive_git`)                           | Commit or stash first; ask a human to run the force checkout manually                                                                                                                                                               |
| B2  | `git switch -f` / `git switch --discard-changes`                                                                                          | `R-GIT-SWITCH-FORCE` (`destructive_git`)                             | Same — commit/stash first, or ask a human                                                                                                                                                                                           |
| B3  | `git reflog expire --expire=now`                                                                                                          | `R-GIT-REFLOG-EXPIRE` (`destructive_git`)                            | Use a real expiry window (`--expire=90.days.ago`), which is not blocked                                                                                                                                                             |
| B4  | `git gc --prune=now`                                                                                                                      | `R-GIT-GC-PRUNE-NOW` (`destructive_git`)                             | Plain `git gc` or `git gc --auto` are not blocked; use a prune window instead of `now`                                                                                                                                              |
| B5  | `git filter-branch` / `git filter-repo`                                                                                                   | `R-GIT-FILTER-HISTORY` (`destructive_git`)                           | Ask a human to run it manually, on a fresh clone with a backup ref                                                                                                                                                                  |
| B6  | `env <command> \| head`/`\| tail` (any command run through `env`)                                                                         | `pipe_blocker` (whitelist entry removed)                             | Use `bin/echd-capture` (see the pipe-blocker guidance in this project's CLAUDE.md), or drop the `env` wrapper if it isn't needed                                                                                                    |
| B7  | A `Bash` write target starting `~/` (e.g. `curl -o ~/x.sh`)                                                                               | `R-WRITE-OUTSIDE-PROJECT-ROOT` (`project_containment`)               | Write inside the repository instead — `untracked/scratch/` is the scratch location; `~` genuinely outside-project writes need a human                                                                                               |
| B8  | `install`/`dd` relocating a file between a worktree and the main repo                                                                     | `R-WORKTREE-FILE-COPY` (`worktree_file_copy`)                        | cd into the worktree, commit, then `git merge` back — the same fix as for `cp`/`mv`/`rsync`                                                                                                                                         |
| B9  | A path-qualified `gh` (`/usr/bin/gh …`, `./gh …`) publishing sensitive content                                                            | `sensitive_content`                                                  | Fix the flagged content — the qualification never made the publish safe, it only avoided detection                                                                                                                                  |
| B10 | `gh release create/edit --notes`, `gh gist create --desc`, `gh pr review --body`, `gh repo edit --description` carrying flaggable content | `sensitive_content`                                                  | Remove the flagged text before publishing; these verbs were always publication surfaces, now they're scanned like the others                                                                                                        |
| B11 | A `git`/`gh` message supplied via `-F <file>`/`--file=<file>` that contains flaggable content                                             | `sensitive_content`, `github_auto_close_keywords`                    | Fix the file's content before use — it is read exactly like an inline `-m`/`--body` value now                                                                                                                                       |
| B12 | Any `Edit` inside the remote-docs tree, regardless of what changed                                                                        | `R-REMOTE-DOCS-PROVENANCE` (`remote_docs_provenance`)                | Do not hand-edit vendored docs — re-capture with `hooks-daemon remote-docs refresh --path <stored-path>` (or `--all` for the whole corpus) instead                                                                                  |
| B13 | A `bash`/`python3`/`ssh` heredoc body that mentions a destructive command                                                                 | already documented in `[Unreleased]` as of v3.64.0 — carries forward | See the existing heredoc-guard guidance; no new action beyond what v3.64.0 already required                                                                                                                                         |
| B14 | A `Stop`/`SubagentStop` while a declared `persistent_crons` job is missing from the session                                               | `cron_stop_enforcer`, `cron_subagent_stop_enforcer`                  | **Conditional — inert by default.** Only fires when `persistent_crons.enabled: true` and at least one job is declared. Re-declare the missing `CronCreate` (the block names the exact id, schedule and prompt)                      |
| B15 | A `PLAN.md` edit/commit/sweep with an unticked criterion that is waiting on a release to ship                                             | `release-blocked-plan` plan-QA check                                 | **Conditional.** Only fires on a non-terminal plan with an unticked release-waiting item. Stage the release-bound consequence into `CLAUDE/UPGRADES/UNRELEASED/` instead, which is exempt                                           |
| B16 | Every `AskUserQuestion` call                                                                                                              | `R-ASK-USER-QUESTION-UNJUSTIFIED` (`ask_user_question_blocker`)      | **Opt-in — inert unless you set it.** Only denies when your config sets `handlers.pre_tool_use.ask_user_question_blocker.options.mode: unattended`. If you rely on interactive questions during unattended runs, leave `mode` unset |

Whether the five `destructive_git` denials (B1–B5) count as "breaking" for
SemVer purposes is a judgement call — they deny commands that were
previously silent, not commands anyone was relying on working a particular
way. This release follows the same precedent v3.64.0 set for its own
breaking change: document it plainly, still ship MINOR.

### Newly allowed / loosened — no action needed

These four were previously-denied shapes that turned out to be false
positives. Nothing to configure; listed here so a "why did this suddenly
pass?" moment has an answer.

| #   | What now passes                                                                                                 | Why                                                                                                                                                           |
| --- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L1  | Writing `__init__.py` (or any other per-language-excluded file) in a project that declares `layout.source_dirs` | `tdd_enforcement`'s per-language exclusions were unreachable once a project declared a layout; a file-level veto now runs ahead of the location rules         |
| L2  | A commit message or prose quoting a `cp <worktree> <repo>` example                                              | `worktree_file_copy` now strips inert (quoted/prose) spans before judging, like `destructive_git` and `pipe_blocker` already did                              |
| L3  | A commit message quoting `ls CLAUDE/Plan/*job*` or similar                                                      | `plan_number_helper` now anchors on the LAST mention of the plan directory, not the first, so a message describing a scan cannot be misread as performing one |
| L4  | A `../`-relative markdown link whose writing file's own directory does not exist yet                            | Links are now resolved lexically (as a renderer would), not by `stat`-ing a path that has no reason to exist yet                                              |

### Message / scope / output changes to existing rules

No output field was renamed this release, but nine existing rules changed
what they say or which surface they cover:

- **`header-body-coherence`** — its COMPLETION finding ("the header says
  `In Progress` / `Not Started` but every box is ticked") moves from BLOCK at
  edit time to ADVISE, and the check gains a **new COMMIT registration at
  BLOCK**. Its `Not Started`-with-boxes-ticked branch is unchanged and still
  blocks on write.

  **This tightens enforcement rather than relaxing it.** The check previously
  had no commit registration at all, so a plan committed in the violating
  state reached history unchallenged and was reported only by the next
  session's sweep. What changes for you is WHEN the denial lands: an agent
  that ticks a plan's last checkbox now gets an advisory instead of a refused
  write, and the very next `git commit` refuses the same state. The commit
  gate is scoped so a commit is blamed for incoherence it INTRODUCES, never
  for incoherence it inherited — so an already-incoherent plan cannot deny
  every later commit that touches the file for unrelated reasons.

  The reason for the move: closing a plan requires two changes to one
  `PLAN.md` — tick the last Success Criterion and flip the status header — and
  the `Edit` tool replaces one contiguous span, which those two never share.
  Both orderings were denied, leaving a whole-file `Write` as the only legal
  move. A gate no legal sequence of moves can satisfy is a defect, not a
  policy. **No action needed**; if you have tooling that asserts on plan-QA
  edit-time denials, the completion case now reports at ADVISE.

- **`WorktreeCreate` forwarder output** — on failure it now prints the
  daemon's own reason (a crashed handler's `systemMessage`, or a deliberate
  refusal's `reason`) instead of asking whether the handler is enabled. When
  no reason is available it says so and points at the logs. Stdout is still
  the worktree PATH and is still empty on failure; only stderr changed. A
  wrapper matching on the old literal text should be updated.

- **`ask_user_question_blocker`** — under `mode: unattended`, the deny
  reason and the generated `CLAUDE.md` row change: the remedy is now
  "choose the option you would have recommended and continue", not
  "retry with a prefix".

- **`guard_config_drift`** — finding text no longer says "in the working
  tree"; it now names which document (working tree vs. `HEAD`) it read.

- **`remote-docs refresh`** — gains a `REFUSED` outcome distinct from
  `FAILED`, and it counts toward a non-zero exit code. A wrapper that only
  checked for `FAILED` should also check `REFUSED`.

- **`harvest-background`** — a TTL-breach report now describes the whole
  process TREE's CPU usage and offers a `kill` naming every process group
  the tree spans, not just the idle waiter.

- **`gitignore_safety_checker`** — lists more required `.gitignore`
  entries, derived from the protected globs rather than a separate
  hand-maintained list. Advisory only; no new refusal.

- **`emit_hook_error()`** — the fresh-clone first-run error message moves
  its remedy prose out of `hookEventName` (which Claude Code validates
  against a closed enum and was silently discarding it) into
  `systemMessage`, and stops recommending `install.py`/bare `python`
  inside this repository's own checkout.

- **`WorktreeRemove.can_block`** in the vendored hooks contract flips
  `False → True` (any non-zero exit now blocks it), matching the upstream
  Claude Code v2.1.272 spec. This corrects a claim table; it has no
  runtime consumer today outside the QA checker that verifies the claim.

## Changes Overview

### New Handlers

- **`guard_config_commit_gate`** (PreToolUse, priority 49) — reports (never
  denies) a commit whose `hooks-daemon.yaml` weakens a guard, at the moment
  it enters history.
- **`guard_config_drift`** (SessionStart, priority 49) — compares the
  working-tree `hooks-daemon.yaml` against `git show HEAD:` and names any
  uncommitted change that weakens a guard. Runs ahead of the whole
  advisory ladder, because every other advisory's value depends on the
  guards actually being live. Silent when the two agree.
- **`routine_qa_sweep`** (SessionStart, priority 72, **opt-in**, default
  `enabled: false`) — reports a recurring `CLAUDE/Routine/` entry that has
  never run, is overdue, or has a gap in its coverage record. Silent on a
  clean tree.
- **`session_actions_directive`** (SessionStart, priority 73, **opt-in**,
  default `enabled: false`) — when a session starts with one or more
  `ACTION_REQUIRED` items, writes a signal and has the ccy supervisor type
  one short directive naming the count. Must stay the LAST SessionStart
  handler in your priority ordering — see the priority-ordering note
  below.
- **`host_hostname`** (StatusLine, priority 7, **opt-in**, default
  `enabled: false`) — a status-line segment showing which machine a
  session is on, resolved from `CCY_HOST_HOSTNAME`, then
  `HOOKS_DAEMON_HOST_HOSTNAME`, then `gethostname()`, then an `/etc/hosts`
  self-alias marked `@~name`. Deliberately has no config-file name option
  (`.claude/hooks-daemon.yaml` is often tracked and public); silent inside
  a container with nothing exported.
- **`cron_stop_enforcer`** (Stop, priority 7) and
  **`cron_subagent_stop_enforcer`** (SubagentStop, priority 7) — compare
  declared `persistent_crons` jobs against the session's `session_crons`
  payload and block the stop, naming the exact missing `CronCreate`, if
  one is absent. An absent `session_crons` field means "no information"
  and never blocks. Inert unless `persistent_crons.enabled: true` with at
  least one declared job (see B14 above).
- **`teammate_reap_advisor`** (Stop) — reports the `background_tasks`
  count the Stop payload carries and names `TaskStop` as the way to clear
  them. Claude Code defers its `/goal` stop-condition evaluation while any
  background work is registered, and a teammate that has finished and gone
  IDLE is still registered. Advisory only: it never denies a stop.

That is eight new handlers. **None removed.**

### Removed Handlers

None this release.

### Configuration Changes

#### New Config Fields (all default-safe)

```yaml
handlers:
  pre_tool_use:
    guard_config_commit_gate:
      enabled: true
      priority: 49 # reports only, never denies
    ask_user_question_blocker:
      options:
        mode: null # set to "unattended" to engage R-ASK-USER-QUESTION-UNJUSTIFIED (B16)
  session_start:
    guard_config_drift:
      enabled: true
      priority: 49 # silent unless the working tree differs from HEAD
    routine_qa_sweep:
      enabled: false # opt-in
      priority: 72
    session_actions_directive:
      enabled: false # opt-in; must stay LAST in the SessionStart ordering
      priority: 73
  stop:
    cron_stop_enforcer:
      enabled: true
      priority: 7 # must stay BELOW auto_continue_stop's priority 10
  subagent_stop:
    cron_subagent_stop_enforcer:
      enabled: true
      priority: 7 # must stay BELOW subagent_report_size_blocker's priority 15
  status_line:
    host_hostname:
      enabled: false # opt-in; deliberately no name option
      priority: 7
  worktree_create:
    worktree_create:
      options:
        seed:
          entries:
            # per-entry, defaults to false -- existing configs are unaffected
            - path: .claude/some-gitignored-local-file
              optional: true
```

**On `seed.entries[].optional`** — seeding treats an absent source as fatal
and abandons the whole `WorktreeCreate` before any worktree exists. That is
right for a typo'd path, since silently handing back a worktree missing files
its agent cannot know are absent is the failure the feature prevents. It is
wrong for a source that is legitimately optional, and there was no way to say
which you meant.

`optional` excuses **absence only**. An optional entry that is absolute,
traverses upwards with `..`, or resolves outside the repository is still
fatal — those are misconfigurations, not missing files. A non-boolean value
(`optional: "false"` is truthy in Python) is warned about and treated as
REQUIRED.

**Action: none, unless worktree creation is currently failing for you.** If it
is, the daemon log names the offending entry — and from this version so does
the hook's own stderr. Mark only the entries whose source may legitimately be
missing; leaving the rest alone keeps a genuine typo failing fast.

#### Removed Fields

None this release.

#### Priority-ordering constraint — read this if you hand-order Stop/SubagentStop

A Stop or SubagentStop handler registered **after** a terminal handler that
matches ordinary stops never runs — the chain stops dispatching once a
terminal handler fires. Both new cron handlers ship at priority 7 with
`terminal=False` specifically so they run ahead of `auto_continue_stop`
(priority 10) and `subagent_report_size_blocker` (priority 15), and
`tests/integration/test_stop_chain_terminal_shadowing.py` now enforces
that ordering in this repository.

**If your project's config hand-orders its Stop or SubagentStop handler
priorities, re-read that ordering after this upgrade.** A custom priority
that places either new cron handler after a terminal handler will make it
silently never run — no error, no log line, it just never gets a turn.
The default priorities above are correct out of the box; only a config
that has overridden Stop/SubagentStop priorities needs to check this.

### API / Output Changes

None — no JSON field was renamed or removed this release. (Compare
v3.64.0's `plan-qa --json` `level` → `severity` rename, which had a
mandatory post-upgrade task; this release has no equivalent.)

## Step-by-Step Upgrade Instructions

1. **Upgrade the daemon**:
   ```bash
   cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
   git -C .claude/hooks-daemon fetch --tags
   bash .claude/hooks-daemon/scripts/upgrade_version.sh \
     "$PWD" "$PWD/.claude/hooks-daemon" v3.65.0
   .claude/hooks-daemon/bin/hooks-daemon restart
   ```
2. **Re-check anything the Pre-Upgrade Checklist found** — a script or
   workflow that used a now-denied shape (B1–B13) needs a different
   command, not a retry.
3. **If you hand-order Stop/SubagentStop priorities**, re-read that
   ordering against the priority-ordering constraint above.
4. **Run the config-optimisation review** (Skill tool:
   `skill=hooks-daemon, args=optimise`) to see whether the two opt-in
   handlers (`routine_qa_sweep`, `session_actions_directive`) or the
   `host_hostname` status-line segment make sense for your project.
5. **Restart Claude Code** to activate the upgraded hooks.

## Verification

```bash
# 1. Version — the first heading names the installed version (there is no --version flag)
.claude/hooks-daemon/bin/hooks-daemon release-notes    # expect v3.65.0

# 2. Daemon healthy
.claude/hooks-daemon/bin/hooks-daemon status

# 3. destructive_git carries the five new rules (comment says "14 rules")
.claude/hooks-daemon/bin/hooks-daemon explain-handler destructive_git | grep -i 'rule'

# 4. New CLI verbs are present
.claude/hooks-daemon/bin/hooks-daemon find-plan --help >/dev/null && echo find-plan OK
.claude/hooks-daemon/bin/hooks-daemon session-actions --format json | head -c1 >/dev/null && echo session-actions OK

# 5. Doc-reconciliation list for this upgrade
.claude/hooks-daemon/bin/hooks-daemon check-truth-changes --from 3.64.0 --to 3.65.0
```

## Rollback

Config migration for this release is additive only (new keys, all
default-safe), so rollback is a plain version checkout:

```bash
cd .claude/hooks-daemon
git checkout v3.64.0
./scripts/install.sh
```

Rolling back restores the previous, looser behaviour for all sixteen
newly-denied shapes in [Breaking Changes](#breaking-changes) above, and
removes the eight new handlers and five new CLI verbs
(`find-plan`, `session-actions`, `run-routine`, `routine-qa`, `signal`).
