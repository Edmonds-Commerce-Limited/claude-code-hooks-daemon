# Upgrade Guide: v3.63.0 → v3.64.0

## Summary

This upgrade is a dogfooding-driven hardening pass: four false-positive/
false-negative classes in the command-judging guards are closed (a heredoc
or `-m`/`-F` message VALUE misread as a command, a multi-line command
convicted past its own end, a backslash-newline word-split that evaded every
guard, and a malformed config silently taking an event down), and the daemon
gains several new checks for staleness it could not previously see — a
second session upgrading its own installed daemon, a `git pull` that left
config or handler code unloaded, a reference clone read without pulling
first, and a QA/acceptance run graded by a daemon that predates the working
tree.

**One breaking change, with a mandatory post-upgrade task.**
`plan-qa --json` renames its `level` finding key to `severity`, matching
`docs-qa --json`. Anything parsing that verb's JSON output must be updated —
see Breaking Changes below and the post-upgrade task in this directory.

**No handler is removed from behaviour available to a client project.**
`daemon_restart_verifier` is removed as a *built-in* handler (it only ever
fired inside the hooks-daemon repository's own checkout — see the full
CHANGELOG entry) and is now dogfooded as a project handler in this
repository. A leftover `handlers.pre_tool_use.daemon_restart_verifier` key
in your config validates cleanly and is simply ignored.

## Version Compatibility

- **Source Version**: v3.63.0
- **Target Version**: v3.64.0
- **Minimum Claude Code Version**: Any
- **Supports Rollback**: Yes
- **Breaking Changes**: Yes — `plan-qa --json` key rename (see below)
- **Config Migration Required**: No. **Eleven** new handlers ship in total —
  not eleven plus a second population. All eleven are registered and enabled;
  what varies is whether the FEATURE behind one is switched on, and that is
  three config keys rather than a set of disabled handlers:
  `plan_workflow.close_requires_human_approval`,
  `worktree.merge_to_main_requires_human_approval` and `persistent_crons.enabled`
  all default `false`, leaving `plan_close_approval`, `merge_to_main_approval`
  and `persistent_cron_assertor` inert until you opt in. See
  `CLAUDE/UPGRADES/config-changes/v3.64.0.yaml`.

## Breaking Changes

### `plan-qa --json` renames `level` to `severity`

**What changed.** `docs-qa --json` and `plan-qa --json` described the same
finding shape under two different field names: `docs-qa` emitted
`"severity"`, `plan-qa` emitted `"level"`. `plan-qa --json` now emits
`"severity"` and nothing else. `docs-qa --json` is unchanged.

**Why.** This is not cosmetic. Two live names for one concept already
produced a defect: a reader that knows only one name silently drops every
finding from the other verb while still counting it toward the total — a
real QA wrapper counted `severity`, so every `plan-qa` finding fell out of
its severity split and the wrapper printed `3 findings (0 block, 0 advise)`,
a summary that contradicts itself.

**Why there is no deprecation window.** Emitting both spellings for a
release would make the two-names defect itself correct by policy for that
release, and would invite a new reader to key on the name about to
disappear. It also would not avoid the break — removing the key later is
the same breaking change, merely deferred. The daemon is installed inside
the consuming repository by an agent with write access, so it can migrate
call sites directly rather than merely announce the change; that migration
is the mandatory post-upgrade task in this directory.

**What you must do.** Anything reading `finding["level"]`,
`finding.get("level")`, `finding.level`, or `jq '.findings[].level'` from
`plan-qa --json` output should read `severity` instead. The values are
identical (`block` / `advise`) — this is a key rename and nothing more.

```diff
- level = finding["level"]
+ severity = finding["severity"]
```

**If you never parse `plan-qa --json`**, this does not affect you. The
human-readable (non-`--json`) output of `plan-qa` is unchanged.

## Changes Overview

### New Handlers

- **`self_matching_process_probe`** gains `R-WAIT-ON-WRAPPER-PID`: denies or
  advises a wait on `$!` behind a pid-hiding wrapper (`setsid`, `nohup sh -c`,
  `timeout`, `env`).
- **`lsp_noise_checker`** (SessionStart, priority 69) — reports a language
  server not excluding daemon-known non-project trees, one check per
  supported language present.
- **`plan_close_approval`** (PreToolUse, priority 43) and
  **`merge_to_main_approval`** (PreToolUse, priority 20) — opt-in human
  approval gates for closing a plan and for merging into main, behind
  `plan_workflow.close_requires_human_approval` and
  `worktree.merge_to_main_requires_human_approval` (both default `false`).
- **`merge_qa_report`** (PostToolUse, priority 34) — reports plan-QA/docs-QA
  findings a `git merge`/`pull`/`rebase` actually introduced.
- **`daemon_sync_after_merge`** (PostToolUse, priority 35) — reports when a
  pull left daemon config or handler code unloaded, or moved the tracked
  version marker out of step with the installed clone.
- **`daemon_upgrade_detector`** (UserPromptSubmit, priority 58) — reports
  when a *different* session/process upgraded this project's installed
  daemon while the running one still serves the old code. Dormant in
  self-install checkouts.
- **`reference_repo_freshness`** (PreToolUse, priority 39) and
  **`reference_repo_sweep`** (SessionStart, priority 71) — freshness
  gate/refresh for read-only reference clones under `untracked/repos/`,
  governed by the new top-level `reference_repos:` config block.
- **`issue_filing_gate`** (PreToolUse, priority 14) — requires
  `gh issue create` against the hooks-daemon repository to use a
  `hooks-daemon issue-report`-generated body.
- **`deployed_artefact_drift`** (SessionStart, priority 59) — reports a
  daemon-owned file deployed into your project that has DRIFTED from its
  template, and the command that repairs it. Every check that asks whether
  such a file is present already passed, because it is present; this one asks
  whether it still matches.
- **`persistent_cron_assertor`** (SessionStart, priority 70) — re-states the
  cron jobs your project declares under the new top-level `persistent_crons:`
  block, because Claude Code crons live in session memory and do not survive a
  session. Silent until you declare some (`persistent_crons.enabled` defaults
  `false`).

That is eleven new handlers. Two of them — the SessionStart pair immediately
above — will print advisories in a fresh session, so they are the ones to
expect output from first.

### Removed Handlers

- **`daemon_restart_verifier`** — removed as a built-in handler; it only
  ever fired inside the hooks-daemon repository's own checkout. Now a
  project-level handler in this repository's own
  `.claude/project-handlers/pre_tool_use/`. Migration: none — the key is
  registered in `RETIRED_HANDLERS` and a leftover config entry is ignored.

- `handlers.pre_tool_use.daemon_restart_verifier` → removed (no
  replacement needed outside this repository's own checkout; a leftover key
  is ignored, not an error).

### API / Output Changes

- `plan-qa --json` finding objects: `level` → `severity` (see Breaking
  Changes above).

## Step-by-Step Upgrade Instructions

1. **Upgrade the daemon**:
   ```bash
   cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
   git -C .claude/hooks-daemon fetch --tags
   bash .claude/hooks-daemon/scripts/upgrade.sh --project-root "$PWD" v3.64.0
   .claude/hooks-daemon/bin/hooks-daemon restart
   ```
2. **Run the mandatory post-upgrade task** in this directory's
   `post-upgrade-tasks/` — rewriting any `plan-qa --json` consumer's
   `level` reads to `severity`. Skip it only if the pre-upgrade checklist's
   grep above printed nothing.
3. **Run the config-optimisation review** (Skill tool:
   `skill=hooks-daemon, args=optimise`) to see which of the new opt-in
   handlers and config keys make sense for your project.
4. **Restart Claude Code** to activate the upgraded hooks.

## Verification

```bash
# 1. Version — the first heading names the installed version (there is no --version flag)
.claude/hooks-daemon/bin/hooks-daemon release-notes    # expect v3.64.0

# 2. Daemon healthy
.claude/hooks-daemon/bin/hooks-daemon status

# 3. plan-qa now emits severity, not level
.claude/hooks-daemon/bin/hooks-daemon plan-qa --sweep --json | grep -o '"severity"' | head -1

# 4. Doc-reconciliation list for this upgrade
.claude/hooks-daemon/bin/hooks-daemon check-truth-changes --from 3.63.0 --to 3.64.0
```

## Rollback

Config migration for this release is additive only (new opt-in keys), so
rollback is a plain version checkout:

```bash
cd .claude/hooks-daemon
git checkout v3.63.0
./scripts/install.sh
```

Rolling back restores the built-in `daemon_restart_verifier` handler (inert
outside this repository) and reverts `plan-qa --json` to the `level` key.
