# Upgrade Guide: v3.69.0 → v3.70.0

## Summary

This upgrade removes the project owner's approval stop from the pre-deploy upgrade gate, and adds a large
amount of guard correctness, venv hygiene and start-up work (see `RELEASES/v3.70.0.md` for every change in the
authors' own words). Two things are REMOVED and may need a config or script edit:

- The upgrade owner-approval tier: the `upgrade_approval_guard` handler, the `approve-upgrade` command, exit
  code 4 of the pre-deploy gate, the `upgrade-approvals/` markers and the rules `R-UPGRADE-APPROVAL-AGENT` and
  `R-UPGRADE-APPROVAL-ENV-BYPASS` (Plan 00503, GitHub #112).
- The `prune-venvs --all-except-current` flag. It exits with a message naming its replacement, `--stale`
  (Plan 00517).

No config key was renamed. A config that still names `upgrade_approval_guard:` keeps validating.

## Version Compatibility

- **Source Version**: v3.69.0 (any earlier v3 release upgrades the same way)
- **Target Version**: v3.70.0
- **Minimum Claude Code Version**: Any
- **Supports Rollback**: Yes
- **Breaking Changes**: Yes - the removals above
- **Config Migration Required**: No. Deleting the retired `upgrade_approval_guard:` key is optional housekeeping.

## Pre-Upgrade Checklist

- [ ] Back up `.claude/hooks-daemon.yaml`
  ```bash
  cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
  ```
- [ ] Look for scripts, docs or agent prompts that call a removed surface:
  ```bash
  grep -rn -e 'approve-upgrade' -e 'upgrade-approvals' -e 'all-except-current' \
    -e 'R-UPGRADE-APPROVAL' . --include='*.sh' --include='*.md' --include='*.yaml' \
    | grep -v '.claude/hooks-daemon/'
  ```
  If this prints nothing, neither removal affects you.

## Changes Overview

### Removed Handlers

- **`upgrade_approval_guard`** (PreToolUse)
  - Deprecation reason: the owner ruled the approval tier friction with no safety value. The threat model is a
    careless agent, not a hostile one, and an installed daemon older than the gate has no `approve-upgrade`, so a
    project could be stuck behind a long pipeline command just to say yes.
  - Alternatives: none needed. What used to need approval is now listed first, under "READ THIS FIRST: this
    upgrade is likely to break the project", in the listing the reading confirmation already stops on.
  - Migration: delete the `upgrade_approval_guard:` block from `.claude/hooks-daemon.yaml` when convenient. The
    key is registered as retired, so a leftover entry is accepted silently and nothing degrades.

### Removed Commands, Exit Codes and Flags

- **`hooks-daemon approve-upgrade`**, exit code **4** of the gate and the standalone gate's `approve` form are
  gone, as are the `upgrade-approvals/` markers. Read the "READ THIS FIRST" listing, carry out the pre-upgrade
  tasks it names, and re-run the upgrade with `--skip-reading-confirmation=<digest>` (exit 3 is the only stop).
- **`prune-venvs --all-except-current`** is removed. Use `prune-venvs --stale`, which removes only venvs it can
  prove stale (the legacy `untracked/venv/`, or a venv of this checkout whose readable `lock_hash` differs from
  the current source's) and never the venv in use.

### Behaviour Changes Worth Knowing

- An upgrade runs the gate from the TARGET release's code, so an upgrade from 3.68 or 3.69 to this release meets
  no approval stop. Only an upgrade whose target is still 3.68.0 or 3.69.0 prints the old stop; move the target
  to this release or later instead of running `approve-upgrade`.
- The gated-install receipt moved to `untracked/upgrade-gate/gated-install.json` (it was under
  `upgrade-approvals/`). A project that had one is asked for the reading once on a same-version re-run that
  claims the target is already installed; its first upgrade through this gate records the new receipt.
- A large jump (across a MAJOR boundary, or more than ten minor releases) prints `ADVICE:` to upgrade in phases,
  naming an intermediate release. It is advice only and never stops the upgrade.
- `hooks-daemon defences --json` now lists only the content and commit gates, so its row count drops sharply;
  use `explain-rule --list` for the full set of rules.

### Configuration Changes

The full manifest is `CLAUDE/UPGRADES/config-changes/v3.70.0.yaml` (`breaking: false`). New keys are default-safe;
`hooks-daemon check-config-migrations --from 3.69.0 --to 3.70.0` shows the ones that apply to your config.

## Step-by-Step Upgrade Instructions

### 1. Fetch the New Version

Do not check the new version out yourself: the upgrade checks it out, runs the pre-deploy gate against what is
installed, and puts the clone back if the gate stops.

```bash
git -C .claude/hooks-daemon fetch --tags
```

### 2. Run the New Version's Own Upgrade Script

```bash
tmp="$(mktemp)"
git -C .claude/hooks-daemon show "v3.70.0:scripts/upgrade.sh" > "$tmp"
bash "$tmp" --project-root "$PWD" v3.70.0
```

If the gate stops (exit `3`), follow "The pre-deploy gate" in `CLAUDE/LLM-UPDATE.md` and re-run the same command
with `--skip-reading-confirmation=<digest>`. There is no exit `4` in this release.

### 3. Clean Up the Retired Handler Key (optional)

```yaml
# Delete this block if it is present:
handlers:
  pre_tool_use:
    upgrade_approval_guard:
      enabled: true
```

See `config-before.yaml` and `config-after.yaml` in this directory.

### 4. Restart the Daemon

```bash
.claude/hooks-daemon/bin/hooks-daemon restart
```

### 5. Carry Out the Post-Upgrade Tasks

```bash
.claude/hooks-daemon/bin/hooks-daemon check-post-upgrade-tasks --from 3.69.0 --to 3.70.0 --project-root "$PWD"
```

Three tasks ship in `post-upgrade-tasks/`: clear unproven venvs (recommended), commit the expected version and
`.claude/provision.sh` (recommended), tune the plan fact-checker (optional).

## Breaking Changes

### Breaking Change 1: the upgrade owner-approval tier is gone

**What broke**: `hooks-daemon approve-upgrade`, exit code 4, the `upgrade-approvals/` markers, the
`upgrade_approval_guard` handler and its two rule IDs no longer exist.

**Why**: see "Removed Handlers" above.

**Who is affected**: a script, runbook or agent prompt that runs `approve-upgrade` or branches on exit code 4;
a config that names `upgrade_approval_guard:` (still valid, now inert).

**Migration Steps**:

1. Remove any `approve-upgrade` step from your upgrade runbook.
2. Treat the "READ THIS FIRST" listing as the whole gate: read it, do the pre-upgrade tasks it names, re-run
   with `--skip-reading-confirmation=<digest>`.
3. Optionally delete the `upgrade_approval_guard:` block from your config.

**Rollback**: restore `.claude/hooks-daemon.yaml.backup` and re-run the upgrade script for v3.69.0.

### Breaking Change 2: `prune-venvs --all-except-current` is removed

**What broke**: the flag exits with a message instead of pruning.

**Why**: "every venv except the current one" removed venvs the code could not show were stale, and the "current"
venv was computed from the project root rather than the daemon directory, so it could select the venv in use.

**Who is affected**: a script or cron that passes the flag.

**Migration Steps**: replace it with `prune-venvs --stale` (preview with `--dry-run`). Venvs the code cannot prove
stale are listed by `list-venvs` as UNPROVEN and removed one at a time with `prune-venvs --unproven <path> --force`.

## Verification Steps

```bash
# The first heading names the installed version
.claude/hooks-daemon/bin/hooks-daemon release-notes    # expect v3.70.0

.claude/hooks-daemon/bin/hooks-daemon status

# The retired rule is gone from the registry
.claude/hooks-daemon/bin/hooks-daemon explain-rule R-UPGRADE-APPROVAL-AGENT   # expect: unknown rule ID

# The doc-reconciliation list for this upgrade
.claude/hooks-daemon/bin/hooks-daemon check-truth-changes --from 3.69.0 --to 3.70.0
```

## Rollback Instructions

1. Restore the config: `cp .claude/hooks-daemon.yaml.backup .claude/hooks-daemon.yaml`
2. Re-run the upgrade script targeting the previous version, which sends a downgrade through the same gate:
   ```bash
   bash .claude/hooks-daemon/scripts/upgrade.sh --project-root "$PWD" v3.69.0
   ```
   The v3.69.0 gate lists nothing for a downgrade, so the rollback proceeds without a reading confirmation or an approval.
3. Restart: `.claude/hooks-daemon/bin/hooks-daemon restart`
