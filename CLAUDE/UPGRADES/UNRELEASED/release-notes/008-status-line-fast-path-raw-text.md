# Callout: the status line has a cheap tick when a relay or nc client is configured

**Plan**: 00542
**Audience**: operators

Every status-line tick used to source the 3,800-line `.claude/init.sh` and start a fresh `python3` before any byte reached the daemon (about 0.08 CPU-seconds per tick). The generated `.claude/hooks/status-line` now carries a fast path, built from bash builtins only, that runs first: it asks the daemon's per-event status socket for raw text and prints the reply (about 0.005 CPU-seconds, measured with the relay binary). It uses only the clients your `daemon.transport` config enables: the relay binary when `relay_enabled` is true and the binary is executable, or `nc` when `nc_enabled` is true and the install probe recorded `HOOKS_DAEMON_NC_UNIX_CAPABLE=1`. With both off, or with no client available (a missing relay binary included), the forwarder is unchanged and nothing is faster. Any failure (no socket, refused, timeout, empty reply, a payload that is not a JSON object) falls through to the existing path with stdin intact, so `DAEMON FAILED`, the loading text and daemon start-up behave as before. A running daemon of the wrong version still answers the fast path; the legacy path's version handling runs only on a fall-through. Regenerate forwarders with the normal upgrade or `transport relay on|off`. (reported as issue #131)
