# Callout: the defences listing carries defect classes, and more denials print an identifier

**Plan**: 00484
**Audience**: everyone

`hooks-daemon defences --json` now lists only the content and commit gates, which are the Defence Before Fix Defences, with a `defect_class` on every row, so the row count drops sharply (about 135 rows to about 30 in this repository) and a script that counted rows or looked a rule up there must use `explain-rule --list` for the full set. A project handler drops out of the listing unless it declares a `defect_class`, a member of the closed `DefectClass` enum (see CLAUDE/HANDLER_DEVELOPMENT.md); the post-write linters (`lint_on_edit`, `validate_eslint_on_write`) and `tdd_enforcement` are not Defences, while `staged_lint_gate` and `github_auto_close_keywords` are. `explain-rule` and `explain-handler` say whether a rule is a Defence or a guardrail instead of calling every rule a defence. Five more handlers (`dispatch_declaration` in strict mode, `subagent_report_size_blocker`, `subagent_report_path_verifier`, `cron_stop_enforcer`, `cron_subagent_stop_enforcer`) print a `BLOCKED [R-...]` identifier, as do the fail-closed denies of `destructive_git` (new `R-GIT-DESTRUCTIVE-UNREADABLE`), `sensitive_content`, `staged_lint_gate`, `conflict_marker_commit_gate`, the three remote-docs gates, `usage_pause_stop_gate` and the `auto_continue_stop` stand-in block (new `R-STOP-STAND-IN-MISSING`). `explain-rule` resolves the plan-QA and docs-QA check IDs such as `plan-doc-size`, and `explain-rule --list` ends with a line pointing at `explain-rule <ID>`, so a script that reads that listing as tab-separated rows should skip its last line. The generated CLAUDE.md block also ends each promoted handler's section with an `IDs:` line.
