# Callout: every typed `/goal clear` is attributed to the ccy supervisor or the human

**Plan**: 00501
**Audience**: operators

Claude Code records a typed `/goal clear` (or `stop`, `off`, `reset`, `none`, `cancel`) identically whoever typed it. The ccy supervisor now writes a `<session>.goal-clear-injected` record in the context-sidecar directory immediately before it types a clear. If that record cannot be written, the supervisor does not type the clear and logs `noop: goal clear NOT typed: attribution record could not be written` to its `decision.log`. On the next Stop, `goal_loop_detector` finds each new clear in the transcript and logs a `goal-clear` line to the session-mode transition log. That line's `detail` is `supervisor` when a fresh matching record exists (the record is consumed). A clear stamped before the record was written is never the supervisor's, so a human clear typed just ahead of a pending supervisor clear stays `human` (Plan 00474 N534). Otherwise it is `human`, or `supervisor-assumed` when the record could not be read. In the `supervisor-assumed` case the agent is also told at its next prompt to ask the human to type `/goal clear` again if they typed it. A clear is attributed once, including after a daemon restart. Three limits apply. A clear typed while Claude Code is mid-turn is not attributed. The clearing aliases come from the shipped binary and were not observed in a transcript. With `goal_loop_detector` disabled, nothing attributes clears. The supervisor change takes effect when its worker hot-reloads.
