# Callout: a closed, unmerged pull request's remote branch can go through the no-value route

**Plan**: 00474
**Audience**: everyone

A remote branch whose work is found nowhere else had no agent route at all: `branch-reject request` reviewed local branches only, and `delete-branch --remote-only` deletes only what the remote-delete proof accepts (merged, or holding no file found nowhere else). `branch-reject request <name> --remote-only` now reviews the REMOTE copy (`branches.remote`) of such a branch, with the same independent reviewer gate and the same daemon-composed prompt (R-BRANCH-REJECT-DISPATCH). It is admitted only when all of these hold: the name is literal and is not the default, exempt or protected; `refs/remotes/<remote>/<name>` exists; the remote's own default is confirmed (`refs/remotes/<remote>/HEAD`, or `branches.default`); no worktree has a local branch of that name checked out; the remote-delete proof does NOT accept it (a merged branch keeps the existing route); the fetch URL and every push URL hold the branch and the default at the commits the tracking refs record; and `gh pr list` shows a pull request of this repository headed by the branch that is CLOSED (not open, not merged) whose head commit is the remote tip. An unreadable PR state (gh failing, bad JSON, a full page of results) refuses. The prompt names the PR by number only. A no-value verdict for exactly that remote tip then lets `delete-branch --remote-only <name>` delete it: every check above is re-read, the verdict must be of the remote scope (a local verdict never unlocks a remote delete, nor a remote verdict a local one), unexpired, unused and for that branch and tip, a recovery bundle of the tracking ref is written under `<bundle_dir>/remotes/<remote>/` and verified, the ledger line and single-use claim are written before git, and the push carries `--force-with-lease` on the judged tip. The output prints the bundle and both restore lines (`git fetch <bundle> refs/remotes/<remote>/<name>:refs/remotes/<remote>/<name>`, then `git push <remote> <tip>:refs/heads/<name>`). Ledger lines and refusals of a remote removal carry a `remote` field; local records are unchanged byte for byte. A local `branch-reject request` refused for a branch with a remote copy now names the `--remote-only` form.
