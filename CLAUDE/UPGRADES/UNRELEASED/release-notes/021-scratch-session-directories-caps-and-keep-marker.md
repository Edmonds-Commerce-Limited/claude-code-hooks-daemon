# Callout: each session gets its own scratch directory, scratch has size caps, and only a human keeps an entry

**Plan**: 00627
**Audience**: everyone

Every session now starts with its own scratch directory, `untracked/scratch/s-<UTC>-<first 8 of the session id>/`, which holds a manifest recording its owner, birth and entries. SessionStart announces it, and `bin/hooks-daemon scratch new <name>` makes an entry inside it. A new entry made directly in the scratch root gets an advisory, because nothing records who made it or why (`scratch_unowned_entry`; set `scratch.sweep.unowned_entry: block` to deny it, or `off`). Scratch also has size caps (`scratch.caps`: directories, bytes, entries and a share of the link index's directory cap), each with a warn and a block figure. At the block figure, a Bash command that creates a directory tree under scratch (`mkdir`, `git clone`, `git init`, `git worktree add`, `cp -r`, `tar -x`, `mktemp -d`) is denied under `R-SCRATCH-CAP` until `scratch-sweep --apply` has run. A file write is never denied. When only LIVE, KEPT or PROTECTED entries hold scratch over the cap, you get an advisory instead, so nothing is stranded. `scratch.caps.mode: advise` turns the deny into an advisory. The caps read a cached inventory, `untracked/scratch-inventory.json`. It is refreshed at SessionStart, after `--apply`, and in the background after each directory-creating command (`scratch_inventory_refresher`). A `.scratch-keep` file keeps its entry from the sweep forever, so creating, changing or removing one is a human's decision. An agent that tries it is denied under `R-SCRATCH-KEEP-MARKER` (`scratch_keep_marker_guard`).
