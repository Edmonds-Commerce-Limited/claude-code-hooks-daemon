# Callout: `git checkout <commit> <path>`, `git checkout <path>` and xargs-fed checkouts are judged

**Plan**: 00474
**Audience**: everyone

R-GIT-CHECKOUT-DISCARD keyed on the `--` separator, so `git checkout <commit> <path>` (which restores the path from the commit exactly as the dashed form does) and `git checkout <path>` (which restores it from the index) were allowed even over unsaved local changes, and so was `... | xargs git checkout <commit> --`, whose paths arrive on stdin. Git reads the undashed form by resolving the first operand, and the guard now reads it the same way. `git checkout <commit> <paths>` gets the SAME allowance as `git checkout <commit> -- <paths>` when the first operand is one literal revision that resolves to a tree and names no path in the working tree or the index; when it is also a path, git refuses it as ambiguous, and when it does not resolve, git restores every operand from the index, so both are denied. A one-operand `git checkout <name>` stays allowed when `<name>` is a commit (a branch switch, even when a file has the same name) or names no path at all (the remote-branch shortcut); when it names a path it is a restore from the index and is denied, as `git checkout -- <path>` is. A checkout with an option a branch switch does not use (`-p`, `--ours`, `--no-overlay`, `--pathspec-from-file`, an abbreviation) is judged as a path checkout and denied. A `git checkout` or `git restore` run by `xargs`, `parallel`, `find`/`fd`, a prefix that is not a plain wrapper (`sudo`, `env`, `timeout`, `nice`, ...), or `env`/`sudo` with any option (`env -C sub` moves the directory) is denied whatever its form, including `echo main | xargs git checkout`. A fed `git restore --staged` that touches only the index stays allowed, as the unfed one is. A checkout inside backticks is judged as one inside `$( )` is. A one-operand switch may carry output-only settings (`X=1`, `-c advice.*`, `--no-pager`, `--conflict=<style>`, stdin); one whose repository cannot be placed (a `GIT_*` variable outside a short safe list, `HOME`, any other `-c` or global option, an unresolvable `cd`) is denied. Also: `git checkout-index -f` (and `-af`, `--force`), which overwrites worktree files from the index and matched no rule, is now denied under R-GIT-CHECKOUT-FORCE; without `-f` git refuses to overwrite an existing file and it stays allowed. Three gaps every destructive-git rule had are closed too: an abbreviated long option (`git reset --ha`, `git clean --forc`, `git checkout --fo`, `git switch --di`, `git restore --staged --wor`, `git checkout-index --f`) is read as the option git takes it for; `$'...'` quoting (`git $'checkout' -- f`) is decoded as bash decodes it; and an alias defined on the command line (`git -c alias.co=checkout co f`) is denied under R-GIT-DESTRUCTIVE-UNREADABLE. An alias in a config file is not yet seen (ledger N771). A one-operand switch (`git checkout <branch>`, `git checkout -`) is now also proven before it is allowed. Git writes over an ignored file the target tracks, removes an untracked symlink standing where the target has a tracked directory, and has been seen to drop a staged edit on a path the target removes. So the switch is denied when anything git does not track sits where it writes, or when any path it touches holds a staged or unstaged change or a hiding index flag. A switch that git would carry local changes across, on paths the target does not touch, stays allowed. The switch is checked against the commit checkout actually switches to, not the one `rev-parse` names: a local branch, the single merge base for `A...B`, and for a name that is no commit and no path, the one `refs/remotes/<remote>/<name>` the shortcut forks. **Deliberately denied now, even when nothing would be lost:** a one-operand switch whose name falls outside the plain ASCII spelling (`fé`, `a,b`, `a=b`, `a%b`, `a#b`). The same goes for a name that is both a branch and a tag; a commit reached through a ref outside `refs/heads`, `refs/tags` and `refs/remotes`; and an `A...B` with no single merge base. The remote-branch shortcut is denied while any remote has a fetch refspec other than `+refs/heads/*:refs/remotes/<remote>/*`, or when more than one ref (or a ref under an unconfigured remote) ends in that name. `--recurse-submodules` is denied, as is a switch that moves a submodule while `submodule.recurse` is set. A checkout or restore operand bash would expand (`{a,b}`, `{1..3}`, a leading `~`) is denied too, in the dashed form as well (`git checkout HEAD -- {f,g}.txt` was allowed before), and so is a quoted file name with such braces. A long path list is now read in batched git calls: a 2,000-path `git checkout <commit> <paths>` takes about 0.4 s. `git reset --merge` (and its abbreviations), which rewrites the working tree and can lose an ignored file, is now denied under R-GIT-RESET-HARD. `git reset --keep` stays allowed by owner ruling A6. A switch may also carry `-c core.quotepath=...`. Still open (ledger N771): `git switch` is not read, `git read-tree -u` matches no rule, and a CRLF file that `core.autocrlf` normalises can be rewritten by a switch that reads it as clean.
