# Callout: an agent may delete an unmerged remote branch that holds nothing unique

**Plan**: 00594
**Audience**: operators

`git push --delete` of a remote branch used to be allowed for an agent only when the branch was merged into the default or an integration line. It is now also allowed when git proves the branch holds nothing unique: every file the branch adds or changes, against its merge base with the remote default, has the same mode and blob at the same path on the remote default's tip or on an integration line's remote tip. Every tip the proof relies on is a remote-tracking ref, never the local default, and `git ls-remote` must confirm the remote still holds each one at the sha the proof read, so content only on an unpushed default, or on a line moved since the last fetch, proves nothing. The remote default is always confirmed this way, even when an integration line holds every file, because it sets the merge base. When the remote has a push URL that names a different repository from its fetch URL, every push URL must also report each deleted branch and each tip the proof relies on at the same sha, or the delete is refused. The tier judges the branch's tip content only: a file the branch added and later changed or removed loses its intermediate revisions when the branch goes, so `surviving-content` does not mean "no history lost". A file the branch deletes is not content, a branch that adds or changes no file is never proven by this tier, and a branch deleted in the same command never counts as a surviving ref. The agent's own claim is never an input, and a branch holding even one file found nowhere else is refused with the files named. The tier is judged afresh on each call and is never cached. No configuration is needed.

`bin/hooks-daemon delete-branch --remote-only <name>...` is the leased route to the same proof: it deletes each remote branch the proof accepts under a lease on the proven tip (a commit pushed after the proof makes git refuse), prints `git push <remote> <sha>:refs/heads/<name>` to restore it, and refuses, naming the reason, every branch the proof does not accept. `--protected-ref` and `--dry-run` do not apply to it. The runnable remote-delete lines printed by `branch-sweep --clean` and the post-merge cleanup now name this command instead of a bare `git push --delete`.
