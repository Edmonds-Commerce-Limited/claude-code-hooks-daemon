# Callout: a squash-merged or cherry-picked remote branch now counts as merged

**Plan**: 00594
**Audience**: client projects

The proof that a remote branch is merged used to be ancestry only, so a branch merged by squash (several commits into one), by a renamed pull request, or by cherry-pick stayed "open" and its remote delete was refused. The proof now tries ancestry, then one net-change check, all offline. The branch's NET change is its diff against `merge-base(default, tip)` with rename detection off. The branch counts as merged when SOME commit on the default branch's first-parent line, after that merge base and up to the default's tip, has a tree that holds the net change: every path the branch adds or modifies has the same blob and mode, and every path it deletes is absent. The content is then permanently in the default branch's history, so deleting the remote branch loses nothing, even if the default has since changed those files again or reverted the work. The candidates are the default's tip plus the first-parent commits that touched the branch's changed paths, checked with one batched lookup each and stopping at the first match; more than 50 candidates is unproven, never proven. Ancestry is sufficient on its own; patch-id (`git cherry`) only labels how the change arrived, and never proves a branch by itself. A branch whose net change is empty (only empty commits, or changes that cancel out, such as a park branch) is unproven, as is one that only deletes (while the default still has the file), renames, copies or changes the mode of a file, reverts the default's change to an older version, changes a path whose name is not valid UTF-8, or whose change no default commit ever held. The proof runs every git call from the repository top level, so a command typed in a subdirectory is judged the same. The `git push --delete` guard, `branch-sweep --clean --remote` and the branch-creation cap all read the same proof, so an agent may delete such a branch, the sweep deletes it behind its recovery bundle, and it no longer counts against the open-branch cap once the proof has run (branch creation reads cached proofs only and never computes one). A branch with even one change the default branch never took stays unproven. Results are cached by algorithm version (v3), tip and default sha in `untracked/branch-inventory/cache.json` (new `proofs` key; entries written by an earlier algorithm are ignored and pruned on the next save). The local `delete-branch` command is unchanged: it still bundles first and accepts content that is merely recoverable.
