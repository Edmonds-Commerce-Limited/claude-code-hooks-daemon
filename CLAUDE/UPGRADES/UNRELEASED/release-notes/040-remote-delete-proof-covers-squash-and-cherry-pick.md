# Callout: a squash-merged or cherry-picked remote branch now counts as merged

**Plan**: 00594
**Audience**: client projects

The proof that a remote branch is merged used to be ancestry only, so a branch merged by squash (several commits into one), by a renamed pull request, or by cherry-pick stayed "open" and its remote delete was refused. The proof now tries ancestry, then one net-change check, all offline: the default branch's tip must hold the branch's NET change, which is its diff against `merge-base(default, tip)` with rename detection off. Every path the branch adds or modifies must have the same blob and mode at the default's tip, and every path it deletes must be gone from it. Ancestry is sufficient on its own; patch-id (`git cherry`) only labels how the change arrived, and never proves a branch by itself, because the default branch may have reverted the patch since. A branch whose net change is empty (only empty commits, or changes that cancel out, such as a park branch) is unproven, as is one that only deletes, renames, copies or changes the mode of a file, reverts the default's change to an older version, or whose change the default later overwrote or reverted. The `git push --delete` guard, `branch-sweep --clean --remote` and the branch-creation cap all read the same proof, so an agent may delete such a branch, the sweep deletes it behind its recovery bundle, and it no longer counts against the open-branch cap once the proof has run (branch creation reads cached proofs only and never computes one). A branch with even one change the default branch never took stays unproven. Results are cached by algorithm version, tip and default sha in `untracked/branch-inventory/cache.json` (new `proofs` key; entries written by an earlier algorithm are ignored and pruned). The local `delete-branch` command is unchanged: it still bundles first and accepts content that is merely recoverable.
