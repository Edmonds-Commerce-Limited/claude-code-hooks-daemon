# v3.39.0 — multithread status-line indicator

**Release date**: 2026-07-13
**Type**: MINOR release

## Summary

v3.39.0 adds a new `🧵 Y/X` status-line segment (Plan 00158) that shows the
current thread's stable rank among the live Claude Code sessions sharing one
daemon — useful for Agent View background-thread workflows. It ships
default-ON but stays silent when only one session is live, so single-thread
users see no change. Also includes Plan 00157 review followups.

No breaking changes. Fully backwards compatible — no new required config
keys, no changed defaults.

## Highlights

- **🧵 multithread indicator.** New `MultithreadIndicatorHandler` renders as
  the first status-line segment (priority 2), showing the current thread's
  stable rank (`Y`) among the live sessions (`X`) sharing one daemon.
  Backed by a pure `thread_registry` module — per-session heartbeat keyed by
  `session_id`, atomic tmp+`os.replace` writes, stale-session pruning, and
  stable ranking by first-seen order.
- **Correctly excludes noise.** Pre-warmed background "spare" PTY hosts and
  agent/subagent sessions (any session with a truthy `agent_type`) are
  excluded so they never inflate the reported count.
- **`refreshInterval: 10` in the recommended `statusLine` settings.** Keeps
  the status bar live — and the multithread count accurate — while idle on
  a background agent.
- **New `session_name` protocol field.** Surfaces the Claude Code session
  name where available, for status-line and diagnostic use.
- **Toggleable `daemon.payload_capture` debug mechanism.** Config-driven,
  off by default, used to dogfood the Agent View / status-line contract
  during development of this feature.
