# Release v3.72.1 - Merged Release Branches Deletable, optimise Suggests claudeMdExcludes

**Release Date:** 2026-11-05
**Type:** Patch Release

## Summary

A patch release on the branch-hygiene line. `optimise` now suggests `claudeMdExcludes` for worktrees kept under the project root, a merged integration line such as `release/*` can be deleted by an agent, and removing a worktree no longer refuses over a seeded symlink. Three release-note callouts are folded into Highlights below, in the authors' own words.

## Read this first

- **No breaking change.** No config-changes manifest, no truth-changes manifest, no pre-upgrade task and no post-upgrade task ships, so the pre-deploy gate adds no stop of its own.
- **If you merge feature branches into a release branch (`release/*`), declare it:** `branches.integration_lines: ["release/*"]` in `.claude/hooks-daemon.yaml`. See the third callout below.
- **Upgrade guide:** `CLAUDE/UPGRADES/v3/v3.72.0-to-v3.72.1/v3.72.0-to-v3.72.1.md`.

## Highlights

#### optimise now suggests `claudeMdExcludes` for worktrees under your project

_Plan 00563 · Audience: client projects_

`/hooks-daemon optimise` now checks for git worktrees kept under the project root (`untracked/worktrees/`, `.claude/worktrees/`, or any path `git worktree list` reports inside the root). When no `claudeMdExcludes` glob in `.claude/settings.json` or `.claude/settings.local.json` covers them, it prints an unscored suggestion with the exact globs to add (for example `**/untracked/worktrees/*/CLAUDE.md`). Without them a sub-agent working in such a worktree loads your root `CLAUDE.md` twice, up to about 30k tokens (reported as issue #156). It only suggests: nothing writes the setting unless you confirm at the apply prompt, and it stays silent when the globs are already present or no worktree lives under the root.

#### removing a worktree no longer refuses over a seeded symlink

_Plan 00474 · Audience: client projects_

The `git worktree remove` guard (R-GIT-WORKTREE-REMOVE-FORCE) used to list an ignored symlink, such as a file the `worktree_create` handler seeds with `default_mode: symlink`, as content the removal would lose. That refused to remove a clean, merged worktree. A symlink is now never counted: removal only unlinks it and its target outside the worktree survives. Real ignored files and non-empty ignored directories still block as before.

#### a merged release branch can now be deleted; release-branch workflows should declare it as an integration line

_Plan 00474 · Audience: client projects_

If you merge feature branches into a release branch (`release/*`), set `branches.integration_lines: ["release/*"]` in `.claude/hooks-daemon.yaml`. Feature branches merged into such a line are then treated as merged by the remote-delete guard (R-GIT-PUSH-DELETE-REMOTE), the WorktreeRemove cleanup and the post-merge cleanup, and the line itself is never counted toward the branch caps.

Previously an integration line was refused by name everywhere, so the release branch's own `git push origin --delete release/x` stayed denied even after it was merged. It is now judged by the same proof as any other branch, against the DEFAULT branch only: a line whose remote-tracking tip is an ancestor of the default branch (and whose live remote tip `git ls-remote` confirms) may be deleted by an agent, locally (`delete-branch`, the WorktreeRemove cleanup) and on the remote. A line that is not yet merged into the default branch is still refused, with a message saying so, and being merged only into another integration line does not count. The default branch, `branches.exempt`, `branches.protected_names` and tags are refused exactly as before, and `branch-sweep --clean` still never offers an integration line.

#### Maintenance

`scripts/release/check_release_ci.py` is now executable. This changes nothing for an installed project.

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.72.1 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon. Never hand-build a venv — the resolver refuses the
# retired pre-v3.7.0 layout.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

# Rebuilds the venv and reinstalls the package for the target version. Runs the
# target's own upgrade.sh: the installed one may predate the pre-deploy gate.
tmp="$(mktemp)"
git -C .claude/hooks-daemon show "v3.72.1:scripts/upgrade.sh" > "$tmp"
bash "$tmp" --project-root "$PWD" "v3.72.1"

.claude/hooks-daemon/bin/hooks-daemon restart
```
