# v3.56.0 — Model-Downgrade Resilience, Secret-File Hygiene, and a Generic Agent-Install Subsystem

This release closes the loop on several handlers that shipped in v3.55.0
(`secret_file_guard`, `goal_injection`, `skill_opportunity_detector`) with
live-production hardening, and adds a new family of handlers around a single
theme: what happens when Anthropic's safety classifier silently substitutes
the session's model. Five new handlers ship — one on by default
(`downgrade_indicator`, a status-line warning), four opt-in
(`model_fallback_detector`, `flaggable_work_advisor`,
`flaggable_content_channel_guard`, `quarantine_artefact_read_guard`) — plus a
new SessionStart hygiene checker for protected files, and a generic,
versioned agent-install subsystem (`hooks-daemon agents`) that deploys the
first agent asset built for this theme, `hooks-daemon-opus-security`.

No breaking changes. No handler was removed or renamed, and no
`@abstractmethod` was added to the `Handler` base class — every project
handler continues to work unmodified.

## Added: `downgrade_indicator` — enabled by default

A new status-line handler makes a silent model-family downgrade visible on
every render, self-detected purely from the model id Claude Code reports — no
dependency on the ccy PTY supervisor or any external signal. It tracks each
session's high-water model-family rank (`haiku` < `sonnet` < `opus` < `fable`)
and renders a compact warning (`⚠️fable→opus`) only while the current render
ranks below that high water. A `↓N↑M` episode-tally suffix makes a session
stuck flip-flopping between downgrade and recovery obvious at a glance —
silent, and costs nothing, on a healthy session.

## Added: `model_fallback_detector` — ships disabled, opt-in

A SessionStart advisory that scans the session transcript for the platform's
own `model_refusal_fallback` record, and — new this release — distinguishes
an ACTIVE fallback (no later assistant turn returned to the original model)
from one that has already RECOVERED, so the alert only demands a session
restart when the substitution is actually still in effect. Dedupe state now
persists to disk and survives a daemon restart, closing a bug where a restart
previously re-advised every historical record and re-wrote its diagnostic
snapshot on every restart. It ships off by default: the continuous "am I
downgraded?" signal is better served by `downgrade_indicator` above, which is
on by default. This detector's unique value is a secret-redacted diagnostic
snapshot of the fallback record plus a bounded window of preceding transcript
records, for tuning a project's flaggable-work delegation config.

## Added: the flaggable-work boundary — three opt-in handlers

Three PreToolUse handlers close the loop between *deciding* work is
safeguard-flaggable and actually keeping it out of the main context, all
ships-disabled and gated on the same `flaggable_path_globs` convention:

- **`flaggable_work_advisor`** reminds an agent to delegate the whole
  sub-task to a quarantine subagent *before* opening flaggable content —
  deciding from the path or framing, never by reading first.
- **`flaggable_content_channel_guard`** DENIES the one channel advice alone
  cannot close: a content-revealing git/grep shape (`git diff`, `git show`,
  `git log -p`, `grep`/`rg`/…) over a flaggable path pulls its content into
  context inside a routine command's output, with no deliberate `Read` at
  all. A plain `git status` or `git add <path>` (no `-p`) stays allowed. No
  escape hatch — an agent that could type its own justification would have
  self-authorised the disclosure this guard exists to prevent.
- **`quarantine_artefact_read_guard`** enforces the two-file quarantine-agent
  artefact contract by pattern: a `*-opus-security-DETAIL*` artefact can
  never be read back into the coordinator's context, by `Read`, `Grep`, or a
  Bash command whose shape reveals file content (`cat`, `head`, `strings`, an
  interpreter one-liner, …). It ships pre-seeded with that glob, so enabling
  it needs no configuration. Writing the artefact, and the subagent's own git
  cycle for it, stay unaffected.

## Added: supervisor effort-restore and flip-flop flag-cleaning

The ccy PTY supervisor now closes the other half of the downgrade story: when
it detects a model-family downgrade across ticks, it injects a coupled
`/effort xhigh` correction (skipped when the live effort is already
`xhigh`/`max`), with the same confirming Enter as its existing `/model`
injection, and a visible audit-trail chat message after every silent
injection so the correction is never invisible. When a downgrade *recurs* —
the session's context keeps re-tripping the classifier despite the restore —
a new opt-in flip-flop flag-cleaning `/compact` (`CCY_FLAG_COMPACT=1`, ships
off) fires once, instructing Claude to summarise the sensitive material at a
high level so the compacted context stops re-triggering the classifier and
the restore actually sticks. Capped per process with a flip-flop backoff and
audit-trailed like every other supervisor injection.

## Added: generic agent-install subsystem + `hooks-daemon agents` CLI

Agent deployment graduates from one ad-hoc case
(`hooks-daemon-plan-dedupe-scout`) to a first-class, generic subsystem: a
registry of daemon-shipped agents, a version/md5 ledger across every shipped
revision, absent/current/outdated/customised classification, and a
deploy/remove engine that never clobbers a customised copy. `hooks-daemon agents list|status|install|remove` inspects and manages deployment state
directly. Historic md5s for the existing dedupe-scout agent were harvested
from git history so existing pristine installs classify correctly and stay
upgradeable.

The first new payload built on this subsystem is `hooks-daemon-opus-security`,
a quarantine-executor sub-agent for safeguard-flaggable security work: the
caller delegates the whole sub-task before reading the sensitive content and
gets back only a clean `SUMMARY` artefact (the paired `DETAIL` artefact is
never read by the coordinator). It is gated on `agents.opus_security.enabled`
(ships `false`, opt-in) and deployed/refreshed by the daemon on start and via
`hooks-daemon agents install`; disabling the key produces a removal advisory
rather than an automatic delete.

## Added: `secret_file_hygiene_checker` — enabled by default

A new SessionStart advisory closes the on-disk half of `secret_file_guard`'s
protection (v3.55.0): for every path matching the effective guard globs that
exists on disk, it advises — never blocks — when the file is not gitignored,
is git-tracked, or is group/world-readable. Enumeration uses `git ls-files`
(three cheap index reads, no filesystem walk) and `stat()` only; content is
never opened, so the advisory cannot leak what it protects.

## Changed: `skill_opportunity_detector` no longer shells out to a model

`bin/hooks-daemon skill-scan` (v3.55.0) previously sent one bounded headless
`claude -p --model haiku` call to judge its clustered evidence. That
shell-out is now gone: the report embeds the judging rubric directly, and an
in-session subagent dispatched at the report appends the judgement under a
`## Findings` heading. No CLI authentication is needed for the scan any more.
The `options.model` config key it used to configure has nothing left to
configure and is now silently ignored — non-breaking, delete the line at your
convenience.

## Fixed

- **`secret_file_guard` closed a glob-truncation leak, then a false-positive
  its own fix introduced.** A trailing- or leading-wildcard truncation of a
  protected filename could slip past the token heuristic and leak the file; a
  bidirectional literal-edge overlap check closes it. The first cut of that
  check then over-blocked ordinary commands sharing an unrelated 2+ character
  boundary with a protected stem; fixed by gating each overlap direction on
  the token actually carrying a wildcard at that edge.
- **A protected path's content could still reach a capture file or a lint
  diagnostic.** `payload_capture` now excludes the whole event when hook
  input names or Bash-mentions a protected path, and `lint_on_edit` /
  `staged_lint_gate` skip a protected path before running any lint command.
- **`lsp_enforcement`'s `block_once` mode is now scoped per session** —
  previously a block recorded against one session could suppress the
  advisory in another.
- **`generate-docs` and `generate-playbook` crashed on a handler config with
  an empty/omitted `priority` key.** `config.handlers.model_dump()`
  materialises an unset `priority` as an explicit `None`, which reached the
  sort comparison unguarded. A shared `resolve_priority()` helper now backs
  both generators and the pre-existing runtime dispatch guard.
- **A goal-injected plan had no sanctioned way to stop on a total block.**
  The built-in work-until-complete `/goal` line named only "until
  completion"; it now names two terminal conditions — complete, or totally
  blocked — so stating the blocker is a valid, satisfiable stop.
- **The `hooks-daemon-opus-security` agent's own frontmatter description was
  contaminating the calling agent's context** with the enumerated trigger
  vocabulary it exists to keep out of that context; rewritten in neutral
  operational language (template v1.1.0).
- **`hooks-daemon agents` printed customisation/removal warnings twice** —
  once via logging, once via a duplicate CLI print.
- **`model_fallback_detector`'s dedupe state now survives a daemon
  restart.**

## Upgrade

**In the Claude Code chat:**

```claude-code
/hooks-daemon upgrade
```

Optionally pass a target tag: `/hooks-daemon upgrade v3.56.0`. The default is
latest.

**From a terminal:**

```bash
.claude/skills/hooks-daemon/scripts/upgrade.sh
```

If the skill is not deployed in your project, fetch the canonical upgrader —
inspect before running, never pipe it to a shell:

```bash
curl -fsSL https://raw.githubusercontent.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon/main/scripts/upgrade.sh -o /tmp/upgrade.sh
less /tmp/upgrade.sh
bash /tmp/upgrade.sh --project-root /path/to/your/project
```

**Two new handlers ship enabled by default** (`downgrade_indicator`,
`secret_file_hygiene_checker`) — both are silent unless they have something
to say, so neither should surprise you on upgrade. Everything else new in
this release ships disabled; check
`hooks-daemon check-config-migrations --from 3.55.0 --to 3.56.0` for the full
set of newly available options, including `agents.opus_security.enabled` and
the four `flaggable_*` handlers, all recommended only for projects doing
safeguard-flaggable (defensive-security-adjacent) work.
