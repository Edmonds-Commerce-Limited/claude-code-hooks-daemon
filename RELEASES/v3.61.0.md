# v3.61.0 — Skill Scripts That Never Ran, a Post-Upgrade Review That Deferred Itself, and Goal Retraction

**Release Date:** 2026-09-02
**Type:** Minor Release (with a narrowly-scoped breaking change)

## Summary

This release fixes three defects that shared one root cause: a mandatory
instruction existed on disk but never reached the agent meant to follow it.
Four skills (`configure`, `mode`, `acceptance-test`, `release`) each kept
52–317 lines of real procedure in an `invoke.sh` their `SKILL.md` never
named — Claude Code loads a skill's markdown only, so every invocation ran
on the summary alone, and `mode`/`release` silently discarded the caller's
typed arguments (Plan 00324). The config-optimisation review checklist
scored four handlers deleted two releases ago, capping every
fully-configured project at 25/29 (86%) forever (Plan 00323). And the
mandatory post-upgrade config-optimisation review addressed "your NEXT
Claude Code session" immediately after telling the agent to exit its
current one, so a real client upgrade filed it as an optional hand-back
note instead of doing it (Plan 00322). The `optimise` review itself moves
into the daemon's own skill namespace as `/hooks-daemon optimise` (Plan
00322 Phase 4), and the supervisor gains a goal-retraction path so a
retired goal can no longer challenge every Stop for the rest of a session
(Plan 00320/00321). Contract tests now fail release CI if any skill's
runnable script goes unreferenced, if a retired handler reappears in the
optimise checklist, or if deferral phrasing returns to the mandatory-review
banner.

## Highlights

- **Four skills kept their real procedure in a script nothing ever ran
  (Plan 00324)** — `configure`, `mode`, `acceptance-test` and `release`
  each opens with the command to run its own `invoke.sh` now, arguments
  passed through; a contract test fails if any skill in either tree
  bundles a runnable `.sh` its markdown never names.
- **The optimise checklist stops scoring deleted handlers (Plan 00323)** —
  four `RETIRED_HANDLERS` names capped every fully-configured project at
  25/29 (86%) and recommended enabling handlers no config key can enable;
  denominator now `/25`, pinned by a contract test.
- **The mandatory post-upgrade review no longer defers itself away (Plan
  00322)** — the banner now claims the CURRENT session and prints before
  the restart instruction, instead of addressing a session that does not
  exist yet.
- **`/optimise` moves into `/hooks-daemon optimise` (Plan 00322 Phase 4)**
  — narrowly-scoped BREAKING CHANGE; the installer automatically removes
  the orphaned `.claude/skills/optimise/` directory on upgrade.
- **Goal retraction: `hooks-daemon clear-goal` and automatic `/goal clear`
  (Plan 00321)** — a retired goal can no longer challenge every Stop for
  the rest of a session.
- **Goal-intent sidecar and out-of-project `PLAN.md` fixes (Plan 00320)**
  — closes the two defects behind the unsatisfiable `CLAUDE/Plan/00099-test`
  goal observed live during the v3.60.0 release.

## ⚠️ BREAKING CHANGES

### Skill Renames

- **`/hooks-daemon optimise`** (renamed/relocated from the standalone
  `/optimise` skill) — Renamed in v3.61.0
  - **Why**: `optimise` was a top-level skill name generic enough to
    collide with whatever else a project or plugin calls `optimise`, with
    no predictable winner (Plan 00322 Phase 4, superseding Plan 00308's
    original choice to promote the standalone name).
  - **Migration**: Update any local docs, scripts, or muscle memory that
    invoke `/optimise` to `/hooks-daemon optimise` instead. On upgrade,
    the installer automatically removes the orphaned
    `.claude/skills/optimise/` directory — deployment previously only
    ever WROTE the skills it bundles, so a retired one would otherwise
    keep working from an earlier install's copy, silently owning its slash
    command. The installer removes named retirements only; a project's
    own skills are never touched.
  - **Guide**: [`CLAUDE/UPGRADES/v3/v3.60-to-v3.61/v3.60-to-v3.61.md`](../CLAUDE/UPGRADES/v3/v3.60-to-v3.61/v3.60-to-v3.61.md)
    — including what happens if your project owns a skill of the same name.

## Upgrade Instructions

Most projects need no manual config changes: the installer automatically
removes the orphaned `.claude/skills/optimise/` directory as part of the
standard upgrade. Update any local docs/scripts that invoke `/optimise`
directly to `/hooks-daemon optimise` instead. See the versioned upgrade
guide under `CLAUDE/UPGRADES/v3/` for this release for full details once it
is published.

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.61.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon. Never hand-build a venv — the resolver refuses the
# retired pre-v3.7.0 layout.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

# Rebuilds the venv and reinstalls the package for the target version.
bash .claude/hooks-daemon/scripts/upgrade_version.sh \
  "$PWD" "$PWD/.claude/hooks-daemon" "v3.61.0"

.claude/hooks-daemon/bin/hooks-daemon restart
```
