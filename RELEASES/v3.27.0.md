# v3.27.0 — Minor: failsafe recovery cron advisor + deep code-review remediation

**Release date**: 2026-06-23
**Type**: MINOR release

## Summary

v3.27.0 ships the `recovery_cron_advisor` PostToolUse handler **enabled by default**
(opt-out) and remediates ~78 confirmed findings from a worktree-orchestrated deep
code review (Plan 00139 + Plan 00140).

The headline feature is the recovery cron advisor: a plan-lifecycle advisory handler
that prompts agents to maintain a non-durable hourly failsafe cron while executing
long-running plans. The cron is a **safety net** that resumes work stalled by
external factors (Claude API overload, rate limits, 5-hour usage limits, network
failure) — it is explicitly NOT a heartbeat. Because the handler is advisory-only
and only fires on writes to `CLAUDE/Plan/*/PLAN.md`, projects that do not use the
plan workflow are unaffected.

The deep review (Plan 00140) fixed ~78 findings across safety handler bypasses,
daemon repair/restart/socket-race logic, core/config validator drift, QA detection
anchoring, install version parsing, and detector scoping — hardening the codebase
against edge cases that had accumulated across the v3.x series.

## Highlights

- **`recovery_cron_advisor` — failsafe recovery cron, enabled by default** —
  Advisory handler fires on plan creation (advises `CronCreate`), plan progress
  (rate-limited per-plan reminder), and plan completion (advises `CronDelete`).
  Never blocks; never fires outside plan-workflow projects.
- **~78 deep-review findings fixed (Plan 00140)** — Safety handler bypass closures,
  daemon repair/restart hardening, core/config drift fixes, QA detection anchoring,
  and detector scoping improvements across six categories.
- **`daemon_location_guard` false-positive fixed** — Config-file path references
  (`.claude/hooks-daemon.yaml`) no longer trigger the guard.
- **`plan_number_helper` / `validate_plan_number` false positives fixed (Plan 00138)**
  — Pattern anchoring eliminates spurious blocks on unrelated commands.
- **No breaking changes** — All existing configurations continue to work unchanged.

## Changes

### Added

- **`recovery_cron_advisor` PostToolUse handler — failsafe recovery cron lifecycle
  advisory (Plan 00139), shipped ENABLED BY DEFAULT (opt-out)** — An advisory-only,
  never-blocking handler that fires on writes to `CLAUDE/Plan/*/PLAN.md` (and on
  `mkplan.bash` invocations) across three lifecycle phases: plan creation (advises
  `CronCreate durable:false recurring:true`), plan progress (rate-limited per-plan
  reminder to confirm the cron is still running), and plan completion (advises
  `CronDelete`). The cron is a **failsafe safety net** — it resumes work stalled by
  external factors (Claude API overload, rate limits, 5-hour usage limits, network
  failure) — and is explicitly **NOT a heartbeat**: agents must never pace themselves
  to the cron between units of work. The canonical recovery-cron prompt is included
  in the handler's CLAUDE.md guidance. Because the handler only fires on
  plan-lifecycle `PLAN.md` writes, projects that do not use the plan workflow never
  see it fire. Carries a `config-changes/v3.27.0.yaml` manifest so the upgrade
  advisory surfaces the new opt-out.

### Fixed

- **Plan 00140: ~78 confirmed deep code-review findings remediated across the
  codebase** — A worktree-orchestrated deep review identified and fixed findings in
  six categories:
  - **Safety handler bypasses (5 PreToolUse handlers)** — closed cross-separator
    bypass patterns that could be evaded via path separator tricks
  - **Daemon repair/restart/socket-race fixes** — corrected repair timeout units,
    restart abort logic, start socket-race window, and PID-file daemon verification
  - **Core/config validator drift** — fixed footer handler tracking, status schema
    mismatches, and `to_response_dict` docstring drift
  - **Stop/QA detection anchoring** — anchored QA-failure detection patterns,
    paired by id, hardened bandit fail-fast, and made transcript reads more robust
  - **Install/upgrade version parsing** — corrected version parsing in upgrade
    tooling
  - **Detector scoping fixes (LSP, plan, 7 PreToolUse detectors)** — anchored
    status detection, scoped gh-pr flag checks, narrowed LSP error surfaces, dropped
    dead code, fixed regex/dead-code issues across seven PreToolUse detectors
- **`daemon_location_guard` false-positive on config-file references** — The handler
  was incorrectly blocking tool calls that referenced `.claude/hooks-daemon.yaml`,
  even when no `cd` into that directory was being performed.
- **`plan_number_helper` and `validate_plan_number` false positives (Plan 00138)**
  — Fixed pattern anchoring to eliminate false positives on unrelated commands.
- **`recovery_cron_advisor` per-plan progress cadence and anchored status detection**
  — Fixed a cooldown-unit mismatch dogfooding bug (progress reminders fired too
  frequently); anchored the plan-status regex so completion detection is not
  confused by partial matches in notes or task lines.

## Post-Upgrade Tasks

After upgrading, review `CLAUDE/UPGRADES/config-changes/v3.27.0.yaml` — this
release adds `recovery_cron_advisor` enabled by default. No action is required to
adopt it; to opt out, set the following in `.claude/hooks-daemon.yaml`:

```yaml
handlers:
  post_tool_use:
    recovery_cron_advisor:
      enabled: false
```

The upgrade advisory (`check-config-migrations`) will surface this new handler
automatically after upgrading.

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required. The new `recovery_cron_advisor` handler is active
automatically after upgrade. If you do not use the plan workflow, you will never
see it fire. To opt out, add the snippet above to your `.claude/hooks-daemon.yaml`.
