# Release v3.48.0 - Settings.json SSoT Reconciliation & Plan-Workflow Provisioning

**Release Date:** 2026-07-21
**Type:** Minor Release

## Summary

This release delivers Plan 00185: installer/upgrade `settings.json` SSoT
reconciliation and plan-workflow asset provisioning. It fixes the
SessionStart "Missing hook registration for {Event}" flood seen on
installed/upgraded projects by introducing a shared, idempotent settings
reconciler used both at install time and by a new opt-out session-time
self-heal, and adds on-demand tooling to (re)deploy plan-workflow assets
plus an advisory handler that detects when they are missing.

## Highlights

- **Settings.json self-heal**: an already-installed project with stale
  `settings.json` hook registrations is automatically repaired on its next
  session — no reinstall required.
- **`reconcile-settings` CLI**: create/merge/`--check` a project's
  `settings.json` against the daemon's SSoT-derived hook registration set
  (`wired_event_metas()`). Idempotent; preserves `permissions`/`env`/
  `statusLine` and any client-added hooks.
- **Installer now delegates to the reconciler**: `install_version.sh`'s
  `generate_settings_json` uses the same SSoT merge core, demoting the
  previously drifting 15-event bash heredoc to an inert last resort.
- **`deploy-plan-workflow` CLI**: on-demand (re)deploy of `mkplan.bash`,
  `_JOURNAL_TEMPLATE_.md`, and `PlanJournalling.md`.
- **New advisory handler `plan_workflow_asset_checker`**: warns at session
  start when `plan_workflow.enabled` is true but its assets are missing.

## Changes

### Added

- **`reconcile-settings` CLI** (create/merge/`--check`) built on a new
  shared `reconcile_settings_hooks()` merge core, SSoT-derived from
  `wired_event_metas()`. Idempotent; preserves `permissions`/`env`/
  `statusLine` and any client-added hooks. `install_version.sh`'s
  `generate_settings_json` now delegates to it, demoting the previously
  drifting 15-event bash heredoc to an inert last resort.
- **SSoT drift regression test** (`test_settings_sources_ssot_drift.py`)
  guarding the installer/reconciler settings sources against future drift.
- **`deploy-plan-workflow` CLI** — on-demand (re)deploy of `mkplan.bash`,
  `_JOURNAL_TEMPLATE_.md`, and `PlanJournalling.md`.
- **New SessionStart advisory handler `plan_workflow_asset_checker`**
  (priority 59, enabled by default) — fires when `plan_workflow.enabled`
  but its assets (`mkplan.bash` / journal template) are missing.

### Changed

- Shares its settings-reconciliation core with the upgrade-time shell
  merge added in Plan 00176.

### Fixed

- **SessionStart "Missing hook registration for {Event}" flood** on
  already-installed/upgraded projects. `hook_registration_checker` now
  self-heals stale `settings.json` on the next session via
  `utils/settings_repair.py`, gated by the new opt-out option
  `auto_repair_registrations` (default `true`), taking a one-shot
  `.bak.pre-registration-repair` backup before merging. No reinstall
  required.

See `CHANGELOG.md` for the complete entry.

## Post-Upgrade Tasks

No breaking changes and no mandatory post-upgrade tasks. See
`CLAUDE/UPGRADES/config-changes/v3.48.0.yaml` for two new, recommended
opt-out/opt-in config options introduced by this release
(`hook_registration_checker.options.auto_repair_registrations`, on by
default, and `plan_workflow_asset_checker`, enabled by default) — no
action is required unless you want to change the defaults.

## Upgrade Instructions

This is a drop-in, non-breaking upgrade. No configuration migration or
upgrade guide is required. The new self-heal and advisory handler both
ship on by default with sensible defaults.

## Installation

### New Installations

```bash
cd .claude
git clone -b v3.48.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
```

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.48.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
