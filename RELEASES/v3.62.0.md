# Release v3.62.0 - Remote Docs Vendoring, Write Containment, and Config Reach

**Release Date:** 2026-09-06
**Type:** Minor Release

## Summary

This release adds a provenance-enforced remote-docs vendoring subsystem and a
deny-by-default guard against writes outside the project root, closes a
class of "declared but never consumed" configuration bugs in `vendor_dirs`
and the QA test-report pipeline, and — via this release's own code-review
gate — closes two security regressions the release would otherwise have
introduced (see Security, below). No breaking changes.

## Highlights

- **Two guard bypasses caught and closed by this release's own code-review
  gate** before shipping: a laundering primitive in the secret-file guard's
  new import exemption, and a heredoc-executor gap in `curl_pipe_shell` that
  let `curl | bash` through a priority-10 RCE guard. See Security, below.

- **Remote docs vendoring (Plan 00326)**: `hooks-daemon remote-docs add <url>`
  captures upstream documentation as tracked markdown with enforced
  provenance frontmatter, backed by four new handlers
  (`remote_docs_provenance`, `remote_docs_commit_gate`, `remote_docs_routing`,
  `remote_docs_staleness`).

- **`project_containment` (Plan 00333)**: a new terminal, deny-by-default
  PreToolUse handler blocks Bash/Write/Edit/NotebookEdit writes that resolve
  outside the project root — including destination-bearing shell constructs
  like `curl -o`, `tar -c`, `mkdir`, and `rsync`/`scp`.

- **`untracked/scratch/`** is now the canonical, daemon-created scratch
  location, replacing every `/tmp` recommendation the daemon used to make —
  a `/tmp` write is denied by containment, so the guidance now agrees with
  the guard.

- **`layout.vendor_dirs` finally works (Plan 00331, Plan 00332)**: docs QA,
  plan QA and the content-blocker handlers now resolve a project's declared
  vendor directories from the file's *owning* project, including inside
  monorepo sub-projects, instead of reading the raw builtin constant that
  every consumer previously used regardless of configuration.

- **Core doc templates (Plan 00334)**: `PlanWorkflow.core.md`,
  `Worktree.core.md` and `DocumentationStrategy.core.md` are now deployed
  into client projects by the installer, so resident guidance stops
  pointing at files that only exist in this repo.

- **Hook/statusLine commands always run through `bash <path>` (Plan 00102
  Phase 6)**: closes a class of exec-bit- and cwd-dependent breakage in
  status lines and hook registration, with a settings migrator that now
  rebuilds bare/relative commands instead of only prefixing them.

## Security

All three found and closed by this release's own code-review gate before
shipping — confirmed by executing the shipped code, and all three
regressions this release itself would have introduced (every shape was
denied at v3.61.0). The gate ran three times, and the third pass — attacking
the fixes made after the first two — is what found the third defect:

- **Secret-file guard: the new import exemption was a general laundering
  primitive.** Exempted an `import`/`from` module path by string identity
  rather than by position, so a fake `import <protected-name>` line
  prefixed onto any command made every real mention of that name invisible
  to the guard — across four DENY/suppress surfaces, including whether
  `payload_capture` writes a command's payload to disk. Now positional:
  only the import statement's own span is blanked.
- **`curl_pipe_shell`: the quoted-heredoc exemption missed three executing
  receivers.** `eval "$(cat <<'EOF' ... EOF)"`, `. /dev/stdin <<'EOF'`, and
  `source /dev/stdin <<'EOF'` all execute a heredoc body without matching
  the fixed interpreter list the exemption checked, letting a
  `curl ... | bash` payload through this priority-10 terminal RCE guard.
  All three now count as executors.
- **`curl_pipe_shell`: the same exemption was defeated by ordinary shell
  punctuation.** The other half of the finding above — the receiver
  VOCABULARY was widened, the receiver WORD was not. A receiver bash
  resolves to `bash` was reported as `(bash`, `"bash"`, `'bash'`, `\bash`
  or `ba"sh"`, matching neither list and blanking the body. Seven shapes,
  five reachable through the interpreter list that predates this release.
  The word is now normalised before comparison, closing the family rather
  than the spellings anyone happened to list. Documented limit: a receiver
  built by EXPANSION (`b$'ash'`, `$SHELL`) is still not resolved — doing so
  would mean running the command the hook exists to judge.

See [CHANGELOG.md](../CHANGELOG.md#3620---2026-09-06) for full detail.

## Breaking Changes

None. No handlers, configuration keys, or CLI subcommands were removed or
renamed in this release.

`project_containment` (see Highlights) is a new, enabled-by-default deny
handler and is therefore a genuine *behaviour* change for any workflow that
wrote outside the repository root (most commonly `/tmp`) — that write will
now be denied. It is not classified as breaking: no configuration key was
removed or renamed, and no previously-valid configuration value now fails
validation, consistent with how this project has always classified new
enabled-by-default handlers (see `CLAUDE/development/RELEASING.md`'s semver
table: "MINOR: New handlers/features ... backwards-compatible"). It is
called out here, and marked `recommended: true` / `dormant: false` in
`CLAUDE/UPGRADES/config-changes/v3.62.0.yaml`, precisely because it is a
real behaviour change worth reading about even though it is not breaking.
See the Upgrade Instructions below for the migration path.

## Upgrade Instructions

No special migration steps are required. Most new handlers and config keys
introduced in this release are dormant by default and inert until you opt
in — see `CLAUDE/UPGRADES/config-changes/v3.62.0.yaml` for the full list.

One is not dormant and needs a read before you upgrade:

- **`project_containment`** is enabled by default and denies any
  Bash/Write/Edit/NotebookEdit write whose target resolves outside the
  repository root — most commonly a script or command that used `/tmp` for
  scratch work. Redirect scratch work to `untracked/scratch/` (created
  automatically by the daemon) instead. If a workflow genuinely needs to
  write outside the repository, declare the path via
  `handlers.pre_tool_use.project_containment.options.allowed_external_paths`,
  or set `handlers.pre_tool_use.project_containment.enabled: false` to opt
  out entirely.
- **`layout.vendor_dirs`**, if your project already declared it, previously
  had no effect on docs QA, plan QA, or the content-blocker handlers. It now
  does. Review your docs QA / plan QA output after upgrading in case a
  previously-inert declaration changes what is reported (most likely:
  fewer findings, as intended exclusions now apply).

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.62.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

bash .claude/hooks-daemon/scripts/upgrade_version.sh \
  "$PWD" "$PWD/.claude/hooks-daemon" "v3.62.0"

.claude/hooks-daemon/bin/hooks-daemon restart
```

## Testing

- **Tests:** 18,000+ passing, 95%+ coverage (see `./scripts/qa/llm_qa.py all`
  for the exact count at tag time)
- **Type Safety:** MyPy strict mode compliant
- **Security:** Bandit scan clean
- **QA gate:** 25/25 checks green
- **Code review gate:** PASS on the third pass; three blocking findings
  raised and closed (see Security)
- **Acceptance gate:** ~200 of 225 tool-call tests executed in the main
  thread, **zero failures**. The gate found one genuine defect — the Go lint
  false denial listed under Fixed — which is what a gate is for. The
  remainder could not be executed in the release session and are listed here
  rather than counted as passes: the `Artifact` tool is disabled by this
  project's tool policy; three tests need a term from the read-protected
  secret word list, which must not be opened; three would interrupt the
  human with an `AskUserQuestion`; two need the `Grep` tool, unavailable in
  that session; two need a second concurrent session; and the rest need
  network access or a live budget. Several were observed firing incidentally
  during the run. Three language checks (Kotlin, Swift, Ansible) were
  inconclusive because their toolchains are absent from the container — in
  each case the handler correctly degraded to an advisory instead of denying.
