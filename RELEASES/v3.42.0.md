# Release v3.42.0 - Worktree Status Indicator + Supervisor Session Isolation

**Release Date:** 2026-07-15
**Type:** Minor Release

## Summary

This minor release adds a **status-line worktree indicator** and hardens the ccy
PTY supervisor (`.claude/ccy/claude-supervise.py`) on two fronts surfaced by real
two-terminal dogfooding.

The new feature makes it obvious at a glance when you are working inside a git
linked worktree: the `git_branch` status handler colours the branch name pink and
appends a tree icon (🌳) to the git status segment. Detection is filesystem-only,
so it costs nothing on the status-line render path.

The supervisor changes fix a cross-terminal injection bug (two `ccy` terminals in
one repo previously matched compaction signals by freshness rather than by
session identity, so a compaction in terminal B could inject a stray `continue`
into terminal A's Claude PTY) and add a safety net guaranteeing the supervisor can
never flood a live Claude session with its own error output. (Plan 00166)

## Highlights

- **Status-line worktree indicator (new)**: inside a git linked worktree the
  branch name is coloured pink (overriding the usual green/orange/grey
  default-branch colour) and a tree icon (🌳) is appended to the git status
  segment. The main worktree and submodules are unaffected. Detection reads the
  worktree's `.git` file rather than forking git, so it adds zero subprocess
  calls to the render hot path.
- **Cross-terminal compaction injection fixed**: the supervisor actuator now
  resolves its own session identity from `/proc/<pid>/environ`
  (`CLAUDE_CODE_SESSION_ID`, scoped to its own PID namespace) and filters every
  signal/sidecar read to sessions it actually owns. Foreign terminals in a
  separate namespace never appear; an empty own-session set fails safe by acting
  on nothing.
- **Supervisor never floods the PTY**: the policy worker's stderr is redirected
  to `claude-supervise-worker.err.log`, never the inherited tty, and a per-tick
  exception (or a host/worker version skew after a hot-reload) is caught, logged
  to that file, and replaced with a safe NOOP tick — so a supervisor fault can
  no longer spam the live session with tracebacks.
- **Verified live**: the worktree indicator was dogfooded against a real
  `git worktree add` checkout (pink branch + 🌳, main repo unaffected); the
  supervisor fix was confirmed by a two-terminal dogfood (terminal B compacts
  while terminal A is armed and idle, and A receives no injection).

## Changes

## [3.42.0] - 2026-07-15

### Added

- **Status-line worktree indicator.** The `git_branch` status handler now
  detects when the working directory is inside a git *linked worktree* (created
  via `git worktree add`) and signals it two ways: the branch name is coloured
  pink (overriding the usual green/orange/grey default-branch colour) and a
  tree icon (🌳) is appended to the git status segment. The main worktree and
  submodules are unaffected. Detection is filesystem-only — it reads the
  worktree's `.git` file rather than forking git — so it adds zero subprocess
  calls to the status-line render hot path.

### Fixed

- **Cross-terminal compaction injection.** Two `ccy` terminals in the same repo
  share one bind-mounted `untracked/context-sidecar/` directory but run in
  separate containers/PID namespaces. The supervisor actuator previously matched
  compaction signals and foreground sidecars by freshness (first fresh file
  wins), never by session identity — so a compaction in terminal B could make
  terminal A resume off B's signal. The actuator now resolves its own session
  identity from `/proc/<pid>/environ` and filters every signal/sidecar read to
  sessions it owns. Fail-safe: an empty own-session set acts on nothing.

### Changed

- **Policy-worker error safety net.** The policy worker's stderr is redirected
  to a file (never the inherited terminal), and a single tick's exception (or a
  host/worker version skew after a hot-reload) is caught, written to that file,
  and replaced with a safe NOOP so the host still gets a reply. Applies to
  `PolicyWorker.start` (Popen `stderr`), the `--worker` entrypoint
  (self-redirect on start), and the per-tick guard in `run_worker`.

See `CHANGELOG.md` for the complete entry.

## Upgrade Instructions

No breaking changes in this release — a standard upgrade is sufficient. See
`CLAUDE/UPGRADES/` for version-specific upgrade guides (none required for this
release). Projects running ccy should relaunch their `ccy` session after
upgrading so the supervisor host re-execs the updated `claude-supervise.py` (the
`ccy_supervisor_integrity` SessionStart handler will advise this when it detects
a newer supervisor on disk than the running process). The status-line worktree
indicator is active automatically after a daemon restart — no configuration
needed.

## Installation

### New Installations

```bash
cd .claude
git clone -b v3.42.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.42.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
