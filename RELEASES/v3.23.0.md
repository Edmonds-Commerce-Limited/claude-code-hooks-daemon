# v3.23.0 — Minor: block untracked Claude memory (tracked-docs policy) + distributed `mkplan.bash`

**Release date**: 2026-06-19
**Type**: MINOR release

## Summary

v3.23.0 delivers two opt-in features.

First, an **`allow_untracked_claude_memory` policy** on the `markdown_organization` handler. Claude Code's cross-session auto-memory writes unversioned, un-reviewed, per-checkout knowledge into untracked Claude meta files (`~/.claude/projects/<slug>/memory/`). A project that wants a single, reviewable, git-tracked source of truth can now forbid this — and the daemon **enforces it by blocking the writes** rather than relying on the fragile, version-dependent attempt to disable Claude's own memory engine. When the policy is active, `Write`/`Edit` and bash `>`/`>>`/`tee` redirect side-doors to memory files are denied with a **specialist message** that routes durable knowledge into tracked project docs via **progressive disclosure**. Reading memory stays allowed so existing memory can be migrated out. Default is `true` — today's behaviour is unchanged until a project opts in.

Second, the audited, git-anchored **`mkplan.bash`** plan-scaffolding script is now **distributed into client projects** by the installer. It allocates the next plan number atomically from the authoritative git counter, so concurrent agents never collide on a number.

## Highlights

- **Forbid untracked Claude memory, enforced by the daemon (Plan 00131)** — `allow_untracked_claude_memory: false` blocks memory writes (tool + bash side-doors) with a specialist tracked-docs / progressive-disclosure message. Reads always allowed. Default `true` = unchanged.
- **Reconciled SessionStart advice** — under the policy, `optimal_config_checker` no longer nags to re-enable auto-memory, so the advisory never contradicts the block.
- **Distributed `mkplan.bash` (Plan 00130)** — the daemon now ships and deploys the git-anchored plan-scaffolding script into client projects; `plan_number_helper` names `CLAUDE/Plan/mkplan.bash "name"` as canonical.

## Changes

### Added

- **`allow_untracked_claude_memory` option on `markdown_organization` (Plan 00131; default `true`)** — With the option `false`, `Write`/`Edit` (and bash `>`/`>>`/`tee` redirect side-doors) targeting `~/.claude/projects/*/memory/*.md` are **denied at the daemon layer** with a specialist message routing durable knowledge into tracked project docs using progressive disclosure (lean `CLAUDE.md`, `.claude/rules/*.md` with `paths:` globs, thin skills, plain links, single-source-of-truth, no `@`-imports). **Reading memory is always allowed** so existing memory can be migrated. Enforcement is the deterministic block — not an attempt to disable Claude's own memory engine. Default `true` preserves today's behaviour exactly.
- **Distributed `mkplan.bash` plan-scaffolding script (Plan 00130)** — The audited, git-anchored plan-numbering script is now bundled with the daemon (wheel `package-data`) and deployed into the client project's plan directory by the installer. It takes a lock, reads the authoritative `hooksdaemon.latestPlanNumber` git counter, allocates the next number atomically, scaffolds `NNNNN-name/PLAN.md`, and advances the counter — so concurrent runs never collide. `plan_number_helper` guidance now names `CLAUDE/Plan/mkplan.bash "name"` as the canonical way to create a plan.

### Changed

- **`optimal_config_checker` reconciled with the memory policy (Plan 00131)** — When `allow_untracked_claude_memory: false` is active, the SessionStart auto-memory check no longer nags to re-enable memory. It reads the policy from config as the single source of truth, fails safe, and frames disabling memory as an optional best-effort step — so the advisory never contradicts the block.

## How to enable the policy

In `.claude/hooks-daemon.yaml`:

```yaml
handlers:
  pre_tool_use:
    markdown_organization:
      options:
        allow_untracked_claude_memory: false
```

Restart the daemon. New memory writes are then blocked with tracked-docs guidance; existing memory remains readable for migration.

## Upgrade

```bash
/hooks-daemon upgrade
```

No breaking changes. No config migration required. All changes are additive and opt-in — the new option defaults to `true`, preserving existing behaviour until a project sets it `false`.

```bash
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..

```
