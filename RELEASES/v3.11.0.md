# Release v3.11.0 - Stability Hardening

**Release Date:** 2026-05-08
**Type:** Minor Release

## Summary

Plan 00105 closes the gaps that allowed the v3.10.0 SEV-1 (`print_info` writing to stdout corrupting `VAR=$(ensure_venv ...)` captures) to escape detection. No breaking changes; this is a pure prevention layer: a new 13th QA gate that statically and dynamically detects print-before-echo corruption, a new H-1 acceptance gate that runs `install.sh` end-to-end against a fresh fixture project, parameterised sha256-verified self-bootstrap stanzas extended from `upgrade.sh` to all four diagnostic scripts, and a loud overlay-fs fallback announcement that replaces the previously silent `print_verbose` path. No user action is required to upgrade.

## What's New

### Added (Plan 00105 Phases 1-4)

- **13th QA gate — capture-corruption static+dynamic check (Phase 2)**: `scripts/qa/audit_capture_corruption.py` scans every `scripts/install/*.sh` helper for the print-before-echo anti-pattern. Detects functions that write to stdout before a bare `echo` return value, and validates that `VAR=$(fn)` capture sites are safe. Integrated into `run_all.sh` as check 13. Catches the v3.10.0 SEV-1 class of bug at QA time on every future commit.

- **H-1 `install.sh` end-to-end acceptance gate (Phase 1, Task 1.1)**: `tests/acceptance/test_install_sh_end_to_end.py` runs the production `install.sh` against a fresh fixture project (isolated tmpdir, no pre-existing venv) and asserts the daemon starts successfully. Closes the gap in the v3.10.0 H-1 gate, which synthesised state via `write-venv-metadata` directly instead of exercising the real `ensure_venv` capture chain. The new gate would have caught the v3.10.1 SEV-1 regression before tagging.

- **H-1 `upgrade_version.sh` end-to-end acceptance gate (Phase 1, Task 1.3)**: Extends the install gate to exercise `upgrade_version.sh` against a fixture project that has already been installed, verifying the full upgrade path end-to-end. Both gates are wired into `RELEASING.md` Step 12.0 as a combined BLOCKING gate (17 tests: 5+1 diagnostic, 1+1 install, 1 upgrade).

- **Parameterised self-bootstrap stanza extended to all four diagnostic scripts (Phase 4)**: `daemon-cli.sh`, `health-check.sh`, and `init-handlers.sh` now include the same sha256-verified self-bootstrap stanza previously shipped only with `upgrade.sh`. The stanza is parameterised by `$(basename "$0")` so each script verifies its own entry in `bootstrap-checksums.txt` before executing. `RELEASING.md` Step 14 updated to publish all four scripts as release artifacts alongside `bootstrap-checksums.txt`. Closes Plan 00104 Decision 3.B (deferred from v3.10.0).

### Changed (Plan 00105 Phases 5-6)

- **`venv.sh` overlay-fs hardlink→copy fallback now announces via `print_warning` (Phase 5)**: The fallback from hardlink to full copy (triggered on overlay filesystems where hardlinks are unavailable) previously used `print_verbose`, which is silent unless `VERBOSE=1`. It now uses `print_warning` so the fallback is always visible in normal operation. Fixes the silent-fallback antipattern documented in the Plan 00100 v2 architectural decision. Retry logic remains in `create_venv_at_path`, not `verify_venv`, per that decision.

- **Plan 00103 housekeeping (Phase 6)**: Completed plan folders moved to `CLAUDE/Plan/Completed/`; `CLAUDE/Plan/README.md` updated to reflect current active and completed plan counts.

### Fixed (Plan 00105 Phases 1, 3)

- **Latent version-detection bug in `_resolve-venv.sh` (Phase 1, Task 1.4)**: A subtle off-by-one in the version-string comparison logic caused version detection to misfire in certain edge cases. Caught and fixed while wiring the H-1 install gate.

- **`scripts/install/*.sh` helpers audited and cleared of print-before-echo anti-pattern (Phase 3)**: Full audit confirmed no remaining instances of progress output written to stdout at capture sites. The 13th QA gate now enforces this permanently at every future commit.

## Breaking Changes

None. This is a MINOR release. No API or configuration changes, no handler additions or removals, no user-facing behavioural changes. Every change is internal: new QA/acceptance gates, extended self-bootstrap coverage, and a louder overlay-fs fallback announcement.

## Install / Upgrade

### Upgrading Existing Installations

No manual steps required. Run the upgrade skill from any Claude Code session in your project:

```
/hooks-daemon upgrade
```

Or directly from the daemon directory:

```bash
cd .claude/hooks-daemon
./scripts/upgrade.sh
```

The skill's self-bootstrap stanza fetches the latest `upgrade.sh` body from this release, sha256-verifies it against `bootstrap-checksums.txt`, and re-execs the fresh body before proceeding.

### New Installations

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon/main/install.sh)
```

Or clone a specific tag:

```bash
git clone -b v3.11.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon
cd .claude/hooks-daemon && ./install.sh
```

### Verify

```bash
/hooks-daemon health
# Expected: "Daemon: RUNNING" with no errors
```
