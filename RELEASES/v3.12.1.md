# Release v3.12.1 - Plan 00101 Closure: tool_use_error Recovery

**Type:** Patch Release

## Summary

This patch release closes out Plan 00101 (recap-stoppage / silent-stop investigation). The plan was prematurely closed in v3.12.0; this release delivers the outstanding Phases 5/6/7 — a handler-level recovery from `tool_use_error` followed by a silent agent stop, plus an acceptance probe that wires the recovery contract into the H-1 release gate.

The field-bug shape: an agent calls `Edit` on a file it has not yet `Read`, Claude Code returns a `tool_use_error` (`File has not been read yet`), and the agent then stops silently — repeating the same failure on re-entry. The new Branch 2.5 in `AutoContinueStopHandler` detects this pattern in the transcript and returns `decision=block` with a recovery-specific reason directing the agent to Read-before-Edit and retry, breaking the loop.

## What's New

### Added (Plan 00101 Phase 6 — handler-level recovery)

- **`AutoContinueStopHandler` Branch 2.5 — `tool_use_error` recovery**. When the last `tool_result` in the transcript has `is_error=true` and the agent stopped silently, the Stop handler now returns `decision=block` with a recovery-specific reason prefixed `TOOL ERROR RECOVERY:` directing the agent to Read-before-Edit and retry.
- **`TranscriptReader.last_tool_result_was_error()` helper**. New transcript-introspection method that locates the most recent `tool_result` content block and returns `True` when `is_error=true`. Used by `AutoContinueStopHandler` Branch 2.5; reusable for any handler that needs to gate on the last tool-call outcome.

### Added (Plan 00101 Phase 5 — agent guidance)

- **`AutoContinueStopHandler.get_claude_md()` Read-before-Edit guidance**. The handler's CLAUDE.md guidance now includes explicit Read-before-Edit instruction, a description of the `tool_use_error` recovery shape, and re-entry `STOPPING BECAUSE:` reminders so the agent recognises the recovery pattern when the daemon re-fires.

### Added (Plan 00101 Phase 7 — acceptance probe wired into H-1)

- **`tests/acceptance/test_tool_use_error_recovery.py`**. New two-case acceptance test wired into `RELEASING.md` Step 12.0. Positive case asserts Branch 2.5 fires with the `TOOL ERROR RECOVERY:` reason on `is_error=true` silent stops. Negative control asserts Branch 2.5 stays dormant on `is_error=false` and the dispatcher falls through to the default branch. Skips cleanly when no daemon is running locally; under H-1 the daemon is always started before this step, so a skip there is itself an abort condition.

### Changed

- **`RELEASING.md` Step 12.0 — H-1 gate extended to 19 combined tests**. The H-1 acceptance suite now runs `test_diagnostic_scripts.py` (15) + `test_install_sh_end_to_end.py` (2) + `test_tool_use_error_recovery.py` (2) = 19 passed. ANY failure in any file = abort release.
- **Plan 00101 closed (Phases 5/6/7/8 delivered post-v3.12.0)**. Plan moved to `CLAUDE/Plan/Completed/`. `CLAUDE/Plan/README.md` index updated — Active Plans count 4 → 3, Completed Plans count 90 → 91.

## Breaking Changes

None. This is a PATCH release. The new Branch 2.5 in `AutoContinueStopHandler` only fires when the last `tool_result` is an error AND the agent stopped silently — a strict superset of the prior conditions. Sessions that did not hit the silent-stop-after-error pattern see no behaviour change.

## Install / Upgrade

### Upgrading Existing Installations

No manual steps required. Run the upgrade skill from any Claude Code session in your project:

```
/hooks-daemon upgrade
```

Or directly from the daemon directory:

```bash
cd .claude/hooks-daemon
./scripts/upgrade.sh
```

The skill's self-bootstrap stanza fetches the latest `upgrade.sh` body from this release, sha256-verifies it against `bootstrap-checksums.txt`, and re-execs the fresh body before proceeding.

### New Installations

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon/main/install.sh)
```

Or clone a specific tag:

```bash
git clone -b v3.12.1 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon
```
