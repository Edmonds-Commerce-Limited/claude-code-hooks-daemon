# v3.59.0 — Subagent Report Handoff, Per-Language Lint Timeouts, and Post-Upgrade Config Optimisation

**Release Date:** 2026-09-01
**Type:** Minor Release

## Summary

This release adds a file-based handoff contract for subagent reports (fixing
a live-reproduced harness bug that silently truncates oversized inline
subagent returns), makes `lint_on_edit`'s extended-lint timeout configurable
per language, and formalises `/optimise` as an autorun post-upgrade
config-optimisation step. It also fixes a `secret_file_guard` false positive
on `git rm --cached` of protected paths, a venv resolver defect that let a
host-level invocation reuse a container-built venv (or vice versa), and
refreshes the vendored Claude Code hooks contract to v2.1.252. No breaking
changes.

## Highlights

- **Subagent file-based report handoff (Plan 00307)** — new
  `dispatch_declaration` (PreToolUse on `Task`) and
  `subagent_report_size_blocker` (SubagentStop) handlers close a
  live-reproduced harness bug where an oversized inline subagent final
  message is silently elided in the middle. Both ship enabled by default:
  `dispatch_declaration` is advisory by default (opt-in `strict` denies);
  `subagent_report_size_blocker` denies an oversized subagent stop at a
  4,000-char default threshold, failing open only on a missing/malformed
  message.
- **Per-language `lint_on_edit` extended-lint timeouts (Plan 00309)** — the
  previously hardcoded 15-second budget is now configurable per language,
  fixing silently-allowed timeouts on slow first-run static analysis (e.g.
  cold `phpstan`).
- **`/optimise` formalised as the post-upgrade config-optimisation step
  (Plan 00308)** — a new `config_optimisation_reminder` advisory prompts
  running `/optimise` after an upgrade.
- **Plan README age-out (Plan 00310)** — the plan index now retains only the
  30 highest-numbered completed rows; older rows move into
  `CLAUDE/Plan/Completed/README.md`.
- **`secret_file_guard` false-positive and hygiene fixes (Plan 00306)** —
  `git rm --cached` on a protected path is now exempted from the
  Bash-mention block, plus registry-iteration and POSIX bracket-handling
  fixes.
- **Venv resolver cross-view reuse fix (Plan 00313)** — a slug-carrying
  `venv-*` directory is now resolved only when its embedded project-root
  slug matches the current root, closing a defect where a host invocation
  could reuse a container-built venv (whose editable-install `.pth` points
  at a path that doesn't exist on the host) and vice versa.

## Breaking Changes

None in the removed/renamed sense — no existing behaviour is removed or
renamed, and no config schema entries were removed or renamed. Both new
handlers ship enabled by default: `dispatch_declaration` is advisory by
default (opt-in `strict` denies); `subagent_report_size_blocker` denies an
oversized subagent stop at a 4,000-char default threshold and fails open
only on a missing/malformed message — an upgrading project that dispatches
subagents with routinely large final messages may see new denials until it
adopts the file-handoff convention or tunes `threshold_chars`.
See `CLAUDE/UPGRADES/config-changes/v3.59.0.yaml` for the recommended new
config keys.

## Upgrade Instructions

No special upgrade steps are required for this minor release. After
upgrading, run `/optimise` (or let the new post-upgrade autorun prompt you)
to review the two new handlers' default configuration for your project.

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.59.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon. Never hand-build a venv — the resolver refuses the
# retired pre-v3.7.0 layout.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

# Rebuilds the venv and reinstalls the package for the target version.
bash .claude/hooks-daemon/scripts/upgrade_version.sh \
  "$PWD" "$PWD/.claude/hooks-daemon" "v3.59.0"

.claude/hooks-daemon/bin/hooks-daemon restart
```
