# v3.35.0 — client-configurable `exclude_paths` for content-scanning blockers

**Release date**: 2026-07-10
**Type**: MINOR release

## Summary

v3.35.0 adds a uniform, client-configurable path-exclusion escape hatch to the
three content-scanning PreToolUse blocking handlers — `security_antipattern`,
`qa_suppression`, and `error_hiding_blocker`. Projects can now exempt specific
paths (per-handler and/or project-wide) from content scanning with gitignore-style
globs, instead of the previous all-or-nothing choice of disabling a whole handler.

The motivating case: a QA/linting library whose job is to contain deliberately
"bad" code — fixtures with `# noqa`, `except: pass`, SQL built by concatenation —
or code that legitimately must suppress an error for a documented reason. Before
this release the only levers were disabling a handler project-wide or renaming
fixtures into the two paths `security_antipattern` happened to hardcode (which did
nothing for the other two handlers).

No breaking changes. Fully backwards compatible: no config means unchanged
behaviour, with the single exception that `error_hiding_blocker` now ships the
same built-in default skips (vendor, node_modules, test fixtures) its two siblings
already had.

## Highlights

- **`exclude_paths` on all three content blockers.** Each of
  `security_antipattern`, `qa_suppression`, and `error_hiding_blocker` accepts
  `options.exclude_paths: [glob, …]`. Matching Write/Edit targets are exempted from
  scanning. Globs use correct gitignore-style semantics — `**` matches zero or more
  path segments, `*`/`?` stay within a segment, unanchored patterns match anywhere
  in the tree.
- **Project-wide `daemon.exclude_paths` default.** Set the exemption list once
  under `daemon:` and all three handlers inherit it (unioned with each handler's own
  `exclude_paths`). Single source of truth for "exempt these paths everywhere",
  plumbed the same way as the existing `daemon.languages` injection.
- **No new runtime dependency.** Backed by one shared stdlib-only glob→regex
  translator (`utils/path_exclusion.py`) with a compiled-pattern cache. `pathspec`
  is only a dev-time transitive dependency, so it was deliberately not used at
  runtime.
- **`error_hiding_blocker` stops being the odd one out.** It gains the same
  built-in default skip set as its siblings, so vendor/node_modules/test-fixture
  code is no longer scanned by default.

## Changes

### Added

- **`exclude_paths` glob option on `security_antipattern`, `qa_suppression`, and
  `error_hiding_blocker`** — layered on top of each handler's existing built-in
  skips (`should_skip()` for security, per-language `skip_directories` for
  qa_suppression, `_DEFAULT_EXCLUDE_GLOBS` for error_hiding). Backed by
  `utils/path_exclusion.py` (`is_path_excluded`, `merge_exclude_patterns`,
  `resolve_project_root`) — stdlib-only, compiled-pattern cache, correct
  zero-or-more-segment `**`.
- **Project-level `daemon.exclude_paths` default** — a new `daemon.exclude_paths`
  schema field (default `[]`) injected as `_project_exclude_paths` through the
  config model → CLI → controller → registry → `Handler` slots, and merged as a
  union with each handler's per-handler option via `merge_exclude_patterns`.

### Changed

- **`error_hiding_blocker` now skips vendor/node_modules/test-fixture dirs by
  default** — it previously had no built-in skip set and scanned everything. It now
  ships `_DEFAULT_EXCLUDE_GLOBS` (`**/vendor/**`, `**/node_modules/**`,
  `**/tests/fixtures/**`, `**/tests/assets/**`, `**/__fixtures__/**`) matching its
  siblings. This is the only behavioural change that occurs absent any config.

No breaking changes — no upgrade guide required.

## New configuration (opt-in)

Per-handler:

```yaml
handlers:
  pre_tool_use:
    security_antipattern:
      options:
        exclude_paths:
          - "**/tests/fixtures/**"
          - "src/legacy/**"
```

Project-wide (inherited by all three content blockers):

```yaml
daemon:
  exclude_paths:
    - "**/fixtures/**"
    - "**/__samples__/**"
```

See `docs/guides/HANDLER_REFERENCE.md` → "Content-Blocker Path Exclusion" and
`CLAUDE/UPGRADES/config-changes/v3.35.0.yaml` for details. The upgrade advisory
surfaces this option as `recommended` for projects that carry fixtures of
deliberately-broken code.

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required — the new keys are opt-in and default to empty.
After upgrading, add `exclude_paths` (per-handler or project-wide) if your project
carries fixtures or code that must legitimately trip these blockers.

## Installation

### New Installations

```bash
mkdir -p .claude && cd .claude
git clone https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
git fetch --tags && git checkout v3.35.0
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.35.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
