# Release v3.63.0 - A Stability Push: Three Review Ledgers Worked to Zero

**Release Date:** 2026-09-09
**Type:** Minor Release

## Summary

This release is a stability push, not a feature push. Three accumulated
review ledgers are worked to zero: the client-upgrade-report defect ledger
(Plan 00362, 26 tasks, filed after a real client upgraded from v3.41 to
v3.62.1 and hit eight distinct defects), the v3.57.0 release-review ledger
(Plan 00295), and the ccy supervisor's v3.60.0 release-review ledger (Plan
00319). The largest single behaviour change is that upgrading now merges
`.claude/settings.json` instead of overwriting it (Plan 00176), so a
customisation you keep there survives an upgrade unattended. Alongside that,
the failsafe-cron / Stop-hook subsystem is retuned after a live dogfooding
incident (Plans 00314, 00337, 00341, 00342), and four follow-up findings from
the v3.62.1 release-review gate itself are closed (Plan 00340). It ships as
MINOR rather than PATCH because it adds two new opt-in config options, a new
default-on handler, and several new CLI verbs (`release-slate-check`,
`contract-status`, `optimise-checklist`, `housekeeping`, `audit-handler-keys`,
`worktree-reap`) — see Changes below. No handler or config key was removed,
and no default behaviour changed in a way that fails previously-valid
configuration.

## Highlights

### Everyone

- **A wait loop can no longer watch for itself.** The Bash tool runs every
  command through `bash -c "<command>"`, so a `pgrep -f "my-job"` always
  finds at least one process: the shell asking the question. A reported
  waiter spent an entire night sleeping on exactly that, and two hand-run
  checks with the same pattern each confirmed the wrong answer. The new
  `self_matching_process_probe` handler denies `pgrep -f`, `pkill -f` and
  `ps … | grep` whose literal pattern is in the calling command's own argv,
  wherever they appear, and the block message carries the rewrite for the
  pattern you actually typed. Two advisories sit beside it: an uncapped
  `while`/`until` wait on a process, and a pattern built by expansion that
  the daemon cannot read. Waiting on an artefact
  (`until grep -q "PLAY RECAP" run.log; do sleep 10; done`) is never
  flagged — that is the shape the block message asks for.
- **Upgrading now merges `.claude/settings.json` instead of overwriting it.**
  The daemon owns the wired-hook block and refreshes it, while everything
  else in the file — your own `statusLine`, an extra hook, a `permissions`
  block, `plansDirectory`, or the deliberate absence of a key — is preserved.
  A recommended default you never expressed an opinion about is upgraded; a
  value you actually chose is not. If a merge cannot complete safely,
  nothing changes and the proposed merge is written beside your file as
  `settings.json.merge-proposal` for you to review. There is nothing to back
  up first and nothing to restore afterwards.
- **A malformed recursive glob (`a**b.md`) no longer skips the quarantine
  artefact guard for the whole call.** The daemon's fail-open policy used to
  catch the raised exception and skip `quarantine_artefact_read_guard`
  entirely; the expansion is now guarded where it actually runs, so a
  malformed pattern is judged like any other command.
- **A bracket expression at a token's edge is no longer read as a wildcard
  by the secret-file guard.** An ordinary `jq '.[0]'` subscript used to be
  denied as an open wildcard; finite bracket forms are now expanded and
  matched literally, and `.vault-p*`-style globs and `[Vv]ault_pass` remain
  denied.
- **`/release` opens with a slate-clean gate.** `hooks-daemon release-slate-check` confirms HEAD's exact sha is CI-green and lists
  mid-work plans, branches ahead of main and live worktrees before a release
  is allowed to start.
- **Hooks that lose their executable bit are detected and repaired.** A
  checkout on a filesystem that ignores file modes, or a copy that lost
  permissions, used to fail silently and take the hook's protection with it;
  `git_filemode_checker` now reports this at session start and the existing
  auto-fixer repairs git hooks in place.
- **Worktree guidance now says how to get a working venv.** A fresh worktree
  has no Python venv of its own — the injected guidance now says to build one
  with the project's setup script instead of symlinking the main checkout's,
  which silently ran the worktree's tests against the wrong source.
- **`project_containment` allows the per-session scratchpad Claude Code's own
  system prompt names.** Every write there used to be denied, burning a
  blocked call on the contradiction between the platform's own instructions
  and the guard; the handler now allows exactly the directory the harness
  names in the hook payload, and nothing else under the temp directory.
- **The status-line refresh-interval suggestion, temp-file naming, and the
  bug-report tool are all cleaner.** The session-start suggestion now
  recommends `refreshInterval: 1`, the value the daemon has shipped since
  Plan 00175; every atomic status/signal writer builds its temp filename from
  one helper carrying the thread and a random token, so two writers in one
  process can no longer collide; and `scripts/debug_info.py` names a blank
  interpreter path as the problem instead of executing it and reporting
  `[Errno 13] Permission denied`.
- **`/hooks-daemon optimise` scores every handler, derived from the
  registry.** No more hand-written list of 22 handlers — all 116 are scored
  on every run, each declaring its own relevance
  (`Handler.get_relevance()`), so a handler cannot ship unreviewed and a
  handler whose precondition is missing is reported "not applicable here"
  rather than as a shortfall.

### Operators

- **The ccy supervisor announces every keystroke it injects.** An escape to
  flush a stalled compaction, an Enter to resubmit — both now raise the
  status-line banner on the tick that sends them, with repeats collapsed to a
  tally such as `esc (20), compact (15)`. The "random ESC presses" some
  operators saw were these flushes, now visible.
- **The ccy supervisor now says when its decision worker dies.**
  `decision.log` carries `worker died (exit N, source <hash>) -> respawned`,
  a crash-loop line if the same source dies again, and `worker recovered` —
  previously a dead worker was silently respawned every tick with the host
  quietly deciding in-process on its own, older code.
- **The v3.57.0 review ledger is worked to zero.** Lint/ESLint skip-paths
  match on path segments (not substrings), a symlinked file no longer
  crashes docs QA, `layout.source_dirs`/`layout.test_dirs` match paths and
  globs as documented, a timed-out transport probe no longer orphans a
  forwarder, `explain-handler --list` exists, `transport-probe` reports the
  digest it actually verified, and the `nc` relay rung honours
  `HOOKS_DAEMON_EVENTS_DIR` on deep client layouts.
- **The supervisor release-review ledger is worked to zero.** The
  budget-exhaustion detector no longer fires on a quoted budget message (a
  sub-agent report, a passthrough Bash command); the audit banner no longer
  clobbers a live Ctrl+C hint; a worker swap that drops a half-typed slash
  command leaves a trace; every BLOCKING acceptance test now carries a
  structured payload the integration suite drives through the real handler.
- **The release slate check lists what the release will say.** A plan that
  changes something a release should announce now leaves a short callout in
  a pending-release holding area as part of closing; `release-slate-check`
  lists those titles, and the release pipeline folds them in and aborts if
  any are left behind (this release notes section is itself an example).
- **`/hooks-daemon optimise` resolves manifests on a client install, and the
  upgrader flags a stale `daemon_stats` override.** Previously the "new since
  vX" recommendations silently never surfaced on any client install; the
  upgrade summary now also targets a pre-v3.40
  `handlers.status_line.daemon_stats.enabled: true` override precisely.
- **The config model now covers every wired event, not 13 of 31.** A
  `handlers.<event>:` section for events such as `post_compact`,
  `subagent_start` or `elicitation` used to be silently discarded at daemon
  start; a plugin may also target `worktree_create`/`worktree_remove`, which
  `config-validate` used to reject.
- **A worktree hook with the daemon down no longer hands Claude Code a JSON
  blob as the path.** `WorktreeCreate`'s daemon-down branch used to print its
  JSON error object to stdout with exit 0, and Claude Code reads that hook's
  stdout as the launch path; it now prints nothing to stdout, sends the
  diagnostic to stderr, and exits non-zero.
- **Two daemons starting at once no longer rebuild the same venv.** A venv
  build now runs under a lock beside the venv (`flock`, with a `mkdir`
  fallback), so a host shell starting beside a container, two terminals in
  one project, or `hooks-daemon repair` alongside a start waits for the first
  build and reuses it instead of deleting it mid-copy — the failure this
  closes presents as an unexplained broken install, not as an obvious race.
- **`hooks-daemon worktree-reap` reports stale agent worktrees, and removes
  nothing unless told to.** Worktrees whose commits are already on the base
  branch are listed; `--reap` actually removes them (resolving each one's
  real path and attached branch from git, not a guessed
  `.claude/worktrees/<name>`), and removing the attached branch is a
  separate, explicit choice from removing the worktree.
- **A new default-on handler publishes the ccy supervisor's downgrade
  signal.** `model_downgrade_recorder` reads Claude Code's own transcript
  record of an automatic safety-classifier model substitution and writes it
  to a per-session file, so the supervisor's model-restore logic can tell a
  machine-driven downgrade from a human's own `/model` choice. It never
  blocks and never speaks.
- **Docs QA and plan QA now honour `daemon.exclude_paths`.** The project-wide
  exclude list previously reached content blockers only; it now reaches
  `docs_qa_edit`, `docs_qa_commit_gate`, `docs_qa_sweep`, `plan_qa_edit`,
  `plan_qa_commit_gate`, `plan_qa_sweep` and both CLIs too. **Check your
  `daemon.exclude_paths` before upgrading** if a fixture tree there must keep
  producing documentation or plan findings — after this release, listing it
  silences those findings as well.
- **`hooks-daemon contract-status` answers "has upstream hooks.md moved?" in
  one command.** Raw-fetches the Claude Code hooks documentation the
  vendored contract was audited against and reports the verdict as its exit
  code, replacing a manual `curl` + `sha256sum` opening step.
- **One housekeeping command, and a smaller skill surface.** `/hooks-daemon housekeeping` runs the whole housekeeping pass in one go — plan QA, docs
  QA, the daemon's own audits, the formatters, `optimise` to close — with
  mutating steps gated behind `--apply <step>`.

### Client Projects

- **The TDD gate can be told about a nested mirror test root.**
  `tdd_enforcement.test_path_map` entries now take `mirror: true`, and a
  nested `layout.test_dirs` entry is searched as a mirror root with no map
  entry at all — a PHP project laid out as `tests/Small/<mirror of src>/FooTest.php` can keep the gate on instead of disabling it.
- **A stdout-only `sed` deny explains itself, and `validate-config` works.**
  `sed -n 'N,Mp' file` is still denied — deliberately — but the message now
  says why and names the working replacements; `hooks-daemon validate-config`
  is accepted as an alias of `config-validate`.
- **`echd-capture` is deployed to clients.** The output-capture helper
  `pipe_blocker` recommends instead of `| tail` is now installed and upgraded
  alongside the CLI wrapper, closing an `echd-capture: command not found`
  report from the field. When its capture directory cannot be created, it
  now passes the output through unchanged with a warning instead of silently
  discarding the stream and exiting 0.
- **The fresh-clone upgrade completes, and every version check accepts the
  tag form.** A client upgrading from a fresh clone (config and forwarders
  present, no venv yet) no longer rolls back at the daemon-stop step; every
  version-comparing check now accepts both `v3.62.0` and `3.62.0`.
- **The post-upgrade truth-changes report surfaces each truth once.** Entries
  sharing an `id` across releases are one truth revised repeatedly and now
  show only the current form, marked with every release that revised it.
- **A handler key that no longer exists for its event is reported, and two
  detectors move themselves.** `config-validate`, `check-config-migrations`
  and the new `hooks-daemon audit-handler-keys` check every configured key
  against the handler registry; the upgrade moves
  `stop.hedging_language_detector` and `stop.dismissive_language_detector`
  into `pseudo_events.nitpick.handlers` for you (see Config Changes below).

### Handler Authors

- **An ALLOW never ends the dispatch chain.** Terminality is now a property
  of the DECISION, not of the handler: a DENY (or ASK/DEFER) from a
  `terminal=True` handler still ends the chain, but an ALLOW from any
  handler now continues to the next handler with its context kept, whatever
  its `terminal` flag says — closing, by invariant, the defect class where a
  terminal handler's advisory ALLOW silently disabled every handler behind
  it. `daemon.chain.collect_all_violations` (off by default) additionally
  keeps the chain running after a deny and returns one merged response
  instead of stopping at the first. An early handler's contentless ALLOW no
  longer drops a later handler's accumulated guidance, `updated_input` or
  `worktree_path` as the chain and the front controller hand off between
  handlers — a defect in this same continue-past-ALLOW behaviour, fixed
  before this release tagged.

## Security

- **`git rm --cached --pathspec-from-file=<protected file>` closed as a
  secret-disclosure route.** Git echoes the protected file's own lines back
  in its error text for this flag, so the `git rm --cached` hygiene
  exemption no longer applies when `--pathspec-from-file` is present. The
  exemption also now skips a leading global git flag (`-C`, `-c`).
- **`sensitive_content` gained two scanning surfaces: staged commit content
  and `gh` bodies.** A `git commit` is denied when the ADDED lines of any
  staged file (the working tree for `-a`) carry a secret-list term or public
  pattern — closing the route where a file arrives by `mv`/`cp`/redirect and
  reaches history unexamined — and a `gh issue|pr comment|create|edit` body,
  inline or from `--body-file`/`-F`, is judged the same way a commit message
  already was. Four follow-up fixes to that same new scanning landed before
  tagging: a content-keyed cache so the same file body is not re-scanned per
  pattern, a quoted `-a` no longer misread as `git commit -a`, a git-quoted
  staged path with escaped characters now unquoted before it is read, and an
  unreadable `--body-file` logged and skipped rather than crashing the scan.
- **Two plumbing synonyms for already-blocked destructive git commands are
  closed, and the second is now scoped correctly.** A `+`-prefixed refspec
  (`git push origin +main:main`) and `git update-ref -d refs/heads/<name>`
  are denied under the same rule IDs as `git push --force` and `git branch -D`; the `update-ref` pattern no longer spans a command separator, so an
  unrelated command chained after it is no longer swept into the match.

## Also In This Release

Four follow-up findings from the v3.62.1 release-review gate itself are
closed (Plan 00340): the ccy supervisor's resubmit Enter is now paced behind
its own escape, shrinking a modal-dialog confirm window (e.g. the `/model`
picker) from up to 60 seconds to a two-second follow window; the duplicated `_walk_into`
docs-QA tree walker is now one shared implementation; `config_preserve.sh`
no longer leaks Layer 1's handover on an early exit and its captured CLI
diagnostics can no longer corrupt a JSON payload; and a heredoc whose
redirect follows a punctuated delimiter (`<<'EOF-1'`) is now recognised, with
the redirect itself kept visible to the guards that judge it. Separately, a
live dogfooding incident (four hourly failsafe-cron ticks each consuming a
full model turn and doing nothing) is fixed at the root: the
failsafe-cron human-input suppression marker now arms reliably (Plan 00314),
the `[awaiting-human]` `STOPPING BECAUSE:` token replaces four hardcoded
phrases nobody was told about (Plan 00337), the prose-guard against a handler
matching its own trigger vocabulary now reaches Stop handlers as well as
PreToolUse (Plan 00342), and Plan QA's `header-body-coherence` check now
catches a stale `Not Started` header sitting behind already-shipped work
(Plan 00341).

## Breaking Changes

None. No handler, configuration key or CLI subcommand was removed in this
release, and no default behaviour changed in a way that fails
previously-valid configuration.

**One config-key move is worth knowing about even though it is not
breaking.** `handlers.stop.hedging_language_detector` and
`handlers.stop.dismissive_language_detector` move to
`pseudo_events.nitpick.handlers.hedging_language`/`.dismissive_language`. A
config still carrying the old keys was **already** silently running neither
detector before this release — `config-validate` called it valid regardless.
This release only makes that previously-invisible gap detectable
(`hooks-daemon audit-handler-keys`) and self-healing (the upgrade migrates
it for you), so nothing that worked before this release stops working. **One
visible consequence still follows the migration**: a detector that was
silently doing nothing starts actually running for any config that carried
`enabled: true` under the old key, so you may see nitpick advisories you have
never seen before — this release is why. See
`CLAUDE/UPGRADES/config-changes/v3.63.0.yaml` for the full manifest entry.

## Post-Upgrade Tasks

`CLAUDE/UPGRADES/v3/v3.62.1-to-v3.63.0/post-upgrade-tasks/` has one
`optional` task: dropping a `HOOKS_DAEMON_PYTHON` override that only existed
to work around the old fixed-candidate-list interpreter discovery, now
superseded by discovery that finds the highest qualifying `python3.NN` on
`PATH` unaided. It applies to nobody who never set the variable.

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.63.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

bash .claude/hooks-daemon/scripts/upgrade.sh --project-root "$PWD" "v3.63.0"

.claude/hooks-daemon/bin/hooks-daemon restart
```

**Use `upgrade.sh` (Layer 1), not `upgrade_version.sh` (Layer 2) directly** —
Layer 1 is the documented entry point; invoking Layer 2 on its own skips
steps Layer 1 is responsible for sequencing.
