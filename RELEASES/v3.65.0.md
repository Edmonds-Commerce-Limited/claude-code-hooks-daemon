# Release v3.65.0 - The Security Review Becomes a Routine

**Release Date:** 2026-09-16
**Type:** Minor Release

## Summary

This is a guard-review release. Plan 00412 turns security review into a
routine with its own append-only ledger (`CLAUDE/Routine/`, `run-routine`,
`routine-qa`) and runs it against every existing guard, closing eleven
bypasses and asymmetric-sibling defects and adding two handlers that watch
the guard config itself — `guard_config_drift` and `guard_config_commit_gate`.
Plans 00416 and 00417 give session start and session end teeth: a computed
action tier, a declared cron that is verified rather than announced, a
must-do list delivered as a turn, and an operator channel for reboot and
shutdown warnings. Plans 00409 and 00413 close the correctness tail: the
v3.64.0 heredoc regression, a fresh clone that can actually start, an
unattended-question gate, and `find-plan`. Sixteen things v3.64.0 allowed
now deny — five new `destructive_git` rules, a widened `sensitive_content`
publication surface, `~` write targets, `install`/`dd` worktree relocation,
and more — with no single flagship rename this cycle; each item in the
"⚠️ BREAKING CHANGES" section below names the exact command shape affected.
Attribution below cites a plan as the TRACKING plan for a work area, not as
the origin of every fix in it.

## Highlights

### Everyone

- **A v3.64.0 regression let destructive git commands through a heredoc —
  upgrade if you are on v3.64.0 (Plan 00409).** That release stopped denying
  five destructive `git` spellings when they were written as
  `bash <<'EOF' … EOF`. The quoted delimiter governs only what the OUTER
  shell expands on the way in — it never stops the receiving interpreter
  from running the bytes — but the command text was blanked before the
  guards judged it, so every guard saw an empty command and allowed it.
  Measured rather than argued: the shipped v3.63.0 module was recovered
  from its tag and run side by side with v3.64.0's — v3.63.0 denied all
  five spellings, v3.64.0 allowed every one. This was a regression
  introduced in v3.64.0, not a pre-existing gap, so v3.63.0 and earlier are
  unaffected. Now fixed: a heredoc body is exempt from scanning only when
  nothing on its line can EXECUTE it. `cat`, `tee`, `git` and similar
  consume their input as data and keep the exemption; `bash`, `sh`,
  `python3`, `ssh` and anything piped onward do not, and their bodies are
  scanned like any other command.

- **SessionStart messages now carry a computed action tier (Plan 00416).**
  Session-start output had grown to the point where an agent reads all of
  it and acts on none of it — every advisory looked equally urgent, so none
  of them was. Each SessionStart message now carries one of three tiers,
  rendered into the emitted block: `ACTION_REQUIRED`, `ACTION_SUGGESTED` or
  `INFO`. **The tier is computed, never declared.** A message is
  `ACTION_REQUIRED` only if it ships a verifier AND that verifier is
  currently failing — a `declared_tier` arriving from anywhere is clamped
  to `INFO` and logged at ERROR, so tier inflation is impossible by
  construction rather than discouraged by convention. `hooks-daemon session-actions` prints the current tier for every SessionStart handler
  (`--format json` for machine reading), so you can see what a session
  would be told without starting one.

- **A declared persistent cron is now enforced, not just announced (Plan
  00416).** Claude Code crons do not survive a session, so a project that
  needs recurring work declares it under `persistent_crons` and the
  SessionStart advisory asks the agent to reconcile with `CronList` — an
  advisory that was routinely read and routinely ignored, and nothing
  noticed. `session_crons` is not delivered to SessionStart, but it IS
  delivered to `Stop`/`SubagentStop`, and two new handlers —
  `cron_stop_enforcer` and `cron_subagent_stop_enforcer` — compare what the
  project declared against what the session actually has, and block the
  stop naming the exact missing `CronCreate` (id, schedule and full
  prompt). An absent `session_crons` field means "no information", never
  "no crons exist", and can never block. Matching is on schedule plus
  prompt, normalised for layout — a declared prompt reaches `CronCreate`
  only by being rendered into an advisory and retyped by an agent, and that
  round trip re-flows it. Both handlers are silent unless
  `persistent_crons` is enabled with at least one declared job.

- **The must-do list can arrive as a turn, not as session-start context
  (Plan 00416).** Tagging session-start messages with a computed tier does
  not make the must-do set get read — injected context is scenery. What
  changes the outcome is the channel: `session_actions_directive` (opt-in)
  writes a `<session>.session-actions` signal when a session starts with
  one or more `ACTION_REQUIRED` items, and the ccy supervisor types one
  short directive naming the count and pointing at
  `hooks-daemon session-actions`. **The signal carries a number and nothing
  else** — a positive integer count the supervisor interpolates into a
  fixed template it owns, so there is no text to forge.

- **Routines: recurring work that never completes (Plan 00412).** This
  project models work as Plans: numbered, one-shot, archived when done —
  a shape that fits nothing that has to happen *again* (a security review,
  a dependency audit, an access re-check). `CLAUDE/Routine/` is the tree
  for that second kind: a Plan finishes, a Routine recurs. Each routine
  declares its cadence and its procedure and records every run in a
  `RUNS/` ledger; `hooks-daemon run-routine <id>` starts a run and derives
  the interval from the ledger rather than asking the operator to remember
  it, and `--finish --outcome clean|findings|skipped` closes it. The hard
  problem is that a run that never happened leaves no record at all, so
  its absence cannot be observed from the records themselves —
  `routine_qa_sweep` (opt-in SessionStart) is the dead-man's switch,
  running five drift checks and staying silent on a clean tree. Ships
  disabled: most projects have no `CLAUDE/Routine/` tree, and `matches()`
  only fires once one is declared.

- **`hooks-daemon find-plan <number|name|words>` (Plan 00413).** Searches
  the whole plan tree including `Completed/`, printing each match's
  number, status and path, and is now named in `plan_number_helper`'s deny
  message — the affordance the folder-scan guard was missing.
  `hooks-daemon explain-handler <name>` also now resolves **project**
  handlers as well as library ones — the generated `CLAUDE.md` tells the
  reader to look up its own project handlers with exactly that command, and
  until now the first entry in that list answered "unknown handler".

- **`ask_user_question_blocker` gains `options.mode: unattended` (Plan
  00413).** Claude Code's own "nobody is watching" mechanisms are launcher
  flags and cannot reach a cron firing into a live interactive session;
  with the mode set (opt-in), every question is refused and the agent is
  told to choose the option it would have recommended and continue.

- **A scoped QA scan no longer overwrites the repository-wide verdict (Plan
  00413).** `check_sensitive_content.py --path <dir>` was publishing its
  answer for whatever it scanned as though it were the whole repository's
  answer — the artefact the QA suite hands an agent to read. A plain test
  run could leave it reading `passed: false` against a path under `/tmp`
  while the repository itself was clean.

- **BREAKING: `destructive_git` gains five rules (Plan 00412).** See the
  "⚠️ BREAKING CHANGES" section below.

### Operators

- **The host can now warn a running session before it reboots (Plan
  00417).** Interactive sessions run in a container on a machine that
  operators and automated patch cycles reboot, and nothing told the agent:
  work in flight was cut off mid-step, uncommitted changes were lost, the
  next session re-derived where things stood. `bin/hooks-daemon signal`
  closes that gap, delivering a warning through the ccy supervisor when
  Claude is next idle — `signal reboot-warning --minutes 10 --all-sessions`,
  `shutdown-warning`, and `reboot-cancelled`. The agent is told to commit
  and push, journal where it got to, finish the current step and start
  nothing new. **The channel carries no free text, deliberately** — it is
  the only signal family writable from outside the container, so it is
  built closed rather than validated: the payload is at most a positive
  integer, a `kind` selects one of three pre-written sentences, and the
  wording lives in the supervisor, in code, under test.

- **Unattended sessions can say so (Plan 00413).** See the `ask_user_question_blocker` entry under Everyone above.

- **`hooks-daemon verdicts` no longer counts its own test harness (Plan
  00418).** `verdicts.jsonl` recorded acceptance-playbook probes and the
  forwarder's socket-test fires in the same undifferentiated stream as your
  agents' real tool calls — on this project's own log that was half the
  window — so every per-handler count the report printed blended a harness
  with a workflow. Records now carry a `synthetic` field naming the harness
  that produced them, and the report excludes them by default; pass
  `--include-synthetic` to fold them back in when debugging the harness
  itself. Expect per-handler counts to drop, and a handler that only ever
  fired in the acceptance suite to move into "never fired" — the accurate
  statement.

- **`host_hostname`, a new opt-in status-line segment (Plan 00411).** Shows
  which MACHINE a session is on beside `environment_indicator`'s which
  KIND, resolved from `CCY_HOST_HOSTNAME`, then
  `HOOKS_DAEMON_HOST_HOSTNAME`, then `gethostname()` (host/LXC only), then
  an `/etc/hosts` self-alias rendered as `@~name` to mark it INFERRED;
  silent inside a container with no export. There is deliberately no
  config option for the name itself, since `.claude/hooks-daemon.yaml` is
  tracked and routinely public.

### Client Projects

- **Four gates that failed on a correctly-configured project, all fixed
  (Plan 00419).** Declaring `layout.source_dirs` silently switched off
  every TDD language strategy's file-level exclusions, so a project that
  described its own layout lost Python's `__init__.py` exemption and was
  asked for a `test___init__.py` — file-level exclusions are now consulted
  ahead of both location rules. The security-downgrade QA check walked
  into linked worktrees and reported every file in them a second time,
  failing the gate with paths that vanish when the worktree does —
  `worktrees` is now excluded from the walk. Worktree seeding gained
  `optional: true` per entry, so a gitignored file that is legitimately
  absent no longer kills every `WorktreeCreate` in the project (absence is
  all it excuses — an entry that escapes the repository is still fatal).
  And when a `WorktreeCreate` handler does fail, the forwarder now prints
  the real reason on stderr instead of asking whether the handler is
  enabled.

- **`scripts/debug_hooks.sh` runs in the repository that dogfoods it, and
  on macOS bash 3.2 (Plan 00419).** Three documents name it as the
  sanctioned way to capture real hook payloads before writing a handler; it
  now finds the socket in both installation layouts and reaches its own
  `CLAUDE_HOOKS_SOCKET_PATH` fallback instead of dying silently under
  `set -e`.

## ⚠️ BREAKING CHANGES

**Sixteen command/edit shapes that v3.64.0 allowed now deny.** None of
them is a config key rename or a behaviour flip on an existing default —
each is a guard that previously let something through and now does not.
No handler was removed or renamed this release, and no existing config
default changed. Full detail, a pre-upgrade checklist, and worked examples
for every row:
[v3.64.0 → v3.65.0 Upgrade Guide](../CLAUDE/UPGRADES/v3/v3.64.0-to-v3.65.0/v3.64.0-to-v3.65.0.md).

### Newly denied — always in effect

| #   | What now denies                                                                                                                           | Rule / handler                                                  | If you need it                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| B1  | `git checkout -f` / `git checkout --force`                                                                                                | `R-GIT-CHECKOUT-FORCE` (`destructive_git`)                      | Commit or stash first; ask a human to run the force checkout manually                                                     |
| B2  | `git switch -f` / `git switch --discard-changes`                                                                                          | `R-GIT-SWITCH-FORCE` (`destructive_git`)                        | Same — commit/stash first, or ask a human                                                                                 |
| B3  | `git reflog expire --expire=now`                                                                                                          | `R-GIT-REFLOG-EXPIRE` (`destructive_git`)                       | Use a real expiry window (`--expire=90.days.ago`), which is not blocked                                                   |
| B4  | `git gc --prune=now`                                                                                                                      | `R-GIT-GC-PRUNE-NOW` (`destructive_git`)                        | Plain `git gc` or `git gc --auto` are not blocked; use a prune window                                                     |
| B5  | `git filter-branch` / `git filter-repo`                                                                                                   | `R-GIT-FILTER-HISTORY` (`destructive_git`)                      | Ask a human to run it manually, on a fresh clone with a backup ref                                                        |
| B6  | `env <command> \| head`/`\| tail` (any command run through `env`)                                                                         | `pipe_blocker` (whitelist entry removed)                        | Use `bin/echd-capture`, or drop the `env` wrapper if it isn't needed                                                      |
| B7  | A `Bash` write target starting `~/` (e.g. `curl -o ~/x.sh`)                                                                               | `R-WRITE-OUTSIDE-PROJECT-ROOT` (`project_containment`)          | Write inside the repository instead — `untracked/scratch/` is the scratch location                                        |
| B8  | `install`/`dd` relocating a file between a worktree and the main repo                                                                     | `R-WORKTREE-FILE-COPY` (`worktree_file_copy`)                   | cd into the worktree, commit, then `git merge` back                                                                       |
| B9  | A path-qualified `gh` (`/usr/bin/gh …`, `./gh …`) publishing sensitive content                                                            | `sensitive_content`                                             | Fix the flagged content — the qualification never made the publish safe                                                   |
| B10 | `gh release create/edit --notes`, `gh gist create --desc`, `gh pr review --body`, `gh repo edit --description` carrying flaggable content | `sensitive_content`                                             | Remove the flagged text before publishing                                                                                 |
| B11 | A `git`/`gh` message via `-F <file>`/`--file=<file>` that contains flaggable content                                                      | `sensitive_content`, `github_auto_close_keywords`               | Fix the file's content before use — it is read like an inline message now                                                 |
| B12 | Any `Edit` inside the remote-docs tree, regardless of what changed                                                                        | `R-REMOTE-DOCS-PROVENANCE` (`remote_docs_provenance`)           | Do not hand-edit vendored docs — re-capture with `hooks-daemon remote-docs refresh --path <stored-path>` (or `--all`)     |
| B13 | A `bash`/`python3`/`ssh` heredoc body that mentions a destructive command                                                                 | already documented as of v3.64.0 — carries forward              | See the existing heredoc-guard guidance                                                                                   |
| B14 | A `Stop`/`SubagentStop` while a declared `persistent_crons` job is missing from the session                                               | `cron_stop_enforcer`, `cron_subagent_stop_enforcer`             | **Conditional.** Only fires with `persistent_crons.enabled: true` and a declared job. Re-declare the missing `CronCreate` |
| B15 | A `PLAN.md` edit/commit/sweep with an unticked criterion waiting on a release to ship                                                     | `release-blocked-plan` plan-QA check                            | **Conditional.** Stage the release-bound consequence into `CLAUDE/UPGRADES/UNRELEASED/` instead                           |
| B16 | Every `AskUserQuestion` call                                                                                                              | `R-ASK-USER-QUESTION-UNJUSTIFIED` (`ask_user_question_blocker`) | **Opt-in.** Only denies when `options.mode: unattended` is set                                                            |

Whether the five `destructive_git` denials (B1–B5) count as "breaking" for
SemVer purposes is a judgement call — they deny commands that were
previously silent, not commands anyone was relying on working a particular
way. This release follows the same precedent v3.64.0 set for its own
breaking change: document it plainly, still ship MINOR.

**Message/scope/output changes to nine existing rules** — `header-body-coherence`'s completion finding moves from BLOCK at edit to ADVISE
plus a new COMMIT registration at BLOCK (a tightening, not a relaxation);
`WorktreeCreate` forwarder failure output; `ask_user_question_blocker`'s
unattended-mode deny reason; `guard_config_drift`'s finding text;
`remote-docs refresh`'s new `REFUSED` outcome; `harvest-background`'s
TTL-breach report; `gitignore_safety_checker`'s derived entry list;
`emit_hook_error()`'s fresh-clone remedy prose; and
`WorktreeRemove.can_block` flipping `False → True` in the vendored hooks
contract. None renames an output field. Full detail in the
[upgrade guide](../CLAUDE/UPGRADES/v3/v3.64.0-to-v3.65.0/v3.64.0-to-v3.65.0.md#message--scope--output-changes-to-existing-rules).

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.65.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

bash .claude/hooks-daemon/scripts/upgrade.sh --project-root "$PWD" "v3.65.0"

.claude/hooks-daemon/bin/hooks-daemon restart
```

**Use `upgrade.sh` (Layer 1), not `upgrade_version.sh` (Layer 2) directly** —
Layer 1 is the documented entry point; invoking Layer 2 on its own skips
steps Layer 1 is responsible for sequencing.

**Read the "⚠️ BREAKING CHANGES" section above before upgrading** if your
project or its agents run any of the sixteen newly-denied command shapes.
