# v3.60.0 — Budget-Exhaustion Advisory and ccy Supervisor Hot-Reload Fixes

**Release Date:** 2026-09-02
**Type:** Minor Release

## Summary

This release adds a generic PostToolUse advisory (`budget_exhaustion_detector`)
that catches hidden agent budget/quota-exhaustion messaging in a completed
tool call's response and tells the agent to surface it to the user
prominently instead of retrying or silently degrading. It also ships three
fixes to the ccy supervisor's hot-reload architecture and model-switch
behaviour: typed-command recognition moves from the never-reloading host
process into the hot-reloadable worker subprocess, a human-typed `/model`
choice now always wins over the supervisor's auto-restore and effort
coupling, and the supervisor's audit trail moves from a chat injection to a
transient, self-clearing status-line banner. A failsafe-cron marker defect
from the v3.59.0 release night — a marker that could match but silently fail
to write — is fixed with observable write outcomes. No breaking changes.

## Highlights

- **`budget_exhaustion_detector` (Plan 00315)** — new PostToolUse handler,
  enabled by default, advises on budget/quota-exhaustion tool-response
  messaging (web-search refusals and generic budget/quota shapes) so the
  agent reports the hit instead of retrying blindly. Logs occurrences to an
  untracked ledger.
- **ccy supervisor host becomes a thin shim (Plan 00317)** — typed-command
  RECOGNITION (`/compact`, `/model <x>`, `/effort <x>`) moves worker-side via
  a new `RawInputTap`, so an edit to command parsing now ships live on the
  worker's next hot-reload with no session restart.
- **Manual `/model` choice always wins (Plan 00316)** — fixes the supervisor
  auto-restore silently overriding a human-typed `/model opus`; model
  switches and effort now apply in time order, and the status line's
  downgrade indicator recognises a manual model change so it is never
  mis-reported as a silent downgrade.
- **Supervisor audit trail becomes a status-line banner (Plan 00318)** — the
  audit trail no longer injects into the chat transcript; `supervisor_indicator`
  renders a live countdown on any message carrying `countdown: true`.
- **Failsafe-cron marker write outcome now observable (Plan 00314)** — fixes
  a v3.59.0-release-night dogfood defect where the "blocked only on human
  input" marker could match but silently fail to write; also widens the
  matched pattern family to catch "waiting on human response" phrasing.

## Changes

See [CHANGELOG.md](../CHANGELOG.md) for the full categorized entry. Summary:

### Added

- `budget_exhaustion_detector` PostToolUse handler (Plan 00315).

### Changed

- ccy supervisor host thin-shim: typed-command recognition moves worker-side
  via `RawInputTap` (Plan 00317).
- Manual `/model` choice wins over supervisor auto-restore and effort
  coupling; `downgrade_indicator` recognises manual model changes (Plan
  00316).
- Supervisor audit trail moves from chat injection to a countdown-bearing
  status-line banner (Plan 00318).

### Fixed

- Failsafe-cron suppression marker write outcome now observable; "blocked
  only on human input" pattern widened to include "human" phrasing (Plan
  00314).
- `budget_exhaustion_detector` no longer false-fires on documentation about
  itself — the self-referential marker guard now also covers the tool
  RESPONSE, not just the command.
- `quarantine_artefact_read_guard` and `sensitive_content` declared
  acceptance-test patterns their own deny reasons could no longer produce,
  making the release acceptance gate unpassable for two correct handlers.
  Both now derive the expected header from their `RuleID`.

## Breaking Changes

None. No handler was removed or renamed, and no config schema entry was
removed, renamed, or had its default behaviour changed. The one new handler,
`budget_exhaustion_detector`, ships enabled by default (opt-out) and is
advisory only — it never blocks a tool call, only appends guidance after the
call has already completed.

## Installation

### New Installations

```bash
mkdir -p .claude
git clone -b v3.60.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon. Never hand-build a venv — the resolver refuses the
# retired pre-v3.7.0 layout.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

### Upgrading Existing Installations

```bash
cp .claude/hooks-daemon.yaml .claude/hooks-daemon.yaml.backup
git -C .claude/hooks-daemon fetch --tags

# Rebuilds the venv and reinstalls the package for the target version.
bash .claude/hooks-daemon/scripts/upgrade_version.sh \
  "$PWD" "$PWD/.claude/hooks-daemon" "v3.60.0"

.claude/hooks-daemon/bin/hooks-daemon restart
```
