# v3.37.0 — graduated supervisor compaction bands + plan-QA root-file allowlist

**Release date**: 2026-07-12
**Type**: MINOR release

## Summary

v3.37.0 refines the ccy PTY supervisor's auto-`/compact` behaviour into a
graduated, three-band escalation and adds an additive plan-QA allowlist for
legitimate non-plan files at the plan root.

v3.36.0 made the supervisor inject `/compact` promptly as soon as context went
red — which kept context bounded but could interrupt a turn that was still
doing useful work. This release brings back the older "wait for a lull"
politeness at the red band, while keeping prompt injection for the more urgent
middle band and the ESC-flush fallback for the critical band. The response now
scales with how full the context actually is:

- **Red band `[red, midpoint)`** — patient: wait for the child to go quiet
  before injecting `/compact`, so an active turn is never cut off mid-burst.
- **Elevated band `[midpoint, critical)`** — inject `/compact` promptly, even
  mid-turn (the v3.36.0 behaviour).
- **Critical band** — inject `/compact` **and** retain the ESC-key flush.

Alongside the supervisor work, `plan_workflow.qa.extra_root_files` lets a
project allowlist a genuinely-placed non-plan file (e.g. a sourced
`_planlib.bash`) at the plan root so it is no longer reported as a stray file on
every session start and commit.

No breaking changes. Fully backwards compatible — one new opt-in
`hooks-daemon.yaml` key (`plan_workflow.qa.extra_root_files`, default empty list
= no behaviour change); the supervisor banding is active by default.

## Highlights

- **Graduated compaction bands.** The supervisor escalates its `/compact`
  response across three depth bands instead of firing identically across the
  whole red range — patient at red, prompt at the midpoint, prompt + ESC-flush
  at critical.
- **Politeness restored at red.** In the red band the supervisor waits for a
  `work_idle` quiet window (default 3s of no child output) before injecting, so
  an in-progress turn is not interrupted.
- **Midpoint is single-sourced.** `context_tiers.py` computes the midpoint as
  `(red + critical) // 2` (200k-window 83%, 1000k-window 50%) and surfaces it
  through the context sidecar as `compact_urgent`, so the supervisor reads the
  band rather than recomputing thresholds.
- **ESC-flush is critical-only.** The `[esc]` flush fallback now fires at the
  critical tier only, rather than across the red range.
- **Plan-QA root-file allowlist.** `plan_workflow.qa.extra_root_files` allowlists
  extra non-plan filenames at the plan root (layered on the built-in accepted
  set), silencing the permanent stray-file advisory for a legitimately-placed
  helper like a sourced `_planlib.bash`. Exact-filename match; default empty.

## Changes

### Added

- **Graduated supervisor compaction bands** (Plan 00152) — three depth bands
  keyed on context: red band is patient (defers injection until the child's
  output settles for the `work_idle` window, default 3s); elevated band
  `[midpoint, critical)` injects `/compact` promptly even mid-turn; critical band
  injects `/compact` and keeps the ESC-key flush. Midpoint is `(red + critical) // 2` — 200k-window 83%, 1000k-window 50%.
- **`compact_urgent` midpoint band in the shared classifier** — `context_tiers.py`
  gains `compact_urgency_pct()` and `is_compact_urgent()` (single source of truth
  for the midpoint), exposed through the context sidecar payload as
  `compact_urgent` so the supervisor consumes the band directly.
- **`plan_workflow.qa.extra_root_files`** (Plan 00153) — additive allowlist of
  extra non-plan filenames permitted at the plan root, layered on top of the
  built-in accepted set (`README.md`, `CLAUDE.md`, `mkplan.bash`, `_TEMPLATE_.md`).
  The `PlanTree.scan` classifier unions the configured names into the accepted
  set. Exact-filename match; default empty list, so absent config changes nothing.

### Changed

- **Supervisor child-output activity tracking** — the forwarding loop records
  master-fd output activity (`OutputActivity`) and derives a `work_idle` signal so
  the patient red band defers injection until the child has been quiet for the
  settle window. The ESC-flush is now gated on the critical tier.

No breaking changes — no upgrade guide required.

## Post-Upgrade / Config

The new `plan_workflow.qa.extra_root_files` key is documented in the config-changes
manifest (`CLAUDE/UPGRADES/config-changes/v3.37.0.yaml`). It is optional and not
recommended-on: add an entry only if you intentionally keep a non-plan file (e.g.
a sourced `_planlib.bash` helper) at the plan root and want to silence its
permanent stray-file advisory. Example:

```yaml
plan_workflow:
  qa:
    extra_root_files:
      - "_planlib.bash"
```

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required. The graduated supervisor bands are active
automatically after upgrade + daemon restart. Projects running the ccy supervisor
should ensure `ccy.deploy_supervisor` is `true` (or absent) so the refreshed
`claude-supervise.py` is deployed.

## Installation

### New Installations

```bash
mkdir -p .claude && cd .claude
git clone https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
git fetch --tags && git checkout v3.37.0
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.37.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
