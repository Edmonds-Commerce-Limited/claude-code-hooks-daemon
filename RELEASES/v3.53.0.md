# v3.53.0 — Scope Is Part of the Contract

**A large release: 231 commits, ~36 plans, since v3.52.0.**

Two things dominate it. A **security fix** — the daemon has been creating every
one of its runtime files world-writable since it was written, and that includes
the raw hook payloads. And a **subtraction**: 22 handlers removed, all of them
either dead, shadowed, or dormant, none of them breaking anyone's config.

## 🔒 Security: your daemon's runtime files are world-writable

**Every release before this one created daemon runtime files at `0666`, and
directories at `0777`** — readable *and writable* by every local user on the
machine. That includes:

- `untracked/logs/hooks/verdicts.jsonl` — what every handler decided about
  every tool call, with the command strings
- `untracked/payload-capture/` — raw hook payloads, i.e. the full body of every
  `Write` and `Edit`, when capture is enabled
- the stop-event log, the per-session sidecars, the PID file, the `.socket-path`
  discovery file

The cause was `os.umask(0)` in the daemonise path. That is the textbook Stevens
daemonise step and it is safe **only** for a daemon that passes an explicit mode
to every create. This one did so at exactly **1 of 98** create sites.

The daemon now applies `umask 0o077`. The three artefacts whose contents are
known-sensitive also pass an explicit mode at the create site, so the guarantee
survives someone later "restoring" the textbook line. Two `tmp`-then-`replace`
writers were silently rewriting their target's mode as well — one of them on a
**git-tracked** file — and now copy it across.

### ⚠️ This does not fix the files you already have

A umask governs **creates**. It retro-fixes nothing. Every file your daemon has
already written keeps `0666` until something changes it:

```bash
.claude/hooks-daemon/bin/hooks-daemon check-permissions        # report (exit 1 while findings remain)
.claude/hooks-daemon/bin/hooks-daemon check-permissions --fix  # tighten
```

**One behaviour change to expect**: a second user account can no longer *read*
the daemon's runtime files — most visibly a container running the daemon as
`root` over a bind-mounted project while you work on the host. That is the
intended fix, not a casualty. It does not break daemon sharing, because
cross-UID sharing was never possible: the socket is `0660` owned by the daemon's
user and no code anywhere sets a shared group, so a second UID was already
refused at `connect()`. Verified with a real second account, not assumed.

## 🔒 Also fixed: a handler could switch off the handlers behind it

The PreToolUse chain stops at the first **terminal** handler that matches —
whatever it decided. So a blocking handler that *also* has an advisory path
ended the chain whenever it took that path. `comment_changelog` and
`comment_size` both did, at priorities 31 and 33.

The practical effect: writing an ordinary English phrase such as "no longer"
in a code comment, or merely *shrinking* an over-long one, was enough to
disable `tdd_enforcement` and every other handler behind them for that write.
`comment_changelog` is on by default, so this reached every install — and
nothing reported it, because a shadowed handler and a handler that simply did
not match look identical from outside. `ancestry_preserving_merge` and
`git_stash` had the same shape in `warn` mode.

All four are now non-terminal, which costs no enforcement: the chain keeps the
most restrictive decision it has seen, so a non-terminal deny still denies.

**`check-permissions` had a blind spot in the same release that introduced
it**: it audited everything *inside* the directory but never the directory
itself, so a world-writable `untracked/` — the exact thing `umask(0)` created,
and the one that lets any local user replace the socket and verdict log inside
it however tight those files' modes are — was reported clean. Fixed, and
`--fix` now tightens it.

Also fixed: the verdict log lost its newest records under concurrent dispatch
and rewrote itself on nearly every hook event once full; `comment_size`
crashed on latin-1/CP1252 sources; `pipe_blocker` denied `git -C … | head`
while allowing the bare spelling, and missed `|&` entirely; and every
generated config carried duplicate YAML keys that a strict loader rejects.

## Removed: 22 handlers, zero breakage

| What                                                      | Why                                                                                                                                |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `transcript_archiver`                                     | Copied the transcript before every compaction and protected nothing. 422 MB of archives guarding 302 MB of originals in this repo. |
| 12 dead handlers                                          | Several registered *behind* a terminal handler, so they had never run in any release. The guard built to find them found more.     |
| 10 `hello_world` canaries + `enable_hello_world_handlers` | Dormant in every project since v3.40.0. The QA smoke test proves more, against the live daemon, with real payloads.                |

**Every one of these is backwards-compatible.** A config still naming a removed
handler validates cleanly — the daemon carries a registry of retired names — so
an unedited config will **not** be put into degraded mode. This was verified by
injecting the retired keys into a real client install and restarting, not by
reasoning about it.

## Added

- **`git_message_backtick`** — a backtick in a double-quoted `git commit -m` is
  *executed* by bash and the span silently replaced. A commit in this
  repository's own history lost a phrase exactly this way. Measured before being
  made blocking: of 1,736 commit messages here, all 120 containing backticks are
  evidence of safe authoring, so the rule would have fired on none of them.
- **`standing_authorisations`** — a durable place for a project to record a
  standing request, since one made in conversation is gone by the next session.
  A filing cabinet, not a countermand: every entry ships **disabled**, because
  the daemon must never assert consent that was not given.
- **`daemon.verdict_log` + `hooks-daemon verdicts`** — metadata-only record of
  what every handler decided, so "which handlers earn their keep?" stops being
  answerable only by anecdote.
- **`hooks-daemon check-permissions [--fix]`** — the batch half of the security
  fix above.
- **`plan_workflow.scripts`** (the planlib bash library) and the
  **`hooks-daemon-plan-dedupe-scout`** agent.

## Changed

- `daemon.verdict_log.record_status_events` now defaults **false**. Status
  renders were 43,929 of 44,180 retained records (99.43%), filling the 10 MiB
  cap in 65 minutes; excluding them stretches it to about 8 days.
- `plan-doc-size` now names **three** remedies, EXTRACT first. The old
  two-remedy wording drove an agent to compress prose five times and delete a
  decision table purely to clear a threshold; extracting instead took that plan
  from 19,045 to 9,520 bytes with all 31 tasks intact.
- Every daemon-owned file committed into your repo now opens with a
  **DAEMON-OWNED** banner. Expect a large comment-only diff.

**In the Claude Code chat.** This is a skill invocation you type into Claude
Code — it is NOT a shell command and will not run in a terminal:

```text
/hooks-daemon upgrade
```

**From a terminal**, run the deployed skill script instead:

```bash
.claude/skills/hooks-daemon/scripts/upgrade.sh
```

No config changes are required. Every removed key and handler name is tolerated
by the validator.
