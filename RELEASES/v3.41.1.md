# Release v3.41.1 - pipe_blocker echd-capture Path Fix

**Release Date:** 2026-07-15
**Type:** Patch Release

## Summary

This patch release fixes a real-world regression: the `pipe_blocker` handler's
recommended alternative to piping into `tail`/`head` — the `echd-capture`
helper introduced in v3.41.0 — was recommended as a bare command name, but in
client installs the helper was not reliably on `PATH`. Agents following the
handler's own guidance would hit a "command not found" error. The resolver now
always returns either an absolute, verified-executable deployed path
(self-healing a lost exec bit via `chmod` where needed) or falls back to the
always-works temp-file redirect — never a bare, potentially-missing name.
Two installer permission-safety fixes are also included.

## Highlights

- **echd-capture path resolution fixed**: `pipe_blocker` recommends an
  absolute deployed path to `echd-capture`, self-heals a lost exec bit, and
  falls back to a temp-file redirect rather than ever suggesting a bare
  command name that might not be on `PATH`.
- **Deploy-time executability**: `hooks_deploy.sh` now ensures the vendored
  `echd-capture` helper is executable at deploy time, mirroring the existing
  hook-permission handling (including `core.fileMode=false` checkouts).
- **Installer fix (Issue #4)**: the installer only marks its own hook
  entrypoints executable, instead of touching unrelated files.
- **Installer fix (Issue #3)**: fixed a nested-install-check false positive
  that blocked consumer projects performing a manual install.

## Changes

## [3.41.1] - 2026-07-15

### Fixed

- `pipe_blocker` now recommends a resolvable, absolute deployed path to
  `echd-capture` (self-healing a lost exec bit via `chmod`, logged on
  failure) instead of a bare command name that could be missing from PATH in
  client installs; falls back to the always-works temp-file redirect when the
  helper cannot be resolved at all. `hooks_deploy.sh` now ensures the
  vendored helper is executable at deploy time (mirrors
  `set_hook_permissions`; handles `core.fileMode=false` checkouts).
- Installer only marks its own hook entrypoints executable, instead of
  touching unrelated files during install (Issue #4).
- Fixed a nested-install-check false positive that blocked consumer projects
  performing a manual install (Issue #3).

### Changed

- Internal: black formatting normalisation of pre-existing long lines and
  regression test line splits touched by the Issue #3/#4 fixes.
- Docs: codified the report-handling standing rule (reports in `untracked/`
  must be cleaned up or tracked into a plan folder, never left in limbo) in
  `CLAUDE.md`.
- Plan 00164 (ccy supervisor lifecycle + upgrade clarity) and Plan 00165
  (install permission bug fixes) marked Complete and archived.
- Plan 00166 opened to investigate supervisor multi-terminal session
  isolation (root cause + hypotheses only; no shipped code in this release).

See `CHANGELOG.md` for the complete entry.

## Installation

### New Installations

