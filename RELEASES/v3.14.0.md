# Release v3.14.0 — ask_user_question_blocker: prefix-positive policy

**Type:** Minor Release

## Summary

This minor release ships the `ask_user_question_blocker` handler (Plan 00108), an opt-in enforcement layer for `AskUserQuestion` tool calls. The handler applies a prefix-positive policy that mirrors the Stop handler's `STOPPING BECAUSE:` convention: questions are only allowed through to the user when the agent explicitly declares why it cannot decide autonomously by prefixing each `question` string with `ASKING BECAUSE:`. Without that prefix, the call is denied with structured guidance to state the assumed-correct answer in plain output text and proceed.

The handler ships disabled by default and is fully backwards-compatible — existing configurations require no changes.

## Highlights

- **Prefix-positive policy for AskUserQuestion**: Only `ASKING BECAUSE:`-prefixed questions reach the user; everything else is denied with actionable guidance.
- **Tautological question detection**: Deny guidance enumerates good-vs-bad archetypes (best-practice vs. bodge, delivering vs. not, fixing vs. leaving broken, following conventions vs. inventing) so the agent understands when a question is tautological and should not be asked.
- **Audit-log pattern**: Agents are instructed to state the assumed answer in output text and proceed, giving the watching user the same oversight they would have had via the question without pausing the session.
- **Strict and advisory modes**: `mode: strict` (default) denies; `mode: advisory` warns and allows, so teams can dogfood the convention before turning on hard blocking.
- **Configurable prefix**: `required_prefix` option allows projects to customise the expected prefix string.

## Changes

### Added

- **`ask_user_question_blocker` handler — prefix-positive policy for `AskUserQuestion`** (Plan 00108): `AskUserQuestion` calls are only allowed through when every `question` string begins with `ASKING BECAUSE:` (case-sensitive, leading whitespace OK). The convention mirrors the Stop handler's `STOPPING BECAUSE:` pattern — the agent must declare why it cannot decide autonomously before pausing the session. Without the prefix the call is denied with structured guidance: a list of tautological question archetypes (best-practice vs. bodge, delivering vs. not delivering, fixing vs. leaving broken, following conventions vs. inventing) and the instruction to state the assumed-correct answer in plain output text and proceed, leaving the user an audit trail to interrupt if the assumption is wrong. Adds `mode: strict` (default, denies) and `mode: advisory` (warns, allows) options plus a configurable `required_prefix` option. Ships with 30 unit tests (96.92% file coverage). **Disabled by default** — enable in `hooks-daemon.yaml` under `pre_tool_use.handlers.ask_user_question_blocker`.

### Fresh Installations

```bash
git clone -b v3.14.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git
cd claude-code-hooks-daemon
./scripts/install.sh
```

### Enabling the New Handler

To opt in to the `ask_user_question_blocker`, add to `.claude/hooks-daemon.yaml`:

```yaml
handlers:
  pre_tool_use:
    ask_user_question_blocker:
      enabled: true
      options:
        mode: strict         # or "advisory" to warn without blocking
        required_prefix: "ASKING BECAUSE:"
```

Restart the daemon after editing config:

```bash
$PYTHON -m claude_code_hooks_daemon.daemon.cli restart
$PYTHON -m claude_code_hooks_daemon.daemon.cli status
# Expected: Daemon: RUNNING
```
