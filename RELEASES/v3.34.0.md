# v3.34.0 — ccy supervisor: arm on deploy, keep files tracked, enforce integrity

**Release date**: 2026-07-10
**Type**: MINOR release

## Summary

v3.34.0 makes the v3.33.0 ccy supervisor auto-deploy (Plan 00148) work
end-to-end and enforces its correct setup. v3.33.0 deployed
`claude-supervise.py` into a project's `.claude/ccy/` but never **armed** it, and
projects whose `.claude/ccy/.gitignore` is a blanket `*` silently git-ignored the
deployed files — so in client projects the supervisor was a no-op that never
reached teammates. Now the deploy **deploys, arms, and keeps the files
trackable**, and a new SessionStart advisory handler surfaces the brick-risk
states an armed-but-misconfigured supervisor can create.

No breaking changes; no removed features; no new config keys.

## Highlights

- **Arm on deploy** — after copying `claude-supervise.py`, the deploy ensures
  `.claude/ccy/ccy.env` exports a self-locating, armed `CCY_CLAUDE_WRAPPER` that
  the ccy launcher sources. The armed line self-locates via `${BASH_SOURCE[0]}`,
  so one line works for both the podman `/workspace` mount and an arbitrary LXC
  project dir. Idempotent; an existing wrapper (set OR commented out) is left
  untouched.
- **Keep the files trackable** — the deploy appends whitelist exceptions
  (`!claude-supervise.py`, `!ccy.env`, `!.gitignore`, `!Dockerfile`) to an
  **existing** `.claude/ccy/.gitignore` so a blanket `*` no longer silently drops
  the supervisor from the repo. It never fabricates a policy file where none
  exists — only the files we own are made trackable.
- **Enforce integrity** — new `ccy_supervisor_integrity` SessionStart handler
  warns (never blocks) when an **armed** supervisor's script is missing, not
  executable, or git-ignored — the states that brick `ccy` launches for the
  project and for teammates. Silent for non-ccy / un-armed projects.

## Changes

### Added

- **`ccy_supervisor_integrity` SessionStart handler (Plan 00148)** — advisory
  brick-risk detector for an armed ccy supervisor. Enabled by default; opt out
  with `handlers.session_start.ccy_supervisor_integrity.enabled: false`.

### Changed

- **ccy deploy keeps the supervisor files trackable (Plan 00148)** — appends
  whitelist exceptions for our files to an existing `.claude/ccy/.gitignore`;
  does not manage the rest of the project's ignore policy.

### Fixed

- **ccy supervisor auto-deploy did not arm `CCY_CLAUDE_WRAPPER` (Plan 00148)** —
  the deploy now arms `ccy.env` idempotently, so the v3.33.0 supervisor actually
  runs instead of sitting deployed-but-inert; `ccy.deploy_supervisor: false`
  still opts out of both deploy and arm.

No breaking changes — no upgrade guide required. No new config keys.

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required. Projects that already set
`ccy.deploy_supervisor: true` (or left it unset, deploying by default) will have
their `.claude/ccy/ccy.env` armed and their existing `.claude/ccy/.gitignore`
whitelisted on the next install/upgrade run. The new integrity handler is
enabled by default and stays silent unless a ccy project's armed supervisor is
misconfigured.

## Installation

### New Installations

```bash
mkdir -p .claude && cd .claude
git clone https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
git fetch --tags && git checkout v3.34.0
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.34.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
