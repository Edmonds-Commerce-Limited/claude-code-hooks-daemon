# v3.21.0 — Minor: parallel-session socket reuse, LXC/LXD container detection

**Release date**: 2026-06-17
**Type**: MINOR release

## Summary

v3.21.0 fixes a long-standing concurrency hazard: when two Claude Code sessions share the same hostname and project root (the common case for parallel agent sessions inside a single LXC container, or a host + container sharing a bind-mounted `untracked/`), a second `start` unconditionally unlinked the live socket and clobbered the PID file, silently orphaning the first daemon. One session's hooks worked; the other's did not, with no error visible to either. The fix introduces socket-liveness probing so that a second start detects a healthy incumbent and reuses it instead. An exclusive `flock` guards the probe→bind critical section against near-simultaneous races.

The release also adds LXC/LXD container detection. `detect_container_runtime()` now identifies LXC sessions via `/run/systemd/container`, `container=lxc` env, cgroup-v1 token, and `/dev/lxd/sock` probes. The `environment_indicator` status-line handler renders 🧊 for LXC, and LXC auto-enables `enforce_single_daemon_process` for new installs (safe because socket reuse runs before enforcement).

## Highlights

- **Parallel sessions share one daemon safely** — A second `start` probes socket liveness and reuses a healthy incumbent (exit 0, incumbent untouched). Live sockets are never unlinked. An exclusive `flock` serialises the critical section so simultaneous starts cannot race. Affects LXC containers running multiple agent sessions and host+container bind-mount setups.
- **LXC/LXD container detection** — New runtime recognised in `detect_container_runtime()` via four independent probes. Status line shows 🧊 for LXC. No subprocess spawned.
- **`enforce_single_daemon_process` respects healthy incumbents** — Previously enforcement unconditionally terminated other daemon processes. It now checks socket liveness first and spares a healthy incumbent, consistent with the new start-up logic.
- **New constant `Timeout.SOCKET_LIVENESS_PROBE_SEC`** — Timeout for the health probe sent to the incumbent socket during start-up, replacing a magic number.

## Changes

### Added

- **LXC/LXD container detection (Plan 00127, Phase 4)** — `detect_container_runtime()` now recognises LXC via `/run/systemd/container` (primary), `container=lxc` / `container=lxc-libvirt` environment variables, cgroup-v1 `lxc` token, and `/dev/lxd/sock` / `/dev/.lxc` device probes (no subprocess). New `_RUNTIME_LXC` constant. The `environment_indicator` status-line handler renders 🧊 for LXC sessions; `yolo_container_detection` recognises LXC as a container environment. LXC now auto-enables `enforce_single_daemon_process` for new container installs (safe — socket-liveness reuse runs before enforcement so a healthy incumbent is never terminated).

### Fixed

- **Parallel Claude Code sessions no longer fight over the daemon socket (Plan 00127, Phases 2+3)** — Previously a second `start` (e.g. a parallel agent session sharing the same hostname + project root inside an LXC container) unconditionally unlinked the live socket and clobbered the PID file, orphaning the first daemon. One session's hooks worked; the other's silently did not. The fix introduces socket-liveness probing: a second start connects to the incumbent socket, sends a lightweight health probe, and — if the response is healthy — exits 0 leaving the incumbent untouched. A live socket is never unlinked. An exclusive `flock` serialises the probe→bind critical section so near-simultaneous starts cannot orphan each other. `enforce_single_daemon_process` is updated to spare a healthy incumbent. New constant `Timeout.SOCKET_LIVENESS_PROBE_SEC`.

## Installation

### New Installations

```bash

git clone https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
git fetch --tags && git checkout v3.21.0
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..
```
