# Release v3.17.0 - Rule Infrastructure, Robust Upgrades, and Worktree Fixes

**Release Date:** 2026-05-29
**Type:** Minor Release

## Summary

v3.17.0 delivers four plans and several standalone fixes. The centrepiece is Plan 00116 (Phases 1-2): a new `Rule`/`RuleID`/`DisclosureTracker` core infrastructure that lays the groundwork for stateful progressive disclosure — terse repeat-block reminders and verbose first-fire messages keyed per rule. Plan 00114 hardens the upgrade system with four targeted fixes (legacy flag compatibility, python_discovery.sh self-fetch, proactive overlay-fs copy mode, and surfaced recovery hints). Plan 00115 mitigates the batch-cancellation footgun with a DENY-suffix signal and a worktree path-classification fix in `markdown_organization`. Plan 00117 enables `ask_user_question_blocker` in the project's own dogfood config. Two additional standalone fixes close the `scheduled_tasks.lock` gitignore gap and a `worktree_paths` None-on-error bug.

## Highlights

- **Rule/RuleID/DisclosureTracker infrastructure (Plan 00116)** — New `Rule` model and `RuleID` constants enable handlers to declare their blocking rules; `DisclosureTracker` powers stateful progressive disclosure (verbose first-fire, terse repeats). `Handler.get_rules()` added with default `return []` for graceful degradation.
- **Four upgrade-system hardening fixes (Plan 00114)** — `--already-bootstrapped` legacy flag, `python_discovery.sh` self-fetch from `/tmp`, proactive overlay-fs copy mode, and recovery hints within the 30-line cap.
- **Batch-cancellation DENY-suffix signal (Plan 00115)** — Block responses now append `-DENY` to their decision ID, warning agents that sibling tool calls were cancelled and must be re-issued.
- **Worktree path-classification fix (Plan 00115 / standalone)** — `markdown_organization` and the `effective_project_relative_path` helper now evaluate files relative to their enclosing worktree root instead of the main repo root.
- **`scheduled_tasks.lock` gitignore enforcement** — `gitignore_safety_checker` now enforces that the runtime lock file is gitignored.

## Changes

### Added

- **Rule/RuleID/DisclosureTracker core infrastructure (Plan 00116, Phases 1-2)** — New `Rule` model, `RuleID` constants, and `DisclosureTracker` at `src/claude_code_hooks_daemon/core/rule.py` and `constants/rule_ids.py`, plus a stateful progressive-disclosure measurement harness. Handlers can now declare their blocking rules via `get_rules()` (default returns `[]` for graceful degradation). Infrastructure for per-block terse reminders, first-fire verbose messages, and a CLAUDE.md rule-ID table is in place — wiring to live handlers is deferred to Phase 3+.
- **`get_rules()` method on `Handler` base class (Plan 00116, Phase 2)** — Non-abstract method with default `return []` body added to `Handler` ABC. Existing handlers continue to work without modification; blocking handlers can override to declare `Rule` objects for the progressive-disclosure system.
- **`worktree-aware effective_project_relative_path` helper (Plan 00115 / worktree fix)** — New utility function that classifies files relative to their enclosing worktree root rather than the main repo root.
- **`scheduled_tasks.lock` gitignore enforcement (standalone)** — `gitignore_safety_checker` now verifies that `.claude/scheduled_tasks.lock` is present in `.gitignore`.

### Changed

- **`markdown_organization` handler classifies worktree files relative to worktree root (Plan 00115 worktree fix)** — Files inside `untracked/worktrees/<branch>/` were incorrectly evaluated against the main project root, causing false blocks on valid markdown paths.
- **Upgrade shim (Layer 1) accepts `--already-bootstrapped` flag (Plan 00114, F1)** — Old-format upgrade shims that pass `--already-bootstrapped` now work correctly.
- **Layer 1 self-fetches `python_discovery.sh` for `/tmp`-based installs (Plan 00114, F2)** — When running from `/tmp`, Layer 1 fetches the canonical script from the release rather than relying on a local copy.
- **Proactive copy mode on overlay-fs (Plan 00114, F3)** — `UV_LINK_MODE=copy` is exported proactively when an overlay filesystem is detected.
- **Upgrade failure messages surface recovery hints (Plan 00114, F4)** — Recovery hint messages are now emitted in a single `printf` block within the 30-line output cap.
- **`ask_user_question_blocker` enabled in project dogfood config (Plan 00117)** — Active in this project's own `.claude/hooks-daemon.yaml`.
- **DENY-suffix appended to block decision IDs (Plan 00115, G1/G3)** — Block responses append `-DENY` to signal batch-cancellation risk to agents.
- **`SkillCommand` constant extracted for rule-explain command name (Plan 00116)** — Named constant replaces magic string in `rule.py`.

### Fixed

- **`worktree_paths` helper no longer returns `None` on error** — Returns empty result consistently instead of `None`.
- **`rule.py` `_EXPLAIN_SUFFIX` dropped slash-command syntax (Plan 00116)** — Removed leading `/` that caused skill-references QA failures.
- **Pre-inject `satisfied` test updated for `scheduled_tasks.lock` gitignore pattern** — Unit test updated to reflect new enforcement.

### Removed

- **Workflow-state-across-compaction subsystem** — Removed the `workflow_state_pre_compact` and `workflow_state_restoration` handlers, their tests, config registrations, the `STATE_MANAGEMENT` tag, `docs/WORKFLOWS.md`, and the release skill's dead workflow-state stage. The SessionStart restoration context was not reliably consumed, so the state files accumulated as stale cruft. **Backwards-compatible** — the registry discovers handlers by directory scan and ignores unknown config keys, so existing installs load cleanly even if these handlers remain listed in `.claude/hooks-daemon.yaml`. You may delete those two config blocks at your convenience.

## Upgrade Instructions

No breaking changes. No configuration migration required. Upgrade normally:

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.17.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```

See `CLAUDE/UPGRADES/` for version-specific upgrade guides.
