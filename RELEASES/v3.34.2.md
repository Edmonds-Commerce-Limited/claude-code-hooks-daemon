# v3.34.2 — stop-hook double-explanation fix + ANSI-safe supervisor input guard

**Release date**: 2026-07-10
**Type**: PATCH release

## Summary

v3.34.2 fixes two High-severity bugs surfaced by dogfooding v3.34.1:

1. A **Stop-hook false-positive** that forced the agent to repeat its
   `STOPPING BECAUSE:` explanation (the "double STOPPING BECAUSE" report),
   most reliably right after a `/compact`.
2. An **ANSI-poisoning regression** in the v3.34.1 ccy supervisor empty-input-box
   guard that left the armed supervisor permanently unable to inject `/compact`
   in any real terminal.

No breaking changes. No new config keys.

## Highlights

- **Stop handler no longer double-asks for a stop reason.** `auto_continue_stop`
  judged a valid explained stop "unexplained" whenever the current turn's final
  message was older than the 4-second staleness threshold with no newer message
  after it — routine right after a `/compact`. It now trusts an unsuperseded
  complete tail instead of denying, while still adopting a genuinely newer
  message whenever one exists (stale-tail leak protection preserved and tested).
- **ccy supervisor survives terminal control sequences.** The v3.34.1 empty-box
  guard counted terminal-generated escape sequences (focus events, cursor/device
  reports, mouse tracking) as typed content, so one window-focus switch wedged
  the box "non-empty" for the whole session (28 deferrals, 0 injections). The
  input-line model now parses and skips whole ANSI control sequences, while still
  counting real content: keystrokes, bracketed-paste payload, and up/down
  history-recall arrows.

## Changes

### Fixed

- **Stop handler wrongly denied a valid explained stop right after `/compact`
  (double `STOPPING BECAUSE:`)** — `_resolve_current_turn_message()` polled for a
  message newer than a complete-but-old final tail; when that tail was itself the
  current turn (no successor ever arrives), the poll returned `None` and the
  default branch denied the stop as unexplained. It now falls back to trusting
  the unsuperseded complete tail. A genuine newer message is still adopted when
  one exists, so the stale-previous-turn leak the staleness guard exists for
  stays closed (covered by a dedicated regression test).
- **ccy supervisor never injected `/compact` in a real terminal — empty-input-box
  guard poisoned by ANSI sequences (Bug C)** — `HumanInputLine.feed()` now runs a
  streaming ANSI state machine that consumes whole control sequences (CSI, SS3,
  OSC/string, even split across `read()` chunks) as non-content, while still
  counting printable keystrokes, bracketed-paste payload (`ESC[200~`…`ESC[201~`),
  and up/down history-recall arrows. Conservative bias preserved: unrecognised
  control bytes and UTF-8 still count; malformed sequences fall back to ground
  without swallowing later content.

No breaking changes — no upgrade guide required. No new config keys.

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

The upgrade refreshes both the daemon handlers and `.claude/ccy/claude-supervise.py`
in any ccy project (via `ccy.deploy_supervisor`). No config migration is required.
After upgrading, the Stop hook no longer forces duplicate explanations and a ccy
project's armed supervisor injects correctly even through terminal focus/mouse
noise.

## Installation

### New Installations

```bash
mkdir -p .claude && cd .claude
git clone https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
git fetch --tags && git checkout v3.34.2
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.34.2
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
