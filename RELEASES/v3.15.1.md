## Summary

This patch fixes a long-standing bug in `scripts/install/gitignore.sh::create_daemon_untracked_gitignore()` that affected every install and every upgrade since the function was introduced (Plan 00041 era).

The bug had two compounding faults:

1. **Wrong content** — the function wrote the literal `/untracked/` line into the inner `untracked/.gitignore`. That string is the **root-level** ignore entry (it's what the parent project's top-level `.gitignore` uses to ignore the dir). Inside the inner `.gitignore` the same line resolves to a nested `untracked/untracked/` path that doesn't exist on disk — providing **zero** ignore protection.
2. **Unconditional clobber** — the write used `echo > file`, so every `install_version.sh` / `upgrade_version.sh` invocation overwrote whatever the user had there. Any user who fixed the file manually (e.g. to the correct self-excluding `*` + `!.gitignore` form) had their fix erased on the next upgrade.

The inner `.gitignore` is meant to be the **second layer** of double `.gitignore` protection. Layer 1 is the parent-dir entry in the project root `.gitignore` (written by `ensure_root_gitignore()`); Layer 2 is the inner self-excluding `.gitignore` (so even if someone removes the Layer 1 entry, the dir contents remain ignored — only the `.gitignore` itself is tracked).

## What changed

### Fixed

- `create_daemon_untracked_gitignore()` now writes the proper two-line self-exclusion pair:
  ```
  *
  !.gitignore
  ```
- The function is now **idempotent** — it only rewrites the file when either self-exclusion line is missing. A correct inner `.gitignore` survives every subsequent upgrade byte-identical.
- The function **heals** prior corruption — a `/untracked/`-content file left over from a previous-version install is rewritten to the correct self-exclusion content on the next run.
- `verify_gitignore_complete()` now checks for both self-exclusion lines (was checking for the wrong `/untracked/` content, so previously passed against corrupted files).

### Changed

- `scripts/install/test_gitignore_manual.sh` Test 4 expanded: now asserts both self-exclusion lines present **and** that the parent-dir entry is absent.
- New Test 4b: idempotent re-call leaves a correct file byte-identical.
- New Test 4c: corrupted-by-prior-bug content is healed on next invocation.
- Two new module-level constants in `scripts/install/gitignore.sh` (`UNTRACKED_SELF_EXCLUDE_LINE_ALL`, `UNTRACKED_SELF_EXCLUDE_LINE_KEEP`) eliminate magic strings.

## Impact / who needs to act

Anyone who installed or upgraded the daemon under any prior 3.x (or earlier) version has a corrupted inner `untracked/.gitignore`. Symptoms:

- File contains a single line `/untracked/` instead of `*` + `!.gitignore`.
- Layer 2 protection is silently absent (Layer 1 typically still works, but the redundancy is gone).
- Manual fixes are reverted on every subsequent upgrade.

### Fix path (one of these)

1. **Run `/hooks-daemon upgrade` after this release lands** — the upgrade script's `setup_all_gitignores` call invokes the fixed function, which heals the corrupted content automatically.
2. **Or fix manually**:
   ```bash
   printf '%s\n%s\n' '*' '!.gitignore' > .claude/hooks-daemon/untracked/.gitignore
   ```
   (Adjust path for self-install layouts — file lives at `${DAEMON_DIR}/untracked/.gitignore`.)
