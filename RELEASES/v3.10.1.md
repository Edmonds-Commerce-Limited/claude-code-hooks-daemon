# Release v3.10.1 - SEV-1 hotfix: print_info-on-stdout broke every upgrade

**Release Date:** 2026-05-01
**Type:** Patch Release (SEV-1 hotfix)

## Summary

v3.10.0 shipped with a stdout-vs-stderr regression in `scripts/install/output.sh` that broke every `/hooks-daemon upgrade` from prior versions in the field. v3.10.1 fixes that one bug and adds a focused regression test that would have caught it.

If you were on v2.x or v3.9.x and your upgrade to v3.10.0 failed with a malformed `$VENV_PATH` or a `bin/python: No such file or directory` error, this release fixes it. Re-run `/hooks-daemon upgrade` after v3.10.1 publishes.

## The Bug

Every helper in `scripts/install/output.sh` except `print_error` was writing to stdout. The install scripts use the bash command-substitution capture pattern in several places:

```bash
VENV_PATH=$(ensure_venv "$daemon_dir" "$python_bin" "$target_version")
"$VENV_PATH/bin/python" -V
```

`ensure_venv` echoes its return value (the venv path) on stdout. When it also called `print_info "ensure_venv: creating venv at $venv_path"` before that echo, the `$()` capture grabbed both lines. The downstream `"$VENV_PATH/bin/python"` then resolved to a malformed two-line path:

```
/path/to/venv-py314-fefc85e6
→ ensure_venv: creating venv at /path/to/venv-py314-fefc85e6
/bin/python: No such file or directory
```

`verify_venv` failed and the upgrade aborted mid-way through, leaving the user's `.claude/hooks-daemon/` half-upgraded with the daemon not running.

## Why the v3.10.0 H-1 Gate Missed It

v3.10.0 added `tests/acceptance/test_diagnostic_scripts.py` as the BLOCKING H-1 acceptance gate (Plan 00104 Phase 9). Five cases passed at release time. The fixture, however, synthesises the venv layout and writes metadata via `write-venv-metadata` *directly* — it never invokes the `ensure_venv` helper or exercises the `VAR=$(...)` capture chain that `install.sh` and `upgrade.sh` use in production. The bug was outside the gate's coverage shape.

This is documented as a deficiency to address in a follow-up plan: the H-1 gate must run `install.sh` end-to-end against a clean fixture project, not synthesise state via CLI calls.

## Changes

### Fixed

- **`scripts/install/output.sh`**: `print_info`, `print_success`, `print_warning`, `print_verbose`, `print_header`, and `log_step` now write to stderr. Only `print_error` was correct in v3.10.0; the rest leaked into stdout and corrupted any caller using `VAR=$(helper ...)` capture patterns.

### Added

- **`tests/integration/test_install_output_stream_separation.py`**: Eight regression tests asserting (a) each progress helper writes to stderr only, and (b) the `VAR=$(fn_that_calls_helper_then_echoes_value)` capture pattern produces an uncorrupted result. The final test (`test_helper_then_echo_captures_only_echo_value`) is the exact shape of the `ensure_venv` failure mode and would have failed against v3.10.0 code.

## Breaking Changes

None. Patch release. No API or configuration changes.

## Upgrade Instructions

### If you are stuck on a half-upgraded v3.10.0 install

If your `/hooks-daemon upgrade v?.?.? → v3.10.0` failed mid-flight and your daemon is not running, you have two options:

**Option A — Wait for v3.10.1 to publish, then re-run upgrade**:

```bash
/hooks-daemon upgrade
```

The skill's self-bootstrap stanza will fetch the latest `upgrade.sh` (sha256-verified against `bootstrap-checksums.txt`) and proceed cleanly with the v3.10.1 fix in place.

**Option B — Patch your local `output.sh` and resume the v3.10.0 upgrade now**:

```bash
cd <your-project>/.claude/hooks-daemon/scripts/install
cp output.sh output.sh.broken
# Apply the same fix v3.10.1 ships:
sed -i 's|^    echo -e "${BLUE}→${NC} \$1"$|    echo -e "${BLUE}→${NC} $1" >\&2|' output.sh
# (and equivalent for print_success / print_warning / print_verbose / print_header / log_step)
cd <your-project>
./.claude/hooks-daemon/scripts/upgrade.sh
```

(If the `sed` is uncomfortable, just `git checkout v3.10.1 -- scripts/install/output.sh` once v3.10.1 is tagged.)

### Fresh installations

```bash
git clone -b v3.10.1 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon
cd .claude/hooks-daemon && ./install.sh
```

### Verify

```bash
/hooks-daemon health
# Expected: "Daemon: RUNNING" with no "venv not found" or "ModuleNotFoundError" errors
```
