# Release v3.13.0 — Status Line: magicmonty-style git status icons

**Type:** Minor Release

## Summary

This minor release extends the status line's `GitBranchHandler` with magicmonty-style status icons. The git element now surfaces working-tree state at a glance — ahead/behind counts, staged/unstaged change counts, untracked files, merge conflicts, and stash count — using the iconography popularised by [magicmonty/bash-git-prompt](https://github.com/magicmonty/bash-git-prompt).

Motivation: the prior status line showed only the current branch, so unpushed commits, uncommitted edits, and stashed work were invisible until you ran `git status` manually. The new icons make divergence and pending work obvious without context-switching.

## What's New

### Added

- **Magicmonty-style git status icons (`GitBranchHandler`)**: After the branch name, the handler now renders status icons parsed from `git status --porcelain=v2 --branch` plus a `git stash list` count. Each icon appears only when its count is non-zero, so a clean repo still shows just the branch.

  | Icon | Meaning                   | Colour |
  | ---- | ------------------------- | ------ |
  | `↑N` | Commits ahead of upstream | green  |
  | `↓N` | Commits behind upstream   | red    |
  | `●N` | Staged changes            | green  |
  | `✚N` | Unstaged changes          | yellow |
  | `✖N` | Merge conflicts           | red    |
  | `…N` | Untracked files           | grey   |
  | `⚑N` | Stashed entries           | cyan   |

  Example: `⎇ feature-branch ↑2 ●1 ✚3 …5` — branch is 2 commits ahead, has 1 staged change, 3 unstaged changes, and 5 untracked files.

### Changed

- **`GitBranchHandler` subprocess fan-out**: up to three additional git subprocess calls per render (`git status --porcelain=v2 --branch`, `git stash list`, and on first invocation the existing `git symbolic-ref` for default-branch detection). All calls reuse the existing `Timeout.GIT_STATUS_SHORT` timeout and fail silently to an empty icon string on any subprocess error, preserving the handler's "never break the status line" contract. The default-branch cache from v3.12.x is preserved — `_default_branch_detected` is only set once per process.

## Breaking Changes

None. This is a MINOR release. The handler's `HookResult` shape and decision contract are unchanged — only the rendered status-line string is extended with optional icon suffix. Status-line consumers that previously rendered just `⎇ {branch}` will now render `⎇ {branch} {icons}` when the working tree has any pending state; clean repos render identically to v3.12.x.

## Install / Upgrade

### Upgrading Existing Installations

No manual steps required. Run the upgrade skill from any Claude Code session in your project:

```
/hooks-daemon upgrade
```

Or directly from the daemon directory:

```bash
cd .claude/hooks-daemon
./scripts/upgrade.sh
```

The skill's self-bootstrap stanza fetches the latest `upgrade.sh` body from this release, sha256-verifies it against `bootstrap-checksums.txt`, and re-execs the fresh body before proceeding.

### New Installations

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon/main/install.sh)
```

Or clone a specific tag:

```bash
git clone -b v3.13.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon
```
