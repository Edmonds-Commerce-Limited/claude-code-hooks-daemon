# v3.41.0 — Supervisor Lifecycle and Upgrade Clarity

**Release date:** 2026-07-14
**Type:** Minor (new features, backwards-compatible, no breaking changes)

## Summary

This release delivers **ccy supervisor lifecycle and upgrade clarity**
improvements (Plan 00164). The supervisor now shows a startup banner and
spinner, detects when it is running stale code after a daemon upgrade, and
runs its decision logic in a restartable worker subprocess so that logic can
hot-reload without disturbing the wrapped `claude` PTY session. Client
upgrades now report a truthful installed→target version transition instead of
unconditionally claiming to already be up to date. A supervisor bug that
caused a queued `/compact` to be silently re-injected on top of itself
(producing 4-5 stacked ignored compactions in the field) is fixed by firing
`[esc]` repeatedly instead. The `echd-capture` output-capture helper is also
introduced, and is now the `pipe_blocker` handler's recommended alternative to
piping expensive commands into `tail`/`head`.

## Highlights

- **Supervisor startup banner + spinner** — visible confirmation of version
  and armed/dry-run mode on every ccy launch (opt-out via
  `CLAUDE_SUPERVISE_NO_BANNER`).
- **Stale-supervisor detection** — `ccy_supervisor_integrity` compares the
  running supervisor's source fingerprint against the on-disk file and warns
  when a daemon upgrade shipped a newer supervisor that hasn't taken effect
  yet.
- **Restartable policy-worker split** — supervisor decision logic runs in a
  separate subprocess that hot-reloads on a fingerprint change, isolating the
  PTY/child from decision-code restarts.
- **Truthful upgrade transition messaging** — upgrades report the real
  installed→target version instead of always saying "already at version X".
- **Compact-injection loop fix** — repeated `[esc]` flush instead of stacking
  ignored `/compact` re-injections.
- **`echd-capture` helper** — full-output capture with a bounded preview,
  recommended by `pipe_blocker`.

## Changes

See [CHANGELOG.md](../CHANGELOG.md) for the full categorised list.

### Added

- ccy supervisor startup banner + spinner (opt-out `CLAUDE_SUPERVISE_NO_BANNER`).
- Stale running-supervisor detection (SessionStart advisory via
  `ccy_supervisor_integrity`).
- Restartable policy-worker split for the ccy supervisor (opt-out
  `CLAUDE_SUPERVISE_NO_WORKER`).
- `scripts/echd-capture` output-capture helper, referenced by `pipe_blocker`
  guidance.

### Changed

- Upgrade messaging now reports the real installed→target version transition
  from the venv's `.daemon-version` stamp.

### Fixed

- Supervisor compact-injection loop — repeated `[esc]` flush instead of
  re-injecting `/compact` while one is already queued.
- `upgrade_transition.sh` helper output-capture corruption.
- `ccy_supervisor_integrity._read_supervisor_status` return-none-on-error
  shape.
- Policy-worker split now keeps a single authoritative compaction state
  machine on the host, so a worker stall/reload can't inject a duplicate
  `/compact` via the in-process fallback.

## Upgrade Instructions

No breaking changes — upgrade in place. See `CLAUDE/UPGRADES/` for the
version-specific upgrade guide directory structure (none required for this
release; there is nothing to migrate).

## Installation

### New Installations

```bash
cd .claude
git clone -b v3.41.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.41.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
