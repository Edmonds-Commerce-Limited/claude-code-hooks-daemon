# v3.57.0 — Progressive-Disclosure CLAUDE.md, Documentation-SSoT Enforcement, and Project-Layout Config SSoT

This release is anchored by three infrastructure themes rather than a single
feature: a two-tier progressive-disclosure rewrite of the injected `CLAUDE.md`
handler guidance (63.6% smaller), a new opt-in documentation-SSoT enforcement
system spanning edit-time lint, commit gate and session-start sweep, and a
project-layout config SSoT that lets a project's own directory names (not
hardcoded defaults) drive ten different handlers. Alongside these: an opt-in
experimental Rust socket relay transport with a one-command safe toggle, a
tool inventory/disable story for trimming schema bloat, and standing-auth
cadence tunables plus a supervisor-typed reinforcement channel.

**No breaking changes.** No handler was removed or renamed, no `@abstractmethod`
was added to the `Handler` base class, and every new config block ships with
defaults pinned byte-identical to prior behaviour — every project handler and
existing configuration continues to work unmodified.

## Added: two-tier progressive-disclosure `CLAUDE.md` injection (Plan 00116)

The injected handler-guidance block is now data-driven instead of uniformly
verbose. A small set of frequently-triggered handlers (~46, migrated onto a
`Rule`/`DisclosureTracker` pair) keep full promoted prose; every other
enforced rule collapses into a compact ID/trigger/why/fix table; purely
advisory handlers collapse further into a one-line-each list. Each collapsed
entry points to a new CLI for full detail on demand:
`bin/hooks-daemon explain-rule <ID>` and `bin/hooks-daemon explain-handler <name>`. A new `bin/hooks-daemon block-report` command and a
`/hooks-daemon rule-explain` skill round out the discovery surface, and
`claude_md.promotion` config lets a project tune which handlers stay
promoted. New `DisclosureReset` PreCompact/SessionStart handlers keep the
tracker's per-session promotion state correct across compaction and daemon
restarts. Measured 63.6% shrink in the injected block versus the prior
always-verbose form.

## Added: documentation-SSoT enforcement system (Plan 00284) — opt-in

New top-level `documentation.enabled` (ships `false`). When enabled, three
surfaces keep a project's documentation corpus honest against
`CLAUDE/DocumentationStrategy.md`'s one-canonical-home-per-fact ruleset,
sharing one check catalogue: a PreToolUse edit-time lint (`docs_qa_edit`), a
git-commit gate (`docs_qa_commit_gate`), and a SessionStart drift sweep
(`docs_qa_sweep`). Checks cover dead pointers, SSoT-quote drift, pointer-only
rules-file shape, hand-edited generated docs, at-import census, module-doc
budgets, and advisory duplicate-block detection. The `hooks-daemon docs-qa`
CLI (`--sweep` / `--lint` / `--check-staged`) always works regardless of the
switch, and policy defaults warn/advise-first (`documentation.qa`), so
enabling is safe — it adds advisory context, not denials, until individual
checks are ratcheted to block via `check_modes`.

A companion opt-in `hooks-daemon-docs-qa` agent (`agents.docs_qa.enabled`,
ships `false`) and matching `docs-qa` skill hunt the semantic drift the
deterministic checks cannot see — conflicting truths, paraphrase duplicates,
stale derived facts, verbose source-comment blocks acting as documentation —
and report file:line findings with remediations, never editing.

A related addition, `documentation.qa.scope_exclude_globs` (Plan 00289,
default `[]`), excludes matched files from the documentation corpus
*entirely* rather than merely capping them at ADVISE severity the way
`grandfather_allowlist` does — intended for frozen historical records such as
a versioned upgrade guide.

## Added: project-layout config SSoT (Plan 00288)

New top-level `layout` config block (`source_dirs`, `test_dirs`,
`config_dirs`, `vendor_dirs`, `mode: additive|replace`), every list defaulting
to empty for byte-identical behaviour to today. A new `ProjectLayout` runtime
facade composes this block with the existing `documentation.trees` /
`plan_workflow.directory` config homes into one handler-facing API, now read
by `markdown_organization`, `goal_injection`, `recovery_cron_advisor`,
`plan_workflow`, `plan_number_helper`, `worktree_file_copy`,
`same_commit_plan_doc`, `path_existence`, `tdd_enforcement`, and
`british_english` instead of each hardcoding `CLAUDE/`, `docs/` or
`CLAUDE/Plan/` independently. A project using non-default tree or
plan-directory names previously saw those handlers behave inconsistently
(`markdown_organization` in particular could block a write to the project's
own configured doc tree); this is now always corrected in the project's
favour, with no change for projects on the defaults.

As a precondition, five previously-independent hand-maintained
vendored/build-directory name sets (which had silently drifted apart) are
unified onto one reviewed `CORE_VENDORED_BUILD_DIR_NAMES` constant (11
names), and `validate_eslint_on_write`'s unsafe bare-substring skip matcher —
which would otherwise have started skipping first-party paths like
`src/builder/x.ts` once `build` joined the shared skip set — is replaced with
the same slash-bounded containment matcher `strategies.lint.common` already
used.

On the first daemon restart after upgrading past this version, 7 new
`.claude/rules/` directory-role pointer files are deployed automatically (one
each for source dirs, test dirs, the human and agent doc trees,
`.claude/skills/`, `.claude/agents/`, and the plan directory when
`plan_workflow.enabled`), each scoped to the project's own configured layout
and routing to `CLAUDE/DirectoryRoles.md`. This needs no config change; a
hand-edited copy is a supported customisation the daemon never touches again.

## Added: opt-in Rust socket relay transport + safe toggle (Plans 00290, 00294)

Every hook currently fires a fresh `bash` process that sources `init.sh` and
spawns a `python3 -c` transport per event. `daemon.transport` (new top-level
block, every rung off by default, byte-identical behaviour pinned by test)
adds an EXPERIMENTAL faster path: a std-only static Rust relay binary
(`relay/hooks_relay.rs`, zero crates) execs directly against a per-event Unix
socket, falling back through `nc -U` to the unchanged bash+python3 transport
on any failure — which is never removed. Opting in is two explicit decisions:
`relay_enabled`/`nc_enabled` to opt the fallback ladder in, and
`relay_source: build` (plain `rustc`, no cargo, first-class whenever a
musl-capable toolchain is present) or `relay_source: download` (a
sha256-digest-verified precompiled asset from the matching GitHub release) to
provision the binary — leaving `relay_source` unset means the ladder starts
one rung down.

Toggling was previously a three-step manual dance with no built-in
verification. `bin/hooks-daemon transport on|off|status` now performs config
flip (comment-preserving targeted edit) → forwarder regeneration → daemon
restart → verification (real socket payload shapes per event type: JSON
decision object, status-line raw text, exit-code-2 Stop block, per-event
listener check) as one command. Any verification failure auto-reverts the
previous state end-to-end and re-verifies it with the same probes; repeating
the current state is a clean no-op, and `transport status` reports the active
rung, listener count, relay binary facts, and the last toggle's persisted
verification result.

## Added: tool inventory/disable story (Plan 00293)

A tool the project never wants could previously only be fought at call time —
its multi-thousand-token schema still loaded into every session regardless.
New `bin/hooks-daemon tool-report` scans a project's session transcripts
(tool names and counts only, never content) and ranks tools by measured
schema cost vs. observed usage into never-want / never-used / low-use / keep
tiers. `artifact_publish_blocker` gained an opt-in `source_disable` option
that keeps a project's `.claude/settings.json` at `"enableArtifact": false`
(additive, idempotent, one-shot-backed) — the documented Claude Code switch
that removes the Artifact tool and its schema from new sessions entirely. New
top-level `tool_policy` block (`never_want`, `low_use_max_calls`) declares
tools a project has decided against, and a new opt-in `tool_disable_advisor`
SessionStart handler checks those declarations against project settings and
names the exact missing change. Nothing is ever disabled automatically except
where a project deliberately enables the blocker's own `source_disable`.

## Added: standing-auth cadence tunables + supervisor-typed channel (Plan 00283)

`standing_authorisations` no longer injects its short-form reminder on every
prompt. It now delivers the full text once per session to establish it, then
reinforces only on whichever comes first: `prompt_interval` (new option,
default 5 human prompts) or `interval_minutes` (new option, default 15)
elapsed since the last delivery. Automated turns — failsafe-recovery cron
ticks, goal-injection lines, and the handler's own reinforcement — neither
advance the counter nor earn a reinforcement, so the reminder no longer rides
every hourly cron tick.

A new opt-in `supervisor_channel_enabled` (ships `false`) routes a due
reinforcement through the ccy PTY supervisor as a real user-role typed line
(via a `<session>.standing-auth-intent` signal, fail-closed against forged
signals attempting to smuggle arbitrary text) instead of folded
hook-additional-context — a stronger channel, available only when a
supervisor is armed and live for the project. It fails open to the existing
channel on any failure, when disabled, or when no supervisor is armed; the
first delivery of a session is always hook-context regardless.

## Added: `archived-status-coherence` plan-QA check (Plan 00286)

A new plan-QA check, block severity at the commit stage, enabled by default
wherever plan QA is enabled. It reads the *staged* blob rather than the
worktree, catching a `git mv` of a plan into an archive directory whose
terminal status header was fixed on disk but never re-`git add`ed — a commit
that previously succeeded and shipped an archived plan with a live status.

## Fixed

- **Legacy bash+python3 transport failed with `ENXIO` on `/dev/stdin` under
  real hook events** — a Plan 00290 follow-up fix.
- **Per-event socket listener registration used the wrong wire name,
  silently breaking the status line** — a Plan 00290 follow-up fix.
- **Relay guard path leak and deep-client-path socket-dir event drop** — Plan
  00290 pre-release punch list findings F1–F4.
- **`skill-bootstrap` resolved a sibling source tree's venv instead of its
  own** (Plan 00285), with a guard added against the same class of bug
  recurring.
- **Quarantine guard produced a false positive on an unexpanded glob** — a
  Plan 00278 follow-up fix.
- **`validate_eslint_on_write`'s skip-path matcher used unsafe bare-substring
  containment** (Plan 00288) — fixed as a precondition of the
  vendored-directory-set unification described above.

## Upgrade

**In the Claude Code chat:**

```claude-code
/hooks-daemon upgrade
```

Optionally pass a target tag: `/hooks-daemon upgrade v3.57.0`. The default is
latest.

**From a terminal:**

```bash
.claude/skills/hooks-daemon/scripts/upgrade.sh
```

If the skill is not deployed in your project, fetch the canonical upgrader —
inspect before running, never pipe it to a shell:

```bash
curl -fsSL https://raw.githubusercontent.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon/main/scripts/upgrade.sh -o /tmp/upgrade.sh
less /tmp/upgrade.sh
bash /tmp/upgrade.sh --project-root /path/to/your/project
```

**New installations:**

```bash
mkdir -p .claude
git clone -b v3.57.0 https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git .claude/hooks-daemon

# The installer builds the fingerprint-keyed venv, installs the package and
# starts the daemon.
bash .claude/hooks-daemon/scripts/install_version.sh "$PWD" "$PWD/.claude/hooks-daemon"
```

Most new *features* ship disabled or gated behind an opt-in. Five changes
apply automatically on upgrade, none breaking: the progressive-disclosure
`CLAUDE.md` rewrite, the 7 new `.claude/rules/` directory-role pointer files,
the unified vendored/build-directory skip set, the `standing_authorisations`
cadence change, and the `archived-status-coherence` plan-QA commit check
(where plan QA is enabled). Two opt-ins are worth turning on deliberately for most
projects: **`documentation.enabled`** (documentation-SSoT enforcement, warns
before it blocks) and **`agents.docs_qa.enabled`** (the paired semantic-drift
agent) — run `hooks-daemon docs-qa --sweep` after enabling to get an initial
findings worklist. Check `hooks-daemon check-config-migrations --from 3.56.0 --to 3.57.0` for the full set of newly available options, including the
experimental `daemon.transport` relay and the `tool_policy` inventory story.
