# v3.40.0 — First-Class Plan Journalling

**Release date:** 2026-07-14
**Type:** Minor (new feature, backwards-compatible, no breaking changes)

## Summary

This release makes **plan journalling a first-class daemon feature** (Plan
00163). Every plan folder can carry a `JOURNAL/` subfolder of append-only,
per-day `NNNNN-Journal-YY-MM-DD.md` files — a chronological activity log
(findings, decisions, dead-ends, hand-off state) that complements `PLAN.md`
(which captures *what/why*; the journal captures *what actually happened*). The
daemon supports and encourages the habit through the **existing plan_qa
machinery** — no new handler, no new hook event — with six advise-first checks
across the edit, sweep, and commit surfaces.

Journalling ships **enabled by default and fully deployed**: `mkplan.bash`
scaffolds a `JOURNAL/` with a seeded day-1 file, and install/upgrade seeds a
client-owned `_JOURNAL_TEMPLATE_.md` (whose presence gates that scaffolding)
plus a `PlanJournalling.md` reference. It is designed to only affect *new*
plans — completed and legacy plans are never nagged (the presence check is
In-Progress-only), and a project excludes any active plan it does not want to
journal via `plan_workflow.qa.journal.grandfather_before`.

Also in this release: the opt-in `idle_housekeeping_advisory` beta handler
(Plan 00161), `daemon_stats` becomes opt-in, the dead
`enable_hello_world_handlers` flag is wired (Plan 00162), and supervisor
robustness fixes (Plan 00160).

### Post-upgrade notes (opt-in features and default flips)

This release adds opt-in features and flips two defaults. See
`CLAUDE/UPGRADES/config-changes/v3.40.0.yaml` (surfaced automatically by the
upgrade advisory):

- **Journalling is on by default** for plan-workflow projects. New plans are
  born with a `JOURNAL/`; your active in-progress plans get an advise-only
  "add a JOURNAL/" nudge. Opt one in by adding a day-file, or exclude the
  pre-journalling ones by setting `plan_workflow.qa.journal.grandfather_before`
  to one past your current highest plan number. See the seeded
  `PlanJournalling.md` for the entry grammar.
- **`daemon_stats` is now OFF by default.** If you relied on the daemon-health
  status line, add `handlers.status_line.daemon_stats.enabled: true`.
- **`enable_hello_world_handlers` now works** — the `✅ … hook system active`
  confirmation messages stop appearing (they were debug output from a dead
  flag). Set `daemon.enable_hello_world_handlers: true` to restore them.

Doc-truth reconciliation for the `Notes & Updates` → `Delivery & Milestones`
convention shift is recorded in `CLAUDE/UPGRADES/truth-changes/v3.40.0.yaml`.
