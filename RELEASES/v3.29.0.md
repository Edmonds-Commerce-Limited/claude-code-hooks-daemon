# v3.29.0 — Minor: two-layer runaway-process defence + recovery_cron_advisor warn-before-delete

**Release date**: 2026-06-24
**Type**: MINOR release

## Summary

v3.29.0 delivers a two-layer defence against runaway background processes motivated by a real incident
where an orphaned `ugrep -rl "class X" /` ran ~115 minutes at >1000% CPU and survived a context
compaction with no protection (Plan 00142).

Layer A (`root_recursion_guard`) prevents catastrophic recursive filesystem scans from starting at
all — blocking `grep -r`, `find`, `fd`, `rg`, and similar tools when their path resolves to `/`,
`/home`, `$HOME`, or other dangerous roots. Layer B (`background_process_tracker` handler +
`harvest-background` CLI subcommand) surface runaway processes after they start — tracking
backgrounded processes to a state file, injecting guidance to set up a watchdog cron, and providing
a `harvest-background` command that scans `ps` for CPU/wall-time breaches and reports them with
remediation commands.

The release also fixes a dogfooding bug in `recovery_cron_advisor`: the completion-phase guidance
previously advised deleting the failsafe recovery cron immediately when a plan completed, which left
the live session with no recovery coverage. The guidance now warns before deleting and advises
keeping the non-durable cron running until the session is genuinely finished.

**Owner steer**: the daemon never kills processes — it only surfaces breaches; the agent decides
what to do.

## Highlights

- **`root_recursion_guard` blocking handler** — Prevents whole-filesystem recursive scans before
  they start. Blocks `grep -r/-R/-rl`, `ugrep -r`, `rgrep`, `find`, `fd`/`fdfind`, `rg` pointed at
  `/`, `/proc`, `/sys`, `/home`, `/root`, `~`, or `$HOME`. Escape hatch:
  `MUST_SCAN_ROOT_BECAUSE="reason"` for the rare legitimate case. Ships ENABLED by default.
- **`background_process_tracker` PostToolUse advisory handler** — Detects backgrounded Bash
  processes (`run_in_background: true`, `&`, `nohup`/`setsid`/`disown`), records them to a JSONL
  state file, and injects rate-limited guidance to set up a watchdog cron and run
  `harvest-background`. Ships ENABLED by default. Never kills.
- **`harvest-background` CLI subcommand** — On-demand runaway scanner. Reports CPU-breach
  (catches reparented orphans) and wall-TTL breach for tracked PGIDs. Outputs `kill -- -<pgid>`
  remediation commands. Exit 0 clean / 1 breaches surfaced / 2 ps error.
- **`recovery_cron_advisor` warn-before-delete** — Completion-phase guidance updated: keep the
  non-durable cron while the session is live; `CronDelete` only when the session is genuinely
  finished. No config changes needed.

## Changes

### Added

- **`root_recursion_guard` PreToolUse blocking handler (priority 15, Plan 00142)** — Blocks
  recursive scanners (`grep -r`/`-R`/`-rl`, `ugrep -r`, `rgrep`, `find`, `fd`/`fdfind`, `rg`)
  whose path argument resolves to a catastrophic root location (`/`, `/proc`, `/sys`, `/home`,
  `/root`, `~`, `$HOME`). Shipped ENABLED by default (opt-out). Escape hatch: prefix the command
  with `MUST_SCAN_ROOT_BECAUSE="reason"` for the rare legitimate whole-disk scan. Motivating
  incident: an orphaned `ugrep -rl "class X" /` ran ~115 minutes at >1000% CPU and survived a
  context compaction with no protection.
- **`background_process_tracker` PostToolUse advisory handler (priority 28, Plan 00142)** —
  Detects backgrounded Bash processes (`run_in_background: true`, `&`, `nohup`/`setsid`/`disown`),
  records them to a per-project JSONL state file, and injects rate-limited guidance advising the
  agent to create a watchdog cron and run `harvest-background`. Shipped ENABLED by default
  (opt-out). The daemon never kills — it only surfaces; the agent decides.
- **`harvest-background` daemon CLI subcommand + `daemon/background_harvester.py` module (Plan
  00142)** — Scans `ps` output for runaway processes: CPU-breach detection for all processes
  (catches reparented orphans that lost their PGID) and wall-TTL breach for tracked PGIDs. Reports
  breaches with `kill -- -<pgid>` remediation commands. Flags: `--max-wall-seconds 600`,
  `--max-cpu-percent 400.0`, `--min-cpu-runtime-seconds 60`, `--state-file`, `--format`. Exit
  codes: 0 = clean, 1 = breaches surfaced, 2 = ps error.

### Changed

- **`recovery_cron_advisor` completion-phase guidance changed to warn-before-delete** — The
  completion-phase message previously advised running `CronDelete` immediately when a plan was
  marked complete. It now warns first: deleting the cron while the session is still live leaves the
  session with no recovery coverage if a rate limit or usage limit hits before the session ends.
  The updated guidance is to keep the non-durable cron running (it dies automatically on session
  exit) and run `CronDelete` only once the session is genuinely finished with no further work. The
  canonical recovery-cron prompt is updated to match. No config changes required.

## Usage Examples

```bash
# Check for runaway background processes
$PYTHON -m claude_code_hooks_daemon.daemon.cli harvest-background

# Custom thresholds
$PYTHON -m claude_code_hooks_daemon.daemon.cli harvest-background \
  --max-wall-seconds 300 \
  --max-cpu-percent 200.0

# JSON output for programmatic use
$PYTHON -m claude_code_hooks_daemon.daemon.cli harvest-background --format json

# Escape hatch for rare legitimate whole-disk scans (root_recursion_guard)
MUST_SCAN_ROOT_BECAUSE="auditing all SUID binaries system-wide"; find / -perm -4000

# Disable background_process_tracker (opt-out)
# In .claude/hooks-daemon.yaml:
#   handlers:
#     post_tool_use:
#       background_process_tracker:
#         enabled: false

# Disable root_recursion_guard (opt-out)
# In .claude/hooks-daemon.yaml:
#   handlers:
#     pre_tool_use:
#       root_recursion_guard:
#         enabled: false
```

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required. Both new handlers ship ENABLED by default. To opt out of either,
set `enabled: false` in `.claude/hooks-daemon.yaml` under the relevant handler key (see Usage
Examples above).
