# v3.30.0 — Minor: regenerate-docs CLI command + regen-docs skill subcommand

**Release date**: 2026-06-25
**Type**: MINOR release

## Summary

v3.30.0 adds an explicit, one-shot way to force-regenerate the daemon's generated
documentation **without restarting the daemon**: a `regenerate-docs` daemon CLI
command and a `/hooks-daemon regen-docs` skill subcommand. Both artifacts are
rewritten from live config + handler metadata in a single invocation —
`.claude/HOOKS-DAEMON.md` and the `<hooksdaemon>` guidance block inside the project
`CLAUDE.md`. This is the recovery path when a git merge/rebase conflict leaves those
generated files stale or conflict-marked: regenerate to the canonical form, then
stage the clean result.

## Highlights

- **`regenerate-docs` CLI command** — `$PYTHON -m claude_code_hooks_daemon.daemon.cli regenerate-docs` rewrites `.claude/HOOKS-DAEMON.md` (via the existing `DocsGenerator`
  path) AND the `CLAUDE.md` `<hooksdaemon>` block (via the same `ClaudeMdInjector` the
  daemon runs at startup), preserving surrounding user content.
- **`/hooks-daemon regen-docs` skill subcommand** — A user-facing alias routing to the
  CLI `regenerate-docs`, so any Claude Code session can refresh the generated docs
  without knowing the Python path.
- **No daemon bounce** — Unlike `restart` (which also refreshes these on startup),
  `regen-docs` regenerates both artifacts in place without stopping the running daemon.
- **Git-conflict recovery** — The intended use case: recover `.claude/HOOKS-DAEMON.md`
  and the `CLAUDE.md` `<hooksdaemon>` block after a merge/rebase leaves them
  conflict-marked or stale.
- **No breaking changes** — All existing configurations continue to work unchanged.

## Changes

### Added

- **`regenerate-docs` daemon CLI command + `/hooks-daemon regen-docs` skill subcommand**
  — `$PYTHON -m claude_code_hooks_daemon.daemon.cli regenerate-docs` rewrites both
  generated-doc artifacts from live config + handler metadata in one shot:
  `.claude/HOOKS-DAEMON.md` (via the existing `DocsGenerator` path) and the
  `<hooksdaemon>` guidance block inside the project `CLAUDE.md` (via the same
  `ClaudeMdInjector` the daemon runs at startup, preserving surrounding user content).
  Unlike `restart`, it regenerates both artifacts without bouncing the running daemon —
  the explicit recovery path when a git merge/rebase conflict leaves the generated docs
  stale or conflict-marked. The `/hooks-daemon` skill exposes it as the user-facing
  alias `regen-docs` (routing to the CLI `regenerate-docs`). Flags:
  `--include-disabled`, `--output PATH`, `--project-root PATH`.
- **Regression test pinning the `plan_number_helper` counter-read contract** — Added
  `test_ignores_git_config_counter_read`, asserting the daemon-recommended
  `git config --local hooksdaemon.latestPlanNumber` counter-read (and batched variants)
  is never matched or blocked by the `plan_number_helper` handler. Closes a gap where a
  future broadening of the handler's matcher could silently re-introduce a false block
  of the very fallback the daemon's own guidance recommends.

### Changed

- **Internal refactor: extracted `_build_initialised_controller(config, project_path)`
  in `daemon/cli.py`** — Single source of truth for the per-event `handler_config`
  mapping plus the `controller.initialise()` call, now shared by daemon startup
  (`cmd_start`) and the new `cmd_regenerate_docs`. Removes a 10-event dict that would
  otherwise be duplicated across the two call sites and drift. No behavioural change to
  daemon startup.

## Usage Examples

```bash
# Regenerate both HOOKS-DAEMON.md and the CLAUDE.md <hooksdaemon> block
$PYTHON -m claude_code_hooks_daemon.daemon.cli regenerate-docs

# Include disabled handlers in HOOKS-DAEMON.md
$PYTHON -m claude_code_hooks_daemon.daemon.cli regenerate-docs --include-disabled

# Alternate HOOKS-DAEMON.md output path
$PYTHON -m claude_code_hooks_daemon.daemon.cli regenerate-docs --output /tmp/HOOKS-DAEMON.md
```

Via the skill (from any Claude Code session):

```
/hooks-daemon regen-docs
/hooks-daemon regen-docs --include-disabled
```

Typical git-conflict recovery flow:

```bash
# A merge/rebase left the generated docs conflict-marked
/hooks-daemon regen-docs
git diff -- .claude/HOOKS-DAEMON.md CLAUDE.md   # only clean, regenerated content
git add .claude/HOOKS-DAEMON.md CLAUDE.md
```

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required. The new `regenerate-docs` subcommand is available
immediately after upgrade. No handler configuration changes are needed.

