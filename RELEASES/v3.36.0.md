# v3.36.0 — supervisor tick-starvation fix + CRITICAL context tier

**Release date**: 2026-07-11
**Type**: MINOR release

## Summary

v3.36.0 hardens the ccy PTY supervisor's auto-`/compact` behaviour on busy
threads and introduces a **CRITICAL** context tier above red.

The headline fix addresses the real reason context climbed unbounded on active
sessions: the supervisor's injection tick was only evaluated when `select()`
timed out, so during a continuous busy burst (steady terminal output) the
context poll never ran and no tier — however high — was ever acted on. Raising
the threshold alone would not have helped, because nothing was being evaluated
mid-burst. The tick now runs on a monotonic fixed interval independent of I/O.

On top of the fix, a new CRITICAL tier makes over-full context impossible to
ignore and to sit on: it renders a literal `COMPACT NOW` call-to-action in the
status line and drives more aggressive compaction by bypassing the post-injection
cooldown. The supervisor also gains an ESC-flush fallback for a `/compact` that
Claude Code queues but never fires, and stops racing a human's own queued
`/compact` (which previously caused `AbortError: Compaction canceled`).

No breaking changes. Fully backwards compatible — no new `hooks-daemon.yaml`
config keys; the CRITICAL tier and supervisor hardening are active by default.

## Highlights

- **Tick starvation fixed.** The `/compact` injection poll now fires on a fixed
  monotonic cadence regardless of terminal I/O, so red/critical context is acted
  on during busy bursts instead of climbing unbounded.
- **CRITICAL tier above red.** New highest tier in the shared classifier, the
  context sidecar, and the status line. 200k-window critical at 90%; 1000k-window
  critical at 60%.
- **`COMPACT NOW` in the status line.** At CRITICAL the status line shows a literal
  `🛑 COMPACT NOW` (bright, inverted) in place of the coloured circle icon.
- **Aggressive compaction at critical.** The supervisor bypasses the
  post-injection cooldown at CRITICAL, compacting exactly when context is most
  dangerous. Non-critical tiers keep the existing cooldown.
- **ESC-flush fallback.** If an injected `/compact` stays queued and unfired for
  `escape_after_seconds` (default 60s), the supervisor sends a single `[esc]` to
  flush it.
- **No more double-compact.** The supervisor defers to a human's queued `/compact`
  instead of racing it, eliminating `AbortError: Compaction canceled`.
- **ccy deploy-consistency warning.** An armed+present supervisor with
  `ccy.deploy_supervisor: false` is now flagged at session start (upgrades would
  otherwise silently leave a stale supervisor in place).

## Changes

### Fixed

- **Supervisor tick starvation on busy threads** — the injection tick only ran on
  `select()` timeout, so a continuous busy burst starved the context poll and
  context climbed unbounded past red. `_forward_io` now schedules ticks on a
  monotonic fixed interval independent of I/O activity; the poll fires on cadence
  and red/critical context is acted on mid-burst.
- **Supervisor double-fired `/compact` over a queued human `/compact`** — a
  human-typed but unfired `/compact` was raced by the supervisor's injection,
  triggering `AbortError: Compaction canceled`. `HumanInputLine` now detects a
  submitted `/compact`; the state machine transitions to AWAIT without injecting,
  deferring to the human's compaction.

### Added

- **CRITICAL context tier above red** — new highest tier in `context_tiers.py`,
  the context sidecar payload, and the status line. 200k-window critical at 90%,
  1000k-window critical at 60%. `is_red()` now covers RED and CRITICAL (all
  red-gated behaviour still triggers); `is_critical()` added for the stricter gate.
- **Status line `COMPACT NOW` call-to-action** — at CRITICAL, `model_context`
  renders a literal `🛑 COMPACT NOW` in place of the circle icon.
- **Critical-tier cooldown bypass** — the supervisor injects `/compact` even inside
  the post-injection cooldown window when the sidecar reports critical.
- **ESC-flush fallback (`escape_after_seconds`, default 60s)** — after injecting
  `/compact`, if it remains queued and unfired for the configured window the
  supervisor emits a single `[esc]` keypress to flush it, once.
- **`ccy_supervisor_integrity` deploy-consistency check** — warns when the
  supervisor is armed+present but `ccy.deploy_supervisor` is explicitly `false`
  (installer skips deploy on `false` → stale supervisor after upgrades). An absent
  key still deploys and is not flagged.

No breaking changes — no upgrade guide required.

## Upgrade

```
Use the hooks-daemon upgrade skill (Skill tool: skill=hooks-daemon, args=upgrade).
```

No config migration is required. The supervisor hardening and CRITICAL tier are
active automatically after upgrade + daemon restart. Projects running the ccy
supervisor should ensure `ccy.deploy_supervisor` is `true` (or absent) so the
refreshed `claude-supervise.py` is deployed — the new session-start advisory will
flag an explicit `false`.

## Installation

### New Installations

```bash
mkdir -p .claude && cd .claude
git clone https://github.com/Edmonds-Commerce-Limited/claude-code-hooks-daemon.git hooks-daemon
cd hooks-daemon
git fetch --tags && git checkout v3.36.0
python3 -m venv untracked/venv
untracked/venv/bin/pip install -e .
untracked/venv/bin/python install.py
cd ../..
```

### Upgrading Existing Installations

```bash
cd .claude/hooks-daemon
git fetch --tags
git checkout v3.36.0
untracked/venv/bin/pip install -e .
untracked/venv/bin/python -m claude_code_hooks_daemon.daemon.cli restart
```
